# タスクの流れ

タスクは GitHub の issue、段階は sub-issue である。ステータスはタスクだけが持ち、Project の欄「Status」に置く。
ステータスの移り変わりと割り当ては**遷移の表**（`tools/flow-gate/flow.config.json: transitions`）だけが決め、
ゲート（`tools/flow-gate/`）が GitHub の出来事を受けて表で照らす。表に無い変化は、誰が起こしてもゲートが前へ戻して
理由をコメントする。人（hidakagit）の判断は、回答フォームで明確な選択肢を選んで行う。

## 置き場と役割

| 置き場・役 | 持つもの・すること |
|---|---|
| 置き場のリポジトリと Project（`flow.config.json: repository`・`project`） | タスクの issue・段階・問いと答え・記録。記録は issue にだけ持ち、git に写さない |
| ゲート（Cloudflare の Worker。Webhook を受ける `ridecompass-gate` と、Access の内側の回答フォーム `ride-compass-answer`） | 表で次のステータスと割り当てを決めて書く。表に無い変化を戻す。回答フォーム |
| Claude（hidakagit-bot の名義） | 作業・問いとコメントを書く・実施の順番・検証中の確かめ・master への push・ラベル（規模・操作） |
| hidakagit | 回答フォームで答える。GitHub の画面で何を動かしてもよい（表に無ければゲートが戻す） |

- Claude は GitHub の置き場へ、hidakagit-bot のトークン（ユーザー環境変数 `FLOW_BOT_TOKEN`）でだけ書く。hidakagit の
  トークンで書かない——hidakagit に通知が届かず、ゲートが hidakagit の操作と見分けられなくなる。
  gh で書くときは `GH_TOKEN` に `FLOW_BOT_TOKEN` の値を渡す。
- ゲートは自分の書き込み（送り主 `flow.config.json: gate`）を無視する。組み込みの自動化「Auto-add to project」が
  issue を Project に入れると、ゲートが入口（下）を処理する。

## ステータスと割り当て

ステータスの名前・意味の並びと表は設定ファイルが正本で、ここに写さない。読み方だけを書く。

- **入口**（`entry`）: issue を書いた人で決まる。hidakagit が書いた issue は未着手で hidakagit-bot に、それ以外
  （Claude が書いた提案）は採否待ちで hidakagit に割り当てる。採否の問い（`adoption`）は決まった中身なのでコメントに書かず、
  回答フォームが設定から出す（採否待ちで Claude の問いのコメントがあれば、そちらが今の問い）。段階は入口にしない。
- **遷移**（`transitions`）: `from` から `to` へ動けて、`assign` がそのときの割り当ての既定（`null` は今のまま）。
  `when: blockersCompleted` の行は、前提（blocked by）が全部 completed で閉じているときだけ通る。
- **割り当て**: 回答フォームを通らない変化は表の既定、回答フォームを通る変化はフォームで選んだ「次に動くのは」。
  開いているタスクには常に hidakagit か hidakagit-bot の1人が割り当たる。**hidakagit-bot に割り当たったものが Claude の番**。
- **完了**: 閉じた理由（completed＝完成／not planned＝見送り）で分ける。Claude は master へ入れたら issue を
  completed で閉じる。開いた段階が残っていれば、ゲートが最初の段階だけを閉じてタスクを `nextStage` へ戻す。
  ボードで完了へ動かしたもの・回答フォームで完了を選んだものは、見送りで閉じる。完了からは戻せない（続きは新しい issue）。

## Claude がステータスを動かす

    node tools/flow-gate/bin/move.js <issue の番号> <ステータス>

表で通らない変化は書く前に断る。回答待ちへ動かすときは、今の問い（次の節）が形に合わなければ断る。

## 問い

hidakagit に求めることは、採否・判断・操作のお願い・確認のどれも、次の形のコメントで書く（hidakagit-bot の名義）。
書いたら回答待ちへ動かす（もう回答待ち・採否待ちなら、hidakagit に割り当て直す）。ゲートが hidakagit に割り当てる。
回答フォームが要る（採否待ち・回答待ちで、答えの無い問いがある）間は、ゲートが issue の出来事のたびに本文の先頭へ
「回答する」のボタンの画像（リンク付き）と、ステータス・問いの文・回答フォームへのリンクの1行を置き、要らなくなると消す
（コメントは古い順にしか並ばず、一番下は見落とすため。GitHub の画面そのものにはボタンを足せない）。

    ## 問い
    <問いの文（1行）>

    ### 選択肢
    - <文> → <次のステータス> / <次に動く者> / +<ラベル>
    - <文> → <次のステータス>
    - <文>

    <details><summary>判断材料</summary>
    （この問い1つだけで判断できるように書く）
    </details>

- 今の問いは、hidakagit-bot かゲートが書いた、1行目が `## 問い` のコメントのうち最新の1つ。
- 選択肢は2つ以上。`→` の後ろは要るときだけ書く: 次のステータス（設定の名前）・次に動く者（`people` の `shown`。
  Claude か hidakagit）・付けるラベル（`+` の後ろ。置き場に在るものだけ。無ければ回答フォームが断る）。
  書かなければ、ステータスは今のまま、次に動く者は表の既定。
- 回答フォームは「その他（コメント）」「今は答えられない」を足し（`formOptions`）、表で行けない選択肢は出さない。
- 答える時点で答えられることだけを聞く。
- **聞くかどうか**: 外から見える振る舞いが変わるときだけ聞く。変わらないなら聞かずに報告して直す。聞いたら答えを待つ。
- **書く順**（判断材料の中）: 利用者への約束を1文 → 問題が起きる場面を1つと、起きない場面を1行 → 選択肢ごとに
  利用者に何が起きるか。背景を知らない人がこの問い1つだけで判断できるように、何の画面・機能の話か・いまどうなって
  いるか・なぜ決める必要があるかを入れる。画面の見た目・情報量に関わる判断は、変更前と変更後の画面かモックを添える。
- **製品の言葉で書く**: 実装の語（関数名・引数名）・固有名詞・タスク番号に頼らない。
- **選択肢**: 自分の領分（どう直すか・書き方）を選択肢に入れない。選択肢の文と実際に当てる作業を一致させる。
  推奨は判断材料の最後に理由と一緒に書く。回答フォームで完了を選ぶと見送りで閉じるので、完成を問いで決めない。
- 形が崩れた問いのまま回答待ちになると、ゲートがそう書いて hidakagit-bot に割り当てる。書き直してから
  hidakagit を割り当て直す。

## 答え

回答フォームが hidakagit の名義で次のコメントを書き、問い・リンク・答えを畳む。Claude はこれだけを読み、
チャットでの答えを判断に使わない。補足は決定を変えない。

    ## 回答
    問い: <問いのコメントへのリンク>
    選んだもの: <文>
    次のステータス: <名前>
    次に動くのは: <Claude／hidakagit>
    補足: <書いたときだけ>

## ラベルと種類

- 種類は Issue types（不具合・要望・保守・調査）で、1つのタスクにちょうど1つ。
- ステータスのラベル（`状態:未着手` など。`flow.config.json: statusLabelPrefix`）は、ゲートが Project の Status と同じ
  1つだけに合わせ続ける写し（スマホの issue の画面は Project の欄を出さず、ラベルなら一覧・詳細・`label:` の絞り込みで
  見える）。手で付け替えても戻る。ステータスを動かすのはボード・回答フォーム・move.js。
- ラベルは 優先・規模S・規模M・規模L・操作。規模の決め方は CLAUDE.md「規模の札」。前提は blocked by で付ける。
- 状態を動かしただけのコメントは書かない。本文と判断材料の詳細は `<details>` に入れる。

## コミット

件名は `tasks#<issue の番号>: <issue の題名>`。本文の行（背景・課題・成果・検証・増減・残り）は CLAUDE.md
「コミット時の同期ルール」のとおり。

## ゲートを変える・公開する

表・入口・問いの形の選択肢は `flow.config.json` を直す。公開は `tools/flow-gate` で `wrangler deploy`（Webhook）と
`wrangler deploy --env form`（回答フォーム）。秘密の値の名前は `tools/flow-gate/wrangler.toml` の先頭にある。
テストは `node --test tools/flow-gate/test/*.test.js`（CI の `flow-gate` も同じ）。
