# 地点の検索（backend）

## 責務

入力した文字列から、出発地・経由地・目的地にできる地点の候補を返す（`GET /api/place-search?q=`）。
候補は**種類**（何から引いたか。今は住所だけ）・**当たった段**（住所ならどこまで細かく当たったか）・表示名・位置を持つ。
住所は配布の住所の辞書（`jageocoder`用、街区まで・全国）を本番のbackendの手元で引き、**外部の検索サービスや別の
サーバーへ問い合わせる経路は持たない**。

**対象ファイル**

| レイヤー | ファイル |
|---|---|
| domain | `place_search.py`（種類・段の語彙と表示名、候補と答えの形、入力の整え方、住所の辞書の配布の版と出典の文言） |
| infrastructure | `address_dictionary.py`（辞書の置き場、辞書を開いて引き候補へ写す。段の写し、旧い行政区画の節の置き換え） |
| services | `place_search_service.py`（入力を整えて辞書を引き、対象範囲の外の候補を落とす） |
| api | `routers/place_search.py`（回数制限と、辞書が無い・範囲を読めないときの応答） |
| scripts | `fetch_address_dictionary.py`（辞書を配布元から取り、引けることを確かめてから置き場へ入れる。デプロイが呼ぶ） |

## 候補の形

| 項目 | 内容 |
|---|---|
| 種類（`PlaceKind`） | `address`（住所）。種類を足すときは語彙と表示名の表（`PLACE_KIND_LABELS`）へ1つずつ足し、口と答えの形は変えない |
| 当たった段（`PlaceMatchLevel`） | 辞書の段（`jageocoder.address.AddressLevel`の1〜8）をそのまま名前にしたもの（都道府県・郡・市区町村・区・大字/町・字/丁目・街区/地番・号）。街区までの辞書は号を返さない |
| 表示名 | 都道府県から当たった段までの名前をつないだもの（「東京都新宿区西新宿二丁目8番」） |
| 位置 | 当たった段の代表点（街区なら街区の代表点）。入口や建物の位置ではない |

種類と段の表示名は、語彙と同じ並びで生成物`vocabulary.ts`（`placeKinds`・`placeMatchLevels`）が画面へ届ける。

## 引き方

| 段 | 内容 |
|---|---|
| 入力を整える | 空白（全角も）を除く。辞書は空白を語の区切りとして読まず、空白から先に当たらない |
| 辞書を引く | 1回の検索ごとにスレッドで辞書を開いて引く。辞書のsqliteの接続は開いたスレッドでしか使えないため、開いた辞書を持ち越さない（開くのは1ms前後） |
| 当たらない入力 | 辞書は何も当たらない入力にも、当たった文字列が空の結果を1件返す。これは候補にしない |
| 旧い行政区画 | 辞書は合併で無くなった市の住所も旧い名前で引けるよう持ち、当たりがその節で終わると旧い名前のまま返す。その節は注記（`ref:`）が指す今の住所の節へ置き換え、同じ節が2度出たら1件にする |
| 範囲で絞る | サービスの対象範囲（取り込んだ道路の範囲、`RegionService.get_ingested_area`）の外の候補を落とす——範囲の外ではルートを作れない。辞書は全国を持つ。関東の外の方が入力の長い部分に当たるときは、関東の候補が辞書の答えに入らない |
| 並び | 辞書の並び（入力のより長い部分に当たったものが先）のまま |

| 失敗 | 応答 |
|---|---|
| 辞書を開けない（置き場に今の版が無い） | 503。起動は止めず、この口だけが使えない。引くたびに抑制付きのWARNINGを出す |
| 対象範囲を読めない（DB障害・道路を未取込） | 502（風の格子と同じ） |

回数制限は経路ごとの別枠（`place_search_rate_limit_per_minute`）。入力のたびに呼ばれる前提で、1件は手元の辞書を引くだけ
（数ms〜200ms前後）。サーバーでは答えを持たず、ブラウザへは1日持たせる（`api/cache_policy.py: MASTER_LOOKUP`）——
答えが変わるのは辞書の版と対象範囲が変わるときだけ。

辞書を開くたびに`jageocoder`が出す異体字の表の知らせ（配布の辞書はどの版もその表を持たない）は、`main.py`がロガー
`jageocoder.itaiji`のレベルを上げて抑える。

## 辞書の置き場と版

| 項目 | 内容 |
|---|---|
| 配布元の版 | `domain/place_search.py: ADDRESS_DICTIONARY_URL`（配布の版ごとのzip。ファイル名が版を表す）。出典の文言`ADDRESS_DICTIONARY_ATTRIBUTION`も同じ所に並べ、常時の出典（`domain/map_display.py: ALWAYS_SHOWN_ATTRIBUTIONS`）が読む |
| 置き場 | `backend/address_dictionary/<版の名前>/`（本番はホスト側のディレクトリを読むだけでマウントする）。zipに同梱のREADME（利用条件）も同じ所に入る |
| 作る時機 | `scripts/fetch_address_dictionary.py`（デプロイがコンテナを入れ替える前に毎回呼ぶ）。置き場に今の版があれば他の版を消すだけ。無ければzipを取り、一時の置き場へ入れ、1件引けることを確かめてから置き場の名前へ移し、zipを消す。引けなければ置き場を作らずに失敗で終わる。入れた回は他の版を消さない——入れ替えまで旧いコンテナが旧い版を検索のたびに開く |
| 版と読めるライブラリ | 辞書の版ごとに読める`jageocoder`の版が決まっている（docs/architecture/tech-stack.md「`jageocoder`は辞書の版が読める版に留める」） |

版の上げ方と頻度は docs/architecture/data-sources.md「版を持つ配布物の入れ替え」が持つ。

テストは配布の辞書を置けないため、`jageocoder`の公開の型で数件の節だけの辞書を書き（`tests/address_dictionary_fixture.py`）、
検索は本物を通す。
