# 地点の検索（backend）

## 責務

入力した文字列から、出発地・経由地・目的地にできる地点の候補を返す（`GET /api/place-search?q=&latitude=&longitude=`。緯度経度は
画面が見ている所の真ん中で、住所と施設を近い順に並べる点）。打ちかけの入力にも
同じ口で答え、入力の続き（入力を頭に持つ住所）を候補に足す——検索のボタンと打ちかけで同じ一覧・同じ回数制限になる。
候補は**種類**（何から引いたか。住所か施設）・**当たった段**（住所ならどの段の区画に当たったか。施設は施設そのものの点）・
表示名・位置を持つ。住所は住所の区画の表（下の「住所の区画の表」。都道府県から丁目・字まで）を引き、施設は立ち寄り先の
表（`stop_places`。[静的な道路の属性](static-road-attributes.md)の立ち寄り先）を名前で引く。**外部の検索サービスや別の
サーバーへ問い合わせる経路は持たない**。

**対象ファイル**

| レイヤー | ファイル |
|---|---|
| domain | `place_search.py`（種類・段の語彙と表示名、候補と答えの形、続きを足す最短の長さと件数（施設の件数も同じ）・画面が打ちかけで引くまでの間、住所の辞書の配布の版と出典の文言、住所の区画の元データの出典の文言）・`address_area.py`（住所の区画の段の語彙・続きに使う段・町字区分と段の対応、表記の揃え方、区画の名前から鍵を作る形、番地付きの残りの頭の形、区画の祖先から施設の辺りの名前と住所の表示名を組み立てる形。下の「住所の区画の表」「施設の辺り」） |
| batch | `derive_addresses.py`（住所の区画・鍵・小地域の境界の結び付きを作る派生の段）・`source_adapters/abr.py`（アドレス・ベース・レジストリの配布の zip を読む。テキストと代表点を1行に合わせ、代表点の無い行を落とす。範囲に掛かる都道府県の決め方も持つ）・`source_adapters/estat_small_area.py`（e-Stat の小地域の境界の Shapefile の zip を読む。分かれた多角形を小地域のコードごとに1つにし、通常の小地域でない行を落とす） |
| infrastructure | `address_search.py`（住所の区画の表を入力で引き、並べて上限で切り、祖先をたどった表示名の候補へ写す。下の「引き方」）・`address_area_lookup.py`（位置を含む小地域の境界に結んだ区画と、区画の祖先の並びを引く SQL の部品。祖先の並びは住所の表示名にも使う。下の「施設の辺り」）・`address_dictionary.py`（辞書の置き場と開き方。取得の道具が使う）・`stop_place_search.py`（立ち寄り先の表を名前で引いて点に近い順に並べ、施設の候補へ写す） |
| services | `place_search_service.py`（対象範囲・住所・施設（渡された点に近い順）を同じ接続で読み、住所と施設を並べる） |
| api | `routers/place_search.py`（回数制限と、範囲を読めないときの応答） |
| scripts | `fetch_address_dictionary.py`（辞書を配布元から取り、引けることを確かめてから置き場へ入れる。デプロイが呼ぶ）・`fetch_abr.py`（アドレス・ベース・レジストリの全国の1ファイルずつと、範囲に掛かる都道府県の町字の代表点を取る）・`fetch_estat_small_areas.py`（範囲に掛かる都道府県の e-Stat の小地域の境界を取る） |

## 候補の形

| 項目 | 内容 |
|---|---|
| 種類（`PlaceKind`） | `address`（住所）・`facility`（施設）。種類を足すときは語彙と表示名の表（`PLACE_KIND_LABELS`）へ1つずつ足し、口と答えの形は変えない |
| 当たった段（`PlaceMatchLevel`） | 住所は当たった区画の段（都道府県・市区町村・区・大字/町・字/丁目。`domain/address_area.py: ADDRESS_AREA_LEVELS`）。街区・号は持たない。施設は`point`（地点。施設そのものの点で、範囲の代表点ではない） |
| 表示名 | 住所は都道府県から区画までの名前をつないだもの（「東京都新宿区西新宿二丁目」。郡は区画の段でないので挟まない）。区画の表の`parent_id`をたどった祖先の名前（`address_area_lookup.py: area_chains_sql`）から`domain/address_area.py: area_label`が組み立てる（施設の辺りと同じ関数で、都道府県から書く）。施設は表の名前（「浅草寺」） |
| 辺り | 施設だけが持つ、施設の位置の市区町村から字・丁目までの名前（「川口市元郷四丁目」）。同じ名前のチェーンの店を見分ける。表の列`area`をそのまま出し、列が空の行（下の「施設の辺り」）と住所は持たない |
| 位置 | 住所は区画の代表点で、入口や建物の位置ではない。施設は表の位置（Overture の地点・寺社の建物） |

種類と段の表示名は、語彙と同じ並びで生成物`vocabulary.ts`（`placeKinds`・`placeMatchLevels`）が画面へ届ける。

## 引き方

| 段 | 内容 |
|---|---|
| 入力を揃える | 鍵と同じ揃え方（`domain/address_area.py: standardize_address`。空白・全角・漢数字・ハイフンと長音の類・数字の後の丁目等）にかける。揃えると空になる入力（「大字」）は住所を引かない（空の頭はどの鍵にも当たる） |
| 住所を引く | 区画の鍵の表（`address_search_keys`）を3通りで引く（`infrastructure/address_search.py`）。**全部に当たる**: 鍵が入力と同じか、入力に区切りを足したもの（「本町2」で二丁目の鍵「本町2-」）。**番地付き**: 入力の頭の部分のうち鍵にある最も長いもので、残りの頭が番地の形（数字・`-`・甲乙丙丁。`NUMBERED_REMAINDER_PATTERN`）のもの（「西新宿2-8-1」で鍵「西新宿2-」の二丁目）——番地は持たないので、番地まで打った入力は丁目・字までに当たる。丁目の無い番号（十二丁目までの町の「本町13-5」）は大字（本町）に当たる。**続き**: 続きに使う鍵（大字・町の段まで）のうち入力を頭に持つもの（「西新」で「西新宿」）。入力の一部にだけ当たった鍵（「小杉湯」の頭の「小杉」で、残りが番地の形でないもの）は引かない |
| 続きの絞り | 続きは、長さごとの鍵の件数を部分索引（`(length(key), key) WHERE continuable`）で数え、短いほうから数えて`PLACE_PREDICTION_LIMIT`件に届く長さまでの鍵だけを引く——1文字の入力では当たる鍵が全国で千を超え、全部を区画へつないで並べると遅い。入力より40文字長い鍵まで数えて届かなければ、長さで切らない。空白を除いて揃えた形で`PLACE_PREDICTION_MIN_LENGTH`（1）文字から足す——「柏」で柏市のような1文字の地名から選べる |
| 住所の並び | 同じ区画に当たった鍵は1件にまとめる（当たり方は全部に当たる・続きを、鍵は短いほうを採る）。並びは「全部に当たる・続き」→ 番地付き、その中は段の粗いもの → 鍵の短いもの → 検索の中心（渡された点）に近いもの（測地の距離）。段を鍵の長さより先にするのは、全国では「柏」という大字が上限を超えてあり、長さを先にすると柏市が上限から漏れるため。番地付きを後にするのは、「本町2」で大字の本町より二丁目を先にするため。`PLACE_PREDICTION_LIMIT`件で切ってから、残った区画の祖先をたどって表示名を作る |
| 時間 | 全国の試作の表（区画 約75万・鍵 約467万。代表点の無い小字を含む）で、1回 5〜50ms（1文字の「大」が最も長い。開発機、2026-10-09） |
| 施設を引く | 立ち寄り先の表の列`search_name`（名前の表記の揺れ（全角・半角・大文字・空白・ハイフン・中点）を除いた形。派生の段が`domain/stop_place.py: normalized_sql`で入れる）を、入力を同じ式で整えて部分一致（`strpos`）で引く——「一蘭」で「らーめん一蘭 新宿店」に当てる。整えると空になる入力（中点・ハイフンだけ）は引かない（空の文字列はどの名前にも含まれる）。対象範囲の中だけを、渡された点に近い店から`PLACE_PREDICTION_LIMIT`件まで（並びは下の「並び」）——チェーンの名前は関東に同じ名前の店が100件を超えてあり（「ファミリーマート」は関東の点のタイルの見本 13,615 件のうち125件、2026-10-08）、点に依らずに選ぶと見ている辺りの店が入らない。時間: 合成の40万行（関東の表は約35万行の見込み）で、列を部分一致で引いて並べて10件までが20〜30ms（住所の続きの1回と同じ桁）。引くたびに名前を`normalized_sql`で整えると約730ms、`lower`だけでも約150msかかるので列を持つ。`pg_trgm`の索引は拡張を本番に入れる操作（スーパーユーザー）が要るので使わない（2026-10-08 の測り） |
| 範囲で絞る | 施設はサービスの対象範囲（取り込んだ道路の範囲、`RegionService.get_ingested_area`）の外を落とす——範囲の外ではルートを作れない。住所は範囲で絞らない（区画の表に入るのは、派生の段が取込の範囲で選んだ区画とその祖先だけ）。対象範囲・住所・施設は同じ接続で読む |
| 並び | 住所 → 施設。施設の中は、名前が入力と同じ → 入力で始まる → 入力を含む、同じ中では渡された点に近い順（測地の距離。度のままの距離は関東の緯度で東西を2割ほど短く数える）。名前の短い順・確からしさの順では並べない——「ファミリーマート王子店」より名前の短い遠くの店が先に出る |

| 失敗 | 応答 |
|---|---|
| 対象範囲を読めない（DB障害・道路を未取込） | 502（風の格子と同じ） |
| 住所・施設の表を読めない（DB障害） | 捕まえない（500）。直前に同じ接続で対象範囲を読めているので起きにくく、片方だけに縮めて返すと、もう片方が無いのと見分けられない |

区画の表が空（住所の生データを取り込んでいない）なら、住所は当たらないだけで失敗にしない——派生の作り直しは`abr`の取込が無ければ
止まる（下の「住所の区画の表」）ので、本番に空の表は出ない。

回数制限は経路ごとの別枠（`place_search_rate_limit_per_minute`）。画面は打つのが止まってから`PLACE_PREDICTION_DELAY_SECONDS`
の間を置いて引くので、打ち続けたときの1分あたりの最大（60秒÷間）を既定の上限にしてある（間から導く）。サーバーでは答えを持たず、ブラウザへは1日持たせる
（`api/cache_policy.py: MASTER_LOOKUP`）——答えが変わるのは対象範囲・住所の区画の表・立ち寄り先の表が変わるときだけ（並べる点はURLに入るので、同じURLの答えは変わらない）。

## 施設の辺り

施設の辺りは、立ち寄り先の派生の段（[静的な道路の属性](static-road-attributes.md)の立ち寄り先）が、入れた地点の位置を含む
小地域の境界に結んだ住所の区画から決めて、表の列`area`に入れる。検索のたびには引かない。住所の辞書は読まない。

| 項目 | 内容 |
|---|---|
| 区画の決め方 | 位置を含む小地域の境界（生データ`estat_small_area`の多角形）の、`address_boundary_links`の区画（`address_area_lookup.py: boundary_area_sql`）。辺の上の点は、区画に結んだ境界のうち鍵の小さいほう。区画に結んだ境界に含まれなければ空（海の上・範囲の外・結べなかった境界の中） |
| 名前 | 区画の祖先を`parent_id`でたどった並び（`address_area_lookup.py: area_chains_sql`）の、市区町村から先の名前をつないだもの（`domain/address_area.py: area_label`）。都道府県・郡は持たず、政令市は市と区をつなぐ。丁目の名前は番号から漢数字でそろえる（`domain/address_area.py: chome_name`） |
| 引く量 | 地点ごとの区画は1つの SQL で決め、行を取り出すのは当たった区画の祖先の並びだけ（地点は取り出さない） |
| 段の順 | 区画の表を読むので、住所の区画の段の後ろに流す（`derive_cli.py: STAGES`） |

辞書を開くたびに`jageocoder`が出す異体字の表の知らせ（配布の辞書はどの版もその表を持たない）は、`main.py`がロガー
`jageocoder.itaiji`のレベルを上げて抑える。

## 辞書の置き場と版

| 項目 | 内容 |
|---|---|
| 配布元の版 | `domain/place_search.py: ADDRESS_DICTIONARY_URL`（配布の版ごとのzip。ファイル名が版を表す）。出典の文言`ADDRESS_DICTIONARY_ATTRIBUTION`も同じ所に並べ、常時の出典（`domain/map_display.py: ALWAYS_SHOWN_ATTRIBUTIONS`）が読む |
| 置き場 | `backend/address_dictionary/<版の名前>/`（本番はホスト側のディレクトリを、backendは読むだけでマウントする）。zipに同梱のREADME（利用条件）も同じ所に入る |
| 作る時機 | `scripts/fetch_address_dictionary.py`（デプロイがコンテナを入れ替える前に毎回呼ぶ）。置き場に今の版があれば他の版を消すだけ。無ければzipを取り、一時の置き場へ入れ、1件引けることを確かめてから置き場の名前へ移し、zipを消す。引けなければ置き場を作らずに失敗で終わる。入れた回は他の版を消さない |
| 版と読めるライブラリ | 辞書の版ごとに読める`jageocoder`の版が決まっている（docs/architecture/tech-stack.md「`jageocoder`は辞書の版が読める版に留める」） |

版の上げ方と頻度は docs/architecture/data-sources.md「版を持つ配布物の入れ替え」が持つ。

## 住所の区画の表

アドレス・ベース・レジストリ（生データ`abr`）と e-Stat の小地域の境界（生データ`estat_small_area`）から、派生の作り直しの段
`derive_addresses.py`（立ち寄り先の段の前）が作る。地点の検索の住所はこの表から引き（上の「引き方」）、施設の辺りもこの表から決める（上の「施設の辺り」）。

| 表 | 中身 |
|---|---|
| `address_areas` | 1行1区画（都道府県・市区町村・区・大字/町・丁目/字）。段・1つ粗い区画（`parent_id`）・自分の段の名前・郡の名前（郡の町村だけ）・代表点。表示の全名は持たない |
| `address_search_keys` | 区画を引く鍵（揃えた形、照合順序`C`）と、続きに使う鍵か（大字・町の段まで）。主キー（鍵, 区画）で等号と前方一致を引き、続きの鍵には長さと鍵の部分索引を張る |
| `address_boundary_links` | 小地域の境界（生データの鍵）1つに当たる大字・町か丁目・字。境界の多角形は生データに置いたまま |

| 決まり | 内容 |
|---|---|
| 生データ | `abr`は1回の取込に都道府県・市区町村（全国）と、範囲に掛かる都道府県の町字を入れ、テキストと代表点を1行にする（鍵は全国地方公共団体コードか`<コード>:<町字ID>`）。代表点の無い行（小字のほとんど）は入れない。代表点は日本測地系2000・2011から 4326 へ移す。`estat_small_area`は範囲に掛かる都道府県の通常の小地域（`HCODE` 8101）を、小地域のコードごとに1つの多角形で入れる。範囲に掛かる都道府県は、ABR の市区町村の代表点が範囲の中にある都道府県（`source_adapters/abr.py: prefectures_in_range`）で、取得も取込も同じ関数で決める |
| 区画にする行 | 廃止の日の無い行。町字は町字区分が`domain/address_area.py: MACHIAZA_TYPE_LEVELS`にあるもの（町字なし・道路名は区画にしない）。ABR に大字自身の行が無い大字は、子の町字IDの頭4桁でまとめ、子の代表点の重心に置く |
| 範囲 | 代表点が道路の取込の範囲（`road_graph_repository.py: INGESTED_BBOX_SQL`）の中にある区画と、その祖先（祖先の代表点は範囲の外でもよい） |
| 鍵 | 書き始める段（都道府県・郡・市区町村・区・大字）ごとの形と、都道府県から書いて郡を省いた形。丁目は区切り付き（「西新宿2-」）、字は「字」を挟む形と挟まない形（`domain/address_area.py: search_keys`） |
| 揃え方 | `domain/address_area.py: standardize_address`（NFKC・小文字・空白 → ハイフンと長音の類 → 漢数字 → 数字の後の丁目 → 「大字」 → 「ケ」「ノ」の類の順）。打った入力と鍵の両方にかける。ハイフンの類の集合は施設の名前の揃え方（`domain/stop_place.py: normalized_sql`）と共有する |
| 境界の結び付け | 同じ市区町村の中で、名前（字の「字」を除いて揃えた形。境界の名前は括弧の中も除く——1つの町丁・字を分けた小地域は「横山（一）四丁目」のように名前の途中に印を挟む）が区画（大字＋丁目・字）と同じ → 頭に当たる最も長い区画 → お尻に当たる最も長い区画（どちらも2文字以上）→ 中に代表点がある区画（丁目・字を先に）。どれにも当たらない境界は行にしない |
| 生データが無いとき | `abr`の取込が無ければ段が止まり、作り直し全体が何も入れ替えない。境界の取込が無ければ結び付きは空 |
| 時間 | 関東の範囲で、取込が`abr`約30秒・境界約90秒、段が約35秒（区画 約3.8万・鍵 約12.5万。開発機、2026-10-09） |

テストの住所は、ABR の行を取込の入口から入れて住所の派生の段を本物のまま流して作り（`tests/test_place_search_route.py`）、施設は
Overture の地点を取り込んで立ち寄り先の派生の段を本物のまま流して作る。住所の区画の表は、配布の形の小さな見本（ABR の CSV の zip・
e-Stat の Shapefile の zip）を置き場に書き、取込と派生の段を本物のまま流して作る（`tests/test_address_areas.py`）。施設の辺りは、
住所・境界・地点を取り込み、住所の段と立ち寄り先の段を本物のまま流して見る（`tests/test_stop_place_areas.py`）。辞書の取得は、
配布の辞書を置けないため、`jageocoder`の公開の型で数件の節だけの辞書を書いて見る（`tests/address_dictionary_fixture.py`）。
