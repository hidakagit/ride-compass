# 地点の検索（backend）

## 責務

入力した文字列から、出発地・経由地・目的地にできる地点の候補を返す（`GET /api/place-search?q=&latitude=&longitude=`。緯度経度は
画面が見ている所の真ん中で、住所と施設を近い順に並べる点）。打ちかけの入力にも
同じ口で答え、入力の続き（入力を頭に持つ住所）を候補に足す——検索のボタンと打ちかけで同じ一覧・同じ回数制限になる。
候補は**種類**（何から引いたか。住所か施設）・**当たった段**（住所ならどの段の区画に当たったか。施設は施設そのものの点）・
表示名・位置を持つ。住所は住所の区画の表（下の「住所の区画の表」。都道府県から丁目・字までと、その中の街区・地番）を引き、施設は立ち寄り先の
表（`stop_places`。[静的な道路の属性](static-road-attributes.md)の立ち寄り先）を名前で引く。**外部の検索サービスや別の
サーバーへ問い合わせる経路は持たない**。

置いた位置の辺り（`GET /api/place-area?latitude=&longitude=`）も返す。地点の詳しくが、地図で置いた地点・現在地・辺りの無い施設に
出す辺りで、施設の辺りと同じ決め方・同じ形（下の「施設の辺り」）を、要求ごとに位置から引く。

**対象ファイル**

| レイヤー | ファイル |
|---|---|
| domain | `place_search.py`（種類・段の語彙と表示名、候補と答えの形、続きを足す最短の長さと件数（施設の件数も同じ）・画面が打ちかけで引くまでの間、住所の区画の元データの出典の文言）・`address_area.py`（住所の区画の段の語彙・続きに使う段・町字区分と段の対応、街区の種類と表示名で番号に付ける語、表記の揃え方、区画の名前から鍵を作る形、番地付きの残りの頭の形と残りから街区の番号を取る形、区画の祖先から住所の表示名を組み立てる形。下の「住所の区画の表」） |
| batch | `derive_addresses.py`（住所の区画・鍵・街区を作る派生の段）・`source_adapters/abr.py`（アドレス・ベース・レジストリの配布の zip を読む。テキストと代表点を1行に合わせ、代表点の無い行を落とす。範囲に掛かる都道府県の決め方も持つ）・`source_adapters/estat_small_area.py`（e-Stat の小地域の境界の Shapefile の zip を読む。分かれた多角形を小地域のコードごとに1つにし、通常の小地域でない行を落とす）・`source_adapters/isj_block.py`（街区レベル位置参照情報の都道府県ごとの zip を読む。代表でない点・削除の行・範囲の外の点を落とす） |
| infrastructure | `address_search.py`（住所の区画の表を入力で引き、並べて上限で切り、祖先をたどった表示名の候補へ写す。下の「引き方」）・`stop_place_search.py`（立ち寄り先の表を名前で引いて点に近い順に並べ、施設の候補へ写す）・`place_area_query.py`（位置の辺りを小地域の境界から引く SQL の部品と、置いた位置の辺りを引く口。下の「施設の辺り」） |
| services | `place_search_service.py`（対象範囲・住所・施設（渡された点に近い順）を同じ接続で読み、住所と施設を並べる。置いた位置の辺りも引く） |
| api | `routers/place_search.py`（検索と置いた位置の辺りの2つの口。回数制限と、範囲を読めないときの応答） |
| scripts | `fetch_abr.py`（アドレス・ベース・レジストリの全国の1ファイルずつと、範囲に掛かる都道府県の町字の代表点・住居表示の街区のテキストと代表点を取る）・`fetch_estat_small_areas.py`（範囲に掛かる都道府県の e-Stat の小地域の境界を取る）・`fetch_isj_blocks.py`（範囲に掛かる都道府県の街区レベル位置参照情報を取る） |

## 候補の形

| 項目 | 内容 |
|---|---|
| 種類（`PlaceKind`） | `address`（住所）・`facility`（施設）。種類を足すときは語彙と表示名の表（`PLACE_KIND_LABELS`）へ1つずつ足し、口と答えの形は変えない |
| 当たった段（`PlaceMatchLevel`） | 住所は当たった区画の段（都道府県・市区町村・区・大字/町・字/丁目。`domain/address_area.py: ADDRESS_AREA_LEVELS`）か、番地まで打って区画の中の街区・地番に当たった`block`。号は持たない。施設は`point`（地点。施設そのものの点で、範囲の代表点ではない） |
| 表示名 | 住所は都道府県から区画までの名前をつないだもの（「東京都新宿区西新宿二丁目」。郡は区画の段でないので挟まない）。街区・地番はその後ろに番号と、住居表示の街区なら「番」・地番なら「番地」を付ける（「東京都新宿区西新宿二丁目8番」「東京都日の出町大字平井123番地」。`domain/address_area.py: block_label`）。区画の表の`parent_id`をたどった祖先の名前（`address_search.py: _AREA_CHAINS`）から`domain/address_area.py: area_label`が組み立てる。施設は表の名前（「浅草寺」） |
| 辺り | 施設だけが持つ、施設の位置の市区町村から字・丁目までの名前（「川口市元郷四丁目」）。同じ名前のチェーンの店を見分ける。表の列`area`をそのまま出し、列が空の行（下の「施設の辺り」）と住所は持たない |
| 位置 | 住所は区画の代表点（街区・地番はその街区・地番の代表点）で、入口や建物の位置ではない。施設は表の位置（Overture の地点・寺社の建物） |

種類と段の表示名は、語彙と同じ並びで生成物`vocabulary.ts`（`placeKinds`・`placeMatchLevels`）が画面へ届ける。

## 引き方

| 段 | 内容 |
|---|---|
| 入力を揃える | 鍵と同じ揃え方（`domain/address_area.py: standardize_address`。空白・全角・漢数字・ハイフンと長音の類・数字の後の丁目等）にかける。揃えると空になる入力（「大字」）は住所を引かない（空の頭はどの鍵にも当たる） |
| 住所を引く | 区画の鍵の表（`address_search_keys`）を3通りで引く（`infrastructure/address_search.py`）。**全部に当たる**: 鍵が入力と同じか、入力に区切りを足したもの（「本町2」で二丁目の鍵「本町2-」）。**番地付き**: 入力の頭の部分のうち鍵にある最も長いもので、残りの頭が番地の形（数字・`-`・甲乙丙丁。`NUMBERED_REMAINDER_PATTERN`）のもの（「西新宿2-8-1」で鍵「西新宿2-」の二丁目）。残りの最初の数字（頭の区切りを飛ばし、地番の頭の甲乙丙丁を含む。`BLOCK_NUMBER_PATTERN`。「8-1」で「8」）をその区画の街区の番号として街区の表（`address_blocks`）を1回引き、当たれば街区・地番、当たらなければ区画に当たる（号は持たない）。丁目の無い番号（十二丁目までの町の「本町13-5」）は大字（本町）の番地として読む。**続き**: 続きに使う鍵（大字・町の段まで）のうち入力を頭に持つもの（「西新」で「西新宿」）。入力の一部にだけ当たった鍵（「小杉湯」の頭の「小杉」で、残りが番地の形でないもの）は引かない |
| 続きの絞り | 続きは、長さごとの鍵の件数を部分索引（`(length(key), key) WHERE continuable`）で数え、短いほうから数えて`PLACE_PREDICTION_LIMIT`件に届く長さまでの鍵だけを引く——1文字の入力では当たる鍵が全国で千を超え、全部を区画へつないで並べると遅い。入力より40文字長い鍵まで数えて届かなければ、長さで切らない。空白を除いて揃えた形で`PLACE_PREDICTION_MIN_LENGTH`（1）文字から足す——「柏」で柏市のような1文字の地名から選べる |
| 住所の並び | 同じ区画に当たった鍵は1件にまとめる（当たり方は全部に当たる・続きを、鍵は短いほうを採る）。並びは「全部に当たる・続き」→ 番地付き、その中は段の粗いもの → 鍵の短いもの → 検索の中心（渡された点）に近いもの（測地の距離。街区・地番はその点から）。段を鍵の長さより先にするのは、全国では「柏」という大字が上限を超えてあり、長さを先にすると柏市が上限から漏れるため。番地付きを後にするのは、「本町2」で大字の本町より二丁目を先にするため。`PLACE_PREDICTION_LIMIT`件で切ってから、残った区画の祖先をたどって表示名を作る |
| 時間 | 全国の試作の表（区画 約75万・鍵 約467万。代表点の無い小字を含む）で、1回 5〜50ms（1文字の「大」が最も長い。開発機、2026-10-09）。街区の表を引く番地付きの入力の時間は未計測 |
| 施設を引く | 立ち寄り先の表の列`search_name`（名前の表記の揺れ（全角・半角・大文字・空白・ハイフン・中点）を除いた形。派生の段が`domain/stop_place.py: normalized_sql`で入れる）を、入力を同じ式で整えて部分一致（`strpos`）で引く——「一蘭」で「らーめん一蘭 新宿店」に当てる。整えると空になる入力（中点・ハイフンだけ）は引かない（空の文字列はどの名前にも含まれる）。対象範囲の中だけを、渡された点に近い店から`PLACE_PREDICTION_LIMIT`件まで（並びは下の「並び」）——チェーンの名前は関東に同じ名前の店が100件を超えてあり（「ファミリーマート」は関東の点のタイルの見本 13,615 件のうち125件、2026-10-08）、点に依らずに選ぶと見ている辺りの店が入らない。時間: 合成の40万行（関東の表は約35万行の見込み）で、列を部分一致で引いて並べて10件までが20〜30ms（住所の続きの1回と同じ桁）。引くたびに名前を`normalized_sql`で整えると約730ms、`lower`だけでも約150msかかるので列を持つ。`pg_trgm`の索引は拡張を本番に入れる操作（スーパーユーザー）が要るので使わない（2026-10-08 の測り）。文は接続ごとに準備して使い回されるので、6回目から入力の値を知らない一般の計画になりうる。本番（約34.5万行）では、範囲で絞る形の文が一般の計画で範囲の索引から全行をたどり、入力を行ごとに整え直して1回 650〜2,400ms かかった（個別の計画では 80〜570ms で、多く当たる短い入力ほど、当たった全行に測地の距離を求める分が長い。2026-10-10 の測り）。今の文は、一般の計画でも範囲の索引を選ばず、入力を1回だけ整え、測地の距離を候補に入りうる行にだけ求める（形と、答えが変わらない理由は`infrastructure/stop_place_search.py: _SEARCH_SQL`のコメント） |
| 範囲で絞る | 施設はサービスの対象範囲（取り込んだ道路の範囲、`RegionService.get_ingested_area`）の外を落とす——範囲の外ではルートを作れない。住所は範囲で絞らない（区画の表に入るのは、派生の段が取込の範囲で選んだ区画とその祖先だけ）。対象範囲・住所・施設は同じ接続で読む |
| 並び | 住所 → 施設。施設の中は、名前が入力と同じ → 入力で始まる → 入力を含む、同じ中では渡された点に近い順（測地の距離。度のままの距離は関東の緯度で東西を2割ほど短く数える）。名前の短い順・確からしさの順では並べない——「ファミリーマート王子店」より名前の短い遠くの店が先に出る |

| 失敗 | 応答 |
|---|---|
| 対象範囲を読めない（DB障害・道路を未取込） | 502（風の格子と同じ） |
| 住所・施設の表を読めない（DB障害） | 捕まえない（500）。直前に同じ接続で対象範囲を読めているので起きにくく、片方だけに縮めて返すと、もう片方が無いのと見分けられない |

区画の表が空（住所の生データを取り込んでいない）なら、住所は当たらないだけで失敗にしない——派生の作り直しは`abr`の取込が無ければ
止まる（下の「住所の区画の表」）ので、本番に空の表は出ない。

回数制限は経路ごとの別枠（`place_search_rate_limit_per_minute`。置いた位置の辺りは`place_area_rate_limit_per_minute`）。画面は打つのが止まってから`PLACE_PREDICTION_DELAY_SECONDS`
の間を置いて引くので、打ち続けたときの1分あたりの最大（60秒÷間）を既定の上限にしてある（間から導く）。サーバーでは答えを持たず、ブラウザへは1日持たせる
（`api/cache_policy.py: MASTER_LOOKUP`。置いた位置の辺りも同じ）——答えが変わるのは対象範囲・住所の区画の表・立ち寄り先の表・小地域の境界の生データが変わるときだけ（並べる点はURLに入るので、同じURLの答えは変わらない）。

## 施設の辺り

施設の辺りは、立ち寄り先の派生の段（[静的な道路の属性](static-road-attributes.md)の立ち寄り先）が、入れた地点の位置を含む
小地域の境界の名前から決めて、表の列`area`に入れる。検索のたびには引かない。置いた位置の辺り（`place_area_query.py`）は、
同じ決め方を、要求ごとに渡された位置1つで引く（範囲では絞らない。境界の生データは取込の範囲に掛かる都道府県の分だけで、外の位置は辺りが無い）。

| 項目 | 内容 |
|---|---|
| 生データ | `estat_small_area`は範囲に掛かる都道府県の通常の小地域（`HCODE` 8101）を、小地域のコードごとに1つの多角形で入れる（属性は最も広い1枚の行）。範囲に掛かる都道府県は住所の生データと同じ関数で決める（下の「住所の区画の表」の生データ） |
| 名前 | 位置を含む境界の市区町村名と町丁・字等の名前を、配布の表記のままつないだもの（`place_area_query.py: area_label_sql`。「川口市元郷四丁目」「さいたま市岩槻区本町」「日の出町大字平井」）。配布の市区町村名は郡を含まず、政令市は市と区をつなぐ。丁目は漢数字、大字は「大字」から書く |
| 境界の決め方 | 辺の上の点は、名前を持つ境界のうち鍵の小さいほう。名前を持つ境界に含まれなければ空（海の上・取り込んだ境界の外・名前の無い境界の中） |
| 住所の区画に結ばない | 境界の名前を住所の区画の名前に当てると、頭・お尻の一致で別の町字に取り違えうる（土浦市「荒川沖西区二丁目」→「荒川沖西」）。取り違えは見本を拾っても全件を確かめられず、誤った辺りは空より害が大きいので、境界の名前をそのまま出す |
| 時間 | 境界の取込が関東の範囲で約90秒（開発機、2026-10-09）。段の中で辺りを入れる時間は未計測 |

## 住所の区画の表

アドレス・ベース・レジストリ（生データ`abr`）と街区レベル位置参照情報（生データ`isj_block`）から、派生の作り直しの段
`derive_addresses.py`が作る。地点の検索の住所はこの表から引く（上の「引き方」）。

| 表 | 中身 |
|---|---|
| `address_areas` | 1行1区画（都道府県・市区町村・区・大字/町・丁目/字）。段・1つ粗い区画（`parent_id`）・自分の段の名前・郡の名前（郡の町村だけ）・代表点。表示の全名は持たない |
| `address_search_keys` | 区画を引く鍵（揃えた形、照合順序`C`）と、続きに使う鍵か（大字・町の段まで）。主キー（鍵, 区画）で等号と前方一致を引き、続きの鍵には長さと鍵の部分索引を張る |
| `address_blocks` | 区画（丁目・字か大字・町）の中の街区1つ。主キー（区画, 番号）。番号（住居表示の街区符号か地番。配布の表記のまま、照合順序`C`）・種類（住居表示の街区`residential`か地番`parcel`）・代表点 |

| 決まり | 内容 |
|---|---|
| 生データ | `abr`は1回の取込に都道府県・市区町村（全国）と、範囲に掛かる都道府県の町字と住居表示の街区を入れ、テキストと代表点を1行にする（鍵は全国地方公共団体コードか`<コード>:<町字ID>`か`<コード>:<町字ID>:<街区ID>`。街区の代表点はテキストと同じ住居表示の印の行、無ければ印の小さいほう）。代表点の無い行（小字のほとんど）は入れない。代表点は日本測地系2000・2011から 4326 へ移す。`isj_block`は範囲に掛かる都道府県の配布のうち、代表の点（代表フラグ 1）で削除（更新後履歴フラグ 3）でなく、点が取込の範囲の中の行を、配布の列のまま入れる（鍵は都道府県名から街区符号・地番までの名前）。範囲に掛かる都道府県は、ABR の市区町村の代表点が範囲の中にある都道府県（`source_adapters/abr.py: prefectures_in_range`）で、取得も取込も同じ関数で決める |
| 区画にする行 | 廃止の日の無い行。町字は町字区分が`domain/address_area.py: MACHIAZA_TYPE_LEVELS`にあるもの（町字なし・道路名は区画にしない）。ABR に大字自身の行が無い大字は、子の町字IDの頭4桁でまとめ、子の代表点の重心に置く |
| 範囲 | 代表点が道路の取込の範囲（`road_graph_repository.py: INGESTED_BBOX_SQL`）の中にある区画と、その祖先（祖先の代表点は範囲の外でもよい） |
| 鍵 | 書き始める段（都道府県・郡・市区町村・区・大字）ごとの形と、都道府県から書いて郡を省いた形。丁目は区切り付き（「西新宿2-」）、字は「字」を挟む形と挟まない形（`domain/address_area.py: search_keys`） |
| 揃え方 | `domain/address_area.py: standardize_address`（NFKC・小文字・空白 → ハイフンと長音の類 → 漢数字 → 数字の後の丁目 → 「大字」 → 「ケ」「ノ」の類の順）。打った入力と鍵の両方にかける。ハイフンの類の集合は施設の名前の揃え方（`domain/stop_place.py: normalized_sql`）と共有する |
| 街区 | 住居表示の区域は、ABR の街区（廃止の日の無い行）を町字の鍵（`<コード>`＋`<町字ID>`）でそのまま区画に結ぶ（区画にしない町字の街区は入らない）。それ以外の区域は、位置参照情報の住居表示でない行を、市区町村名（郡・政令市の区を含む書き方。区画の表の市区町村・郡・政令市から同じ形を作る）で市区町村に当て、その中で大字・丁目名＋小字・通称名（字の「字」を除いて揃えた形。括弧の中——大字の無い行の「（大字なし）」——も除く）が区画（大字＋丁目・字）と同じ → 頭に当たる最も長い区画 → お尻に当たる最も長い区画（どちらも2文字以上）の順で区画に結ぶ。区画にしない小字の地番は大字に寄り、同じ区画の同じ番号は1つ（小字の名前の小さい行）。ABR の街区を1つでも持つ区画（住居表示の区域）には地番を入れない |
| 生データが無いとき | `abr`の取込が無ければ段が止まり、作り直し全体が何も入れ替えない。位置参照情報の取込が無ければ地番は空 |
| 時間 | 関東の範囲で、取込が`abr`約30秒、段が約35秒（区画 約3.8万・鍵 約12.5万。開発機、2026-10-09）。街区・地番を足したあとの取込と段の時間は未計測 |

Overture の地点を取り込んで立ち寄り先の派生の段を本物のまま流して作る。住所の区画の表は、配布の形の小さな見本（ABR の CSV の zip・
