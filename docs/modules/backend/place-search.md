# 地点の検索（backend）

## 責務

入力した文字列から、出発地・経由地・目的地にできる地点の候補を返す（`GET /api/place-search?q=&latitude=&longitude=`。緯度経度は
画面が見ている所の真ん中で、施設を近い順に並べる点）。打ちかけの入力にも
同じ口で答え、入力の続き（入力を頭に持つ住所）を候補に足す——検索のボタンと打ちかけで同じ一覧・同じ回数制限になる。
候補は**種類**（何から引いたか。住所か施設）・**当たった段**（住所ならどこまで細かく当たったか。施設は施設そのものの点）・
表示名・位置を持つ。住所は配布の住所の辞書（`jageocoder`用、街区まで・全国）を本番のbackendの手元で引き、施設は立ち寄り先の
表（`stop_places`。[静的な道路の属性](static-road-attributes.md)の立ち寄り先）を名前で引く。**外部の検索サービスや別の
サーバーへ問い合わせる経路は持たない**。

**対象ファイル**

| レイヤー | ファイル |
|---|---|
| domain | `place_search.py`（種類・段の語彙と表示名、候補と答えの形、入力の整え方、続きを足す最短の長さと件数（施設の件数も同じ）・画面が打ちかけで引くまでの間、住所の辞書の配布の版と出典の文言、住所の区画の元データの出典の文言）・`address_area.py`（住所の区画の段の語彙・続きに使う段・町字区分と段の対応、表記の揃え方、区画の名前から鍵を作る形。下の「住所の区画の表」） |
| batch | `derive_addresses.py`（住所の区画・鍵・小地域の境界の結び付きを作る派生の段）・`source_adapters/abr.py`（アドレス・ベース・レジストリの配布の zip を読む。テキストと代表点を1行に合わせ、代表点の無い行を落とす。範囲に掛かる都道府県の決め方も持つ）・`source_adapters/estat_small_area.py`（e-Stat の小地域の境界の Shapefile の zip を読む。分かれた多角形を小地域のコードごとに1つにし、通常の小地域でない行を落とす） |
| infrastructure | `address_dictionary.py`（辞書の置き場、辞書を開いて引き候補へ写す。段の写し、旧い行政区画の節の置き換え、入力の続きの引き方、対象範囲の外の候補を落とす。入力の全部に当たった住所と一部にだけ当たった住所を分けて返す。位置を逆引きした辺り（立ち寄り先の派生の段が呼ぶ。下の「施設の辺り」））・`stop_place_search.py`（立ち寄り先の表を名前で引いて点に近い順に並べ、施設の候補へ写す） |
| services | `place_search_service.py`（対象範囲と施設（渡された点に近い順）を同じ接続で読み、入力を整えて辞書を範囲の中で引き、住所と施設を並べる） |
| api | `routers/place_search.py`（回数制限と、辞書が無い・範囲を読めないときの応答） |
| scripts | `fetch_address_dictionary.py`（辞書を配布元から取り、引けることを確かめてから置き場へ入れる。デプロイが呼ぶ）・`fetch_abr.py`（アドレス・ベース・レジストリの全国の1ファイルずつと、範囲に掛かる都道府県の町字の代表点を取る）・`fetch_estat_small_areas.py`（範囲に掛かる都道府県の e-Stat の小地域の境界を取る） |

## 候補の形

| 項目 | 内容 |
|---|---|
| 種類（`PlaceKind`） | `address`（住所）・`facility`（施設）。種類を足すときは語彙と表示名の表（`PLACE_KIND_LABELS`）へ1つずつ足し、口と答えの形は変えない |
| 当たった段（`PlaceMatchLevel`） | 住所は辞書の段（`jageocoder.address.AddressLevel`の1〜8）をそのまま名前にしたもの（都道府県・郡・市区町村・区・大字/町・字/丁目・街区/地番・号）。街区までの辞書は号を返さない。施設は`point`（地点。施設そのものの点で、範囲の代表点ではない） |
| 表示名 | 住所は都道府県から当たった段までの名前をつないだもの（「東京都新宿区西新宿二丁目8番」）。施設は表の名前（「浅草寺」） |
| 辺り | 施設だけが持つ、施設の位置の市区町村から字・丁目までの名前（「川口市元郷四丁目」）。同じ名前のチェーンの店を見分ける。表の列`area`をそのまま出し、列が空の行（下の「施設の辺り」）と住所は持たない |
| 位置 | 住所は当たった段の代表点（街区なら街区の代表点）で、入口や建物の位置ではない。施設は表の位置（Overture の地点・寺社の建物） |

種類と段の表示名は、語彙と同じ並びで生成物`vocabulary.ts`（`placeKinds`・`placeMatchLevels`）が画面へ届ける。

## 引き方

| 段 | 内容 |
|---|---|
| 入力を整える | 空白（全角も）を除く。辞書は空白を語の区切りとして読まず、空白から先に当たらない |
| 辞書を引く | 1回の検索ごとにスレッドで辞書を開いて引く。辞書のsqliteの接続は開いたスレッドでしか使えないため、開いた辞書を持ち越さない（開くのは1ms前後） |
| 当たらない入力 | 辞書は何も当たらない入力にも、当たった文字列が空の結果を1件返す。これは候補にしない |
| 旧い行政区画 | 辞書は合併で無くなった市の住所も旧い名前で引けるよう持ち、当たりがその節で終わると旧い名前のまま返す。その節は注記（`ref:`）が指す今の住所の節へ置き換え、同じ節が2度出たら1件にする。行き先が大字の無い区域（名前の無い大字の節。`ref:`では`<市区町村>.`）なら、その市区町村にする。市区町村の段までの節は歴史的行政区域データセットの名前の1件ずつから作られ、廃止の日を持たず、今は無い区画（東京府渋谷区・千葉県東葛飾郡柏町等）も`ref:`無しで今の区画と並ぶので、今の区画にだけ付くもの（郵便番号か、今の住所だけを持つデータセットの子の節か、郵便番号を持つ子の節）の無い節は落とす。政令市・郡・都道府県は郵便番号を持たず子が持ち、郵便番号の無い島の村は子の大字が今の住所のデータから来る |
| 入力の続き | 辞書の索引（標準化した表記の`marisa_trie`のトライ。大字の段まで）から、入力を標準化した表記を頭に持つ表記を前方一致で引き（`jageocoder`の`AddressTrie.predict_prefixes`と同じ引き方）、表記から節への表で節へ引く。短い表記から（同じ長さなら粗い段から）、範囲の中の節を`PLACE_PREDICTION_LIMIT`件まで足す——同じ長さを文字の順に並べると、1文字の入力（「柏」）で同じ長さの大字（「柏下」「柏井」…）が市区町村（「柏市」）より先に上限を埋める。段は節を読むだけで分かるので先に並べ、旧い行政区画の置き換え（辞書の検索で、高くつく）は上限に達するまでだけ行う。丁目より先は索引に無いので、丁目・街区まで打った入力には続きが無い。空白を除いて`PLACE_PREDICTION_MIN_LENGTH`（1）文字から足す——1文字は続きの表記が全国で1万を超えるが、見る節の数を区切るので本物の辞書で1回 10〜40ms ほどに収まり、「柏」で柏市のような1文字の地名から選べる（2026-10-08 にユーザーが求めた）。範囲の外ばかりに当たる語でも時間を抑えるため、見る節の数を区切る（`_PREDICTION_SCAN_LIMIT`）。索引は位置を持たない節（同じ市区町村の別の節等）も指すので、辞書の検索と同じく子の位置を借り、借りられない節は候補にしない（位置を持つ同じ住所の節が別にある） |
| 施設を引く | 立ち寄り先の表の列`search_name`（名前の表記の揺れ（全角・半角・大文字・空白・ハイフン・中点）を除いた形。派生の段が`domain/stop_place.py: normalized_sql`で入れる）を、入力を同じ式で整えて部分一致（`strpos`）で引く——「一蘭」で「らーめん一蘭 新宿店」に当てる。整えると空になる入力（中点・ハイフンだけ）は引かない（空の文字列はどの名前にも含まれる）。対象範囲の中だけを、渡された点に近い店から`PLACE_PREDICTION_LIMIT`件まで（並びは下の「並び」）——チェーンの名前は関東に同じ名前の店が100件を超えてあり（「ファミリーマート」は関東の点のタイルの見本 13,615 件のうち125件、2026-10-08）、点に依らずに選ぶと見ている辺りの店が入らない。時間: 合成の40万行（関東の表は約35万行の見込み）で、列を部分一致で引いて並べて10件までが20〜30ms（住所の続きの1回と同じ桁）。引くたびに名前を`normalized_sql`で整えると約730ms、`lower`だけでも約150msかかるので列を持つ。`pg_trgm`の索引は拡張を本番に入れる操作（スーパーユーザー）が要るので使わない（2026-10-08 の測り） |
| 範囲で絞る | サービスの対象範囲（取り込んだ道路の範囲、`RegionService.get_ingested_area`）の外の候補を落とす——範囲の外ではルートを作れない。辞書は全国を持つ。関東の外の方が入力の長い部分に当たるときは、関東の候補が辞書の答えに入らない。続きは範囲で絞りながら引くので、対象範囲は辞書を引く前に読む。施設は対象範囲を読んだのと同じ接続で引き、接続を返してから辞書を引く（辞書を引く間にDBの接続を持たない） |
| 並び | 入力の全部に当たった住所（続きを含む）→ 施設 → 入力の一部にだけ当たった住所——「小杉湯」で、施設の小杉湯が、入力の一部の「小杉」に当たった住所より先に出る。住所の中は、入力のより長い部分に当たったものが先（辞書の並び）で、続きは入力の全部に当たった住所の後に並ぶ。同じ節は1件にする。施設の中は、名前が入力と同じ → 入力で始まる → 入力を含む、同じ中では渡された点に近い順（測地の距離。度のままの距離は関東の緯度で東西を2割ほど短く数える）。名前の短い順・確からしさの順では並べない——「ファミリーマート王子店」より名前の短い遠くの店が先に出る |

| 失敗 | 応答 |
|---|---|
| 辞書を開けない（置き場に今の版が無い） | 503。起動は止めず、この口だけが使えない。引くたびに抑制付きのWARNINGを出す |
| 対象範囲を読めない（DB障害・道路を未取込） | 502（風の格子と同じ） |
| 施設の表を読めない（DB障害） | 捕まえない（500）。直前に同じ接続で対象範囲を読めているので起きにくく、住所だけに縮めて返すと施設が無いのと見分けられない |

回数制限は経路ごとの別枠（`place_search_rate_limit_per_minute`）。画面は打つのが止まってから`PLACE_PREDICTION_DELAY_SECONDS`
の間を置いて引くので、打ち続けたときの1分あたりの最大（60秒÷間）を既定の上限にしてある（間から導く）。1件は手元の辞書を
引くだけ（数ms〜200ms前後）と、施設の表を引くだけ（数十ms）。サーバーでは答えを持たず、ブラウザへは1日持たせる
（`api/cache_policy.py: MASTER_LOOKUP`）——答えが変わるのは辞書の版・対象範囲・立ち寄り先の表が変わるときだけ（並べる点はURLに入るので、同じURLの答えは変わらない）。

辞書を開くたびに`jageocoder`が出す異体字の表の知らせ（配布の辞書はどの版もその表を持たない）は、`main.py`がロガー
`jageocoder.itaiji`のレベルを上げて抑える。

## 施設の辺り

施設の辺りは、立ち寄り先の派生の段（[静的な道路の属性](static-road-attributes.md)の立ち寄り先）が、入れた地点の位置を
住所の辞書で逆引きして表の列`area`に入れる（`address_dictionary.py: areas`）。検索のたびには引かない。

| 項目 | 内容 |
|---|---|
| 引き方 | `jageocoder`の逆引き（`reverse`）を字・丁目の段までで引き、返った節（囲む三角形の頂点の最大3つ）から旧い住所の節（出どころが住所変更履歴。合併で無くなった市の住所等で、今の住所の節と並んで当たり、今の住所の節より近いこともある）を除いて、最も近い節を採る。名前は市区町村から先をつなぐ（都道府県・郡は持たない。政令市は市と区をつなぐ）。名前の無い大字の節（大字の無い区域）は市区町村まで。採れる節が無ければ空 |
| 逆引きの索引 | 逆引きは辞書の置き場の索引（`rtree.dat`・`rtree.idx`）を読み、無ければ最初の1回が作って置き場へ書く（全国の辞書で約5分・約240MB）。索引を開くには置き場を書けなければならず、引くたびにも索引のファイルへ書き戻す（`rtree`の`Index`が置き場の書き込みの可否を見て、閉じるときに見出しを書く）。backendは置き場を読むだけでマウントするので逆引きせず、派生の段だけが書けるマウントで引く（[deployment-sync.md](../../conventions/deployment-sync.md)「派生データの作り直し」） |
| 時間 | 1点で約2ms（全国の辞書、関東の無作為の点の中央値） |
| 地点が無いとき | 辞書を開かない（地点を取り込んでいないDBの作り直しに、辞書は要らない） |

## 辞書の置き場と版

| 項目 | 内容 |
|---|---|
| 配布元の版 | `domain/place_search.py: ADDRESS_DICTIONARY_URL`（配布の版ごとのzip。ファイル名が版を表す）。出典の文言`ADDRESS_DICTIONARY_ATTRIBUTION`も同じ所に並べ、常時の出典（`domain/map_display.py: ALWAYS_SHOWN_ATTRIBUTIONS`）が読む |
| 置き場 | `backend/address_dictionary/<版の名前>/`（本番はホスト側のディレクトリを、backendは読むだけで、派生の作り直しは逆引きの索引を書くので書けるようにマウントする）。zipに同梱のREADME（利用条件）も同じ所に入る |
| 作る時機 | `scripts/fetch_address_dictionary.py`（デプロイがコンテナを入れ替える前に毎回呼ぶ）。置き場に今の版があれば他の版を消すだけ。無ければzipを取り、一時の置き場へ入れ、1件引けることを確かめてから置き場の名前へ移し、zipを消す。引けなければ置き場を作らずに失敗で終わる。入れた回は他の版を消さない——入れ替えまで旧いコンテナが旧い版を検索のたびに開く |
| 版と読めるライブラリ | 辞書の版ごとに読める`jageocoder`の版が決まっている（docs/architecture/tech-stack.md「`jageocoder`は辞書の版が読める版に留める」） |

版の上げ方と頻度は docs/architecture/data-sources.md「版を持つ配布物の入れ替え」が持つ。

## 住所の区画の表

アドレス・ベース・レジストリ（生データ`abr`）と e-Stat の小地域の境界（生データ`estat_small_area`）から、派生の作り直しの段
`derive_addresses.py`（立ち寄り先の段の前）が作る。今の検索と施設の辺りはこの表を読まず、住所の辞書から引く。

| 表 | 中身 |
|---|---|
| `address_areas` | 1行1区画（都道府県・市区町村・区・大字/町・丁目/字）。段・1つ粗い区画（`parent_id`）・自分の段の名前・郡の名前（郡の町村だけ）・代表点。表示の全名は持たない |
| `address_search_keys` | 区画を引く鍵（揃えた形、照合順序`C`）と、続きに使う鍵か（大字・町の段まで）。主キー（鍵, 区画）で等号と前方一致を引き、続きの鍵には長さと鍵の部分索引を張る |
| `address_boundary_links` | 小地域の境界（生データの鍵）1つに当たる大字・町か丁目・字。境界の多角形は生データに置いたまま |

| 決まり | 内容 |
|---|---|
| 生データ | `abr`は1回の取込に都道府県・市区町村（全国）と、範囲に掛かる都道府県の町字を入れ、テキストと代表点を1行にする（鍵は全国地方公共団体コードか`<コード>:<町字ID>`）。代表点の無い行（小字のほとんど）は入れない。代表点は日本測地系2000・2011から 4326 へ移す。`estat_small_area`は範囲に掛かる都道府県の通常の小地域（`HCODE` 8101）を、小地域のコードごとに1つの多角形で入れる。範囲に掛かる都道府県は、ABR の市区町村の代表点が範囲の中にある都道府県（`source_adapters/abr.py: prefectures_in_range`）で、取得も取込も同じ関数で決める |
| 区画にする行 | 廃止の日の無い行。町字は町字区分が`domain/address_area.py: MACHIAZA_TYPE_LEVELS`にあるもの（町字なし・道路名は区画にしない）。ABR に大字自身の行が無い大字は、子の町字IDの頭4桁でまとめ、子の代表点の重心に置く |
| 範囲 | 代表点が道路の取込の範囲（`road_graph_repository.py: INGESTED_BBOX_SQL`）の中にある区画と、その祖先（祖先の代表点は範囲の外でもよい） |
| 鍵 | 書き始める段（都道府県・郡・市区町村・区・大字）ごとの形と、都道府県から書いて郡を省いた形。丁目は区切り付き（「西新宿2-」）、字は「字」を挟む形と挟まない形（`domain/address_area.py: search_keys`） |
| 揃え方 | `domain/address_area.py: standardize_address`（NFKC・小文字・空白 → ハイフンと長音の類 → 漢数字 → 数字の後の丁目 → 「大字」 → 「ケ」「ノ」の類の順）。打った入力と鍵の両方にかける。ハイフンの類の集合は施設の名前の揃え方（`domain/stop_place.py: normalized_sql`）と共有する |
| 境界の結び付け | 同じ市区町村の中で、名前（字の「字」を除いて揃えた形）が区画（大字＋丁目・字）と同じ → 頭に当たる最も長い区画 → お尻に当たる最も長い区画（どちらも2文字以上）→ 中に代表点がある区画（丁目・字を先に）。どれにも当たらない境界は行にしない |
| 生データが無いとき | `abr`の取込が無ければ段が止まり、作り直し全体が何も入れ替えない。境界の取込が無ければ結び付きは空 |
| 時間 | 関東の範囲で、取込が`abr`約30秒・境界約90秒、段が約35秒（区画 約3.8万・鍵 約12.5万。開発機、2026-10-09） |

テストは配布の辞書を置けないため、`jageocoder`の公開の型で数件の節だけの辞書を書き（`tests/address_dictionary_fixture.py`）、
検索は本物を通す。施設は Overture の地点を取り込んで立ち寄り先の派生の段を本物のまま流して作る（`tests/test_place_search_route.py`）。
住所の区画の表は、配布の形の小さな見本（ABR の CSV の zip・e-Stat の Shapefile の zip）を置き場に書き、取込と派生の段を本物のまま
流して作る（`tests/test_address_areas.py`）。
