# T804. 走行モデル・ターン・停止の暫定値を管理画面から変えられるようにする

規模M〜L。
状態: 未着手（2026-09-13起票。[T799](T799.md)の作業中にユーザー要望
「Pはじめ、ここまであまり根拠なく決めてきた値を管理画面から変更できるようにして」）

## 背景

[T790](T790.md)〜T799で入れた探索のコストモデルには、**実測ではなく実感に合わせて置いた値**が
多数ある。どれもコードの定数で、変えるにはデプロイが要る。較正は実走してみないと決まらない
性質のため、デプロイなしで回せないと収束しない。

評価軸（`axis_definitions`）は既に軸スタジオ（/admin）からDB経由で変えられる。同じ器に
載せられないか、という話。

## 対象の値（着手時に棚卸しする。以下は起票時点で分かっているもの）

| 置き場所 | 値 | 根拠 |
|---|---|---|
| `domain/evaluation.py` | `DEFAULT_PENALTY_STRENGTH`（主観と時間の換算レート） | 本番実測で釣り合いを見た暫定 |
| `domain/routing.py: TurnCostSpec` | 左折・右折・Uターン・直進とみなす方位差・上位道路の横断/右左折の秒 | 方位差だけの暫定値 |
| `domain/traffic.py: STOP_SECONDS` | 信号・一時停止・踏切・車止めの秒 | 一般的な信号サイクルからの見積もり |
| `domain/cycling_speed.py` | `CLIMB_POWER_PER_GRADE`・`MAX_CLIMB_POWER_RATIO`・`UNPAVED_CRR`・`MAX_DESCENT_SPEED_KMH`・`WALKING_SPEED_KMH`・`DEFAULT_CDA_M2`・`DEFAULT_CRR`・`DEFAULT_MASS_KG` | いずれも実感合わせの暫定（各定数のコメントに明記） |
| `services/road_graph_engine.py` | `RETRACE_PENALTY_MULTIPLIER`・`TIME_BIN_HOURS`・`MAX_TIME_BINS`・`ALTERNATIVE_MAX_STRETCH`・重複率のしきい値 | 設計上の選択と実測の混在 |

## 論点（着手前に決める）

- **どこまで載せるか**。「較正値（走ってみて決める）」と「設計上の選択（変えると挙動の
  性質が変わる）」は別物で、後者を画面から触れるようにすると壊し方が増える。例えば
  `TIME_BIN_HOURS`は風の予報の刻みから決まっており、自由に変えるものではない
- **キャッシュとの関係**。`TurnCostSpec`は`TurnExpandedStructure`のキャッシュキーに入って
  いるため変更が自然に効く。一方`STOP_SECONDS`や走行モデルの定数はコスト配列の合成時に
  読むだけで、キャッシュ鍵には入っていない（`cache_identity.py`の管理対象外）——DB化した
  ときに古い値のキャッシュが残らないかを確認する
- **器の形**。`axis_definitions`と同じテーブル方式か、単一行の設定テーブルか、
  `axis_registry_meta`のような版管理を持つか。軸と同じく「起動時に読み込んでプロセス内へ
  持つ＋変更時にrefresh」の経路（`refresh_axis_definitions`）へ相乗りできるか
- **権限と事故**。/adminはBasic認証済み（[T272](T272.md)）。値の範囲チェックをどこに置くか
  （`axis_admin`は「極端な重みへの意味的な歯止めは設けない」方針）
