# T493: ルート設定パネルの重み配分をポップオーバー方式へ再設計、除外道路の並び順修正

## 状態

完了(2026-08-31)

## 背景

T492で風・勾配のコンパスをルート設定パネル内へ移設した直後、ユーザーから3件の
実機フィードバックがあった。

1. 「除外する道路」セクションが「重み配分」より上にあるのは順序として不自然
2. 重み配分の各要素設定（スライダー）がスクロールを圧迫している、もっとスマートな
   入力方式にできないか
3. T492で追加したコンパスが常時行内に表示されるようになった結果、コンパスの
   表示領域（`WindBearingSlider`の`.panel`が持つ`touch-action: none`）がリストの
   スクロールジェスチャーを奪ってしまい、「コンパス部分のエリアはすべてコンパスが
   移動してしまう」状態になっていた

2と3は根っこが同じ問題（ドラッグ操作用のUI要素が常時スクロール可能なリスト行の中に
居座っている）と判断し、まとめて対応した。

## 対応方針（2と3、ユーザー選択）

重み配分・コンパスの入力方式について、AskUserQuestionで4案を提示しユーザーが
「タップで詳細を開くポップオーバー方式」を選択した。他の案（数値ステッパー化・
3段階ボタン化・スライダー維持+縮小のみ）は不採用。

採用した設計: 各軸の行を「チェックボックス・ラベル・現在値ボタン・色分けチップ」
だけの常時1行表示に圧縮する。重みスライダー・向きコンパスは、現在値ボタンをタップ
すると開くRadix Popover（`Popover.Portal`でdocument.body直下に描画、`FieldLabel`の
説明ポップオーバーと同じパターン）の中へ格納する。ポップオーバーは非表示中はDOMに
存在しないため、常時表示のリストにドラッグ系UI（スライダー・コンパスとも
`touch-action`を必要とする）が一切存在しなくなり、3のスクロール奪取問題は
ポップオーバー化の副次効果として構造的に解消した。

## 実装

- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.tsx`:
  - 「除外する道路」の`Disclosure`ブロックを「重み配分」`.group`の後ろへ移動。
  - 各軸行から`<input type="range">`・`{renderBearingControl(axis)}`を撤去し、
    現在値を表示する`Popover.Trigger`ボタン（`weightValueTrigger`）に置き換え。
    `Popover.Content`（`weightDetailPopover`）の中にスライダーと
    `renderBearingControl(axis)`を移した。`renderBearingControl`自体は変更なし
    （呼び出し位置のみ変更）。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.module.css`:
  - `.row`をT435由来の2段CSS Grid（`grid-template-areas`）から、スライダー用の
    可変幅列を確保する必要が無くなったため単純なflexへ戻した。
  - `.slider`/`.weightValue`を`.weightValueTrigger`/`.weightDetailPopover`/
    `.detailSlider`へ置き換え。`.bearingRow`は行インデント用の`padding-left`を
    撤去し、ポップオーバー内区切り用の`border-top`へ変更。
  - モバイル用`@media (max-width: 640px)`ブロックを大幅縮小
    （T489由来のスライダー開始位置揃え用`.rowLabel`固定幅指定・`.slider`/
    `.weightValue`の調整を削除。スライダーが常時表示で無くなったため不要）。
    チェックボックスサイズ・色分けチップサイズの縮小ルールは維持。

## 検証結果

- `npx vitest run src/components/RouteSettingsPanel/ src/components/WindBearingSlider/ --pool=threads`:
  3ファイル23件全て成功（スライダーが常時DOMに存在しない前提のテストは元々無く、
  既存テストへの影響は無かった）。
- `npx tsc --noEmit`: エラーなし。
- Browserペインで実機確認:
  - デスクトップ幅: 現在値ボタンをタップするとスライダーが浮遊表示され、勾配の
    「色分け」をONにした状態で開くとコンパスも一緒に表示されることを確認。
  - モバイル幅(375x812)、BottomSheet展開中: 除外する道路が重み配分の下に来たこと、
    重み配分8軸すべてが1画面（スクロール無し）に収まったこと、現在値ボタンで
    ポップオーバーが正しく開閉すること、ポップオーバーを閉じた状態でリスト全体を
    指でスクロールしてもコンパス領域に引っかからないことを確認。

## 残課題

- T492からの既知の残課題（`windBearingDeg`/`gradientBearingDeg`の軸id別state技術的
  負債[T483参照]、方角設定UIのタッチ操作性そのものへの懸念）は本タスクでも未着手
  のまま。ポップオーバー化によりコンパスの表示領域自体は縮小したが、
  `WindBearingSlider`の内部実装（`@fseehawer/react-circular-slider`のドラッグ処理）は
  変更していない。
