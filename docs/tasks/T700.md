# T700. 軸スタジオのバリデータ非対称を是正する（GUI操作で全ルート生成が500になりうる） 規模S

状態: 未着手（2026-09-10起票、統合レビュー第6回 I-7）

## 背景

`app/api/routers/axis_admin.py:206-229`の
`_check_dynamic_and_static_materials_are_not_mixed`は`self.shape.terms`しか見ず、
冒頭の`if not isinstance(self.shape, BreakpointLinearShape): return self`で
`CategoricalShape`を素通しする。

一方、その軸が動的軸と判定されるかは`_axes_depending_on_materials`
（`app/domain/axis_definitions.py:537`）が`definition.materials`を根拠にし、
その`materials`プロパティ（同`:268-283`）は
**`priority_overrides`が参照する材料も含む**とdocstringで明記している。

`evaluate_dynamic_axis_arrays`（`app/domain/dynamic_materials.py:122-137`）が渡す辞書は
「タイル単位でキャッシュ済みの静的軸スコア＋動的材料」だけで静的材料の配列を含まないため、
`evaluate_axis_array`の`values = materials[override.material]`
（`axis_definitions.py:762`）がKeyErrorになる。

つまり「`shape.terms=[wind_drag_ratio]`、
`priority_overrides=[{material:"motor_vehicle_no", equals:"true", value:0}]`」の軸を
軸スタジオのGUIから保存でき、以後`/api/routes/generate`が**全リクエスト500**になる。
バリデータのdocstring自身が「GUI操作だけで全ルート生成が落ちる」ことを防ぐ目的だと述べている。

## 対応方針

判定を`self.shape.terms`ではなく`AxisDefinition.materials`と同じ導出
（terms＋priority_overrides、shape種別を問わない）へ揃える。

`backend/tests/test_axis_admin_routes.py:189`もterms経由の混在しか検証していないため、
`priority_overrides`経由・`CategoricalShape`のケースを追加する。

## 併せて塞ぐ（同じファイルの兄弟エンドポイント）

新設された2つの管理エンドポイント
（`POST /api/admin/axis-definitions/preview-distribution`・
`GET /api/admin/material-catalog/{material_id}/distribution`）にテストが1件も無い。
既存エンドポイントは全件について「認可なしは401」「DBエラーは503」を対で持っている。
また`api/routers/material_catalog.py:151-172`の`get_material_distribution`だけ
DBAPIError→503変換を持たず、migration 0036未適用の環境で素の500になる
（双子の`preview_axis_distribution`は`_guard_db_errors`を通している）。
