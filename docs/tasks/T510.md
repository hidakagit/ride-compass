# T510: JMA動的タイルの429対策（レート制限順序修正＋Redisキャッシュ＋定期プリウォーム）

状態: 着手中（2026-08-31）

- 背景: ユーザー報告「地図を頻繁に動かすと429が出る（`/api/jma-tile/...`）」。
  調査の結果、`enforce_rate_limit`がキャッシュ参照より先に呼ばれておりキャッシュ
  ヒットでもレート制限を消費していたことが直接原因と判明。あわせて「動的データは
  どこまでRedisか」の調査・設計検討を実施（詳細はPlan承認済みの設計を参照、後日
  このファイルへ追記）。
- 対応方針の要点: (1) キャッシュヒットをレート制限のカウント対象外にする、
  (2) タイル本体のキャッシュ先をファイルからRedisへ移す、(3) アメダスと同じ
  APSchedulerパターンで対象範囲（WIND_GRID_BBOX相当・各レイヤーの自前maxzoom）を
  定期プリウォームする。floodレイヤーの`maxzoom`を14→11へ下げ他レイヤーと揃える
  （ユーザー了承済みのトレードオフ）。
- 詳細な設計判断・タイル数試算・Redis想定消費メモリ等は実装完了後にこのファイルへ
  追記する。
