# T777. フルスイートでのみ落ちるテスト（テスト間で共有されるprocess.env） 規模S

状態: 完了（2026-09-12起票・完了）

## 背景

[T776](T776.md)の最終検証で`npx vitest run`（フルスイート）を回した1回だけ、
`src/components/Map/thunderNowcast.test.ts`の3件が落ちた。同じ作業ツリーでそのファイル単体を
回すと9件green、フルスイートを回し直すと全件green。落ちたのはすべてタイルURL文字列の
完全一致アサーションだった。

## 機序（特定済み）

frontendのvitestは`pool: "vmThreads"`で走り、**`process.env`はテストファイルをまたいで
共有される**。`tileBaseUrl()`は`process.env.NEXT_PUBLIC_TILE_BASE_URL`を呼び出しのたびに読み
（SSRで`window`を参照しないための意図的な設計）、`jmaProxyUrl`経由でJMAのタイルURLに載る。
一方`jmaNowcastFrames.test.ts`と`regionApi.test.ts`がこの環境変数を立てていた。立っている間に
別ファイルがURLを組み立てると、期待値と実際が食い違う。

同じ性質がもう1件あった。`proxy.test.ts`・`adminApiProxy.test.ts`は
`process.env = { ...ORIGINAL_ENV }`で**`process.env`ごと差し替えて**おり、これは他ファイルの
`vi.stubEnv`の復元も壊す（本タスクの調査中、移設先の`tileBaseUrl.test.ts`が自分で立てた値を
`vi.unstubAllEnvs()`後も引きずる形で再現した）。

## 影響範囲（実測）

漏れている状態を外から再現する（`NEXT_PUBLIC_TILE_BASE_URL=... npx vitest run`）と、
**5ファイル14件**が落ちた——`thunderNowcast`3件・`riskMap`5件・`precipitationNowcast`2件・
`regionApi`3件・`lidenLayer`1件。報告された3件はこの部分集合。
`ADMIN_BASIC_AUTH_*`・`RENDER_GIT_COMMIT`を同じ手順で漏らした場合は0件（各テストが
`beforeEach`で自分の状態を作り直すため、外から与えた値では落ちない）。

## 対応

**環境変数を読む処理から判断を外へ出す**。`tileBaseUrl`・管理画面のBasic認証のいずれも、
分岐を持つ部分を引数だけで決まる純関数（`resolveTileBaseUrl`・`resolveAdminBasicAuth`）へ分け、
環境変数を読むのは分岐の無い薄い関数だけにした。テストは純関数を直接呼ぶため`process.env`に
触らない。値を**使う側**のテスト（URLの組み立て、認証の成否）は読み取り口のモジュールを
`vi.mock`で固定する。

Basic認証は`proxy.ts`と`adminApiProxy.ts`が同じ2変数を別々に読んでいたため、
`lib/adminBasicAuth.ts`へ集約した（重複の解消も兼ねる）。

**検知器**: `scripts/review_checks.py`の`cross_file_env_writes`が、テストが書き換える環境変数を
そのテスト自身の対象以外の実装も読んでいる場合と、`process.env`ごとの差し替えを検出する。
pre-commit・CI・全件の3経路へ配線した。自分のテスト対象だけが読む環境変数は対象外
（`app/api/version/route.test.ts`の`RENDER_GIT_COMMIT`が該当し、上の実測でも0件だった）。

方針はdocs/testing.md「パターン7」に置いた。

## 検証結果

- 漏れを外から再現するハーネス（`NEXT_PUBLIC_TILE_BASE_URL=... npx vitest run`）で、
  修正前14件failure → 修正後0件。
- 移設先が既知の挙動を今も検知することを変異で確認した: 末尾スラッシュ除去をやめる→1件、
  環境変数を無視する→2件、オリジン無しのフォールバックを変える→1件。
  `resolveAdminBasicAuth`も片方のみ設定・両方未設定を個別に検証している。
- 検知器の実効性: `thunderNowcast.test.ts`へ当時と同じ書き換えを1行足すと2件検知
  （変数名指定と`process.env`ごとの差し替え）、戻すと0件。
- フルスイートを3回連続でgreen（137ファイル1280件）。
