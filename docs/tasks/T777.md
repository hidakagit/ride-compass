# T777. thunderNowcastのテストがフルスイートでのみ落ちることがある 規模S

状態: 未着手（2026-09-12起票）

## 背景

[T776](T776.md)の最終検証で`npx vitest run`（フルスイート）を回した1回だけ、
`src/components/Map/thunderNowcast.test.ts`の3件が落ちた。同じ作業ツリーで
そのファイル単体（`npx vitest run src/components/Map/thunderNowcast.test.ts`）を回すと
9件green、続けてフルスイートを回し直すと1279件green。落ちたのは「liden-onlyの
最新エントリから直近のthns/trnsまで遡る」系と`thunderRenderPayload`/
`tornadoRenderPayload`のペイロード検証。

このタスクの変更はこのファイルに触れていない（`RouteAxisProfile`周辺のみ）。

## 保留することで何が起きうる

同じ非決定性はCIでも出る。CIが赤くなったときに「無関係なテストのflake」として扱われる
状態が続き、**本物の退行を隠す**。落ち方が再現しないため、まず何が実行順に依存して
いるか（fetchモックの共有・モジュール状態・vitestのファイル並列）を特定する必要がある。

## 調べること

- 落ちた3件が共有している前提（同じfetchモック・同じフレーム解決経路）を洗い出す
- `vitest run --sequence.shuffle`等で順序依存を再現できるか
- 再現したら、テスト側の独立性（モックのリセット漏れ）か実装側のモジュール状態かを切り分ける
