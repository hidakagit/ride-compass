# T577: 材料ごとの欠損割合を管理画面で可視化する

## 背景

2026-09-04、[T552](T552.md)対応方針4（surface_q軸の取込側既定値補完の要否判断）の
検討中に、材料`surface`（OSMのsurfaceタグ）が本番DB全体で85.0%欠損していることが
判明した。同じ調査で`elevation_attributes`（gradient軸の材料元）も88.4%欠損して
いたが、こちらは⑦precompute_elevation_attributesの未完走という運用上の問題
（[T575](T575.md)・[T576](T576.md)参照）で、根本原因が全く異なる2つの欠損が
同時に見つかったことになる。

いずれも発見手段は手作業のSQLクエリだった。`/api/material-catalog/{material_id}/values`
（既存API）は材料が取りうる値の一覧を返すのみで、NULL/未取得の割合は一切扱っていない。
管理画面・APIのどちらにも、材料ごとの欠損割合を継続的に把握する仕組みが無い
（surfaceに限らず全材料が対象外）。

## 方針（ユーザー判断、2026-09-04）

欠損データについて、取込側で既定値を推測して埋める（対応方針4的なアプローチ）のでは
なく、**欠損の実態を可視化し、埋めるかどうかの判断は利用側（軸定義・評価ロジック）へ
委ねる**方針を採る。この可視化の仕組みが本タスクの対象。

イメージ: 管理画面に材料一覧（`material_catalog.py`のレジストリが既に持つ全材料）と、
各材料の欠損割合（該当primary_attribute_idを持つEdge/Way総数に対する、値が
NULL/未取得のEdge/Wayの割合）を表示する。
