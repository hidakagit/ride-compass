# T494: 洪水キキクル(vectorTile)のタイルURL相対パス起因のクラッシュを修正

## 状態

完了(2026-08-31)

## 背景

ユーザー報告「地図が出なくなった」。コンソールに以下のエラー:

```
[map:error] Failed to construct 'Request': Failed to parse URL from
/api/jma-tile/bosai/jmatile/data/risk/20260831040000/immed0/20260831040000/surf/flood/4/14/6.pbf
```

T416（洪水キキクル、`vectorTile` kind新設）が同日中に別セッションでmasterへ
マージ済みだったが、既存の`roadSurfaceTileUrl`等（`frontend/src/services/regionApi.ts`）が
既に踏んでいた既知の落とし穴——**MapLibreはベクタタイル（.pbf）をWeb Worker内で
取得するため、タイルURLが相対パスのままだと`new Request(url)`がWorkerのbase URLに対して
解決できず例外を投げる**（regionApi.tsのコメント「実機確認した」を参照、既存の
road-surface/accident/poiベクタタイルは`window.location.origin`で絶対URL化済み）——を
リグレッションしていた。ラスタタイル（.png、`<img>`要素・メインスレッド読み込み）は
相対パスのままで問題なく動くため、キキクル3種（土砂・大雨・浸水、いずれも.png）は
無症状で、洪水（.pbf）だけがクラッシュした。

## 対応方針

洪水キキクルのタイルURL生成箇所2箇所を、既存のroad-surface等と同じ
`window.location.origin`による絶対URL化パターンへ揃えた。

## 実装

- `frontend/src/components/Map/riskMap.ts`: `tileUrlTemplate()`を拡張子`pbf`のときだけ
  `window.location.origin`を付与するよう修正（`png`のラスタ3種は既存の相対パスのまま、
  実機で問題なく動いているため変更しない）。
- `frontend/src/components/Map/MapView.tsx`: `DYNAMIC_WEATHER_RENDERERS.floodRisk`の
  初期化時プレースホルダURLも同様に絶対URL化。このオブジェクトはモジュール読み込み時に
  評価される定数で、`MapView.routes.test.ts`等の純ロジックテスト（`@vitest-environment
  node`、windowを持たない）からも本ファイルがimportされるため、`typeof window !==
  "undefined"`ガードを入れて安全側に倒した（実ブラウザでは必ずwindowが存在し絶対URL化
  される。node環境ではこの値自体テストで参照されない）。
- `frontend/src/components/Map/riskMap.test.ts`: `tileUrlTemplate`のpbf分岐が
  `window.location.origin`を参照するようになったため、`@vitest-environment node`
  docblockを外し既定のDOM環境（happy-dom）で実行するよう変更（regionApi.test.tsと同じ
  対応）。floodRenderPayloadのテストのURL期待値も絶対URL（`${window.location.origin}...`）
  へ更新。

## 検証結果

- `npx vitest run src/components/Map/ src/hooks/useDynamicWeatherLayers.test.ts
  --pool=threads`: 33ファイル349件全て成功（riskMap.test.tsの環境変更・MapView関連の
  node環境テストが引き続き成功することを含む）。
- `npx tsc --noEmit`: エラーなし。
- Browserペインで実機確認: 修正前は地図が「地図を読み込み中…」のまま止まり
  コンソールに報告のエラーが出ていたが、修正後は同じ操作で地図が正常に描画され、
  当該エラーは一切出なくなったことを確認。他の危険度分布（土砂・大雨・浸水、ラスタ
  タイル）のリクエストも引き続き成功していることを確認。
