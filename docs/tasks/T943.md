## 再発防止

**自己申告のチェックを増やさない。** 今回の6件はいずれも「**かつて存在して撤去された**」名前を
指しており、「これから作るもの」の名前とは区別できる。撤去済み識別子の履歴と未完了タスク本文の
突き合わせを検知器にできないかを、**まず実測してから**決める（現在の未完了36件で何件出て、
そのうち何件が真の違反かを数える）。届かなければ周期レビューの手順として残す。

  無くなっていた。役割はレンズが`LensControl`へ、ON/OFF・凡例が地図上のチップへ移っている。
  トリガーを「下部2区分のどちらかを再編するとき、または同じ役割のスタイルが4ファイル目へ
  増えたとき」へ置き換えた。汎化の必要そのものは残っている。
- **T640**: 手で上げるタイル世代の定数はT848が撤去済み。「レイヤーごとに独立している」という
  要件は変わらないが、それを**定数で持つ**という書き方を、形の署名と
  `derived_data_meta.revision`から実行時に組み立てる現在の形へ直した。
- **T715**: 名指ししていた2つは`AxisFormFields.tsx`へ移設済み（T713の抽出で、軸スタジオの
  中では既に共有部品になっている）。行番号を落とし、残る論点が「軸スタジオの外へ出すか」で

- **T714**: 「まず観測を足す」はT840が`/admin`「鮮度」タブへ入れて達成済み。足りないのは

- **T389**: 「JMAの予報を自前で使う」はT645が別経路で達成し本番稼働中。「本タスク完了までは
  検証不能」はもう成立しないため、残る論点がJMBSC契約経由の配信を使うかという費用の判断
  だけであることを冒頭へ書いた。
- **T127**: 容量試算のスナップショットを、着手判断の材料として読まれない位置づけへ変えた
  （2026-09-04の実測以後もDDLのmigrationが15本積まれている）。残すのは測り方と、結論が
  「容量は問題なし・所要時間の不確実性が本体」で一貫していることの2つ。

## 検知器の可否（実測）

未完了49件の本文からバッククォート付きの綴りを取り、現在の実装に無いものを候補とした。

| 段階 | 件数 |
|---|---|
| 候補（現在の実装に無い綴り） | 27 |
| うち**かつて実装にあった**（gitのpickaxeで判定） | 12 |
| うち真に前提が崩れていたもの | 7（58%） |

**「実在しない」だけでは使えない**——未完了タスクは「これから作るもの」の名前を正当に
書くため、候補27件のうち15件は一度も実装に無い名前（新設予定のカラム名・外部の製品コード）
だった。**撤去された**ことを履歴で確かめると12件まで絞れる。残る誤りは、テストの補助関数名
（`beforeEach`）・外部の製品コード・**その撤去自体を扱うタスク**（T951・本タスク）で、
これは人にしか見分けられない。

そこで`stale_task_premises`として**参考出力の検知器**にした（ブロックはしない）。
候補1つにつきpickaxeを1回引くため全件走査で25秒かかる。毎コミットのCIが払う時間ではないので
`--staged`/`--since`からは外し、**全件走査（周期レビュー）のときだけ**走らせる——撤去済みか
どうかは差分ではなく履歴で決まるため、周期的に見れば取りこぼさない。

この検知器は、レビューが挙げた6件のうち2件（T629・T640）を捕まえ、**レビューが挙げていない
3件（T480・T307・T703）を新たに見つけた**。残る4件（T389・T714・T715・T127）は「名前が
撤去された」型ではない（実装が別の経路で達成された・行番号がずれた・数字が陳腐化した）ため
この検知器では捕まらない。

## 検証

- `python scripts/review_checks.py docs --only stale_task_premises`: 是正前12件 → 是正後10件
  （T629・T640の綴りが消えたぶん減った）。残る10件は上記の内訳どおり。
- わざとpickaxeの判定を外すと、`test_find_stale_task_premises_ignores_a_name_that_never_existed`
  （一度も実装に無い名前を挙げないこと）が落ちる。
- `python scripts/review_checks.py docs` 全件で違反なし、
  `pytest scripts/tests/test_review_checks.py -q` 149 passed
  （残る1件`test_npx_cli_path_finds_it_next_to_the_resolved_npm_cli`はWinError 1314＝
  Windowsのシンボリックリンク権限による既存の失敗で、CIのLinuxでは通る）。
- CI経路（`--since`）の所要時間は12.3秒で、この検知器を足す前と変わらない（外したため）。

**コミットした直後にCIが落ちた**（run 861）。テストが番兵として書いた綴りを、その
コミット自身が`scripts/`の履歴へ入れてしまい、pickaxeが自分を見つけて「かつて実装に
あった名前」と判定したためである。**手元で壊して確かめた時点ではまだコミットしていな
かったので出なかった**——検証を、修正を書いたのと同じ状態で行ったことによる取りこぼし。
番兵を実行時に組み立てる形へ直した（`review_checks.py`の`GUARD_PROBE_IDENT`が同じ理由で
そうしている）。一度まるごと書いた綴りは履歴から消えないため、別の綴りへ替えている。
