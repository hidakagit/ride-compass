# T937. 軸スタジオで、既存軸の折れ点が入力に触れただけで作り直される／再公開の成功が失敗と表示される 規模S

状態: 未着手（2026-09-19起票、統合レビュー第11回）

## 背景

T922が「生成」ボタンを撤去して入力のたびに折れ点を作り直す形にしたが、生成フォームの3入力が
`draft.breakpoints`と同期されていない。あわせてT924の「調整する→保存で再公開」が、成功した直後に
「下書きのまま残った」という赤字の通知を必ず出す。どちらもこの保存経路を通るテストが0件である。

詳細は[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)。

## 対応方針

2つは別の原因だが、同じ画面・同じ未検査の保存経路にあるため1タスクで扱う。

1. **折れ点が作り直される**: `AxisScoringSection.tsx`の生成フォーム3入力を`draft.breakpoints`から
   導出する。`useState`の初期化関数と、`editing`が変わったときの同期の両方が要る。
   同ファイルのコメント「『生成』を押すまで`draft.breakpoints`へは反映しない」は、実在しない
   安全装置を名指ししているので実態へ合わせる。
2. **成功時の誤った通知**: `AxisStudio.tsx`の`handleSave`が状態を消した直後に同一レンダーの
   `closeComposer()`を呼ぶため、クロージャが古い値を読む。通知は`listError`と同じ配色で描かれて
   いるが、内容は失敗ではなく状態の案内のため配色も分ける。
3. **「調整する」中の「公開する」チェック**が保存時に無条件で上書きされる（画面の操作結果が無言で
   反転する）。表示と送る値を揃える。

**テストを先に置く**——この保存経路を通るテストは現在0件で、両方の欠陥がそこに落ちた。

## 完了条件

- 既存軸を開いて「効き方」だけを変えたとき、折れ点の端点が保存されることをテストで固定する
- 再公開に成功したとき通知が出ないこと、中断したときだけ出ることをテストで固定する
- `updateAxisDefinition`へ渡るpayloadの`is_published`を1件ずつ検証する
