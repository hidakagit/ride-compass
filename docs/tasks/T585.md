# T585: `round1_array`（Python `round()`の要素ループ）をビット一致のままベクトル化する

状態: 未着手（2026-09-05起票。[T532](T532.md)の設計検討で発覚。T532の前提タスク）

## 背景

`domain/axis_templates.py: round1_array`は、`np.round`が.X5境界でPython組み込み`round()`と
食い違うのを避けるため、要素ごとに`round(float(v), 1)`を呼ぶPythonループになっている。
`compose_costs_from_axis_matrix`（bbox全体ぶんのコスト合成）がcomposite・costの2回呼ぶため、
本番25km（Edge 47.7万件）の`prepare_ms`約2.9秒のうち`cost_ms`約1.8秒
（[T531](T531.md)実測「prepare_ms温の大半はcost_ms≈1.8秒」）の大半をこのループが占める。

開発機での合成データ実測（Edge 73万件＝本番30km相当、公開軸8本）:

| 処理 | 現行 | ベクトル化後 |
|---|---|---|
| `round1_array` 1回 | 4,310ms | 23ms |
| `compose_costs_from_axis_matrix` 全体 | 8,194ms | 884ms（残りはNeumaier加算のnumpy演算） |

## 対応方針

- `×10 → np.rint → ÷10`をnumpyで行い、**計算後の値がちょうど`.5`に乗った要素だけ**
  Pythonの`round()`（10進の正しい丸め）で決め直す。真の積が`.5`境界の反対側にある場合、
  float64の積は必ずちょうど`.5`へ丸まる（境界を跨いで反対側へ着地することはない）ため、
  この要素集合の外では`np.rint`の判定がPython `round()`と一致する。
- 検証済み（scratch実験、2026-09-05）: 一様乱数250万要素・小数2桁/3桁へ丸めた値
  （`.5`境界要素5.5万件を含む）・既知の境界値（385.95、385.949999999999988、41.25、
  0.25、−1.25、2.675、1e15+0.25、NaN等）で現行実装とビット単位で一致。
- テスト: 現行実装（参照実装として残す）との一致テスト（乱数＋境界値）を追加し、
  `tests/test_evaluation_bulk.py`（スカラー版オラクル一致）がgreenのままであることを確認する。
- 完了条件: 本番使い捨てコンテナでT531と同条件の`cost_ms`前後比較（1.8秒→0.3秒前後を見込む）。

## 影響範囲

`domain/axis_templates.py`のみ（呼び出し側の`evaluation.py`・`difficulty.py`は無変更）。
docsは`docs/modules/backend/evaluation-scoring.md`の該当記述があれば更新。

この固定費が倍増するため、T532はこのタスクの完了を前提にする。
