# T539: 交差点分割（split）を実行時ではなくPBF取込後のバッチで全域に済ませる

状態: 未着手（2026-09-02起票、[T522](T522.md)「評価ロジック全体の再点検」で判明）

- 背景: 未splitエリアへの初回リクエストは`get_or_build_graph_with_attributes`の再構築
  経路（closure取得9.9秒＋`build_road_graph`8.8秒＋`save_graph`26.9秒、本番実測
  T522.md「本番環境での再現・内訳調査」節）がリクエスト内で走り、さらにタイル
  キャッシュも温まらない（`_maybe_warm_tile_cache`の後追い温めが別途走る）。
  `app/batch/`には分割を事前に行うバッチが無く、`precompute_elevation_attributes`等は
  `road_edges`が存在するEdgeしか対象にできないため、未splitエリアは標高等の事前計算
  からも漏れる。
- 対応方針: 取込済み全タイル（`road_graph_tiles`）をz12タイル単位で走査し、
  `GraphService.get_or_build_graph_with_attributes`と同じ再構築経路（closure→
  `build_road_graph`→`save_graph`）を順に適用する`app/batch/presplit_road_graph.py`を
  追加する。既存の`is_split_up_to_date`判定を使い、split済みタイルはスキップして
  冪等にする。実行順は`import_pbf`→本バッチ→各precomputeバッチ（`docs/osm-pbf-import.md`
  の手順へ追記）。実行時の再構築経路は、再取込後にバッチを回し忘れた場合の安全網として
  残す。
- 関連: [T538](T538.md)（冷パスの別の段）。過去の本番バックフィル漏れの実績
  （T74・T101、改善計画参照）を踏まえ、新規事前計算は本番実行まで完了条件に含める。
- 完了条件: 本番の取込範囲全域でバッチ実行後に`is_split_up_to_date`が全タイルTrue、
  以後の`get_or_build_graph_with_attributes rebuild`ログが出ないことを確認、バッチの
  冪等性テスト、`docs/osm-pbf-import.md`と`docs/modules/`の該当設計書を同一コミットで更新。
