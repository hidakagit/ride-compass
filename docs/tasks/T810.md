# T810. T790が置き換えた前提を語る記述を一掃し、死んだ識別子の検知をコード内コメントへ広げる

規模M。
状態: 未着手（統合レビュー第8回のP1、2026-09-13）

## 背景

[T790](T790.md)で探索の土台（コストの単位・状態表現・時刻依存）を入れ替えたが、旧前提を
述べる記述が8箇所残っている。しかもその多くが**最初に読まれる場所**（モジュール冒頭・
`architecture.md`・モジュール文書の概要段落）にある。

- `domain/routing.py:4-7`が「探索アルゴリズム自体は独自実装せず、標準的なライブラリの実装を
  そのまま利用する」と宣言し、`:14-19`が「ライブラリの実装を使わないのは…自前で書く」と
  正反対を書く（同一docstring内の自己矛盾）。
- `docs/modules/backend/routing-engine.md:90`が「風に依存する公開軸の**重みが0**の場合は
  スナップショット1本を共有する」と書くが、実装は`time_varying = wind_series is not None`。
  [T790](T790.md)はこの重み依存を「直した欠陥」として明記しており、同文書の`:54`は正しく
  書いている（**同一文書内で矛盾**）。
- `services/road_graph_engine.py:26-27`が「風は出発時点の風を一様適用する（探索中は到達時刻が
  未確定のため）」、`:13`・`:1149`が実装として「scipy」（実際はnumba）。
- `TurnCostSpec`（`routing.py:591-596`）が「探索へ渡すときに巡航速度でm換算する」と、存在しない
  換算を語る。
- `docs/architecture.md:312-313`・`routing-engine.md:31-37`が撤去済みの「直線距離×迂回率÷
  仮定巡航速度」による静的推定を現行機構として書く。
- `routing-engine.md:353-355`が「`TurnExpandedStructure`はキャッシュ対象ではない」と書くが、
  実際は`TurnStructureKey = (TileSet, TurnCostSpec)`でキャッシュされている。
- `routing-engine.md:66`の`contribution_arrays`は実装に存在しない（`review_checks.py docs`が
  既に違反として検知）。
- `domain/evaluation.py:84-85`（「costは距離ベース＝探索にそのまま使える単位」）・
  `domain/cycling_speed.py:18`（「ニュートン法で解く」、実装は二分法でそのdocstringが
  明示的にニュートン法を退けている）。

**実害は「次に触る人が、直したばかりの欠陥を戻す」こと。** `routing-engine.md:90`を根拠に
「重み0なら時刻固定でよい」と実装を"整合"させると、T790が直した「重み0で走行モデルまで
時刻固定に落ちる」不具合が戻る。`TurnCostSpec`のm換算は[T801](T801.md)（ターン費用の較正）が
最初に読む場所で、換算を探して見つからないまま桁を外す。

あわせて、コード内コメントが名指しする**実在しない識別子**は現在どの検知経路にも掛からない
（`ShortestPathTree`・`STATIC_OVERLAY_LAYERS`・`weather_client.py`・`WIND_GRID_CACHE_TTL_SECONDS`・
`refreshBasemapCache`・`MapLayersPanel`）。`dead_identifier_refs`は`docs/modules`しか走査しない。

## 対応方針

1. **先に検知器の射程を広げる**（`dead_identifier_refs`をソースコード内のコメント・docstringへ）。
   広げてから直せば、直し漏れがその場で分かる。緩和・除外を入れる場合は、対象から外す件数と
   母集団に対する割合を実測してこのエントリへ書く。
2. 検知された分と、上記8箇所を一掃する。散っているが原因は1つ（T790の各段階で実装だけを
   進めた）なので1タスクで扱う。
3. `docs/comments.md`の方針どおり、経緯として残す価値のあるものは[T790](T790.md)本文へ寄せ、
   コード側には「今も成り立つ非自明な制約」だけを現在形で残す。
