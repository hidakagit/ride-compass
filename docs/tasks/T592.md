# T592: 区間・候補の物理量表示を材料カタログ駆動へ汎用化する

状態: 未着手（2026-09-05起票、分割元は[T590](T590.md)）

## 背景

`wind_score`・`wind_penalty`・`gradient_percent`・`road_surface_good`等の軸固有レガシー
フィールドと比較パネルの固定行を、「重み>0の軸が参照する材料id→値」の汎用辞書へ
置き換える。比較パネルの「風スコア m/s」は風軸の重みに関係なく常に出る固定行で、
「評価に使っていない軸は出てこない」というユーザーの期待と食い違っている。

## 対応方針

- `RouteSegmentDetail`に`material_values: dict[str, float]`、`RouteCandidate`に同名の
  距離加重平均を追加する。中身は「重みが0より大きい公開軸が参照している材料」だけ
  （`AXIS_DEFINITIONS`の`shape.terms`から導出、軸名のハードコード無し）。
  `LegCostArrays.wind_penalty`（風専用フィールド）は「材料id→配列」の辞書へ置き換え、
  `_wind_penalty_at`・`_aggregate_wind_score`は材料非依存の関数へ一般化する。
- 比較パネル（`ComparisonPanel.tsx`）の`PHYSICAL_METRIC_ROWS`から風スコア・舗装率を外し、
  `material_values`と材料カタログのラベル・単位から行を生成する。距離・獲得標高は
  材料ではないルート属性として残す。
- 区間クリック詳細（`page.tsx: selectedRouteSegment`）に材料値を出すかは要相談
  （ユーザー指示2026-09-05: 走行中のスマホ利用が主で情報量を増やしたくない。
  [T590](T590.md)「UI設計の基準」6）。既定は出さず、出す場合も研究モード限定か折りたたみの
  奥とし、実装前に詳細案をユーザーへ提示して決める。データとしての`material_values`は
  比較パネル（研究モード）向けに持つ。倍率材料の参考換算（[T598](T598.md)の参考点）も
  同じ判断に従う。
- 材料カタログへ`unit`フィールドを追加し配信する（凡例・詳細の単位表記の唯一の正）。
- レガシーフィールドの撤去は2段階。第1段で汎用辞書を追加し比較パネル・区間詳細を
  切り替える。第2段で`wind_score`・`RouteSegmentDetail.wind_penalty`・`gradient_percent`・
  `road_surface_good`・`road_score`・`max_gradient_percent`を撤去する。勾配のルート後
  色分け（`routeStyleModes.ts: isSignedAbsShape`経路が`gradient_percent`を直接読む）は
  第2段で`material_values`から読むよう合わせる。

## 対象ファイル

`backend/app/domain/route.py`・`services/road_graph_engine.py`・`domain/material_catalog.py`・
`api/routers/material_catalog.py`・`frontend/src/components/ComparisonPanel/ComparisonPanel.tsx`・
`frontend/src/app/page.tsx`（区間詳細）・`frontend/src/components/Map/routeStyleModes.ts`（第2段）・
`docs/modules/backend/routing-engine.md`・`docs/modules/frontend/`該当モジュール。

## 完了条件

- 風・勾配・路面の名前を知るフィールドがルート結果のAPIモデルから消えている（第2段）。
- 風軸の重み0で生成したとき、比較パネル・区間詳細に風の行が出ない。重み>0では軸が参照する
  材料の値が単位付きで出る。
- 軸スタジオで軸の材料を変えると表示も追従する（コード変更なし）。
- 設計原則5（同名フィールドの意味を変えない）に照らし、旧フィールドは意味を変えずに撤去
  する（改名・再利用しない）。
