# T768. UI検証の導線を毎回書き直している

規模S〜M。
状態: 完了（2026-09-12）

## 背景

ユーザー指摘「ブラウザを起動して、UIをテストしたいところまで導線進めて、確認にも
トライアンドエラーがあって、みたいなように見えている」から。T755の検証では、実際に
UIの中身を見る前の段階——シートを開く・生成の完了を待つ——の書き方を外して2回失敗し
約80秒を費やした。モバイル幅の同じ導線はT757・T758・T759・T761でも通る。

## 対応

`frontend/e2e/fixtures.ts`へ導線のヘルパーを置く（`openMobileApp`・`openMobileSheet`・
`generateRoutes`・`seedStoredState`）。シートを開く操作は、ハイドレーション前のクリックが
画面に何も起こさないことを踏まえ「開くまで再試行」にして、固定の待ち時間を置かない。
保存される画面状態はクリックで作らずlocalStorageへ直接与えられるようにする。

ヘルパーの使い手として`frontend/e2e/mobile.spec.ts`を追加した。モバイル（390px）の
導線はデスクトップ向けの`smoke.spec.ts`が通る経路とは別物で、これまで自動テストが
無かった。

## 検証

- 新規の`mobile.spec.ts`は**初回実行で通過（19.0秒）**。T755の検証では同じ導線を
  その場で書き、シートが開く前に入力欄を探す・候補タブが別のシートにあることを
  知らずに待つ、の2回で約80秒を失っていた。
- 方針はdocs/testing.mdのパターン4へ追記した。

## 依存の実体を共有する案（実測の上で不採用）

worktreeごとの`npm ci`（frontendは32,563ファイル・579MB）を避けるため、
`frontend/node_modules`をジャンクションで共有する案を測った。作成は0.42秒で、
`vitest`はそのまま通る。ただし次の2点で採らない。

- `next dev`（Turbopack）が`Symlink node_modules is invalid, it points out of the
  filesystem root`として拒否する（共有元が当該プロジェクトルートの外にあるため）。
- 共有先のworktreeを`git worktree remove --force`すると、再帰削除がジャンクションの
  中へ入り**共有元を壊す**。実際に共有元の`node_modules/.bin`が消え、`npx next`が
  動かなくなった（`npm ci`で復旧）。

代わりに「worktreeはテーマ単位で長く使い回す」という運用側の対応をCLAUDE.mdへ入れた。
