# T550: ルート結果・区間詳細の軸表示統一（重み付き寄与度をbackend算出へ・区間詳細をボトムシート統合・タップ判定拡大）

状態: 完了（2026-09-03）

## 背景

ユーザーから複数の実機指摘があり、やり取りの中で以下3原則へ収斂した（「場当たり的な対応は
やめて」という明示指摘を受け、個別修正ではなく統一原則として整理）。

1. **データソースの一元化**: 地図の色分けチップ・内訳の対象軸は、常にルート設定タブでON
   （重み>0）の軸と一致する（既に実装済み・本番反映済み、[T545](T545.md)フォローアップ・
   本タスク着手前に確認済みのため対応不要）。
2. **表示部品の一元化**: 「色ドット＋ラベル＋値」という1つの表現を、ルート結果の内訳・
   区間クリックの内訳で共用する。区間ごとに異なる専用表現（レーダーチャート）は撤去する。
3. **モバイルでは浮くポップアップを増やさない**: 区間クリックの詳細はボトムシート
   （「ルート結果」タブ）側に統合し、地図上はマーカーのみにする。

加えて、以下の具体指摘があった:

- 「内訳（重み付き寄与度）」を独自にフロント側で再計算すると、backendの`overall_difficulty`
  （区間ごとに欠損軸を除いて重みを再正規化→距離加重平均）と算数的に一致しない
  （実測で誤差確認済み、約34.8 vs 独自計算35.4）。フロントで同じアルゴリズムを再実装せず、
  backend側で「区間ごとの合成に使ったのと同じ重み配分」を軸別に分解し距離加重平均した値を
  APIで返し、フロントはそのまま表示する（合計が数学的に必ずoverall_difficultyと一致する）。
- 内訳の表示は、軸ごとの個別棒グラフをやめ、RouteSettingsPanelの「重み配分」と同じ
  積み上げ1本バー（総合難易度の数字の隣、下に凡例）へ統一する。
- 区間クリックの当たり判定が細く（見た目の線幅6pxそのまま）タップしにくい。見た目の線は
  そのまま、当たり判定専用の見えない太い線を重ねる。

対応方針・実装メモ・検証結果は実装完了後に追記する。

## 実装メモ

隔離git worktree（`.claude/worktrees/agent-a1fac5b48a722df86`、
ブランチ`worktree-agent-a1fac5b48a722df86`）で実施。

- **対応1（backend算出化）**: `backend/app/domain/evaluation.py:
  compose_costs_from_axis_matrix`の戻り値を`(cost, composite)`から
  `(cost, composite, axis_contributions)`（3個目はaxis_id→区間ごとの寄与度配列、
  `arr*weight/weighted_weight_sums`、validな軸のみ）へ拡張。呼び出し元
  `backend/app/services/road_graph_engine.py: _build_search_graph`は結果を
  `_SearchGraph.contribution_arrays`/`_RoadGraphContext.contribution_arrays`
  （`axis_arrays`と同じ形の並行フィールド）として保持し、`_build_segment_details`が
  `context.axis_arrays`と同じ行から読んで`RouteSegmentDetail.axis_contributions`へ
  詰める。ルート単位の集約は`domain/route.py`の`merge_axis_difficulties`を
  `_merge_axis_value_dict`共有ヘルパーへ一般化し、新しい`merge_axis_contributions`を
  追加（`_merge_segment_bin`のビン単位集約・`route_generator.py`の新規
  `_with_axis_contributions`静的メソッドの両方から使う、既存の
  `_with_axis_difficulties`と対称な構造）。`compute_edge_costs_bulk`
  （回帰テストオラクル専用経路）は3個目の戻り値を使わないため無視するだけで済んだ。
  Pydanticモデル変更のため`export_openapi.py`→`npm run generate:api`を実行し、
  `RouteCandidate`/`RouteSegmentDetail`両方に`axis_contributions`フィールドが
  追加されたことを確認した。
- **対応2（積み上げバー統一）**: 新規`frontend/src/components/RouteAxisProfile/
  AxisContributionBar.tsx`（axes・contributions・axisColorsのみを受け取る汎用部品、
  `RouteSettingsPanel.module.css`の`stackBar`/`stackSegment`をcomposesではなく
  そのままimportして流用）を作成し、`RouteAxisProfile.tsx`の旧「内訳」セクション
  （`.list`/`.row`/`.track`/`.bar`、frontend独自の`contribution()`/`weightSum`計算）を
  全撤去して置き換えた。`RouteAxisProfile`のprops自体も`axisDifficulties`+`weights`から
  `axisContributions`（`RouteCandidate.axis_contributions`をそのまま渡す）へ変更。
- **対応3（ボトムシート統合）**: `page.tsx`に`selectedRouteSegment`
  state（`{ segment: RouteSegmentDetail, latitude, longitude }`、新規型
  `@/types/route: SelectedRouteSegment`）を追加し、`MapView`へcontrolled
  prop（`selectedRouteSegment`/`onRouteSegmentSelect`）として配線。
  `MapView.tsx: handleRouteSegmentClick`はテキストポップアップ生成をやめ、パースした
  区間データとクリック座標を`onRouteSegmentSelectRef.current(...)`で呼び出し元へ
  渡すだけにした。実際のマーカー表示は`destinationMarker`と同じ「controlled prop変化を
  監視するuseEffect」パターンで別途実装（`selectedSegmentMarkerRef`、絵文字マーカー
  `📍`、クリックで選択解除）。`page.tsx`側は`selectedRouteSegment`が非nullの間、
  該当タブの中身を`RouteAxisProfile`から地点・到達予想時刻＋`AxisContributionBar`
  （区間の`axis_contributions`）へ差し替える。候補タブ切り替え・再生成・
  「ルートをクリア」の3箇所で`selectedRouteSegment`をnullへリセットする。
  `Map/routeSegmentChartPopup.ts`（レーダーチャート本体・凡例組み立て）と対応する
  テストファイルは削除。副次的に、レーダーチャート専用だった
  `axisLayers.ts: rampColorForValue`（他に消費者無し）と対応するテストも削除した。
- **対応4（タップ判定拡大）**: `DETAIL_LAYER_ID`と同じ`DETAIL_SOURCE_ID`を参照する
  新レイヤー`DETAIL_HIT_LAYER_ID`（line-width 24・line-opacity 0）を追加し、
  クリックイベント登録（`map.on("click", ...)`）・`buildInteractiveLayerIds`
  （hoverカーソル判定）・`handleClick`の早期returnガードをすべてこちらへ差し替えた。
  可視レイヤー（`DETAIL_LAYER_ID`、幅6px）自体の見た目は無変更。
- **モジュール設計書同期**: `docs/modules/frontend/route-settings-and-results.md`
  （`RouteAxisProfile.tsx`行の更新・`AxisContributionBar.tsx`行の新規追加・
