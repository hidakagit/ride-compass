# T895. 土地被覆タイルの世代がラスタ構成を含まないのに、immutableで24時間配っている

規模S。
状態: 未着手（2026-09-16起票、統合レビュー第10回）

## 背景

タイルの中身は「どのラスタを開いているか」に依存するのに、その構成が世代（URL）にも
ディスクキャッシュの鍵にも入っていない。`LANDCOVER_TILE_VERSION`の署名材料は手書きリビジョンと
配色レジストリだけで、環境変数で増減する`settings.lulc_raster_paths`が入らない。
一方でHTTPは`PERMANENT`（`max-age=86400, immutable`）を割り当てている。

対応範囲を広げるためラスタを1枚足しても、URLは変わらない。サーバーのディスクキャッシュは
継ぎ目の古い絵を返し続け、ブラウザは`immutable`のため条件付きリクエストすらせず24時間白いまま
——利用者側からは復旧できない。バッチ側では同じ問題が`raster_set_fingerprint`と
`WayLandcover.source_raster_set`で既に解決済みで、その方針を新しい配信機構へ適用しなかった。

あわせて、世代番号をパスへ埋めるディスクキャッシュを新設したのに旧世代を消す導線が無い
（`docs/caching.md`は「世代番号を使うなら古い世代を削除する手段を必ず用意する」と定める）。
z6〜z14でPNGを吐くため、`tile_cache`を「量が小さく実害無し（11MB）」として例外扱いしている
条件が当てはまるかは未測定。

統合レビュー第10回のP1 F-6（[2026-09-16_all.md](../../.claude/commands/review/history/2026-09-16_all.md)）。

## 完了条件

- `LULC_RASTER_PATHS`を変えると`LANDCOVER_TILE_VERSION`が変わる。
- ディスク保持量を実測し、`docs/caching.md`のディスク保持の表へ追記する。免除条件が
  当てはまらないなら`tile_persistent_cache`側（容量上限＋退避あり）へ寄せる。
