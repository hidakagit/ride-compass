# T933: 平面のST_Azimuthを方位として使っている箇所が残っている

状態: 未着手（2026-09-18起票）

## 背景

[T931](T931.md)で、`ST_Azimuth(geometry, geometry)`が**経度緯度を平面として扱った角度**を
返すことが分かった（緯度35度で真の方位と約6度ずれ、`domain/geo.py: bearing_between`・
`road_edges.bearing_deg`と定義が合わない）。T931では`::geography`キャストで直した。

`road_graph_repository.py`の`_WAY_TRAVEL_BEARING_SQL`に、キャストの無い同じ形が残っている。

```
degrees(ST_Azimuth(ST_StartPoint({alias}.geom), ST_EndPoint({alias}.geom)))
```

これは上下線が分かれた道の判定（`_ANTIPARALLEL_SQL`、`:bearing_tolerance_deg`との比較）で
使われる。許容角と数度の系統誤差が同じ桁のため、東西方向の道ほど判定が歪む可能性がある。
migration 0013のコメントが「ST_Azimuthとbearing_betweenは同じ定義」と書いているのも、
この形では正しくない。

## 調べること

- キャストの有無で判定結果が変わるwayの件数（`precompute_way_divided_carriageway.py`の
  対象を両方の式で数えて差を取る）。許容角に対する誤差の比を、道の方位別（南北／東西）に見る。
- 直すなら、T931と同じ`::geography`キャスト。ただし**事前計算バッチの結果が変わる**ため、
  再計算とタイル世代の扱いをセットで決める。
- migration 0013のコメントの訂正。
