# T654. OSM取込対象（層0）へ自転車の停止要因を追加する 規模S

状態: 未着手

## 背景

`osm_raw_pois`へ取り込むノードの種類は`backend/app/batch/import_profile.yaml`が宣言する。
現在の対象は信号・横断歩道・一時停止・徐行（`highway=*`）と車道用踏切
（`railway=level_crossing`）だけで、**車止め（`barrier=*`）が入っていない**。
河川敷サイクリングロード等で自転車を停止・降車させる最大の要因が、DBに存在しない。

停止要因のデータは3層あり、やり直しコストが層ごとに3桁違う。

| 層 | 何を決めるか | やり直しコスト | 方針 |
|---|---|---|---|
| 層0 取込 | どの種類のノードを持つか | **数時間**（PBF再取込） | **迷ったら取る**（本タスク） |
| 層1 タグ | ノードのどのタグを持つか | — | **変更不要**（既に全部持っている） |
| 層2 集計キー | 数え上げをどう分けるか | 数分（バッチ再実行） | 迷ったら分けない（[T655](T655.md)） |

層1が変更不要なのは、取込が`{t.k: t.v for t in n.tags}`でノードのタグを全件保存しており、
絞り込みをしていないため（`backend/app/batch/pbf_source.py`）。開発DBで確認したところ、
信号ノードが持つタグキーは`highway`と`crossing`だけ、踏切の`crossing:barrier`は0件だが、
これは取込で捨てているのではなく**日本のOSMがそう書いていない**ことによる。

## 追加する取込対象

### 採る（自転車が止まる・降りる）

| タグ | 何か | 理由 |
|---|---|---|
| `barrier=cycle_barrier` | 自転車用の柵（A型バリケード） | 降車を強いられる。影響が最も大きい |
| `barrier=bollard` | 車止めポール | すり抜けで減速。河川敷に多数 |
| `barrier=gate` / `lift_gate` / `swing_gate` | ゲート | 停止 |
| `barrier=block` / `chicane` | ブロック・食い違い柵 | 減速 |
| `railway=crossing` | 歩行者・自転車用の踏切 | 現在は車道用（`level_crossing`）のみ取得しており、歩道側の踏切が丸ごと抜けている |

### 採るか要検討（件数を見てから判断する）

| タグ | 何か | 論点 |
|---|---|---|
| `traffic_calming=hump` / `bump` / `table` / `cushion` | ハンプ・凸部 | 減速はするが停止ではない。日本の生活道路で増加中 |
| `highway=mini_roundabout` | ミニ環状交差点 | 日本では稀 |

### 採らない（理由を残す）

| タグ | 採らない理由 |
|---|---|
| `highway=street_lamp` | 街灯の有無は既にwayのタグ（`lit`）として持っている |
| `highway=turning_circle` / `motorway_junction` | 自転車の停止と無関係 |
| shop / amenity の追加 | 補給POIは別目的。停止密度の議論に混ぜない |

「OSM wikiにあるものを全部取る」は採らない。ノードタグは数千種類あり、`osm_raw_pois`が
実質「地図全部」になって取込時間と容量が跳ね上がるうえ、**材料の候補が数千個になって
[T655](T655.md)で決めた「人間が重みを判断できる粒度」が崩壊する**ため。判定基準は
「自転車が止まる・降りる・大きく減速する原因になりうる点か」の一点に絞る。

## 実施タイミング

**単独では実施しない。** 取込対象の変更はPBF再取込（数時間）を伴うため、次回の地図データ
更新に相乗りさせる。それまで[T655](T655.md)は既存5種（信号・横断歩道・一時停止・徐行・
車道用踏切）だけで進められる。

## 層2との関係

層0で種類を増やしても、[T655](T655.md)の集計キーは増やさなくてよい。`barrier`系5種は
まず**1キー`barrier`**にまとめる（層2の原則「迷ったら分けない」。後からバッチ再実行だけで
分けられる）。`barrier`ノードは`bicycle=yes/no`・`access`を併せ持つことがあるが、層1が
全件保存するため、取りさえすれば後から使える。

## 完了条件

- `import_profile.yaml`へ上記「採る」のルールが追加され、PBF再取込後に`osm_raw_pois`へ
  実データが入っていること
- 「採らない」判断の理由が本ファイルに残っていること（再検討時に同じ議論を繰り返さない）
- [T655](T655.md)の集計キーへ`barrier`が1キーとして追加されていること
