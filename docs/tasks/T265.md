- **実装（2026-08-28完了、検討対象1「バックグラウンドウォームアップ」）**: ユーザーが
  候補1を選択（2026-08-28）。事前にプランモードで設計をまとめ承認を得てから実装した。
  1. **`POST /api/routes/generate`を非同期ジョブ化**: 即座（数百ms）に`job_id`を返す
     （HTTP 202）。実際の生成は新設`GET /api/routes/generate/{job_id}`をポーリングして
     待つ形へ変更した（`docs/architecture.md`「汎用ジョブレジストリ」節参照）。
  2. **`infrastructure/job_registry.py`（新規）**: プロセス内メモリのみの汎用非同期
     ジョブレジストリ（`create_job`/`get_job`/`set_running`/`set_done`/`set_failed`、
     完了から10分経過したジョブはTTLベースで自動パージ）。ルート生成の型を一切知らない
     汎用モジュールにし、`api/routers/routes.py`との循環importを避けた。
  3. **`api/dependencies.py`のDI抽出**: `get_route_generation_builder`のクロージャが
     持っていた「どのサービスをどのエンジンへ組み立てるか」ロジックを純粋関数
     `_assemble_route_generation_setup`へ抽出。バックグラウンドジョブ専用の
     `open_route_generation_setup`（`@asynccontextmanager`）を新設し、リクエストスコープ
     外で独立したDBセッションを開く（`graph_service.py: _warm_tile_cache_background`と
     同じ制約への対応）。既存のDI用ジェネレータ関数を`asynccontextmanager()`でラップして
     再利用し、セッション開閉ロジックは複製していない。未使用になった旧
     `get_route_generation_builder`/`RouteGenerationBuilder`は削除した。
  4. **FastAPIの`BackgroundTasks`を採用**（`asyncio.create_task`ではなく）:
     本番のASGIサーバーはレスポンス送出後にタスクを実行するため「即座に返す」要件を
     満たしつつ、`TestClient`はリクエストサイクル内で同期的に実行するため、テストが
     `asyncio.sleep`によるポーリング待ちを必要とせず決定的になる。
  5. **フロント（`routeApi.ts`）**: `generateRoutes()`の外部シグネチャ・戻り値の形は
     変えず（`page.test.tsx`が`generateRoutes`をモジュール丸ごとモックしているため
     無改修で済んだ）、内部実装をsubmit→poll（1.5秒間隔、最大6分）へ変更。第2引数に
     任意の進捗コールバック`onProgress?: (progress: {status, elapsedMs}) => void`を
     追加した。GETのポーリングは`lib/fetchJson.ts`の既存GET共通ラッパーをそのまま再利用
     （新規ヘルパーを書かなかった）。
  6. **`page.tsx`/`RouteForm.tsx`**: `handleGenerate`が`onProgress`を渡し、新規state
