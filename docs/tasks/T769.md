# T769. ルート結果を「見る」と「作る」に分ける 規模M〜L

状態: 未着手（2026-09-12起票、[T621](T621.md)の実機確認で「ルート結果タブが情報量が多くて
見にくい」から。ユーザー判断で、結果パネルの作り直しはT621から切り離す）

## 背景

いまの「ルート結果」は性質の違う4つを混ぜている——候補を見比べる（見る）／区間クリック
詳細（見る）／保存・GPX出力（持ち出す）／区間の乗り換え（作る）。[T759](T759.md)が
測ったとおり、デスクトップのサイドバーは既に`scrollHeight`=1614 / `clientHeight`=764で
2画面ぶんあり、そこへT621が3つ目のブロックを足した。

## ユーザーの構想（2026-09-12）

- 「ルート結果」は生成結果を**見る**画面に徹する
- そこから派生してルートを**作る**操作は「ルート編集」として分ける
- 枠は「地図の見え方」を潰して充当する

## 検討の材料

**「地図の見え方」は潰せる見込みがある。** レイヤー操作の入口は二重で、
`MapOverlayControls`（地図上チップ）と`MapLayersPanel`（サイドバー）が同じ
`layerVisibility`を共有する。レンズは既に地図上だけにある
（`docs/modules/frontend/map-axis-coloring.md`）。

**ただし[T754](T754.md)（P0）が効いている領域**のため、チップ側で同じ操作が完全に
できることを確かめてから潰す——確かめずに消すと、P0の回避手段を先に失う。

**合成結果は候補一覧へ置いたままにする。** 合成ルートは
[design-principles.md](../design-principles.md)構造仕様10により既存候補と同じ経路で
評価された同じ形の候補で、比較・選択・GPX出力はすべて結果側にある。編集パネルへ別タブで
置くと候補が2箇所に分かれ、「どれを採用するか」の比較がパネルをまたぐ（T621論点3）。
派生であることはタブの表記で示す（T621で対応済み）。

## 保留することで何が起きうるか

- 候補を見比べる導線（T759）と、そこから作る導線（T621）が同じ画面を取り合い続ける。
  どちらを直しても、もう一方の縦の長さが増える。
