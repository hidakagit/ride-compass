# T769. ルート結果を「見る」と「作る」に分ける 規模M〜L

状態: 完了（2026-09-12起票・完了。[T621](T621.md)の実機確認で「ルート結果タブが情報量が多くて
見にくい」から。ユーザー判断で、結果パネルの作り直しはT621から切り離す）

## 背景

いまの「ルート結果」は性質の違う4つを混ぜている——候補を見比べる（見る）／区間クリック
詳細（見る）／保存・GPX出力（持ち出す）／区間の乗り換え（作る）。[T759](T759.md)が
測ったとおり、デスクトップのサイドバーは既に`scrollHeight`=1614 / `clientHeight`=764で
2画面ぶんあり、そこへT621が3つ目のブロックを足した。

## ユーザーの構想（2026-09-12）

- 「ルート結果」は生成結果を**見る**画面に徹する
- そこから派生してルートを**作る**操作は「ルート編集」として分ける
- 枠は「地図の見え方」を潰して充当する

## 検討の材料

**「地図の見え方」は潰せる見込みがある。** レイヤー操作の入口は二重で、
`MapOverlayControls`（地図上チップ）と`MapLayersPanel`（サイドバー）が同じ
`layerVisibility`を共有する。レンズは既に地図上だけにある
（`docs/modules/frontend/map-axis-coloring.md`）。

**ただし[T754](T754.md)（P0）が効いている領域**のため、チップ側で同じ操作が完全に
できることを確かめてから潰す——確かめずに消すと、P0の回避手段を先に失う。

### 確かめた結果（2026-09-12）

| 操作 | 地図上チップ | サイドバー |
|---|---|---|
| レイヤーON/OFF | できる | できる |
| 凡例の絞り込み（軸ごとの個別・一括） | できる（▶パネルの`LegendCheckboxList`＋軸見出しのチェックボックス） | できる |
| データ取得状態の表示 | できる（`OverlayLayerChip.dataStatus`） | できる |
| ズームインを促す案内 | できる（`OverlayLayerChip.summary`） | できる |
| **全軸まとめて絞り込み解除** | **できない** | できる（`hasHiddenFilters`/`onClearAllFilters`） |

**サイドバー固有なのは「全軸まとめて解除」だけ**で、これを移せば潰せる。

**`MapOverlayControls.tsx`のコメントが古くなっている**（「絞り込みの編集…はすべて
サイドバーで行う。地図上の▶はあくまで確認用」）。実際にはチップの▶で編集できるため、
このタスクで触るときに直す。

**合成結果は候補一覧へ置いたままにする。** 合成ルートは
[design-principles.md](../design-principles.md)構造仕様10により既存候補と同じ経路で
評価された同じ形の候補で、比較・選択・GPX出力はすべて結果側にある。編集パネルへ別タブで
置くと候補が2箇所に分かれ、「どれを採用するか」の比較がパネルをまたぐ（T621論点3）。
派生であることはタブの表記で示す（T621で対応済み）。

## 保留することで何が起きうるか

- 候補を見比べる導線（T759）と、そこから作る導線（T621）が同じ画面を取り合い続ける。
  どちらを直しても、もう一方の縦の長さが増える。


## 着手時点の更新（2026-09-12）

起票時に「サイドバー固有なのは全軸まとめて解除だけで、これを移せば潰せる」と書いた条件は、
**既に満たされていた**——地図下部中央の一括操作行に漏斗＋×のボタン（`handleClearAllFilters`）が
入っている。地図上チップの▶パネルは`LegendCheckboxList`・`WidthSwatch`をサイドバーと共有して
おり、絞り込みの編集・太さ凡例まで同じ表現で持つ。よってサイドバー固有の操作は残っていない。

**分ける判断の基準はスマホ下部シートの高さ**（ユーザー指示「スマホで言う下部パネルは、低く
すめば済むほどいい」）。実測（390×812、候補2件・周回モード）ではシートの中身は302pxで、
内訳はハンドル20・ヘッダ33・候補タブ列33・総合難易度と負荷30・帯10・凡例チップ129・余白39。
区間の乗り換えパネルはこれに**積み増さる**形で目的地モードのときだけ出ていた。

## 対応

- 区間の乗り換え（`RouteSplicePanel`）をルート結果タブから外し、「ルート編集」へ移した。
  デスクトップはサイドバーの3つ目の`Disclosure`、モバイルは下部タブの3枚目のシート。
  条件が揃わない間は空のパネルではなく「何が要るか」を1行で出す。
- 「地図の見え方」パネル（`MapLayersPanel`）を撤去した。レイヤーのON/OFF・凡例の絞り込み・
  データ取得状態・ズーム案内は地図上チップが、全軸まとめての解除は地図下部の一括操作行が持つ。
- サイドバーにしか無かった「地図の表示を再描画」は、地図下部の一括操作行へ3つ目のボタンとして
  移した（同じ「まとめて元に戻す」性質のため）。
- `WidthSwatch`は`components/Map/`へ移設（`LegendCheckboxList`・`MapOverlayControls`が使う）。
- `MapLayerDescriptor.hideFromLayersPanel`は消費者が無くなったため撤去した。

## 保留にした判断

- **保存・GPX出力・クリアはルート結果に残した**。候補を見ながら持ち出す操作で、対象が
  「表示中の候補」であるため。
- **区間クリック詳細もルート結果に残した**。生成結果を読む操作で、作る操作ではない。
- **合成結果は候補一覧のまま**（起票時の判断どおり）。

## 検証結果

- 周回モードでのシートの中身は302pxで変わらない（乗り換えパネルはもともと出ないため）。
  目的地モードでは、乗り換えパネルのぶんがルート結果から無くなる。
- テストの効きを意図的な変異2件で確認した: 空状態の分岐を外す→2件failure、
  ルート結果タブへ乗り換えパネルを戻す→2件failure。いずれも元へ戻して44件green。
- 地図下部の3ボタン（レイヤー一括OFF・絞り込み一括解除・再描画）がモバイル実機で
  押せることをPlaywrightで確認した。
- frontend全体1261件green、Playwrightのスモーク5件green。

## 残り

**下部シートの高さは中身に依らず`DEFAULT_SHEET_HEIGHT_VH = 50`の固定**で、中身302pxに対して
104pxが空いたままである。中身を減らしても画面上は何も変わらないため、既定値を中身へ
合わせる判断が別途要る（[T778](T778.md)）。
