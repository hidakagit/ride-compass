# T414. 風の「環境」グループ表現（時刻＋方向指定→gridFill面表示）とルート確定後のroute StyleModes統合

状態: 未着手（起票のみ）

- 背景: [T400.md](T400.md)節2「動的要素（時刻・向き等）を含む材料は『環境』と『道路』の
  二重表現を持つ」で設計した風の2つの見せ方のうち、「道路（評価軸）」側（way自身の向きから
  計算、時刻固定）は[T405](T405.md)で実装済みだが、「環境」側は未実装のまま残っている。
  T405.mdは「環境グループの風（時刻＋方位[連続回転]スライダーのUI、`gridFill`面表示）と
  ルート確定後の`routeStyleModes`統合はT400.md記載の別タスク（未起票）であり、本タスクの
  スコープ外（意図的に着手していない）」と明記していたが、T400自体は節1〜6（T401〜T406）の
  完了をもって完了扱いにした際、このフラグが実際に起票されたかの確認が行われず、
  タスク番号を振られないまま見過ごされていた（2026-08-30、実機フィードバック「風は方向と
  時刻を指定して連動するんじゃなかった？」で発覚）。
- 影響: 現在地図上の「風（矢印）」チップ（windVector）は風向・風速をそのまま矢印表示する
  だけで、「自分が指定した任意の進行方向に走ったらどうか」という問いには答えられない。
  それが見られるのは評価軸チップ（windAxis、道路自身の向き基準・時刻は常に現在固定）の
  みで、T400節2が設計した「環境」側の体験（時刻＋方向を自分で指定→面で確認）は存在しない。
- 未実装の内容（T400.md節2より）:
  1. 新規UI部品: 方位の**連続回転**スライダー（円環データのため、時刻スライダーと同じ
     横スクロールルーラーの流用は技術的に困難、新規コンポーネントが必要）。時刻スライダーと
     対で表示する。
  2. 選択中の時刻・方向での向かい風/追い風の強さを、風グリッドの各格子点に対し既存の
     `WindCalculator.wind_penalty(wind_speed_ms, wind_direction_deg, travel_bearing_deg)`
     （[wind.py](../../backend/app/domain/wind.py)）を適用し、`gridFill`
     （降水延長予報と同じ既存レンダラー、`precipitationNowcast.ts`参照）で面塗りする。
     ドメインロジック自体は既存流用で新規実装不要、フロントの表示配線が主な作業。
  3. **ルート確定後の統合**: 「環境」グループの風チップは、ルートの有無で見た目が変わる
     同一チップとする。ルート未確定時は上記の面表示、確定後は時刻・方位スライダーが消え
     （方位はルートが決める、時刻はルート出発時刻から自動）、代わりにルート線自体が風の
     影響で着色される——これは既存`routeStyleModes`の「風」モードと同じ見た目になるため、
     「環境」の風チップと既存の風モードボタンを1つに統合し、二重に存在させない
     （T400.md節2「ルート確定後の風の扱い」参照）。
- 依存: なし（T405完了済みのため`WindCalculator.wind_penalty`・風グリッド取得経路は
  そのまま再利用可能）。
