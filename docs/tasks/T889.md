# T889. 軸スタジオの分布プレビューが本番で必ず500を返す

規模S。
状態: 完了（2026-09-16）

## 背景

軸の折れ点を決めるときに使う分布プレビューが、呼ぶたびに`TypeError`で落ちる。
`way_scalar_materials`の位置引数は7個だが、`backend/app/services/axis_preview_service.py`
だけが8個を渡している。[T881](T881.md)が`curvature_deg_per_km`を1つ落とし、
[T887](T887.md)が`trees_percent`・`built_percent`を`landcover_percents`の1つへ畳んだ
差し引きで、1つ余っている。引数の数を合わせても型が違う（floatとdict）。

影響するのは`POST /api/admin/axis-definitions/preview-distribution`と
`GET /api/admin/material-catalog/{material_id}/distribution`、
`backend/scripts/measure_axis_saturation.py`。backendのテストは全件緑だが、
この経路を通るテストが1件も無い（`grep -rn "load_way_sample" backend/tests` → 0件）。
ルーターは分布関数ごとmonkeypatchし、本体側は純関数だけを見るため、
両者の境目にある組み立て関数を誰も実行していない。

統合レビュー第10回のP0 F-1（[2026-09-16_all.md](../../.claude/commands/review/history/2026-09-16_all.md)）。

## 完了条件

- 本番の2エンドポイントが200を返す。
- `load_way_sample`を通すテストがあり、**呼び出しを壊すとそのテストだけが落ちる**ことを
  確認する（「修正の原則」の「効いている」を確認して完了にする）。

## 対応方針

引数の個数を合わせるだけでは、次にクラスを1つ配線したときに同じずれが戻る。標本行の
土地被覆を`WIRED_LANDCOVER_KEYS`から導く形へ変え、**呼び出し側が並べる値を無くす**。

## 実装メモ

- `_SAMPLE_WAY_MATERIALS_TEMPLATE`の`lc.trees_percent, lc.built_percent`を
  `_LANDCOVER_SAMPLE_COLUMNS_SQL`（配線するクラスの並びから組み立て）へ置き換えた。
  同じファイルの焼き込み列（`_LANDCOVER_TILE_COLUMNS_SQL`）と同じ作り方。
- `WayMaterialSampleRow`の2列を`landcover_percents: dict[str, float] | None`の1つへ畳んだ。
  行が無いときのNone判定は全クラスがNULLかで見る（1列で行全体を代表させない）。
- `load_way_sample`は`row.landcover_percents, row.surface`の7引数を渡すだけになった。

## 検証結果

- `tests/test_axis_preview_service.py::TestLoadWaySample`を3件追加（組み立ての正常系・
  土地被覆が無い行・長さ0の行）。
- **効いていることの確認**: 呼び出しへ引数を1つ足して壊すと、backend全件
  （`pytest -m "not postgis"`、1,998件）のうち**この2件だけ**が
  `TypeError: way_scalar_materials() takes from 5 to 7 positional arguments but 8 were given`
  で落ちる。戻すと1,998件緑。
- 実SQLは`pytest -m postgis -k sample_way_rows`の3件で通した（導出した列並びでも
  `TABLESAMPLE`版・bbox版の両方が引ける）。
- `ruff check app scripts tests` 緑、OpenAPI生成物に差分なし。
