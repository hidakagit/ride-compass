# T956: 材料の受け取りを行から列へ寄せ、Python側の組み立てを無くす

状態: 未着手（2026-09-19起票）

## 背景

材料は列指向（`EdgeMaterialTable`）で持つのに、DBからは1行ずつ受けてPythonで列へ詰めている。
`array_agg`で列ごとの配列として受ければ、Pythonが触るのは区間数×列数ではなく列数になる。

本番コンテナ内の実測（z12/3638/1612、42,144区間・25列）:

| | 取得 | Python側 | 合計 |
|---|---|---|---|
| 行で受ける（現行） | 2,033ms | 849ms | 2,883ms |
| 配列で受ける | 1,956ms | **22ms** | 1,978ms |

Python側が38倍速くなる。取得は変わらない（DB側の仕事が増えるぶんと転送が減るぶんが相殺）。

`array_agg`はDB側では効かない（現行のJOINのまま掛けても2,208msで変わらない）。効くのは
**受け取るPython側**である。

## 位置づけ

[T955](T955.md)の冷パス1タイル7.8秒のうち、この方向が消せるのは
「行→`EdgeMaterialBundle`」1,432msと「bundle→列」198ms。DB側の2,575msは
[T958](T958.md)（読み出し用テーブル）が対象で、両者は独立に効く。

`to_legacy_dicts`（列を区間ごとの辞書へ戻す）と抽出ループも同じ性質の無駄だが、
`_evaluate_axes_bulk`の入力の形を変える話になるためこのタスクの範囲に含める
（T955の「表現が4回変わる」節参照）。

## 注意: 列がずれても誰も気づかない

列ごとに`array_agg`するとき、**すべての列が同じ`ORDER BY`を持つ**必要がある。
1つでも違えば値が列間で静かに食い違い、エラーは出ない。区間idの配列を正本にし、
組み立てたあとに他の列の長さと並びが一致することを検査する。
