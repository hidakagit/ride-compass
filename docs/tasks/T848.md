# T848. タイルへ焼き込む世代だけ、いまも手で上げる運用が残っている

規模M。
状態: 未着手（2026-09-14起票。[T847](T847.md)から分離）

## 背景

T847で材料キャッシュの世代はDBが正になり、バッチを回せば手作業なしで追随するようになった。
一方`cache_identity.py`の`ROAD_SURFACE_REVISION`・`POI_REVISION`・`ACCIDENT_REVISION`
（タイルへ焼き込む側）は手で上げる運用のまま残っている。上げ忘れると、既に配信済みの
タイルが古い値のまま返り続ける——材料側で直したのと同じ形の欠陥が、配信側に残っている。

単純にDBへ移せない理由がある。これらの世代は生成物`region-tile-config.json`を通じて
フロントへ配られるため、実行時に変えるとフロントが知っている世代とずれる。解くには
「配信側の世代をどうフロントへ伝えるか」から決める必要がある。
