# T718. カテゴリ材料の内訳（値ごとの延長割合）を出せるようにする 規模M

状態: 未着手（2026-09-10起票、[T689](T689.md)より分離）

## 背景

[T689](T689.md)で、単位が定まらない軸を材料単位まで分解して絶対量を並べられるようにした。
値の運搬は静的スコア行列の数値列（`route_facing_material_ids`）で行うため、
**categorical材料は載せられない**（列が`float`の行列で、文字列を持てない）。

現在この制約に当たっているのは`highway`（車の圧迫感の内部軸`car_stress_highway_base`が
参照、正規化重み20%で内訳の先頭）と`surface`。軸カタログの`material_breakdown`には
並び順ごと含まれる（軸定義から決まる並びを運搬側の都合で変えると、軸定義との対応が
読めなくなるため）が、値が来ないためフロントが飛ばしている。

## 保留することでブロックされること

車の圧迫感の内訳から「幹線道路が延長の◯%」という、最も直感的な1件が欠けたままになる。
残る4件（制限速度・車線数・指定路線・自動車通行不可）で軸単体の判断はできるため、
[T689](T689.md)が解いた問題自体は再発しない。

## 対応方針（未確定）

数値行列に載せられない値をどう運ぶかの選択になる。着手時に選ぶ。

1. カテゴリを整数の符号へ落として数値列で運び、符号→文字列の対応表をタイル単位で持つ。
   行列の構造は変わらないが、対応表の世代管理が増える。
2. 区間（`RouteSegmentDetail`）へカテゴリ材料専用の辞書を足し、ルート集約時に
   値ごとの延長割合へまとめる。数値列とは別経路になるが、行列には触らない。
3. 一次属性の分布として別APIで返す。ルート結果の内訳とは別の器になる。
