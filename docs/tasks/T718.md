# T718. カテゴリ材料の内訳（値ごとの延長割合）を出せるようにする 規模M

状態: 完了（2026-09-10起票、[T689](T689.md)より分離。2026-09-11完了）

## 背景

[T689](T689.md)で、単位が定まらない軸を材料単位まで分解して絶対量を並べられるようにした。
値の運搬は静的スコア行列の数値列（`route_facing_material_ids`）で行うため、
**categorical材料は載せられない**（列が`float`の行列で、文字列を持てない）。

現在この制約に当たっているのは`highway`（車の圧迫感の内部軸`car_stress_highway_base`が
参照、正規化重み20%で内訳の先頭）と`surface`。軸カタログの`material_breakdown`には
並び順ごと含まれる（軸定義から決まる並びを運搬側の都合で変えると、軸定義との対応が
読めなくなるため）が、値が来ないためフロントが飛ばしている。

## 保留することでブロックされること

車の圧迫感の内訳から「幹線道路が延長の◯%」という、最も直感的な1件が欠けたままになる。
残る4件（制限速度・車線数・指定路線・自動車通行不可）で軸単体の判断はできるため、
[T689](T689.md)が解いた問題自体は再発しない。

## 対応方針（2026-09-11 確定）

**案2を採る**——区間ごとにカテゴリ材料の値を持たせ、ルート集約で値ごとの延長割合へまとめる。
ただし運搬は[T689](T689.md)が数値材料に対して作った形をそのままなぞり、材料ごとの分岐を
持たない。

| 案 | 判断 |
|---|---|
| 1. 整数の符号＋符号→文字列の対応表 | 不採用。値の表現が2つになり、対応表の生成と世代管理が新たな同期ペアになる（「同じ決まりごとが2箇所」の形そのもの） |
| **2. 区間へ値を持たせ、集約で割合へ** | **採用**。数値材料の経路と同じ器・同じ述語の形で書ける |
| 3. 一次属性の分布として別API | 不採用。内訳はルート結果の1行で、2回目のフェッチと「軸→材料」の対応を知る2つ目の場所が要る |

### 運搬

数値材料（`material_ids`/`material_values`）と対になる形で、
`StaticEdgeScoreMatrix`へ`categorical_material_ids`/`categorical_material_values`
（文字列のobject配列）を足す。列の集合と並びは`route_facing_categorical_material_ids`が
唯一の定義元とする——空タイル（列だけを揃える分岐）と通常のタイルが別々に条件を書くと
列がずれる（T536と同型）。

区間は`RouteSegmentDetail.material_categories`（材料id→その区間の値）で持ち、
`merge_material_category_shares`が`材料id→{値: 延長割合}`へ距離加重で畳む。

### 表示

**最も延長の長い値のラベルと割合**を1件出す（例:「住宅街の道 62%」）。ラベルは
`MaterialSpec.value_label`（既存の「論理名 - 物理名」対訳）を使う。

本タスクの背景に書いた「幹線道路が延長の◯%」という形は**採らない**。どの値を
「幹線」とまとめるかという判断表が要り、それは軸定義にも材料カタログにも無い新しい
対応表——フロントが軸ごと・材料ごとの分類を持つことになり、
[設計原則](../design-principles.md)構造仕様2「評価軸追加の1本道」を崩す。
最も長い値そのものを出せば判断表は要らず、`residential`が62%という事実は
車の圧迫感の内訳として十分に読める。

### 現在の対象

公開軸の内訳に現れるカテゴリ材料は`highway`1件だけ（車の圧迫感、正規化重み20%）。
`surface`は舗装質軸が1材料へ分解されるため内訳を持たない。1件しか無いからといって
`edge.highway`を直接読む特別扱いにはしない——`highway`は`EdgeLike`にあるが`surface`は
無く、次にカテゴリ材料を参照する軸が増えたとき静かに何も出なくなる。

### 割合の分母

その材料の値を持つ区間の距離合計で、値の無い区間は分母にも入れない。「観測できた範囲で
どの値が多いか」を表す量にするため——値の無い区間を分母へ入れると、データ欠損が
「その値ではない」として割合を押し下げる。

### 値ラベルは`value_label()`の形を使わない

軸スタジオが使う`MaterialSpec.value_label()`は「住宅街の道 - residential」という
「論理名 - 物理名」形式で、これは軸定義や外部ドキュメントで物理名を探す必要がある
軸スタジオ向けの表記（[T661](T661.md)）。走行中に見る画面へ物理名を並べても読み手の
判断は増えないため、対訳表（`value_labels`）そのものを返し、論理名だけを出す。

### タイルキャッシュの世代

`StaticEdgeScoreMatrix`の列構成が変わるため`_SCORE_MATRIX_REVISION`を10→11へ上げた
（[T689](T689.md)の9→10に続く2回目）。列のシグネチャを見るテストが機械的に検出する。
