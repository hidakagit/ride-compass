# T976. 基礎地図タイルを第0層から出す 規模M

状態: 未着手（2026-09-20起票）。**段階D（関東再構築）より前に決めること。**

## 背景

`openfreemap_tile` アダプタが取り込む基礎地図のベクタタイルは、`source_features` の
`basemap` パーティション（第0層）に入っている。タイル1枚が1行で、`payload` にpbfの実体、
`geom` にタイルの範囲（POLYGON）、`attrs` に z/x/y と配信元のURLテンプレートを持つ。

**第0層の他のソースはすべて派生の入力になっている**（DEM→標高、LULC→土地被覆、OSM→道路網、
事故→件数）。基礎地図タイルだけは何も導出せず、ブラウザへそのまま流すだけの描画資材である。
それが取込のrun・鮮度・カバレッジの仕組みを丸ごと背負っている。

## 規模（2026-09-20実測）

- 開発DB（都心のみ）: 30枚 / payload **18 MB**（平均 614 KB/枚）
- `source_profile.yaml` の `target.bbox = [34.9, 138.4, 37.2, 140.9]`（関東）を
  z14（配信元のmaxzoom、プロファイルの指定値）で覆うタイル数: **15,065枚**
- 上の平均で換算すると **約 8.8 GB**

比較のため、現行の `road_edges`（有向枝5,065,850行・索引込み）が **3,719 MB**。つまり
**第0層で最大の表が、何も導出しないタイルの複製になる**。

**この数字の但し書き**: 614 KB/枚は開発DBの都心30枚の平均で、密度が高い側に寄っている。
山間部・海域のタイルは軽いため関東全域の実値はこれより下がる。正確な値は取り込まないと
分からないが、桁の判断には足りる。

**まだ起きていない**——本番は旧スキーマのままで `source_features` が無い。段階Dで
関東を再構築した瞬間に作られる。

## 決めること

1. **そもそもDBへ置くか**。配信元（OpenFreeMap）は公開インスタンスを無料・無制限で提供し、
   自己ホスト用の週次プラネット配布も出している。複製自体は想定内だが、置き場所は
   ファイルシステム・オブジェクトストレージでもよい。[docs/caching.md](../caching.md)の
   「保持層は共有範囲×寿命の2軸で選ぶ」「失っても自前のPostGISから復元できるものは
   プロセス内かディスクへ置く」に照らすと、**失っても配信元から取り直せるものをDBへ置く
   理由が要る**
2. 置くならどの層か。第0層でないなら、鮮度・カバレッジの仕組みから外れることになるので、
   「古くなったことをどう気づくか」を代わりに決める
3. z14で全域を持つ必要があるか。実際に利用者が見るズーム・範囲の分布を測ってから決める

## 完了条件
