# T569: preview_segmentがSearchGraphStaticsを不要に構築・キャッシュしている問題の分離

状態: 未着手（2026-09-03起票、[T557](T557.md)項目17の`/code-review`指摘に着手して判明した
相互作用を専用タスクへ切り出し）

## 背景

`RoadGraphEngine._build_search_graph`は`prepare`（周回生成、フロンティア方式）・
`preview_segment`（単発区間確認、`/api/routes/preview`）の両方から共通で呼ばれる
（`backend/app/services/road_graph_engine.py`）。この共通経路が内部で必ず
`_get_or_build_search_statics`（一対全最短経路木用の`SearchGraphStatics`をタイル集合キーで
構築・キャッシュ）を呼ぶが、`preview_segment`は2点間の直接A*探索
（`shortest_path_node_ids_lazy`）だけを行い、一対全木を要する`SearchGraphStatics`を
一切使わない。`/code-review`はこれを「`preview_segment`で不要な構築・キャッシュコストを
払っている」と指摘した（[history/2026-09-03_codereview.md](../../.claude/commands/review/history/2026-09-03_codereview.md)）。

## T557での着手時に判明した相互作用（未解決のまま残す理由）

[T557](T557.md)項目4で、`_get_or_build_search_statics`は`domain/routing.py:
build_search_graph_statics`が検出する`LazyGraphEdgeMismatchError`
（タイル再split後のキャッシュ済み`lazy_graph`と新しい`graph`のedge_id不整合）を
検知し、該当タイル集合のキャッシュ3種を破棄して`lazy_graph`ごと再構築する保護機構を
追加した。この保護は`build_search_graph_statics`の内部に実装されているため、
`_build_search_graph`を経由する`preview_segment`もこの保護を副次的に受けている——
`preview_segment`自身のコスト配列構築（`cost_by_edge_id[edge_id] for edge_id in
lazy_graph.edge_ids`）も同種のKeyErrorに理論上は脆弱なため、この副次的な保護は
偶然ではなく実質的に必要な保護になっている。

そのため、項目17の指摘どおり単純に`preview_segment`から
`_get_or_build_search_statics`の呼び出しを外すと、この保護も一緒に失われ、
`preview_segment`が再split直後にKeyError相当で失敗する経路を再び持つことになる。

## 対応方針（案、着手時に精査する）

1. lazy_graphの整合性チェック（`graph.edges`に`lazy_graph.edge_ids`が全て存在するかの
   検証と、不整合時のタイル集合キャッシュ無効化・再構築）を、`build_search_graph_statics`
   から独立した専用関数へ切り出す（例: `_ensure_lazy_graph_consistent(lazy_graph, graph,
   tile_set)`）。
2. `_build_search_graph`が、`prepare`/`preview_segment`のどちらの経路でも1に切り出した
   整合性チェックを共通で呼び、`SearchGraphStatics`自体の構築・キャッシュは`prepare`側
   （一対全木を実際に使う`select_loop_turnarounds`の手前）だけで行うよう配線を変える。
3. 実測: `preview_segment`のタイル集合キャッシュ使用量・応答時間の前後を
   `benchmarks/`配下の適切なスクリプトで比較する。

## 完了条件（案、着手時に精査する）

- `preview_segment`が`SearchGraphStatics`を構築・キャッシュしなくなったことを、
  `search_graph_cache.search_statics_cache_size()`をテストから直接確認する形で検証する。
- 再split後のキャッシュ不整合シナリオ（[T557](T557.md)項目4の回帰テストと同型）を
  `preview_segment`向けにも追加し、`prepare`側と同様に例外を出さず正しく再構築されることを
  確認する。
- `pytest -q -m "not postgis"` green。docs/modules（`docs/modules/backend/
  routing-engine.md`）を同一コミットで更新する。
