## 実施記録（2026-08-31完了）

6件中4件を修正、2件は対応不要と判断した。

1. **clearRoadTileFeatureState（key指定なし全消去）**: **対応不要**。T444で風/勾配間の
   実害は解消済み。この構造的懸念自体は複雑度平衡性レビュー2026-08-31 F-1で既に
   「3件目の動的材料を追加する判断をした時点」というトリガー付きDEFERとして記録済み
   （T444.md参照）であり、principles.mdの「DEFERにはトリガーを付け、トリガー未到達の
   項目をついでに実装しない」原則により、トリガー未到達の今は着手しない。
   （なお、T444.mdが「context.mdのKeep Listへ記録済み」と主張していたが実際には
   未登録と判明——別途T454類似の軽微指摘として拾う価値があるが本タスクの対象外）。
2. **ensureDesignationLayer/ensureTunnelLayer/ensureOnewayLayer（コピペ増殖）**:
   `makeEnsureAttributeLineLayer(layerId, colorExpression, opacityExpression)`
   ファクトリへ統合（`makeEnsureAxisRampLayer`/`makeEnsureDedicatedWayValueLayer`と
   同じ「1ファクトリ+N呼び出し」パターン）。
3. **handleMapError（初回ロード成功後はバナーが出ない）**: `__rcStyleReady`は
   `runWhenStyleReady`が頼る"load"イベントが地図の生涯で一度しか発火しない前提のため
   リセット不可（誤ってリセットするとrunWhenStyleReadyがデッドロックする重大な副作用に
   気づき、実装を一度撤回して設計をやり直した）。代わりに独立した`styleReloadPendingRef`
   を新設し、setStyle()呼び出し中のみtrueにする方式で解決。
4. **refreshTokenエフェクト（連打時のsetStyle重複）**: item3で新設した
   `styleReloadPendingRef`を再利用し、非同期の待ち合わせに入る前の同期区間でガードを
   立てることで、連続発火したeffect同士が両方ガードを素通りする窓を閉じた。
5. **applyAxisFeatureStateValues（way_idごとの個別setFeatureState）**: **対応不要**。
   MapLibre GL JSの型定義を直接確認したところ、公開APIの`Map.setFeatureState`は
   `(feature: FeatureIdentifier, state)`という単一フィーチャー版のみで、バッチ版は
   存在しない（内部実装にはバッチ構造があるが非公開）。アプリケーションコード側で
   改善する手段が無い。
6. **buildStopPoiPopupHtml/buildSupplyPoiPopupHtml（ほぼ同一の2組）**:
   `buildPoiPopupHtml(prefix, labels, properties)`（review指摘どおりのシグネチャ）へ統合。

- **検証**: `tsc --noEmit`・eslint通過。`vitest run src/components/Map/`31ファイル
  327件すべて通過。開発サーバー実機で新規タブから確認しコンソールエラー無し
  （地図ロード・axis-catalog取得とも正常）。**「変わらないデータを更新」ボタン
  （item3/4の対象、深い設定メニュー内）は今回のBrowserペイン操作では到達できず
  クリックでの実機確認はできていない**——ロジックは型チェック・既存の周辺テストと
  手動でのイベント発火順序の追跡により正しさを確認した。
  途中、開発サーバーのコンソール履歴が古いHMR接続の残骸（存在しない関数への参照
  エラー）を返し続ける現象に遭遇し、フレッシュな新規タブで再確認して誤検知と判明した
  （`.next`キャッシュクリア＋サーバー再起動では解消せず、タブ自体の刷新が必要だった）。
