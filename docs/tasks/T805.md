# T805. 走行モデル・ターン・停止の暫定値を管理画面から変えられるようにする

規模M〜L。
状態: 未着手（2026-09-13起票。当初T804で起票したが並行セッションが同じ番号を
先に使ったため振り直した。[T799](T799.md)の作業中にユーザー要望
「Pはじめ、ここまであまり根拠なく決めてきた値を管理画面から変更できるようにして」）

## この作業の位置づけ

`docs/design-principles.md`構造仕様13が、変更の責任を3つに分けている——**物理の較正値**
（停止・ターンの秒数、主観割増レートP）と**軸の形**（材料構成・折れ点）は管理者、
**軸の重み**は利用者。このうち軸の形は既に軸スタジオで管理者が変えられ、重みは利用者が
変えられる。**物理の較正値だけがコードにベタ書きで、変えるたびにデプロイが要る**。
本タスクはその1つを埋めるもので、原則13が求める分担を実装へ揃える作業にあたる。

## 背景

[T790](T790.md)〜T799で入れた探索のコストモデルには、**実測ではなく実感に合わせて置いた値**が
多数ある。どれもコードの定数で、変えるにはデプロイが要る。較正は実走してみないと決まらない
性質のため、デプロイなしで回せないと収束しない。

評価軸（`axis_definitions`）は既に軸スタジオ（/admin）からDB経由で変えられる。同じ器に
載せられないか、という話。

## パラメータ化の対象＝管理画面の対象（2026-09-16、ユーザー判断）

[T801](T801.md)が持っていた「ターンの費用のパラメータ化」を本タスクへ寄せた。**変えられる
ようにする対象と、管理画面が面倒を見る対象を別々に決めると必ずズレる**ため、較正値の宣言を
1つ持ち、そこから次の3つを導く。

| 導く先 | 意味 |
|---|---|
| 探索エンジン | 定数を直接読むのをやめ、宣言から引く＝これが「パラメータ化」 |
| 管理画面 | 画面を宣言から生成する。値を1つ足しても画面側の作業は要らない |
| キャッシュの同一性（`cache_identity`） | 変えた値が実際に効く |

**3つ目が設計を決める**。`STOP_SECONDS`も走行モデルの定数も`cache_identity.py`からは
参照されていない（`TurnCostSpec`だけが`TurnExpandedStructure`のキャッシュ鍵に入っており、
変更が自然に効く）。値ごとに鍵へ足す運用にすると足し忘れが次の不具合になるため、宣言1つから
導いて余地を無くす。

宣言が挙げるのは**較正値だけ**で、全ての定数ではない。「設計上の選択」（`TIME_BIN_HOURS`は
風の予報の刻みから決まる等）は載せない——どれが較正値かの宣言を1つにすることが目的であって、
画面から触れる範囲を広げることではない。

## 論点（着手前に決める）

- **フロントの値も載せるか**。`MIN_SPLIT_STRETCH_KM`はbackendの探索には関係せず、画面の刻みを決めるだけの値。backendの較正値と同じ器に置くか、フロント専用の設定として分けるか。
- **どこまで載せるか**。「較正値（走ってみて決める）」と「設計上の選択（変えると挙動の
  性質が変わる）」は別物で、後者を画面から触れるようにすると壊し方が増える。例えば
  `TIME_BIN_HOURS`は風の予報の刻みから決まっており、自由に変えるものではない
- **キャッシュとの関係**。`TurnCostSpec`は`TurnExpandedStructure`のキャッシュキーに入って
  いるため変更が自然に効く。一方`STOP_SECONDS`や走行モデルの定数はコスト配列の合成時に
  読むだけで、キャッシュ鍵には入っていない（`cache_identity.py`の管理対象外）——DB化した
  ときに古い値のキャッシュが残らないかを確認する
- **器の形**。`axis_definitions`と同じテーブル方式か、単一行の設定テーブルか、
  `axis_registry_meta`のような版管理を持つか。軸と同じく「起動時に読み込んでプロセス内へ
  持つ＋変更時にrefresh」の経路（`refresh_axis_definitions`）へ相乗りできるか
- **権限と事故**。/adminはBasic認証済み（[T272](T272.md)）。値の範囲チェックをどこに置くか
  （`axis_admin`は「極端な重みへの意味的な歯止めは設けない」方針）
