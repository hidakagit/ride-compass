# T734. --staged経路の段落判定をインデックス由来の内容で行う 規模S

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 I-10（P2））

## 背景

行番号は`git diff --cached`（インデックス）由来なのに、撤去マーカーの段落判定は作業ツリーの実体を読む。部分ステージ等で両者がずれると別の段落の免除が適用される。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対応

段落の判定は**行番号の出所と同じ内容**で行う。`doc_text_at(doc, revision)`を新設し、
`--staged`はインデックス（`git show :path`）、`--since`はHEAD、全件走査は作業ツリーを読む。
pre-commitはインデックスを検査する契約なので、結果が作業ツリーの状態に依存してはいけない。

## `cmd_mutate`が原理的にこれを露見させられなかった件

probeが常に`git add -A`するため、インデックスと作業ツリーが常に同じで区別がつかなかった。
**ステージ後に作業ツリーだけを書き換える手順**（`guard_probe_post_stage`）を足した
——`undeclared_dead_refs`のprobeは、ステージ済みの違反行と同じ段落へ、作業ツリーでだけ
撤去の断りを入れる。作業ツリーを読む実装なら免除されて0件になり、`MISS`として落ちる。

## 検証結果

- **配線を壊すと`mutate`が落ちることを確認**した（`find_undeclared_dead_refs`から
  `revision`の受け渡しを外すと、`| undeclared_dead_refs | pre-commit | MISS | 検査はあるが
  0件（見逃し）|`）。戻して全22件PASS。
- 単体テストを1本追加（インデックスと作業ツリーで段落の位置が入れ替わっているとき、
  `revision=""`はインデックス側の行番号を返す）。判定側を作業ツリー固定へ戻すと
  `assert {1} == {3}`で落ちることも確認した。
- `pytest scripts/tests/test_review_checks.py` → 60 passed。
- `python scripts/review_checks.py docs` → 違反なし。
