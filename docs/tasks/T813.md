# T813. キャッシュ鍵の署名が拾えていない2つの穴を塞ぐ

規模M。
状態: 完了（2026-09-14。統合レビュー第8回のP1、2026-09-13起票）

## 背景

`app/infrastructure/cache_identity.py`が掲げる「**形を変えれば鍵が自動で変わる**」という保証に
2つの穴がある。どちらも「静かに古い結果を返し続ける」形で出る。

### 1. `shape_digest`がバインドパラメータの値を署名しない

`shape_digest`は`str(source)`でSQLを署名するため、`bindparams`で渡した**値**が署名に入らない。
路面タイルの場合、`domain/road.py`の`GOOD_OSM_SURFACE_TAGS`/`BAD_OSM_SURFACE_TAGS`がこれに
当たる（実測: `str(_ROAD_SURFACE_TILE_MVT_SQL)`に`good_tags`というプレースホルダ名は現れるが
実タグ値は現れない＝署名不変）。

タグを1つ足すと全タイルの`surface_good`の焼き込み値が変わるのに`ROAD_SURFACE_TILE_VERSION`は
変わらず、`tile_persistent_cache`・ブラウザ・CDNは旧分類を返し続ける。一方Python側
`classify_osm_surface`を使うルート評価には新分類が効くため、**地図の「舗装/未舗装」とルート採点の
食い違いが無警告で続く**。

さらに`docs/caching.md`・`docs/architecture.md`は「形を変えたのに版を上げ忘れる、という最も
多い事故が**原理的に**起きなくなる」「式を変えれば自動で変わる」と断言しており、読むと
手上げが不要に見える。

### 2. `tile_score_matrix_cache`のガードが`highway_filter_flags`を検証しない

読み出し時のガードは「`dataclasses.fields()`に現れない中身で決まる列」として
`raw_axis_ids`/`material_ids`/`categorical_material_ids`の3つを検証するが、同じ性質を持つ
`highway_filter_flags`（キー集合は`domain/hard_filters.py: HARD_FILTER_HIGHWAY_TYPES`由来）を
検証していない。`hard_filters.py`は「1行足すだけで済む」と明記しており、その1行では
`StaticEdgeScoreMatrix`の宣言フィールドが変わらないため鍵の署名も変わらない。

デプロイをまたいで残るディスクキャッシュから旧キー集合の行列が復元されると、
`domain/evaluation.py`が「先頭タイルのキーで揃える」ため、(a)旧行列が先頭に来れば
その新フィルタは全タイルで**静かに無効化**され**利用者が除外したはずの道を通るルートが出る**
（`.items()`で回すため例外にもならない）、(b)新行列が先頭に来れば`KeyError`でそのbboxの
ルート生成が丸ごと落ちる。

## 対応方針と結果

**1は塞いだ**（断言を残したまま穴だけ塞ぐ、の逆——穴を塞いだうえで文書も実態へ合わせた）。
`shape_digest`が、SQLの文字列に加えて**あらかじめ値を束ねたバインドパラメータ**も署名へ入れる
（`bound_values`）。実行時に値を渡すパラメータ（タイル座標等）は値を持たないため入らない
——定義時点で決まっている集合だけが署名の材料になる。

**2も塞いだ**。ガードへ`highway_filter_flags`のキー集合の一致を足した。

文書側（`caching.md`・`architecture.md`・`cache_identity.py`のdocstring）は、署名の材料に
バインド値が含まれることを明記し、あわせて「署名に入らないものを増やさないこと」を残した。

## 実装メモ

- `bound_values`は`TextClause._bindparams`を読む。私有属性のため、SQLAlchemy側が形を変えれば
  静かに空へ戻りうる——**分類タグを変えると鍵が変わることをテストで固定**して、そのときは
  テストが落ちるようにしてある。
- ガードの条件を`set(...)`で書くと、このモジュール自身が持つ`set()`関数が組み込みを隠して
  `TypeError`になる。`dict.keys()`同士の比較にしてある。
- テストのフィクスチャが持っていた`highway_filter_flags`の固定値は宣言から作る形へ変えた
  （固定で書くと、宣言が増えたときにフィクスチャの古さと区別できない）。

## 影響（デプロイ後に一度だけ起きること）

路面・事故・POIタイルの世代が変わる（例: 路面`25-bb4ca819b676`→`25-d271340a28ec`）。
これらのタイルは初回アクセスで焼き直され、旧世代のディスク実体は起動時の
`prune_stale_generations`が回収する。

## 検証結果

- **1が効いていること**: `GOOD_OSM_SURFACE_TAGS`へタグを1つ足すと路面タイル世代が
  `25-d271340a28ec`→`25-d968f35d5523`へ変わる（足す前後で実測）。戻して元の値に戻ることを確認。
- **2が効いていること**: `HARD_FILTER_HIGHWAY_TYPES`へ1行足した状態で、旧キー集合
  （motorway/trunkのみ）の行列をガードへ通すと`False`、新しい宣言で作った行列は`True`。
  ディスクからの復元を模した形で確認した。
- `pytest -q -m "not postgis"` → 1953 passed、`pytest -q -m postgis` → 286 passed、
  `ruff check app tests` → All checks passed。
- `export_openapi.py`→`npm run generate:api`で生成物を同一コミットで更新
  （`region-tile-config.json`のtile_versionが3件）。
