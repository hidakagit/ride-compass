# T813. キャッシュ鍵の署名が拾えていない2つの穴を塞ぐ

規模M。
状態: 未着手（統合レビュー第8回のP1、2026-09-13）

## 背景

`app/infrastructure/cache_identity.py`が掲げる「**形を変えれば鍵が自動で変わる**」という保証に
2つの穴がある。どちらも「静かに古い結果を返し続ける」形で出る。

### 1. `shape_digest`がバインドパラメータの値を署名しない

`shape_digest`は`str(source)`でSQLを署名するため、`bindparams`で渡した**値**が署名に入らない。
路面タイルの場合、`domain/road.py`の`GOOD_OSM_SURFACE_TAGS`/`BAD_OSM_SURFACE_TAGS`がこれに
当たる（実測: `str(_ROAD_SURFACE_TILE_MVT_SQL)`に`good_tags`というプレースホルダ名は現れるが
実タグ値は現れない＝署名不変）。

タグを1つ足すと全タイルの`surface_good`の焼き込み値が変わるのに`ROAD_SURFACE_TILE_VERSION`は
変わらず、`tile_persistent_cache`・ブラウザ・CDNは旧分類を返し続ける。一方Python側
`classify_osm_surface`を使うルート評価には新分類が効くため、**地図の「舗装/未舗装」とルート採点の
食い違いが無警告で続く**。`cache_identity.py:25-28`の手上げ条件リストにもこのケースが無い。

さらに`docs/caching.md:272-275`・`docs/architecture.md:2074-2076`は「形を変えたのに版を
上げ忘れる、という最も多い事故が**原理的に**起きなくなる」「式を変えれば自動で変わる」と
断言しており、読むと手上げが不要に見える。

### 2. `tile_score_matrix_cache`のガードが`highway_filter_flags`を検証しない

`tile_score_matrix_cache.py:93-106`のガードは「`dataclasses.fields()`に現れない中身で決まる列」
として`raw_axis_ids`/`material_ids`/`categorical_material_ids`の3つを検証するが、同じ性質を持つ
`highway_filter_flags`（キー集合は`domain/hard_filters.py: HARD_FILTER_HIGHWAY_TYPES`由来）を
検証していない。`hard_filters.py:28-42`は「1行足すだけで済む」と明記しており、その1行では
`StaticEdgeScoreMatrix`の宣言フィールドが変わらないため鍵の署名も変わらない。

デプロイをまたいで残るディスクキャッシュから旧キー集合の行列が復元されると、
`domain/evaluation.py:1064-1066`が「先頭タイルのキーで揃える」ため、(a)旧行列が先頭に来れば
その新フィルタは全タイルで**静かに無効化**され**利用者が除外したはずの道を通るルートが出る**
（`hard_filters.py:147`は`.items()`で回すため例外にもならない）、(b)新行列が先頭に来れば
`KeyError`でそのbboxのルート生成が丸ごと落ちる。

## 対応方針

1. `shape_digest`がバインド値も署名するようにする。できない場合は`cache_identity.py:25-28`の
   手上げ条件へこのケースを明記し、`docs/caching.md`・`docs/architecture.md`の「原理的に」を
   実態へ合わせる（**断言を残したまま穴だけ塞がない**——読み手はどちらかを根拠にする）。
2. `highway_filter_flags`のキー集合をガードの検証対象へ足す。
3. どちらも**わざと壊して落ちることを確認してから完了扱いにする**（タグを1つ足して世代が
   変わること、`HARD_FILTER_HIGHWAY_TYPES`へ1行足して旧キャッシュが弾かれること）。
