# T893. 関数の引数の個数ずれを検知器にする

規模M。
状態: 完了（2026-09-16）

## 背景

[T889](T889.md)は、シグネチャを変えた側が呼び出し元の1つを取り残して本番を壊した例である。
CIにbackendの型検査は無く（`.github/workflows/ci.yml`はruffのみ）、テストの分担
（ルーターはmock・本体は純関数）の隙間に落ちると誰も実行しない。

同じ型の再発は機械的に止められる: モジュール直下で定義された関数と、その素の名前での
呼び出しをASTで照合し、位置引数の個数が取りうる範囲から外れていたら落とす。
[T883](T883.md)（同名の二重定義）と同じ枠組みで足せる。

統合レビュー第10回の実施順序5（[2026-09-16_all.md](../../.claude/commands/review/history/2026-09-16_all.md)）。

## 完了条件

- [T889](T889.md)の違反を入れ直すと検知される。
- 既存のリポジトリ全体で誤検知0件（`**kwargs`・`*args`を取る関数、デコレータで包まれた関数、
  同名の別モジュール定義を正しく除外できていること）。

## 対応方針

型検査を丸ごと入れるのではなく、**実際に壊れた1つの形**だけを見る検知器にする
（`mypy`の導入はbackend全体の型注釈の整備が要り、判断も費用も別の話になる）。
見るのはモジュール直下の関数を素の名前で呼ぶ形だけで、メソッド呼び出しは対象外
——呼び先の型が静的に決まらないため、取りこぼす方向へ倒して誤検知をゼロにする。

## 実装メモ

- `find_call_arity_mismatches`。定義側は`ast`でモジュール直下の`def`/`async def`から
  位置引数の範囲（必須数〜受け取れる数、`*args`があれば上限なし）を取る。
- **素の名前がどの定義を指すか決まるものだけ**を見る: 同じファイルのモジュール直下の定義と、
  `from <モジュール> import <名前>`で持ち込んだもの（モジュール名→ファイルの対応が付く場合）。
  `import ... as`・解決できないモジュール・`*`展開は見ない。
- デコレータ付きの定義は対象外（シグネチャを変えうる）。
- **キーワードで渡したぶんは「足りている」と数える**。これを入れる前は全件で8件の誤検知が
  出ていた（`weighted_quantiles(pairs, targets, digits=3)`のような形）。`**d`での展開が
  ある呼び出しは、足りない側の判定をしない。
