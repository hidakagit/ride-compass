# T846. 「鮮度」タブの名前が、中身の一部しか指していない

規模S。
状態: 完了（2026-09-14。ユーザー指摘「鮮度台帳や本番DB含めて『鮮度』タブに入っているけれど、
タブ名が実態に合っていない」から）

## 背景

`/admin`の「鮮度」タブは派生データ鮮度台帳・本番DBの状態・タイルキャッシュ消去を持つ。
鮮度はそのうち1枚が見るものでしかなく、DBの状態（取込run・容量・統計・接続）も
キャッシュを消す操作もこの名前からは読めない。

## 対応方針

「データ保守」へ改名する（ユーザー選択、2026-09-14）。読み取りの診断と、直すための操作の
両方を含む名前にする。タブの内部値も`freshness`から`maintenance`へ揃える——値だけ古い名前で
残ると、次に読む人がタブの範囲を鮮度だと誤解する。

**置換するのは現状を語る場所だけ**とし、`docs/tasks/*.md`と`.claude/commands/review/history/`
は触らない（その時点の記録であり、書き換えると当時の画面と食い違う）。

## 実装メモ

- 現状記述側の「鮮度」タブを一括置換（frontendのコンポーネント・型・route handlerのコメント、
  backendの`basemap.py`のdocstring、`architecture.md`・`batch-pipeline-dependencies.md`・
  `docs/modules/`）。
- `basemap.py`のdocstringはOpenAPIのdescriptionになるため、`export_openapi.py`→
  `npm run generate:api`で生成物を同一コミットで更新した（`openapi.json`・`api.d.ts`が
  各1行）。
- `docs/improvement-plan.md`に残る「鮮度」タブは完了済みエントリの記録のため残した。

## 検証結果

- `npx vitest run src/app/admin/page.test.tsx src/components/AxisStudio/` → 17ファイル
  168 passed。タブ一覧・タブ切り替えのテストが新しい名前で通る。
- `pytest tests/test_db_status.py -q` → 9 passed、`ruff check app scripts tests` → All checks passed。
- 置換漏れの確認: `grep -rln 「鮮度」タブ`（docs/tasksを除く）で残るのは
  `docs/improvement-plan.md`（過去エントリ、意図的に残す）のみ。タブ内部値`"freshness"`の
  参照は0件。
