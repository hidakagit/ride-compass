# T727. 区間インスペクタのXSS到達経路を塞ぐ 規模S

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 I-1（P0））

## 背景

`axisInspectorPopup.ts`がOSMタグの生値（`name`/`ref`/`maxspeed`等、自由記述）を無エスケープで`innerHTML`へ入れている。`Popup.setHTML()`を経由しないためMapLibreの`DOM.sanitize()`すら通らない。T703段階1の「到達経路は3箇所」という列挙が不完全だった。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対応方針

直す範囲は「`axisInspectorPopup.ts`のどの行が指摘されたか」ではなく、
**「このファイルの外から来る文字列がHTML文字列へ連結される箇所」**という性質から決めた。
T703が同じ誤りをしている——`MapView.tsx`というファイル単位で洗い出し、
`innerHTML`/`setHTML`をリポジトリ全体でgrepしなかったため4箇所目を落とした。

判断の基準を**行き先ではなく出所**へ変える。`setHTML()`経由なら`DOM.sanitize()`が後ろに
いる、という経路ごとの判断をやめる——サニタイザを通らない経路が後から増えたときに、
そこだけ素通しで残るのがまさに今回の形である。

## 実装メモ

`frontend/src/components/Map/axisInspectorPopup.ts`でエスケープした箇所と、その出所:

| 値 | 出所 |
|---|---|
| `result.tags`のキー | OSM編集者の自由記述（`osm_adapter.py`の取込対象に`name`・`ref`・`maxspeed`・`width`・`smoothness`が含まれる） |
| `result.tags`の値 | 同上 |
| `result.highway` | `osm_raw_ways.highway` |
| 軸ラベル・軸id | 軸スタジオ経由でDBへ入る値（コード中のリテラルではない） |

一次属性のキーは`labelOrEscapedRaw`（対訳表に載れば固定文言、無ければエスケープ）、
それ以外は`escapeHtml`を通す。

`innerHTML`/`setHTML`/`outerHTML`/`insertAdjacentHTML`/`dangerouslySetInnerHTML`を
`frontend/src`全体でgrepし、残る2箇所を確認した:

- `MapView.tsx:127`（現在地マーカーのSVG）: 埋め込む`color`は`ORIGIN_MARKER_COLOR`/
  `ORIGIN_MARKER_FALLBACK_COLOR`のコード中リテラルのみ。外から来る値は無い。
- `MapView.tsx:2903`（`setHTML`）: T703段階1で`labelOrEscapedRaw`済み。

## 検証結果

- 回帰テストを追加し、**エスケープを1箇所外すと落ちることを確認**してから戻した
  （`expected <img src="x" onerror="alert(1)"></img> to be null`）。
- 判定はDOMで行う。`innerHTML`を読み返すと、テキストノード中の`&quot;`が`"`へ戻って
  再直列化されるため、エスケープされていても文字列比較では見分けられない
  （最初にそう書いて偽の失敗を出した）。`querySelector("img")`がnullであること＋
  攻撃文字列が`textContent`に丸ごと残ることで「タグ境界として解釈されていない」を見る。
- `npx vitest run src/components/Map/axisInspectorPopup.test.ts` → 6 passed。
