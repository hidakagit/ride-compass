# T541: liden（雷放電位置データ）の地図表示導入要否を判断する

状態: 未着手（2026-09-02起票、[T520](T520.md)で技術仕様確定・実装要否をプロダクト判断へ分割）

## 背景

[T520](T520.md)の調査で、気象庁nowcグループの`liden`要素は雷放電の位置・時刻を示す
GeoJSON点データ（`LIDEN`=LIghtning DEtection Network system、全国30空港の検知局＋
中央処理局による標定）と技術仕様を確定した。配信URLは
`https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/liden/data.geojson?id=liden`、
`properties`に`id`・`obstimeJST`（観測時刻）・`type`（数値、実データで0/1/4を観測、
雲放電/対地放電等の種別と推測されるが対応表は未確認）を持つ。

RideCompassは既に`thns`（雷活動度、エリア単位のラスタタイル）を実装済み。`liden`は
個々の落雷地点そのものを点で示す点で`thns`と異質であり、導入する場合は現行の
`JmaTileClient`（z/x/yラスタタイル専用設計）とは別のfetch経路・別のレンダリング
（MapLibreの点マーカー等）が必要になる。

## 判断すべきこと

- 既存`thns`（エリア単位の活動度表示）に対し、`liden`の個々の落雷地点表示を追加する
  ユーザー体験上の価値があるか（サイクリング中の落雷回避判断にどう資するか）
- 価値があると判断した場合、実装規模（別レンダリング経路の新設コスト）に見合うか
- `type`値の意味（雲放電/対地放電の別など）を導入前に気象庁の仕様書等で確定する必要が
  あるか
