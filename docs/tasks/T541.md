# T541: liden（雷放電位置データ）の地図表示を実装する

状態: 完了（2026-09-02起票・2026-09-04実装。[T520](T520.md)で技術仕様確定・実装要否を
プロダクト判断へ分割していたが、ユーザー判断で導入決定。「判断すべきこと」節はその判断の
記録として残し、以下へ実装内容を追記する）

## 背景

[T520](T520.md)の調査で、気象庁nowcグループの`liden`要素は雷放電の位置・時刻を示す
GeoJSON点データ（`LIDEN`=LIghtning DEtection Network system、全国30空港の検知局＋
中央処理局による標定）と技術仕様を確定した。配信URLは
`https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/liden/data.geojson?id=liden`、
`properties`に`id`・`obstimeJST`（観測時刻）・`type`（数値、実データで0/1/4を観測、
雲放電/対地放電等の種別と推測されるが対応表は未確認）を持つ。

RideCompassは既に`thns`（雷活動度、エリア単位のラスタタイル）を実装済み。`liden`は
個々の落雷地点そのものを点で示す点で`thns`と異質であり、導入する場合は現行の
`JmaTileClient`（z/x/yラスタタイル専用設計）とは別のfetch経路・別のレンダリング
（MapLibreの点マーカー等）が必要になる。

## 判断すべきこと

- 既存`thns`（エリア単位の活動度表示）に対し、`liden`の個々の落雷地点表示を追加する
  ユーザー体験上の価値があるか（サイクリング中の落雷回避判断にどう資するか）
- 価値があると判断した場合、実装規模（別レンダリング経路の新設コスト）に見合うか
- `type`値の意味（雲放電/対地放電の別など）を導入前に気象庁の仕様書等で確定する必要が
  あるか

## 実装（2026-09-04）

`type`値の意味（雲放電/対地放電の別）は未確定のまま残るため、色分けには使わず全落雷を
同一色の点マーカーで表示する（判断すべきこと3点目は「確定不要、実装は進める」という
判断）。

### backend

- `app/api/routers/jma_tile.py`: プロキシがクエリ文字列（`?id=liden`）を無視していたため
  `request.url.query`があれば`path`へ連結してから`JmaTileClient`へ渡すよう変更（透過
  プロキシのため中身は解釈しない、既存のraster/targetTimes系はクエリ文字列を使わないため
  影響なし）。

### frontend

既存の`DYNAMIC_WEATHER_RENDERERS`（`dynamicWeather.ts`4本柱の1本道）へ、風の矢印と同じ
`gridMark`表現の新規要素として追加した。

- `Map/lidenLayer.ts`（新規）: `thunderNowcast.ts`と同じ`targetTimes_N3.json`から
  `elements`に`liden`を含む全エントリ（thns/trnsと異なり5分おきの全エントリに存在する）を
  フレーム列として取得する`fetchLidenFrames`。他要素と異なり、配信元が実際の落雷地点を
  GeoJSONで提供するため、選択フレームごとに個別fetchする`fetchLidenGeojson`を持つ
  （既存の「格子データから同期的にペイロードを組み立てる」パターンには無い非同期取得。
  詳細はdocs/modules/frontend/dynamic-weather-layers.md参照）。落雷ごとの強弱を示す値を
  配信元が持たないため、`gridMark`が必須とする`valueProperty`用に固定値1を各featureへ
  合成する。
- `Map/lidenIcon.ts`（新規）: 地図上マーカー用の稲妻シルエット（Canvas 2D、`sdf: true`で
  登録）。`icons.tsx: LidenIcon`（チップ用の小さいSVG、同じ形）とは別ファイル
  （windArrowIcon.ts/icons.tsx: WindIconの分離と同じ構成）。
- `MapView.tsx`: `DYNAMIC_WEATHER_RENDERERS.liden`（`gridMark`、色は固定の琥珀色、
  縁取りは`icon-halo-color`/`icon-halo-width`——[T559](T559.md)で確立した「縁取りは
  別レイヤーではなく主層のpaintプロパティで表現する」方式にそのまま従う）。
- `hooks/useDynamicWeatherLayers.ts`: `showLiden`オプション追加。フレーム列の取得は
  `usePolledFetch`（既存の骨格をそのまま利用）、選択中フレームのGeoJSON取得は専用の
  `useEffect`（`frameIndexForTime`で求めた選択中refが変わるたびfetchし、`{ref, geojson}`で
  保持——保持しているrefと選択中refが一致するときだけpayloadへ反映することで、フレーム
  切替中に古いフェッチが後から解決しても直前の時刻のデータを混ぜない）。
- `dynamicWeather.ts`・`mapLayers.ts`・`MapOverlayControls.tsx`・`page.tsx`: 「liden」を
  チップ・`MapLayerId`・アイコン辞書・既定visibility・共有タイムライン参加条件へ1本道で
  追加（他のnowcast系要素と同じ追加点、新しい仕組みは増やしていない）。

### 検証

- `pytest -q`（backend、jma_tile関連含む全件）green。新規: クエリ文字列転送のルーター
  テスト1件。
- `npx tsc --noEmit`・`eslint`・`npx vitest run`（frontend全体）green。新規:
  `lidenLayer.test.ts`（6件）・`MapView.dynamicWeatherLayers.test.ts`は[T559](T559.md)で
  既存、`useDynamicWeatherLayers.test.ts`へliden関連3件追加。
- 実機（Playwright/ブラウザ）での目視確認は本セッションでは未実施（雷放電位置データは
  実際の落雷が発生していないと配信データが空のため、確認には落雷が観測されているタイミング
  が必要）。MapLibre style spec標準の`gridMark`/`icon-halo-*`機構を既存のwindVector矢印
  ([T559](T559.md)で同じ方式を確立済み)と同じ形で使っており、新規のstyle表現は導入して
  いない。
