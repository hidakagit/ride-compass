# T926: 公開済み軸の「表示だけ編集」が保存できない（categoryを定数で上書きしていた）

状態: 完了（2026-09-17）

## 背景

公開済みの`gradient`軸へ`display_thresholds_override`を入れようとすると、backendが
`axis 'gradient' is published and cannot be updated (publish-immutability principle, T271)`
で拒否する。表示専用フィールドだけの差分なら公開済み軸でも直接更新できる設計
（`domain/axis_definitions.py: _COSMETIC_ONLY_FIELDS`・`is_cosmetic_only_update`）なので、
本来はこの導線が通るはず。

原因は**フォームが編集欄を持たない`category`を定数`"推定"`で作り直して送っていた**こと。
`gradient`の`category`は`"観測"`のため差分が表示専用フィールドだけにならず、
「見た目しか変えていないのに拒否される」状態になっていた。

`category`を材料の性質から作れないのは事実（軸スタジオが**新規に作る**軸は常に「推定」）
だが、それは新規作成時の既定値であって、既存軸の値を上書きしてよい理由ではない。

## 範囲

症状が出たのは`gradient`だが、欠陥を成立させている性質は「`category`が`"推定"`以外の
公開済み軸」。スナップショット（実DBのダンプ）で数えると該当は`gradient`・`surface_q`・
`night`の3軸で、いずれも「表示だけ編集」が同じ理由で保存できなかった。

## 対応

`category`を`EditedPayloadKey`から`PASSTHROUGH_PAYLOAD_KEYS`へ移す。新規作成時は
`DEFAULT_PASSTHROUGH_FIELDS`の`"推定"`が入り、既存軸は`pickPassthroughFields`が実値を
そのまま素通しする——同じ仕組みが既に`priority_overrides`等の「編集欄を持たない
フィールド」で使われており、`category`だけがそこから漏れていた。

## 検証結果

- 回帰テスト`AxisComposer.cosmeticRoundTrip.test.tsx`を追加。**実在する全軸**
  （`backend/fixtures/axis_definitions_snapshot.json`）のうち公開済みのものを順に開いて
  何も触らず保存し、表示専用フィールド以外が既存値のまま送られることを確かめる
  （フォームの初期値と同じ軸を1件置いたテストでは、この欠陥は現れない）。母集団が空でも
  通らないよう、公開済み軸が1件以上あること自体も検査する。
- **わざと壊して落ちることを確認**: `category: "推定"`をpayload組み立てへ戻すと
  `gradient`・`surface_q`・`night`の3件が
  `expected { category: '推定' } to deeply equal { category: '観測' }`で落ち、
  戻すと9件全て通る。
