# T542: slmcs系（線状降水帯直前検出・予測領域）の地図表示導入要否を判断する

状態: 未着手（2026-09-02起票、[T520](T520.md)で技術仕様確定・実装要否をプロダクト判断へ分割）

## 背景

[T520](T520.md)の調査で、気象庁nowcグループの`slmcs`/`slmcs_fcst`/`slmcs_unify`/
`slmcs_unifyfcst`要素は「線状降水帯予測マップ」機能の一部と技術仕様を確定した。
配信URLは
`https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/{element}/data.geojson?id={element}`
というGeoJSON（気象庁公式UIが実際にfetchするのは`slmcs_unify`・`slmcs_unifyfcst`）。
公式説明では「雨雲の動き」「今後の雨」上に線状降水帯の雨域を赤い楕円（実況は実線、
10〜30分先予測は破線）として重ねる表示。

RideCompassは既に`sjfcstmap`（同じ「線状降水帯予測マップ」機能のうち、`rasrf`グループ
から配信される3時間先までの20km格子の粗い予測、[T410](T410.md)で実装済み、適中率10%
程度・捕捉率ほぼ100%の「見逃さない」設計）を持つ。`slmcs`系は`sjfcstmap`を補完する、
nowcastの5分刻み更新に同期したより即時的・高精度な線状降水帯領域そのものの表示という
位置づけと考えられる（気象庁公式UI上も両者は同じ「線状降水帯予測マップ」ボタンから
セットで表示される）。調査時点で線状降水帯が発生していなかったため実データは
`{"type":"FeatureCollection","features":[]}`の空配列で取得しており、実際のgeometry種別
（Polygon近似かLineStringか等）は未検証。

## 判断すべきこと

- 既存`sjfcstmap`（3時間先までの粗い20km格子表示）で足りるか、`slmcs`系の追加
  （より即時的・高精度な領域表示）に価値があるか
- 価値があると判断した場合、実データ（線状降水帯発生時）でのgeometry構造の検証が
  実装前に必要
- `slmcs`/`slmcs_fcst`（生データ）と`slmcs_unify`/`slmcs_unifyfcst`（統合版、気象庁公式
  UIが採用）のどちらを使うべきかも導入時に確認する
