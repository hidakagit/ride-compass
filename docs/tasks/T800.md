# T800. 交差点ノードの属性を事前計算する（信号の有無・接続する道の最大階級）

規模M。
状態: 着手中（2026-09-13起票。[T790](T790.md)の段階2cから切り出し）

## 背景

実走フィードバック「交通量の多い道を突っ切る／右折（車線跨ぎ）のコストがばかにならない。
基幹道路をまたぐ横断が非常に苦労」への対応。

T790段階2aでターンの費用は入り、**接続する道の最大highway階級が進入した区間より上位なら
横断・右左折に費用を足す**ところまでは実装済み（`domain/traffic.py: highway_rank`で比べる）。
ただし階級は探索時にEdgeの属性から都度比べており、**信号の有無は見ていない**。

信号のある交差点の待ちは停止密度の材料（`poi_signal_per_km`）が数えているため二重にしない、
という理由で今は見ていない。しかし実走の苦労は「信号の**無い**幹線横断」に集中している。
これを表すには、交差点ノードごとに「信号があるか」「集まる道の最大階級は何か」を持つ必要がある。

## 対応方針

`road_nodes`へ信号の有無・接続する道の最大highway階級を持たせ、バッチで事前計算する
（`precompute_road_node_degrees.py`と同じ形）。ターンの費用がこれを読むことで「信号のある
交差点の直進より、信号の無い交差点で上位階級の道を横断・右折する方が高い」を表せる。

**Edgeへ畳み込んだ値を`road_edges`の列やMVTタイルへ焼かないこと**——Edge側へ焼くと同じ事実が
2箇所に出て、状態を移したとき片方が古くなる。畳み込みによる近似では「交差点を通ること自体を
嫌う」までしか表せず、右折と直進横断を区別できない。

## 調査項目

- `road_nodes`のスキーマ変更（DDL migration）と本番バックフィルの手順
- 停止密度の材料（信号の数）との二重計上をどう避けるか。T790で停止の待ちは走行モデルへ
  移ったため、「待ち」と「横断の怖さ」を別物として置けるようになっている

## 段階1: データ側（2026-09-15）

`road_nodes`へ2列を足し、事前計算するバッチを作った。

- migration `0041_add_road_node_intersection_attributes.sql`:
  `has_traffic_signals`（既定`false`）・`max_highway_rank`（既定`0`）
- 集計SQLは`DerivedGraphRepository`側（`recompute_node_traffic_signals`・
  `recompute_node_max_highway_rank`）、バッチ
  `precompute_road_node_intersections.py`はそれを呼ぶだけ（既存のprecomputeと同じ規約）
- `refresh_derived.py`の⑭段として登録。`docs/batch-pipeline-dependencies.md`にも追記

**既定値はどちらも「このバッチ導入前と同じ挙動になる側」へ倒してある**。
`has_traffic_signals=false`＝信号が無い扱いなので、いまと同じく上位の道を渡るときは
必ず追加の秒数が付く。`max_highway_rank=0`は探索側の導出（読み込んだ部分グラフから
同じ値を出す）を下回るため、DB側の値は下限を上げる方向にしか効かない。
本番バックフィル前にデプロイしても経路は変わらない。

### 信号の判定と半径（実測、開発DB 138,163ノード）

信号は交差点そのもののノードではなく流入路ごと・横断歩道位置ごとの別ノードとして
描かれるため、`osm_node_id`の一致では拾えない。同じ交差点の点をまとめるのに使っている
距離（`POI_CLUSTER_EPS_M` = 40m）を半径にした。**この値は結果を大きく動かす**——
上位の道（rank 4以上＝primary以上）が集まる交差点12,583件のうち「信号あり」になる割合:

| 半径 | 信号あり | 割合 |
|---:|---:|---:|
| 10m | 4,708 | 37.4% |
| 20m | 5,971 | 47.5% |
| 30m | 6,607 | 52.5% |
| **40m** | **7,287** | **57.9%** |
| 60m | 8,550 | 67.9% |

**頭打ちが無い**ため、データからは「正しい半径」が出てこない。40mを採ったのは既に
同じ交差点の点をまとめるのに使っている値だからで、較正された値ではない。半径を広げると
「信号あり」が増え、そのぶんターンの費用が下がる（＝幹線横断を避けなくなる）。
較正は[T801](T801.md)の対象に含める。
