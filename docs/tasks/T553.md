# T553: フロンティア方式の候補間で「同じ周回の逆回り」を重複として棄却する（周回単位の重複率チェック）

状態: 完了（2026-09-03起票・同日完了。[T531](T531.md)推敲時のユーザー質問「すごく似たルートばかり
n件生成されないか」を受けて起票。T531パッケージBの復路探索が入った後に着手、T531完了と
同時期を想定）

## 背景

T531の多様性間引きは**往路**のEdge重複率だけを見る。候補Aが道Xで出て道Yで戻り、候補Bが
道Yで出て道Xで戻ると、物理的には同じ周回だが往路同士（XとY）は重複しないため間引きを
すり抜ける。T274（`_build_best_candidate`）は1候補内の順方向・逆回りの比較であり、候補間の
重複は見ていない。

## 対応方針

1. 復路探索の完了後（距離フィルタ合格後、hydrate前）に、周回全体のEdge集合を**進行方向を
   無視して**（`-fwd`/`-bwd`を同一物理区間として正規化、`lazy_graph.edge_index_by_node_pair`の
   逆引きで対応）採用済み候補と比較し、距離加重の重複率が`LOOP_MAX_OVERLAP_RATIO`
   （初期値0.7、往路用の0.6より緩め）を超えれば棄却してプールの次の折返し点へ進む。
2. 棄却件数はINFOサマリの`dedup_skipped`へ合算し、DEBUGで棄却した候補の重複率を出す
   （docs/logging.md準拠）。
3. 早期停止（n件合格）の判定は、このチェックを通過した候補数で数える。
4. 2026-09-03の`/code-review`（[T557](T557.md)項目8）で、逆回りだけでなく「往路は異なるが復路が同じ裏道へ収束して
   ほぼ同一になる周回」も同じ穴と指摘された。1の比較を「候補間の周回全体（往路＋復路）の
   進行方向無視の重複率」として定義すれば両方を1つの判定で扱える（別々の判定を増やさない）。

## 完了条件

- 合成グリッドで「AのX→Y周回とBのY→X周回のうち後者が棄却される」「重複率が閾値未満の
  別周回は残る」「棄却後もプールが続く限りn件埋まる」のテストがpass。
- 実機確認（Browserペイン）で、生成されたn件に同一周回の逆回りが含まれない。

## 実装（2026-09-03）

- **戦略層への配線**: `LoopRoutingEngine`（`route_generator.py`）へ`is_loop_too_similar
  (context, candidate, accepted)`を追加（同期メソッド、他の5メソッドと違いI/Oを伴わない
  純計算のため`async`にしなかった）。`generate_loops`が距離フィルタ通過後・`traced.append`
  直前でこれを呼び、Trueなら`dedup_skipped`をインクリメントしてその候補を採用せず次の
  折返し点候補へ進む。早期停止（`len(traced) >= max_routes`のbreak判定）はこのチェックを
  通過した候補数のみを数えるため、対応方針3は配置だけで自動的に満たされる。
  `dedup_skipped`はINFOサマリ（成功時・候補0件時の両方）へ合算した。
- **エンジン側の判定**（`road_graph_engine.py`）: `RoadGraphEngine.is_loop_too_similar`が
  `_loop_edge_lengths_by_physical_segment(graph, edge_ids)`（新規モジュール関数、
  `TracedLoop.data`のedge_id列を`{from_node_id, to_node_id}`のfrozenset→距離(m)の辞書へ
  正規化）を候補・採用済み候補それぞれに適用し、距離加重の重複率が`LOOP_MAX_OVERLAP_RATIO`
  （0.7、往路のみの`TURNAROUND_MAX_OVERLAP_RATIO`＝0.6より緩め）を超えたらTrueを返す。
  対応方針4のとおり、往路＋復路を合わせた1つの重複率判定で「同じ周回の逆回り」と
  「往路は違うが復路が同じ裏道へ収束する」の両方を扱う（別々の判定を増やしていない）。
  棄却時はDEBUGログへ`overlap_ratio`と比較対象のbearingを出す（docs/logging.md準拠）。
- **テスト**: `tests/test_road_graph_engine.py`に、完全な逆回り（重複率100%、`e4-rev`・
  `e2-rev`・`e1-rev`）が棄却され、3区間中2区間だけ共有（重複率2/3≈0.67、閾値未満）する
  候補は残ることを検証する合成グラフテストを追加。`tests/test_route_generator.py`には
  `FakeEngine.is_loop_too_similar`（既定Falseで全既存テストへ影響しない、コンストラクタ引数
  `too_similar_bearings`で明示的にTrueへ切替可能）を追加し、(1)重複判定された候補は
  スキップされ早期停止のカウントに含まれない、(2)比較対象は「これまでに採用済みの候補」
  のみ（最初の候補は比較なしで呼ばれない）ことを検証する2件のテストを追加。
- **見送り**: 実機確認（Browserペインでn件の生成結果に同一周回の逆回りが含まれないことの
  目視確認）は、本セッションが実DB・ブラウザを持たないサンドボックス環境のため未実施。
  ユーザー側でのpush後の実機確認が必要。
