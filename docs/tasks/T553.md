# T553: フロンティア方式の候補間で「同じ周回の逆回り」を重複として棄却する（周回単位の重複率チェック）

状態: 未着手（2026-09-03起票、[T531](T531.md)推敲時のユーザー質問「すごく似たルートばかり
n件生成されないか」を受けて起票。T531パッケージBの復路探索が入った後に着手、T531完了と
同時期を想定）

## 背景

T531の多様性間引きは**往路**のEdge重複率だけを見る。候補Aが道Xで出て道Yで戻り、候補Bが
道Yで出て道Xで戻ると、物理的には同じ周回だが往路同士（XとY）は重複しないため間引きを
すり抜ける。T274（`_build_best_candidate`）は1候補内の順方向・逆回りの比較であり、候補間の
重複は見ていない。

## 対応方針

1. 復路探索の完了後（距離フィルタ合格後、hydrate前）に、周回全体のEdge集合を**進行方向を
   無視して**（`-fwd`/`-bwd`を同一物理区間として正規化、`lazy_graph.edge_index_by_node_pair`の
   逆引きで対応）採用済み候補と比較し、距離加重の重複率が`LOOP_MAX_OVERLAP_RATIO`
   （初期値0.7、往路用の0.6より緩め）を超えれば棄却してプールの次の折返し点へ進む。
2. 棄却件数はINFOサマリの`dedup_skipped`へ合算し、DEBUGで棄却した候補の重複率を出す
   （docs/logging.md準拠）。
3. 早期停止（n件合格）の判定は、このチェックを通過した候補数で数える。
4. 2026-09-03の`/code-review`（[T557](T557.md)項目8）で、逆回りだけでなく「往路は異なるが復路が同じ裏道へ収束して
   ほぼ同一になる周回」も同じ穴と指摘された。1の比較を「候補間の周回全体（往路＋復路）の
   進行方向無視の重複率」として定義すれば両方を1つの判定で扱える（別々の判定を増やさない）。

## 完了条件

- 合成グリッドで「AのX→Y周回とBのY→X周回のうち後者が棄却される」「重複率が閾値未満の
  別周回は残る」「棄却後もプールが続く限りn件埋まる」のテストがpass。
- 実機確認（Browserペイン）で、生成されたn件に同一周回の逆回りが含まれない。
