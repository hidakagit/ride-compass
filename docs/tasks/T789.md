# T789. 「条件」タブの入力値を次回も引き継ぐ

規模S。
状態: 完了（2026-09-13、ユーザー要望「周回/目的地、距離、候補数、毎回直すの面倒」）

## 背景

周回/目的地モード・距離・候補数は、開くたびに既定値へ戻る。同じ人が同じような条件で
繰り返し生成するため、毎回直す手間がそのまま毎回かかる。地図レイヤーの表示状態や
下部シートの高さ（[T785](T785.md)）は既にlocalStorageで引き継いでいる。

## 対応方針

同じ仕組み（`useStoredState`）で「条件」タブの入力値を保存し、次に開いたときの初期値に
する。目的地・経由地そのもの（地図上のピン）は対象にしない——場所は行くたびに変わるうえ、
古いピンが残っていると気づかないまま生成してしまう。

## 実装メモ

`useStoredState`で3つのキー（`ridecompass:route-mode`・`ridecompass:distance-km`・
`ridecompass:max-routes`）へ保存する。復元時は**UIが受け付ける範囲内かを検査**し、外れた値・
壊れた値は既定値のまま扱う（スライダーの範囲が縮んだ後でも、範囲外の距離が復元されて
送信されることはない）。

## 検証

Playwright（dev実機）:

- 距離55km・候補数10件・目的地モードへ変えると、その場でlocalStorageへ
  `{mode:"destination", distance:"55", maxRoutes:"10"}`が入る
- 開き直すと目的地モードが選択済み・距離55・候補数10件で復元
- 範囲外の保存値（距離9999・候補数0）を仕込むと距離30・候補数8件（既定値）へ

単体テストは`page.test.tsx`へ2件追加（保存値が生成リクエストへ反映される／範囲外は既定値）。
