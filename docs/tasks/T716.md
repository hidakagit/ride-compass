# T716. domain/material_catalog.pyへ規模ウォッチの個別閾値を設定する 規模S

状態: 完了（2026-09-10起票、統合レビュー第6回。2026-09-10にユーザー承認を得て設定・完了）

## 背景

`backend/app/domain/material_catalog.py`が**1,003行**となり、規模ウォッチの発火条件
「1,000行の新規超過」に該当した（`.claude/commands/review/history/size_watch.json`、`87f7333e`時点）。

complexity.md「規模ウォッチ」節2は、発火したファイルを
(a)理由つきKEEP / (b)抽出・分割の提案 / (c)閾値付きKEEPの個別設定 のいずれかへ分類することを求める。
統合レビュー第6回は**(c)** と判断した。

## 判断根拠

内訳は`MaterialSpec`宣言32件＋小さな抽出器ファクトリ（`raw_way_tag_extractor`・
`tag_equals_extractor`・`keyed_density_extractor`等）で、**宣言的カタログ**である。
成長は材料数に比例し、[T673](T673.md)が回復した「材料追加の1本道」の**単一正本そのもの**。
分割は正本を割ることになるため行わない。

## 提案する閾値

**1,400行**（現在32材料・1,003行から、材料が約1.5倍になるまでを吸収できる値）。

## 承認後の作業

`.claude/commands/review/history/size_watch.json`の`thresholds`へ
`"backend/app/domain/material_catalog.py": 1400`を追加する。
complexity.mdが警告するとおり、**閾値を発火させたまま次の閾値を設定しないと
安全弁が一度きりで機能しなくなる**ため、承認と同一コミットで書き戻すこと。

## 対応

ユーザー承認（提案値1,400行のまま）を得て、
`.claude/commands/review/history/size_watch.json`の`thresholds`へ
`"backend/app/domain/material_catalog.py": 1400`を追加した。

設定時点で規模ウォッチ表を見ると、このファイルは既に**発火しなくなっていた**——
発火条件「1,000行の新規超過」は前回値が1,000行未満であることを前提にしており、
前回値（1,003行）が既に超えているため二度と鳴らない。閾値を設定しなければ、
このファイルは以後どの条件でも監視されない状態のまま残るところだった。
complexity.mdの警告（安全弁が一度きりで機能しなくなる）が指す状態そのもので、
「発火したまま次の閾値を設定しない」ことの実害がここで確認できた。

## 検証

- `python scripts/review_checks.py size`の規模ウォッチ表へ閾値1,400が出ることを確認
- 閾値を一時的に900へ下げると「Keep List閾値900超過」で発火することを確認
  （設定が実際に効いている）。確認後に1,400へ戻した
