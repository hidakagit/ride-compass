# T771. 既存の仕組みを作り直していないかを、実装前に機械で気づく 規模S〜M

状態: 未着手（2026-09-12起票、ユーザー指摘「すでに同じ仕組みがないか、実装する前に確認する
進め方をプロセス固定できればいいね」から）

## 背景

[T621](T621.md)のテストを書く際、`page.test.tsx`のMapViewモックを「目的地を置くボタンを
持つスタブ」へ自前で差し替えた。**同じ用途の仕組みが同じファイルに既にあった**
——`renderFreshHome({ exposeMapClickHandlers: true })`が`onDestinationSet`を叩く
ボタンを出す。全テストを回して初めて食い違いに気づき、撤回して既存側へ寄せた
（既存スタブへボタンを1つ足すだけで済んだ）。

同じ型は[T648](T648.md)・[T650](T650.md)が扱った「写経」と近いが、あちらは**同じ処理が
複数箇所へ書かれた結果**を見つける。こちらは**書く前に既にあるものへ気づく**側で、
jscpdのコピペ検出には小さすぎて掛からない。

## 検知器にできるか（[T650](T650.md)と同じく、まず測る）

CLAUDE.md「修正の原則」に従い、文章のルールを足す前に機械的な検知を検討する。候補:

- **同一テストファイル内で同じモジュールを複数回モックしている**（`vi.mock`/`vi.doMock`）。
  今回の混入はこれに当たる。**ただしこのプロジェクトの正当なパターンを誤検知する**
  ——トップレベルの`vi.mock`で既定を潰し、テストごとに`vi.doMock`で上書きする形が
  `page.test.tsx`で現に使われている。母集団と誤検知率を実測してから採否を決める。
- **テストの足場が正本の置き場（frontend `src/testing`・backend `tests/`直下、
  [T650](T650.md)が集約した場所）の外に増えている**。こちらは「足場を足すなら正本へ」と
  いう既存方針の裏返しで、誤検知は少ない見込み。ただし`renderFreshHome`のように
  **1ファイル内に閉じた足場**は正本の外にあるのが正常なため、そのまま検知器にすると
  既存分が大量に挙がる。実測が要る。

**どちらも母集団を測らずに入れない**。緩和・許可リストを後から足すと、直した件数より
多くを静かに見逃す側に回る。

## 保留することで何が起きうるか

- 同じ型の作り直しが繰り返される。今回は全テストを回して気づけたが、**既存側と新規側が
  両立してしまう場合は気づけない**（どちらも通るため、仕組みが2つ並んだまま残る）。
- 「実装前に探す」を文章のルールとして足すだけでは、探し漏れたときに何も起きない
  （CLAUDE.md「再発防止として自己申告のチェックを増やさないこと」）。
