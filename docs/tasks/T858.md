# T858. 線レイヤーの視覚言語を「意味を運ぶのは色だけ」へ揃える

状態: 完了（2026-09-15）
規模: M

## 背景

道路グループの色分けが読みにくい（ユーザー指摘「道路種別とか、太さで言われても他とズレて
いる。線レイヤ全般の凡例色分けを見直してほしい。シンプルなルールにして」）。線レイヤーに
4つの視覚言語が同時に走っている: 道路の種類だけが太さ（6/4.5/3/1.75px）と破線で意味を運び、
他はすべて色で運ぶ。さらに道路の種類の色は、路面の種類がONの間は使われない（同じレイヤーの
色の意味が、別レイヤーのON/OFFで入れ替わる）。

## ルール（ユーザー承認済み）

1. 意味を運ぶのは色だけ。太さと線種は情報を持たない。
2. 1レイヤー＝1つの色の意味。他レイヤーのON/OFFで色の意味を変えない。
3. 色の体系は3つ: 評価に効く順序＝緑→赤／順序のない分類＝レイヤーごとの色相の濃淡／
   該当・非該当＝そのレイヤーの色と灰色（非該当は薄く）。
4. 同時にONのレイヤーは並列トラック（`line-offset`）で分ける。

## ルールの適用範囲（意図的な例外）

「太さ・線種が情報を持たない」は**データの値を表すチャンネル**の話で、次の2つは値ではなく
重なりや操作状態を表すため対象外とする。

- 二次軸の下敷き（`SECONDARY_AXIS_CASING_WIDTH`）: 同じ道に複数のレイヤーが重なったとき、
  どれが下敷きかを示すためだけの太さ。値の大小は色が持つ。
- 区間の乗り換え（`SPLICE_LAYER_ID`）の破線／実線: いま選んでいる道かどうかという操作状態。
  データの分類ではない。

## 実装

- `roadFilterAxes.ts`: `widthExpression`・`dashArrayExpression`と太さ・線種の定数、
  `CategoryGroup.width`、凡例の`width`/`dashed`を撤去。軸idの定数名は撤去したチャンネルを
  指していたため`ROAD_SURFACE_AXIS_ID`/`ROAD_TYPE_AXIS_ID`へ改名した。
- `MapView.tsx`: 「道路の種類」を独立レイヤー（`ROAD_TYPE_LAYER_ID`）にし、
  `applyRoadLayerState`は軸ごとに自分の色式・不透明度式・絞り込みだけを適用する形へ。
  並列トラック（`ROAD_MATERIAL_TRACK_LAYER_IDS`）へ1本加え、クリック対象にも加えた。
- `LegendEntry`から`width`/`dashed`を外し、`WidthSwatch.tsx`とそのCSSを削除。凡例は
  どのカテゴリも色ドットで描く。
