# T883. 同じ名前をモジュール直下で2回定義しても、どの検査にも引っかからない

規模S。
状態: 未着手（2026-09-16起票。[T881](T881.md)の撤去で実際に作り込んだ欠陥が、
テスト1,981件・`-m postgis` 278件・`ruff`・`review_checks.py docs`のどれも通過した）

## 背景

撤去の切り出しが広すぎた箇所を`git show HEAD:`から貼り直したとき、既に残っていた部分へ
重ねて貼り、同じ塊が2組並ぶ状態になった。後の定義が前を**同じ値で**上書きするため、
観測できる違いが何も出ない。

- `ruff`は`--select ALL`でも拾わない（モジュール直下の変数再代入は正当なPythonのため。
  F811は未使用の関数・クラス・importの再定義しか見ない）。実際に試して確認した。
- `review_checks.py duplication`（jscpd）は、当該ファイルが100KB超で走査外
  （[T882](T882.md)）。仮に走査されても`cmd_duplication`は同一ファイル内の重複を
  捨てるため表には出ない。
- テストは、値が同じである以上どう書いても落ちない。

## 保留することで何が起きうるか

貼り直しは撤去・分割のたびに起きる操作で、同じ形の残骸が今後も入る。値が同じなら無害だが、
**2組が別々に編集されると、後の定義だけが効いて前の編集が静かに巻き戻る**。

## 対応方針

`scripts/review_checks.py`の検知器にする。`ast`でモジュール直下の`Assign`/`FunctionDef`/
`ClassDef`の名前を集め、同じ名前が2回以上現れるものを出す。条件分岐の中の定義
（`if`/`try`の下）は正当なため、直下の`body`だけを見る。

完了条件として、わざと重複を1件入れて検知されることを確かめる。
