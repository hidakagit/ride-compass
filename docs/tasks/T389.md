# T389. MSM（5kmメッシュ）GRIB2パーサーの本実装 規模M〜L

状態: 未着手

- 背景: T387（JMA気象データ連携基盤）でRedis保存インターフェース・データ構造の
  スケルトン（`app/services/jma_msm_service.py: parse_grib2_stub`）のみ用意し、実際の
  GRIB2バイナリ解析は「pygrib/cfgrib等のネイティブ依存を伴う新規ライブラリ導入の判断が
  必要」という理由で意図的に未実装のまま残した（ユーザー指示2026-08-29「MSM本実装は
  別タスクとして切り出して」を受け本タスクとして分離）。
- 対応方針（着手時に確定）: GRIB2デコードライブラリの選定（pygrib vs cfgrib vs 他）、
  MSMデータの取得元（気象業務支援センター経由か、気象庁の公開GPVエンドポイントかを含む
  入手経路の確認・認証要否の確認）、5kmメッシュ→ルート上の任意地点への空間補間方法、
  予報時間解像度（直近は1時間毎、先は3時間毎）の扱いを決める必要がある。
- 関連: T387（Open-Meteo代替可否の検討）で、ルート評価（WindService、区間ごと・将来時刻の
  風速風向）と風の格子点マップ（関東本土624地点・2日先まで）はOpen-Meteoの代替として
  MSMが理論上唯一のJMA候補と判定されたが、本タスク完了までは検証不能。
- **着手前に必ず確認すること（T387で2026-08-29に実機調査済み）**: `jmbsc.or.jp`上に
  「数値予報モデルGPV（MSM）」という気象業務支援センター（JMBSC）専用ページが実在する
  ことを確認済み。これはJMAが数値予報モデルデータの配布をJMBSCへ委託していることの
  裏付けで、amedas/nowcast/警報のようなJMA直営の無料公開APIとは配布経路が異なる。
  ページ内に料金・契約条件の明記は無く、無料利用枠の有無はT387のセッションでは確定
  できなかった。**JMBSCとの契約が必要（＝有料）な場合、GRIB2パーサーを実装しても
  データ自体を本番で入手できない**ため、パーサー実装に着手する前に契約要否・費用を
  必ず確認すること（確認せず実装を先行させると手戻りになる）。
