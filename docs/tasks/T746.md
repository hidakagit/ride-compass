# T746. LoopRoutingEngineのevaluate_loopsに位置対応の契約を明示する 規模S

状態: 完了（2026-09-12。起票は2026-09-11、T696の派生（統合レビュー第7回で発見））

## 背景

`route_generator.py:494-495`が`candidates[shortest_index]`で引数`traced`と戻り値の位置対応に依存しているが、Protocolのdocstringがそれを契約として述べていない。T696完了時に本文へ残されたまま起票されていなかった。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対応: 書くだけにしない

契約を書き足すだけでは、破れたときに何も起きない。この契約が破れた場合の症状は
**候補が消えるのではなく、印・ラベルだけが静かに入れ替わる**（最短経路の「最短」表示が
別の候補に付く）ため、結果を見ても気づけない。

`RouteGenerator._evaluate_loops`を1枚挟み、件数のずれを`RoutingError`で落とす形にした。
`evaluate_loops`を呼ぶ3箇所（周回・経由地・目的地）すべてがここを通る。併せて契約自体を
`route_generator.py`のモジュールdocstring（エンジンの契約を述べている場所）と
`docs/modules/backend/routing-engine.md`へ明示した。

件数ではなく「同じ順」までは検査していない——順序の同一性を戦略層が独立に確かめる手段が
無い（`TracedLoop.data`の中身を知らないのが前提）。現在の唯一の実装は
`zip(traced, edges_by_candidate)`を`asyncio.gather`へ渡す形で、件数が一致する限り順序も
一致する。
