# T761. 目的地モードの目的地チップの状態表示と、生成後の地図タップの挙動

規模S〜M。
状態: 完了（2026-09-12）

## 背景

目的地モードの「ルート設定」には「🏁」チップだけがあり、未設定／タップ待ち／設定済みの状態は`title`と`aria-label`（「目的地を設定（地図をタップ）」等）だけで表す。設定済みは市松模様になる。モバイルにツールチップは無く、「次に何をすればよいか」がチップから読めない。

生成後に地図をタップすると、目的地は動かず選択中ルートの区間詳細（「5.6 km地点」）が開いた。区間クリックの当たり判定（幅24px）がルート沿いにあり、目的地を変えたいタップと区別されない。

個票は[history/2026-09-12_ui.md](../../.claude/commands/review/history/2026-09-12_ui.md)のF-7。

## 調査項目

1. チップに状態の文言（「地図をタップ」「設定済み・タップで解除」）を添える。幅の制約（モバイルでチップは4文字以内という過去の実機指摘）との折り合い
2. 目的地モードへ切り替えた直後に自動で武装する既存設計（`handleRouteModeChange`）は維持する。設定済みの状態で地図をタップしたときの意図（経由地の追加／目的地の変更／区間の詳細）をどう区別するか
3. 空状態の案内文（周回・目的地で出し分け済み）と、チップの状態文言の役割分担

## 完了条件

- 390px幅で、目的地モードの3状態がツールチップ無しで読めることをスクリーンショットで示す
- 生成後に目的地を変えたいときの操作が1手順で分かること

## 対応

- **チップに状態の文言を出す**（未設定「目的地を指定」／タップ待ち「地図をタップ」／
  設定済み「目的地を変更」）。「モバイルのチップは4文字以内」という過去の実機指摘は地図に
  重なるチップ（`MapOverlayControls`）に対するもので、ここは設定パネル内のため文言を置ける。
  390px幅でも1行に収まることを実機で確認した。
- **チップの役割を「指定する／置き直す」に一本化する**。押すたびに武装をトグルし、設定済み
  から武装しても目的地は残る（次の地図タップが置き換え）。解除は設定済みのときだけ出る
  別ボタン（✕、経由地チップと同じ形）。これで「生成後に目的地を変えたい」が
  チップ1つ押す→地図タップで済み、解除してから指定し直す2段階が消える。
- 目的地モードへ切り替えた直後の自動武装（`handleRouteModeChange`）は維持した。

生成後の地図タップが区間詳細になること自体は変えていない——ルート線の当たり判定
（幅24px）は区間を読むための導線で、目的地の変更はチップ側の文言で示す方が
「どちらの意図か」を利用者が選べる。

## 検証

- `RouteForm.test.tsx`へ2件（3状態が文言で読める／設定済みのときだけ解除ボタンが出て
  押すと`onDestinationClear`が呼ばれる）、`page.test.tsx`へ1件（設定済みのチップを押すと
  目的地を残したまま武装し、もう一度押すと設定済みへ戻る＝旧実装なら未設定へ落ちる）
- Playwright（390x812）で3状態のスクリーンショットを採取。タップ待ちは強調色で
  「🏁 地図をタップ」、設定済みは市松模様で「🏁 目的地を変更」＋「✕」
