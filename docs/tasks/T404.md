# T404. display_override廃止（JS変換ロジック拡張＋軸スタジオの色分けしきい値編集）

状態: 完了（2026-08-30）

- 背景: 詳細はT400.md「6. display_overrideの廃止方針」参照。`derive_ramp_inputs`を拡張し、
  軸参照の再帰解決・実行時スケール変換の定数化に対応する。軸スタジオのGUIへ「色分けのしきい値
  だけを自分で調整する」項目を追加し、バックエンド専用の`display_override`（生JSON）を
  car_stress/stop_density/accidentの3軸で廃止する。

## 実装内容

### 1. `derive_ramp_inputs`の拡張（`backend/app/domain/axis_display.py`）

- **軸参照の再帰解決**: `MaterialTerm.material`がMATERIAL_CATALOGに無く
  `AXIS_DEFINITIONS`の別の軸idを指す場合、新設の`_resolve_referenced_axis_tile_input()`が
  参照先を再帰的に解決する。安全に変換できるのは(a) 参照先が`CategoricalShape`（値を
  そのまま返す、追加変換なし）、(b) 参照先が単一term・weight=1.0・preprocess="identity"の
  `BreakpointLinearShape`（`TileInputSpec.breakpoints`の自己変換材料としてそのまま
  表現できる）の2パターンのみ。それ以外（複数term・weight≠1.0等）は安全側でNoneを返す。
  `visited`集合で循環参照からも保護する。
- **実行時スケール変換の定数化**: `tile_property_needs_runtime_scale=True`な材料
  （`accident_count_per_km_year`）も自動導出の対象に含めるよう緩和した。`TileInputSpec`へ
  新設した`needs_runtime_scale`フラグで印を付け、実際のスケール係数（収録年数の逆数）は
  `GET /api/axis-catalog`が返す`material_runtime_scales`（tile property名→係数）から
  フロント側（`axisLayers.ts: rampAxesFromCatalogAxes`）が構築時に一度だけ`weight`へ
  掛け合わせて解決する（未解決時はweight=0で安全側デグレード）。
- `preprocess="abs"`対応は本タスクの対象外とした（car_stress/stop_density/accidentの
  いずれもabsを使わない。absを使う唯一の軸gradientは方向依存材料[gradient_percent]の
  ためabs対応してもkind=noneのままで、対応する動機が無い。T405[Redis経由way_id→値配信]で
  gradientが解決すれば、その時点で改めてabs対応の要否を検討する）。
- `is_designated`材料（`material_catalog.py`）に`tile_property="designation"`・新設の
  `tile_property_categorical_true_values`（真偽値材料だがタイル側は複数値の文字列
  プロパティで表現される場合の値一覧）を追加し、car_stress_designation_adjustment内部軸
  （元はタイル非依存だった）もタイル駆動で自動導出できるようにした。
- 副次的なバグ修正: `CategoricalShape`の2値bool分岐で`has_unknown_fallback`が常にTrue
  固定だったのを`spec.bool_default == "nan"`ベースへ修正（motor_vehicle_no/is_designated
  等bool_default="false"の材料で、欠損を「不明」ではなく確定Falseとして扱うべきだった）。

### 2. `display_thresholds_override`新設（色分けしきい値の軽量な上書き）

- `domain/axis_definitions.py: AxisDefinition.display_thresholds_override: list[float] | None`
- `axis_definitions`テーブルへ`display_thresholds_override`列を追加（`backend/migrations/
  0025_axis_definitions_display_thresholds_override.sql`、DDLのみ）
- `axis_display_for()`の優先順位を書き換え: ①`derive_ramp_inputs`成功＋
  `display_thresholds_override`設定→自動導出tile_inputs＋このしきい値、②成功＋未設定→
  自動導出のしきい値そのまま、③`derive_ramp_inputs`失敗時のみ旧`display_override`を
  後方互換フォールバックとして使用、④どちらも無ければkind="none"
- `axis_admin.py`: `AxisDefinitionPayload`へ`display_thresholds_override`のバリデーション
  （昇順必須・空リスト拒否）を追加。`AxisDefinitionResponse`へ`display`（`axis_display_for()`
  の計算結果）を新設——下書き軸は`GET /api/axis-catalog`に現れないため、軸スタジオが
  kind="none"判定を行うにはこの管理APIのレスポンスが必要
- 軸スタジオGUI（`AxisComposer.tsx`）へ「地図の色分けしきい値」編集項目を追加。生JSON編集
  ではなく数値配列の追加/削除/編集のみのシンプルなUI。`step="any"`を明示（`step="0.1"`だと
  浮動小数点誤差でvalue=1のようなよくある値がHTML5 step制約検証に引っかかり、フォーム
  submitイベント自体が発火しなくなる実バグをテスト作成中に発見・修正した）
- kind="none"の軸を編集中は以下の注記を表示（T400.mdで確定済みの文言、既存軸の編集時のみ
  判定——新規作成中はbackend計算前のため注記を出さない）:
  > この軸で使っている材料の一部は、まだ地図表示用のデータ取得経路が用意されていません
  > （ルート探索のコストには反映されます）

### 3. dev DBの移行（car_stress/stop_density/accident）

axis_admin APIと同じ`AxisRegistryAdminService`を直接呼ぶ一回限りのスクリプトで
（unpublish→update→再publish、CLAUDE.mdの「axis_definitionsの行データはAPI経由」原則に
沿う）、3軸の`display_override`をNULL化し`display_thresholds_override`へ移行した:

| 軸 | 旧display_override.thresholds | 新display_thresholds_override |
|---|---|---|
| car_stress | [2.0, 3.0, 4.0] | [2.0, 3.0, 4.0]（同一スケール、変更なし） |
| stop_density | [1.0, 2.0, 4.0] | [1.0, 2.0, 4.0]（同一スケール、変更なし） |
| accident | [0.4, 0.8, 1.5]（タイル生値スケール、年正規化前） | [0.133, 0.267, 0.5]（材料スケール、収録年数3で除算。実行時スケール定数化に伴いJS式が年正規化後の値と比較するようになったため再較正） |

car_stressのhighway系tile_inputは、自動導出により従来の手書きoverride（13値、footway/path
抜け）より正確な15値（`car_stress_highway_base`の実際のmapping、`footway`/`path`を含む）に
なった——これは意図しない値のドリフト（T359で内部軸へfootway/pathを追加した際、
display_overrideへの反映が漏れていた）を自動導出への移行が偶然修正した副産物。
