# T817. penalty_strengthの既定値を片側importへ寄せ、回帰テストを置く

規模S。
状態: 未着手（統合レビュー第8回のP1、2026-09-13）

## 背景

[T799](T799.md)で主観的割増のレート`penalty_strength`を1.0から0.7へ較正したが、
`app/api/dependencies.py:165, 203`（`_assemble_route_generation_setup`・
`open_route_generation_setup`）の既定値が**`1.0`のリテラルのまま**残っている。正本は
`domain/evaluation.py: DEFAULT_PENALTY_STRENGTH = 0.7`で、`api/routers/routes.py:157`は
そちらをimportして使う。

APIハンドラ以外からこの工場を呼ぶ経路（現に`tests/test_routes_generate.py:453`の
`_lightweight_route_generation_setup`がそう呼ぶ）はP=1.0で`RoadGraphEngine`を組み立てる。
T799は「物理を写した軸の重みを0にしdifficultyが大きく出る前提」で0.7へ下げたので、
この経路だけ割増が約1.4倍強く効き、悪路回避が過剰な経路が返る。

**しかもこの値を守るテストが無い。** `test_routes_generate.py:94,102`は
`captured["penalty_strength"]`へ記録はするが、リポジトリ全体でこの値をassertしている箇所が
1つも無い（`0.7`・`DEFAULT_PENALTY_STRENGTH`をassertするテストもゼロ）。既定を1.0へ戻す・
`conditions`のエコーを落とす・工場への受け渡しを取り違える、のいずれをやっても全緑で通る。

ドキュメント側も2箇所ずれている。

- `docs/architecture.md:947`が「省略時1.0」（生成物`route-generate-config.json`は
  `default_penalty_strength: 0.7`で実装と一致している）。
- `docs/architecture.md:579-580`は文が壊れており、`max_average_grade_percent`の説明が欠落した
  結果**`penalty_strength`が勾配しきい値だと述べている**。値域は`ge=0`なので勾配%（例: 8）を
  入れても422にならず、P=8＝「難易度100の道は体感9倍の時間」という極端な割増で探索される。

## 対応方針

1. `dependencies.py`の2箇所を`DEFAULT_PENALTY_STRENGTH`の片側importへ寄せる。
2. 既定値をassertするテストを足す（**わざと1.0へ戻して落ちることを確認する**）。
3. `docs/architecture.md:947`・`:579-580`を直す。
