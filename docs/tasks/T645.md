# T645. 風・降水予報をOpen-Meteo REST APIから気象庁MSM（.om直読み）へ移行 規模L

状態: 実施中（2026-09-07起票。段階1は実装済み、段階2以降は未着手）

## 背景

風・降水の格子点マップ（`/api/weather/wind-grid`・`wind-grid-detail`）はOpen-Meteoの
公開REST APIを都度叩いており、429 Too Many Requestsが常態化している。Open-Meteoは
複数地点リクエストを地点数ぶんのAPIコールとして数えるため、624点の格子1回で624コール、
無料枠（10,000コール/日）に対して構造的に足りない。呼び出し方の最適化（POST集約・変数の
絞り込み・TTL 3時間・Redis L2）は実施済みで、これ以上は改善余地が無い。

Open-MeteoがAWS Open Dataで公開している前処理済みデータ（`s3://openmeteo/data/jma_msm/`、
CC-BY-4.0）に気象庁MSMが含まれており、公式Pythonリーダー（`omfiles`）で直接読める。
JMBSC契約（月額約13,500円＋初回50,000円、[T389](T389.md)）もOpen-Meteoサーバーの
自前ホスト（要件8〜16GB）も不要で、外部APIリクエスト自体が消える。

## 方針（ユーザー判断済み、2026-09-07）

- 予報＝MSM（Open-Meteoが公開するS3の静的ファイル）、実測＝JMA公開API（アメダス・
  ナウキャスト・警報・洪水）の住み分けとする。両者は性質が違うため統合しない
- MSMに無い項目（突風・降水確率・UV指数）は削除する。突風・現在値UV・現在値降水確率は
  そもそもどこからも参照されていない死にフィールド
- 今日の見通しパネルの時間帯別「降水確率(%)」は「予想降水量(mm)」へ置換する
- `/api/weather`のdaily.sunrise/sunsetは`domain/twilight.py: sunrise_sunset_jst`
  （自前計算、アメダス経路で使用中）へ切り替える

## 実測（2026-09-07）

本番VM（`ridecompass-postgis`、aarch64・2 OCPU/11GB、負荷ほぼゼロの時間帯）で計測:

| 項目 | 結果 |
|---|---|
| 同期（S3→VM） | 34.2 MB を7.5秒（日本全域・114時間・風U/風V/降水の3変数）。1日あたり約7.2MB相当 |
| 関東全域格子 0.1°（624点×48時間） | 読み出し＋双一次補間の中央値 **4.1 ms**（JSON直列化まで含めて+69 ms、応答0.63MB） |
| 詳細格子 0.02°（270点） | 1.3 ms |
| 詳細格子 0.01°（900点） | 3.5 ms（JSON直列化まで含めて+95 ms、応答0.88MB） |
| ピークRSS | 85 MB |

精度は公式API（`models=jma_msm`）との突き合わせで風速平均差0.156 m/s（最大0.508）・
風向平均5.7度・降水はAPI側の0.1mm丸めの範囲内で一致。差は補間方式の違い（こちらは
双一次、公式APIは最近傍とみられる）とAPI側の丸めで説明できる。

配信の鮮度はrun初期時刻の3.5時間後（メタ情報の`last_run_availability_time`で実測）、
3時間ごと8run/日。現在時刻から先の予報の長さはrunのタイミングで32〜74時間の間を変動する。
移行前のOpen-Meteo経路も`forecast_days=2`＋当日00:00起点のため実効24〜48時間で変動して
おり、フロントは`times.length`から範囲を決めるため画面側の変更は不要。

## 実装メモ（段階1）

- `domain/msm.py`（純関数）: 配信元メタ情報のbboxと実データ形状から格子の原点・間隔を
  導出する`MsmGrid`、双一次補間、風速風向変換。格子定数を持たないのは、配信元が格子を
  変えたときにエラーにならないまま値がずれるのを防ぐため
- `infrastructure/msm_client.py`: チャンクの同期（ETag条件付きGET・予報窓外の削除）と
  読み出し。読み出しは`asyncio.to_thread`経由（ファイルI/Oとデコードが同期処理のため）
- `main.py`のAPSchedulerへ`sync_msm`ジョブを追加（`msm_sync_interval_minutes`＝30分、
  起動直後にも1回）
- `WeatherService.get_wind_grid`・`get_wind_forecast_series`をMSM経由へ差し替え
- 撤去: `weather_client.get_forecast_many`・`WIND_GRID_*`定数・`_wind_forecast_cache`
  （L1）・`infrastructure/wind_forecast_cache.py`（Redis L2）とそのテスト。
  `_fetch_json`のPOST対応も利用者が無くなったためGET専用へ戻した
- `dynamic_way_value_cache`へ渡す風のTTLは`msm_client.update_interval_seconds()`
  （配信元のrun更新間隔）から取る
- 依存追加: `omfiles==1.2.0`（win_amd64・manylinux aarch64のwheelあり。開発機・本番VMとも対応）
