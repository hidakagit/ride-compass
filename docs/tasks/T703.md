# T703. ポップアップのXSS到達経路を塞ぐ（maplibre-gl `DOM.sanitize()` バイパス、CVSS 10） 規模S＋M

状態: 未着手（2026-09-10起票、統合レビュー第6回 I-9の分割。2026-09-11に記載を全面的に見直した
——起票時の「6系へ更新する」という前提が、初日から記録されている制約と矛盾していたため）

## 背景

`maplibre-gl`（`^5.24.0`、直接依存）に
**XSS Sanitizer Bypass in `DOM.sanitize()` via Live NamedNodeMap Removal Skip**（CVSS 10）。
ライブラリ側の修正版は6.9.0で**semver major**。

## 到達可能性（実在する。経路は3箇所に特定済み）

地図ポップアップが表示する値はOSMタグ由来＝**第三者が編集できるデータ**で、
ラベル対訳表に載らない値は**生のタグ値がそのままHTML文字列へ入る**
（いずれも`components/Map/MapView.tsx`）:

| 箇所 | 式 | 生値が出る条件 |
|---|---|---|
| `buildRoadSurfacePopupHtml` | `SMOOTHNESS_LABELS[properties.smoothness] ?? properties.smoothness` | `smoothness`が対訳表に無い値 |
| 同上 | `DESIGNATION_LABELS[properties.designation] ?? properties.designation` | `designation`が対訳表に無い値 |
| `buildPoiPopupHtml` | `labels[properties.kind] ?? properties.kind` | `kind`が対訳表に無い値 |

組み立てた文字列は`Popup.setHTML()`へ渡り、そこで`DOM.sanitize()`が走る。
**つまり現在の安全性はライブラリのサニタイザ1枚に依存しており、そのサニタイザに
バイパスがある。** `next`側の2つのRCEが本プロジェクトの構成では届きにくいのに対し、
これは実際に効きうる。

（`formatRoad(surface_good)`は真偽値、`occurred_year`は数値のため対象外。）

## 6系へ上げられない既知の制約（2026-09-11に6.9.0で再確認）

**この制約は[docs/architecture.md](../architecture.md)「フロントエンド実装上の注意
（maplibre-gl バージョン固定）」にプロジェクト初日から記録されている。**
起票時の本ファイルはこれに言及しておらず、単なるメジャー更新として規模Mを見積もっていた。

記録されている内容は、6.9.0の配布物を実際に読んで**現在も有効であること**を確認した:

```js
// maplibre-gl@6.9.0 dist/maplibre-gl.mjs
function qi(){
  let e = import.meta.url;
  if(!/^https?:/.test(e)) return ``;          // http(s)でなければ空文字
  let t = e.endsWith(`-dev.mjs`) ? `maplibre-gl-worker-dev.mjs` : `maplibre-gl-worker.mjs`;
  return new URL(`./${t}`, e).href            // 動的テンプレートリテラル
}
```

Next.jsのバンドラ（Turbopack/Webpackとも）はこの動的テンプレートリテラルを静的解析できず、
兄弟ファイルを成果物として出力しない。空文字が返ると`new Worker("")`が現在のページを
読み込み、**スタイル処理・タイル取得が永久に止まる**（`isStyleLoaded()`が`true`に
ならない）——architecture.mdが記録した症状と一致する。

配布構成そのものが変わっている点も併せて確認した:

| | v5.24.0 | v6.9.0 |
|---|---|---|
| 形式 | UMD/CJS（`.js`） | **ESM専用**（`.mjs`） |
| worker | 本体へ文字列で内包しBlob URLで生成（外部ファイル不要） | `maplibre-gl-worker.mjs`が別ファイル＋`maplibre-gl-shared.mjs` |
| CSP向けビルド | `maplibre-gl-csp.js`＋外部worker | **廃止** |

v5は「バンドラに何も要求しない」設計で、v6は「バンドラが兄弟ファイルを解決できること」を
前提にしている。

**逃げ道はある**: v6にも`maplibregl.setWorkerUrl()`が残っている（型定義・実装の両方で確認）。
`maplibre-gl-worker.mjs`を静的アセットとして配信し、Map生成前にURLを明示すれば回避できる。
worker生成は`new Worker(url, {type:"module"})`を試し、失敗時はクラシックworkerへ落ちる。

## 対応方針: 実害の除去とバージョン更新を切り離す

**バージョンを上げないと直らない、という前提が誤り。** 到達経路が上記3箇所に特定
できているため、`setHTML()`へ渡す前に自前でエスケープすればライブラリのサニタイザへの
依存自体が消える。

### 段階1: 到達経路を塞ぐ（規模S、6系更新に依存しない）

生のタグ値がHTML文字列へ入る3箇所をエスケープする。対訳表に載る値は固定の文言なので
対象外でよいが、**`?? 生値`のフォールバック側は例外なく通す**。

- エスケープ関数は1つにまとめ、3箇所が同じものを使う（「同じ決まりごとを複数箇所へ
  書き写さない」）。
- 回帰テストは「`<img src=x onerror=...>`のような値を`kind`/`smoothness`/`designation`へ
  入れたとき、出力にタグとして現れないこと」を固定する。エスケープを外すと落ちることを
  確認する。
- これが済めば、`DOM.sanitize()`のバイパスは**本プロジェクトからは到達不能**になる。
  CVSS 10の依存自体は`npm audit`に残るが、実害は無くなる。

### 段階2: 6系更新の可否を判断する（規模M、トリガー付き）

段階1で実害が消えるため、こちらは「いつかは追随したい」性質の作業になる。

1. `maplibre-gl@6.9.x`＋`setWorkerUrl()`＋workerの静的アセット配信で、実機の地図が
   描画されるかを確認する。**ここで止まるならそれ以上進めない**（architecture.mdの
   「将来 v6系対応が改善された場合はアップグレードを検討する」の判断点）。
2. 描画されたら、`addProtocol`（jmatile・om）・`Marker`・
   `@maplibre/maplibre-gl-style-spec@24.10.0`との整合を確認する。
3. **地図UIの変更確認は必ずPlaywrightで実機確認する**（context.md「テスト構成」）
   ——失敗の出方が「エラー」ではなく「地図が出ない」で、vitest/tsc/eslintでは捕まらない。

トリガー: 一般公開の意思決定、または段階1完了後に余力ができた時点。

## 分離した理由（起票時の判断、記録として残す）

5→6はmajorで地図UI全体の再確認が要る。現フェーズは**一般公開前・低利用規模**で、
攻撃者が特定利用者を狙う動機が薄い。`next`（minor、低リスク）と一括にすると
両方が止まるため、確実に進められる方を先に出した（[T702](T702.md)）。
