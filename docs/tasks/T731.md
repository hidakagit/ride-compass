# T731. 静的スコア行列の列集合を読み出し時に検証する 規模M

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 I-5（P1））

## 背景

`raw_axis_ids`等は述語で決まる可変長の列なのに、世代対上げ規則は`evaluation.py`の計算式変更しか挙げず、機械ガードはdataclassのフィールド名のSHA-1しか見ない。`combine_static_edge_score_matrices`にも列一致の検証が無い。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対応方針: 列の集合を1箇所へ寄せ、読み出し時に突き合わせる

`raw_axis_ids`/`material_ids`/`categorical_material_ids`は`dataclasses.fields()`に現れない
**中身で決まる列**で、[T747](T747.md)で導出にした鍵の署名（列名の並び）は変化しない。
集合を決める述語はこのモジュールを触らずに変えられる（実例: T709が`axis_display.py`へ
`if term.weight != 1.0: return None`を入れて列集合を変えたが、変更ファイルに
`tile_score_matrix_cache.py`が含まれない）。

### 途中で見つけた、もう1つの列ずれ

`raw_axis_ids`の作られ方が**2箇所で違っていた**。空タイルの分岐は
`has_route_facing_raw_value`だけで判定し、通常タイルはそれに加えて
`axis_raw_value_array`がNoneを返した軸を落としていた（`CategoricalShape`の軸）。
`raw_value_unit`を持つcategorical軸が1本でも公開された瞬間、空タイルだけ列が1つ多くなる
——`has_route_facing_raw_value`のdocstringが「述語はここ1箇所だけが持つ」と述べて警告して
いた壊れ方そのものが、別の条件として紛れ込んでいた。

`route_facing_raw_axis_ids()`を**並びも含めた唯一の定義元**として新設し、空タイル分岐・
通常タイル構築・読み出し時の検証の3箇所が同じものを使う形にした。判定にデータが要らない
よう、`axis_raw_value_array`の「配列を返せるか」を`has_axis_raw_value_array`（軸の宣言だけで
決まる述語）へ切り出した。

### 2つの守り

- `tile_score_matrix_cache.get()`: 復元した行列の3つのidリストが現在の述語と一致しなければ
  **キャッシュミス扱い**（`read_stats["source"]="stale_columns"`）。呼び出し側が作り直すだけで
  済み、壊れた行列が探索へ入らない。版の上げ忘れをここで吸収する。
- `combine_static_edge_score_matrices`: 全タイルの列が一致することを確かめてから
  `np.concatenate`する。列数が違えばValueErrorで落ちるが、**偶然一致して意味だけ入れ替わると
  例外にならず別の軸の生値を表示する**——後者を捕まえるために名前で突き合わせる。

## 検証結果

- 読み出し時検証を`if False:`へ潰すと、`test_stale_columns_are_treated_as_a_miss`が
  復元された行列を返して落ちることを確認。
- 結合時の一致確認を潰すと、`test_combine_rejects_matrices_whose_columns_disagree`が
  `DID NOT RAISE`で落ちることを確認。どちらも戻して全緑。
- テストフィクスチャの列を述語から作る形へ直した——固定値のままだと「述語が変わった」のか
  「フィクスチャが古い」のか区別できない（実際、この変更で8件が落ちて気づいた）。
- `pytest -q -m "not postgis"` → 1,822 passed。`ruff check` → All checks passed。
- `python scripts/review_checks.py docs` → 違反なし。
