# T952. 規模ウォッチの発火6件に、次の閾値または分割を決める 規模S

状態: 未着手（2026-09-19起票、統合レビュー第11回のP2/P3）

## 背景

第11回の規模ウォッチで**6件が発火した**（`scripts/review_checks.py` 3,952行・
`backend/app/infrastructure/road_graph_repository.py` 3,236行・
`scripts/tests/test_review_checks.py` 1,642行・
`frontend/src/components/AxisStudio/AxisScoringSection.tsx` 682行・
`scripts/literal_scan.py`・`scripts/check_master_ci.py`）が、
**次の閾値を`history/size_watch.json`へ書き戻していない**。

`complexity.md`は「次閾値の提案を結果ファイルへ書いただけで終わらせないこと——書き戻さない限り
次回も同じファイルが発火し続け、安全弁が『鳴りっぱなし』になって機能しなくなる」と定めており、
**現状はその状態**。とくに`road_graph_repository.py`は個別閾値3,100を超えたまま据え置かれている。

## 対応方針

第11回の判断材料（[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)「Phase 7: 矛盾と判断」2、および「Keep List」）を踏まえ、
各ファイルを(a)理由つきKEEP・(b)抽出/分割・(c)閾値付きKEEPの個別設定のいずれかへ分類する。
**閾値はユーザー承認のうえ`size_watch.json`の`thresholds`へ書き戻す**。

`review_checks.py`は、分割するなら計測群（`size`/`metrics`/`duplication`/`trigger`、約340行）を
出し検知器群は据え置くのが構造に沿う（検知器群とmutateは同じ理由で一緒に動くため、
分けると`DETECTOR_ENFORCEMENT`と`guard_probe_*`が離れ、前回P0の「表と配線のずれ」を作りやすい）。

## 完了条件

- 発火6件すべてが3分類のいずれかに割り当てられている
- 閾値付きKEEPにしたものは`history/size_watch.json`の`thresholds`へ書き戻されている
