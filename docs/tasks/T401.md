# T401. RouteScorerをdistance/difficultyの2指標へ単純化

状態: 完了（2026-08-30）

- 背景: 詳細はT400.md「5. 候補順位付け（RouteScorer）をdistance/difficultyの2指標へ単純化」参照。
  `RouteScorer`の`elevation`/`wind`/`road`をハードコード計算から`overall_difficulty`（既存
  フィールド、軸スタジオの重みで既に合成済み）参照へ置き換え、`scoring.yaml`を
  `distance_weight`/`difficulty_weight`の2キーへ単純化する。
- 実装内容:
  - `backend/app/scoring.yaml`: 4キー→`distance_weight`/`difficulty_weight`の2キー
  - `backend/app/api/routers/routes.py`: `ScoringWeights` Pydanticモデルを2フィールドへ
  - `backend/app/services/route_scorer.py`: `RouteScorer.score()`の`component_scores`を
    `distance`/`difficulty`（`candidate.overall_difficulty`参照）へ書き換え。
    `_build_breakdown`等の汎用ロジックは変更不要
  - フロント: `evaluationAxes.ts`の`SCORING_AXIS_META`・`WeightPanel.tsx`の
    `DEFAULT_SCORING_WEIGHTS`を2キーへ（`SCORING_FIELDS`はカタログから汎用生成のため
    JSX側の変更は不要だった）
  - OpenAPI再生成（`export_openapi.py`→`npm run generate:api`）、`docs/architecture.md`の
    関連記述（RouteScorerの説明・リクエスト/レスポンス例・scoring.yaml例・「距離・標高・風・
    路面の4指標のみ」という記述）を更新
  - テスト: `test_route_scorer.py`を新しい2指標ベースへ全面書き換え。
    `test_road_graph_engine.py`/`test_openrouteservice_engine.py`/`test_route_generator.py`/
    `test_routes_generate.py`のWEIGHTS定数・個別テストケースを更新。フロント側は
    `WeightPanel.test.tsx`（入力欄数4→2の期待値修正）・`ComparisonPanel.test.tsx`・
    `routeApi.test.ts`・`page.test.tsx`・`e2e/fixtures.ts`のfixtureを更新
- 検証結果: backend全テスト1388件通過（1件failは他セッションの並行作業[新規migration]に
  起因する無関係な既存失敗、T401とは無関係）。フロントの関連テスト40件通過、`tsc --noEmit`・
  `eslint`ともクリーン
