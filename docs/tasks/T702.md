# T702. nextを16.3.4へ更新する（critical 1件の解消） 規模S

状態: 完了（2026-09-10。critical 2→1・high 3→0。残るcriticalはmaplibre-glのみで[T703](T703.md)へ分離済み）

## 実施結果

`next`・`eslint-config-next`を16.3.4へ（`--save-exact`、元も16.3.0固定だったため流儀を維持）。
`sharp`はnextの推移依存のため同時に解消した。

`js-yaml`・`@redocly/openapi-core`のhigh 2件は`npm audit fix`（`--force`なし）で解消した。
どちらも`eslint`・`openapi-typescript`からの推移依存＝ビルド時ツールで本番イメージには入らず、
直接依存の版は変わっていない（`maplibre-gl`へは触れていないことを確認済み）。

| | 実施前 | 実施後 |
|---|---|---|
| critical | 2（next・maplibre-gl） | 1（maplibre-glのみ） |
| high | 3（sharp・js-yaml・@redocly） | 0 |

検証: lint・`next typegen && tsc --noEmit`エラー0、vitest 1,144 passed、
`npm run build`（standalone）成功、e2e 2 passed。

## 背景

`npm audit`が critical 2 / high 3 を報告している（前回レビュー時点は全0件で、上流の新規advisoryによる）。
本タスクはそのうち`next`だけを扱う（`maplibre-gl`は[T703](T703.md)へ分離）。

| 深刻度 | パッケージ | 現在 | 修正版 |
|---|---|---|---|
| critical | `next` | 16.3.0（直接依存） | **16.3.4（semver minor）** |
| high | `sharp` / `js-yaml` / `@redocly/openapi-core` | 推移依存 | いずれも修正あり |

`next`のadvisoryは2件:

- Unauthenticated RCE on **windows-hosted** servers（CVSS 9）— **該当しない**
  （`frontend/Dockerfile`は`node:20-slim`、Linuxコンテナ）
- Image Optimization APIのAVIF経由RCE — 直接の攻撃面は小さい
  （`next/image`の利用が`frontend/src`配下に**0件**、`next.config.ts`に`images`設定なし、
  `public/`にAVIFなし）。ただし`/_next/image`エンドポイント自体はstandaloneサーバに存在するため
  「無い」とは言い切れない

## 対応方針

`next`を16.3.4へ（minorなので低リスク）、推移依存のhigh 3件も併せて解消する。
更新後は`npx next typegen && npx tsc --noEmit`・`npm run lint`・`npm test`・
`npm run test:e2e`まで通す（standalone構成の起動確認までE2Eが見る）。
