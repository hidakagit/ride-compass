# T705. review_checks.pyの検知範囲を広げる（検知器自身の適用範囲の穴） 規模M

状態: 未着手（2026-09-10起票、統合レビュー第6回。[T693](T693.md)の後）

## 背景

`scripts/review_checks.py docs`は「違反なし」を返すが、**検知器自身の適用範囲に3つの穴**があり、
実際にはそこから違反が入っている。[T656](T656.md)（経緯コメント検知の穴を塞ぐ）・
[T675](T675.md)（未定義CSSトークン検知）の**直後の差分で、別の穴から再発している**。

### 1. 経緯コメント: 時制表現を含まない

`review_checks.py:83-87`の`NARRATIVE_PATTERN`は
`以前は|従来は|旧「|旧『|旧T[0-9]|旧実装|旧デザイン|旧方式|改善計画T[0-9]+|T[0-9]{3,4}で|指摘を受け|…`で、
**「〜だった頃は」「〜ころは」という時制表現を含まない**。そのため次の2件が素通りしている:

- `frontend/src/services/regionApi.ts:159-160`「独自実装だった頃はここだけrequestIdを残さず…」
- `frontend/src/lib/axisMaterialsCatalog.ts:9-10`「手書きで持っていたころは…」

### 2. 未定義CSSトークン: `.tsx`を見ていない

`find_undefined_css_tokens`は`if not f.endswith(".css"): continue`で`.tsx`を対象外にしている。
`.tsx`内の`var(--…)`参照は31件あり（`app/error.tsx:35`の`var(--color-muted)`を含む）どれも検査されない。
`docs/frontend-design-system.md:65`は「存在しないトークン名は機械的に弾く……pre-commitでブロックする」と
**無条件に書いており、契約を過大に主張している**。

またフォールバック付き参照（`var(--shadow-md, …)`・`var(--font-size-xs, …)`・
`var(--color-warning-soft, …)`）も検知対象外で、実際に
**`--font-size-xs`は参照3箇所・定義0件・実効値2種**（0.72rem/0.75rem）という状態が発生している。

### 3. 死んだ参照: ファイル名しか見ていない

`find_dead_file_refs`（`:280-290`）はdocs/modulesの**バッククォート付きファイル名**のみを見るため、
**識別子は全て素通りする**。`docs/modules`全15ファイルの走査で、実装に存在しない識別子を
名指しする箇所が10件残っている（[T707](T707.md)で一覧を扱う）。

## 対応方針

3つの検知の適用範囲を広げる。**あわせて、各検知器について「意図的に壊したときに落ちること」を
確認する回帰テストを置く**（T656はこの形の回帰テスト11件をCIへ追加しており、その方針を
新しい範囲へも適用する）。

## この穴が示していること

CLAUDE.md・consistency.mdは「同種の手動同期ペアで2回以上の再発が観測されたら、
手順の再徹底ではなく**機械的検知の追加**を既定の第一候補にする」と定めており、この方針自体は
正しく機能している。しかし**検知器自身の適用範囲を検証する段がどこにも無い**ことが、
統合レビュー第6回の中心的な発見（I-1）と同根の問題として現れている。
