# T698. 生値の精度をdifficulty用の丸めから分離する 規模M

状態: 未着手（2026-09-10起票、統合レビュー第6回 I-5）

## 背景

[T687](T687.md)が掲げた「得点だけでは軸単体で判断できないので、目盛りに依存しない
**絶対の事実である生値**を添える」（docs/design-principles.md 構造仕様11）が、
事故密度軸で成立していない。

`domain/route.py:205`の`merge_axis_raw_values`が、0〜100のdifficulty専用集約
`distance_weighted_difficulty`（`domain/difficulty.py:84`で`round(total, 1)`）を流用している。
区間単位（`road_graph_engine.py:1577`）では未丸めのfloatだが、
`aggregate_segments_into_bins`と`route_generator.py:575`の2段で**小数1桁へ丸められる**。

公開軸`accident`の単位は`件/(km・年)`で、`domain/material_catalog.py:385-389`の代表点は
**少ない=0.02 / 普通=0.1 / 多い=0.3**。実データの典型値0.03〜0.15は「0.0」か「0.1」にしかならず、
0.05未満はすべて0.0になる。

frontend `components/RouteAxisProfile/axisRawValue.ts:34-38`の`formatNumber`は
絶対値1未満で`toFixed(2)`を使う前提のため「**0.00件/(km・年)**」と表示され、
**事故ゼロの道と完全に区別できない**。単位が`/km`で終わらないため実数の併記
（`totalUnitFor`、同`:28-30`）も出ない。

## テストがこれを検出できない理由

- `backend/tests/test_route.py:292-310`の生値テストはすべて0.5以上の値（0.5・2.5・4.0）。
  `test_route_generator.py:460-477`も4.0/0.0/1.0のみ。
- `frontend/src/components/RouteAxisProfile/axisRawValue.test.ts:30,34`は
  `formatAxisRawValue(0.08, "回/km", null)`のように**実運用では到達しない入力**の期待値を固定している。
  「配信される精度で何が表示されるか」（0.04→0.0→"0.00"）を押さえたテストは無い。

## 対応方針

生値の集約をdifficulty用の丸めから分離し、桁数を材料の`unit`と代表点のスケールから導く
（または丸めずに配信して表示側で決める）。`domain/route.py:179-184`の`_merge_axis_value_dict`の
docstringが共有者を「両フィールド」（difficulty系2つ）と書いているが、現在の呼び出し元は
`merge_axis_raw_values`・`merge_material_values`を含む4つで、**この記述が丸めの流用を招いた**。

frontendの表示精度・テストの入力も配信される精度に合わせて揃える。
