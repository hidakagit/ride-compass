# T758. 生成中・エラー・候補0件のフィードバックが操作している場所から見えない

規模M。
状態: 未着手（2026-09-12起票）

## 背景

- **生成中**: 合図はボタン文言（「生成中...」→「生成中...(N秒経過)」）だけ。モバイルではボタン幅に収まらず「生成中…」に省略され経過秒が見えない。旧候補と地図はそのまま残り、中断手段も無い
- **エラー**: 候補0件・429・検証エラーの文言は`page.tsx: renderRouteSectionBody`（「ルート設定」本文）にしか出ない。デスクトップは区分を畳んだまま見出し行のボタンで生成できるため、エラーが畳まれた本文の中に出て見えない
- **候補0件**: `setRoutes([])`で結果欄が「『ルート生成』を押すと候補がここに並びます」に戻り、押したのに無反応に見える
- **条件変更のヒント**: 「条件が変更されています」は結果欄の先頭にだけ出て、設定を変えている場所からは見えない

個票は[history/2026-09-12_ui.md](../../.claude/commands/review/history/2026-09-12_ui.md)のF-5・F-6・F-23。

## 調査項目

1. **状態の出し先を1箇所に決める**。生成ボタンの近く（見出し行）と結果欄のどちらが「操作している場所」か。デスクトップ（設定と結果が縦に並ぶ）とモバイル（シートが排他）で同じ答えになるか
2. **旧候補の扱い**。生成中に前回の候補を残す（比較のため）なら「前回の結果」と分かる表示が要る。消すなら空状態の文言を「生成中」に切り替える
3. **候補0件の理由**。backendの`no_candidates_reason`を結果欄に出す（現在は設定本文のエラー文言に流している）
4. **中断**。バックグラウンドジョブ化済み（queued/running）のため、フロントから取り消せるか。取り消せないなら「押し直し」の扱いを決める
5. モバイルのボタン文言の省略は、経過秒をボタン以外へ出せば解消するか

## 完了条件

- デスクトップで「ルート設定」を畳んだまま候補0件・429を起こしたとき、文言が見える位置に出ることを示す
- 390px幅で生成中の経過が読めることを示す
- 候補0件時に結果欄が生成前の案内文へ戻らないこと
