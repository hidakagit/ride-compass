# T398. 風グリッド（Open-Meteo）のキャッシュをSQLiteからRedisへ移行する検討

状態: 起票のみ（背景メモ、未着手）

- 発端: 地図×評価軸の再設計セッション（2026-08-29〜30）で、軸スタジオが作る「道路」グループの
  軸（車ストレス等）とは別に、「環境」グループ（標高・気象）を新設し、風は面表示
  （時刻＋方位スライダー＋`gridFill`）に統一する方針を決めた。この面表示の裏側データ
  （`WindGridPoint`、Open-Meteo経由）は現状`cache_db.py`のSQLite永続キャッシュ
  （T195、標高キャッシュと相乗り）を使っているが、JMAアメダス連携（T387）は既にRedisを
  導入済みのため、キャッシュ基盤をRedisへ1本化できないか、という提案がユーザーから
  出た。
- 想定作業: `weather_client.get_forecast_many`のL1（プロセス内メモリ）→L2（現状SQLite）
  →実フェッチという既存の3段構成のうち、L2をRedisへ置き換える。TTL・失敗時のstale
  フォールバック許容幅（T195で30分→3時間、24時間へ拡大済み）等の既存の運用値は
  そのまま踏襲できるか確認が必要。
- **注意**: Redis化は「環境グループの風表示」を支えるキャッシュの高速化・基盤統一が
  目的であり、「道路グループの軸をタイルへ焼き込む」話とは別（風は進行方向依存・
  時刻依存のため、Redis化してもMVTタイル焼き込みの対象にはならない、という整理が
  同セッションで確定済み）。
- トリガー: ユーザーが着手を判断した時点。標高キャッシュ（同じcache_db.py）を含めて
  検討するかは着手時に確認する。
