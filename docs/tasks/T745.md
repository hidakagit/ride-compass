# T745. 目的地モードでmax_routes=1のとき軸の重みが結果に反映されない 規模S〜M

状態: 完了（2026-09-12。起票は2026-09-11、T696の派生（統合レビュー第7回で発見））

## 背景

`route_generator.py`が距離最短ルートを先頭固定したうえで`candidates[:max_routes]`するため、`max_routes=1`では返る唯一の候補が常に距離最短になり、軸設定が一切効かない。T696完了時に本文へ残されたまま起票されていなかった。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対応方針: 先頭固定の目的から条件を導く

最短経路を難易度順の外へ出して先頭へ固定するのは、「軸設定に沿った候補が最短からどれだけ
余分に走るか」を読むための**基準線**だからである。つまり**比べる相手があって初めて基準**で、
1本だけ返すなら比べる相手が無い。`max_routes`が1のときだけ固定をやめる。

```python
if max_routes >= 2:
    candidates.sort(key=lambda c: not c.is_shortest_distance)
candidates = candidates[:max_routes]
```

`max_routes`の下限は1（`routes.py`の`Field(ge=1, ...)`）なので、この条件は
「比べる相手が1本も残らないとき」とちょうど一致する。

frontend側の手当ては要らない。タブの「+4.0km」表記（`lib/routeTabLabel.ts`）は
`shortestDistanceKm`がnullのときnullを返す形で、基準線が無い場合を既に扱っている。

## 検証結果

| 確認 | 観測 |
|---|---|
| 直す前の壊れ方で落ちる | 条件を`>= 1`（＝常に固定）へ戻すと、新しいテストが`assert 18.0 == 22.0`で落ちる——返るのが距離最短の18kmで、難易度10.0の22km候補ではない |
| 境界の反対側 | `max_routes=2`では先頭固定を維持する（同じフィクスチャで`[18.0, 22.0]`・先頭が`is_shortest_distance=True`）。条件を戻しても通るため、この1本だけでは修正の証拠にならない——上の1本と対で意味を持つ |
