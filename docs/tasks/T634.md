# T634. targetTimes*.jsonの取得をタイルと同じ直接配信オリジンへ揃える

規模S。2026-09-07完了。

## 背景

JMA動的タイル系のうち、タイル本体は`lib/tileBaseUrl.ts: tileBaseUrl()`で
`NEXT_PUBLIC_TILE_BASE_URL`（本番ではbackendのオリジン、HTTP/3対応のnginx）へ直接
取りに行くが、`targetTimes*.json`（`jmaNowcastFrames.ts`・`precipitationNowcast.ts`・
`lidenLayer.ts`・`riskMap.ts`）は相対パスのままで、Render frontendの
`next.config.ts: rewrites`プロキシを経由する。

実測レイテンシの差:

| 経路 | 実測 |
|---|---|
| backend直接配信 | 0.049〜0.172秒 |
| Render frontend経由 | 0.404秒 |

**タイルURLは`targetTimes`が返るまで確定しない**ため、この0.4秒は初回表示の
クリティカルパスに直列で乗る。降水（N1/N2）・雷竜巻（N3）・rasrf・riskで計4〜5本ある。

## 対応方針

`targetTimes*.json`のURLにも`tileBaseUrl()`を適用する。

**CORSの追加作業は不要だった**。起票時は「別オリジンへの`fetch()`になるためCORS許可が
要る」と見込んでいたが、他のAPI（`/api/weather`等）が既に`API_BASE_URL`経由でbackendへ
直接fetchしており、本番の応答を実測しても許可済みだった。

```
access-control-allow-origin: https://ride-compass-frontend.onrender.com
access-control-expose-headers: X-Request-ID
```

`targetTimes`だけが相対パスのまま取り残されていた、というのが実態。

## 実装メモ

- `jmaNowcastFrames.ts`へ`jmaProxyUrl(path)`を追加し、JMAプロキシ配下のURL生成を1箇所へ
  集約した。`tileBaseUrl()`は`window`を参照するため、モジュール直下の定数ではなく
  **呼び出し時に評価する関数**として持つ（SSRで空文字に固定されるのを避ける）。
  そのため各所の`const XXX_URL = ...`は`const xxxUrl = () => ...`へ変えている。
- 対象は時刻一覧5本（nowc N1/N2/N3・rasrf・risk）と、雷放電位置データのGeoJSON1本。
  後者も同じくアプリの`fetch()`で読むため同じ問題を抱えていた。
- **タイル本体側11箇所も同じヘルパーへ寄せた**（`precipitationNowcast.ts`2・
  `thunderNowcast.ts`1・`MapView.tsx`8）。これらは`${tileBaseUrl()}${JMA_TILE_BASE_URL}`を
  各所で手書きしており、**「配信オリジンを付けるかどうか」が箇所ごとの判断に委ねられていた
  ことが、時刻一覧6本で付け忘れが起きた原因**である。
- さらに、オリジンだけを一本化しても
  `.../data/<group>/<basetime>/<member>/<validtime>/surf/<element>/{z}/{x}/{y}.<ext>`という
  **パス構造自体が12箇所（上記11＋`riskMap.ts: tileUrlTemplate`）に写経されたまま**だった。
  `jmaTileUrlTemplate(target)`・`jmaPlaceholderTileUrl(group, element)`・
  `jmaElementUrl(target, suffix)`を追加し、呼び出し側は**系統と要素だけを渡す**形にした。
  パス構造を組み立てる場所は`jmaNowcastFrames.ts`の1箇所のみになり、雷放電位置データの
  GeoJSON（末尾が`data.geojson`）も同じ構造定義から作る。

## 検証結果

frontend全体 1,060件パス、`tsc --noEmit`・`eslint`ともにクリーン。

`jmaNowcastFrames.test.ts`へ3件追加し、配信オリジンが設定されていればタイルと同じ絶対URLに
なること・末尾スラッシュが重複しないこと・未設定（ローカル開発）では相対パスのまま従来
どおり動くことを検証する。

本番反映後のレイテンシ実測は未実施。

## 保留した場合の影響

初回表示が0.4秒×本数ぶん遅いままになる。[T632](T632.md)のCache-Controlは
`targetTimes`にも付くが、`max-age=60`と短くクリティカルパスの初回アクセスは救えない。
