# T634. targetTimes*.jsonの取得をタイルと同じ直接配信オリジンへ揃える

規模S。起票のみ・実装未着手。

## 背景

JMA動的タイル系のうち、タイル本体は`lib/tileBaseUrl.ts: tileBaseUrl()`で
`NEXT_PUBLIC_TILE_BASE_URL`（本番ではbackendのオリジン、HTTP/3対応のnginx）へ直接
取りに行くが、`targetTimes*.json`（`jmaNowcastFrames.ts`・`precipitationNowcast.ts`・
`lidenLayer.ts`・`riskMap.ts`）は相対パスのままで、Render frontendの
`next.config.ts: rewrites`プロキシを経由する。

実測レイテンシの差:

| 経路 | 実測 |
|---|---|
| backend直接配信 | 0.049〜0.172秒 |
| Render frontend経由 | 0.404秒 |

**タイルURLは`targetTimes`が返るまで確定しない**ため、この0.4秒は初回表示の
クリティカルパスに直列で乗る。降水（N1/N2）・雷竜巻（N3）・rasrf・riskで計4〜5本ある。

## 対応方針（案）

`targetTimes*.json`のURLにも`tileBaseUrl()`を適用する。ページとは別オリジンへの
`fetch()`になるため、backend側にCORS許可（`Access-Control-Allow-Origin`）が要る
（タイルはMapLibreの`<img>`/Worker経由で取得されるためCORS設定なしで動いていたが、
`fetch()`は同じようにはいかない）。

## 保留した場合の影響

初回表示が0.4秒×本数ぶん遅いままになる。[T632](T632.md)のCache-Controlは
`targetTimes`にも付くが、`max-age=60`と短くクリティカルパスの初回アクセスは救えない。
