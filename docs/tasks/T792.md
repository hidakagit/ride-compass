# T792. A*のヒューリスティックが実データで効いていない

規模S〜M。
状態: 未着手（2026-09-13起票）

## 背景

[T790](T790.md)段階1の実測で、2点間探索が訪れるNodeの割合が**68.4%**だった（dev DB・
蒲田付近→王子・経路25.5km、nodes=76,960のうち52,639をpop）。`domain/routing.py:
LazyRoadGraph`のdocstringにある「A*は全Edgeの2.79%しか評価せずに済む」は**合成グリッド
グラフでの値**で、実データの20km級では桁が違う。

コストは`distance_m × (1 + P × difficulty / 100)`で距離の1〜2倍に膨らむのに、A*の下界
（`road_graph_engine.py: _build_estimate_cost_fn`）は直線距離のまま。下界が実コストから
大きく離れているため、A*が実質ダイクストラとして動いている。状態の取り方（ノード／有向区間）
を変えても訪問割合は68%で変わらなかったため、状態設計ではなく下界の問題。

## 調査項目

- 下界の強め方と、admissibility（真の最小コスト以下であること）の担保。例えばbbox内の最小
  difficultyを掛ける（`distance × (1 + P × min_difficulty / 100)`）なら下界であることは
  保てるが、実データで最小difficultyが0に近ければ効果が出ない——実際の分布を見て決める
- 強めた下界で訪問状態数・探索時間がどれだけ減るか。`backend/benchmarks/
  bench_t790_turn_expanded.py`が訪問状態数を数えるので、下界を差し替えて比較できる
- 一対全木（`build_shortest_path_tree`）はヒューリスティックを使わないため対象外。効くのは
  2点間探索（`shortest_path_node_ids_lazy`を使う経路）だけで、周回生成の支配的な部分が
  一対全木ならば全体への効きは限定的になる。まず効く範囲を見積もってから着手する
