# T656. 経緯コメントの機械的検知の穴を塞ぐ（docstring・CSS・パターン）

規模S。状態: 完了（2026-09-08）。

## 背景

`docs/comments.md`の経緯コメント禁止は[T570](T570.md)で機械的な強制を入れ、CLAUDE.mdにも
「新規混入分はpre-commitフック・CIが機械的に検出しブロックする」と書いてある。
しかし統合レビュー第5回で、**その検知器に3つの穴があり対象範囲の追加行が実際に
すり抜けている**ことが判明した。

「機械が止めてくれる」という前提で運用しているのに実際には止まっていない、というのが
問題の本質である。[T567](T567.md)で既存分を一掃しても、この穴から入り続ける。

| 穴 | 何が漏れていたか |
|---|---|
| Pythonは`#`しか見ない | **docstringが完全に素通り**。backendの説明文は大半がdocstringにある |
| パスに`.css`が無い | CSS Modulesのコメントが素通り。本プロジェクトはCSSへ設計意図を長文で書く運用 |
| パターンが`改善計画T\d+`＋`で`/`：`を要求 | 「改善計画T572**。**」「改善計画T87**/**T606」「改善計画T278**、**」が素通り |

実例（いずれも本レビュー範囲の追加行）: `routers/__init__.py:16,29`・`jma_tile_specs.py:11`・
`attributes.py:90,92`・`landcover.py:8`・`page.module.css:387-391`・`axisLayers.ts:20`。
`page.module.css`のものは「ユーザー要望」「実機フィードバック」という**既存パターンに
完全一致する文言**で、パスさえ対象なら確実に止まっていた。

## 実施内容（2026-09-08）

### 1. Pythonのdocstringを走査対象にした

行単位のヒューリスティックでは三重引用符の開閉を追えない（diffの追加行は連続していない）
ため、`python_comment_lines()`を追加してファイル全体を`ast`で解析し、
module/class/functionのdocstringが占める行を求め、`tokenize`で`#`コメント行を足す。
検出ループは`.py`についてこの行番号集合で先に絞り込む。解析できないファイル
（編集途中の構文エラー等）は`None`を返して従来どおり全行を対象にする。

### 2. CSS Modulesを対象に加えた

`SOURCE_COMMENT_PATHSPECS`へ`frontend/src/*.css`を追加し、`comment_only()`へCSS分岐
（`/* */`のみ。`//`はCSSのコメントではない）を実装した。複数行ブロックの継続行は
JSXコメントと同じ状態保持方式で追う。

### 3. パターンを緩めた

`改善計画T[0-9]+`から区切り文字の要求を外し、言い換え3種（`旧実装`・`旧デザイン`・
`旧方式`・`ユーザーから`・`していたのを`）を足した。

### 4. 拾えるようになった既存違反を是正した

パターンを緩めた結果、`docs/modules`の記載粒度違反が**0件→20件**になった。
いずれも「（改善計画Txxx）」という括弧の経緯参照で、8ファイルすべてを現在形の記述へ
書き換えて**0件へ戻した**。あわせて全件監査で残っていた記載漏れ1件
（`Map/secondaryAxes.ts`）も`static-map-layers.md`へ追記した。

**結果: `review_checks.py docs`の全件監査が「違反なし」になった。**

ソースコメント側は参考出力が57件→79件へ増えたが、これは[T567](T567.md)の対象
（既存の残存分）であり、本タスクでは扱わない。

### 5. 検知器自体の回帰テストを置いた

`scripts/tests/test_review_checks.py`（11件）。**過去に実際すり抜けた形**を
テストケースとして固定してある——句点・スラッシュ・読点区切りの「改善計画Txxx」、
言い換え、Pythonのmodule/function docstring、CSSの単行・複数行ブロック。
あわせて誤検出しないこと（現在形の制約表現・実装コード・文字列リテラル・CSS宣言）も
検証する。`.github/workflows/docs-consistency.yml`へ実行ステップを足し、
検知器が壊れたらCIが落ちるようにした。

### 6. 「機械が止める」という表現を実態へ合わせた

`docs/comments.md`へ「検知の範囲と限界（過信しないこと）」節を追加した。
`NARRATIVE_PATTERN`は語彙の列挙であり言い換えは原理的に取りこぼすため、
**機械的強制は典型例を確実に止めるためのもので網羅の保証ではない**こと、
「機械が止めるから自己申告のチェックは省いてよい」とは考えないことを明記した。
検知器の能力を実際より高く見せている記述が、自己申告チェックを緩める方向に働くのが
本質的な危険であるため、パターンの強化とセットで行う必要がある。
