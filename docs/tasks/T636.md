# T636. JMAタイルのRedisキャッシュからbase64+JSONの包装を外す

規模S。起票のみ・実装未着手。

## 背景

`infrastructure/jma_tile_redis_cache.py`は、`redis_client.py`が`decode_responses=True`
（文字列前提）でクライアントを生成するためPNG/PBFの生バイト列を直接保存できず、
base64エンコードした文字列をJSONへ包んで1キーに保存している。

キャッシュヒットのたびにJSONパースとbase64デコードが走り、Redis上のメモリも約1.33倍に
なる。画面表示中の可視タイルは災害チップだけで7ソース×約40枚のため、ヒット時でも
無視できないCPUを使う。

## 対応方針（案）

バイナリ用の別Redis接続（`decode_responses=False`）を用意し、タイル本体を生バイトで
保存する。Content-Typeはパスの拡張子（`.png`/`.pbf`のみ）から導出するか、別キーに置く。

## 保留した場合の影響

[T632](T632.md)（ブラウザキャッシュ）が効けばbackendへ到達するリクエスト自体が大きく
減るため、単独での効果は限定的。逆に言えばT632を入れた後に実測して、なお
backendのCPUが問題になる場合にだけ着手すればよい——**T632・T633の効果を実測してから
判断する**。
