# T576: precompute_elevation_attributesの高速化（地理的順序＋タイル単位バッチ化）

状態: コード対応完了（2026-09-04起票・同日完了）。本番への再実行は別途ユーザー確認後に実施。

## 背景

[T575](T575.md)（`_tile_grid_cache`のLRU上限化）実施後、Fableモデルへ本番規模での
さらなる高速化を検討依頼したところ、以下が判明した:

- `_fetch_all_edge_ids`のEdge取得順が地理的にバラバラ（実質`edge_id`文字列順＝OSM
  way id順）なため、T575のLRU上限（500）と組み合わせると、1チャンクあたり本番規模で
  約70〜100枚のタイルをディスクから再パースする見込みで、**T575時点の見積もり
  （約2.5時間）より遅くなりうる**（現状のまま=3.7〜5.5時間の見込み）。
- Edgeを地理的順序（`ORDER BY geom`）へ変更すると、1チャンクが触る一意タイル数が
  大幅に減り（dev実測で65.2枚→4.7枚）、再パースがほぼ解消する（→2.2〜2.5時間）。
- 点単位のasyncioタスク生成・`log_external_call`のオーバーヘッドが、キャッシュヒット
  経路のコストの9割を占める（dev実測、12,000点で0.41秒のうち0.34秒相当）。タイル単位の
  バッチAPIへ書き換えるとこの経路が約10分の1になる。
- 同一タイルへの重複リクエスト（`Semaphore(5)`分の先頭点が同じタイルを重複取得）が
  発生しうる。

Fableの提案A（地理的順序＋anti-join）・B（同一タイルのsingle-flight）・
C（タイル単位バッチAPI＋同期補間）を組み合わせると、本番規模で約30〜45分まで
短縮できる見込み（すべてdev実測からの外挿、確定値ではない）。

## 対応方針

A・B・Cをまとめて実装する。いずれも「どのEdgeを計算するか」「計算結果の値」を
変えない（冪等性・再実行安全性に影響しない）。あわせてユーザー判断で、Fable提案の
E（バッチのRedis cache-aside迂回）も対応した。

## 実施内容（2026-09-04完了）

- **A（地理的順序＋anti-join）**: `precompute_elevation_attributes.py:
  _fetch_all_edge_ids`を、未計算Edgeのみanti-joinで絞り込み、`ORDER BY geom`で
  地理的順序へ変更。
- **B（single-flight）**: `elevation_client.py`へ`_in_flight_tile_fetches`
  （モジュールグローバル、タイルキー→`asyncio.Future`）を追加。同一タイルへの
  同時フェッチは1回へ束ねる。
- **C（タイル単位バッチAPI）**: `ElevationClient.get_elevations(client, points)`を
  新設。`DEM_TYPE_PRIORITY`を1ラウンドずつ進め、そのラウンドで未解決の地点が
  必要とするタイルをまとめて1回のフェッチへ束ねる（最大4ラウンド）。`get_elevation`
  （1地点版）は`get_elevations([point])`を呼ぶ薄いラッパーへ変更（結果は同一）。
  `MAX_CONCURRENT_REQUESTS=5`は`ElevationAttributeService`から`ElevationClient`
  （タイル単位のフェッチ）へ移設。`ElevationAttributeService._compute_attributes`
  （旧`_get_attribute`）はEdge横断で形状点をまとめ`get_elevations`を1回呼ぶ形へ
  書き換え。
- **E（Redis回避、ユーザー追加判断）**: `RoadGraphRepository.get_edges_with_geometry`
  へ`use_cache: bool = True`引数を追加。`False`時はRedis cache-asideを迂回し
  PostGISへ直接問い合わせる。バッチ側は`use_cache=False`で呼ぶ。
- `docs/modules/backend/elevation.md`をA〜Cの変更・データフロー図・同時実行制御の
  記述に合わせて更新。
- テスト: `tests/test_elevation_attribute_service.py`の`FakeElevationClient`へ
  `get_elevations`を追加（既存の`call_count`アサーションはそのまま通過）。
  `pytest -q -m "not postgis"`（1373件）green。
