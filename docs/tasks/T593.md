# T593: 専用way値レイヤーの配信値を難易度スケールへ統一しdisplay_thresholds_overrideの二重帰属を解消する

状態: 未着手（2026-09-05起票、分割元は[T590](T590.md)）

## 背景

風軸の`display_thresholds_override`がルート前（材料スケールm/s、`page.tsx:
dedicatedWayValueBoundaries`→`windAxisColorExpression`）とルート後（難易度0〜100、
`routeStyleModes.ts: routeColorableModeFromAxis`）の2系統で共用されている。勾配は前後とも
符号付き%で整合するが、風は不整合。本番の`[10,20,30,40,50]`は難易度スケールとしては
妥当な値で、[T587](T587.md)で「異常値」とされた真因はこの二重帰属である可能性が高い。

## 対応方針

- `GET /api/region/dynamic-way-values/{material_id}/...`の配信値を、その軸のshapeが
  signed-abs（`breakpoint_linear`かつ`preprocess="abs"`かつterms単数）でなければ軸の難易度
  （`evaluate_axis_scalar`で軸スタジオのbreakpointsを適用した0〜100）にする。signed-absの
  軸（勾配）は符号付き材料のまま。分岐はshape属性で行い、`routeStyleModes.ts:
  isSignedAbsShape`と同じ判定をbackendへ寄せる。
- `WindWayService`は風の材料をタイル中心の風から計算した後、軸の評価まで行って返す。
  材料の計算はT591の1関数を経由し、第4の式重複を解消する。
- 軸カタログに「専用レイヤーの配信値の種類」（`difficulty` / `signed_material`）と単位を
  含め、フロントは凡例の単位・色式・しきい値のフォールバックをそこから決める。
  `windAxisLayer.ts`の`WIND_AXIS_THRESHOLDS`・"m/s"固定・風専用の色式は撤去し、
  `gradientAxisLayer.ts`と共通の汎用機構（配信値の種類で分岐）へ畳む。
- 本番DBの風軸`display_thresholds_override=[10,20,30,40,50]`は難易度スケールとして
  そのまま有効になる。段階ラベル（`display_band_labels_override`）を5段階ぶん設定する
  （axis_admin API経由、[docs/deployment-sync.md](../deployment-sync.md)の完了条件）。

## 対象ファイル

`backend/app/services/wind_way_service.py`・`services/gradient_way_service.py`・
`api/routers/region.py`・`api/routers/axis_catalog.py`・`domain/axis_display.py`・
`frontend/src/components/Map/windAxisLayer.ts`・`gradientAxisLayer.ts`・`MapView.tsx`
（`makeEnsureDedicatedWayValueLayer`）・`page.tsx`（`dedicatedWayValueBoundaries`）・
`docs/modules/backend/dynamic-way-values.md`・`docs/modules/frontend/`該当モジュール。

## 完了条件

- 風軸について、ルート前の全道路色分けとルート後のルート線色分けが同じしきい値・同じ凡例で
  描かれる（実機確認、Playwright headless）。
- `display_thresholds_override`の意味が軸ごとに1つになっている（材料スケールと難易度
  スケールの混在が無い）。
- フロントに風の名前を持つ色分けファイルが残っていない。
