# T936. 検知器の「既知のGAP」を落ちるようにし、記法と母集団の穴を塞ぐ 規模M

状態: 完了（2026-09-19。機構と2つの穴を直し、15件の穴すべてへ実測付きの理由を書いた。**穴そのものは0件しか閉じていない**——実測の結果、当初の完了条件「GAP 0件」は今回の射程では達成すべきでないと判断した。下記「閉じなかった穴と、その判断」参照）

## 背景

`review_checks.py docs`はフル実行で「違反なし」を返すが、その0件の相当部分は「違反が無い」ではなく
「母集団に入っていない」である。`guard_probe_edges`は穴を「既知のGAP」として宣言している（22件中15件）が、
`cmd_mutate`は件数を印字するだけで落ちないため、閉じる圧力がどこにも掛かっていない。

詳細は[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)。

## 対応方針

次の順に潰す。**(1)を最初に入れる**——これが無いと、以降の是正が「直った」かどうかを検知器で言えない。

1. **GAPを落とす側へ倒す**: `cmd_mutate`が`detected=False`を1件でも持つときに非0で終わる形にする。
   現在の15件は「閉じる」か「閉じない理由と母集団への影響を数字で書く」かのどちらかへ追い込む。
   **落とすこと自体を目的にして母集団を狭める方向へ逃げないこと**——それがこの欠陥の原因そのもの。
2. **記法の3条件を外す**: `DOC_IDENT_RE`がバッククォート内全体を識別子として要求する条件／裸の綴りを
   見ない条件／同一行に閉じたバッククォートしか見ない条件。裸の綴りは誤検知が増えるため、
   まず参考出力で件数を測ってからenforcedへ移す。
3. **コメント側corpusからテストのローカル定数を外す**: doc側の`_source_corpus`に実装が既にある
   （`TEST_DEFINITION_RE`が`def`/`class`/`function`だけを拾い、変数を含めない理由は同じファイルの
   コメントが説明している）。コメント側だけがその扱いから外れている。
4. **`docs/*.md`を母集団へ入れる**: 実測145件の内訳を見て、記録文書を除外条件にする。
5. **pre-commitのゲートとmutateの実行経路を同じにする**: `scripts/pre-commit-docs-consistency.sh`の
   パス一致ゲートを通らない経路があるのに、mutateはラッパを通さず直接叩くため「PASS」と報告する。
6. **緩和の影響を記録する**: architecture.mdの段落免除（非空行の42.8%）・`FIXED_VALUES`の母集団外
   （60ファイル141定数）・`source_narrative`の母集団外（765件）。数値は第11回F-1に実測がある。

## 完了条件

**対象を本文へ列挙しない**（列挙した瞬間にその一覧が母集団になる）。

- `python scripts/review_checks.py mutate` がGAP 0件で緑になる
- `python scripts/review_checks.py docs` が、現在の残骸を**検出したうえで**0件になる
  （検出できることの確認には、わざと戻した1件が鳴ることを見る）

**穴を宣言しただけで通っていた状態**（15件をprintするだけでexit 0）を、宣言に数字を要求する形へ
変えた。

### 2. コメント側の実在判定corpusを、doc側と同じにした

`find_source_comment_dead_identifier_refs`はテストの**コード全文**をcorpusにしていたため、
**撤去した本番の定数をテストが同名のローカル変数として持っているだけで「実在する」と判定**して
いた。doc側の`source_corpus`（テストの`def`/`class`/`function`は入れるが変数は入れない）へ
揃えた。同じファイル内に理由が書かれていたのに、コメント側だけがその扱いから外れていた。

表に出た3件はいずれも外部由来の名前（`__setstate__`＝Pythonのデータモデル、`boundary_3`＝
OpenFreeMapのレイヤー名）で、`EXTERNAL_VOCABULARY`へ足した。
**この修正は、書いた直後に自分の説明コメントを1件捕まえた**（撤去済みの定数名を例として
バッククォート付きで書いた行）。

### 3. pre-commitの起動ゲートを検知器側へ移した

`scripts/pre-commit-docs-consistency.sh`がパス一致で検査を**丸ごと飛ばす**規則を持っていたが、
`mutate`はラッパを通さず`review_checks.py docs --staged`を直接叩くため、**表は「pre-commit
PASS」と報告しながら実際のフックは検査を起動しない**という食い違いがあった。

判定を`STAGED_GATE_PREFIXES`として検知器側に1つだけ置き、シェル側の規則を消した。
あわせて対象を広げた——旧ゲートは`docs/architecture.md`・`scripts/`・`CLAUDE.md`・
`backend/tests/`だけを触るコミットで検査を起動しなかった（実測: いずれも旧ゲートに
1つも当たらない）。

**代償**: `docs --staged`はステージが空でも**9.7秒**かかる（実測）。広げた分、これらのパスだけを
触るコミットもこの時間を払う。CIが`--since`で同じ検査を行うため取りこぼしはしていなかったが、
「pre-commitで止まる」という表の記述が事実でなかったのを直した。

**この脱出の初版はCIを落とした**。ゲートに当たらないとき`cmd_docs`を`return 0`で抜けて
いたため、検知器の**配線の検査**（`unwired_detectors`。宣言だけあって呼ばれない検知器を
見つける、検知器の一覧そのものの整合性）まで飛ばしていた。
`test_cmd_docs_fails_when_a_declared_detector_is_not_wired`（ステージが空の状態で配線の
切れた検知器を差し込み、落ちることを見る）が検知した。抜けるのをやめ、飛ばすのは
**各検知器の計算だけ**にして、キーの登録と配線の検査は必ず通るようにした。

速くするための脱出は、**同じ実行が担っている別の役目**を道連れにしうる——この`cmd_docs`は
「差分に違反が無いか」と「検知器の表が実行経路と合っているか」の2つを1回で見ており、
前者だけが差分に依存する。

## 閉じなかった穴と、その判断

**15件のうち0件を閉じた。** 当初の完了条件は「`mutate`がGAP 0件で緑」だったが、実測の結果
**この条件は今回の射程では達成すべきでない**と判断した。

- **記法の穴（`source_comment_dead_identifier_refs`）は、外すと成立しない**。レビューは
  「記法の絞り込みを外す」と書いたが、実測すると裸の綴りは770件・342種で、上位は`E402`・
  `BLE001`（ruffのコード）・`Successful`・`Stage`（英単語）・`T624`（タスク番号）・
  `test_migrate`（テストのモジュール名）。複合語へ絞っても104件・78種で、真の違反は
  10数件。**バッククォートの要求は誤った絞り込みではなく、機能している絞り込みだった。**
  正しい設計は「撤去済み識別子の履歴から母集団を導く」形で、これは[T943](T943.md)の
  再発防止で検討する対象と同じ。設計が決まるまで開けておく。
- **残り12件はパスの広げ方の問題**で、どれも「広げた先の既存分をどうするか」を先に決める
  必要がある（`source_narrative`なら765件、`undeclared_fixed_values`なら141定数）。
  広げるだけなら1行だが、広げた瞬間にpre-commitとCIが既存コードで赤になる。
- **`call_arity`と`undocumented_files`は検知の方式そのものの限界**で、パスを広げても閉じない。

**この判断こそが本タスクの成果である。** 15件が「宣言されているが誰も数字を持っていない」
状態から、「それぞれ何がどれだけ外にあるか」が記録された状態になった。次に閉じる人は、
どれが安いか・どれが設計変更かを数字で選べる。
