# T936. 検知器の「既知のGAP」を落ちるようにし、記法と母集団の穴を塞ぐ 規模M

状態: 未着手（2026-09-19起票、統合レビュー第11回）

## 背景

`review_checks.py docs`はフル実行で「違反なし」を返すが、その0件の相当部分は「違反が無い」ではなく
「母集団に入っていない」である。`guard_probe_edges`は穴を「既知のGAP」として宣言している（22件中15件）が、
`cmd_mutate`は件数を印字するだけで落ちないため、閉じる圧力がどこにも掛かっていない。

詳細は[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)。

## 対応方針

次の順に潰す。**(1)を最初に入れる**——これが無いと、以降の是正が「直った」かどうかを検知器で言えない。

1. **GAPを落とす側へ倒す**: `cmd_mutate`が`detected=False`を1件でも持つときに非0で終わる形にする。
   現在の15件は「閉じる」か「閉じない理由と母集団への影響を数字で書く」かのどちらかへ追い込む。
   **落とすこと自体を目的にして母集団を狭める方向へ逃げないこと**——それがこの欠陥の原因そのもの。
2. **記法の3条件を外す**: `DOC_IDENT_RE`がバッククォート内全体を識別子として要求する条件／裸の綴りを
   見ない条件／同一行に閉じたバッククォートしか見ない条件。裸の綴りは誤検知が増えるため、
   まず参考出力で件数を測ってからenforcedへ移す。
3. **コメント側corpusからテストのローカル定数を外す**: doc側の`_source_corpus`に実装が既にある
   （`TEST_DEFINITION_RE`が`def`/`class`/`function`だけを拾い、変数を含めない理由は同じファイルの
   コメントが説明している）。コメント側だけがその扱いから外れている。
4. **`docs/*.md`を母集団へ入れる**: 実測145件の内訳を見て、記録文書を除外条件にする。
5. **pre-commitのゲートとmutateの実行経路を同じにする**: `scripts/pre-commit-docs-consistency.sh`の
   パス一致ゲートを通らない経路があるのに、mutateはラッパを通さず直接叩くため「PASS」と報告する。
6. **緩和の影響を記録する**: architecture.mdの段落免除（非空行の42.8%）・`FIXED_VALUES`の母集団外
   （60ファイル141定数）・`source_narrative`の母集団外（765件）。数値は第11回F-1に実測がある。

## 完了条件

**対象を本文へ列挙しない**（列挙した瞬間にその一覧が母集団になる）。

- `python scripts/review_checks.py mutate` がGAP 0件で緑になる
- `python scripts/review_checks.py docs` が、現在の残骸を**検出したうえで**0件になる
  （検出できることの確認には、わざと戻した1件が鳴ることを見る）
