# T475. 軸スタジオAPI経由のDB変更に「本番DB反映」を完了条件として明記するCLAUDE.md追記提案

状態: 完了（2026-08-31）

- **実装メモ**: ユーザーへ提案したところ、「CLAUDE.mdへ足すと肥大化する、作業の実施方法の
  ような階層に追記できないか」という指摘を受けた。CLAUDE.md「ドキュメント階層」節の基準
  （トピック別詳細方針はdocs/&lt;topic&gt;.mdへ）に照らし、既にaxis_admin API・fresh
  bootstrap・スナップショット手動運用の暗黙の前提を記述している
  [docs/modules/backend/axis-studio.md](../modules/backend/axis-studio.md)の該当節へ
  完了条件の明記ルールを追記した。CLAUDE.md本体は変更していない
  （既存の「既存モジュールへの修正時は対象docsを先に精読する」運用で今後この節が
  発見される）。

- 背景: 「軸スタジオAPI経由の変更が開発DBのみに留まり本番DBへの反映を忘れる」という
  同型の不整合が、T294・T353・T360・T396・T440系列（T455で発覚・修正）と5回発生している
  （統合レビュー第3回 `history/2026-08-31_all.md` O-1、Shard H）。直近のT455実施記録・
  統合レビュー第3回（overall）はいずれも独立に「タスク完了条件へ本番DB反映を明記する」旨の
  CLAUDE.md追記を提案しているが、2回とも`/review:improve`への正式提案として起票されないまま
  放置されている。
- 対応方針: `/review:improve`の通常フローに乗せ、CLAUDE.md「コミット時の同期ルール」節へ
  「axis_admin API経由でDB行データ（`axis_definitions`等）を変更した場合、開発DBと本番DB
  両方に適用したことをタスク完了条件へ明記する」旨を追記するかどうかをユーザーへ提案する。
  承認されればCLAUDE.md本体を更新する。
- 規模: S
