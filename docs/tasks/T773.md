# T773. ルート結果タブの中身を減らす 規模M

状態: 未着手（2026-09-12起票、ユーザー指示「ルート結果タブの再編は、今のタブ内をもっと
シンプルにしてから改めて詰めたい」から。[T769](T769.md)の前段にあたる）

## 背景

「ルート結果」は生成結果を見る画面だが、候補1本ぶんのタブに公開軸すべての難易度一覧と
「重み付き寄与度」の内訳が縦に並ぶ。[T759](T759.md)が測ったとおりデスクトップの
サイドバーは`scrollHeight`=1614 / `clientHeight`=764で、読み切るのに2画面ぶんある。

パネルをどう分けるか（[T769](T769.md)）の前に、**1つの候補を読むのに必要な情報量自体**を
減らす。分ける前に減らさないと、分けた先が同じ密度のまま増えるだけになる。

## 検討する案（ユーザー提示、2026-09-12）

- **ルート生成に使っていない軸の横棒グラフをたたむ**。重み0の軸は「未使用」バッジ付きで
  常時出ている（`RouteAxisProfile`）。評価に効いていない軸が、効いている軸と同じ高さを
  占めている。
- **物理量表示をポップアップにする**。`design-principles.md`「UI仕様」の**数値は3層で
  見せる**（地図は色、パネルは段階ラベルと0〜100、区間の詳細が元の物理量）に照らすと、
  パネル側に物理量が出るのは「軸1本につき生値1つ」に限られる。いまの出方がその線を
  超えていないかを確かめる。

## measurement（着手時に取る）

**何がどれだけの高さを占めているかを測ってから減らす**。公開軸の本数・重み0の軸の本数・
それぞれのブロックの実測高さを取り、削る候補の効果を数字で比べる（減らした結果が
「読みたいものまで隠れた」にならないよう、隠す対象は重みで決まるものに限る）。

## 保留することで何が起きうるか

- [T769](T769.md)（見る／作るの分離）を先にやると、分けた先のパネルも同じ密度を引き継ぐ。
  枠を増やしても1画面あたりの読みにくさは変わらない。
