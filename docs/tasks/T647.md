# T647. キャッシュ方針の機械的な強制とCLAUDE.mdへの接続 規模S

状態: 未着手（2026-09-07起票）

## 背景

サーバー側キャッシュの共通骨格（`redis_json_cache.py`）は[T635](T635.md)で用意され、
方針の正本も[docs/caching.md](../caching.md)として整備した。しかし**守らせる仕組みが無い**。

- 利用者は`jma_tile_index.py`の1つだけで、既存4モジュールは各自の実装のまま
- 骨格を写経してもアプリは動く（fail-open設計のため）。写経ミス（`record_redis_failure`の
  呼び忘れ等）は表に出ず、**Redis障害の検知だけが静かに欠ける**という壊れ方をする
- 実際、[T635](T635.md)の実装中に12個目の同型モジュールを書き始めていたことが
  [T644](T644.md)起票のきっかけになっている

ログ方針（docs/logging.md）・コメント方針（docs/comments.md、[T570](T570.md)で
pre-commitフック化）は「正本のdocs＋機械チェック＋CLAUDE.mdからの参照」の3層で守られて
いるのに対し、キャッシュだけ正本しか無い状態になっている。

## 対応方針

1. **機械的なチェック**を`scripts/review_checks.py`の`docs`サブコマンドへ追加する
   （pre-commitとCIが実行する既存の枠組みへ相乗り）。
   - `get_redis_client_or_none`・`record_redis_failure`が`redis_client.py`・
     `redis_json_cache.py`**以外**の追加行に現れたら違反
   - 既存4モジュール（`jma_tile_redis_cache`・`dynamic_way_value_cache`・
     `road_edge_geometry_cache`・`road_graph_tile_cache`）は許可リストで免除する。
     [T644](T644.md)の移行が済むたびにリストから1つ削り、**残り数がそのまま進捗になる**
   - 許可リストへ残す/追加する場合は理由をモジュールのdocstringへ書くこと（docs/caching.md
     「自前で骨格を書いてよい例外」）
2. **CLAUDE.mdへ1行**追加し、ログ・コメント・テストと同じ並びにする
   （「キャッシュを新設・変更するときは docs/caching.md に従う」）。並びが揃っていないと
   キャッシュだけ例外に見えるため。

## 完了条件

- 許可リスト外のファイルで骨格を写経したコミットが、pre-commitでブロックされること
- 既存4モジュールは違反として検出されないこと（移行前でもコミットが通る）
- docs/caching.mdの「機械的な強制」節から「未実装」の注記が外れていること
