# T597: デスクトップのサイドバーをモバイルと同じ3区分にし、ルート結果ヘッダに保存・GPX出力の操作枠を確保する

状態: 未着手（2026-09-05起票、分割元は[T590](T590.md)）

## 背景

デスクトップは「A. ルートを作る（設定＋結果を内包）」「B. 地図の見え方」の2段
（`page.tsx`のDisclosure構成）、モバイルは「ルート設定 / ルート結果 / 地図の見え方」の
3タブで情報設計が食い違う。将来のルート保存・参照・GPX出力（ユーザー要望2026-09-05）の
置き場も先に決めておく。

## 対応方針

- デスクトップのサイドバーを3区分（ルート設定 / ルート結果 / 地図の見え方）のフラットな
  Disclosureにし、モバイルの3タブと同じ順序・同じ見出しにする。両端末で説明が1種類で済む。
- ルート結果ヘッダの操作群（現状「ルートをクリア」と説明アイコン）を横並びの操作枠として
  固定し、「保存」「GPX出力」のアイコンを並べられる余地を作る。本タスクでは枠の確保と
  レイアウトだけを行い、機能は別途起票する（未起票。着手時に保存先[ローカル/サーバー]・
  GPX仕様を決めてから採番する）。
- 保存済みルートの参照は候補タブ列の先頭に固定タブ「保存済み」として置く設計とする。
  3区分は増やさない。本タスクではタブ列が先頭固定タブを持てる構造（`Tabs.Root`の
  value体系）にしておく。
- おすすめ度は撤去済みのため、ルート結果の先頭は総合難易度のみ。

## 対象ファイル

`frontend/src/app/page.tsx`（`renderRouteSectionBody`・`renderRouteOutcomeSectionBody`・
サイドバーのDisclosure構成）・`components/BottomSheet/`（変更なしの見込み）・
`docs/modules/frontend/`該当モジュール。

## 完了条件

- デスクトップとモバイルで区分の名前・順序・中身が一致する。
- ルート結果ヘッダに操作アイコンを追加しても再レイアウトが不要な構造になっている。
