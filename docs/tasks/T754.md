# T754. 災害レイヤーの既定ONが地図全面を塗り、レンズ配色と衝突してルート線が見えない

規模M。
状態: 実装済み・本番確認待ち（2026-09-12起票・同日実装）

## 背景

本番で災害レイヤーが既定ON（`page.tsx`の`DEFAULT_LAYER_VISIBILITY`で`disaster: true`）のまま、当日は関東全域が不透明な緑一色に塗られ、道路・河川が読めない。総合難易度レンズは「易しい＝緑」で、生成されたルート線が背景と同化して見えない。災害チップをOFFにすると通常の地図に戻ることを本番で確認した。研究モードの比較タブが地図へ重ね描きするスロット線（緑・橙・紫）も同じ背景と衝突する。

個票は[history/2026-09-12_ui.md](../../.claude/commands/review/history/2026-09-12_ui.md)のF-2・F-22。

## 調査項目

1. **何が緑を塗っているか**を確定する。災害チップが束ねる要素（キキクル各種・警報注意報等）のうち、どの要素のどのレベルが当日の緑に対応するか。「危険が無い」状態を塗っているのか、注意報級の広域情報を塗っているのか
2. **既定ONの是非**。走行中のスマホという主用途で、災害情報を既定で面塗りする価値と、地図が読めなくなる害を比べる。ONにするなら「情報が無い/危険が無い」状態は塗らない条件が要る
3. **色空間の分離**。環境グループの面塗り・評価軸レンズの線・実験スロットの線が同じ緑系を使っている。面は無彩色寄りか低不透明度、線は高彩度、のように役割ごとに色の帯域を分ける方針を`docs/design-principles.md`の該当節と突き合わせる

## 原因（2026-09-12、本番で特定）

**空タイルの代わりに返していた1x1 PNGが、透明ではなく`rgba(0, 255, 0, 127)`（真緑・半透明）
だった。** `Map/jmaTileProtocol.ts`の定数は`TRANSPARENT_PNG`という名前で「1x1の完全に
透明なPNG」とコメントされていたが、base64の中身が別物だった。

MapLibreはこの1画素を`tileSize`（256px）ぶんへ引き伸ばす。空タイルは全ズーム・全座標で
返るため、**災害レイヤーのラスタ5種（大雨・土砂・浸水・雷・竜巻）がそれぞれ画面全体を
緑で塗り、重なって不透明になっていた**。

### 特定の手順（本番、Playwright）

1. 災害チップの▶パネルで7要素を1つずつだけONにして地図をハッシュ比較した。ラスタ5種は
   **どれも同一のハッシュ**になり、ベクタの洪水・点の落雷だけが「災害OFF」と一致した
2. 同一ハッシュということは配信元のデータではなく共通の何かが描かれている。雷ナウキャストは
   当日その領域のタイルを1枚も取得していないのに緑になることを確認した
3. 空タイルの代替として返す定数を復号し、画素が`[0, 255, 0, 127]`であることを確認した

「危険度ゼロの領域は配信元のタイルが透明」という設計自体は正しく、壊れていたのは
**配信元へ行かずに自前で返す側**だった。

## 対応（2026-09-12）

定数を全チャネル0の1x1 PNGへ差し替えた。`jmaTileProtocol.test.ts`がPNGを復号して画素の
不透明度が0であることを検査する（元の緑へ戻すと落ちることを確認済み）。

調査項目2（既定ONの是非）・3（色空間の分離）は**着手しない**。既定ONは「防災級の情報は
ユーザー操作を待たず表示すべき」という判断で入っており、平常時に地図が塗られなくなった
今はその前提が成り立つ。色空間の分離も、面が平常時に無色へ戻ったことで衝突自体が消える。
