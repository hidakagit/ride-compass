# T692. Edge単位の材料をway単位でも見られるようにする 規模M

状態: 実装中（2026-09-10起票、[T691](T691.md)より分離）

## 背景

[T691](T691.md)で足した`curvature_deg_per_km`はEdge（`road_edges`）単位の材料で、
ルート探索とルート結果には効いている。一方、**way（`osm_raw_ways`）単位で材料を組む
経路には出てこない**:

- 区間インスペクタ（クリックした道の材料一覧）に蛇行が出ない
- 軸スタジオの分布プレビューで蛇行の値域・折れ点の効きを確認できない
- 地図タイルへ焼けないため、蛇行軸は地図レイヤーを持てない（`tile_property=None`）

3つとも原因は同じ「wayに対応する値が無い」で、way単位の集計（そのwayに属するEdgeの
延長加重平均）を1つ用意すれば同時に解ける。

## 保留した場合に何が起きるか

- Edge単位の材料を今後増やすたびに同じ3つの穴が開き、軸スタジオで折れ点を較正できない
  軸が積み上がる（較正できない軸は[T686](T686.md)の分布プレビューの外側に置かれる）
- 蛇行軸は「ルートを選ぶ基準にはなるが、地図でどの道が蛇行しているか見えない」状態が続く
- 区間インスペクタの材料一覧が「軸に効いている材料の一部しか映さない」ものになり、
  なぜこの区間の得点が高いのかを画面から追えない

## 実測（本番、2026-09-10）

抽選4,031way・784kmで確認した:

- **road_edgesは本番のwayの99.5%（延長でも99.5%）を覆う**。ただし`road_edges`はルート生成時に
  遅延構築される派生データで、母集団としての保証が無い（`WayAttributeCountsRow`の
  docstringが同じ理由でway単位の事前集計を選んでいる）。way単位の値はEdgeの集計ではなく
  **`osm_raw_ways.geom`から直接測る**。
- way形状から測った値とEdge集計値の差（延長加重）は p50 +1・p75 +20・p90 +69・p99 +399 度/km。
  差が20度/km未満の延長が75.5%。wayの折れ線はEdgeを切り出す交差点の頂点も含むため、
  way単位の値は常にEdge単位の延長加重平均以上になる。

## 先に直す: 同じ列に2つの定義が残っていた

[T691](T691.md)で入れた蛇行には、頂点2点の折れ線の扱いにPythonとSQLの食い違いがある。

| | 頂点2点の折れ線 |
|---|---|
| `domain/geo.py: curvature_deg_per_km` | `None`（測れない） |
| `precompute_edge_curvature.py`のSQL | `0.0`（`COALESCE(total.deg, 0)`） |

本番のroad_edgesは**行数の46%・延長の27.6%が2頂点**で、現在は全件0.0が入っている。
再split（PBF再取込）でこの延長が「0点＝最良」から「材料欠損＝軸が評価不能」へ反転する。

2点の折れ線は幾何的に直線であり、方位変化の合計は0と測れる。「曲がりが無い」と
「測れない」を混同していたのはPython側で、`< 3`の門を`< 2`へ下げる。距離0は従来どおりNone。
[T691](T691.md)のSQL↔Python一致テストは3頂点のwayしか通していなかったため素通りしていた。

## 対応方針

### way単位の蛇行を持つ（`way_geometry`）

`way_landcover`・`way_attribute_counts`と同じ「way単位の事前集計テーブル」の流儀に揃える。
母集団は`osm_raw_ways`全域で`road_edges`に依存しない。行が無い＝未計算、
列がNULL＝算出不能（頂点1点・長さ0）。

蛇行を測るSQLはEdge版とway版で同一のため、`road_graph_repository.py`へ1つ置いて
両方から使う（テーブル・列名だけを差し替える）。既存のprecomputeバッチが
「SQLはリポジトリに置き、バッチは呼ぶだけ」という規約なのに、`precompute_edge_curvature.py`
だけが自前のSQLを持っていたのを揃える。

### 3つの消費者への配線

| 消費者 | 変更 |
|---|---|
| 区間インスペクタ | way取得SQLへ`way_geometry`をLEFT JOIN、`way_scalar_materials`へ渡す |
| 分布プレビュー | `_SAMPLE_WAY_MATERIALS_SQL`へ同上 |
| 地図タイル | `_ROAD_SURFACE_TILE_MVT_SQL`へ同上、`curvature_deg_per_km`を焼く |

タイルへ焼くと`MaterialSpec.tile_property`を設定でき、`derive_ramp_inputs`が通って
**蛇行軸は自動で地図レンズを得る**（`axis_display_for`が`kind="ramp"`を返すため、
フロントエンドの変更は不要）。0はNULLIFでキーを省く（既存のaccident_per_km等と同じ流儀、
フロントは欠損を0として読む）。

`way_scalar_materials`の引数は材料ごとに増え続ける形のまま残る（土地被覆の2列に続いて
蛇行で3つ目）。まとめて渡す形への整理はここでは行わない。
