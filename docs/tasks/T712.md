  色は追随するのに間引き条件とサイズ曲線だけが古いという、**発見しづらい形**で壊れる。

### 対応方針

個別に直すのではなく、**「ensure関数は必ず既存レイヤーへも設定を再適用する」をファクトリ側で強制する**
（各関数が個別にearly returnを書けない構造にする）。T587が4関数を直して1関数が残った経緯からして、
個別修正では次も取り残しが出る。

### （1）ensure*関数の再適用強制

個別に直すのではなく、**specから追加と再適用の両方を行う1関数**を置き、ensure系がそこを
通る形にした（`MapView.tsx: ensureLayerFromSpec`）。

```ts
export function ensureLayerFromSpec(map, spec) {
  if (!map.getLayer(spec.id)) { map.addLayer(spec); return; }
  // spec.paint / spec.layout（visibilityを除く）/ spec.filter をすべて再適用する
}
```

これで「ensure関数がearly returnを書ける」形自体が無くなり、新しいプロパティをspecへ
足せば再適用も自動で付いてくる。T587が4関数を直して1関数を取り残したのは、再適用を
関数ごとに書く形だったため。

- `makeEnsureAttributeLineLayer`（T587の横展開漏れ）・`makeEnsureDedicatedWayValueLayer`・
  `makeEnsureAxisRampLayer`・`ensureDynamicWeatherLayer`の4経路すべてを移行した。
- `ensureDynamicWeatherLayer`はpaintしか再適用しておらず、`minValueToShow`由来のfilterと
  gridMarkのicon-size式が初回の値で固定されていた。specから再適用するため両方が追随する。
- `visibility`だけは再適用しない（specが持つのは追加時の初期値で、表示ON/OFFは
  `setStaticOverlayVisibility`等が持つ状態。上書きすると利用者の選択が消える）。
- `filter`はraster/background/hillshadeでは設定できないため、持ちうる型のときだけ触る。
  specがfilterキーを失ったら`undefined`で明示的に外す（絞り込みだけ古い条件で効き続けるのを防ぐ）。
- `makeEnsureAttributeLineLayer`のspecから`line-offset: 0`を外した。MapLibreの既定値と同じで
  追加時に不要なうえ、再適用すると`applyRoadMaterialTrackOffsets`が設定した並行トラックの
  オフセットを毎回0へ戻してしまう。

### （2）共通骨格の写経取り残し

- **precompute系ドライバ**: `_common.py`へ`run_chunked_precompute`を新設し、
  `precompute_edge_attribute_counts`・`precompute_elevation_attributes`・
  `precompute_way_attribute_counts`・`precompute_way_curvature`の4本を移行した。
  各バッチに残るのは`handle_chunk`（1チャンクぶんの実処理、件数を返す）だけ。
  進捗ログの体裁が4本で揃い、`total_chunks`算出・0件時の扱いも1箇所になった。
  `precompute_way_landcover.py`は予告どおり移行しない（範囲外判定・部分被覆の集計という
  固有の関心事をループ内に持ち、`handle_chunk`が返す件数1つでは進捗を表せない）。
  系譜のrun idは進捗行から独立した1行のログへ移した。
- `services/axisPreviewApi.ts`の独自`getJson`を撤去し`lib/fetchJson.ts: requestJson`へ。
  欠けていた`x-request-id`のログが付き、backendログとの突き合わせキーが残るようになった。
- `services/healthApi.ts`の`AbortSignal.timeout(5000)`直書きを`STATUS_API_TIMEOUT_MS`へ。
- `jmaNowcastFrames.ts: fetchJmaTargetTimes`へ未解決フェッチの重複排除を入れた
  （`rasrf`を降水短時間予報と線状降水帯予測マップが独立に取りに行き、降水チップONのたびに
  同一URLの往復が2回発生していた）。解決後はキャッシュしない——時刻一覧は数分で更新される。

## 検証結果

- ensure*の再適用強制: `makeEnsureAttributeLineLayer`を早期returnへ戻すと、新規テスト
  `一次属性レイヤー（designation等）も再適用の対象になっている`が落ちることを確認。
  `ensureLayerFromSpec`自体のテスト（paint/layout/filterの再適用、visibilityは触らない、
  filterを持てない型には触らない、未追加ならaddLayerのみ）も追加した。
- JMA時刻一覧の重複排除: 排除を外すと`同時に呼ばれた同じidは1回のfetchで済む`が落ちる
  ことを確認。「解決後は取り直す」対の正例も置いた。
- precompute系: `tests/test_precompute_elevation_attributes.py`を、4本すべてが共有ドライバを
  そのまま使っていることのパラメータ化テストへ書き直した（自前ドライバを書き戻すと落ちる）。
- backend: `pytest -m "not postgis"` 1,762 passed／`pytest -m "postgis"` 283 passed／
  `ruff check app scripts benchmarks tests` クリーン。
- frontend: `tsc --noEmit`・`eslint src` クリーン／`vitest run` 126 files / 1,164 tests passed。
- `export_openapi.py`→`npm run generate:api`を実行。差分はdocstringの文言だけ
  （`EvaluationService`→`evaluate_graph`、`DEFAULT_HARD_FILTERS`→`HARD_FILTER_NAMES`）で、
  同一コミットへ含めた。

## 変更しなかった1件

`MapView.tsx`と`page.tsx`が`buildRoadSurfaceSharedLayerIds(rampAxes, dedicatedAxes)`を
独立に計算している件は、そのままにした。**同じ純関数へ同じ入力を渡しており値がズレようが
なく**（消費者も別——`page.tsx`側は`MapLayersPanel`へ、`MapView`側は内部のズーム案内へ）、
どちらも`useMemo`で1回ずつ。propで渡す形にすると、`MapView`が`rampAxes`から自分で導ける
ものを外から受け取る結合が増える。導出値をそれぞれの必要な場所で計算するのは通常の形で、
「同じ計算が2回ある」こと自体は欠陥ではないと判断した。
