# T712. ensure*関数の再適用強制と、共通骨格の写経取り残しを片付ける 規模M

状態: 未着手（2026-09-10起票、統合レビュー第6回 P2/P3の束ねF。対象9件）

## 背景（1）ensure*関数の構造的欠陥

[T587](T587.md)で「既存レイヤーがあってもsetPaintPropertyで再適用する」形へ4関数を直したが、
**同じパターンの取り残しが2箇所**ある。principles.md 判断原則16
（「実害が無い」を理由に構造的欠陥を放置しない／1箇所を直したら横展開して確認する）の対象。

- `MapView.tsx:1567-1574` `makeEnsureAttributeLineLayer`（designation/tunnel/oneway）だけが
  `if (map.getLayer(layerId)) return;`のままで色式・不透明度式を再適用しない。
  現在は`DESIGNATION_COLOR_EXPRESSION`等がモジュール定数のため実害は無いが、
  配色を軸カタログや実行時フェッチ由来にした瞬間、初回addLayer時の値で固定され二度と更新されない。
- `MapView.tsx:1068-1207` `ensureDynamicWeatherLayer`は**paintプロパティだけ**を再適用しており、
  `minValueToShow`由来のfilter（`:1113-1117`・`:1168-1170`・`:1200-1204`）と
  gridMarkのicon-size式（`:1153-1159`）はaddLayer時の値で固定されたまま。
  色は追随するのに間引き条件とサイズ曲線だけが古いという、**発見しづらい形**で壊れる。

### 対応方針

個別に直すのではなく、**「ensure関数は必ず既存レイヤーへも設定を再適用する」をファクトリ側で強制する**
（各関数が個別にearly returnを書けない構造にする）。T587が4関数を直して1関数が残った経緯からして、
個別修正では次も取り残しが出る。

## 背景（2）共通骨格の写経取り残し

- **precompute系バッチのドライバ骨格が5本へ写されている**。`_common.py`が
  `batch_session_factory`/`count_targets`/`stream_id_chunks`のプリミティブを提供している一方、
  その上のドライバ（対象件数ログ → dry-run早期return → 0件WARNING → `total_chunks`算出 →
  `stream_id_chunks`ループ → チャンク進捗INFO）が
  `precompute_edge_attribute_counts.py:67-92`・`precompute_elevation_attributes.py:63-84`・
  `precompute_way_attribute_counts.py:66-94`・`precompute_way_curvature.py:50-68`・
  `precompute_way_landcover.py:167-205`へ同じ形で書かれている。
  jscpdも1組を20行のクローンとして検出（今回範囲で最大の新規クローン）。
  → `_common.py`へ`run_chunked_precompute(stmt, chunk_handler, *, label, dry_run)`を1本足す。
  **ただし`precompute_way_landcover.py`は範囲外判定・部分被覆の集計という固有の関心事を
  ループ内に持つため、無理に同じ器へ入れない**（4本＋例外1本でよい）。
- `services/axisPreviewApi.ts:20-34,151-169` — [T679](T679.md)が`lib/fetchJson.ts`へ集約した骨格
  （fetch→通信エラーcatch→ok確認→detail解析→debugLog）を独自の`getJson`が持ち直しており、
  **`x-request-id`のログだけが欠けている**。`fetchJson.ts:4-12`が警告する
  「片方だけ改良された非対称」がそのまま再現している。分布APIが失敗したとき
  backendログとの突き合わせキーが残らない。
  なお`docs/tasks/T676.md:121-123`が「本タスクでは骨格の統合は触っていない」と保留を記録しているが、
  `docs/improvement-plan.md`へ独立した`- [ ]`行として起票されておらず
  （CLAUDE.md「毎タスク完了時の即時チェック」6）、`/task:next`等の機械抽出から漏れていた。
- `services/healthApi.ts:6` — `AbortSignal.timeout(5000)`が1箇所残っている。
  値も用途も`STATUS_API_TIMEOUT_MS`と完全に一致（`lib/apiTimeouts.ts`が
  「7ファイル・14箇所の直書きを全部これへ寄せた」と述べている取り残し）。
- `riskMap.ts:100`／`precipitationNowcast.ts:90` — 同じ`rasrf/targetTimes.json`をそれぞれ独立に取得。
  `fetchJmaTargetTimes`に重複排除が無く、降水チップONのたびに同一URLの往復が2回発生する。
  同ファイル`:86-87`の「1回のfetchで4種共通」という設計方針と非対称。
- `MapView.tsx:2371-2374`／`page.tsx:846-849` — `buildRoadSurfaceSharedLayerIds(rampAxes, dedicatedAxes)`を
  同じ入力から独立に2回計算している。
