# T802. 時刻ビンが1本のときに2点間探索の手間を省く

規模S。
状態: 未着手（2026-09-13起票。[T790](T790.md)の本番計測から）

## 背景

[T790](T790.md)段階Dで、探索は出発からの経過時間をラベルとして持ち回り、`(時刻ビン, 状態)`の
2次元コスト配列からその時刻の行を引くようになった。

本番計測（東京駅・目標30km・温パス）で、2点間探索（`trace`）が**179ms→704ms**になっている。
目標30kmの周回はレグ0.75時間で**時刻ビンが1本に収まる**ため、この増分は
「ビンが1本でもラベルの持ち回りと2次元の添字アクセスを通っている」ぶんの手間になる。

## 調査項目

- 増分が本当にラベル処理由来か（2次元の添字アクセス・到達時刻の配列更新・ヒープの積み方の
  どれが効いているか）を切り分ける。`benchmarks/bench_t790_turn_expanded.py`が訪問状態数を
  数えるので、同じ入力でビン1本と複数を比べられる
- ビン1本のときだけ通る経路を持つ価値があるか。numbaのカーネルを2つ持つと、同じ探索の
  実装が2箇所になる（片方だけ直したときに静かに食い違う）——**まず切り分けの結果を見てから
  決める**。添字アクセスだけの問題なら、カーネルを分けずに済む書き方があるかもしれない
