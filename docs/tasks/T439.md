# T439. モバイルでルート生成完了時に「ルート結果」タブへ視覚的に誘導する 規模S〜M

状態: 完了（2026-08-30）

- 背景: review:ui（2026-08-30、[history/2026-08-30_ui.md](../../.claude/commands/review/history/2026-08-30_ui.md) F-5）。
  モバイルの「ルート結果」タブの通知ドットは`conditionsDirty`（条件変更後）にのみ点灯し、
  生成完了と同時に消灯するため、新しい結果が用意できた瞬間に見に行くべき合図が何も残らない。
- 対応: `page.tsx`に新規state `hasUnseenResults`を追加。`handleGenerate`の成功パス
  （`setRoutes(candidates)`直後）で`candidates.length > 0`のとき true にし、
  `handleMobileTabClick("routeOutcome")`（「ルート結果」タブを開いた時点）で false へ戻す。
  タブの通知ドットの表示条件を`conditionsDirty`単独から`(conditionsDirty || hasUnseenResults)`
  へ変更し、「生成前に条件が変わった」「生成が完了し新しい結果がある」の両方を同じドットで
  知らせ続けるようにした（生成の前後でドットが途切れない）。デザインとしては新規の色分けは
  設けず、既存の警告色ドット1種類に統合している（オプション案「自動タブ切替」は
  ユーザーの操作タイミングを奪う可能性があるため、既存の合図方式を補完する今回の
  最小変更を採用した）。
- 検証: `tsc --noEmit`・`eslint`とも問題なし。`page.test.tsx`（`handleGenerateハンドラ`の
  既存テストを含む13件）は全件成功（`useIsMobile`をfalseへモックしておりモバイルタブ
  バー自体は描画対象外のためユニットテストでの追加検証はしていない）。Playwright実機確認
  （モバイル390px幅）でタブバーのレンダリング自体に崩れ・コンソールエラーが無いことを
  確認済み。バックエンド実接続時の生成成功→ドット点灯→タブ訪問でのドット消灯という
  一連の流れは、次回このコンポーネントへ触れる際に合わせて実機確認することを推奨する。
