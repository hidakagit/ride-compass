# T599: 本番の風軸を新材料へ切り替えbreakpoints・override・段階ラベルを較正しスナップショットを更新する

状態: 未着手（2026-09-05起票、分割元は[T590](T590.md)。前提: [T591](T591.md)・[T593](T593.md)・
[T598](T598.md)の完了と本番デプロイ）

## 背景

T591の第1デプロイ後に、axis_admin API経由で本番の風軸の参照先・折れ点・表示しきい値を
切り替える運用タスク。コード変更を伴わないが、[docs/deployment-sync.md](../deployment-sync.md)
の完了条件（開発DBのみの反映で完了扱いにしない）に従う。

## 手順

1. 本番の風軸を unpublish → PUT（`shape.terms[0].material`を新材料へ、breakpointsを
   `[[0,0],[5,100]]`を初期値として、`display_thresholds_override`は難易度スケールで
   `[20,40,60,80]`、`display_band_labels_override`を5段階） → republish。
2. 追い風を横風より優遇するか（無風へ小さな基準値を置くか）はこの時点でユーザーと決める
   （[T590](T590.md)「決定事項 1」）。
3. 開発DBにも同じ変更を適用し、`backend/scripts/dump_axis_definitions_snapshot.py`で
   `backend/fixtures/axis_definitions_snapshot.json`を更新してコミットする。
4. T591で残した旧材料idの非推奨エイリアスを撤去する（第2デプロイ）。
5. 本番で20km/h・30km/hの同一条件で生成し、風軸の難易度が速度で変わることを実測する。

## 完了条件

- 本番・開発DB・スナップショットの風軸定義が一致している。
- 旧材料`wind_penalty`への参照がコード・DB・スナップショットのどこにも残っていない。
