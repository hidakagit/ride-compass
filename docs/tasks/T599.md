# T599: 本番の風軸を新材料へ切り替えbreakpoints・override・段階ラベルを較正しスナップショットを更新する

状態: 完了（2026-09-05起票・2026-09-06完了、分割元は[T590](T590.md)。前提: [T591](T591.md)・
[T593](T593.md)・[T598](T598.md)の完了と本番デプロイ）

## 背景

T591の第1デプロイ後に、axis_admin API経由で本番の風軸の参照先・折れ点・表示しきい値を
切り替える運用タスク。コード変更を伴わないが、[docs/deployment-sync.md](../deployment-sync.md)
の完了条件（開発DBのみの反映で完了扱いにしない）に従う。

## 手順

1. 本番の風軸を unpublish → PUT（`shape.terms[0].material`を新材料へ、breakpointsを
   `[[0,0],[5,100]]`を初期値として、`display_thresholds_override`は難易度スケールで
   `[20,40,60,80]`、`display_band_labels_override`を5段階） → republish。
2. 追い風を横風より優遇するか（無風へ小さな基準値を置くか）はこの時点でユーザーと決める
   （[T590](T590.md)「決定事項 1」）。
3. 開発DBにも同じ変更を適用し、`backend/scripts/dump_axis_definitions_snapshot.py`で
   `backend/fixtures/axis_definitions_snapshot.json`を更新してコミットする。
4. T591で残した旧材料idの非推奨エイリアスを撤去する（第2デプロイ）。
5. 本番で20km/h・30km/hの同一条件で生成し、風軸の難易度が速度で変わることを実測する。

## 完了条件

- 本番・開発DB・スナップショットの風軸定義が一致している。
- 旧材料`wind_penalty`への参照がコード・DB・スナップショットのどこにも残っていない。

## 実装メモ（2026-09-06）

- 手順2（追い風優遇の可否）: ユーザー判断により優遇する方針を採用。breakpointsは
  `[[-1.2,0],[0,15],[5,100]]`（無風=15を基準に追い風側を0まで下げる。cost≥distance不変条件
  [`docs/decisions/t12-routing-scale.md`不変条件1]と両立させるため、材料値をそのまま
  スコアにせずbreakpoint_linearのy軸[0-100]へ収める設計）。
- 本番・開発DBともaxis_admin API（unpublish→PUT→republish）経由で切替。
  `display_thresholds_override=[20,40,60,80]`・`display_band_labels_override=["無風・追い風",
  "軽い向かい風","普通の向かい風","強い向かい風","非常に強い向かい風"]`・
  `dynamic_way_value_needs_speed=true`も同時設定（T594完了メモの指摘どおり、
  material参照切替とセットで設定しないと`GET /api/region/dynamic-way-values/wind/...`が
  speed_kmhを要求しないまま`wind_drag_ratio`を呼び出し破綻する）。
- 手順4（旧材料撤去、第2デプロイ）: `domain/wind.py: headwind_component_ms`・
  `domain/material_catalog.py`の`wind_penalty`エントリ・`REQUEST_DYNAMIC_MATERIAL_IDS`/
  `DYNAMIC_MATERIAL_EVALUATORS`の`wind_penalty`登録・`material_coverage.py`の除外理由エントリ・
  `WindWayService`の参照先分岐（`LEGACY_MATERIAL_ID`/`material_id`プロパティ）を削除し、
  `material_id`を`"wind_drag_ratio"`固定のクラス属性へ単純化。バックエンド・フロントエンドの
  テスト（`test_wind.py`・`test_wind_way_service.py`・`test_evaluation.py`・
  `test_evaluation_bulk.py`・`test_wind_time_varying.py`・`test_material_catalog*.py`・
  `test_dynamic_way_values.py`・`test_difficulty.py`・`test_axis_hierarchy.py`・
  `test_axis_registry_service.py`・`test_route*.py`・`routeStyleModes.test.ts`・
  `ComparisonPanel.test.tsx`）を新材料・新breakpoints・新削除内容に追従。
  `docs/modules/backend/{dynamic-way-values,evaluation-scoring,routing-engine}.md`・
  `docs/architecture.md`の現状記述も追従。
- 手順5（実測）: 本番backend（`193.123.166.150`、bearing=0固定）で`speed_kmh`を10/20/30/60と
  変えて`GET /api/region/dynamic-way-values/wind/...`を実行し、同一風条件でdifficultyが
  21.8→27.0→32.2→47.8と速度に応じて単調増加することを確認済み。
- 開発DBに無関係なテスト用軸`test_axis`（下書き、ラベル"t"）が残存していたため、
  スナップショットへ混入させないよう削除した（本タスクとは無関係な残骸、発見ついでに削除）。
