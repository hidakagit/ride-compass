# T940. 較正値`evaluation.penalty_strength`の`RESTART`が実現不能で、管理画面は効かない値を「効いている」と表示する 規模S

状態: 未着手（2026-09-19起票、統合レビュー第11回）

## 背景

`DEFAULT_PENALTY_STRENGTH`はモジュールimport時に1回だけ評価されるが、DBの上書きを重ねる
`refresh_tuning_values`はlifespan（全import完了後）で走る。再起動しても同じ順序を繰り返すため、
`TuningEffect.RESTART`という宣言がこの起動順序では実現できない。

詳細は[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)。

## 対応方針

`TuningEffect`の宣言そのものは正しい設計で、問題は`RESTART`という効き方がこの起動順序では
実現できない点にある。

1. `evaluation.penalty_strength`を`IMMEDIATE`へ移し、**リクエスト処理時に`tuning_value()`から読む**。
   APIスキーマの既定は未指定を許し、サービス側で解決する。
2. フロントが送る値は現在ビルド時生成物の既定（0.7固定）。`CLIENT_RELOAD`として配るか、
   そもそもフロントから送らないかを決める。
3. **`TestReachesTheConsumers`の母集団を`TUNING_PARAMETERS`から導出する**。このテストは
   docstringで「届かない値が混ざっていると、管理画面から変えても何も起きない」とこの欠陥を
   目的として宣言しているのに、検証する消費者が手書きの6ケースだったため、
   **唯一実際に届かない1件だけがテストの外**にあった。

## 完了条件

- 管理画面から値を変えた後、ルート生成が実際にその値でコストを合成することをテストで固定する
- `TUNING_PARAMETERS`へ1件足したとき、消費者を検証するテストが自動で対象へ含めること
