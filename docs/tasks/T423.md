# T423. 勾配（gradient）を評価軸として実装する（動的材料の第2の具体例、道路自身の向きとの補正方法の決定を含む）

状態: 未着手（起票のみ、2026-08-30・T400.md全体の再監査で発見）

- 背景: [T400.md](T400.md)「2. 動的要素…の状態機械」節・[T414](T414.md)は、動的材料の
  状態別表現契約を風（第1の具体例）で実装するが、勾配はこの契約の**第2の具体例**として
  表に登場するのみで、実装するタスク自体がどこにも起票されていなかった
  （[T414.md](T414.md)「未検討事項」はrainについて「実装する場合は別タスクとして起票する
  こと」と明記していたが、gradientについて同じ扱いを明記し忘れていた）。
- 勾配は風と異なり**向きが道路自身に内在する**特殊なケースで、実装着手前に以下の設計判断
  が必要（T400.md節2の表より）: `gradient_percent`は道路自身の始点→終点方向を基準にした
  符号付き値。ユーザーが指定した向きと道路自身の向きが「概ね同じ」か「概ね逆」かで符号を
  採用/反転するか、両者のなす角度で連続的に補正するか（例: `cos(道路の向き - 指定の向き)`で
  重み付け）は**未決定**。
- 関連: [T404](T404.md)（display_override廃止）の「preprocess="abs"対応」は「gradientが
  解決すれば、その時点で改めてabs対応の要否を検討する」として本タスクへ先送りされている
  （T404.md参照）。勾配実装時はこの点も合わせて検討すること。
- 依存: [T411](T411.md)（動的＋向きあり要素の配信機構の汎用化、風・勾配の2例が揃ってから
  検討）のトリガーそのものが本タスク。[T414](T414.md)（風、第1の具体例）の実装パターンを
  先に読んでから着手すること。
