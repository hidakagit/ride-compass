# T444. 風・勾配のfeature-stateクリアが共有され、同時ON時に片方OFFで両方消える

状態: 起票

- 背景: `統合レビュー第2回`（`.claude/commands/review/history/2026-08-30_all_2.md`P1-3）の
  指摘。`MapView.tsx:2949-2953`・`:2965-2969`が、風・勾配それぞれのOFF処理から共通の
  `clearRoadTileFeatureState`を呼ぶ。この関数は`map.removeFeatureState({source,
  sourceLayer})`でソース単位の全feature-stateキーを消す（MapLibre仕様、キー単位の
  選択的削除はできない）。T414設計により風・勾配は排他ドメインではなく同時ON可能なため、
  両方ON状態で片方だけOFFにすると、もう片方の色分けも次のフェッチ/ビューポート変更まで
  灰色に戻ってしまう。
- Root Cause: T440のPart D統合（`ensureWindAxisLayer`/`ensureGradientAxisLayer`等6関数を
  3関数へ集約）以前から、`clearWindAxisFeatureState`/`clearGradientAxisFeatureState`は
  元々同一実装だった（T440.mdにも「動作を変えず統合しただけ」と明記）。T440が持ち込んだ
  不具合ではなく、既存の潜在バグが今回の統合レビューで初めて言語化された。
- 対応方針: way_id単位で`setFeatureState(way_id, {[featureStateKey]: null})`する形へ
  変更するか、もう片方の軸がONのままならクリア自体をスキップするガードを追加する。
- 検証手順: 実機で風・勾配を両方ON→片方だけOFF→もう片方の色分けが消えないことを確認
  （統合レビュー時点では未実施、コード読解のみで確認済み）。
- Confidence: High（コード読解、MapLibre APIの仕様確認込み）。実機再現は未実施。
- 規模S〜M。
