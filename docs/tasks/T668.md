## 対応方針と実装

### 18ファイルの書式を揃えた

すり抜けは2パターンあった。`規模S。状態: 完了（2026-09-08）。`のように規模と同じ行へ
畳んだもの（`line.startswith("状態:")`に掛からない）と、`規模S。2026-09-07完了。`のように
「状態:」という語自体が無いもの。T632〜T658の18ファイルを
`規模X。` + 空行 + `状態: …`の形へ揃えた。

### 照合不能を参考情報から違反へ格上げ

`check_plan_vs_tasks`は「状態:」行が無いとき`infos`（違反にならない参考出力）へ回して
いた。これでは書き忘れが黙って通り、次に誰かが全件監査するまで照合がスキップされ続ける。
違反へ格上げし、pre-commitが新規タスクの書き忘れをブロックするようにした。18ファイルを
直した直後で既存の引っかかりが無い今が格上げの機会だった。

### 「見送り」の語の分類を用語法へ合わせた

`OPEN_STATUS_WORDS`に「見送り」が入っており、コメントは「見送り・保留はトリガー待ちで
improvement-plan側も[ ]のまま」と述べていた。しかしCLAUDE.md「コミット時の同期ルール」
6番は「見送り」を**今後もやらない確定判断**と定義し、実際`T642`は見送りで`[x]`。語が2つの
意味で使われていた。

「見送り」をCLOSED側へ移し、トリガー待ちは「保留」で表すことに一本化した。唯一の例外
だった`T422`（見送りと書きつつ本文にトリガー条件があり`[ ]`）は実態どおり「保留」へ直した。

### 再発防止

- `docs/workflow.md`「1. 着手前」へ書式（行頭が`状態:`）と語の選び方を明記した。
- `scripts/tests/test_review_checks.py`へ`task_status_kind`の回帰テスト4件を追加
  （行頭でないと検出されないこと・見送り/保留の分類）。
