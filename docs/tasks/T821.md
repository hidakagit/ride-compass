# T821. 同じ規則が複数箇所へ書き写されている箇所を1つへ寄せる

規模M。
状態: 完了（2026-09-14。統合レビュー第8回のP2/P3を束ねたもの、2026-09-13起票）

## 背景

**同じ理由で変わるものが分かれて書かれている**箇所。`review_checks.py duplication`
（完全一致のクローン検出）は17件で前回23件から減っているが、**下記はいずれも1件も
捕まっていない**——値の直書き・組み立て規則の手書き・処理順序の写しは原理的に検出できない
（`complexity.md`「写経の監視」3項）。

## 実施結果

一覧の全件を1つへ寄せた。寄せ方が単純な抽出でなかったものだけ記す。

- **停止の待ちの材料id**: `stop_count_material_ids()`から取る形にした。ここだけ組み立てて
  いると、向こうで綴りを変えたときにこちらだけが`None`を引き、全区間の停止の待ちが無言で
  0秒になる（例外も出ない）。
- **災害グループのソースキー**: `dynamicWeather.ts`へ`DISASTER_SOURCES`（キーとフェッチ単位の
  組）を新設し、凡例・フェッチの有効判定・表示状態の3箇所がそこを読むようにした。凡例の
  `key`は`DisasterSourceKey`型で縛ったので、改名すると型検査が落ちる。
- **天気カテゴリの語彙とアイコン**: 上位集合を持つ`weatherCode.ts`が
  `WEATHER_CATEGORY_LABEL`/`WEATHER_CATEGORY_ICON`を公開し、アメダス側はそれを読んで
  「晴れの昼夜切り替え」だけを足す形にした。
- **`ROAD_FILTER_AXES`の配線**: 軸宣言へ`layerId`を足し、画面側は軸を走査して
  サマリ・内訳を作る。これで「軸定義を1つ足すだけでよい」が画面側でも本当になった。
- **真偽値プロパティのレイヤー**: `buildBooleanLayerDefs`を新設（文字列列挙版の
  `buildCategoricalLayerDefs`と同じ役割）。tunnel/onewayが同じビルダーを通る。
- **区分線形補間**: 計算（丸めなし）と表示用の丸めを分け、`scoreDistribution`は委譲だけに
  した。**同じxが並んだときの返り値が食い違っていた**（片方はy0、もう片方はy1）ので、
  np.interpと同じy1へ揃えた。
- **重み付き項の作り方**: `_axis_terms`へ切り出し、和だけ求める経路と合成の本体が同じ
  関数を通るようにした（docstringが手動同期を前提にしていた状態を解消）。
- **寄与の有無の判定**: `hasContribution`をexportし、空状態の案内を出す側とバーを描く側が
  同じ関数を見る。
- **dirty印**: CSS Modules側に`dirtyDotOnTab`（位置だけ足す）を置き、Tailwindの任意値で
  同じ形を書き直すのをやめた。
- **`healthApi`**: 素の`fetch`＋`catch {}`をやめ、共通骨格（`lib/fetchJson.ts`）を通す。
  失敗の中身がdebugLogへ残る。返り値の契約（OK/NGの2値）は変えていない。
- **`DISTANCE_TOLERANCE_KM`**: backendへ`DEFAULT_DISTANCE_TOLERANCE_KM`を置き、生成物
  （`route-generate-config.json`）経由でフロントへ配る形にした（本筋どおり生成物側へ足した）。
- **得点帯の警告**: 表示ラベル文字列で引くのをやめ、両端の位置で引く。ラベルを言い換えても
  警告が消えない。
