# T763. 候補の後処理チェーンを1箇所へ寄せる 規模S

状態: 完了（2026-09-12。起票は同日、[T621](T621.md)の設計中に見つけた）

## 背景

`route_generator.py`は、候補を返す3経路（周回・目的地・経由地）それぞれで同じ4行を
並べていた（`_with_overall_difficulty`→`_with_axis_difficulties`→
`_with_axis_contributions`→`_with_material_values`）。「候補を評価済みの完成形へ
仕上げる」という1つの手順が、呼び出し側に3回写経されている状態で、
[design-principles.md](../design-principles.md)構造仕様8の「拡張点は1本道」に当てはまる。

## 起票時の理由は、測ったら裏付けられなかった

起票時は「揃わなくても型は通り、テストも経路ごとに独立しているため気づきにくい」
「合成と独立に価値がある」と書いた。**どちらも実測ではなく想像だった**
（2026-09-12ユーザー指摘「T763は、ルート合成をしなくても独立して意味があるものなのか」）。

`route_generator.py`の全履歴37コミットについて、4段それぞれが何箇所に書かれていたかを
数えた:

```
for c in $(git log --format=%h -- backend/app/services/route_generator.py); do
  git show $c:backend/app/services/route_generator.py |
    grep -c '_with_overall_difficulty(c) for c'   # 他3段も同様に数える
done
```

| 時点 | overall | axis_difficulties | contributions | material |
|---|---|---|---|---|
| 現在 | 3 | 3 | 3 | 3 |
| T592（4段目を追加）直前 | 3 | 3 | 3 | 0 |
| T551（3経路目が増えた）時点 | 3 | 3 | 3 | 0 |
| T550（3段目を追加）時点 | 2 | 2 | 2 | 0 |
| T402（2段目を追加）時点 | 2 | 2 | 0 | 0 |

**4つの数が食い違ったコミットは1つも無い。** 段が3回増え（T402・T550・T592）、経路が
2回増えた（T364・T551）にもかかわらず、毎回すべての箇所へ同一コミットで入っている。
`evaluate_loops`を呼ぶ箇所も`route_generator.py`以外に存在せず、チェーンを迂回して
`RouteCandidate`を作る経路も無かった。

**予測した失敗（どれか1経路だけ後処理が1段抜ける）は一度も起きていない。**
この写経を寄せることの価値は、実績ではなく構造仕様8に照らした先回りであり、
[T621](T621.md)が4本目の経路（合成ルート）を足す直前に効かせるのが素直だった。

### 一方で、実在した乖離はドキュメント側にあった

`docs/modules/backend/routing-engine.md`の生成フロー図は3段しか書いておらず、
**T592で入った4段目（`_with_material_values`）が欠けていた**。集約されるフィールドの
説明からも材料値が落ちていた。**揃わなかったのは写経した3箇所ではなく、写経を説明した
1箇所だった**——これは合成と無関係に、いま実在する乖離。

## 実施内容

| 変更 | 内容 |
|---|---|
| `route_generator.py` | 契約検査の1枚（[T746](T746.md)で入れたもの）へ集約段を取り込み、`_evaluate_loops`→`_evaluate_and_aggregate`へ改名。呼び出し3箇所から4行ずつを削除 |
| `routing-engine.md` | フロー図の集約段を、段を数え上げる書き方から「候補を返す経路はすべてこの1メソッドを通る」という挙動の記述へ置き換え（docs/documentation.md）。契約検査の名前も追随 |

目的地経路は`is_shortest_distance`の印付けを評価とチェーンの間で行っていたため、
チェーンの後へ移した。集約段は候補の並び順・印を読まない（`model_copy`で対象フィールド
だけを更新する）ため、印付けが前でも後でも結果は変わらない。この不変条件は
`_evaluate_and_aggregate`のdocstringへ現在形で書いた。

## 検証結果

- `pytest tests/test_route_generator.py` → 50 passed。
- **1箇所の削除が3経路すべてへ効くことを確認**（「実装した」ではなく「効いている」）:

  | わざと消した段 | 落ちたテスト（経路） |
  |---|---|
  | `_with_axis_contributions` | `..._is_distance_weighted_average_of_segments`・`..._sum_matches_overall_difficulty`（周回）／`test_generate_via_waypoints_also_aggregates_axis_contributions`（経由地） |
  | `_with_overall_difficulty` | 上記に加え`test_generate_destination_routes_sorts_by_overall_difficulty`（目的地） |

  寄せる前は各経路が自分のコピーを持っていたため、1箇所を消しても1経路しか落ちなかった。
