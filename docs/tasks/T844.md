# T844. 鮮度台帳が出すコマンドが、そのまま打つと本番へ効かないか本番を止める

規模S。
状態: 完了（2026-09-14。ユーザー指摘「管理画面でコピーできてもどうにもならなくない？
本番環境で実行する必要があるし、実行するにもdocker内で実行する必要があるからコピペそのまま
できない」から）

## 背景

「鮮度」タブは作り直し待ちの件数とともに `python -m app.batch.refresh_derived` を出すが、
これは本番で打つべきコマンドの内側半分でしかなく、素直に使うと2通りに壊れる。

- 手元へコピペすると `backend/.env` が向く開発DBを作り直して成功する。本番は古いままで、
  直したつもりになる。
- 本番VMで最も自然な打ち方（稼働中の `ridecompass-backend` へ `docker exec`）をすると、
  `--memory=6g` のコンテナ内で走りOOM killでサービスごと落ちうる。

管理画面から実行を要求できるようにする本筋は[T839](T839.md)（規模L、保留中）。本タスクは
その保留の間、**表示側だけ**を安全な側へ倒す。

## 対応方針

画面が出すのは「本番VMでそのまま打てる1コマンド」とする。打つ場所・実行後に要る後処理は
ⓘの奥へ置き、手順の正本は`docs/disaster-recovery.md`に置いたままにする（画面へ手順書を
写さない）。

コマンドの形は`deploy-backend.yml`がmigration適用に使っている使い捨てコンテナと同じ骨格
（`docker run --rm --network=host --env-file`）に、メモリ上限・キャッシュのマウント・
`--skip-landcover`を足したもの。

**既知のトレードオフ**: イメージ名・env fileのパス・キャッシュのマウント先は
`deploy-backend.yml`と重複する。片方だけが変わると画面のコマンドが静かに古くなるが、
コピーできる形で出すことを優先した（正本の所在はコード側コメントとモジュール文書に書いた）。

`--memory=4g`は実測値ではなく初期値。VM全体11GBをbackend（上限6g）・Redis（2gb）・
PostgreSQL・OSで分け合う中で、`docs/disaster-recovery.md`の目安（物理メモリの50〜70%、
他プロセスの分を残す）へ収まる範囲から置いた。超えた場合に死ぬのはこの使い捨てコンテナだけ
なので、外した方向が安全側に倒れる。

## 実装メモ

- `DerivedDataFreshnessPanel.tsx`: `REBUILD_COMMAND`を`docker run`一式へ差し替え、export
  してテストが実物を参照できるようにした。コマンド行に`InfoPopover`を1つ足した。
- 作業中に、`styles.commandRow`がCSSに**定義されていない**（TSXからのみ参照）ことが判明。
  `<code>`がinlineのままで`overflow-x`が効かず、複数行にした途端に破綻する状態だった。
  `.commandRow`を定義し`.command`を`display: block`にした。
- `axis-studio.md`へ現状の挙動（本番でそのまま打てる形で出す・正本はdisaster-recovery.md）
  を反映。

## 検証結果

- `npx vitest run src/components/AxisStudio/DerivedDataFreshnessPanel.test.tsx` → 10 passed。
- ガードが効いていることの確認: `REBUILD_COMMAND`を素の`python -m app.batch.refresh_derived`
  へわざと戻すと「作り直しのコマンドは、本番で安全に実行できる形になっている」が
  `expected 'python -m app.batch.refresh_derived' to contain 'docker run --rm'` で落ちる
  （1 failed | 9 passed）。戻して10 passedを再確認。
- 390px幅でplaywright（chromium headless）へ実描画し実測: `documentScrollWidth` 390 =
  viewport 390（ページは横に伸びない）、コマンド枠は clientWidth 285 / scrollWidth 337 で
  枠の中だけが横スクロールする。コピーボタンの右端は350pxで画面内。
  CSS修正前の同じ測定では clientWidth 0 / scrollWidth 0（inlineのため枠が成立していない）。
