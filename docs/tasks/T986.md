# T986. 事故データの対象年が、移行で3年から1年へ縮んでいる 規模S

状態: 未着手（2026-09-21起票）。

## 背景

旧の取込は`--years 2022-2024`（3年分）で、本番DBには303,455件が入っている。T970で
取込をプロファイルの宣言へ移したとき、`source_profile.yaml`の`years`が`[2024]`だけに
なり、新DBは108,409件（ほぼ2024年のみ）になった。件数比は約2.8倍で、3年対1年と整合する。

**設計は正しく、値の引き継ぎが漏れている。** 母集団の宣言をプロファイルへ寄せる方針
（CLAUDE.md・`source_profile.yaml`冒頭）はそのままで、宣言する値が変わってしまった。

## 利用者から見て何が変わるか

事故密度は**件/(km・年)**で正規化するため、対象年が変わると軸の値が変わる。新旧を同じ
wayで突き合わせると、`accident`軸は60本中16本で差が出て、最大差は満点から0への振り切り
だった（0.0→48.9、13.3→0.0など、両方向）。その年に事故があったかどうかで決まるため、
**1年分では特定の年の偶然に左右されやすい**。

同じ比較で、タグ由来の軸（`bicycle_infra_quality`・`night`・`surface_q`）は60/60・25/25で
完全一致している。差は事故データの母集団だけに由来する。

## 対応方針

`source_profile.yaml`の`years`を旧と同じ範囲へ戻し、事故の取込と、それを読む派生
（`derive_counts`）を流し直す。何年を対象にするのが妥当かは、較正の観点から別途決める
価値があるが、**まず移行前と揃えてから**判断する（移行で静かに変わったものを、そのまま
新しい既定にしない）。

## 完了条件

- 新DBの事故データが旧と同じ年範囲を含む
- 同じwayで`accident`軸を突き合わせ、差が事故データの更新分で説明できる範囲に収まる
  （`benchmarks/bench_output_diff.py`で確認する）
