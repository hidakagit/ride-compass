# T884. テストの足場が写経で膨らんでいる

規模M。
状態: 実施中（段階1をmasterへ反映済み、残りは段階2。2026-09-16起票。[T882](T882.md)で走査対象を広げたときに初めて見えた）

## 背景

[T882](T882.md)までコピペ検出は1,000行超のファイルを走査していなかった。上限を外して
見えるようになった重複は、**ほぼすべてテストの足場**だった。

同一ファイル内の重複が大きいもの:

    924行 / 35件  frontend/src/components/AxisStudio/AxisComposer.test.tsx
    451行 / 36件  frontend/src/app/page.test.tsx
    281行 / 23件  backend/tests/test_road_graph_engine.py
    153行 / 18件  backend/tests/test_road_graph_repository.py
    117行 / 12件  frontend/src/components/AxisStudio/AxisStudio.test.tsx

ファイルをまたぐぶんも、10件のうち8件が`AxisStudio`のテスト群どうしである。最大の
クローンは`page.test.tsx`と`RouteSettingsPanel.test.tsx`の間の20行。

中身は、軸スタジオのウィザードを歩く手順（表示名を入力→次へ→評価の形を選ぶ→次へ→
材料を選ぶ→係数を入れる）が、テストケースごとにそのまま書き写されている形。

## 対象から外すもの

`frontend/src/components/Map/icons.tsx`（757行・1件）は外す。51個のアイコンが同じSVGの殻
（`<svg width={size} height={size}>`＋`stroke="currentColor"`・`strokeWidth="1.6"`）を
共有しているために1つの大きなクローンとして出るもので、各アイコンは`d`だけが違う。
殻を共通化することはできるが、1件ずつ独立して読めることの方が価値が高い。

## 保留することで何が起きうるか

- ウィザードの手順が1つ変わるたびに、書き写した数だけ直すことになる。直し漏れたテストは
  古い手順のまま緑になり続ける（通らなくなって初めて気づく形ですらない）。
- [T882](T882.md)で前回比の起点を27件へ置き直したばかりで、ここを畳まないと「増えたか」の
  判断がテストの足場の増減に埋もれる。

## 段階1: AxisComposer.test.tsx（2026-09-16完了）

2つのヘルパーへ寄せた。**足場だけを寄せ、テストが確かめている中身は変えていない。**

- `renderComposer(options)`: 41箇所の`render(<AxisComposer ... />)`。`editing`/
  `duplicateFrom`/`onSave`だけが違い、残りは同一だった。
- `goToShapeParams(user, label, shape?)`: 25箇所のウィザード歩行（表示名を入力→次へ→
  点数のつけ方を選ぶ→次へ）。`shape`省略時は既定の選択のまま進む。

    1,107行 → 1,030行（-177行/+100行）
    同一ファイル内の重複 924行/35件 → 上位から消滅（残るのは8〜11行のテストケースの類似）
    ファイルをまたぐクローン 27件 → 23件

`onSave`の型は`makeSaveSpy()`の戻り値から引く。`ReturnType<typeof vi.fn>`と書くと
呼び出し可能な形を失い、propへ渡せない（`tsc`で捕まえた）。

## 寄せないと決めたもの

- **`frontend/src/app/page.test.tsx`（451行/36件）**: 重複はテストの入力データ
  （`makeCandidate`で候補ルートを組む部分）で、`edge_ids`がテストごとに違う。畳むと
  各テストが何を確かめているか読めなくなる。`cmd_duplication`が同一ファイル内を
  数えないのはこの型のためで、その判断どおりに残す。
- **`frontend/src/components/Map/icons.tsx`（757行/1件）**: 51個のアイコンが同じSVGの殻
  （`<svg width={size} height={size}>`＋`stroke="currentColor"`・`strokeWidth="1.6"`）を
  共有しているために1つの大きなクローンとして出る。各アイコンは`d`だけが違い、
  1件ずつ独立して読める方が価値が高い。

## 残っている作業

- **`backend/tests/test_road_graph_engine.py`（281行/23件）**: こちらは本物の足場で、
  5ノードの直線グラフと`WeatherConditions`を毎回組み直している（47行・40行・23行）。
  同等の`_spliceable_context(edge_count=4)`が同じファイルの下にあり、2箇所がそれを
  使わず手で組んでいる。ノード名（`o,a,b,c,d`と`o,n1..n4`）の違いを吸収して寄せる。
- **`backend/tests/test_road_graph_repository.py`（153行/18件）**: 未調査。
- **`vi.mock`の前置き**: `axisPreviewApi`・`materialCatalogApi`を落とす14行が
  `AxisStudio`のテスト5ファイルで共有されている（ファイルまたぎのクローンの残り）。
  `vi.mock`はホイストされるため工場をそのまま外へ出せず、共有モジュールを動的importで
  読む形になる。指の込んだ書き方になるので、効果と読みやすさを比べてから決める。
## 対応方針

ケースごとに書き写されている手順を、テストごとのヘルパーへ寄せる。**足場の共通化であって、
テストが確かめている中身は変えない**——1件ずつ独立して読めることは保つ。

`review_checks.py`には既に`duplicate_test_scaffold`（同じ名前のテスト足場が複数ファイルに
ある、参考表示）があり、ファイルをまたぐぶんはそこにも現れる。
