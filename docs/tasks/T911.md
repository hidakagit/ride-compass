# T911. 外縁のケースが違反として成立していなくても、GAPに見える

規模S〜M。
状態: 未着手（2026-09-16起票。[T901](T901.md)の実装中に、塞いだ穴の**逆向き**として残ると
分かって分離）

## 背景

[T901](T901.md)は「外縁を母集団の内側へ書いた」ケースを塞いだ。`detected=True`の外縁は
`history/guard_edges.json`の観測記録を要求され、記録の無いものは`UNPROVEN`で落ちる。

塞いでいないのは逆向きである。**外縁の違反そのものが成立していないと、検知器が見逃すのは
当たり前**で、それも`GAP`として同じ見た目になる。実例がある——[T890](T890.md)が置いた
`map_redraw_coverage`の外縁は、繋ぎ方に名前を書いていたせいで「到達している」と読まれ、
**何も試していない状態で`GAP`を出し続けていた**（[T905](T905.md)で判明し、副作用importへ
書き換えた）。

T901が入ったことで、この見え方の問題は少し重くなった。`mutate --update`が観測した`GAP`を
記録へ足すため、**成立していない外縁にも「一度は見逃した」という記録が付く**。記録は
`detected=True`を正当化する根拠として使われるので、成立していない外縁が後で母集団へ
入った（ように見えた）とき、それを検算する手段が無い。

## 保留することで何が起きうるか

穴として数えている14件のうち、いくつが本当に穴なのかが分からないままになる。周期レビューは
「既知の穴◯件」を進捗の分母として報告しているため、成立していない外縁が混じると
**埋めるべき対象の数そのものが間違う**。T901が塞いだのは「穴が無いと誤認する」側で、
こちらは「穴があると誤認する」側である。

## 対応方針（未検討、起票時の見立て）

案1（起票時の[T901](T901.md)案2に相当）: 外縁ごとに**対照ケース**——同じ違反を母集団の
内側へ置いたもの——を一緒に走らせ、「内側は検知・外縁は見逃し」が両立するときだけその
外縁を正当とみなす。違反が成立していなければ内側でも検知されないので落ちる。
**注意**: この案は`GAP`の行だけを検算する。`COVERED`の行では「外縁は見逃し」が成り立た
ないため判定できず、T901が塞いだ側は塞げない（T901の起票時にはこの案が上位互換と
書かれていたが、実際には直交している）。

案2: 外縁の多くは「同じテキストを別のパスへ置く」形をしている（`narrative`・
`dead_file_refs`・`source_narrative`・`redis_skeleton`・`bare_basemodel`・
`module_redefinition`・`review_doc_dead_refs`等）。`EdgeProbe`が手続きではなく
`(内容, 内側のパス, 外側のパス)`を持つ形にできれば、対照ケースは追加の記述なしで導ける。
持てないもの（`call_arity`の「メソッド経由」、`source_comment_dead_identifier_refs`の
「バッククォート無し」のような**記法**が外縁のもの）だけ手続きのまま残す。

どちらを採るにせよ、**入れた後に`map_redraw_coverage`の壊れていた頃の外縁を再現し、
それが落ちることを確認する**（T905以前のコードが実例として履歴にある）。
