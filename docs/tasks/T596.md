# T596: 出発時刻・走行方位・想定速度を地図下辺の条件バー1本へ集約する

状態: 完了（2026-09-05起票・実装、分割元は[T590](T590.md)）

## 背景

生成にもレンズにも効く共通入力が、地図上のコンパス（`TravelBearingControl`）・動的レイヤーの
時刻スライダー（`DynamicLayerTimeSlider`）・生成フォームの想定速度欄（`RouteForm`）に
分散していた。[T590](T590.md)「UI設計の基準」2（1つの状態は1つの場所で操作する）に反する。

## 決定事項（ユーザー確認済み）

- 走行方位は既存の`TravelBearingControl`（MapLibreのズーム/回転コントロール直下のコンパス）を
  そのまま活かし、常時表示にする（表示条件を撤廃）。条件バーには置かない。
- 出発時刻はナウキャストの表示時刻と統合する（B1）: `useDynamicWeatherLayers`の
  `dynamicLayerTargetTime`が唯一のstateで、条件バーの出発時刻・気象レイヤーの表示時刻・
  レンズの`at`・生成リクエストの`start_time`がすべて同じ値を読む。
- 出発チップは絶対時刻表示「出発 9:30」（B2。別日は「9/6 9:30」）。
- モバイルでの地図面積の減少は許容する（B3、未回答のため既定として採用）。

## 実装

- backend: `RouteGenerateRequest.start_time: datetime | None`（naiveはJST扱い、省略時は
  `datetime.now(JST)`）→ `RouteGenerator.generate_loops/generate_via_waypoints/
  _generate_destination_routes(start_time=)` → `engine.prepare(..., now=start_time)`・
  `evaluate_loops(context, traced, start_time)`。`GenerationConditions.start_time`へエコー。
  `LoopRoutingEngine.prepare`のProtocolへ`now`を追加。
- frontend: 新規`components/RideConditionBar/`（出発チップ: 今/+1h/+2h/+3h＋
  `datetime-local`、速度チップ: range 5〜60＋数値入力、範囲は`route-generate-config.json`）を
  `page.tsx`の`.bottomControlRow`へ配置。`DynamicLayerTimeSlider`を削除し、
  `useDynamicWeatherLayers`から`sliderFrames/sliderIndex/sliderCurrentIndex/
  handleSliderIndexChange`を撤去、代わりに`setDynamicLayerTargetTime`を公開。
  `RouteForm`の速度欄と`assumedSpeed`propsを撤去。速度stateは`assumedSpeedKmh: number`。
  生成リクエストへ`start_time`（ISO文字列）を追加。
