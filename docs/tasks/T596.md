# T596: 出発時刻・走行方位・想定速度を地図下辺の条件バー1本へ集約する

状態: 未着手（2026-09-05起票、分割元は[T590](T590.md)）

## 背景

生成にもレンズにも効く共通入力が、ルート設定パネルの「走行方位を設定」ボタン・地図下部の
コンパス（`TravelBearingControl`）・動的レイヤーの時刻スライダー（`DynamicLayerTimeSlider`）・
生成フォームの想定速度欄（`RouteForm`）に分散している。[T590](T590.md)「UI設計の基準」2
（1つの状態は1つの場所で操作する）に反する。

## 対応方針

- 地図下辺に条件バー（出発時刻・走行方位・想定速度の3項目）を1本置く。デスクトップは
  地図の下辺、モバイルは下部タブバーの直上（シートが開いていても隠れない高さ）。
- 反映は即時（レンズはすぐ、探索は次の生成で）。生成後に変えたときは既存の
  「条件が変更されています」表示で足りる。
- 走行方位はコンパスのポップオーバー、出発時刻は時刻ピッカー（ナウキャストのスライダーは
  気象レイヤー専用の別物として残すか、同じ時刻状態に統合するかを着手時に判断する。
  統合する場合は`dynamicLayerTargetTime`と生成の`start_time`が同じ状態になる）。
- ルート設定パネルの方位ボタン、生成フォームの速度欄、地図のコンパスを撤去する。
  生成フォームには距離・候補数・周回/経由地だけが残る。

## 対象ファイル

`frontend/src/app/page.tsx`・`components/RouteForm/`・`components/TravelBearingControl/`・
`components/DynamicLayerTimeSlider/`・`components/RouteSettingsPanel/RouteSettingsPanel.tsx`・
新規`components/ConditionBar/`（[T590](T590.md)の設計に基づく新規、`docs/modules/README.md`
索引から責務が一致するモジュールへ追記）・`docs/modules/frontend/`該当モジュール。

## 完了条件

- 3項目の操作UIがアプリ内に各1箇所しかない。
- 条件バーの変更がルート前のレンズ（風・勾配）へ即時反映され、生成時のリクエストにも
  同じ値が乗る。
- モバイルでシートを最大高さ（80vh）にしても条件バーが隠れない（実機確認）。
