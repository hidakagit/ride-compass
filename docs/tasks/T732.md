# T732. npx()のパス解決を直し、写経の監視をLinuxでも動かす 規模S

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 I-8（P2））

## 背景

`Path(npm).resolve().parent / "node_modules" / "npm" / "bin" / "npx-cli.js"`が二重解決になり、CIと同じLinux環境では`duplication`が常にスキップされる。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 原因

`shutil.which("npm")`が返すのはPATH上のシンボリックリンク（POSIX）かシム（Windows）で、
**OSによってその先の並びが違う**。POSIXでリンクを解決するとnpm本体の`bin/npm-cli.js`
そのものになるため、そこから改めて`node_modules/npm/bin`を足すと二重になる。

```
/opt/node22/bin/npm -> ../lib/node_modules/npm/bin/npm-cli.js
Path(npm).resolve()                       = /opt/node22/lib/node_modules/npm/bin/npm-cli.js
... .parent / "node_modules/npm/bin/npx-cli.js"
                                          = /opt/node22/lib/node_modules/npm/bin/node_modules/npm/bin/npx-cli.js  ← 存在しない
実体                                       = /opt/node22/lib/node_modules/npm/bin/npx-cli.js
```

## 対応

**パスを組み立てて当てにいくのをやめ、候補を順に確かめて実在するものを返す**
（`npx_cli_path`）。OSごとの分岐を書くより、ファイルシステムに聞く方が正しい
——並びは環境（nvm・Volta・Windowsのシム）によっても変わる。

## 検証結果

- `python scripts/review_checks.py duplication` がこのLinux環境で**実際に動いた**
  （修正前は「スキップしました」）。ファイルをまたぐクローン17件・重複行186行/100,189行
  （0.19%）を出力。写経・重複は指摘が増えている2型のうちの1つで、その監視が復活した。
- 検出結果には[T737](T737.md)（重複・写経の一括是正）の対象がそのまま並んでいる
  （`measure_axis_saturation.py:82`↔`axis_preview_service.py:63`の25行等）。
- 単体テストを3本追加（POSIXのリンク解決後の並び・シムの隣にnode_modulesがある並び・
  どちらでもないときはNone）。`pytest scripts/tests/test_review_checks.py` → 57 passed。
