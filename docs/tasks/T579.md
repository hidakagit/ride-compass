# T579: test_wind_way_serviceの時刻依存フレーク（23時台に必ず失敗する）

状態: 完了（2026-09-04起票・同日修正）

## 背景

2026-09-04 23:20（JST）にbackend全体テスト（`pytest -q -m "not postgis"`）を実行した
ところ、`tests/test_wind_way_service.py::test_at_none_defaults_to_now_without_raising`だけが
失敗した。変更前のHEAD（c68b50b）でも同じ時刻に再現し、[T578](T578.md)の変更とは無関係。

原因: テストが用意するhourly時刻配列`wide_times`が「今日の00:00〜23:00」の24本のみで、
`WindWayService.get_way_values`が既定で使う`datetime.now(JST)`が23:00を超えると
`_nearest_time_index`の範囲判定（`target > max(parsed)`）で範囲外（None）になり、
「風の評価対象時刻が風グリッドの範囲外」として値が返らない。23:00〜23:59に実行すると
必ず失敗する。

## 対応方針

テスト側の修正で足りる（実装の`_nearest_time_index`は「範囲外は不明扱い」という
意図どおり）。`wide_times`を翌日00:00まで（または今日と翌日の48本）用意し、
どの時刻に実行しても範囲内に収まるようにする。

## 影響

放置すると、23時台に走るCI・ローカルのフルスイートが本タスクと無関係な理由で赤になり、
他タスクの最終検証を再実行させる。

## 実施内容（2026-09-04）

`tests/test_wind_way_service.py::test_at_none_defaults_to_now_without_raising`の
`wide_times`を「今日00:00〜翌日00:00」の25本（`timedelta`で生成）へ変更した。
`_nearest_time_index`は配列の最終時刻を超えると範囲外扱いにするため、翌日00:00を
含めることで23時台の実行でも範囲内に収まる。実装側は変更なし。同ファイル11件通過。
