# T901. 外縁のケースが母集団の内側に書かれても、初日からCOVEREDに見える

規模S。
状態: 未着手（2026-09-16起票。[T890](T890.md)・[T891](T891.md)の実施後に、同じ型が
もう1段外側に残っていないかを点検して見つけた）

## 背景

[T890](T890.md)は「検知器が取りこぼしていないこと」を測るために、検知器ごとの**外縁の
ケース**（拾うべきなのに母集団へ入らない位置）を`guard_probe_edges`へ1件ずつ置いた。
**ケースを足し忘れることは機械的に防げている**——強制検知器に外縁が無ければ
`scripts/tests/test_review_checks.py`が落ち、`mutate`も`NO-EDGE`を違反として出す
（検知器キーを1つ足して実験し、両方が名指しで報告することを確認した）。

防げていないのは**中身**である。外縁のケースを母集団の**内側**へ書いてしまうと、その行は
初日から`COVERED`になり、穴が無いのと同じ見た目になる。いまの23件のうち21件は
「一度は`GAP`だった」ことが記録の代わりになっている（17件は今も`GAP`、4件は
[T891](T891.md)で`GAP`→`COVERED`へ変わった）が、**これから足す行にはその裏付けが無い**。

## 保留することで何が起きうるか

次の周期レビューが「検知器は取りこぼしていない」と報告するとき、その根拠は
「外縁が全件COVERED」になる。内側に書かれた外縁ケースが混じっていると、**母集団に穴が
あっても報告の見た目は同じ**になり、レビューの結論からその区別が消える。第9回→第10回で
起きた「検知器の母集団が1段メタな層で再発した」のと、層が1つ増えただけの同じ型である。

## 対応方針（未検討）

案1: 新しく足す外縁は`detected=False`から始めることを規約にし、`COVERED`で生まれた行を
`mutate`が参考出力する（「内側に書いていないか」を書いた人の目へ入れる）。
案2: 外縁ケースが母集団の外にあることを機械で確かめる——同じ違反を母集団の**内側**へ
置いた対照ケースも一緒に走らせ、「内側は検知・外縁は見逃し」の両方が成り立つときだけ
その外縁を正当とみなす。案1より強いが、ケースごとに対照をもう1つ書くコストがかかる。
