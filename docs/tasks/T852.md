# T852. JMAタイルの配信障害が、地図の上では「危険度ゼロ」と見分けられない

規模M。
状態: 未着手（2026-09-14起票。[T820](T820.md)から分離）

## 背景

`jmaTileProtocol.ts`は`response.ok`でない応答をすべて空タイルへ倒す。MapLibreは失敗タイルを
再試行しないため、例外にすると以後その位置が永久に空白になるからで、この挙動自体は正しい。

T820で404（疎な格子状タイルでは正常系）と5xx（配信の障害）を区別してログへ残すようにしたが、
**画面には何も出ない**。キキクルのように「平常時は透明」が正常系のレイヤーでは、利用者が
配信障害を危険度ゼロと読む余地が残っている。

## 保留することで何が起きうるか

大雨で土砂災害の危険度が上がっている最中に配信が落ちても、地図は平常時と同じ見た目になる。
気づく手段はデバッグモードのログだけで、走行中の利用者には届かない。

## 難しいところ

プロトコルハンドラは`maplibregl.addProtocol`へ登録するグローバルな関数で、MapLibreの
ソースidを知らない。レイヤーのデータ状態（`useLayerDataStatus`の`markSourceErrored`）へ
繋ぐには、タイルURL→ソースidの対応をハンドラ側へ渡す経路が要る。
