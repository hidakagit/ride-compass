# T519. 研究モードを一般利用者向けのヘッダーメニューへ再配置し、/admin依存を解消する 規模S〜M

状態: 完了（2026-09-01）

- 背景: `researchEnabled`フラグ（`frontend/src/lib/researchMode.ts`、`localStorage`キー
  `ridecompass:research-enabled`）はサーバー側検証を一切持たない。フラグを有効化する
  唯一の意図されたUI（`ResearchPanel`）は`/admin`（Basic認証保護下）の「研究」タブに
  しかないが、フラグの実体は素の`localStorage`のため、一般公開トップページ（`/`、
  認証なし）を開いたブラウザのDevToolsコンソールから
  `localStorage.setItem('ridecompass:research-enabled','1')`を実行するだけで、`/admin`を
  一切経由せず任意の訪問者が研究機能（実験スロット記録・「比較」タブ・`ComparisonPanel`・
  地図上の実験スロット重ね描き。いずれも一般公開ページ`frontend/src/app/page.tsx`側に
  実装済み）を有効化できることが判明した（ユーザー指摘を受けた調査、2026-09-01）。
  `docs/tasks/T272.md`（2026-08-24完了）は「`researchMode.ts`は変更不要と判断（`/admin`
  自体が認証済みユーザーのみ到達可能になったため、表示ON/OFFトグルとしての役割のみ
  残っても意味の重複は生じない）」と記録していたが、この前提（`/admin`の認証を通った
  人だけが実質的にトグルを操作する）は技術的に成立していなかった。意図的なトレードオフ
  ではなく見落としと判断する（T272.mdへ遡及訂正を別途追記）。

  当初はこれを「セキュリティホールの穴塞ぎ」と捉え、`/admin`のBasic認証成功時に
  署名付きCookieを発行し、page.tsx側で研究機能の実効化可否をサーバー検証する案を
  検討したが、ユーザーから「それでも一般利用者向けのはずのpage.tsxに管理者権限判定
  ロジックが混在するという構造上のねじれは残ったままであり対症療法に過ぎない」との
  指摘を受けた。協議の結果、方針を転換: **比較タブ・実験スロット記録・地図重ね描きは
  一般利用者向けの機能として正式に公開する。** 元々「隠すべき機微な機能」ではなく、
  単なる「気軽に試せる比較機能」として扱ってよいという結論。一方、`WeightPanel`
  （評価重み上書きUI）は複雑さゆえに引き続き`/admin`限定のツールとして残す。

- 対応方針:
  1. `frontend/src/app/page.tsx`のヘッダー（`.headerActions`、line ~1630-1651）に、
     単一のコンテキストメニュー（アイコンボタン+ポップオーバー）を新設する。ヘッダーの
     スペースを消費しないよう、個別のトグルボタンを並べるのではなく1個のメニュー
     アイコンに集約する（ユーザー指示、2026-09-01）。実装パターンは既存の
     `WarningBadgeList`（`frontend/src/components/WarningBadge/WarningBadge.tsx`、同じ
     `.headerActions`内に既に配置されている）がRadix Popover
     （`@radix-ui/react-popover`、package.json導入済み・新規依存追加不要）で
     「常時1行のトリガーボタン→タップで詳細パネル」を実現しているのをそのまま踏襲する
     （新規UI機構は自前実装より定番ライブラリ優先の方針と合致）。
     メニュー内の項目:
     - **研究モードON/OFF**（新規） — `isResearchEnabled()`/`setResearchEnabled()`
       （`frontend/src/lib/researchMode.ts`、変更不要、既存API）を直接呼ぶトグル項目。
     - **デバッグログを表示**（既存、移設） — 現行のヘッダー直置きアイコンボタン
       （line ~1637-1649、`debugEnabled`時のみ表示という既存条件は変更しない）を、
       新設メニューの中の1項目として移す。
     新設するメニュー起動用のアイコンボタン自体は常時表示とする。
  2. `/admin`の`ResearchPanel`（`frontend/src/components/ResearchPanel/ResearchPanel.tsx`、
     チェックボックスのみ）の扱いを見直す。同じフラグを2箇所で操作できる状態を避ける
     ため、`/admin`側のチェックボックスは削除するか、一般ページ側が正になったことを
     示す案内表示に置き換える（実装時に判断）。`WeightPanel`の表示条件として
     researchEnabledの現在値は`/admin`側（`frontend/src/app/admin/page.tsx`）でも
     参照され続けるため、フラグ自体の削除ではなく「操作UIの重複」だけを解消する。
  3. docs更新（同一コミット）:
     - `docs/modules/frontend/developer-research-tools.md`: 研究モードのpage.tsx側
       サブ機能（実験スロット記録・比較タブ・ComparisonPanel・地図重ね描き）を
       「一般利用者向けのopt-in機能」として再定義。`WeightPanel`は引き続き内部限定と
       明記し、両者の切り分けを明確にする。
     - `docs/modules/frontend/page-composition.md`: 研究モードON/OFFの主導線が一般
       ページヘッダーへ変わったことを反映。
     - `docs/tasks/T270.md`: 「一般画面に開発者導線を残さない」方針でresearchMode
       関連UIを`/admin`へ寄せた経緯があるため、今回の再分類（比較機能は一般公開に
       戻す）との関係を一言補記する。
- 完了条件: 一般公開トップページのヘッダーから、`/admin`の認証を一切経由せずに研究
  モードをON/OFFでき、比較タブ・ComparisonPanel・地図重ね描きが即座に出現/消滅する
  ことを実機確認する。`/admin`側のWeightPanelがこのフラグに引き続き連動することも
  確認する。docs/modules/frontend/developer-research-tools.md・page-composition.md
  追従。
- 依存: T272（権限制御の土台、前提の誤りをT519で訂正）。T270（一般画面から研究UIを
  `/admin`へ寄せた経緯、今回一部を一般画面へ戻す）。
- 注意（実装時）: 変更箇所（`page.tsx`のヘッダー`.headerActions`部分、`/admin`の
  `ResearchPanel`）は、並行して進む「ルート結果パネル『全体プロファイル』への色分け
  設定統合」（T518、Tabs構成・ComparisonPanelのaxesフィルタ変更）と同じ
  `frontend/src/app/page.tsx`を触る。直接の競合は無い見込みだが、着手前にT518の
  進捗・完了状況を確認すること。
