# T906. 走行モデルと探索に、小さな不整合が残っている

規模M。
状態: 未着手（2026-09-16起票、統合レビュー第10回のP2/P3を型ごとに束ねたもの）

## 対象の指し方

**対象を本文へ列挙しない**（[T876](T876.md)で決めた指し方）。母集団は
[統合レビュー第10回](../../.claude/commands/review/history/2026-09-16_all.md)のP3の表のうち`domain/routing.py`・`services/`が対象の行（P3-12〜P3-16）と、P2-4・P2-6で、個票（Evidence・Impact・Recommendation）は
[シャードの生出力](../../.claude/commands/review/history/2026-09-16_all_shards.md)の該当節にある。列挙すると、列挙した側だけが古くなり、
**起票した束ねタスクが後から対象を指せなくなる**（第7回がこれに当たり、対象を確定できないまま
[T735](T735.md)が残った）。

## 型

どれも**利用者に見える結果を静かに変える**。二重計上（設計原則13）が1箇所残っている、
自転車道が「上位の道と交わる」と判定されて[T800](T800.md)で発火頻度が上がった、
合成ルートの失敗理由が汎用catchへ流れて利用者向けの説明が捨てられる、など。
落ちも警告も出ないため、**次に同じ場所を測るまで誰も気づかない**。

P3-16（合成ルートの失敗理由）は第9回から**未解消かつ悪化**（[T621](T621.md)の終点チェックで
落ちる入力が1種増えた）。

## 完了条件

- 二重計上・判定条件の是正は、**是正前の入力で結果が変わることをテストで固定する**
  （[T894](T894.md)と同じ形——直した1行を外すとそのテストだけが落ちる）。
- 失敗理由の握り潰しは、利用者向けの理由が画面へ届くところまで確認する。
- 性能に触れるもの（P3-13の最悪ケース）は、**利用者から見た単位**で測ってから判断する
  （CLAUDE.md「修正の原則」）。
