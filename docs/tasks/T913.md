# T913. 面レイヤーの差し込み位置が、基礎地図では道路より後ろへ落ちていた

状態: 完了（2026-09-17）
規模: S

## 背景

[T912](T912.md)は面レイヤーの差し込み位置を「基礎地図が最後に面を描いたレイヤーの次」と
して導いた。起票時は実行環境から`tiles.openfreemap.org`へもCDNへも出られず、実物の
レイヤー構成を確かめられないまま入れていた。

実機のログが返した位置は`boundary_3`——境界線は道路より後ろに並ぶため、面は道路を覆った
ままだった（地名だけがその上に残る中途半端な位置）。

基礎地図（OpenFreeMap liberty、111レイヤー）を取得して並びを確認すると、原因は
**基礎地図が面と線を交互に描き、道路網より後ろにも面を置いている**ことだった。

```
 20- 40 (21) 線・記号: aeroway_runway … tunnel_transit_rail_hatching
 41- 41 ( 1) 面: road_area_pattern
 42- 82 (41) 線・記号: road_motorway_link_casing … bridge_transit_rail_hatching
 83- 84 ( 2) 面: building（fill） … building-3d（fill-extrusion）
 85-110 (26) 線・記号: boundary_3 … label_country_1
```

「最後の面の次」は84の次＝`boundary_3`になる。一方、単純に道路の手前（42）へ下げるだけでは
今度は建物が面を覆う——`building`は`hsl(35,8%,85%)`の**不透明な**塗りでminzoom 13のため、
市街地では面が建物の形に穴だらけになる。両立には並びの側を直す必要がある。

## 対応

**1. 差し込み位置を`source-layer`から導く。** 道路網はベクタタイルのスキーマ
（OpenMapTiles、基礎地図はこのスキーマのタイルを配る）が`transportation`という名前で
持っている。その最初のレイヤー（libertyでは`tunnel_motorway_link_casing`、22）が
「土地の塗りを描き終えて道路網を描き始める位置」になる。

**並び順からは導かない。** 試した2通りはどちらも外れた:

- 「最後に面を描いたレイヤーの次」→ `boundary_3`（85）。建物が道路より後ろにあるため位置が
  道路の後ろまで下がり、面が道路を覆ったまま残る。
- 「線・記号が最も長く連なる区間の先頭」→ `road_motorway_link_casing`（42）。トンネル
  （22-40）と地上の道路（42-82）の境目に入り、道路網がトンネル区間だけ面の下に沈む。
  実機で「道も途切れているものがあって、主要道と細かい道の間に色が差し込まれてない？」
  として現れた。「道路網はたくさんのレイヤーで描かれる」という相関であって、道路網である
  ことの根拠ではなかった。

スキーマの名前は、スタイルの配色や見せ方が変わっても変わらない。

**2. 道路網より後ろに残る面を、道路網の手前へ動かす**（`prepareBasemapForAreaLayers`）。
libertyでは`road_area_pattern`（歩行者areaの塗り）・`building`・`building-3d`の3枚。
これで並びは「土地の塗り→このアプリの面→道路網→境界→地名」になり、面は建物の上・
道路と地名の下へ収まる。動かさないと、道路の下へ潜らせた面が`building`の不透明な塗り
（`hsl(35,8%,85%)`、minzoom 13）に穴を開けられる。

基礎地図そのものの見た目も「建物の上に道路」へ変わるが、この地図はpitchを持たず建物は
平面の足元しか描かれないため影響は小さく、面が穴を開けられない利点が上回ると判断した。

**3. 位置を決める時点を`style.load`へ移した。** 基礎地図だけが載っている瞬間でなければ
ならない（このアプリが足すレイヤーを数に入れない）。地図生成直後に購読するため、
「変わらないデータを更新」が`setStyle`後に登録する再描画のリスナーより先に走る。
差し替え時は`resetBasemapAreaLayerPreparation`で解決済みの記録を落とす。

## 効いていることの確認

- 実物のlibertyの並び（種別・`source-layer`・id、111枚）をテストのフィクスチャに置き、
  `transportation`で道路網が**トンネルも橋も含めて**全部拾えること・位置より前に土地の塗り
  （公園・土地利用・水面・空港）だけが残ること・道路網より後ろの面が3枚であることを固定した。
  **このフィクスチャは根拠ではなく、スキーマの名前で実物が拾えることの確認である**。配信元が
  スキーマを変えれば実物とずれるが、ずれたことは実行時のログ（`map:lifecycle`「面レイヤーの
  差し込み位置」、`anchorId`と`lowered`）で分かる。
- 導出を「線が最も長く連なる区間の先頭」へ戻すと5件が落ちる。戻すと11件とも通る。

## 残っていること

実機での見た目の確認は未実施（この実行環境にブラウザと配信元への到達手段が無い）。
位置そのものはログで確認できる。
