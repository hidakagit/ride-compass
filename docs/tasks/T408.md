# T408. 線状降水帯予測マップ（気象庁sjfcstmap）の導入可否調査 規模S（調査のみ）

状態: 完了（2026-08-30・調査のみ。判定: 見送り）

- 背景: T387「無償範囲で追加できるJMAデータの調査」（2026-08-29）で発見した2候補
  （降水短時間予報[rasrf]・線状降水帯予測マップ[sjfcstmap]）のうち、rasrfは[T407](T407.md)
  （2026-08-30）で実装済み。sjfcstmapは局地的豪雨・突発的な河川氾濫の主因である線状降水帯の
  発生予測プロダクトで、サイクリング中の安全という観点では降水短時間予報より実用価値が
  高い可能性がある。
- T407実装時に判明した追加情報: sjfcstmapはrasrfと同じ`targetTimes.json`
  （`https://www.jma.go.jp/bosai/jmatile/data/rasrf/targetTimes.json`）にmember="none"の
  行として混在しており（`elements: ["sjfcstmap"]`のみ、rasrfを含まない）、時刻一覧の
  取得元は既に判明している。ただし**実際のタイル画像URL・配色パターンは未検証**
  （T387時点の推測「rasrfと同系統と推測されるが未検証」のまま）。
- トリガー: ユーザーの着手指示。

## 調査結果（2026-08-30完了）

JMA公式ページ「今後の雨」（`https://www.jma.go.jp/bosai/kaikotan/`）が読み込む
`kaikotan.properties__061a966c27254fd9b2e4.xml`（コンテンツ定義XML）を実機取得し確認した。

- **タイルURLは確定・実機疎通確認済み**: `<element id="sjfcstmap" group="rasrf">`と定義されており、
  rasrfと**同じタイル配信系**（実機確認: `https://www.jma.go.jp/bosai/jmatile/data/rasrf/
  {basetime}/{member}/{validtime}/surf/sjfcstmap/{z}/{x}/{y}.png`、200 OK・`image/png`を確認済み）。
  T387の「rasrfと同系統と推測されるが未検証」は正しかったと裏付けられた。
  zoom範囲は`minZoom=4`/`maxZoom=14`/`maxNativeZoom=10`（rasrfの既存表示範囲と同等）。
- **時間軸の性質がrasrfと根本的に異なると判明（実装を左右する発見）**: 凡例SVG
  （`kaikotan/images/legend_jp_riskmap.svg`）の文言は「**今後3時間以内**に線状降水帯による
  大雨のおそれのある領域」。すなわち各`(basetime, validtime)`エントリ（`validtime===basetime`、
  targetTimes.json実データで全73件が該当）は、**その時点を起点とした固定3時間先までの
  危険域を示す単一スナップショット**であり、rasrfのような「1回のfetchで15時間先まで
  複数フレームの未来予報が並ぶ」時系列ではない。XML内の「過去12時間について、10分間隔の
  線状降水帯予測マップを表示できます」という説明は、**過去のスナップショットを遡って
  閲覧できる**（＝ナウキャストの実況フレームと同じ「過去を振り返る」機能）という意味で、
  未来方向へ予報が延びているわけではない。
- **既存の動的気象レイヤー設計（T184共通契約）との不整合**: 本アプリの動的レイヤーは
  「ONの全レイヤーが未来方向のフレーム列を持ち、共有スライダーで未来のどの時点を見るか
  選ぶ」という設計（`dynamicWeather.ts`のモジュールdocstring参照）を前提にしている。
  sjfcstmapは未来方向の複数フレームを持たないため、この設計にそのまま乗せると
  「スライダーをどこへ動かしても同じ1枚（最新スナップショット）しか出ない」か
  「範囲外として何も描画されない」のどちらかになり、他レイヤー（風・降水短時間予報等）と
  一貫した体験にならない。素直に組み込むなら、雷・竜巻ナウキャストと同じ「回避一択の
  危険、警告表示のみ」路線よりもさらに単純な、**「現在の危険域があれば警告バッジ的に
  表示するだけ」という、時系列スライダーと無関係な別実装**が必要になる。

## 判断（2026-08-30、ユーザー確認済み）

**見送り**。理由: (1) 危険域の性質上、既存の時系列スライダーに素直に乗らず、警告バッジ
相当の別設計・別実装が必要になり投資規模が調査時点の想定（規模S、rasrfと同型の拡張）より
大きくなる、(2) 「今後3時間以内の危険域」という情報は気象庁の防災気象情報
（既に`jma_warning_client.py`の警報・注意報連携でカバー範囲に近い領域を扱っている）と
役割が重なる可能性があり、独自レイヤーとして追加する優先度は高くないと判断。
再検討する場合のトリガー: 警報・注意報連携（既存）だけでは線状降水帯の危険を捉えきれない
という利用実績・要望が出た時点。
