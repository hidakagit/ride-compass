# T863. ベンチマークの起動は明示的にし、測ったコミットを記録する

状態: 未着手（2026-09-15起票）
規模: S

## 背景

[T793](T793.md)は「ベンチマークを押しただけで本番のビルドとコンテナ入れ替えが走る」無駄を、
ワークフローの中で振り分ける形（`paths`は`backend/**`のまま、イメージに入る変更が無ければ
ビルドをしない）で解いた。ユーザーの意図は別の形——**押しただけで起動しない**ようにし、
VMの作業コピーを新しくしたいときは明示的に起動すればよい、というもの。

明示起動にするとワークフローの振り分けを丸ごと削れるが、穴が1つある:
`backend/benchmarks/run_all.py`は**どのコミットを測っているかを記録も検査もしない**。
起動を忘れたときに出るのはエラーではなく、古いコードのもっともらしい数字で、その数字は
後からタスクエントリへ「本番実測」として引用される。

## 方針

1. `run_all.py`が実行時の作業コピーのHEADを測定結果へ添え、`origin/master`と乖離していたら
   止める（測る前に気づける）。
2. `deploy-backend.yml`の`paths`から`backend/benchmarks/**`を外し、中の振り分けを削る。
   VMの作業コピーを更新したいときは`workflow_dispatch`で明示的に起動する。
