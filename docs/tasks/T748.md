# T748. 手で列挙している母集団を洗い出し、導出へ置き換える 規模M

状態: 未着手（2026-09-11起票、[design-principles.md](../design-principles.md)構造仕様12の適用）

## 背景

統合レビュー第6回・第7回で「検知できない修正をしてしまう」型の指摘が繰り返し出た。
原因は個別の修正の質ではなく、**検査の母集団が「書いた時点の実例の書き写し」になっている**
ことにある。書いた時点では導出と書き写しは同じ結果を返すため見分けがつかず、
差が観測できるのは新しいメンバーが増えた瞬間＝既に見逃した後になる。

型別の推移がこれを裏づけている。集合を導出に変えた領域（軸の1本道）は指摘が
8件→3件へ減り、手で数えている領域（docs/コメントのずれ、写経）は13→17件・6→13件へ増えた。

## 対応方針

**一度きりの棚卸し**として、母集団を手で書いている箇所を洗い出し、導出できるものを
置き換える。個別に判明済みのものは各タスクが持つ（[T728](T728.md)・[T730](T730.md)・
[T731](T731.md)・[T736](T736.md)・[T740](T740.md)・[T747](T747.md)）ため、
本タスクは**まだ誰も気づいていないものを見つける**ことが目的。

探し方（それ自体を手で列挙しないよう、機械的な手掛かりから入る）:

- テスト・検知器の中のリテラル集合（`== dict[str, float]`のような型の名指し、
  軸id・材料id・ファイル名の配列、`glob("precompute_*.py")`のようなパターン）
- 「◯箇所だけ」「現在はN件」と書いたコメントの近くにある列挙
- 除外リスト（`*_ALLOWLIST`・`AXES_WITHOUT_*`・`continue`で飛ばしている条件）

各箇所について、(a) 導出へ置き換える、(b) 過剰検出のコストが実害を上回るため手動に留める
（理由をその場に書く）、のいずれかへ分類する。

## 完了条件

- [ ] 洗い出した箇所が(a)(b)のいずれかへ分類され、(a)は置き換えが済んでいること
- [ ] (b)に留めたものは、何を手動にしたかと理由がその場に書かれていること
- [ ] 「手書きの一覧の更新漏れを検出するための検査」が新たに増えていないこと
