## 実施内容（2026-09-10）

### 未定義トークン

`--shadow-md`・`--font-size-xs`・`--color-warning-soft`に加え、同じ形で見つかった
`--color-accent-soft`・`--color-surface-hover`・`--font-mono`・`--color-danger-muted`も
同時に閉じた（同じ欠陥が同じファイルに並んでおり、片方だけ直すと残りが次の指摘になる）。

| トークン | 対応 |
|---|---|
| `--shadow-md` | 参照を`var(--shadow-float)`へ。出発時刻ポップオーバーだけ濃い影だったのを他の浮きパネルへ揃える |
| `--font-size-xs` | `globals.css`へ定義（0.75rem、モバイル0.7rem）。`--font-size-sm`/`md`と同じ3段のスケールになる。実効値が3箇所で2種（0.72/0.75）に割れていたのを1つへ |
| `--color-warning-soft` | `globals.css`へ定義（ライト/ダーク両方） |
| `--color-accent-soft`・`--color-surface-hover` | 同上（`LensControl`の選択行・ホバー面） |
| `--color-danger-muted` | 同上（エラー行の下敷き） |
| `--font-mono` | 定義せず、実体だった`monospace`を直接書く（1箇所のみで、フォント指定の抽象化を新設する理由が無い） |

**ダークテーマのコントラスト**: `--color-warning-strong`（`#b45309`）は暗い面
（`--color-surface`=`#2a2a2d`）で約2.85:1しか出ず、0.65rem級の小さい文字ではWCAG AAの
4.5:1に届かない。ダークの`@media`ブロックへ`#fbbf24`（約8.5:1）を足した。

**フォールバック付き参照の一掃**: 定義済みトークンへの冗長なフォールバック
（`var(--color-accent, #2563eb)`等、19箇所）も外した。残したのは呼び出し側がインライン
styleで実行時に注入する2つ（`--width-swatch-color`・`--bottom-control-row-height`、
定義がCSSに無いのが正しい）だけ。あわせて`docs/frontend-design-system.md`へ
「テーマトークンにフォールバックを付けない」を明文化した——検知器がフォールバック付きを
「意図的な既定値」とみなして見逃す（パターン側の修正は[T705](T705.md)）ため、規約側で止める。

### 重複

- 「未使用」バッジを`components/ui/unusedBadge.module.css`へ切り出し、`RouteAxisProfile`・
  `LensControl`の両方が`composes`で参照する形にした（食い違っていた字送り・余白が1つになる）。
- `MapOverlayControls.module.css`の`.visibilityInfoButton`を
  `ui/roundIconButton.module.css`の`composes`＋サイズ上書きへ。
- `.visibilityCheckbox`系（文字「✓」ボタンの自作チェックボックス）を撤去し、同ファイルが
  既に使っている共有`ui/Checkbox`へ統一。正当化コメント（「ネイティブフォームコントロールを
  使わない方針」）は同じパネルが既にRadix Checkboxを使っており成立していなかった。
  `.detailPanel`は`document.body`直下へポータルするため`pointer-events: none`を継承せず、
  自作側が持っていた`pointer-events: auto`/`touch-action: none`も不要だった。
- `LensControl.tsx`のネイティブ`<input type="checkbox">`を共有`ui/Checkbox`へ
  （`LegendCheckboxList`と同じ`<label>`＋`aria-label`の形）。

### 語彙・配色の不整合

- 停止要因POIの`barrier`（車止め・ゲート）を`#ea580c`から中立色`#475569`へ。同ファイルの
  規約が「評価配色（緑・アンバー・オレンジ・赤）を避けた中立色」と定めており、
  `AXIS_RAMP_COLORS[2]`と同系のため「危険側」に読めていた。
- 天候ラベルを`clear`＝「晴れ」に統一（`weatherCode.ts`が「快晴」、`amedasWeatherIcon.ts`が
  「晴れ」で、同じ`SunIcon`に対しヘッダーと真下の見通しが別の呼び方をしていた）。
- `ui/statusDot.module.css`の「（設計原則8）」を平文の理由へ（現行の番号体系に無く、
  `frontend/src`で番号付き参照が残る唯一の箇所だった）。
- `global-error.tsx`が`#666`のままである理由（`layout.tsx`ごと置き換わるため`globals.css`が
  読み込まれておらず、トークンは未定義＝色指定が丸ごと無効になる）をファイル先頭へ明記。
- `MaterialRangeHint`を`.termRow`の末尾へ移し、`flex-basis: 100%`で1行を占有させた
  （ⓘと係数スライダーの間にあり、狭幅で操作要素と説明文が混ざって折り返していた）。
  置き場所は呼び出し側が`className`で足す形にし、部品自身は中身だけを持つ。

### 規約違反

`page.tsx`が`MapLayersPanel.module.css`を直接importして`.group`を借りていたのを解消。
借りていた`.group`は**単体の定義を持たず`.group + .group`だけ**で、唯一の利用箇所は
兄弟が無いため**実際には何のスタイルも当たっていなかった**。使う側（`page.module.css`）へ
`.settingsGroup`として持たせ、貸し手側の死んだ定義（`.group + .group`・消費者0件の
`.groupTitle`）を削除した。`.groupTitle`の不在を数えていた
`MapLayersPanel.test.tsx`のアサーションは、クラスが消えると`.undefined`を数えて常に0件になり
何も検出しなくなるため、h3の数とレイヤーセクション数の一致を見る形へ差し替えた。

## 見送った判断

`traffic_calming`（`#0d9488`）と補給休憩POIの「給水」が同色である点は変更しなかった。
`staticAttributeLayers.ts`の配色規約自身が「各カテゴリ群は互いに独立した凡例・レイヤーの
ため色の使い回しは問題にならない」と定めており、指定路線・コンビニ等でも既に3色が
両群で重複している。ここだけ変えると規約と実装の関係がかえって分かりにくくなるため、
規約の是非（両レイヤーは同時ONにできる）は色の付け替えではなく規約の見直しとして扱う。
