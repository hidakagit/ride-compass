# T473. windBoundaries/gradientBoundariesの軸専用propを汎用機構へ統合し、環境グループの配線漏れを解消

状態: 未着手（統合レビュー第3回で起票、2026-08-31）

- 背景: `docs/design-principles.md`構造仕様3は「`dedicated_way_value_layer`軸（wind/gradient等）の
  color expression（しきい値・配色）は、軸スタジオのデータから導出する汎用機構1つが持つ。
  軸ごとにfrontend側のファイル・関数・定数・propを新設してはならない」と明記しているが、
  design-principles.md新設（`2fef457`）・CLAUDE.mdへの必須点検追加（`d573fda`）の**後**の
  コミットで、T443が`gradientBoundaries`という軸専用prop、T466が`windBoundaries`という
  別名の軸専用prop（T443と「同型」と自己申告のうえ意図的に複製）を新設し、原則が違反された
  （統合レビュー第3回 `history/2026-08-31_all.md` P1、complexityレンズF-1）。
  加えて、環境グループ（`windPenalty.ts`のgridFill）側の表示しきい値は今回の配線から
  スコープ外とされたまま`WIND_AXIS_THRESHOLDS`のハードコードが残り、モジュール自身が
  謳う「評価軸グループと環境グループで色の意味を揃える」契約に反している（Shard D）。
  `docs/modules/frontend/page-composition.md`「暗黙の前提」節・
  `docs/modules/frontend/map-axis-coloring.md`もこの状態変化に未追従（Shard F・Shard G）。
- 対象ファイル: `frontend/src/app/page.tsx`（`windBoundaries`/`gradientBoundaries`の
  専用useMemo・専用prop）、`frontend/src/components/Map/MapView.tsx`（軸ごとの型宣言・
  分割代入・ensure引数）、`frontend/src/components/Map/windAxisLayer.ts`・
  `gradientAxisLayer.ts`、`frontend/src/components/Map/windPenalty.ts`
  （`WIND_AXIS_THRESHOLDS`ハードコード）。
- 対応方針: `page.tsx`の`windBoundaries`/`gradientBoundaries`という2つの専用useMemo/propを、
  `axisCatalog`（`axes`+`secondaryAxes`の`dedicated_way_value_layer=true`軸を横断的に抽出）
  から導出する`ReadonlyMap<string, readonly number[]>`1本（例: `dedicatedWayValueBoundaries`）
  へ統合し、MapView側も軸idキーで参照する形へ一般化する。あわせて`windPenalty.ts`の
  環境グループgridFill側も同じタイミングで同じ汎用機構から配線し、
  「評価軸グループ・環境グループで色の意味を揃える」契約を実際に満たす。
  `docs/modules/frontend/page-composition.md`「暗黙の前提」・
  `docs/modules/frontend/map-axis-coloring.md`を同一コミットで更新する。
- 規模: S〜M
