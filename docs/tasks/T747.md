# T747. キャッシュ鍵の署名を計算値にし、「上げ忘れ検出」テストを撤去する 規模S

状態: 未着手（2026-09-11起票、[design-principles.md](../design-principles.md)構造仕様12の適用）

## 背景

`CACHED_TABLE_SIGNATURE`・`SCORE_MATRIX_COLUMN_SIGNATURE`は、どちらも
`dataclasses.fields(...)`の名前から2行で計算できる純粋な値なのに、手で写した定数として
置かれている。定数の存在理由は「別の手書きの番号（`TILE_MATERIALS_CACHE_VERSION`・
`_SCORE_MATRIX_REVISION`）を上げ忘れないよう注意する」ことだけで、その注意のために
テストが2本ある（`test_graph_material_cache.py`・`test_tile_score_matrix_cache.py`）。

**計算できる値を手で写し、写し間違いを検出する検査を足している**——構造仕様12が
「その検査が必要になったこと自体が、導出にできる証拠」と述べている形そのもの。

## 対応方針

署名を計算値にし、世代を署名との複合にする。

```python
CACHED_TABLE_SIGNATURE = hashlib.sha1(
    ",".join(f.name for f in dataclasses.fields(EdgeMaterialTable)).encode()
).hexdigest()[:12]
TILE_MATERIALS_CACHE_VERSION = f"{_MATERIALS_REVISION}-{CACHED_TABLE_SIGNATURE}"
```

`TILE_SCORE_MATRIX_CACHE_VERSION`が既に材料世代との複合で機能しており
（統合レビュー第7回のKEEP）、同じ形を署名へ広げるだけ。

## 消えるもの

- 手書きの署名定数2つ
- 「上げ忘れを注意する」だけのテスト2本
- 「列を変えたら版を上げる」という手順（列を変えたら鍵が自動で変わる）
- CLAUDE.md「コミット時の同期ルール」の該当項の一部

あわせて、[T731](T731.md)（実行時にしか決まらない列は鍵ではなくキャッシュの中身へ
保存し読み出し時に突き合わせる）で、静的に署名できない次元も版の管理から外れる。

## 手動に留めるもの（理由つき）

`ROAD_SURFACE_TILE_VERSION`・`POI_TILE_VERSION`・`ACCIDENT_TILE_VERSION`は手動のままにする。
SQL文字列のハッシュから導くとコメント1行の変更で関東全域のタイル再生成が走り、
**過剰な無効化のコストが実害を上回る**（構造仕様12の例外条項）。

## 完了条件

- [ ] 列を1つ足すと鍵が自動で変わることを確認するテストが1本あること
      （「定数を更新せよ」ではなく「鍵が変わる」を固定する）
- [ ] CLAUDE.mdの同期ルールから、列変更時の版上げ手順が削られていること
