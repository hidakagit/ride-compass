# T609. 出発時刻ポップオーバーの透過バグ修正とドラッグタイムラインの直接日時指定UIへの置き換え

状態: 完了（2026-09-05）

## 背景

T601の「出発時刻ポップオーバーのクイック設定ボタンが地図に透けて見える不具合を修正」
（13b8e63）で`.quickButton`の背景を不透明化したはずが、ユーザーから「まだボタンが透けて
消える」「クリック後に透過している」と再度報告された。加えて、ドラッグ式タイムライン
（`DynamicLayerTimeSlider`、T255→T601で出発時刻ポップオーバーへ再利用）の使い勝手が
微妙なので、直接日時指定できるシンプルなUIへ変更してほしいと依頼された。

## 調査結果（透過バグの真因）

`.quickButton:hover { background: var(--color-surface-hover, rgba(0, 0, 0, 0.05)); }`
（RideConditionBar.module.css）が真因。`--color-surface-hover`はプロジェクト全体で
どこにも定義されておらず、常にフォールバックのrgba(0,0,0,0.05)（95%透明）が採用される。
T601の修正は`background`の**既定値**だけを不透明化しており、`:hover`側は直していなかった。
モバイルのタップは`:hover`を疑似的にトリガーしタップ後もその状態が残るため、
「クリック後に透過している」という報告と一致する。

`LensControl.module.css`にも同じ`var(--color-surface-hover, rgba(0, 0, 0, 0.05))`が
あるが、そちらは不透明な`.content`（ポップオーバー本体）の内側に置かれた行の
hoverのため、実害は無い（不透明な背景の上に薄い網掛けが乗るだけ）と確認し対応不要と
判断した。

## 対応方針・実装内容

- `RideConditionBar.module.css`: `.quickButton:hover`を`background`ではなく
  `border-color: var(--color-accent)`へ変更（`MapOverlayControls.module.css:
  .pageButton:hover`と同じ、地図に直接浮くコントロールの既存パターンに揃える）。
- `RideConditionBar.tsx`: 出発時刻ポップオーバーの中身を、ドラッグ式タイムライン
  （`DynamicLayerTimeSlider`）から`input[type=datetime-local]`による直接指定へ置き換えた。
  クイック設定ボタン（今/+1h/+2h/+3h）はそのまま残す。ポップオーバー自体のコンテナも
  `.timelinePopover`（背景を持たせない特殊仕様）から、想定速度ポップオーバーと共通の
  `.popover`（不透明な背景・枠・影を持つ）へ統一した——「コンテナは背景を持たず、
  中身の各要素が個別に不透明背景を持つ」という設計が今回の透過バグの温床だったため、
  そもそもその設計自体をやめた。
- 上記の置き換えにより`DynamicLayerTimeSlider`（コンポーネント・CSS・テスト）・
  `departureTimeline.ts`（同テスト）が完全に不要になったため削除した。
  `embla-carousel-react`/`embla-carousel-wheel-gestures`（`DynamicLayerTimeSlider`の
  唯一の利用元だった）もpackage.jsonから削除した。
- `docs/modules/frontend/page-composition.md`の対象ファイル表から
  `components/DynamicLayerTimeSlider`行を削除し、`RideConditionBar`の説明を新しいUIに
  合わせて更新した。
