# T862. 走行条件のポップオーバーがスマホ幅で画面外へ出る

状態: 完了（2026-09-15。ユーザー実機フィードバック「時刻スライダーがスマホで見ると画面左端まで
突き抜けていて不格好。巡航速度も他の部品と余白などが合っていなく感じる。両方とも省スペースを
意識してレイアウト改善して」から）

## 背景

出発時刻・想定速度のポップオーバーは、地図右上のアイコンから`side="left"`で開いていた。
右端のアイコンから左へ開くため、狭い画面では左に置き場が無い。加えて中身の時刻スライダーは
`width: min(90vw, 26rem)`という画面幅だけを見た幅を持ち、**その位置に実際どれだけ空きが
あるかを知らない**。390px幅で実測すると左端の外へ出ていた:

    ポップオーバーの矩形 x=-8 width=351（画面幅390）

想定速度側は見出し1行（「想定速度（km/h）」）＋スライダー行の2段で、隣の時刻スライダーとは
余白・角丸・影が別々の値だった。

## 対応

- 配置を`side="bottom" align="end"`へ。下には画面幅ぶんの置き場があり、トリガーの右端へ
  揃うので左へ伸びても画面内に収まる。
- 幅の上限をRadixが実測した空き（`--radix-popover-content-available-width`）から取る。
  時刻スライダーの`.panel`にも`max-width: min(26rem, 100%)`を与え、幅を制限した親の中では
  そちらへ従って縮むようにした（90vwは画面幅しか見ていない）。
- 想定速度は見出し行を畳んで1行（スライダー＋数値＋単位）にし、アクセシブル名は数値入力の
  `aria-label`が引き継ぐ。箱の余白・角丸・影は時刻スライダーの`.panel`へ揃えた。
- 出発時刻の直接指定（`input[type=datetime-local]`）は横いっぱいをやめ、中身ぶんの幅で
  ルーラーの右端へ揃えた（同じ時刻をルーラーの見出しと二重に見せる帯が画面幅ぶん居座って
  いた）。

## 検証

e2eフィクスチャ（backendモック）で実測。390px幅:

    修正前 出発時刻 x=-8   width=351  height=107.5
    修正後 出発時刻 x=29   width=351  height=104.3   右端380（画面内）
    修正後 想定速度 x=124  width=256  height=46.8    右端380（画面内）

1280px幅でも右端がトリガーへ揃い画面内に収まることを確認した。
