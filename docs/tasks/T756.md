# T756. 本番の地図初期表示が「地図を読み込み中」のまま長時間止まる

規模M。
状態: 完了（2026-09-12）

## 背景

本番で初期表示の「地図を読み込み中…」が30〜70秒続くセッションが5回中3回あった。ルート生成は先に完了して候補一覧だけ出る（backendは応答している）。他の2回は6〜15秒で表示された。初見ユーザーは白紙の画面で待たされ、壊れているのか待てばよいのか判断できない。

個票は[history/2026-09-12_ui.md](../../.claude/commands/review/history/2026-09-12_ui.md)のF-1。

## 調査項目

1. **どこで止まっているか**の切り分け。基礎地図スタイル（`/api/basemap`経由、Next.jsのrewritesでbackendへ転送）・スタイルが参照するタイル・フロントのMapLibre初期化のどれか。ブラウザのネットワーク記録で最初のスタイル取得の所要時間を測る
2. **backend側の要因**。同時刻にアメダス観測値の取得も失敗していた（T757）。backend起動直後に外部データ系だけが失敗する既知の事象や、Renderのコールドスタートと重なっていないか。`/health`の`started_at`と症状時刻を突き合わせる
3. **フロント側の表示**。一定時間を超えたら「再試行」と原因の見当を出す。dev環境で観測されたMapLibre初期化停止（[T578](T578.md)前後の記録）と同型かも確認する

## 完了条件

- 止まる箇所を1つに特定し、実測値（秒）とともに個票の「対応状況」欄へ書く
- 特定した箇所への対応、または一定時間超過時の再試行導線のどちらかを入れる

## 切り分け（調査項目1・2）

本番の基礎地図配信は健全だった。同日に各資材を直接測った値（curl、`total`）:

| 対象 | 所要 |
|---|---|
| スタイルJSON（frontend経由 `/api/basemap/styles/liberty`） | 0.88秒 |
| TileJSON（`/api/basemap/planet`） | 0.17秒 |
| スプライト（json / png） | 0.05秒 / 0.07秒 |
| グリフ（`fonts/.../0-255.pbf`） | 0.06秒 |
| ベクタタイル 東京 z12（キャッシュ命中） | 0.07〜0.16秒 |
| ベクタタイル 遠方 z14（キャッシュ未命中＝上流取得） | 0.79〜0.80秒 |

**止まっていたのは配信側ではなくフロントの覆いの外し方**。覆い（`initialTilesLoading`）は
MapLibreの最初の`idle`で外すが、`idle`は表示中のすべての取得が落ち着くまで来ない。
取得が終わらない・極端に遅いソースが1つでもあると、基礎地図が描けていても覆いが残る。
症状の「ルート生成は先に完了して候補一覧だけ出る」「地図だけ白紙」は、これで説明がつく
（アプリは動いており、不透明な覆いだけが残っていた）。

## 対応

`idle`が来なくても`INITIAL_TILES_OVERLAY_MAX_MS`（6秒）で覆いを外す。

## 検証

取得が終わらないソースを持つスタイルを返し、そのタイル要求に一切応答しない状態を作って測った
（Playwright、`e2e/smoke.spec.ts`へ常設）:

- 上限を入れる前: 覆いは15秒待っても外れない（テストが落ちる）
- 上限を入れた後: 6.8秒で外れる

## 残り

「一定時間を超えたら再試行導線を出す」（調査項目3）は入れていない。覆いが外れれば地図
そのものは操作でき、再試行は「地図の見え方」の再描画で既に行える。
