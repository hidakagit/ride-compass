# T834. CIのpostgisテストが2日間赤のままだった（実装変更にテストが追随していない2件）

規模S。
状態: 完了（2026-09-14）

## 背景

CI（`backend`ジョブ）が2件失敗し続けていた。どちらも`@postgis`マークのテストで、実装を
変えたコミットがテスト側を直していない。

| 失敗したテスト | 原因コミット | 実装側の変更 |
|---|---|---|
| `test_get_way_tags_by_osm_way_id_returns_highway_tags_and_is_designated` | `650e060a`（2026-09-12 23:26、T753） | 戻り値が`(highway, tags, is_designated)`→`(..., surface)`の4要素になった |
| `test_refresh_preserves_tile_score_matrix_disk_cache_when_revision_unchanged` | `c6693c15`（2026-09-12 03:53、T731） | 読み出し時に列構成を現在の述語と突き合わせる検証が入り、固定の列で組んだ行列は「列構成が古い」としてミス扱いになる |

**気づかれなかった理由**: このプロジェクトの反復実行は`pytest -q -m "not postgis"`が既定
（`docs/testing.md`・CLAUDE.md「テスト方針」）で、`@postgis`のテストはローカルの通常実行に
現れない。CIだけが実行するため、赤くなっても次にCIのログを開くまで分からない。

**赤のまま放置した場合に起きること**: 既に赤いCIには新しい赤が埋もれる。この2日間に入った
どの変更も「CIが通ったこと」を根拠にできていない。

## 実装

- `get_way_tags_by_osm_way_id`のテストは4要素で受け、`surface`が専用列から返ることまで
  検証する（`WaySpec(surface="asphalt")`を与える）。T753の変更点そのものが契約として
  テストに現れる形にした。
- スコア行列のテストは、可変長の列（生値・材料・categorical材料）を`route_facing_*`の
  述語から組む`_score_matrix_with_current_columns()`を通す。固定の列で組むと述語が増えた
  瞬間に同じ壊れ方をするため、同ファイルで固定の列を使っていた他の2テストも同じヘルパへ
  寄せた——うち1つは`get()`が`None`になることを確認するテストで、列構成が古いままだと
  **無効化されたからではなく列が古いからNone**になり、本来見たい契約を検証しないまま
  緑で通っていた。

検証:

- 直す前の書き方（固定の列）へ戻すとローカルでもCIと同じ`assert None is not None`で落ちる
  ことを確認してから直した
- `pytest -m postgis -q` → 285 passed（CIが実行する母集団をローカルで全件）
- `ruff check` クリーン

## 台帳にあった補足

- 2026-09-14完了。T753の戻り値4要素化とT731の列構成検証に、それぞれテストが追随していなかった。postgisマークはローカルの既定実行[-m "not postgis"]から外れCIでしか落ちないため、赤が2日間気づかれなかった
