# T566: ソースコード内の経緯コメント氾濫の恒久防止ルール化

状態: 完了（2026-09-03）

## 背景

`docs/modules/README.md`は2026-08-31、設計書（`docs/modules/*.md`）に対して「経緯（以前は…・
改善計画Txxxで…に変更した・実機/実測で…だったため）を書かない」というルールを明文化済みだが、
このルールはドキュメントのみを対象にしており、ソースコードのコメント自体には適用されて
いなかった。実際、`RouteSettingsPanel.tsx`等の実装ファイルには、既に`docs/modules/*.md`側に
同内容が現在形で記載済みの経緯コメントが多数残っており、二重管理（かつ経緯側は参照先Txxxが
リファクタで陳腐化しうる）になっていた。ユーザー指摘「全般的にソースコードに大量の過去経緯の
コメントが残っていて読みにくい」を受けて`改善計画T[0-9]+`等のマーカーで機械的に調査した結果、
backend/frontend合わせて2,844件・373ファイルに達することが判明した（他に「以前は」289件・
「実機フィードバック等」212件・「ユーザー要望/指摘/判断/報告」185件、重複ヒットあり）。
実際のクリーンアップ（[T567](T567.md)）に着手する前に、同じことが繰り返されないようルール化
してほしいという指示を受けた。

## 対応

1. **docs/comments.mdを新設**し、判定基準（3分類: 設計書と重複＝削除／非自明な現在の理由＝
   現在形で残す／日記的記述のみ＝削除）と実例を記載した。
2. **CLAUDE.mdへ「コメント方針（必読）」節を追加**し、docs/comments.mdへのポインタとした。
3. **CLAUDE.md「毎タスク完了時の即時チェック」へ項目5を追加**し、新規に書く/変更する
   コメントへ即座に方針を適用する（既存分の一掃を待たない）。
4. **`.claude/commands/review/consistency.md`「設計 ↔ 実装」節へ周期レビュー側の二重チェックを
   追加**（本レビュー対象のdiffの追加行のみを対象にする。全ソース373ファイル超の毎回走査は
   高コストなため）。

## 追記（同日、ユーザー指摘「claude.mdにも過去の経緯がのこっている。今有効なルールいがい
はクリーンアップできない？」）

上記の作業中に追加したCLAUDE.mdの記述自体も含め、CLAUDE.md全体を棚卸しし、各ルールに
付随する「いつ・どのTxxxで何が起きたか」という経緯の記述を、（1）既にdocs/tasks/Txxx.mdに
同内容がある場合は削除しリンクへ置き換え、（2）そのTxxxファイル自体が存在しない古い番号
（T130・T135、2026-08-27のタスク単位ファイル分割以前のためdocs/improvement-plan-archive/
側にのみ存在）は具体的な番号を出さず一般化した記述へ、という方針で整理した。単なる件数・
日付の記述で今後も陳腐化し続けるもの（「T180・T185・T218の3回のドリフト実績」等）も同様に
圧縮した。ルール本体（「〜すること」という指示文）は一切削除・弱化していない。あわせて
CLAUDE.md「ドキュメント階層」節の表へ「ルール自体の経緯はCLAUDE.mdに書かずdocs/tasks/Txxx.md
へ任せる」という規定を追加し、今後の再発を防ぐ恒久ルールにした。

この整理に伴い、`docs/workflow.md`が参照していた「毎タスク完了時の即時チェック2件」という
記述が実際は5件（本タスクの項目5追加以前から4件だった）と食い違っていたことも発覚し、
同一コミットで是正した。
