# T566: ソースコード内の経緯コメント氾濫の恒久防止ルール化

状態: 着手中（2026-09-03起票、ユーザー指摘「全般的にソースコードに大量の過去経緯のコメントが
のこっていて読みにくい」を受けた調査の結果、backend/frontend合わせて`改善計画T[0-9]+`だけで
2,844件・373ファイルに達することが判明。実際のクリーンアップに着手する前に、同じことが
繰り返されないようルール化してほしいという指示）

## 背景

`docs/modules/README.md`は2026-08-31、設計書（`docs/modules/*.md`）に対して「経緯（以前は…・
改善計画Txxxで…に変更した・実機/実測で…だったため）を書かない」というルールを明文化済みだが、
このルールはドキュメントのみを対象にしており、ソースコードのコメント自体には適用されて
いなかった。実際、`RouteSettingsPanel.tsx`等の実装ファイルには、既に`docs/modules/*.md`側に
同内容が現在形で記載済みの経緯コメントが多数残っており、二重管理（かつ経緯側は参照先Txxxが
リファクタで陳腐化しうる）になっていた。
