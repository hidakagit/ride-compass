# T419. ルート設定・ルート結果パネルのレイアウト見直し（地図を圧迫する「遊び」を削る）

状態: 未着手（起票のみ）

## 目的（先に固定する）

[T418](T418.md)（評価軸チップをルート設定/結果パネルへ統合）が実現すると、パネルを開き
ながら地図を確認したい場面が今より増える（「この条件で見るとどこが厳しいか」を重み設定と
地図の両方を見ながら判断するため）。モバイルはBottomSheet（画面下部から最大70%程度せり
上がる部分高さシート）で地図の上側は見えたまま操作できる設計だが、**シート自体のレイアウトに
「遊び」（不要に大きい余白・重複表示）が多く、地図を確認できる残り面積を圧迫している**。
評価軸統合で地図確認の重要性が増す前に、既存の遊びを削っておく。

## 指摘済みの具体項目（実機フィードバック、2026-08-30）

- **下部シートを開くつまみ（BottomSheet.tsx: `.handle`）が大きすぎる**: `padding: 0.9rem 0`
  で44px角のタップ領域を意図した設計だが、地図を圧迫する見た目になっている。タップ領域の
  確保とサイズ削減のバランスを取り直す必要がある。
- **「ルート設定」の見出しが二重に表示される**: モバイルのBottomSheet自体のtitle（"ルート設定"）
  と、`renderRouteSettingsSectionBody()`内の`<h2>ルート設定</h2>`（デスクトップの「ルートを
  作る」details内で必要な見出し）が、モバイルでは同じ文言で重複する。デスクトップ・モバイル
  両方から呼ばれる共通関数のため、呼び出し元でこの見出しの要否を切り替える必要がある。
- **「除外する道路」（RouteSettingsPanel.tsx、3件固定チップ）がスペースを取りすぎる**:
  既定でON（除外）の3項目が常に展開された状態で表示されている。使用頻度が低い・既定値のまま
  変えない利用者が大半と見込まれるなら、折りたたみ式にする・より小さい表示にする等の見直しが
  必要。

## 対応方針（未確定、着手時に実機で洗い出すこと）

- 上記3件に加えて、**実際にBrowserペインでモバイル・デスクトップ両方の表示を確認しながら、
  他にも「遊び」がないか洗い出す**（CLAUDE.mdの方針どおり、コードを読むだけでなく実機確認を
  行うこと）。
- パネル内の余白トークン（`--space-*`）の使い方、Disclosure（各レイヤーセクション）の
  開閉時の余白、BottomSheetの`.header`/`.body`のpadding等を総点検する。
- [T418](T418.md)実装で追加される「軸選択→地図色分け連動」UIのスペースを見込んで、
  既存要素の省スペース化を優先する。
