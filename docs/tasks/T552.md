# T552: 重み付き軸がすべてデータ欠損のEdgeのコストを「最良扱い」から「bbox平均difficultyで補完」へ変える

状態: 未着手（2026-09-03起票、[T531](T531.md)推敲時のユーザー質問「候補がデータ欠損Edgeへ
偏っている場合、自然なルートに近づける拡張はできるか」を受けて起票。T531とは独立に着手可能
だがコスト式の意味論に触るため別番号で切り出した）

## 背景

コスト式`cost = distance × (1 + P × composite/100)`は、composite difficultyがNaN
（リクエストで重みを振った軸すべてで材料が欠損）のEdgeを`penalty_multiplier = 1.0`、
つまりdifficulty 0相当の「最良の道」として扱う（`domain/evaluation.py:
compose_costs_from_axis_matrix`のNaN分岐、スカラー版`compute_cost_from_axis_scores`も同じ）。
一部の軸だけ欠損なら残りの軸で再正規化される（「データ無しは除外」方針）が、全軸欠損の
補完値は未定義のままこの挙動になっている。自転車インフラ100%のような単一軸の重み設定では、
タグ未取得の道路がサイクリングロードと同じコストになり、T531のフロンティア方式では
そうした道を優先的に折返し候補へ拾う方向に働く。

## 対応方針

1. **実態把握を先に行う**: `_build_search_graph`のINFOサマリへ「重み付き軸がすべてNaNの
   Edge比率（件数・距離加重）」を追加し、本番同等bbox（東京駅30km等）で計測する。比率が
   1%未満なら2のみ、それ以上なら4（取込側）も検討する。
2. **補完**: 全重み付き軸がNaNのEdgeのcompositeを、同じリクエストのbbox内でデータのある
   Edgeの**距離加重平均difficulty**で補完する（`compose_costs_from_axis_matrix`へ
   ベクトル演算を1段追加。固定定数[50等]ではなくリクエスト内の実データ由来にし、軸名に
   依存しない汎用処理にする）。スカラー版`compute_cost_from_axis_scores`はbbox平均を
   引数で受け取る形に揃え、`tests/test_evaluation_bulk.py`のビット単位一致オラクルを維持する。
3. **表示は変えない**: 区間表示（`_build_segment_details`）のdifficulty・axis_difficultiesは
   「データ無し＝None」のまま。探索コストのみ補完し、その旨を`docs/design-principles.md`へ
   「全軸欠損Edgeの探索コストは補完値、表示は欠損のまま」として明記する（T536で揃えた
   探索と表示の一致に、意図的な例外を1つ作ることになるため必ず文書化する）。
4. **取込側の補完（比率次第）**: highway種別から材料の既定値を埋めて欠損自体を減らす案。
   取込バッチと本番再取込が要るため、1の計測結果を見てから別タスクとして判断する。

## 完了条件

- 合成データで「全軸欠損Edgeのcostが、データありEdgeの距離加重平均difficultyに対応する
  コストと一致する」「一部欠損は従来どおり再正規化」「全Edge欠損ならcost=distance」の
  テストがpass、`tests/test_evaluation_bulk.py`のオラクル一致が維持される。
- 本番同等bboxでの欠損比率をT552.mdへ記録し、`pytest -q -m "not postgis"`green。
- `docs/design-principles.md`・`docs/modules/backend/evaluation-*.md`（該当設計書）を
  同一コミットで更新。
