# T689. 合成軸も軸単体で判断できるようにする 規模M

状態: 未着手（2026-09-09起票、[T687](T687.md)より分離）

## 背景

[T687](T687.md)で、得点の隣に生値（折れ点を通す前の物理量）を出せるようにした。ただし
出せるのは`terms`の材料の単位が揃い、かつ重みがすべて正の軸に限られる。

| 軸 | 生値 | 出せない理由 |
|---|---|---|
| 停止密度・事故密度・勾配 | 出る | — |
| 車の圧迫感 | 出ない | 内部軸5本の合成で、単位そのものが無い |
| 夜間・自転車インフラ・路面 | 出ない | 真偽値/カテゴリ材料で単位が無い |
| 開放度 | 出ない | %は足し合わせて意味を持つ量ではない（`樹木% + 建物%`は母数の違う割合の和）。重みも負で生値が常に負になる |

[設計原則](../design-principles.md)11「軸は単体で評価できる」を、これらの軸はまだ
満たしていない。得点だけを見せている状態のため、T687の元になった「10点と出るが実際は
ストレスの多い経路」と同じ誤読が起きうる。

## 保留することでブロックされること

これらの軸については、利用者は引き続き得点0〜100だけで判断することになる。得点は
目盛りの引き方に依存する相対評価であり、較正を変えるたびに同じ経路の数字が動く。
軸の較正を見直すたびに「利用者から見て何がどう変わったか」を説明できない状態が続く。

## 対応方針（2026-09-10 確定）

起票時の3案（内部軸の生値／真偽値軸の割合／開放度の被覆率合計）は、どれも**軸の種類ごとに
別の機構を作る**形だった。代わりに**どの軸も材料単位まで分解して絶対量を並べる**1つの機構に
統一する。軸定義の`terms`から機械的に導けるため、軸を1本足しても表示側のコード変更が要らない
（[設計原則](../design-principles.md)構造仕様2「評価軸追加の1本道」と同じ形）。

### 規則

1. **参照材料が1件に分解される軸は分解しない**。現行の軸単位の生値をそのまま出す
   （表示は今のまま。理由は下記「preprocessが効かなくなる」）。
2. 2件以上へ分解される軸は**材料まで再帰的に辿る**。`referenced_materials`が返すidは
   材料と軸が同じ名前空間に混じっており、`MATERIAL_CATALOG`にあれば葉、
   `AXIS_DEFINITIONS`にあれば軸参照として さらに辿る。循環は`topological_axis_order`が
   `AxisDependencyCycleError`で排除済みのため再帰は必ず有限で終わる。
3. **軸の得点は内訳に出さない。** 得点（0〜100）は較正依存で、出すと本タスクが解こうと
   している問題が入れ子でそのまま再発する（「車の圧迫感の内訳＝highway基準値62点」では
   何も分からない）。辿る先は必ず材料。
4. **表記は材料の型から決まる**（軸ごとの対応表を持たない）:
   numeric＝距離加重平均＋単位／boolean＝該当区間の延長割合／categorical＝値ごとの延長割合。
5. **並び順は正規化重みの降順、同率は探索の浅い順、なお同率なら定義順**。
   生の重みを階層をまたいで掛けても意味が無い（内部軸の`breakpoints`・`mapping`は
   非線形変換で、外の1.0と中の1.0は別のスケール）。一方、**同じshapeの中のterms
   どうしは必ず比較可能**——重み付き和が得点として意味を持つよう作者が重みを決めている
   ことが前提だから。したがって階層ごとに正規化してから掛ければ葉まで一貫する:
   `share(葉) = Π（各階層で |w_i| / Σ|w_j|）`。これは軸定義だけから決まり、
   ルートのデータも追加の行列列も要らない。
6. **重み0の材料は出さない**（得点に一切影響しないものを事実として出すと誤読を招く）。
7. **動的材料（風）を参照する軸は対象外**。静的スコア行列は`weather=None`で組むため
   生値がNaNになる。現行`has_route_facing_raw_value`の除外を分解後も維持する。
8. 既定表示は先頭2件、残りは軸の説明ポップオーバー（既存の`InfoPopover`）へ。
   軸1本あたり最大5件になり、常に全件並べると[設計原則](../design-principles.md)
   「走行中に見るかを基準に情報量を絞る」と衝突するため。

### 規則1（1材料の軸は分解しない）の理由

勾配軸は`shape.preprocess="abs"`を持ち、生値は`_breakpoint_raw_total_array`が
**|重み付き和|を取ってから**距離加重平均される。材料単位へ降りると`preprocess`が効かず、
登りと下りが相殺されて平均がほぼ0になる（周回ルートでは標高差が戻るためほぼ確実）。
現行より悪化するため、1材料の軸は分解せず軸単位の生値を使う。あわせて材料ラベルも
出さない——「勾配」の行に材料名「勾配%（符号付き）」が並ぶのは冗長で、しかも
「符号付き」はabs適用後の表示値と食い違う。

### 適用結果（実データ、確定前に全公開軸で確認済み）

| 軸 | 今 | 確定した規則の適用後 |
|---|---|---|
| 勾配・事故密度・蛇行 | 生値が出る | **変わらない**（いずれも1材料100%） |
| 風 | 出ない | 出ない（規則7） |
| 舗装質 | 出ない | 舗装良否 ◯% |
| 車の圧迫感 | 出ない | 道路種別 値ごとに◯%／制限速度 平均◯km/h ＋popover 3件（5件とも20%同率、定義順） |
| 夜間 | 出ない | 街灯あり ◯%／トンネル ◯%（50%ずつ） |
| 自転車インフラ | 出ない | 道路種別が自転車道 ◯%／自転車道(track)を併設 ◯% ＋popover 3件 |
| 開放度 | 出ない | 樹木被覆率 平均◯%／建物被覆率 平均◯%（50%ずつ） |
| 停止密度 | 出ない | 踏切 平均◯回/km［54%］／信号 平均◯回/km［36%］＋popover 1件 |

停止密度は現在[T709](T709.md)の「重みがすべてちょうど1」条件で生値が出ていないが、
分解すれば材料ごとには出せる。重み付き和が意味を持たないことと、材料それぞれが
意味を持つことは別のため、この枠のほうが正直。
