# T650. コピペ検出で挙がった重複を個別に潰す

規模S〜M。起票のみ・実装未着手。

## 背景

[T648](T648.md)でコピペ検出（jscpd）をレビュー基盤へ組み込んだ結果、**24件・838行・1.93%**
の完全一致クローンが判明した。検出の仕組みは入ったが、**既に存在する重複はそのまま**である
（T648の目的は「新しい写経が増えたときに気づけること」であり、既存件数をゼロにすることでは
なかった）。

## 対象（2026-09-07時点の検出結果から、直す価値のあるもの）

| 行数 | 箇所 | 見立て |
|---|---|---|
| 36 | `DerivedDataFreshnessPanel.module.css` ↔ `BackendLogsPanel.module.css` | 管理画面パネルの外枠スタイル。共通クラスへ抽出できる見込み |
| 23 | `MaterialCoveragePanel.module.css` ↔ `BackendLogsPanel.module.css` | 同上 |
| 18 | `page.module.css` ↔ `MapOverlayControls.module.css` | 同上とは別系統。要確認 |
| 14 | `precompute_edge_attribute_counts.py` ↔ `precompute_way_attribute_counts.py` | バッチの集計処理 |
| 11×3 | `batch/precompute_*.py`同士 | `async def run(database_url, dry_run)`の骨格。4本のバッチが同じ並びを持つ |

除外して構わないもの:

- 586行の`Map/icons.tsx`同士 … 同一ファイル内のSVGアイコン定義。1アイコン1定義であり、
  共通化すると却って読みにくい。
- 14行の`dynamic_way_value_cache.py` ↔ `jma_tile_redis_cache.py` … Redis cache-asideの
  骨格で、[T644](T644.md)が既に扱う。
- 17行の`road_graph_tile_cache.py`同一ファイル内 … 同上の系統。

## 対応方針（案）

CSS 3件とバッチ`run()`骨格は性質が違うため、着手するなら分けて進める。

- **管理画面CSS**: 共通のパネル外枠クラスを1箇所へ置く。ただし`components/ui/`へ置くか
  各パネルのCSS Modulesのまま共有するかは、[frontend/page-composition.md](../modules/frontend/page-composition.md)の
  「汎用UI部品はここへ集約する」方針と突き合わせて決める。
- **バッチ`run()`骨格**: `precompute_*.py`4本が同じ引数・同じ手順（DB接続→dry_run分岐→
  集計→書き戻し→件数返却）を持つ。共通の骨格関数へ寄せられるか、バッチごとの差異が
  大きいかを確認してから判断する。

## 保留した場合の影響

機能上の実害は無い（いずれも動作しているコード）。ただし`review_checks.py duplication`の
前回値が24件のまま据え置かれるため、**「増えたら気づく」という監視の基準線が高いところに
固定される**。基準線を下げておくほど、新しい写経が相対的に目立ちやすくなる。
