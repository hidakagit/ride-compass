## 実施内容（2026-09-09）

5件すべて実施した。11-6（lint導入）を先に済ませ、残り4件はそれが検出したものと
手作業のものを合わせて直している。

### 11-6: ruffの導入

| 追加物 | 内容 |
|---|---|
| `backend/ruff.toml` | 設定。`pytest.ini`と同じ「pyproject.tomlを持たずツールごとの個別ファイル」の流儀に合わせた |
| `backend/requirements-dev.txt` | 開発・CI専用の依存（`ruff==0.16.6`）。本番webイメージには入れない（`requirements-batch.txt`がバッチ専用依存を分けているのと同じ理由） |
| `.github/workflows/ci.yml` | backendジョブへ`ruff check`を追加。pytestより前（frontendがeslint→tsc→vitestの順であるのと同じ、速いものから） |
| `scripts/pre-commit-ruff.sh` | **ステージ済みの`backend/**.py`だけ**を対象にする。既存違反で無関係なコミットを止めない（`review_checks.py docs --staged`と同じ考え方）。`.venv`・ruffが無い環境ではsoft-fail（`pre-commit-api-contract.sh`と同じ、worktreeを壊さないため） |

**選択ルールはruffの既定（E4/E7/E9/F）に絞った。** 広げなかったのは、実測した違反数が
直す価値に見合わないため（数値と根拠は`ruff.toml`のコメントに残した）:

| ルール | 実測違反 | 広げなかった理由 |
|---|---|---|
| E501（行長） | 4,488件 | 日本語コメントの折り返し位置の問題で、コードの欠陥ではない |
| ARG（未使用引数） | 300件 | Protocol実装・FastAPIの依存性注入で意図的に受け取る引数が大半 |
| I（import順） | 109ファイル | 全ファイルへ差分が出るのに対し、得られるのは並び順の統一だけ（他セッションと広く競合する） |
| B/SIM/C4等 | 69/16/35件 | 実バグに近いので有望だが、既存違反を1件ずつ判断する必要がある。個別に足すのは別タスク |

`tests/conftest.py`のE402（10件）だけは`per-file-ignores`で除外した——rasterioより先に
`pin_bundled_proj_data()`を呼ぶ必要があり、import順を動かせないため。

### 8-4・8-8・8-11・8-12

| # | 対応 |
|---|---|
| 8-4 | `EvaluationService.__init__`ごと撤去（`self._preference`は一度も読まれず、`evaluate_graph`が引数で受け取る設計だった）。呼び出し元はテスト9箇所・ベンチマーク1箇所のみ |
| 8-8 | batch配下5ファイル7シンボル（`async_sessionmaker`/`create_async_engine`/`settings`）。レビュー時点の「6ファイル13シンボル」より少ないのは、[T682](T682.md)で`precompute_edge_attribute_counts.py`を整理した分が既に減っているため。テスト・benchmarks側にも同種が16件あり、ruffの`--fix`でまとめて解消した |
| 8-11 | `road_graph_engine.py`の`is_known_material`を関数内importからモジュール冒頭へ移した（`material_catalog`はdomain層のみに依存し、servicesからの循環は起きない——importして確認済み） |
| 8-12 | `match_designations.py`の`data_version_local = data_version`（無意味な再束縛）を撤去 |

**副産物**: `test_routes_generate.py`の2箇所に`# noqa: <日本語の説明>`という無効な
noqa記法があり、ruffが「Invalid noqa directive」を警告していた。noqaとして機能して
いないので通常のコメントへ直した。

## 他タスクとの関係

`backend/app/domain/evaluation.py`の未使用import 1行（`evaluate_axis_scalar`）を削除して
いる。同ファイルは[T673](T673.md)の主対象のため、マージ時にコンフリクトする可能性がある
（import行1行なので解消は自明）。ruffをCIへ入れた以上、この1行を残すとT673のマージ時に
CIが落ちるため、今回まとめて解消した。
