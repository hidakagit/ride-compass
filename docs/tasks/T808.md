# T808. ルート結果から続く編集導線（元を固定し、区間ごとに全候補の代替から選ぶ）

規模L。
状態: 着手中（段階1・2を実装済み、残りは段階3。2026-09-13、ユーザー要望「ルート結果パネルからつながる導線がいい。今は独立して
いてやりにくい」。モックで合意）

## 背景

[T769](T769.md)で「見る（ルート結果）」と「作る（ルート編集）」を別のタブへ分けたが、編集は
結果から切り離された独立パネルになり、次の3つが操作しにくさの原因になっている。

- 入口が結果と繋がっていない。どのルートを編集しているのかを、編集側で選び直す形になる。
- 先に「比較相手」を1本選ばせる。選ぶまで何が起きるか分からず、選び直すと区間の選択も消える。
- 地図の帯は表示専用で、パネルの「1本目の区間」がどの帯かを目で追うしかない。

## 決定（モックを見ながら合意）

1. 編集は**ルート結果パネルの中のモード**にする。結果で候補を選び「このルートを編集」で入る。
   「ルート編集」タブは無くし、下部タブは「ルート設定／ルート結果」の2つへ。
2. **編集の元は1本に固定**。相手を選び直しても元は変わらない。
3. **相手を1本選ぶ形はやめる**。元ルートの区間ごとに、**全候補の中からその区間の代替**を出し、
   区間ごとに「元のまま／どれかの代替」を選ぶ。
4. **合成したルートもさらに編集できる**（元を辿れるようにする話は[T779](T779.md)が持つ）。
5. 地図のオレンジの帯をタップして採否を切り替える。パネルは選んだ区間と、できるルートの差
   （距離・難易度）だけを示す。

## 段階

- **段階1（導線）**: 結果パネルへ編集モードを持たせ、「ルート編集」タブを廃止する。元は
  選んでいた候補で固定。相手の選び方は当面いまのまま（1本を選ぶ）。作ったら結果モードへ戻り、
  作ったルートが選択された状態で並ぶ。
- **段階2（代替の集約）**: 区間ごとに全候補の代替を集める。`lib/routeSplice.ts`へ、元と各候補の
  差分から「区間グループ（重なる範囲は同じグループ）」と「その区間の代替案（候補id＋差し替え後の
  Edge列）」を求める純関数を足す。区間グループごとに1つだけ選べる。地図の帯のタップもここで。
- **段階3（採用ルート）**: 合成ルートを元にした再編集と、元との差の見せ方。[T779](T779.md)と
  合流させる。

## 実装の見通し（段階2）

`differingStretches`/`targetStretchEdgeIds`は既に「元の区間→相手側のEdge列」を出せる。候補ごとに
これを求め、**元側の範囲が重なるものを1グループ**へまとめれば、グループ内は排他・グループ間は
独立になる（重ならないため後ろから順に差し替えれば経路が壊れない）。backendへ渡すのは従来どおり
`spliced_edge_ids`（完成したEdge列）で、API契約は変わらない。

## 段階1の実装メモ（2026-09-13完了）

- `editingRouteId`（nullなら通常の一覧、非nullならその場が編集面）を`page.tsx`が持つ。編集の
  元は押した候補で固定し、候補を選び直しても変わらない。
- 入口は候補の中身の「このルートを編集」。乗り換えできない生成（周回・候補1件）では**入口
  自体を出さない**——押しても何もできない入口を残さない。
- 「ルート編集」区分（デスクトップのDisclosure・モバイルのタブとシート・開閉の保存キー）を
  撤去。モバイルの下部タブは「ルート設定／ルート結果」の2つになった。
- 作ったら`editingRouteId`をnullへ戻す。同じ場所が一覧へ戻り、作ったルートが選択された状態で
  並ぶ（[T807](T807.md)でシートを切り替えていた応急処置は不要になり、撤去した）。

## 段階2の実装メモ（2026-09-13完了）

- `lib/routeSplice.ts`へ`stretchAlternativeGroups`（元ルートの区間ごとに、全候補の代替を
  集めてグループ化）と`spliceEdgeIdsFromAlternatives`（選んだ代替を後ろから差し替え）を追加。
  同じ区間を同じ道へ差し替える代替は候補が違っても1つにまとめ、元側の範囲が重なる代替は同じ
  グループへ入れる（グループ内は排他・グループ間は独立）。
- パネルは「比較相手のプルダウン」を廃止し、区間ごとに「元のまま／候補横断の代替」を並べる
  形へ。候補の名前は一覧のタブと同じ「順位 距離」。
- 地図の帯はタップで選べるようにした（`MapView`の`onSpliceStretchSelect`）。帯のfeatureの
  `index`へ「グループの位置と選択肢の位置」を1つの数として埋め、タップからどの区間のどの道か
  を引き戻す。汎用クリックのガードへも帯を足し、ポップアップと二重に反応させない。

## 段階2の追補（2026-09-13、実機フィードバック）

「1本目の区間／2 16.0km／3 15.5km」では、**どこが・どう変わるのかが読めない**（候補に名前が
無いため、番号と全長を見せられても区別がつかない）。示す内容を変えた。

- 区間は**元ルートの何km地点か**（「3.2〜5.0km地点」）。
- 選べる道は**その区間が何km長く（短く）なるか**（「+0.4km」「−0.2km」「距離ほぼ同じ」）。
  どの候補から来た道かは補助（同じ差の道が複数あるときの見分け）として`title`・`aria-label`へ。
- 距離は座標列から求める（`lib/geoDistance.ts`を新設し、`page.tsx`にあったhaversineも寄せた）。
  座標の対応が取れない候補では候補の名前へ落とす。
- 「このルートを編集」は全幅の大きなボタンをやめ、他と同じ小さな枠のボタンにした。

検証: `npx vitest run` 139ファイル1299件 passed（`geoDistance.test.ts`5件を新規）。

## 差分の見せ方（2026-09-13、実装済み）

「選んだ瞬間に評価差分を出す」は**採らなかった**。合成の評価は探索こそやり直さないが
`prepare()`（道路グラフの構築）は必ず通る（評価が`prepare`の産物のコスト配列を読む設計。
design-principles.md 構造仕様10）。本番実測（[T621](T621.md)・[T532](T532.md)）で
`prepare_ms`は**温630〜1,272ms／冷22.5〜59.3秒**。加えて生成APIは**1分10回**の上限
（`generate_rate_limit_per_minute`）があり、選ぶたびに投げると選び直し10回で弾かれる。

採ったのは**「差分を見る」ボタン**（ユーザー判断）。まとめて選んでから1回だけ投げる。

- 同じ組み合わせの結果は覚えていて投げ直さない（`splicePreviews`、キーは選んだ代替の並び）。
- 「新しいルートを作る」も同じ評価を使う——差分を見た後に作るなら**追加のリクエストは飛ばない**。
- 差は「距離 +0.4km ・ 難易度 −3」の形。0は符号付きで出さず「変わらない」と書く。
