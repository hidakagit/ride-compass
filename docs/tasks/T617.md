# T617: 「ルート結果」の実機調整（ルートをクリアのアイコン化・区間クリックのクラッシュ修正・AxisContributionBarの未使用軸表示バグ修正）

状態: 完了（2026-09-06）

## 背景

ユーザーから「ルート結果」まわりで3点の指摘があった。

1. 「ルートをクリア」の文言リンクをアイコン化してほしい（保存・GPX出力と見た目を揃える）。
2. 区間（ルート線のセグメント）をクリックするとアプリが落ちる。
3. 軸別内訳の`AxisContributionBar`（積み上げ棒グラフ）について、未使用軸のスコアを
   含めて何のために必要か理由を確認してほしい。

3については当初「棒グラフ自体（有効軸の積み上げバー）を消す」という依頼と誤解したが、
実際は逆で「有効軸の積み上げバーは必要、未使用軸を含めてしまっている表示不具合を直して
ほしい」という指摘だった（下記「調査結果」参照）。

## 対応内容

### 1. 「ルートをクリア」のアイコン化

`ClearAllLayersIcon`（保存・GPX出力と同じ`outcomeHeaderIcon`スタイル）へ置き換え。
未使用になった`.outcomeTabAction`CSSクラスも削除した。

### 2. 区間クリックのクラッシュ修正

**原因**: `MapView.tsx: handleRouteSegmentClick`が、地図から返るfeature propertiesのうち
`material_values`のJSON文字列パースを忘れていた（`axis_difficulties`・
`axis_contributions`はパースしていたが`material_values`が漏れていた。コメント
「唯一のオブジェクト型フィールド」はT592で`material_values`が追加された時点で
陳腐化していた）。MapLibreはGeoJSONソースのタイル化時にプリミティブ以外の値を
JSON文字列化するため、`queryRenderedFeatures`で読み戻した`material_values`は
生オブジェクトではなく文字列になる。`page.tsx`側の
`Object.keys(selectedRouteSegment.segment.material_values).length > 0`が文字列に
対しても真になり（文字列のインデックスがキーとして返るため）、`Object.entries()`が
文字を1文字ずつ返し、`formatMaterialValue`が1文字の文字列へ`.toFixed()`を呼んで
`TypeError`になりReact Error Boundaryが全画面フォールバックへ切り替わる。
**研究モード（researchEnabled）ON時のみ**発生していた。

**修正**: `MapView.tsx`に`ROUTE_SEGMENT_OBJECT_PROPERTY_KEYS`（オブジェクト型フィールドの
一覧、新規フィールド追加時はここへの追加が必須）と、それを使う`restoreRouteSegmentProperties`
（純関数、export済み）を新設し、フィールド名の手書き列挙をやめた。
`handleRouteSegmentClick`はこの関数を呼ぶだけにした。

**テスト**: `MapView.segments.test.ts`に`restoreRouteSegmentProperties`の単体テストを
追加（JSON文字列化されたpropertiesを入力にする、実際に発生していたクラッシュ
シナリオ[material_valuesのパース漏れでObject.entries()が1文字ずつ返す]の再現を含む）。
既存の`page.test.tsx: exposeSegmentSelect`スタブは`onRouteSegmentSelect`を生オブジェクトで
直接呼ぶためMapLibreの直列化層を素通りしており、このバグを検知できていなかった。

### 3. AxisContributionBarの未使用軸表示バグ修正

**調査結果**: backendの`axis_contributions`（ルート全体・区間の両方）は、公開軸すべてに
キーを返す。未使用（重み0）の軸は**キーが省略されるのではなく、値が常に0.0になる**
（`domain/evaluation.py: compose_costs_from_axis_matrix`。キーが省略されるのは
その軸のデータが本当に欠損している場合のみ）。`AxisContributionBar.tsx`は
`contributions[axis.axisId] != null`でしか絞り込んでおらず、値0の未使用軸を除外できて
いなかった。そのためルート全体・区間クリック詳細どちらの棒グラフ・凡例にも、未使用軸が
「軸名: 0.0」という常に無意味な行として残り続けていた（ユーザー指摘「全軸の棒グラフは、
未使用軸は常にゼロ固定で情報量を増やしていない」が的中）。

**修正**: `AxisContributionBar.tsx`のフィルタを`contributions[axis.axisId] != null`から
「値が0でない」条件へ変更（負の値はクランプ前の実データのため除外しない）。
`RouteAxisProfile.tsx`側の同種フィルタ（`contributionRows`、内訳セクションの空状態判定に
使う）も同じ条件へ揃えた。両ファイルの古いprop説明コメント（「重み0の軸は寄与を持たない」
という誤った記述）も現状に合わせて修正した。

**テスト**: `AxisContributionBar.test.tsx`・`RouteAxisProfile.test.tsx`へ、値0の軸が
除外されること・負の値は除外されないことを検証するテストを追加した。
