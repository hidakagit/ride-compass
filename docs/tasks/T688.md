# T688. way_landcoverの増分実行が「未計算」と「計算済み・値なし」を区別できるようにする

規模M。

状態: 完了（2026-09-09起票、[T682](T682.md)より分離。2026-09-10完了）

## 背景

`precompute_way_landcover.py`の増分実行（`--recompute`無し）は、`way_landcover`に行が
無いwayを対象にする。ラスタ範囲外・境界またぎ・有効画素不足のwayは行を作らないため、
これらは実行のたびに毎回ラスタ読み込みからやり直される（結果は毎回同じ「値なし」）。

## 保留による影響

無駄な再処理が増えるだけで、書き込まれる値は正しい（欠損は欠損のまま）。関東（`54S`
1枚）では該当wayが少なく実害は小さいが、全国展開（[T127](T127.md)）でラスタが複数枚に
なると境界またぎのwayが増え、再実行のたびに効いてくる。

## 対応方針（案）

`way_landcover`の割合8列をNULL可にし、`valid_pixels=0`＋割合NULLの行で「計算済み・
値なし」を表す（migrationが要る）。消費者側（`road_graph_repository`の読み出し・
`domain/evaluation.py`の材料解決）がNULLを欠損として扱えることの確認が前提。

T682で同時に行わなかったのは、消費者側の変更が`domain/evaluation.py`・
`domain/attributes.py`に及び、同ファイルを対象とする[T673](T673.md)と競合するため。

## 対応

対応方針（案）どおり割合8列をNULL可にし、NULLを「計算済み・値なし」の意味にした
（migration 0037。[0034](../../backend/migrations/0034_poi_counts_null_means_not_aggregated.sql)で
`poi_counts`へ同じ意味づけを与えたのと同じ流儀）。`valid_pixels`も同時にNULL可にした——
範囲外・境界またぎのwayは画素を数えてすらいないため、0を書くと「数えて0だった」と
区別できなくなる。

### 案に無かった点: 「値なし」はラスタ構成に対する結論でしかない

案のままだと**ラスタを追加しても取りこぼす**。境界またぎ・範囲外のwayは1枚足せば値を
持ちうるのに、値なしの行があると増分実行が二度と対象にしない。本タスクが挙げる
全国展開（[T127](T127.md)）は「ラスタが複数枚になる」ことが前提のため、この穴は
本タスクの動機と正面から衝突する。

そこで`source_raster_set`列を足し、`raster_set_fingerprint`（ラスタのファイル名の集合から
作る指紋、順序に依存しない）を値なし行へ残す。増分実行が除外するのは
「値を持つ行があるway」と「今回と同じ指紋・同じ`algorithm_version`で値なしと確定済みのway」
だけで、指紋かアルゴリズム版が変われば対象へ戻る。

既存の`data_version`をこの判定に使えないのは、先頭ラスタのファイル名から年を推定する値で、
別タイルのラスタを足しても変わらないため（ラスタ構成の変化を表さない）。

### 消費者側

読み出しは`LEFT JOIN way_landcover lc` + 列参照の形しかないため、NULL列は行が無い場合と
同じ欠損として自然に扱われる（タイル焼き込み・分布プレビューは無変更）。
明示的な対応が要ったのは2箇所:

- `RoadGraphRepository.get_way_landcover`: 割合がNULLの行は`percentages=None`で返す
  （`LandcoverPercentages`の各列を`float | None`にはしない——値がある行では常に全列
  揃っており、Noneを許すと消費者側が列ごとにNoneを気にすることになる）。
- `domain/axis_inspector.py`: `percentages`がNoneなら開放度軸を算出不能として扱う。
  ここが区別されないと、開放度が「算出不能」ではなく0として評価される。

## 本番への適用

migrationはアプリ起動時の`apply_pending_migrations`で適用される（NOT NULL制約の解除と
列追加のみで、既存行の値は変わらない）。値なし行が実際に記録されるのは次に
`precompute_way_landcover.py`を流したときで、それまでは現状のまま動く。
