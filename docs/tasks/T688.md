# T688. way_landcoverの増分実行が「未計算」と「計算済み・値なし」を区別できるようにする

規模M。

状態: 未着手（2026-09-09起票、[T682](T682.md)より分離）

## 背景

`precompute_way_landcover.py`の増分実行（`--recompute`無し）は、`way_landcover`に行が
無いwayを対象にする。ラスタ範囲外・境界またぎ・有効画素不足のwayは行を作らないため、
これらは実行のたびに毎回ラスタ読み込みからやり直される（結果は毎回同じ「値なし」）。

## 保留による影響

無駄な再処理が増えるだけで、書き込まれる値は正しい（欠損は欠損のまま）。関東（`54S`
1枚）では該当wayが少なく実害は小さいが、全国展開（[T127](T127.md)）でラスタが複数枚に
なると境界またぎのwayが増え、再実行のたびに効いてくる。

## 対応方針（案）

`way_landcover`の割合8列をNULL可にし、`valid_pixels=0`＋割合NULLの行で「計算済み・
値なし」を表す（migrationが要る）。消費者側（`road_graph_repository`の読み出し・
`domain/evaluation.py`の材料解決）がNULLを欠損として扱えることの確認が前提。

T682で同時に行わなかったのは、消費者側の変更が`domain/evaluation.py`・
`domain/attributes.py`に及び、同ファイルを対象とする[T673](T673.md)と競合するため。
