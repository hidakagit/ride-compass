# T796. 起票の瞬間に、既存の未完了エントリとの重なりを機械的に出す

規模S。
状態: 完了（2026-09-13、ユーザー要望「改善計画追加時、未完了のものと重複しているか、
関連がないかチェックしてほしい」＝運用の標準化）

## 背景

重み配分のプロファイル機能を新規に起票したところ、同じ構想が[T307](T307.md)として
2026-08-25に起票済みだった（ユーザーの記憶で気づいた）。台帳は未完了だけで30件超・全体で
500行を超えており、起票時に既存へ目を通す運用は人の記憶頼みになっていた。`/task:next`は
候補を優先度順に出すだけで、近さは見ない。

自己申告のチェックを増やさない方針（CLAUDE.md「修正の原則」）に従い、文章のルールではなく
検知器にする。

## 対応

`scripts/review_checks.py`へ`plan_entry_overlap`を新設した。ステージ済みの
`docs/improvement-plan.md`に**新しく足された`- [ ]`行**を拾い、既存の未完了エントリと
語（漢字・カタカナの連なりと英数字識別子。台帳のほぼ全行に出る語は除外）が2つ以上重なるものを
最大3件まで出す。**参考表示**——別々に進めるのが正しいこともあり、寄せるかどうかは人が決める。

## 効いていることの確認

- わざと重複するエントリ（「目的地の名前検索（ジオコーディング）を入れる」）をステージして
  `review_checks.py docs --staged`を実行 → `T799とT631が「名前検索・目的地」を共有している`
  を出力。
- 現在の未完了34件を総当たりしても、閾値（語2つ）を超える組は[T288](T288.md)と
  [T388](T388.md)の1組だけ（どちらも「複数メンバーが触る状態になった時点」がトリガーの
  マルチワーカー対応で、既に相互リンク済み）。誤検知で埋もれる状態にはなっていない。
