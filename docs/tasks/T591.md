# T591: 二乗則の風材料を追加しバックエンドの3経路へ走行速度を配線する

状態: 未着手（2026-09-05起票、分割元は[T590](T590.md)）

## 背景

現行の`wind_penalty`（風速×cos）は走行速度に依存せず「速く走るほど同じ風がきつい」を
表現できない。相対風速ベクトルの二乗則による新材料を追加し、式の実体を1関数へ集約する。
数式・スケール・値域の試算は[T590](T590.md)「決定事項 1」参照。

## 対応方針

- `domain/wind.py`にベクトル版1関数を新設し、新材料（仮id `wind_drag_ratio`、ラベル
  「風の追加負荷(倍率)」）を計算する。引数は風速配列・風向配列・走行方位配列・走行速度
  （m/s）。スカラー版はその薄いラッパーにする。基準速度は`WIND_DRAG_REFERENCE_SPEED_MS`
  のような専用定数（`ASSUMED_SPEED_KMH`とは別）。
- 既存の`wind_penalty`は撤去する（表示用に残さない。[T590](T590.md)「決定事項 2」）。
  `REQUEST_DYNAMIC_MATERIAL_IDS`・`DYNAMIC_MATERIAL_EVALUATORS`・`material_catalog.py`の
  エントリを新材料へ差し替える。第1デプロイ時点では本番DBの風軸がまだ旧材料を参照する
  ため、[T584](T584.md)と同じく旧idを一時的に非推奨エイリアスとして残し、T599の切替後に
  撤去する（本番DB移行順序の制約、CLAUDE.md「コミット時の同期ルール」）。
- `DynamicAxisRequestContext`へ`travel_speed_ms`を必須フィールドで追加する
  （`_LegCostComposer.speed_kmh`が既に持つ値を渡す）。フォールバック既定値は置かず、
  伝播漏れが即座に失敗する形にする。
- `_evaluate_axes_bulk`内のインライン式・`_evaluate_wind_penalty_array`をいずれも
  wind.pyの関数呼び出しへ置き換え、式の実体を1箇所にする。`compute_edge_costs_bulk`の
  呼び出し元（`evaluation_service.py`）へも速度を明示的に渡す。
- `services/wind_way_service.py`（地図配信）の速度伝播は[T594](T594.md)で行う。本タスクでは
  スカラー版ラッパーの引数変更に追従するのみ。
- 材料の説明文（材料カタログ`description`）に、20km/hでの向かい風m/sとの換算早見表を
  含める（[T598](T598.md)の参考点配信が入るまでの暫定）。
