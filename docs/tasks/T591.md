# T591: 二乗則の風材料を追加しバックエンドの3経路へ走行速度を配線する

状態: 完了（2026-09-05起票・同日完了、分割元は[T590](T590.md)。設計判断・検証結果は末尾「実装メモ」参照）

## 背景

現行の`wind_penalty`（風速×cos）は走行速度に依存せず「速く走るほど同じ風がきつい」を
表現できない。相対風速ベクトルの二乗則による新材料を追加し、式の実体を1関数へ集約する。
数式・スケール・値域の試算は[T590](T590.md)「決定事項 1」参照。

## 対応方針

- `domain/wind.py`にベクトル版1関数を新設し、新材料（仮id `wind_drag_ratio`、ラベル
  「風の追加負荷(倍率)」）を計算する。引数は風速配列・風向配列・走行方位配列・走行速度
  （m/s）。スカラー版はその薄いラッパーにする。基準速度は`WIND_DRAG_REFERENCE_SPEED_MS`
  のような専用定数（`ASSUMED_SPEED_KMH`とは別）。
- 既存の`wind_penalty`は撤去する（表示用に残さない。[T590](T590.md)「決定事項 2」）。
  `REQUEST_DYNAMIC_MATERIAL_IDS`・`DYNAMIC_MATERIAL_EVALUATORS`・`material_catalog.py`の
  エントリを新材料へ差し替える。第1デプロイ時点では本番DBの風軸がまだ旧材料を参照する
  ため、[T584](T584.md)と同じく旧idを一時的に非推奨エイリアスとして残し、T599の切替後に
  撤去する（本番DB移行順序の制約、CLAUDE.md「コミット時の同期ルール」）。
- `DynamicAxisRequestContext`へ`travel_speed_ms`を必須フィールドで追加する
  （`_LegCostComposer.speed_kmh`が既に持つ値を渡す）。フォールバック既定値は置かず、
  伝播漏れが即座に失敗する形にする。
- `_evaluate_axes_bulk`内のインライン式・`_evaluate_wind_penalty_array`をいずれも
  wind.pyの関数呼び出しへ置き換え、式の実体を1箇所にする。`compute_edge_costs_bulk`の
  呼び出し元（`evaluation_service.py`）へも速度を明示的に渡す。
- `services/wind_way_service.py`（地図配信）の速度伝播は[T594](T594.md)で行う。本タスクでは
  スカラー版ラッパーの引数変更に追従するのみ。
- 材料の説明文（材料カタログ`description`）に、20km/hでの向かい風m/sとの換算早見表を
  含める（[T598](T598.md)の参考点配信が入るまでの暫定）。

## 実装メモ（2026-09-05）

### 設計判断

- `wind_penalty`は撤去せず**非推奨エイリアス**として残す（`display_only=True`、値は旧式の
  「進行方向に平行な風成分m/s」のまま。本番DBの風軸がこの材料を参照しているため、値の意味を
  変えると設計原則5に反する）。式は`domain/wind.py: headwind_component_ms`1箇所にあり、
  新式`wind_drag_ratio_array`の部品（`x = v + w·cos(d)`のcos項）でもある。
  T599で本番の風軸を切り替えた後にエイリアスを撤去する。
- `REQUEST_DYNAMIC_MATERIAL_IDS = {"wind_drag_ratio", "wind_penalty"}`。両材料とも
  `DYNAMIC_MATERIAL_EVALUATORS`で評価し、`evaluate_dynamic_material_arrays`（新設）を
  スカラー経路（`compute_dynamic_edge_materials`、旧`compute_wind_penalty`の後継）・
  bulk経路（`_evaluate_axes_bulk`）・静的行列＋動的軸合成（`evaluate_dynamic_axis_arrays`）
  の3経路が共通で通る。スカラー経路は配列版を長さ1で呼ぶ薄いラッパーにしたため式は
  乖離しない（スカラー経路は回帰テストのオラクル専用で本番のホットパスではない）。
- `DynamicAxisRequestContext.travel_speed_ms`は既定値なしの必須フィールド。
  `compute_edge_axis_scores`/`compute_edge_cost`/`compute_edge_costs_bulk`/
  `EvaluationService.evaluate_graph`は`travel_speed_ms: float | None = None`を持ち、
  `weather`を渡すのに速度が無ければ`ValueError`で即失敗する。
- `LegCostArrays.wind_penalty`・`RouteSegmentDetail.wind_penalty`・`wind_score`はエイリアス
  材料の配列を読むため値・単位（m/s）とも不変（汎用化は[T592](T592.md)）。
- `WindWayService`は速度が届かないため`material_id="wind_penalty"`のまま
  `headwind_component_ms`を呼ぶ（新材料への切替と速度伝播は[T594](T594.md)）。
- 単位: `wind_drag_ratio`は無次元（`unit=""`）。基準速度`WIND_DRAG_REFERENCE_SPEED_MS`
  （20km/h）。`kmh_to_ms`を`wind.py`に追加し`_LegCostComposer.compose`で変換する。
