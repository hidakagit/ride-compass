# T775. 軸別難易度の一覧を畳み、寄与度の凡例チップを詳細の入口にする 規模M

状態: 完了（2026-09-12起票・完了）

## 背景

ルート結果タブの縦の過半は軸別難易度の一覧（1軸1行のグリッド）で、公開軸の本数に比例して
伸びる。[T773](T773.md)で重み0の軸の折りたたみと材料内訳の移動を入れた後もデスクトップ
247px・モバイル390pxで232pxを占め、モバイルの結果シートは44pxはみ出したままである。

一方、その真上には「重み付き寄与度」の積み上げバーと凡例（`AxisContributionBar`）があり、
同じ軸が折り返し付きのチップで並んでいる（1軸1行ではないため密度が桁違いに高い）。
凡例チップを詳細の入口にすれば、一覧が担っている情報（軸別難易度・生値・説明）は
チップの中へ収まる。

## 決定（2026-09-12）

[T773](T773.md)完了後、行に残った生値（`raw_value_unit`を持つ軸だけが2段目を持つ状態）が
軸ごとのばらつきとしてユーザー指摘を受けた。そこから「一覧そのものが要るか」へ発展し、
**一覧を畳んで凡例チップを詳細の入口にする**方針で合意した。

凡例が肩代わりできない2点は次のように決めた。

- **凡例に出るのは寄与度が0でない軸だけ**。出ない軸はバーの下の折り返しチップ行へ置き、
  重み0の軸は「未使用の軸 N本」へ畳み、値が来ないだけの軸は「データなし」チップで残す
  （[T773](T773.md)で決めた「畳む条件は重みだけ」をそのまま引き継ぐ）。
- **凡例の数字は重み付き寄与度、一覧の数字は軸別難易度**という別物の混同を避けるため、
  詳細の中では「軸別難易度 N/100」と単位付きで書く。

押せることは下線ではなくチップ内の(i)アイコンで示す（このアプリで「押すと説明が出る」を
表す形を共有する）。下線だけの案を実機で見て、押せると分からなかったため差し替えた。

`AxisContributionBar`は区間クリック詳細とも共有するため、詳細の中身はコンポーネントが
組み立てず`renderDetail`（軸→中身）で呼び出し側から受ける——軸別難易度も材料値も
呼び出し側のデータで、ここが知ると「値の出どころを知らない」という前提が崩れる。
区間側は当面`renderDetail`を渡さず、静的な凡例のままにしている
（区間は`material_categories`が値そのもの（文字列）でルート集約の`material_category_shares`
とは器が違うため、同じ整形関数をそのまま使えない）。
