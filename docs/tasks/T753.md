# T753. Way単位の材料解決が舗装タグを拾えていない 規模S

状態: 未着手（2026-09-12起票、[T720](T720.md)の本番計測中に発覚）

## 背景

`domain/axis_inspector.py: way_scalar_materials`が舗装を
`surface_attributes={_WAY_SCOPE_KEY: tags.get("surface")}`として渡しているが、
`surface`は`osm_raw_ways.surface`の専用列で、tags jsonbには入らない
（`domain/osm_adapter.py: ALLOWED_WAY_TAGS`が「highway/surface/onewayは既存の専用
フィールドで扱うためここには含めない」と宣言している）。そのため材料`surface_good`は
Way単位の経路では常に欠損する。

区間インスペクタが読む`road_graph_repository.py: _WAY_TAGS_BY_OSM_WAY_ID_SQL`も、
軸スタジオの分布プレビューが読む`_SAMPLE_WAY_MATERIALS_TEMPLATE`も、
`w.surface`をSELECTしていない。

## 実害

- 地図で道路をクリックして出る区間インスペクタで、公開軸「舗装質」が**全区間で
  「データなし」**になる。合わせて`covered_weight_fraction`（「◯%相当の軸のみで算出」）も
  実際より低く出るため、他の軸の内訳まで過小に見える。
- `scripts/measure_axis_saturation.py`が舗装質を測れない（本番で「全区間で材料が欠損」）。
  折れ点の当て方を実データで点検できる軸から1つ落ちている。

ルート評価そのもの（Edge単位、`domain/evaluation.py`）は
`road_graph_repository.get_surface_attributes`が専用列をJOINして読むため影響を受けない。

## 確認した事実（2026-09-12、本番DB）

- `osm_raw_ways`の無作為標本6,790本のうち`tags ? 'surface'`は**0本**（`lit`は50本あり、
  tags jsonb自体は機能している）。
- `measure_axis_saturation.py`を本番へ実行すると、全域・都心bboxのいずれでも
  `surface_q`が「全区間で材料が欠損」。

## 対応方針（未確定）

`w.surface`を2つのSQLの選択列へ足し、`way_scalar_materials`の引数へ通す。
`sample_way_rows`側は`WayMaterialSampleRow`へ1フィールド増える。
tagsに入らない専用列が他にもある（`highway`は既に別引数、`oneway`は
`WaySpec.direction`へ解決済み）ため、同じ取りこぼしが他の材料にも無いかを
`MaterialExtractionContext`の各フィールドについて確認してから直す。

## 完了条件

- 区間インスペクタで舗装質が算出されること（本番の任意のwayで確認）
- `measure_axis_saturation.py`が`surface_q`の分布を出せること
- Way単位で解決できるはずの材料が他に欠損していないか点検した結果を記録すること
