# T549: `supports_route_coloring`フラグの全面撤去（全公開軸を自動的にルート地図色分け対象へ）

状態: 着手中（2026-09-03）

## 背景

ユーザーから「自転車インフラを重み設定したのに地図の色分けで選べない」という指摘を受け
調査したところ、`bicycle_infra_quality`軸は`supports_route_coloring=False`（地図の
色分け対象外）だった。`backend/app/domain/axis_definitions.py`の該当docstring
（改善計画T440の訂正記録）を確認したところ、以前は`gradient`のみこの機構の対象外という
非対称な設計だったが、「軸スタジオと同期していない」という指摘を受けて訂正され、
**現在はこの機構（`axis_difficulties[axis_id]`を汎用の3段階色分けとして使う仕組み）の
対象外になる軸は技術的に存在しない**ことが判明した。つまり`supports_route_coloring=False`の
軸（car_stress・night・accident・bicycle_infra_quality・stop_density）は、技術的制約では
なく「まだ誰も軸スタジオでtrueにしていないだけ」。

ユーザーへこの経緯を説明したところ、「全部色付けできるなら除外できる設定を残す意味ない」
という判断に至った。地図の色分けチップ列は既にroute_preferenceの重み>0でフィルタ済み
（`filterRouteStyleModesByPreference`）のため、実際に使っている軸だけに絞り込む役割は
既にそちらが担っており、`supports_route_coloring`という追加の手動フラグを二重に持つ意味が
薄いという判断。ユーザー承認済み（「問題ない。バックグラウンドで進めて」）。

## 対応方針

`supports_route_coloring`フィールドをシステム全体（DBカラム含む）から撤去し、
`routeStyleModesFromCatalogAxes`が公開軸すべてを無条件でルート色分けモードの候補にする
（実際の表示絞り込みはroute_preferenceの重みのみが担う）よう変更する。

対応方針・実装メモ・検証結果は実装完了後に追記する。
