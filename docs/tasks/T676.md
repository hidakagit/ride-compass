# T676. UI/CSSの重複と不整合を解消する

規模M。

状態: 完了（2026-09-08起票、2026-09-09完了）

## 背景

統合レビュー第5回（[2026-09-08_all.md](../../.claude/commands/review/history/2026-09-08_all.md)）
が検出した指摘のうち、下表の7件を1つの起票単位として扱う。

状態ドットの視覚表現が3ファイルへ複製、z-indexが素の数値で10ファイル以上に散在、
29px四方ボタンが3箇所へ手書きコピー。`composes`による共有パターンは確立済みで、
新規追加側だけがそれを踏襲していない。

## 対応方針と結果

対象7件すべてを実施した（見送りなし）。**見た目は1ピクセルも変えない**ことを完了条件に
置き（下記「検証」参照）、重複の解消は共有スタイルへの`composes`と`globals.css`の
トークン化だけで行っている。

### 1. 重なり順（7-2）

`globals.css`の`:root`へ7段のスケール（`--z-map-control` 20／`--z-map-popup` 25／
`--z-map-detail` 30／`--z-bottom-sheet` 45／`--z-header-popover` 46／
`--z-floating-panel` 50／`--z-top-popover` 60）を置き、10ファイル＋インラインstyle 2箇所の
素の数値を全部これへ寄せた。**バグの実体**は`LensControl`のポップオーバーが40だったこと
——Portal先の`document.body`直下ではBottomSheet・モバイルタブバー（45）より下になり、
シートを開いたままレンズを開くと一覧の下半分が背後に潜っていた。他の
「必ず最前面に見えるべきポップオーバー」と同じ`--z-top-popover`へ揃えて解消した
（Playwrightで開いた状態のz-indexが60になることを実測）。

1つの部品の内側だけで重なる要素（読み込みオーバーレイ・sticky列見出し・地図の失敗
メッセージ）はスケールの対象外とし、素の小さい値のまま残した。

### 2. 状態ドット（7-3）

`components/ui/statusDot.module.css`へ形（塗り＝点滅／中空／danger）とkeyframesを1つ置き、
`LayerChip`・`MapOverlayControls`・`LensControl`の3ファイルは`composes`＋置き場所
（行内の余白／絶対配置／flexで縮まない）だけを持つ形にした。クラス名の接尾辞が
`LayerDataStatus`の値と一致する仕組み（対訳表をコンポーネント内に持たない）はそのまま。

### 3. 地図右上のボタン（7-4）

`components/ui/mapCtrlButton.module.css`（MapLibre純正コントロールへ揃えた29px四方）を
新設し、`TravelBearingControl`・`RideConditionBar`が`composes`する形にした。寸法と余白は
`globals.css`の`--map-ctrl-button-size`/`--map-ctrl-margin`/`--map-ctrl-stack-top`/
`--map-ctrl-stack-gap`へ出し、`page.module.css`の`.rideConditionColumn`の位置は
`calc()`でそれらから導出する——**手動同期を明示していたコメントが不要になった**
（実測でtop 137px = 104 + 29 + 4、変更前と同値）。

### 4. 管理画面・ログ・凡例（7-5）

- 表シェル（`.tableWrap`/`.table`）を`ui/adminPanel.module.css`へ集約。行内の縦揃えだけは
  パネルごとに違うため共有側に置かず、各パネルが`.table th, .table td`へ足す。
- ログの重大度色を`--color-log-error`/`--color-log-warning`/`--color-log-info`へ集約
  （13箇所）。薄い塗り・枠線の`rgba(...)`も`color-mix`で同じトークンから作る。これらは
  固定ダークな面の上でだけ使うため、**ライト/ダークで切り替えない**。
- **別コンポーネントのCSS Modulesを直接importして借りる**3系統を解消した
  （`RouteAxisProfile`→`RouteSettingsPanel`、`AxisContributionBar`→同、
  軸スタジオ2ファイル→`recipeControls`）。借り物は改名時にCSS Modulesが`undefined`を返し、
  tscもlintも止めないまま無スタイルで本番へ出る。共有分は
  `ui/infoButton.module.css`・`ui/axisLegend.module.css`へ出し、双方が`composes`する。
  `AxisContributionBar`の凡例ドットだけは行内に折り返す都合で一回り小さいため、共通の
  形を`composes`した上でサイズだけ上書きする。

### 5. タイムアウト（7-6）

`lib/apiTimeouts.ts`へ呼び出しの性質ごとの名前付き定数（既定15秒・状態確認5秒・
カタログ10秒・分布プレビュー60秒・管理画面の重い集計90秒）を置き、frontend 7ファイル・
14箇所の直書きと、route handler側の4つの個別定数を全部これへ寄せた。**ブラウザ側の
クライアントとNext.js route handlerが同じ定数を共有する**ため、「片方だけ延ばしても
症状が変わらない」状態が構造として作れなくなる。

**副産物**: route handlerからの`export const *_PROXY_TIMEOUT_MS`は、Next.jsが生成する
ルート型（route moduleのexportは決められたものだけ）に反しており、
`next typegen && tsc --noEmit`（CIのfrontend型チェックと同じ手順）が着手前の時点で
4件のエラーで落ちていた。定数を`lib/`へ移したことでこれも解消している。

### 6. 色（7-8・7-9）

- `error.tsx`の`#666`を`var(--color-muted)`へ（ダークモードのコントラスト比が約3.4:1
  だった）。
- `SystemStatusPanel`の`.msmRow`だけがテーマトークンを使っていたのを、同ファイルの
  他の行と同じ固定値（`rgba(255, 255, 255, 0.15)`と`--color-log-error`）へ揃えた
  ——このパネルは固定ダークな面の上にあり、ダークテーマでは`--color-border`（暗い灰）が
  背景に溶けて枠線が消えていた。

## 検証

chromiumで撮影して比較した。対象はモバイル420×860（ライト/ダーク）・デスクトップ
1280×900の各画面と、レンズ一覧を開いた状態・ボトムシート/サイドバーの3タブ
（ルート設定・ルート結果・地図の見え方）・グループチップ展開。

- `next build --webpack` 成功／`next typegen && tsc --noEmit` エラー0（着手前は上記の
  4件で失敗）／`eslint src` クリーン
- `vitest run` 1143 passed（126ファイル）
- Playwrightでの実測: 全トークンが解決すること、地図右上ボタンが29px四方・白背景・
  角丸4px・`z-index: 20`であること、走行条件列のtopが変更前と同じ137pxであること、
  レンズ／走行方位／出発時刻のポップオーバーが60、ヘッダーメニューが46であること

  骨格の統合は触っていない。

  ため残した。
