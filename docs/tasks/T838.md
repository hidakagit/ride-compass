# T838. 区間の乗り換えが「他ルート1本と丸ごと入れ替え」になり、複数ルートを乗り継げない

規模M。
状態: 完了（2026-09-14。割る下限の管理画面化は[T805](T805.md)へ渡した）

起票のきっかけは実機の指摘「自分の一部分を他ルート1つと置き換えるだけ。他ルートを複数
乗り継ぐかたちに区間タップして編集できないか」。

## 何が起きているか

実機（4.0kmの目的地ルート）で、選べる区間が`0.2〜4.0km`の1つだけになり、その中から
他候補3本のうち1本を選ぶ形になっていた。**区間の乗り換えというより、ルートごとの入れ替え**。

複数の区間を別々の候補から取ることは、いまの実装でも**区間が重ならなければできる**
（グループは独立）。できないのは、候補が元ルートとほぼ全域で違うとき——その候補の区間が
他の候補の区間をすべて飲み込み、1グループへまとまる（重なる区間を同時に差し替えると
経路が壊れるため、グループ内は排他。[T837](T837.md)で見送りとして記録）。

## 原因は区間の切り出し方

`lib/routeSplice.ts: differingStretches`は**Edge idの一致だけ**で「同じ道」を判定する。
2本のルートが同じノードで交差・接触していても、そこで同じEdgeを通っていなければ
「違う道が続いている」と見なし、1本の長い区間になる。

実際には、交差・接触したノードは**乗り換え可能な地点**である。そこで切れば、長い区間が
複数の短い区間へ分かれ、区間ごとに別の候補を選べる（＝複数ルートの乗り継ぎ）。

## 方針の候補

1. **共有する地点で区間を割る**（第一候補）。フロントの`geometry.coordinates`と
   `edge_point_offsets`から、元と候補が同じ座標を通る点を順序を保って拾い、区間を割る。
   座標は同じグラフのノード由来なので一致は厳密。backendの変更が要らない。
2. **backendがノードidを返す**。`edge_ids`と同じ形でノード列を返せば、座標の一致に頼らずに
   割れる。APIとフロントの両方に手が要るが、意味としてはこちらが素直。
3. 割った結果の区間が細かくなりすぎないよう、**最短長（例: 200m未満は割らない）**を置く。
   1区間=1行のUIは区間が増えるほど縦に伸びる。

## 決める必要があること（着手前にユーザーと詰める）

- 地図のタップで区間を選ぶ操作を主にするか、パネルの行を主にするか（いまは両方できる）
- 区間が10個以上になったときのパネルの見せ方（1区間=1行のまま縦に伸ばすかどうか）
- 「乗り継いだ結果が元のどの候補とも違う」ことをどう示すか

## 影響（このままの場合）

編集の入口を「ルート結果から続く導線」へ寄せた（[T808](T808.md)）意味が薄い。候補一覧から
1本選び直すのと結果が変わらないため、編集という操作そのものが要らなくなる。

## 決定（2026-09-14、ユーザー判断）

- 評価は従来どおり「差分を見る」で**まとめて1回だけ**投げる。区間を選ぶたびには投げない
- 区間が多いときは、選んだ区間と上から数区間だけ残して畳む
- 割る下限は200mから始める。**妥当か分からないため管理画面から変えたい**
  → 器は[T805](T805.md)（暫定値の管理画面化）へ渡し、こちらは単一の定数
  （`MIN_SPLIT_STRETCH_KM`）に置いてT805の対象表へ載せた

## 実装

- `lib/routeSplice.ts: splitPairedStretch`を新設。元と相手が**同じ座標を通るEdgeの境界**で
  区間を割る（座標はどちらも同じグラフのノード由来なので完全一致で判定）。割った結果に
  `MIN_SPLIT_STRETCH_KM`未満の断片を作らない
- `stretchAlternativeGroups`は座標（`shape`）を渡されたときだけ割る。渡さなければ従来どおり
- 差し替え後のEdge列は相手側の範囲そのものを使う。共有Edgeを目印に切り出す
  `targetStretchEdgeIds`は、共有**地点**で割った区間では両端に共有Edgeが無く使えない
- パネルは「N区間を乗り継ぎ」を見出し行へ出し、区間が10を超えたら選んだ区間＋上から数区間
  だけ残して「残りN区間を出す」で開く

検証:

- `splitPairedStretch`の単体テスト（割れる／下限未満は割らない／同じ地点を通らなければ
  割らない／座標が無ければ従来どおり）と、割れた区間が別グループになり区間ごとに別の候補を
  選べることの確認
- [T837](T837.md)の回帰テストは、割れない形（元と同じ地点を通らない迂回）へ作り替えて維持。
  T837の修正を戻すと落ちることを再確認した
