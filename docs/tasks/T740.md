# T740. テストの空白と偽陽性を是正する 規模M

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 P3束ね）

## 背景

対象8件。`page.test.tsx`の`route_preference`が恒真、`secondaryAxes.test.ts`が対象0件で空振り、categorical材料のエンジン側統合テスト不在ほか。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対象の確定: 列挙ではなく導出

第7回のP3は分類と件数だけを残し個票が残っていない（[T752](T752.md)）。名前が挙がった3件を
直すだけでは残り5件に届かないため、**「空振り」という性質そのものを機械的に列挙した**
（[design-principles.md](../design-principles.md)構造仕様12）。

性質: **絞り込みを経て作られた母集団をループし、要素ごとにアサーションする。母集団が0件に
なるとそのアサーションは1回も走らず緑になる。** これを`scripts/review_checks.py`の
`vacuous_test_loops`として検知器にした（テストファイル275本を走査）。

実測 **11件**——レビューが挙げた「8件」より多い。うち`staticAttributeLayers.test.ts`の
3組は、同じ形のテストが並んでいて**一方だけ空でないことを確かめていた**（事故レイヤーには
`expect(expressionColors.length).toBeGreaterThan(0)`があり、停止要因POI・補給POI・指定路線には
無い）。手で列挙していたら「同じテストが既にあるから大丈夫」と読み飛ばす側だった。

11件すべてを是正し、検知器は`staged`/`since`/`full`の3経路で強制する。

## 名前が挙がっていた3件

### `secondaryAxes.test.ts`の空振りが隠していたもの

空振りしていたのは「`category="動的"`の軸は推定指標グループへ出ない」の実データ側確認で、
`axis-catalog.json`に`category="動的"`の軸が**0件**（実測: 全10軸が`観測`か`推定`）のため、
ループが1回も回らない。

母集団が空なのは実データの都合ではなく、**コード側の除外条件が死んでいた**ためだった。
windの`category`はスナップショット上`"推定"`（実測）で、`secondaryAxes.ts`の
`category !== "動的"`は何も除外していない。そのすぐ上のコメントは「windの`category`は
`"動的"`のまま——この条件は生きた現役のフィルタ」と書いており、現物と食い違っていた。

対応: 死んだ条件を撤去し、除外の経路を`show_map_icon`（軸スタジオから設定する、軸スタジオ
GUIのON/OFFがそのまま効く唯一のスイッチ）1本に寄せた。**現データに対する挙動は変わらない**
（windは`category`条件でも落ちていなかった）。実際に`SECONDARY_AXES`を読む先は候補線の
下敷きレイヤーidと重み一覧の並び順で、windは専用レイヤーを持たない（`display.kind="none"`）
ため下敷きには元から出ない。消費者側のコメント（`axisLayers.ts`・`evaluationAxes.ts`）も
`category="動的"`を除外理由として名指ししていたので同時に直した。

テストは実データの`show_map_icon`で検証する形へ置き換え、両方向の母集団が空でないことを
主張する（どちらかが0件になったら「除外が効いている」の確認が消えた合図）。

### `page.test.tsx`の`route_preference`が恒真

「軸カタログ取得失敗時は`route_preference`を送らない」の確認だが、`route_preference`が載る
条件は`weightOverrideEnabled && axisCatalog.loaded`で、テストは前者をOFFのまま走っていた
——カタログの成否に関わらず`undefined`になる。重み上書きをONにし、成功側のテストへ
「同じ条件なら実際に載る」対の主張を足した。

同じ形が`generationRequest.test.ts`にもあった（`lens_axis_id`/`route_preference`の
`toBeUndefined()`に対となる肯定側が無い。`waypoints`/`destination`にはある）。こちらも
肯定側のテストを足した。

### categorical材料のエンジン側統合テスト不在

[T728](T728.md)で是正した配線（静的スコア行列のcategorical列→区間の`material_categories`→
候補の`material_category_shares`）に、エンジンを通した検証が無かった。畳み込み単体
（`test_route.py`）と後処理で消えないこと（`test_route_generator.py`）はあるが、どちらも
配線が切れていても通る。`test_road_graph_engine.py`へ通しのテストを追加した。

## 偽陽性の側を検知器にしなかった理由

「否定の主張に対となる肯定が無い」形も機械的に数えられる（frontendの
`toBeUndefined`/`toBeNull` 38件中、同一ファイルに肯定側が無いもの13件）。ただし中身を見ると
GETリクエストの`init.body`・レンダリング結果が空である確認など**対を持たないのが正しいもの**
が大半で、検知器にすると誤検知が先に立つ。数えた結果を根拠に見送り、代わりに上の2件を
人が見て直した。
