# T749. ドキュメントの要素の数え上げを挙動の記述へ置き換える 規模M

状態: 完了（2026-09-12。起票は2026-09-11、ユーザー指摘「ドキュメントに要素をすべて列挙するのやめない？
示すべきは挙動だと思う」。[documentation.md](../documentation.md)の適用）

## 背景

ドキュメントの陳腐化は統合レビューで一貫して最大の指摘カテゴリで、かつ**増え続けている型**
（8月13件→9月17件）。中身を見ると、その多くが**個数と全件の一覧**である。

- `architecture.md`のファイル樹形図（`_common.py`の「4バッチが参照」は実際は12本、
  `refresh_derived.py`は全体で出現0回、`scripts/`の列挙が実装より少ない）
- `routers/__init__.py`のエンドポイント索引（region.py・material_catalog.pyで不足）
- `page-composition.md`のstate一覧（3件不足、1件は名前が違う）
- 個数表現（統合レビュー第6回で12件検出）

いずれも**書いた時点では正しく、要素が増えても文書側は何も壊れない**ため誰も気づかない。

## 対応方針

[documentation.md](../documentation.md)に従い、数え上げを挙動の記述へ置き換える。
**全部消すのではなく、「要素が1つ増えたときに嘘になる文」を探して書き換える。**

優先順位:

1. `docs/architecture.md`のファイル樹形図。`docs/modules/*.md`の対象ファイル表と重複して
   おり、**検査が無い側だけが古くなっている**。役割の説明とモジュール文書への導線へ畳む。
2. `routers/__init__.py`・`page-composition.md`等、コード側・文書側に散った索引。
3. 個数表現の一掃（「N本」「N軸」「N値」）。

代表例を残すのは許容する（「`ROAD_SURFACE_TILE_VERSION`など」）。全件のつもりで
読まれる書き方をしないこと。

## 例外として残すもの

`docs/modules/*.md`の対象ファイル表。`find_undocumented_files`が完全性を検査するため
静かに古くならず、「この新規ファイルの責務はどのモジュールが持つか」の逆引きは
コード側に等価な表現が無い。

## 実装メモ

### 1. `architecture.md`のファイル樹形図（243行 → 46行）

`## 2. ディレクトリ構成`は、全ファイルを1行ずつ並べ各行に改善計画Txxxの経緯を付けた
樹形図だった。同じ一覧が`docs/modules/*.md`の対象ファイル表にもあり、**片方だけ機械検査が
あるため、検査の無いこちらだけが古くなっていた**（`tests/`は実在の一部しか並んでおらず、
`infrastructure/`は近年追加したファイルが載っていない）。

層の役割と、層をまたぐときの約束（依存の向き、frontendがbackendの値を手書き複製しない）
だけを残し、ファイル単位の責務は`docs/modules/README.md`へ誘導する形へ畳んだ。誘導先は
`find_undocumented_files`が「実装ファイルがどこにも載っていない」状態を検出するため、
新しいファイルが増えても静かに古くならない。

### 2. コード側・文書側の索引

- `api/routers/__init__.py`のdocstring: 全エンドポイントのパスを列挙していた索引を、
  分割の基準（外部との境界の種類）の説明へ置き換えた。全パスは`/docs`のOpenAPIか
  `export_openapi.py`の出力で引ける。
- `docs/modules/frontend/page-composition.md`: page.tsxのstate全件表を、
  **永続化するかどうかの判断基準**の表＋代表例へ置き換えた。復元時に整合が要る
  `hardFilters`の扱い（キー集合の完全一致を要求するAPIのため、古い保存値をそのまま
  送ると422になる）は挙動として残した。

### 3. 個数表現

現在の状態を語っているものだけを直した（過去の変更を記録している「8軸→7軸」等は記録の
ため残す）:

- `CLAUDE.md`の「backend8・frontend7の全15モジュール」
- `architecture.md`の「現行8軸の材料には」「全26材料（うちcategoricalは…の5件）」
  ——材料の全件は生成物`material-catalog.json`を指す形へ
- `docs/modules/backend/dynamic-way-values.md`の「現状wind/gradientの2軸のみ」
  ——軸スタジオで足せるフラグである、という挙動の説明へ
- `docs/modules/backend/axis-studio.md`の「car_stressの5内部軸が実例」

`AxisShape`の「2プリミティブ」・警戒度バッジの「4段階」・材料解決の「3段階」は残した。
いずれも**設計として個数を決めている**ものであり、増やすにはコード変更とこの文書の更新が
同時に要る——GUIから静かに増える軸・材料とは性質が違う。
