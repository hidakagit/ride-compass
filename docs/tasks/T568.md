# T568: SearchGraphStatics/選定間引きのメモリ最適化（entry_keys撤去・int32化・ビットマスク化）

状態: 未着手（2026-09-03起票、[T557](T557.md)項目6の`/code-review`指摘を専用タスクへ切り出し。
CSR dtype変更・タイル集合キーキャッシュの上限分離・間引きアルゴリズムのビットマスク化という
独立した3つの性能変更を含み、T557で既に2回改修した同じホットパスへさらに手を入れるため、
正しさ修正と同じコミットへ積み増さずレビュー・検証の焦点を保つ目的で分離した）

## 背景

`/code-review`（[history/2026-09-03_codereview.md](../../.claude/commands/review/history/2026-09-03_codereview.md)）が指摘したメモリ使用量の懸念:

- `SearchGraphStatics`（`backend/app/domain/routing.py`の`CsrGraphStructure`）が持つ
  `entry_keys`は`build_shortest_path_tree`実行のたびに`np.searchsorted`の検索対象として
  使うだけの派生値だが、フィールドとして永続保持している。タイル集合キーの
  プロセス内LRU（`infrastructure/search_graph_cache.py`、上限64件）ぶん常駐し、
  実データ規模の見積もりで最大約1.2GBに達しうる。
- `indptr`/`indices`/`entry_edge_index`が既定のint64のままで、int32で十分な値域
  （Edge数・Node数が2^31を超えない前提）に対し2倍のメモリを使っている。
- `_lazy_graph_cache`と`_search_statics_cache`が同じ上限件数（64）を共有しているが、
  後者の1エントリの方が重い（CSR構造一式）ため、上限を分離して`SearchGraphStatics`側は
  より小さく（例: 16）絞る余地がある。
- `domain/routing.py: select_diverse_by_overlap`内部の間引き判定が、採用済み集合を
  `masks`（`(max_count, edge_count)`のbool二次元配列）で持ち、リクエストごとに
  約22MB×2本（2閾値パスぶん、[T557](T557.md)項目15で1回のループへ統合済みだが配列自体の
  サイズは変わらず）確保する。`TURNAROUND_POOL_MAX=40 ≤ 64`のため、採用済み集合を
  Edgeごとのuint64ビットマスク1本（Edge数×8B）で表現できれば大幅に削減できる。

## 対応方針（`/code-review`指摘のまま、着手時に再検証すること）

1. `entry_keys`を`CsrGraphStructure`のフィールドから外し、`_accumulate_tree_lengths`が
   都度（`np.searchsorted`が必要になった時点で）`indptr`/`indices`から再構築する形へ。
2. `indptr`/`indices`/`entry_edge_index`をint32へ（Edge数・Node数の実際の上限を確認し、
   オーバーフローしないことを検証してから変更する）。
3. `infrastructure/search_graph_cache.py`の`_search_statics_cache`に、`_lazy_graph_cache`とは
   別の（より小さい）上限件数を設定する。
4. `select_diverse_by_overlap`の`masks`をuint64ビットマスク1本（Edge数ぶん）へ置き換え、
   ビット演算（AND＋popcount相当）で重複率を求める形へ再設計する。

## 完了条件（案、着手時に精査する）

- 上記4点の実装後、`pytest -q -m "not postgis"`・`benchmarks/bench_t531_route_generation.py`
  （dev DB）でRSS（常駐メモリ）と`select_ms`の前後を実測し記録する。
- 既存の`select_diverse_by_overlap`関連テスト（`tests/test_routing.py`）が、ビットマスク化後も
  同じ決定的な選定結果を返すことを確認する（境界ケース: `max_count`が64を超える呼び出しが
  無いことのassert、または64超過時のフォールバックを設計する）。
- docs/modules（`docs/modules/backend/routing-engine.md`「探索・索引構築のキャッシュ」節）を
  同一コミットで更新する。
