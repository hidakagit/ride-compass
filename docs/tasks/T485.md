# T485. ルート線クリック時のレーダーチャートポップアップが常にエラーで表示されない不具合を修正

状態: 完了（2026-08-31）

- 背景: ユーザー報告「マップ上をクリックするとレーダーチャートが出るようにしていなかった？
  今出ない」。T403で実装した機能（ルート線区間クリック時のレーダーチャートポップアップ、
  `routeSegmentChartPopup.ts: buildRouteSegmentChartPopupHtml`）が実機で機能していなかった。
- 原因: `MapView.tsx: handleRouteSegmentClick`が`feature.properties`をそのまま
  `RouteSegmentProperties`として`buildRouteSegmentChartPopupHtml`へ渡していたが、
  MapLibre GLはGeoJSONソースのfeature propertiesをvector tile相当の内部表現へ変換する際、
  オブジェクト値（`axis_difficulties`、`RouteSegmentDetail`で唯一のオブジェクト型
  フィールド）をJSON文字列へ自動的にシリアライズする（vector tile仕様がプリミティブ型
  [string/number/boolean]しか保持できないため）。`buildRouteSegmentChartPopupHtml`内の
  `Object.entries(segment.axis_difficulties ?? {})`が文字列を文字単位でイテレートしてしまい、
  各文字（1文字のstring）を数値として扱おうとして`value.toFixed is not a function`で
  例外になっていた。ユニットテスト（`routeSegmentChartPopup.test.ts`）はモックオブジェクトを
  直接渡すため、MapLibreの実際のプロパティシリアライズを経由せずこの不具合を検出できて
  いなかった。
- 調査方法: Browserペインでのクリック操作では座標系（screenshotのCSSピクセルとMapLibre
  canvasの実ピクセルの対応）を正確に特定できず再現に手間取ったため、`map.project()`で
  実際にレンダリングされたfeatureの座標をピクセル座標へ変換し、`map.fire('click', ...)`で
  MapLibreの内部イベントパイプラインへ直接合成クリックを発火させて再現・検証した
  （このとき実際のスタックトレースで`formatDifficultyValue`内の`value.toFixed`エラーが
  `handleRouteSegmentClick`から連鎖していることを確認）。
- 対応: `handleRouteSegmentClick`で`axis_difficulties`が文字列型なら`JSON.parse`してから
  `buildRouteSegmentChartPopupHtml`へ渡すよう修正。
- 検証: `vitest run src/components/Map/`332件・`tsc --noEmit`通過。Browserペインで
  実際にルート生成→合成クリックを発火させ、例外が出ずレーダーチャートポップアップが
  正しい内容（区間距離・到達予想時刻・勾配・風・路面・軸別内訳）で表示されることを確認。
- 経緯（並行セッションとの作業ツリー共有について）: この修正の実装中、別セッションが
  同じ作業ツリーでT478（統合レビュー第3回P3級指摘対応、MapView.tsx含む）を並行して
  作業・コミットしており、本タスクの未コミット変更（MapView.tsxの`handleRouteSegmentClick`
  修正）がその方のコミット`42dc536`（T478完了）へ意図せず一緒に取り込まれた形でpushされた
  （working treeを共有しているため、`git add`の対象範囲がファイル単位でしか区別できず、
  他セッションが先にcommitした時点でこちらの未コミット分も同じワーキングツリー状態から
  一緒にコミットされた）。コード自体は正しくmasterへ反映・push済みのため実害は無いが、
  コミット履歴上はT478のものとして記録されている。
