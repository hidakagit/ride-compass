# T981. テストの共通部品が、そのテストに関係ない属性を渡している 規模M

状態: 未着手（2026-09-20起票）。

## 何が問題か

テストが使う共通部品（フィクスチャ・ビルダー・ファクトリ）が、**型を満たすため以外の
「もっともらしい値」**を既定で持っていると、その値に関心のないテストまでそこに依存する。
共通部品を1つ直すと、無関係なテストが巻き添えで落ちる。

実例（2026-09-20、T970段階Eで作って作り直した）: 軸カタログの共通フィクスチャが
`unit: "点"`・`thresholds: [20,40,60,80]` を焼き込んでいたため、**単位にもしきい値にも
関心のない凡例ラベルのテスト**が `'0未満'` と `'0%未満'` の食い違いで落ちた。

あるべき形は**透明な部品**——既定値は型を満たすための空（`[]`・`""`・`null`）だけにし、
見たい性質は呼び出し側のテストが上書きで書く。

## 母集団の導出（誰がやっても同じになるように）

1. 共通部品を機械的に挙げる:
   - `frontend/src/**/__fixtures__/*.ts`・`frontend/src/testing/*.ts`・`frontend/e2e/fixtures.ts`
   - `backend/tests/` 直下の非 `test_*.py`（`realistic_axis_fixtures.py`・`material_arrays.py`・
     `admin_auth.py` 等）と `conftest.py` のfixture
2. 各部品について、**既定で値を持つフィールド**を列挙する（空・`None`・`0件`は除く）
3. その部品を使うテストを列挙し、**そのフィールドを読んでいないテストが1本でもあれば違反**
   ——読まないテストにとって、その値は落ちる理由にしかならない

## 直し方

- 既定値を空へ落とし、必要な性質は各テストが上書きで書く
- 「よく使う組み合わせ」を残したいときは、**部品の中に隠さず**テスト側のローカル定数にする
- 複数のテストが同じ組み合わせを必要とするなら、その組み合わせ自体が検証対象の性質か
  どうかを先に問う（性質ならその名前で部品にしてよい）

## 完了条件

- 上の手順で挙げた共通部品それぞれについて、既定で持つ値と、それを読まない利用テストの
  件数をこのエントリへ実測で書く
- 違反しているものを直し、**直した後に共通部品の既定値を1つ変えて、関係ないテストが
  落ちないことを確認する**（効いている確認）
- 直さないと決めたものは理由を書く（例: その値がその部品の定義そのもの）
