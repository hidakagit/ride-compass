## 背景

`docs/documentation.md`は「個数・全件の一覧を書かない。**要素が1つ増えたときに嘘になる文は
数え上げている**」と定めているが、**機械が検査しているのは`docs/modules/*.md`の対象ファイル表
だけ**（`find_undocumented_files`）。コード内コメント・その他のdocsには検査が無く、
第8回のレビューだけで29件が見つかった。

うち何件かは**既に嘘になっている**（下記★）。軸・材料・レイヤーはDBや軸スタジオから
デプロイを伴わずに増減するため、この型は放置すると必ず古くなる。

## 対応と結果

### 1. 検知器にできるか——測った結果、ブロックには使えない

「増減しうる集合の大きさを表す助数詞（個・種・値・箇所・つ・軸・レイヤー・材料等）＋
2以上の数」というパターンで、docs（tasks・記録文書を除く）と実装コメントを走査した。

| 走査 | 母集団 | 検知 |
|---|---|---|
| 助数詞つきの数（全件） | docs 47ファイル＋実装 323ファイル | 734件 |
| 直後に括弧の列挙がある | 同上 | 33件 |
| 列挙の件数が数と一致する | 同上 | 22件 |

レビューが挙げた実際の違反は29件で、**全件走査は96%が誤検出**になる。助数詞ごとでは
「つ」198件・「軸」85件・「種」83件・「段階」79件が上位で、その大半は
「2つの入力から決まる」「3段階で絞り込む」のような正当な記述だった。最も絞った
「数＋括弧の列挙が一致」（22件）でも、`キキクル4種（土砂・大雨・浸水・洪水）`のような
**外部システムの側で固定されている集合**が半数を占め、これは`docs/documentation.md`が
書いてよいと定めている「外部システムの挙動」にあたる。

そのため**ブロックする検知器は作らない**。代わりに`count_narrative`を
**追加行に対する参考表示**として置いた（`DETECTOR_ENFORCEMENT`は空集合）。書いた本人の
目に入れば直せる型で、既存の700件を毎回並べても意味が無いため、母集団は追加行に限る。
`docs/tasks/`・`improvement-plan.md`・レビューの記録文書は当時の数をそのまま持つため対象外。

### 2. 直した内容

★（事実と違っていたもの）は全件直した。数を落として挙動だけ残す形と、正本
（コードの定義・生成物）を指す形のどちらかへ寄せている。

- 停止要因POIの「5値のいずれかへ分類済み」→ 種別の数を書かない
- car_stressの「内部軸6つ」→ 「car_stressが参照する内部軸」
- 自転車インフラの正規化フラグ材料「3材料」「4材料」「5材料」→ 「この群」
- `smoothness`の`description`「excellent〜impassableの7段階」→ 段階数を落とす
  （軸スタジオのⓘに出る説明文）
- 動的気象の「表現は3パターン」→ 「表現の型は決まっている」
- `usePolledFetch`の「5箇所（…）独立実装されていた」→ 骨格の説明へ（経緯も落とした）
- `useWeatherConditions`の「4つとも」「5つのフェッチ」→ 数を書かない
- `MapView.tsx`の「5レイヤー（標高・車ストレス・…）」等の列挙→ 代表例へ
- `search_graph_cache`の「4キャッシュ」「順方向・転置版」→ 数と、存在しない転置版を落とす

★以外も一覧どおり直した（`traffic.py`・`routing-engine.md`・`material_catalog.py`の
レスポンス項目・`apiBaseUrl.ts`の消費者一覧・`windLayer.ts`・`precipitationNowcast.ts`・
`mapLayers.ts`・`roadFilterAxes.ts`・`curveDistributionOverlay.ts`・`weatherCode.ts`・
`amedasWeatherIcon.ts`・`statusDot.module.css`・`TodayOutlook.tsx`・`globals.css`・
`frontend-design-system.md`）。

### 一覧に無かったぶん（6件）

災害の「7要素」は一覧が挙げた3箇所だけでなく、`hooks/useDynamicWeatherLayers.ts`
（2箇所）・`app/page.tsx`（2箇所）・`Map/mapLayers.ts:448`にもあった。
`search_graph_cache.py`の「他の4キャッシュ」も同様。同じ性質のため併せて直した。

`Map/dynamicWeather.test.ts`の「災害系7要素は…」は、題が数を持つだけでなく、撤去済みidを
手で並べて「含まれないこと」を見ていた。母集団を`DISASTER_SOURCES`から引く形へ直して
あり、ソースを足したぶんも自動で対象に入る。

### 直さなかったもの

`globals.css`の色分けコメントにあった「4色（緑系=道路・紫系=評価軸・…）」は、
「評価軸」グループが既に地図チップから外れているため数も列挙も誤っていた。数と列挙を
落として「色相を分ける」という挙動だけ残した——現在どのグループがあるかは
`mapOverlayGroupFor`が正本。
