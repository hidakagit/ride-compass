# T584: 材料`no_lit`（街灯なし）を`lit`（街灯あり）へ正規化し、専用の反転機構を撤去する

状態: 着手中（2026-09-05起票、ユーザー指摘。同日、対応方針の第1デプロイ分[`lit`材料の
追加・`no_lit`を非推奨エイリアス化]を実装・実機確認まで完了。残るのは本番の軸定義移行
[第2デプロイ相当]と`no_lit`・反転機構の削除[第3デプロイ相当]、詳細は下記「実装
（第1デプロイ分、2026-09-05）」参照）

## 背景

管理画面「材料」タブ（[T577](T577.md)・[T583](T583.md)）を見たユーザーから、「他の真偽値材料は
『該当あり=true』なのに`no_lit`だけ『無いこと=true』で逆転している」という指摘があった。

- 真偽値材料は`has_tunnel`・`bridge`・`motor_vehicle_no`・`cycleway_has_track/lane/shared`・
  `shared_pedestrian_path`がすべて「該当あり=true」。`no_lit`だけ「`lit=yes`でない=true」で、
  抽出器は`tag_equals_extractor("lit", "yes", negate=True)`という特例（`domain/material_catalog.py`）。
- この反転を地図の色分け（ramp自動導出）まで通すため、`MaterialSpec.tile_property_inverted`→
  `registry.RampInput.invert`→`domain/axis_display.py`（3箇所）→API型`invert`→フロント
  `hooks/useAxisCatalog.ts`・`components/Map/axisLayers.ts`という専用の経路が、この1材料のためだけに
  存在する（他に`tile_property_inverted=True`の材料は無い）。設計原則「材料ごとの作り込みを
  避け、汎用の仕組みだけで表現する」に反する。
- 材料タブでは「街灯なし 90.4%欠損（確定値として評価）」と表示され、直感と逆に読める。

こうなっている理由は、夜間軸（`night`、公開済み）が「街灯なし(重み50)＋トンネル(重み50)」の
加点合計として作られており、フラグをすべて「ペナルティ方向でtrue」に揃えたかったこと、および
「タグ不明＝街灯なし（安全側）」という判断がこの向きの方が書きやすかったことによる。しかし
フラグは全部がペナルティ方向ではなく（自転車道系は「良い」方向）、向きは軸側の重みで表現できる
ため、材料をペナルティ方向に揃える必然性は無い。

## 対応方針

1. **材料の正規化**: `no_lit`を`lit`（ラベル「街灯あり」、`lit=yes`でtrue、タグ不在はfalse＝
   `missing_semantics="definite"`のまま）へ置き換える。抽出器は`tag_equals_extractor("lit", "yes")`
   （`negate`引数自体を撤去）。`tile_property="lit"`はそのまま、`tile_property_inverted`は
   フィールドごと削除し、`registry.invert`・`axis_display`の反転分岐・API型`invert`・
   フロントの`invert`処理を撤去する（`export_openapi.py`→`npm run generate:api`で生成物を同期）。
   `domain/night.py: resolve_night_flags`の`no_lit`も`lit`へ。
   `infrastructure/material_coverage.py: MATERIAL_COVERAGE_SPECS`の`no_lit`→`lit`
   （判定式は同じ`lit`タグの有無、source文言を「タグ不在は街灯なし扱い」のまま）。
2. **夜間軸の等価な書き換え**: 現行`terms=[no_lit(50), has_tunnel(50)]`・
   `breakpoints=[(0,0),(100,100)]`を、`terms=[lit(-50), has_tunnel(50)]`・
   `breakpoints=[(-50,0),(50,100)]`にする。街灯あり・トンネルなし=0、どちらも該当なし=50、
   街灯なし・トンネル=100で、現行と全組み合わせで同じスコアになる（`MaterialTerm.weight`は
   モデル上は負値可）。
3. **本番の適用順序**（[T396](T396.md)と同じ構図: 公開済み夜間軸のDB行が`no_lit`を参照しており、
   コードから消してpushすると`refresh_axis_definitions`の検証で本番backendが起動失敗する）:
   1. 第1デプロイ: `lit`を追加し、`no_lit`は非推奨エイリアス（同じ抽出器の否定、材料カタログ
      には出さない）として残す。
   2. 本番の軸定義をaxis_admin API経由で移行（夜間軸をunpublish→PUT[上記2]→republish。
      公開軸は不変のため複製ではなくこの手順）。`dump_axis_definitions_snapshot.py`で
      `backend/fixtures/axis_definitions_snapshot.json`を更新しコミット。dev DBも同様に移行。
   3. 第2デプロイ: `no_lit`エイリアスと反転機構を削除。
4. 事前に確認する点: 軸スタジオの重み入力UI（`AxisComposer`）が負値を受け付けるか、
   rampの自動導出（`domain/axis_display.py: derive_ramp_inputs`、真偽値項の加点合計を
   閾値へ変換する）が負の重みを正しく扱うか。扱えない場合は、`derive_ramp_inputs`側を
   「重みの符号で色の向きを決める」汎用処理にする（反転フラグの復活はしない）。

## 放置した場合の影響

材料タブの読み違い（「街灯なし」の欠損）と、1材料専用の反転経路（backend 4ファイル・
frontend 2ファイル・API型）の保守が続く。新しい「無いこと」系材料を追加するときに、
この特例を踏襲するか汎用の負の重みで表すかの判断が毎回発生する。

## 実装（第1デプロイ分、2026-09-05）

対応方針1の「第1デプロイ」部分のみを実施した（反転機構自体の撤去・夜間軸のDB移行は
未実施、下記「残作業」参照）。

- `domain/material_catalog.py`: 新規`"lit"`材料（`tile_property="lit"`、非反転、
  `extractor=tag_equals_extractor("lit", "yes")`）を追加。既存`"no_lit"`は抽出器・
  `tile_property_inverted`ともそのまま残し、`display_only=True`のみ追加（軸スタジオの
  材料選択肢から除外、実機確認済み）。
- `domain/night.py: night_materials`: 戻り値へ`"lit"`キーを追加（`"no_lit"`はその否定を
  返す後方互換エイリアスとして残す）。公開済み夜間軸のDB行は依然`no_lit`を参照するため、
  両方のキーを提供する必要がある。
- `infrastructure/material_coverage.py`: `MATERIAL_COVERAGE_SPECS`へ`"lit"`を追加
  （`no_lit`と同じSQL断片、`MATERIAL_CATALOGの全材料はいずれかのSPECSに載る`という
  既存の網羅性前提を満たすため）。
- `api/routers/material_catalog.py`: `display_only`材料の説明docstringを
  designation・no_litの2件に更新。
- frontend: `lib/axisMaterialsCatalog.ts`の静的フォールバックから`no_lit`を削除し
  `lit`へ置き換え（動的取得[`GET /api/material-catalog`]失敗時のみ参照される一覧）。
- docs: `docs/modules/backend/weather-dynamic-layers.md`・`evaluation-scoring.md`の
  `night.py`/`tile_property_inverted`記述を更新。

**検証**: `pytest`（backend全件、postgis込み1729件）green。新規/更新テスト:
`tests/test_night.py`（`lit`キー追加）、`tests/test_material_catalog.py`
（`lit`の非対称既定値テスト・`no_lit`のdisplay_only確認）、`tests/test_material_coverage.py`・
`tests/test_material_coverage_repository.py`（`lit`のSQL断片・実DB欠損件数）。
`export_openapi.py`実行→`git diff --exit-code`クリーン（Pydanticモデルの形は変わって
いないため無変化）。frontend: 関連テスト4ファイル70件・全体979件green、`tsc --noEmit`・
`eslint`とも0件。

**実機確認**（Browserペイン、dev backend+frontend、`/admin`Basic認証）: 「材料」タブの
欠損割合集計で「街灯あり - lit」「街灯なし - no_lit」が両方とも90.8%で並んで表示される
ことを確認（`no_lit`はコード上はまだ`MATERIAL_CATALOG`に残るため、`GET /api/admin/
material-catalog/coverage`はdisplay_onlyに関わらず全材料を対象にする——これは想定どおりで、
完全に「街灯なし」表示が消えるのは下記「残作業」の第3デプロイ完了後）。新規軸作成
フローの材料選択ドロップダウンには「街灯あり - lit」のみが表示され、「街灯なし - no_lit」
は選択肢から消えていることを確認（`display_only=True`が効いている）。

## 残作業（対応方針2・3、本番デプロイ後に別途実施）

1. **本番の軸定義移行**: axis_admin API経由で夜間軸をunpublish→PUT
   （`terms=[lit(-50, weight負値), has_tunnel(50)]`・`breakpoints=[(-50,0),(50,100)]`）→
   republish。事前に軸スタジオの重み入力UI・`derive_ramp_inputs`が負の重みを正しく
   扱えるか確認すること（対応方針4）。本番・dev DB両方で実施し、
   `dump_axis_definitions_snapshot.py`で`backend/fixtures/axis_definitions_snapshot.json`を
   更新・コミットする。
2. **第2デプロイ完了後、`no_lit`と反転機構を削除**: `domain/material_catalog.py`から
   `no_lit`エントリを削除、`MaterialSpec.tile_property_inverted`フィールド・
   `registry.py: TileInputSpec.invert`・`axis_display.py`の反転分岐（3箇所）・
   API型`invert`・フロント`hooks/useAxisCatalog.ts`・`components/Map/axisLayers.ts`の
   invert処理を撤去する。`infrastructure/material_coverage.py`から`no_lit`のSPECも削除。
   この時点で初めて「材料タブに街灯なしの欠損が出る」という元の問題が完全に解消する。
