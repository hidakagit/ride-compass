# T797. 出発地・経由地・目的地を同じ形で置けるようにする

規模M。
状態: 完了（2026-09-13、ユーザー要望「出発地、目的地、経由地、を明示的にピンを選んで
配置したい。出発地はデフォルトは現在地で良いが、現在地を移動できるのが分かりにくい」）

## 背景

3つとも役割は同じ「地点を置く」なのに、操作の形が揃っていない。

- 出発地: 地図の赤ピンを**ドラッグ**でしか動かせず、画面に手掛かりが無い。戻す操作は
  別の「現在地に移動」ボタンが兼ねている。
- 目的地: ボタンで武装してから地図をタップ。
- 経由地: **武装なしの素のタップ**で増える。パネルには件数と全消しの✕だけ。

## 対応方針（案A、モックで合意）

「条件」タブの目的地モードに、3つの地点を**同じ形の行**で並べる。行頭には地図のピンと
同じ色の印を置き、行とピンを見た目で結ぶ。

- 行の操作で武装し、武装した行だけを強調する。出発地の行にも操作が出るため、動かせること
  自体が画面に現れる（置いたあとは「現在地に戻す」へ変わる）。
- **ピンを置けるのは行を選んでいる間だけ**にする（[T781](T781.md)と同じ理屈で、地図を
  触っただけで経由地が増える事故が無くなる）。経由地だけは連続して置けるようにする。
- 地名での検索（[T631](T631.md)）は別タスク。行の値表示をそのまま使える形にしておく。

## 実装メモ

- 役割ごとの武装フラグを持たず、`PinRole`（"origin"|"waypoint"|"destination"）1つで表す。
  `MapView`は`armedPinRole`と`onPinPlace`の2つだけを受け取る（`destinationArmed`・
  `pinPlacementEnabled`・`onWaypointAdd`・`onDestinationSet`は撤去）。
- 置ける場所の条件は`pinPlacementArmedRole`へ集約した（目的地モード＋「ルート設定」を見て
  いる＋「条件」タブ）。[T781](T781.md)のゲートをタブ単位まで広げた形。
- 「条件」タブの中身は周回/目的地で高さが大きく変わるため、下部シートの`fitKey`へモードも
  含めた（[T785](T785.md)の仕組み。切り替えた先の行が隠れたままにならない）。

## 検証

Playwright（dev実機・390px）:

  武装（未指定のまま入ったときの自動武装）
- 出発地の行で「地図で選ぶ」→地図タップ → 行が「地図で指定」＋「現在地に戻す」へ
- 経由地は「追加」のまま2回タップで「2地点」（置くたびに押し直さない）
- **武装していない状態で地図をタップしても増えない**（2地点のまま）
- 「現在地に戻す」で出発地の行が「現在地」へ戻る（位置情報を許可した文脈で確認）

## 追補（2026-09-13、同日のフィードバック）

「候補数は周回でも目的地でも共通」「目的地モードの高さをもう少し抑えたい」を受けて:

- 候補数ステッパーをモード切替と同じ行へ移した（モードごとの中身の下にあると、モードに
  属する条件に見えるうえ1行ぶん縦を使う）。
- 地点の行は行全体を1つの押下領域にし、右端の文言（地図で選ぶ／追加／やめる）は押下領域の
  中の表示にした。ボタンの枠が3つ消え、行の高さも縮む。

実測（Playwright、390px、「条件」タブ本文の高さ）:

| | 変更前 | 変更後 |
|---|---|---|
| 目的地モード | 185px | 130px（行36px→28〜30px） |
| 周回モード | 110px | 80px |

候補数の位置はモード行と同じ高さ（top 652 / モード 649、left 235＝行の右側）。

値（現在地／なし／地図をタップ）の開始位置は3行で揃える（実測 left=104で一致）。役割名に
固定幅を与え、`button`の既定である中央寄せを打ち消している——値がばらばらの位置から始まると
行を縦に読み比べられない。
