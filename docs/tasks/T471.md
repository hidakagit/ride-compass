# T471. ゼロベース網羅レビュー§9(frontend components、Map除く)の残指摘7件対応

状態: 完了（2026-08-31）

- 背景: [T426](T426.md)棚卸し結果の§9（frontend/src/components/、Map除く）、有効7件。
  元は[zero-base-review-2026-08-30.md](../zero-base-review-2026-08-30.md)の§9。
- 対象7件（severity・file:line・要旨。P0[AxisComposerクラッシュ]/P1の2件[折れ点昇順・
  循環参照]は別タスクT424/T425で対応済みのため対象外）:
  1. `SystemStatusPanel.tsx`(L43-58) P2: `loading`状態が`getFrontendVersion()`の
     `.finally()`にしか紐付いていない。
  2. `RouteForm.tsx`(L36、`MAX_DISTANCE_KM = 100`) P2: backendのPydantic制約の
     手書きコピー、OpenAPI生成物から未導出（設計原則1違反）。
  3. `MapOverlayControls.tsx: renderLegendSwatch`(L235-252) P2: `WidthSwatch.tsx`と
     同じスウォッチを独立再実装、縮尺が食い違う。
  4. `MapOverlayControls.tsx`の`usePagedOverflow`内`registerViewport`/
     `registerTrack`(L302-361) P2: refコールバックが毎レンダー新規生成され
     Observerが破棄・再構築される。
  5. `RouteSettingsPanel.tsx`(L102-104、`lastWeights`) P2: 初回マウント時の
     `catalog.defaultWeights`で固定され非同期取得後の値と再同期されない。
  6. `WindBearingSlider.tsx`(L59) P3: `onChange`で`Number(next)`の結果がNaNに
     なりうる経路のガードが無い。
  7. `MapOverlayControls.tsx`全体(1-1491行) P3: 汎用フック・共通コンポーネント・
     複数グループ描画ロジックが単一ファイルへ集約（altitude/simplification指摘）。
- 対応方針・実装メモ:
  1. `SystemStatusPanel.tsx`: `loading`解除を`getFrontendVersion()`側の`.finally()`のみに
     頼っていたのを`Promise.all([backendFetch, frontendFetch]).then(() => setLoading(false))`
     へ変更し、両方の完了を待つようにした。回帰テスト追加（backendが遅延している間
     「更新中…」表示が維持されることを確認）。
  2. `RouteForm.tsx`の`MAX_DISTANCE_KM = 100`ハードコード（page.tsxにも独立した同値の
     重複があった）を解消。backend`api/routers/routes.py`に`MAX_ROUTE_DISTANCE_KM`定数を
     新設し`RouteGenerateRequest.distance_km`のField制約から参照、`export_openapi.py`が
     新規生成物`route-generate-config.json`（`{"max_distance_km": 100}`）として書き出す
     ようにした。フロント側2ファイルはこの生成物からimportする形へ変更（他の生成物
     [wind-grid-config.json等]と同じ「片側import」パターン）。
  3. `MapOverlayControls.tsx: renderLegendSwatch`が`WidthSwatch.tsx`（MapLayersPanel）と
     ほぼ同じ太さバー描画を独立実装しており、拡大率（`DISPLAY_SCALE=1.8`）が
     適用されずentry.widthが同じでも2箇所で見た目の太さが食い違っていた実害のあるバグ
     だった。`WidthSwatch`をそのままimportして使う形へ置き換え、重複実装と縮尺の食い違いを
     解消。使われなくなったCSS（`.detailSwatchBar`/`.detailSwatchBarDashed`）も削除。
  4. `usePagedOverflow`内の`registerViewport`/`registerTrack`（refコールバック）が
     `useCallback`で安定化されておらず、無関係な再レンダーのたびに新しい関数参照が
     渡ってReactがref変更とみなしdetach/reattach（`ResizeObserver`の破棄・再構築）を
     繰り返していた。`measure`/`rewireObserver`/`registerViewport`/`registerTrack`の
     チェーン全体を`useCallback`化して参照を安定させた。
  5. `RouteSettingsPanel.tsx`の`lastWeights`が、マウント時点の`catalog.defaultWeights`
     （フェッチ完了前は静的フォールバック値）のスナップショットで固定され、フェッチ完了後に
     `catalog.defaultWeights`が実際の値へ更新されても追従しなかった（一度チェックを外して
     戻すと古いフォールバック値へ復元される）バグを修正。`catalog.defaultWeights`が
     変わるたびに、「前回の既定値のまま変更されていない」軸だけを新しい既定値へ追従させる
     （ユーザーが`handleWeightChange`で実際に変更した値は保持する）。回帰テスト追加。
  6. `WindBearingSlider.tsx`: `@fseehawer/react-circular-slider`のonChangeがnumber以外を
     渡した場合`Number(next)`がNaNになりうる経路にガードが無かったのを修正。変換に
     失敗した場合は`onChange`を呼ばずフェイルソフトにする。回帰テスト2件追加
     （数値は伝播・NaNになる値は伝播しない）。
  7. `MapOverlayControls.tsx`全体（1491行、汎用フック・共通コンポーネント・複数グループ
     描画ロジックの単一ファイル集約）は対応不要と判断。P3の単発ファイルサイズ指摘であり、
     CLAUDE.mdの「規模ウォッチ」原則（単発の指摘だけでは能動的な閾値対応をしない、
     周期レビューで繰り返し検出されてから判断する）に従い、今回の分割はスコープ外とした。
     大規模な分割はそれ自体が回帰リスクを伴うため、周期的な複雑度レビュー
     （`/review:*`）側の判断へ委ねる。
