# T799. 評価基準の較正（物理を写した軸の重み・主観のレート・路面）

規模M。
状態: 未着手（2026-09-13起票。[T790](T790.md)から切り出し）

## 背景

T790で探索のコストを「所要時間 × (1 + P × difficulty/100)」＝体感の所要時間にした。
風・勾配・停止は走行モデル（物理）へ入り、軸には「遅くなる以上に避けたい」という主観だけが
残る設計になった。**構造は入ったが、値がその設計に合っていない。**

## 直すべきこと

### 1. 物理を写した軸の既定重みが走行モデルと二重に効く

本番スナップショットの既定重みは風0.26・停止密度0.20・勾配0.15・舗装0.19で、**配分の8割が
走行モデルと同じ現象を見ている**。設計上は「実際に遅くなる（走行モデル）」と「遅くなる以上に
避けたい（軸）」の別物だが、既定値が0でない限り利用者は一度の意図で二重に払う。

停止密度はずれの大きさも分かっている。[T787](T787.md)が測った現行の実効値は停止1回＝
200〜400m相当の迂回で、走行モデル側の信号21秒は20km/h巡航で約117m相当——**軸側が1.7〜3.4倍**。

既定重みの変更は`axis_definitions`のDB行データ操作（軸スタジオAPI＋本番反映）のため、
コードの変更とは切り離してある。

### 2. 主観と時間の換算レート（`penalty_strength`）の既定値

P=1は「difficulty 100の道は体感で所要時間2倍」の意味になった。距離ベースだった頃の1.0を
そのまま引き継いでいるだけで、時間ベースでの妥当性は確かめていない。
フロントは`penaltyStrength: 1.0`をベタ書きで送っている。

### 3. 路面が走行モデルへ繋がっていない

`domain/cycling_speed.py: speed_ms`は`crr`（転がり抵抗）を区間ごとに受け取れるが、呼び出し側が
渡していない。未舗装で実際に遅くなることが所要時間に出ない。繋ぐには路面区分ごとのCrrを
決める必要があり、値決めと一体のためここで判断する。

### 4. 停止密度の軸を残すか

待ち時間は走行モデルへ移った。軸として残すなら「待ち時間以上に止まりたくない」の意味になる。
残す・廃止するをここで決める。

## 進め方

値は実際に生成された候補を見て決める（主観のため実測はできない）。実走での確認も要る。
DB行データの変更は[docs/deployment-sync.md](../deployment-sync.md)の完了条件に従う。
