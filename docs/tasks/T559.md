# T559: 風の矢印（動的気象レイヤーwindVector）の縁取り層が1つも配置されない問題の修正

状態: 完了（2026-09-03起票・同日完了。[T558](T558.md)の残作業確認で発覚）

## 背景

`MapView.tsx: ensureDynamicWeatherLayer`のgridMark（風の矢印）は、濃色の縁取り層
（`region-dynamic-weather-windVector-arrow-mark-halo`）と主層（`...-main`）の2層重ねで、
両層とも`icon-allow-overlap: false`・`icon-ignore-placement: false`。MapLibreはレイヤーの
上から順にシンボルを配置するため、先に置かれた主層（上）と同位置・大きめの縁取り層（下）が
「衝突」として全て落とされる。Playwright診断（dev、東京駅付近ズーム13、風チップON）で
主層63件配置・縁取り層0件を確認した。T558（周回ルートの進行方向矢印）と同じ構造の潜在バグ。

## 対応方針（案）

- T558と同様に縁取り層の衝突判定を無効化する（`icon-allow-overlap`/`icon-ignore-placement:
  true`）か、SDFアイコンの`icon-halo-color`/`icon-halo-width`（paintプロパティ）で1層に
  まとめる。風の矢印は格子点ごとの点シンボルで主層側の衝突間引き（密なズームで矢印を
  減らす）が意図的な可能性があるため、主層の設定は変えず縁取り層だけを主層に追従させる
  形（主層が配置された地点にだけ縁取りが出る）が望ましい——`icon-halo-*`方式なら自然に
  そうなる。
- 影響範囲: `DYNAMIC_WEATHER_RENDERERS`のgridMark全般（現状はwindVectorのみ）。
  `docs/modules/frontend/dynamic-weather-layers.md`（該当設計書）の記述追従。

## 保留した場合の影響

風の矢印は縁取り無しの単層として表示され続ける（機能は動く。basemapの濃色部と重なる
地点で矢印が読みにくいだけ）。

## 実装（2026-09-03）

対応方針（案）どおり、縁取り層を独立レイヤーとして別立てするのではなく、主層自身の
`icon-halo-color`/`icon-halo-width`（SDFアイコンのpaintプロパティ）へ置き換えた
（`frontend/src/components/Map/MapView.tsx`）。

- `DynamicWeatherMarkSpec`の`haloScaleMultiplier: number`を`haloColor: string`・
  `haloWidth: number`へ置き換え、windVectorの`arrow`スペックを追従させた
  （`WIND_ICON_HALO_COLOR`＝旧ハロー層と同じ配色`rgba(31, 41, 55, 0.85)`、
  `WIND_ICON_HALO_WIDTH_PX`＝1.5px）。
- `ensureDynamicWeatherLayer`のgridMark分岐から、縁取り専用の`map.addLayer`呼び出しを
  削除し、主層のpaintへ`icon-halo-color`/`icon-halo-width`を追加。`dynamicWeatherIds`の
  戻り値から不要になった`haloLayerId`を削除し、`applyDynamicWeatherState`側の
  可視性切り替えも主層1つだけに整理した。
- 主層自身の`icon-allow-overlap: false`/`icon-ignore-placement: false`は変更していない
  （密なズームでの格子点間引きという既存の意図的な挙動を保つ）。1層にまとめたことで、
  縁取りは常に主層と同じ判定・同じ地点に追従する。
- `ensureRouteArrowLayer`（T293/T558のルート矢印、2層重ね自体は維持）内の、風の矢印を
  「同じ既存パターン」と紹介していたコメントが本タスクの変更で不正確になったため、
  現在の構造を指す説明へ更新した。
- `docs/modules/frontend/dynamic-weather-layers.md`「表示層の実装」節へ、gridMarkの
  縁取りが1層（icon-halo-*）で表現される旨を追記。

  `queryRenderedFeatures`件数確認）を行うのが望ましいフォローアップ。
