# T735. 契約不一致の一括是正（docstring・型・docsが述べる前提の不成立） 規模M

状態: 保留（2026-09-12。名前が挙がっていた4件は是正済み。残りの対象が復元できず[T752](T752.md)待ち。起票は2026-09-11、統合レビュー第7回 P2束ね）

## 背景

対象9件。`strict_model.py`の適用範囲宣言（DBのJSONB・Redis永続データが例外）、`hard_filters.py`の「2箇所だけ」、`axis_templates.py`が存在しない関数を共有相手と名指し、Draft保持の契約ほか。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 是正した4件（2026-09-12）

| 箇所 | 述べていた前提 | 実際 |
|---|---|---|
| `strict_model.py` | 提供側のペイロードがそのままモデルへ流れ込む経路は無い | 外部APIについては正しいが、**自前で書いた過去のデータは流れ込む**（`shape_params`のJSONB・軸定義スナップショット）。`forbid`でフィールドを消すと既存の行が読めず起動に失敗する（[T396](T396.md)で本番障害の実績）。意図した挙動である旨と、本番DBの移行を先に済ませる必要を明記した |
| `hard_filters.py` | フィルタを増やすときに書き換えるのはこの2箇所だけ | highway種別のフィルタにしか当てはまらない。タグ由来は`is_edge_allowed`へ判定を1本書く必要がある（`no_bicycle`が唯一の実例）。種類ごとに書き分けた |
| `axis_templates.py` | `domain/night.py`の各`*_difficulty`関数と実装を共有する | その関数群は存在しない（`night.py`は`night_materials`のみ）。実在する共有の形（スカラー経路`evaluate_axis_scalar`とベクトル化経路`evaluate_axis_array`）へ書き換えた |
| `curveDistributionOverlay.ts` | 範囲内の棒と範囲外の割合は同じ範囲定義に従う | `visibleBars`だけが`xMax <= xMin`で早期returnし、`offRangeShare`が分岐していなかった。`overlap(-∞, xMin)`と`overlap(xMax, ∞)`が同じ区間を二重に数え、合計が1を超える |

## 機械的な裏取り

ソース内のコメント・docstringがバッククォートで名指しする識別子を全件走査し、
実在しないものが**0件**であることを確認した。`axis_templates.py`の`*_difficulty`は
ワイルドカード表記のためこの走査では拾えない（個別に確認して直した）。
