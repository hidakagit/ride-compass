- `docs/modules/README.md`のbackend8・frontend7の全15モジュールを単位に、1モジュールずつ
  片付ける。T425/T426→T463〜T471のような子タスク（個別Txxx）は起票しない——各モジュールの
  作業内容はコメントの要否判定という同一パターンの繰り返しで、実際の規模もモジュールごとに
  大きくばらつく（今回のelevation.mdは対象3ファイルのみで小規模）ため、進捗はこのファイルの

## 実施メモ（標高モジュール、2026-09-05）

- 対象ファイルは`elevation_client.py`・`elevation_attribute_service.py`・
  `precompute_elevation_attributes.py`の3件（`attributes.py`のElevationAttribute・
  compute_elevation_attribute部分にはNARRATIVE_PATTERNの一致は無かった。同ファイル内の
  他の経緯コメントはEdgeAttributeCounts/EdgeMaterialTable等[別モジュール管轄]のもの）。
- 設計書と重複＝削除: `elevation_client.py`のDEMタイル方式・キャッシュ2段・LRU上限の説明、
  `ElevationAttributeService`の同時実行制御・repository前提の説明等、`docs/modules/backend/
  elevation.md`に既に現在形で書かれている内容は削除した。
- 非自明な現在の理由＝現在形で残す: `_CoverageGap`（一時的通信エラーと404の区別が無いと
  一時障害まで恒久キャッシュされるバグになる）、GSI失敗Edgeの非永続化（再試行を続けさせる
  ため）等は経緯の言い回しだけ落として残した。
- 昇格: `elevation_client.py`のタイル仕様コメントに埋もれていた非自明な事実
  （`dem`は`dem5a/b/c`のGSI側自動フォールバック統合種別ではなく別の粗いデータセットである
  こと、非対応エリアは明示的に404を返すこと、全種別をz=14固定で扱う理由）が
  `docs/modules/backend/elevation.md`に書かれていなかったため、同ドキュメントへ現在の事実
  として追記してから削除した。
- 実害の発見: `elevation_client.py`のLRU上限コメントが「`precompute_elevation_attributes.py`
  はEdgeを地理的に並べ替えず処理する」と書いていたが、実際は`_fetch_all_edge_ids`が
  `ORDER BY geom`で地理的順序を返す実装に変わっており（`docs/modules/backend/elevation.md`
  の記載と一致）、コメントだけが古いまま食い違っていた。経緯コメントが実態に追従されず
  陳腐化する典型例のため、正しい記述に置き換えて削除した。
- 検証: `pytest tests/test_elevation_attribute_service.py tests/test_elevation_client_cache.py
  tests/test_precompute_elevation_attributes.py -q`と`pytest -q -m "not postgis"`（1521件）
  green。コメントのみの変更のため挙動に影響なし。
