# T939. レンズ凡例の段階が、ルート前後で別系統のキー・別の表記で作られている 規模M

状態: 未着手（2026-09-19起票、統合レビュー第11回）

## 背景

同じ軸の同じ段階が、ルート生成の前と後で別の実装から作られている。非表示キーの保存先は共有のため、
ルート前に隠した段が生成後に黙って復活し、「一部非表示」の表示だけが残る。
最上位帯の語も`以上`と`超`で食い違い、`超`の側は述語（`>=`）と逆である。

詳細は[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)。

## 対応方針

「ルート前の全道路の塗り」と「ルート後のレンズ」を1つの凡例概念として扱いながら、
それを組み立てるコードが統合されていないことが根本。

1. **段階キーと帯ラベルの生成を1箇所へ寄せる**: `mapColorLegend`へ寄せ、`routeStyleModes`と
   `axisLayers`がそれを呼ぶ形にする。現在は2系統のキーが`hiddenLegendKeysByMode`という
   同じ1配列を共有している。
2. **最上位帯の語**を述語に合わせて統一する。`routeStyleModes.ts`だけが「超」で、ちょうど境界値の
   区間が「超」と書かれた行で数えられている。
3. 段階レンジ文字列を作る関数は現在3実装ある。`mapColorLegend`のコメントは「同じ表記規則を
   共有する」と書くが、共有しているのは文章だけ。
4. `docs/modules/frontend/map-axis-coloring.md`と`static-map-layers.md`の該当記述も同時に直す
   （前者は同一文書内で矛盾し、後者は非表示キーの書き手に`LensControl`を挙げていない）。

## 完了条件

- **全公開軸について「ルート前の凡例キー集合とルート後の凡例キー集合が一致する」テスト**を置く。
  母集団は軸カタログから導出する（手で列挙しない）
- `routeStyleModes.test.ts`の「ルート前と同じ表記になる」テストが、先頭帯だけでなく全帯を比べる
