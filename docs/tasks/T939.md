# T939. レンズ凡例の段階が、ルート前後で別系統のキー・別の表記で作られている 規模M

状態: 完了（2026-09-19起票・完了、統合レビュー第11回）

## 背景

同じ軸の同じ段階が、ルート生成の前と後で別の実装から作られている。非表示キーの保存先は共有のため、
ルート前に隠した段が生成後に黙って復活し、「一部非表示」の表示だけが残る。
最上位帯の語も`以上`と`超`で食い違い、`超`の側は述語（`>=`）と逆である。

詳細は[history/2026-09-19_all.md](../../.claude/commands/review/history/2026-09-19_all.md)。

## 対応方針

「ルート前の全道路の塗り」と「ルート後のレンズ」を1つの凡例概念として扱いながら、
それを組み立てるコードが統合されていないことが根本。

1. **段階キーと帯ラベルの生成を1箇所へ寄せる**: `mapColorLegend`へ寄せ、`routeStyleModes`と
   `axisLayers`がそれを呼ぶ形にする。現在は2系統のキーが`hiddenLegendKeysByMode`という
   同じ1配列を共有している。
2. **最上位帯の語**を述語に合わせて統一する。`routeStyleModes.ts`だけが「超」で、ちょうど境界値の
   区間が「超」と書かれた行で数えられている。
3. 段階レンジ文字列を作る関数は現在3実装ある。`mapColorLegend`のコメントは「同じ表記規則を
   共有する」と書くが、共有しているのは文章だけ。
4. `docs/modules/frontend/map-axis-coloring.md`と`static-map-layers.md`の該当記述も同時に直す
   （前者は同一文書内で矛盾し、後者は非表示キーの書き手に`LensControl`を挙げていない）。

## 実装メモ

### 起票時の見立ては、実測で覆った

起票時は「キーと表記」の問題として切り出し、段の値はT921側だと書いていた。着手して測ると
**ルート前後は別の量を別の段数で塗っており**、キーだけ揃えると「16段の生値の2番目」が
「3段の難易度の2番目」に結び付く——隠したのに戻るより悪い、別の段を隠す不具合になる。

| 軸 | 着手前: 前の段数 | 着手前: 後の段数 |
|---|---|---|
| surface_q / car_stress / accident | 2 | 3（既定値へ転落） |
| night | 3 | 3（偶然一致、意味は別） |
| bicycle_infra_quality | 16 | 3 |
| axis_abdaded0be20 | 5 | 5 |

揃える仕組み自体は既にあった。`map_value_thresholds`はルート前の境界を**軸の折れ線で難易度へ
写して**返す（docstringが理由も書いている）。ただし**人が`display_thresholds_override`を
設定した軸でしか動かず**、自動導出のしきい値しか無い軸はNoneを返して読む側の既定値
（`[33, 66]`）へ転落していた。これが前後不一致の正体である。

### 段を決める場所を1つにした

`domain/axis_display.py: ramp_band_thresholds`を置き、ルート前の段の境界はここだけが決める。
ルート線側（`map_value_thresholds`）はその値を折れ線で写すだけになり、**段数が一致することが
構造から出る**（写像後に重複を畳むので、畳む前も畳んでおく必要がある——それも同じ関数の中）。

あわせて、**折れ線が同じ難易度へ写す境界は段として作らない**ようにした。評価が区別できない
差に色の境界を引くと、色だけが変わって評価は同じという見分けを地図が見せることになり、
しかもルート線側にはその段が作れない。この畳み込みは人の上書きにも効くため、画面が何も
伝えない点を[T957](T957.md)として分離した。

結果、**公開軸すべてで前後の段数が一致**した（`bicycle_infra_quality`は16→6へ畳まれ、
ルート後も6）。本番の`axis_abdaded0be20`は上書きの4値が折れ線の別々のスコアへ写るため
表示は変わらない。

### フロント側

- ramp軸の段のキーを`legendBandKey`（`step-N`）・受け皿を`LEGEND_NO_DATA_KEY`へ揃えた。
  軸idを綴りへ混ぜない——保存先は前後で同じ`hiddenLegendKeysByMode[軸id]`のため。
- 段のレンジ文字列の3実装を`mapColorLegend.ts: rangeStepLabel`へ寄せ、最上位帯を述語
  （`>=`）に合わせて「以上」へ統一した（`routeStyleModes.ts`だけが「超」で、ちょうど境界値の
  区間がその行で数えられていた）。
- 「一部非表示」が、いまの凡例に実在しないキーだけでも出ていたのを直した
  （`legendFilter.ts: hasVisibleHiddenKeys`）。旧い綴りで保存した利用者はこれに当たる。
