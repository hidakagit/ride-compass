# T346. 軸スタジオ: ウィザード最終ステップの暗黙送信バグ修正・軸同士の線形結合(nX+mY)テンプレート修正 規模M（2026-08-26完了）

状態: 完了


- 背景: ユーザーからの実機フィードバック3点。
  1. 既定重み(default_weight)は軸単位で決めるものではない気がする。将来的にプロファイル
     （軸の組み合わせの最適化）機能が来たらそちらで決められるようにしたい。
  2. 本番環境で、既存軸（勾配）を複製・編集し、内容を変えずに「次へ」を押して進めていくと
     ウィザードの4/4画面で勝手に閉じる。
  3. 「他の軸の計算結果をもとに点数を変える」という結合方法が歪に感じる。軸同士を結合する
     時は、単純にnX+mYのn,mを決められるようにするのが設計原則に近いのでは。
- 1（既定重み）は「対応不要」の回答をユーザーから得た（現状のまま）。2・3を本タスクで対応。
- **2. ウィザード4/4での暗黙送信バグ**:
  - 原因: `AxisComposer.tsx`の「次へ」(type="button")↔保存ボタン(type="submit")は
    JSXの同じ位置にある三項演算子の分岐で、明示的な`key`が無かったためReactが同じ
    `<button>`のDOM要素を使い回し、type属性だけをその場で書き換えていた。「次へ」を
    クリックしてshape_paramsからdisplay_publishへ遷移すると、クリックを受けたその
    `<button>`自身のtype属性が"button"→"submit"へ同期的に書き換わり、ブラウザ側の
    クリックのデフォルト動作判定（type="submit"ならフォーム送信）がこの書き換え後の
    typeを見てしまい、「次へ」を押しただけで未変更のドラフトのままフォームが暗黙に
    送信されていた（保存自体は成功するため、ユーザーの目には「4/4画面に着くと
    勝手に閉じる」ように見える）。
  - 再現確認: ローカルにPostGIS込みのPostgreSQL・backend・frontendを一式立ち上げ
    （本番同様、docker非搭載環境のためapt-get install postgresql-16-postgis-3で追加）、
    Playwrightで「勾配」軸を複製→「次へ」を3回押すだけの操作で実際に
    `POST /admin/api/axis-definitions`が暗黙発火することを確認した（material排他
    制約の409で顕在化。競合しない内容なら成功しモーダルが閉じる）。
  - 修正: 2つの`<button>`へ`key="next"`/`key="submit"`を明示し、Reactに「別の要素」と
    認識させて必ずunmount→mountさせる（type属性がクリック後に書き変わる余地を無くす）。
    修正後は同じPlaywright操作でPOSTが発火しないことを確認済み。
  - 検証: 単体テスト（jsdom）ではブラウザ側のクリックのデフォルト動作判定タイミングの
    差が再現できないため、この不具合を直接再現する形の回帰テストは書けない。代わりに
    React側の対策（key指定による強制的な要素の作り直し）が効いているかを、「次へ」
    クリック後に取得した保存ボタンのDOM要素参照が、直前の「次へ」ボタンの参照と
    別物になっているかで検証する回帰テストを追加した（修正前のコードに戻すと実際に
    失敗することを確認済み）。
- **3. 軸同士の線形結合(nX+mY)テンプレート修正**:
  - 調査の結果、「他の軸の計算結果をもとに点数を変える」(`recipe_then_breakpoint_linear`)
    テンプレートは、backend側は元々`MaterialTerm.material`へ他の軸のaxis_idを指定
    できる設計（`domain/axis_definitions.py: AxisDefinition`docstring「軸の階層」、
    改善計画T292）だったにもかかわらず、`AxisComposer.tsx`の材料(terms)セレクトが
    `MATERIAL_CATALOG`の材料しか候補に出しておらず、実際には他の軸を選ぶ手段自体が
    GUI上に存在しなかった（説明文と矛盾する実装漏れ）。ユーザーが「歪」と感じたのは
    この実装漏れが原因だったと判断した。
  - 修正: このテンプレート選択時のみ、材料セレクトの候補を`MATERIAL_CATALOG`ではなく
    他の軸一覧（`otherAxes`、編集中の軸自身は自己参照になるため除外）へ切り替えた。
    複数の軸に係数(n, m…)を設定して重み付き線形和を取る（terms×weightの合計→
    breakpointsで最終調整）という既存のBreakpointLinearShapeの計算はそのまま
    （4テンプレート限定というADRの方針を維持、新しいshape kindは追加しない）。
    このテンプレートを新規選択した際の既定折れ点は、以前の`[[0,0],[10,100]]`
    （生の材料向け）ではなく`[[0,0],[100,100]]`（軸のスコアは常に0〜100のため）に
    変更した。材料/軸セレクトの候補一覧が入れ替わるテンプレート切り替え時は、
    保存不能な組み合わせを持ち越さないようtermsを候補の先頭で作り直す。
  - 文言見直し: カード見出しを「他の軸の計算結果をもとに点数を変える」から
    「他の軸を重みで足し合わせて点数を変える（nX + mYのように）」へ変更し、
    説明文にも「勾配の軸を2倍重視、風の軸を1倍」という具体例を追加した。
  - 組み合わせられる他の軸がまだ無い場合（最初の1軸を作る時等）は、その旨のヒントを
    表示し「+ 軸を追加」ボタンを無効化する。
  - 1（既定重みのプロファイル化）は対応不要のためスコープ外のまま。
- 検証: Playwrightでローカル実機確認（勾配×2・風×1の重み付き線形結合を実際に作成し
  `POST`が`{"material": "gradient", "weight": 2.0}`/`{"material": "wind", "weight": 1.0}`
  のterms・`breakpoints: [[0,0],[100,100]]`で送信され201が返ることを確認）。
  frontend: `AxisComposer.test.tsx`に軸同士のnX+mY結合・組み合わせ候補0件時のヒント・
  ステップ遷移の回帰テスト（上記2件）を追加、既存の「他の軸の計算結果を〜」文言に
  依存していたテストを新文言・新候補（他の軸）へ更新。全680件・lint・tsc green。
- フォローアップ（同日、実機のスマートフォン画面でユーザーが発見）: 材料/軸セレクトが
  画面外へはみ出す不具合。T345・T346で材料名・軸名のラベルへ物理名(id)を併記する
  ようになり選択肢テキストが伸びたことで顕在化した。原因は`.field`/`.termRow select`が
  横方向flexコンテナ内のflexアイテムで、既定の`min-width:auto`（中身の最小コンテンツ幅、
  ここでは最長の選択肢テキスト幅）が既存の`max-width:100%`（改善計画T301）より優先され、
  縮まずに画面外へあふれていたこと。`min-width:0`を追加してこの既定値を上書きし解消した
  （`AxisStudio.module.css`）。Playwrightでモバイル相当の狭い画面幅(412px)にて実機確認し、
  水平スクロールが発生しないことを確認済み。
