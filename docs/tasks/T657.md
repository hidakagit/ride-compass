# T657. backendの列挙・既定値をexport_openapiの生成物へ集約する

規模M。状態: 完了（2026-09-08）。

## 背景

`export_openapi.py`が生成物を書き出しfrontendが片側importする経路は既に確立していた
（`surface-tags.json`・`axis-catalog.json`・`region-tile-config.json`等）。しかし
backendが持つ値の一覧・既定値のうち**5系統がこの経路に載らず、frontendが手書きで複製**
していた。統合レビュー第5回（G3）で検出。

厄介なのは**どれも「テストがある」ように見えたこと**である。たとえばPOI種別のテストは
「backendと一致する」という名前だが、中身はテストファイル側にも同じ値をベタ書きして
比較しているだけで、backendを一切参照していなかった。片側だけ変えても全部緑のまま通る。

| 系統 | 壊れ方 |
|---|---|
| `DEFAULT_HARD_FILTERS`（3キー） | backendが`_check_filter_keys`でキー集合の**完全一致**を要求するため、4つ目を足した瞬間に**すべてのルート生成が422** |
| `StopPoiKind`/`SupplyPoiKind` | 6種目を足すとbaseFilterに弾かれて**地図から完全に消える**（凡例にも出ないため「データが無い」としか見えない） |
| `ROAD_TILE_MIN/MAX_ZOOM` | z16へ拡張しても路面レイヤーが出ない |
| 材料カタログ | **既に1件欠落していた**（`shared_pedestrian_path`）。APIが落ちているときだけ古い選択肢が出るため気づく機会が無い |
| smoothnessの値ラベル | **既に食い違っていた**（「かなり悪い」vs「非常に悪い」、`very_horrible`と`horrible`がフロントでは同じ「劣悪」に潰れる） |

## 実施内容（2026-09-08）

### 生成物側

既存の生成物へ載せられるものは載せ、載せる場所が無い2系統だけ新設した。

| 生成物 | 追加した内容 |
|---|---|
| `route-generate-config.json` | `hard_filters.keys` / `hard_filters.defaults` |
| `region-tile-config.json` | `road_tile_min_zoom` / `road_tile_max_zoom` |
| `poi-kinds.json`（新設） | `stop` / `supply` のkind正準集合 |
| `material-catalog.json`（新設） | 公開材料の id・label・description・dtype・unit・value_labels |

### frontend側

- `RouteSettingsPanel.tsx`: `HARD_FILTER_CHIPS`・`DEFAULT_HARD_FILTERS`を生成物から導出。
  **表示ラベルはUIの語彙なのでfrontendが持つ**——backendが持つのはキーと既定値だけ。
- `regionApi.ts`: ズーム範囲に加えて**タイル世代3種も**生成物から受け取る形にした（下記参照）。
- `axisMaterialsCatalog.ts`: 手書き約200行の配列を生成物からの`map`へ置換（254行→70行）。
  欠落していた材料も自動的に解消した。
- `MapView.tsx`: `SMOOTHNESS_LABELS`を生成物の`value_labels`から引く形へ。
- `staticAttributeLayers.test.ts`: 期待値のベタ書きをやめ、生成物と照合する形へ。
  `STOP_POI_KINDS`/`SUPPLY_POI_KINDS`のbaseFilter用キー集合の照合も追加した。
- `regionApi.test.ts`: ズーム範囲・タイル世代の期待値を生成物参照へ。

### 途中で見つけた実バグ（master上で既にテストが1件落ちていた）

並行セッションの[T655](T655.md)（`97b9388c`）がbackendの`ROAD_SURFACE_TILE_VERSION`を
19へ上げ生成物も更新したが、**`regionApi.ts`のハードコード「18」を更新していなかった**。
`regionApi.test.ts`の照合テストが落ちた状態でmasterに入っていた。

これはまさに本タスクが直している型のため、タイル世代3種（road_surface / accident / poi）も
生成物由来へ変えて恒久的に潰した。手動同期の指示コメント（「対で更新すること」）も
現状（生成物経由で受け取る）へ書き換えた。
