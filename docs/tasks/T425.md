## 対応結果（2026-08-31、13件全部を1セッションでまとめて対応）

着手前に各項目のfile:lineを現状のコードで再確認したところ、9件（1・2・6・7・8・9・10・11、
番号は上の一覧）は依然有効なバグと確認できた一方、5件（3・4・5・12・13）はT418等の後続変更で
file:lineがドリフトしていたため、現物確認しながら対応した。

1. **elevation_client.py**: `_fetch_tile`が404（カバレッジ外、恒久的に正しい）と一時的な通信
   エラーを区別せず両方Noneを返し、`_get_tile_grid`がどちらも`_tile_grid_cache`へ恒久キャッシュ
   していた。`_CoverageGap`センチネルを導入し、通信エラー時は恒久キャッシュしないよう修正
   （回帰テスト`test_transient_communication_error_is_not_cached_permanently`追加）。
2. **Redis cache-aside 4モジュール**（road_edge_geometry_cache.py・road_graph_tile_cache.py・
   wind_forecast_cache.py・dynamic_way_value_cache.py[旧wind_way_penalty_cache.py、T423で
   汎用化・改名済み]）: 全12関数を`log_external_call`で囲むよう書き換え、`/api/debug/stats`へ
   統計が乗るようにした。
3. **MapView.tsx「変わらないデータを更新」**: `redrawAllLayers`が`WIND_AXIS_LAYER_ID`/
   `GRADIENT_AXIS_LAYER_ID`のsetFeatureState値（windAxisPenalties/gradientAxisValues）を
   再適用していなかった。`redrawPropsRef`へ両値を追加し、`redrawAllLayers`内で
   `applyAxisFeatureStateValues`を明示的に呼ぶよう修正。
4. **windPenaltyFillのクリック誤爆**: T432でwindPenaltyFillがDYNAMIC_WEATHER_RENDERERS汎用機構へ
   統合されたため、file:lineは陳腐化していたが問題自体は現行コードにも存在した
   （interactiveLayerIdsに含まれず、専用ポップアップも無いため、クリックが下のroad_surface
   タイルへ抜けていた）。DETAIL_LAYER_IDと同じ「ヒットしたら何もしない」早期returnガードを
   `WIND_PENALTY_FILL_LAYER_ID`へ追加。
5. **jmaNowcastFrames.ts**: `latestObservedFrameIndex`が実況フレーム0件時に末尾index（最も
   未来の1件だけ残す）を返す逆転したフォールバックだった。先頭(0、全件保持)へ修正
   （回帰テスト追加）。
6. **429処理の重複**: `app/api/dependencies.py`へ`enforce_rate_limit`を新設し、weather.py
   （7箇所）・basemap.py（2箇所）・jma_tile.py（1箇所）・routes.py（2箇所）の重複ブロックを
   置き換え。既存の`_tile_validation.py: check_tile_rate_limit`（region.py/accidents.py向け）も
   この汎用版へ統合し、`_tile_validation.py`からは座標検証のみ残した。
7. **axis_admin.py priority_overrides未検証**: `_check_materials_are_known`
   （`AxisDefinitionPayload`、書き込み専用）へ`priority_overrides[*].material`の未知材料/軸参照
   チェックを追加（回帰テスト追加）。
8. **jma_amedas_service.py refresh_all_stations**: 3箇所の早期return（stations空・
   latest_time None・observation_map None）全てへ`logger.warning`を追加（回帰テスト3件追加）。
9. **region_service.py高頻度WARNING**: `_get_tile`内の「PostGIS取込範囲外」WARNING2箇所を
   `log_throttled_warning`（毎分カテゴリごと5件で抑制）経由へ変更。なお同ファイル356/388/411
   行目の`fields["warned"]=True`後の独自WARNING（P3、別枠のT426対象）は、gradient_way_service.py・
   wind_way_service.py等リポジトリ全体で確立済みの既存パターンと一致しており、本タスクの
   スコープ（P1のみ）外と判断し変更していない。
10. **frontend `*Api.ts` 7ファイルのAPI_BASE_URL重複**: `backendInternalUrl.ts`と同型の
    `frontend/src/lib/apiBaseUrl.ts`を新設し、7ファイルとも単一importへ置き換え。
11. **useDynamicWeatherLayers.tsのキキクル/線状降水帯エラー未反映**: `currentRiskError`/
    `linearRainbandError`のstateを追加し、`dynamicLayerError`の合成式へ組み込んだ（回帰テスト
    ファイル`useDynamicWeatherLayers.test.ts`を新規作成）。
12. **AxisComposer.tsx breakpoints昇順未チェック**: backend側（`shape.breakpoints`、
    `evaluate_breakpoint_linear`のnp.interpが前提とする不変条件）・frontend側
    （`validateStep`、保存前の即時フィードバック）の両方へ昇順チェックを追加。
    display_thresholds_override側の既存チェック（T404）とは対象フィールドが別（表示用途 vs
    評価用途）で、これまで漏れていた（回帰テスト両方に追加）。
13. **AxisComposer.tsx循環参照未検出**: 調査の結果、**実装済みと判明・修正不要**。
    `backend/app/domain/axis_definitions.py: topological_axis_order`が深さ優先探索で多段の
    循環を検出し`AxisDependencyCycleError`を送出、`axis_admin.py`のcreate/update両方が
    これを捕捉し409+明確なチェーン文言（例:「circular axis dependency detected: A -> B -> C
    -> A」）で返している。フロント側`onSave`の`catch`は`err.message`（`formatErrorDetail`
    経由でdetailを保持）をそのまま表示するため、送信時に正しくユーザーへ伝わる。ゼロベース
    レビューの「保存前に検出しない」はクライアント側の早期（送信前）検出が無いだけを指して
    いたと考えられ、実害（多段循環参照の見逃し）は無い。

**検証**: backend `pytest -m "not postgis"`（1250件）・frontend `vitest run`（842件）・
`tsc --noEmit`・`eslint .`すべてgreen。item6の429共通化に伴い
`tests/test_client_ip_behind_proxy.py`が`_tile_validation`モジュールの`client_id`属性を
monkeypatchしていた箇所が壊れたため、`app.api.dependencies`側へ向け直して修正済み。
item3・4（MapView.tsxのクリック挙動・スタイル再読み込み後の再適用）はjsdomでのユニット
テストが技術的に難しい内部クロージャのため、ロジック追跡による修正のみで実機（Playwright等）
未検証。
