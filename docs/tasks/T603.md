# T603: JMAタイルプロキシが「疎な格子で珍しくない404」を他の失敗と同じ502/WARNINGにしていた不具合の是正

状態: 完了（2026-09-05起票・同日完了）

## 背景

T602の実機検証中、ユーザーから`/api/jma-tile/*`の502ログが大量に出ているという報告を受けた。
`ridecompass.external`ロガーの詳細（`error_type: http_404`）を確認したところ、原因は
気象庁側の障害やタイムアウトではなく、降水・浸水想定区域等の疎な格子状タイルで
特定のz/x/yに対応するデータが存在しない（珍しくない正常系）ことによる404だった。
`jma_tile_prewarm_service.py`には以前から同種の404を前提にしたコメント
（「絞り込まずに最新basetimeを採用すると...存在しないタイルを要求し続けて404になる」）が
あり、この404自体は既知の現象だったが、`jma_tile.py`は上流の失敗を種類を問わず一律502へ
変換していたため、本来ユーザー影響のある異常（タイムアウト・5xx等）と区別がつかず、
`/api/debug/stats`のerror集計・WARNINGログも不必要に埋まっていた。

## 対応内容

- `jma_tile_client.py`: `fetch()`が上流404を`JmaTileNotFoundError`として送出するようにし、
  `log_external_call`のresultは`"ok"`のまま記録する（`with`ブロックを例外無しで抜けさせ、
  ブロックの外で改めて`raise`する構成——ブロック内で例外を送出すると
  `log_external_call`側が無条件にエラー扱いしてしまうため）。`get()`
  （プリウォームバッチ等、404を区別する必要が無い呼び出し元向け）は
  `JmaTileNotFoundError`をNoneへ揃えて返す（従来通りの挙動を維持）。
- `jma_tile.py`: `JmaTileNotFoundError`を404、それ以外の失敗は従来通り502として返す。
- テスト: `test_jma_tile_client.py`（`fetch`が例外を送出すること・`get`がNoneへ揃えること・
  `/api/debug/stats`のerror集計に乗らないこと）・`test_jma_tile_routes.py`
  （ルーターが404を返すこと）。
- docs: `docs/modules/backend/weather-dynamic-layers.md`に「フェイルステータスの使い分け」を追記。

## 検証

- backend: `pytest`全件green（1750件、PostGIS込み）。
- 実機（本番）検証済み（2026-09-06）。本番backend（commit `3a9635f`）へ未知のz/x/yパスを
  リクエストし`404`が返ることを確認。`/api/debug/stats`の`weather:jma-tile`統計を
  リクエスト前後で比較し、`cache_misses`が増加（実際に上流フェッチが発生）したにもかかわらず
  `errors`が0のままであることを確認した（`ridecompass.access`のログレベル自体は
  未確認だが、`log_external_call`のエラー非算入という本修正の核心は確認済み）。
