# T545: ルート結果パネルの再設計（ルートごとのタブ化・説明文整理・切り替えUI統一）

状態: 完了（2026-09-02）

## 背景

ユーザーが本番サイト（モバイル実機）でルート結果を確認中、以下4点の改善要望を受けた:

1. ルート確認をもっとやりやすくしたい
2. ルートごとにタブを分けてほしい（ルートクリアするとタブが消える）
3. 冗長な説明文は消すか情報アイコンにする
4. 総合難易度と軸の切り替えを、ルート設定タブの軸チップ列と同じ見た目・操作性にする

現状は候補一覧（`RouteList.tsx`、縦積みボタン）→選択中候補の内訳（`RouteAxisProfile.tsx`）が
同じスクロール領域に縦に並ぶ構成で、候補を比較するには選択→スクロールして内訳確認→
また上へ戻って選び直す、という往復操作が必要だった。

## 対応方針（ユーザー承認済み）

- `RouteList`をRadix Tabsベースの候補ごとタブへ再構成（page.tsxの「ルート選択/比較」タブと
  同じパターン）。タブラベルは短縮表示（例:「南東 22.9km」）。「ルートをクリア」で
  `routes`が空になりタブごと消える。
- `RouteAxisProfile.tsx`の常時表示テキスト（おすすめ度/総合難易度の説明段落）を、
  `RouteList.tsx`の「おすすめ度について ⓘ」と同じ`FieldLabel`パターンへ変更。
- 総合難易度・各軸の選択チップを上部に1行の折り返しチップ列（ルート設定タブの
  `chipRow`と同じ見た目）としてまとめ、選んだ軸の棒グラフをその下へ表示する形へ変更。

## 実装（2026-09-02）

- `RouteList.tsx`: 縦積みボタン一覧をRadix Tabs（`Tabs.List`/`Tabs.Trigger`、
  `aria-label="ルート候補"`、`Tabs.Content`は使わない純粋な選択UI）へ再構成。タブ自体に
  「おすすめ度」・方向・距離を残し、切り替えずに候補間のおすすめ度を比較できるようにした
  （下のRouteAxisProfileは選択中1件だけの表示のため）。候補数が画面幅を超える場合は
  タブ列自身が横スクロールする。`RouteList.module.css`をタブ用スタイル（`.tabList`
  `overflow-x:auto`、`.tab[data-state="active"]`の選択枠）へ全面書き換え。
- `RouteAxisProfile.tsx`: 「総合難易度」単独行＋内訳の各行に埋め込まれていたチップを、
  `RouteSettingsPanel`の軸チップ列と同じ`chipRow`（折り返す1行）へ統合。内訳
  （`.breakdown`）側は選択操作を持たない色ドット＋ラベルの読み取り専用表示に変更
  （`.rowLabel`新設、`legendChip`ボタンから置き換え）。常時表示していた説明段落
  （`.scoreHint`）を`FieldLabel`（情報アイコン→ポップオーバー、`RouteList`の
  「おすすめ度について」と同じパターン）へ変更し、`.scoreHint`CSSクラスを削除。
- `docs/modules/frontend/route-settings-and-results.md`のRouteList.tsx/RouteAxisProfile.tsx
  節を実装に合わせて更新。

## 修正（2026-09-02、初回実装がユーザーのイメージと不一致）

初回実装は「ルート選択」タブの中に候補ごとのタブ（RouteList.tsx、独立コンポーネント）を
ネストする2段構成だった。ユーザー指摘「イメージと違う。ルート選択、研究タブと同じ形で
ルートごとタブにして。（ルート選択タブは不要になる。）」を受け、**候補ごとのタブを
「比較」タブと同じ1段のフラットなタブ列へ昇格し、「ルート選択」という中間タブ自体を
撤去した**。

- `app/page.tsx`の`renderRouteOutcomeSectionBody`を全面書き換え。外側`Tabs.Root`の
  タブ列を「候補ごとのタブ（`routes`の件数ぶん）＋『比較』」のフラット1列に変更。
  外側タブの選択値は`selectedRouteId`（候補タブ選択時）と新設した`comparisonTabActive`
  state（比較タブ選択時）を組み合わせて求める——`selectedRouteId`は比較タブを見ている間も
  「最後に見ていた候補」を保持し続け、地図の色分け対象等の既存の使われ方を変えない。
  `handleRoutesClear`で`comparisonTabActive`も一緒にリセットする。
  各候補タブの中身（`Tabs.Content`）は`RouteAxisProfile`単体（`selectedCandidate`の
  条件分岐は撤去、候補ごとにそのまま渡す）。
- `RouteList.tsx`/`.test.tsx`/`.module.css`を削除（候補ごとのタブ・「おすすめ度について」
  情報アイコンをpage.tsx側へ直接移設したため、独立コンポーネントとしては不要になった）。
  `SCORE_HINT`文言・`NON_DIRECTIONAL_ROUTE_IDS`定数はpage.tsxへ移設。
  `page.module.css`の`.outcomeTabTrigger`を2行コンテンツ（おすすめ度+方向/距離）対応へ拡張、
  `.outcomeTabList`へ`overflow-x:auto`を追加（候補数が画面幅を超える場合の横スクロール）。
  `page.test.tsx`の`RouteList`モックを削除（実体が無くなったため）。
- `docs/modules/frontend/route-settings-and-results.md`・`page-composition.md`・
  `docs/architecture.md`のRouteList言及を、page.tsx直下のフラットタブ構成の説明へ更新。

## フォローアップ1（2026-09-02、タブ名の簡略化）

ユーザー指摘「タブ名のおすすめ度もう少しシンプルにならない？」を受け、候補タブの表示を
「{点数}点 おすすめ度」から「{点数}点」のみへ簡略化した（`app/page.tsx`の
`Tabs.Trigger`）。「おすすめ度」という語自体はタブ列脇の情報アイコン（当時）のラベルに
既に出ているため、タブごとに繰り返さない。

## フォローアップ2（2026-09-02、補足情報の「ルート結果」ヘッダへの集約）

ユーザー指摘「おすすめ度の説明とか、ルート結果諸々の補足は、ルート結果ヘッダのところに
情報アイコンをつけて集約できない？」を受け、散らばっていた2箇所の説明を「ルート結果」
セクション見出し1箇所（情報アイコン1個）へ統合した。

- 対象: `app/page.tsx`のタブ列脇にあった「おすすめ度について」`FieldLabel`と、
  `RouteAxisProfile.tsx`のスコア行にあった「おすすめ度・総合難易度について」`FieldLabel`
  （候補タブの数だけ同じ説明が繰り返し表示されていた）。両方を削除し、文言を
  `ROUTE_RESULT_HINT`（`app/page.tsx`）1本へ統合した。
- `components/Map/recipeControls.tsx`の`FieldLabel`へ`hideLabel?: boolean`propを追加
  （`ui/Dialog/Dialog.tsx`の`hideTitle`と同じ、Tailwindの`sr-only`でラベル文言のみ視覚的に
  隠す既存パターン）。見出し脇のアイコンは文言を伴わずアイコン単体の見た目にしたいため。
- `components/BottomSheet/BottomSheet.tsx`へ`headerAction?: React.ReactNode`propを追加。
  タイトル（`<h2>`）と並べる`.titleGroup`でラップし、閉じるボタンとの間はheader側の
  `justify-content: space-between`に委ねる。
- `renderRouteOutcomeSectionBody`に`showHeading: boolean = true`引数を追加
  （`renderRouteSettingsSectionBody`と同じ、見出しの二重表示回避パターン）。デスクトップ
  （既定true）はこの関数自身が`<h2>ルート結果</h2>` + 情報アイコンを描画する
  （`.outcomeSectionHeader`新設）。モバイルはBottomSheet自体が`title="ルート結果"`の
  見出しを持つため`showHeading=false`で抑制し、同じ情報アイコンをBottomSheetの
  `headerAction`propとして呼び出し側から渡す（`routes.length > 0`の間のみ）。
