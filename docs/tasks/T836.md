# T836. 「鮮度」タブが、読めない・押すまで何も無い・直した後にどうすればよいか分からない

規模M。
状態: 着手（2026-09-14、本番実機のユーザー指摘「文字がずらっと書いてあってよくわからない、
以下のテーブルって言ってもボタン押すまで何もない、この画面で不整合なら何すればいいか
わからない」「uiは省スペース化してシンプル直感的にして」から）

## 背景

`/admin`「鮮度」タブ（`DerivedDataFreshnessPanel.tsx`）の3つの問題。いずれも
[design-principles.md](../design-principles.md)「冗長なものは削る」（説明文をベタ書きで画面へ
置かずⓘの奥へ）・「1画面の情報量を増やさない」に反している。

1. **説明文を8行ベタ書きしている。** 読むのは1度きりなのに場所は常に取り続ける。
2. **集計前から「下の表に並ぶ各テーブルが…」と表の話をしている。** ボタンを押すまで表は
   無いため、最初に開いた人は存在しないものの説明を読まされる。
3. **不整合と分かっても次の行動が画面に無い。** [T832](T832.md)で完成度の枠にだけ
   「どのバッチを再実行するか」を入れ、世代比較の枠には入れなかった。
4. モバイル実機では表が横に切れ、「比較対象」の列だけが見えて肝心の数字が読めない。

## 対応方針

ユーザー選択（2026-09-14）は**「状態だけ＋必要時に詳細」**。

- 説明はⓘ（`InfoPopover`）の奥へ。見出しの隣に置く。
- 集計前はボタンだけ（表の話をしない）。
- 集計後は上部に1行のまとめ（何件が古い・何件に未計算があるか）と、**再構築の単一コマンド**
  （`app/batch/refresh_derived.py`が依存順に全段を回す唯一の入口）をコピーできる形で置く。
- 一覧は1件1行（状態・名前・規模）にし、run番号などの数字はタップで開く。世代比較と完成度を
  同じ見た目の行にする——読み手にとっては「古いかどうか」が知りたいことで、判定方式の違いは
  開いた先に書けばよい。
- 表（`<table>`）をやめる。横スクロールを前提にしない。
