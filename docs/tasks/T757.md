# T757. ヘッダーの観測値取得エラーが常駐し、モバイルではヘッダーが画面外へ溢れる

規模S〜M。
状態: 完了（2026-09-12）

## 背景

アメダス観測値の取得失敗が「アメダス観測値の取得に失敗しました[req: …]」とリクエストID付きでヘッダーの天候欄に出たまま、セッション中ずっと残った（本番、複数セッション）。内部のリクエストIDが一般画面に露出し、日付チップが押し出される。

390px幅ではヘッダーの`scrollWidth`が515で幅390を超え、メニュー「⋮」ボタンが画面外（x=473）にある。「注意」バッジも右端で切れる。研究モードのON/OFFはこのメニューにしか無いため、モバイルからは到達できない。

個票は[history/2026-09-12_ui.md](../../.claude/commands/review/history/2026-09-12_ui.md)のF-3・F-4。

## 調査項目

1. **エラーの寿命**。観測値の取得は定期ポーリングか。失敗後に再取得しているか、成功したら文言が消えるか
2. **リクエストIDの出し先**。`fetchJson.ts`が付けるIDは開発者向け（デバッグログ・`BackendLogsPanel`）で足りるか。一般画面には短い文言だけを出す
3. **ヘッダーの幅**。天候の項目が固定幅で並ぶため、項目が増えると溢れる構造。狭幅では天候をまとめる（ヘッダーへの要素追加はPopoverへ集約する既存方針に沿う）か、折り返しを許すか
4. メニューが画面外でも`aria`上は存在するため、既存の自動テストでは検出できない。幅390での`scrollWidth`検査をテストに入れられるか

## 完了条件

- 390px幅でヘッダーの`scrollWidth`が幅を超えないこと、メニューが指で押せる位置にあることを実測で示す
- 観測値の取得失敗時、一般画面にリクエストIDが出ないこと、回復後に文言が消えること

## 対応

3つを直した。

1. **エラーの寿命**: `useWeatherConditions.ts: useLocationFetch`は`location`が変わるまで
   1回しか取りに行かず、一度の失敗がそのセッション中ずっと表示に残っていた。10分間隔の
   取り直しを入れ、成功したらエラーを消す。同じフックを使う5種（予報・アメダス・警報・
   WBGT・氾濫）すべてが同じ性質だったため、フック側で直している。
2. **リクエストIDの出し先**: `fetchJson.ts`がHTTPエラーのmessageへ`[req: …]`を
   埋め込んでいたのをやめ、`ApiError`の属性（`requestId`・`status`）にした。画面へ出るのは
   短い文言だけになり、IDはdebugLog・`BackendLogsPanel`に残る。全画面のエラー表示が対象。
3. **値を失敗の文言で置き換えない**: `WeatherPanel`・`TodayOutlook`は手元に値があっても
   直近の失敗を優先して表示していた。値があるときは値を出し、無いときだけ短い文言
   （「観測値なし」、詳細はtitle）にする。メニュー（⋮）は`position: sticky; right: 0`で
   右端へ貼り付け、バッジがスクロールアウトしても押せる位置に残す。

## 検証

Playwright（390x812、`e2e/fixtures.ts`のモック。アメダスだけ503を返すよう上書き）で実測:

| | レビュー時 | 対応後 |
|---|---|---|
| ヘッダーの`scrollWidth` / 幅 | 515 / 390（溢れ） | 390 / 390（溢れなし） |
| メニュー（⋮）の位置 | x=473（画面外） | x=348、右端は390以内 |
| 文言 | 「アメダス観測値の取得に失敗しました[req: …]」 | 「観測値なし」（`[req:`はDOMに無い） |

回復でエラーが消えることは`useWeatherConditions.test.ts`の回帰テストで固定した。
再取得を一時的に外すとこのテストが落ちることも確認済み（検知が効いている）。
ヘッダーの溢れ検査は`e2e/mobile.spec.ts`へ常設した——画面外の要素もaria上は見つかるため、
role・名前ベースの検査では捕まらない。
