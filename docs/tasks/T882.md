# T882. コピペ検出が、リポジトリで最も大きいファイルを黙って走査していない

規模S。
状態: 着手中（2026-09-16起票。[T881](T881.md)の撤去で入れた重複がどの検査にも引っかからず、
既存のコピペ検出で捕まえられないか確かめたときに判明）

## 背景

`scripts/review_checks.py duplication`（jscpd）の既定`maxSize`は100KBで、それを超える
ファイルは走査対象から外れる。**外れたことは出力のどこにも出ない**ため、「クローン0件」が
「見ていない」と区別できない。

外れているのは対象714ファイル中7件で、いずれもリポジトリで最も大きいものである。

    176.5KB  frontend/src/components/Map/MapView.tsx
    164.3KB  backend/tests/test_road_graph_engine.py
    156.8KB  backend/app/services/road_graph_engine.py
    154.7KB  backend/app/infrastructure/road_graph_repository.py
    153.2KB  scripts/review_checks.py
    148.9KB  frontend/src/app/page.tsx
    122.8KB  backend/tests/test_road_graph_repository.py

走査済みのPythonで最大は972行（`domain/material_catalog.py`）。実際に測れているのは
小さい側だけである。

## 保留することで何が起きうるか

- 大きいファイルほど「同じものが少しずつ増えた」結果である確率が高いのに、そこだけが
  検出の外にある。[T881](T881.md)の重複（同一ファイル内で33行のコメントと定義が2組）は
  実際にここで見逃された。
- `duplication`の前回比（クローン件数の増減）は、この7ファイルの中で何が起きても動かない。
  「増えていない」という判断の根拠が、母集団の欠落で成り立たなくなる。

## 対応方針

`maxSize`を引き上げるだけでは足りない。**除外されたファイルを名指しで報告させる**ことを
同時に行う——上限は運用上いつか再び当たるもので、当たったことが分からない形のままだと
同じ見落としが繰り返される。
