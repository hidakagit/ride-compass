# T882. コピペ検出が、リポジトリで最も大きいファイルを黙って走査していない

規模S。
状態: 完了（2026-09-16起票・同日実装。[T881](T881.md)の撤去で入れた重複がどの検査にも引っかからず、
既存のコピペ検出で捕まえられないか確かめたときに判明）

## 背景

`scripts/review_checks.py duplication`（jscpd）は、既定で**1,000行**または**100KB**を
超えるファイルを走査対象から外す。**外れたことは出力のどこにも出ない**ため、
「クローン0件」が「見ていない」と区別できない。

起票時は100KB（`maxSize`）が原因だと書いたが、実際に効いていたのは行数の方
（`maxLines`）だった。走査できた最大は972行（`domain/material_catalog.py`）で、
外れていた18件は`errors.py`（2行、`--min-lines`未満で外れるのが正しい）を除き
すべて1,000行超である。サイズだけを見ていたときの7件より対象は広く、
`domain/evaluation.py`・`domain/routing.py`のような中規模のファイルも入っていた。

測ると、**対象の37%が走査されていなかった**。

    走査したファイル   688件 → 706件
    走査した行数    104,789行 → 143,294行（+38,505行）
    ファイルをまたぐクローン  19件 → 27件
    同一ファイル内の重複    108件 → 242件

大きいファイルほど「同じものが少しずつ増えた」結果である確率が高いのに、そこだけが
検出の外にあった。[T881](T881.md)の重複（同一ファイル内で33行のコメントと定義が2組）は
実際にここで見逃されている。
## 保留することで何が起きうるか

- 大きいファイルほど「同じものが少しずつ増えた」結果である確率が高いのに、そこだけが
  検出の外にある。[T881](T881.md)の重複（同一ファイル内で33行のコメントと定義が2組）は
  実際にここで見逃された。
- `duplication`の前回比（クローン件数の増減）は、この7ファイルの中で何が起きても動かない。
  「増えていない」という判断の根拠が、母集団の欠落で成り立たなくなる。

## 対応（2026-09-16）

上限を外す（`--max-lines 20000`・`--max-size 1mb`）だけでは足りない。上限は運用上いつか
再び当たるもので、当たったことが分からない形のままだと同じ見落としが繰り返される。
**走査されなかったファイルを毎回その場で導出して名指しで報告する**
（`unscanned_target_files`）。

名前の一覧は持たない。対象の拡張子も**jscpdが実際に読んだファイルから逆算する**
——手で並べると、jscpdが対応形式を増やしたときに検査の側が黙って狭くなる
（[design-principles.md](../design-principles.md)構造仕様12）。どのファイルが今後
肥大化しても、その時点で名前が出る。

効いていることの確認: `JSCPD_MAX_LINES`を既定の1,000へ戻すと、18件が名指しで
報告される（2行の`errors.py`は`--min-lines`未満のため出ない）。

前回値（`history/duplication.json`）はクローン21件→27件へ更新した。**増えたのは
写経が増えたからではなく、母集団が増えたから**である。次回以降の前回比は27件が起点になる。
