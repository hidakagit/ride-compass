# T429. `pytest -m "not postgis"`が実は何もフィルタしていない問題を修正

状態: 未着手（起票のみ、2026-08-30・統合レビュー`/review:all`第9回consistency F-2で発見）

- 背景: CLAUDE.md・docs/architecture.mdは「PostGIS統合テストは`pytest -m "not postgis"`で
  スキップされる」と説明しているが、リポジトリ全体に`@pytest.mark.postgis`というbare marker
  は1件も存在しない（存在するのは別名の`pytest.mark.xdist_group(name="postgis")`のみ）。
  実測（統合レビューが独立に2回検証済み）: `-m "not postgis"`と無指定は同じ1456件を収集
  （deselect 0件）。実際のスキップは`conftest.py`等9ファイルのfixtureレベルの
  `try/except pytest.skip()`による。
- 影響: 現状は9ファイル全てが同じ安全なfixtureパターンに従っているため実害は限定的。
  ただし将来この慣習に従わない新規PostGIS依存テストが追加された場合、ドキュメントが
  約束する防御が機能せずCI等で予期しないハード失敗を招くリスクがある。
- 対応方針（未確定、着手時に選ぶ）: (a) `pytest.ini`へ`markers = postgis: PostGIS統合テスト`
  を登録し該当テストへ`@pytest.mark.postgis`を実際に付与して文言どおり機能させる、
  または (b) CLAUDE.md・docs/architecture.mdの記述を実態（fixtureレベルの`try/except
  pytest.skip()`）に合わせて訂正する。同種ドリフトの再発防止という観点では(a)（機械的に
  保証する）が優先候補。
