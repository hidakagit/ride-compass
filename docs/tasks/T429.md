# T429. `pytest -m "not postgis"`が実は何もフィルタしていない問題を修正

状態: 完了（2026-08-31）

- 背景: CLAUDE.md・docs/architecture.mdは「PostGIS統合テストは`pytest -m "not postgis"`で
  スキップされる」と説明しているが、リポジトリ全体に`@pytest.mark.postgis`というbare marker
  は1件も存在しない（存在するのは別名の`pytest.mark.xdist_group(name="postgis")`のみ）。
  実測（統合レビューが独立に2回検証済み）: `-m "not postgis"`と無指定は同じ1456件を収集
  （deselect 0件）。実際のスキップは`conftest.py`等9ファイルのfixtureレベルの
  `try/except pytest.skip()`による。
- 影響: 現状は9ファイル全てが同じ安全なfixtureパターンに従っているため実害は限定的。
  ただし将来この慣習に従わない新規PostGIS依存テストが追加された場合、ドキュメントが
  約束する防御が機能せずCI等で予期しないハード失敗を招くリスクがある。
- 対応方針（未確定、着手時に選ぶ）: (a) `pytest.ini`へ`markers = postgis: PostGIS統合テスト`
  を登録し該当テストへ`@pytest.mark.postgis`を実際に付与して文言どおり機能させる、
  または (b) CLAUDE.md・docs/architecture.mdの記述を実態（fixtureレベルの`try/except
  pytest.skip()`）に合わせて訂正する。同種ドリフトの再発防止という観点では(a)（機械的に
  保証する）が優先候補。
- **対応（2026-08-31完了）**: (a)を採用。`backend/pytest.ini`へ`markers = postgis: ...`を
  登録し、`xdist_group(name="postgis")`を付けていた全12ファイル
  （test_axis_definition_repository/test_axis_registry_service/test_accident_repository/
  test_health/test_import_accidents/test_import_pbf/test_import_designations/
  test_match_designations/test_migrate/test_precompute_edge_attribute_counts[クラス限定]/
  test_precompute_way_attribute_counts[クラス限定]/test_road_graph_repository）へ
  `pytest.mark.postgis`を追記した。検証: `pytest -m "not postgis" --collect-only`で
  1244/1486件（242件deselected、以前は0件deselected）と実際にフィルタされることを確認。
  `-W error::pytest.PytestUnknownMarkWarning`でも警告なしを確認（マーカー登録済み）。
  docs/architecture.md・CLAUDE.mdの既存記述（「`pytest -m "not postgis"`実行時はスキップ
  される」）は、今回の修正で文言どおり真になったため訂正不要。docs/testing.mdの
  パターン2節へ`pytest.mark.postgis`の付与を手順に追記済み（今後の新規PostGIS統合
  テストファイルが同じ抜け漏れを再発しないため）。CI設定
  （`.github/workflows/`）は変更不要（既存の`-m "not postgis"`呼び出しがそのまま
  正しく機能するようになる側の修正のため）。
