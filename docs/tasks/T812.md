# T812. 時刻ビンを渡す探索経路にテストを置き、逆向き木の制約を実装で表明する

規模S。
状態: 完了（2026-09-13。統合レビュー第8回のP1）

## 背景

[T790](T790.md)段階Dで探索を時刻ラベル対応にしたが、`build_turn_expanded_tree`のテストは
**すべて1次元コスト**（`edge_seconds=cost`、`bin_seconds`既定=inf）で呼んでおり、
**2次元コスト（時刻ビン）を渡す経路のテストが1件も無い**
（`tests/test_routing_turn_expanded.py:148-161, 226-232`）。時刻ビンのテストがあるのは
A*側だけ（274-307行）。

一方、本番の周回生成（`road_graph_engine.py:1192-1197`）と目的地ルートの前向き木
（`:1387-1391`）はどちらも`cost_bins_lazy`＋`bin_seconds`で木を張る。つまり
**T790の中核経路にテストが無い**。

`_turn_expanded_dijkstra`の`time_bin`クランプ（`routing.py:828-832`）や
`arrival[nxt] = travelled + edge_seconds[time_bin, nxt] + wait`（`:843`）を壊しても、
テストは全件緑のまま通る。実害は「風を無視した経路が返る」という値の劣化で、例外も候補0件も
起こさないため気づく契機が無い。

あわせて`build_turn_expanded_tree`は「**逆向きの木は時刻ビンを使えない**——目的地から遡るため
各状態の到達時刻が決まらない。呼び出し元は1本のビンで呼ぶこと」を`routing.py:918-919`の
docstringで**文章でだけ**要求しており、`reverse=True`かつ2次元コストを弾く表明が実装に無い。
後ろ向き木に素直に`cost_bins_lazy`を渡すと、`arrival`が「残り時間」であるためビンが逆向きに
引かれ、例外もNaNも出ないまま**時刻が反転した風で評価した経路**が返る。

## 対応方針

1. 時刻ビンを渡すDijkstraのテストを足す。ビンごとに違うコストを与え、**選ばれる経路がビンで
   変わる**ことを検証する（ラベルが効いていることを値で示す）。
2. `reverse=True`かつ2次元コストを`ValueError`で弾く。
3. **わざと壊して落ちることを確認してから完了扱いにする**（`time_bin`クランプを外す・
   `arrival`の加算を落とす、の2通りで確認する）。

## 実装・検証（2026-09-13）

**時刻ビンを渡す木のテスト**（`tests/test_routing_turn_expanded.py`）:

- 経路がビンで変わることを値で示す。S→C→E（200m）とS→A→B→E（300m）へ、ビン0は素の
  所要時間・ビン1はC-Eだけ100倍のコストを渡し、1区間（18秒）でビン1へ移る幅（10秒）に置くと、
  木は遠回りを選ぶ。A*側に既にある同型のテストと同じ組み方にした。
- 所要時間の積算が「着いた時刻のビンの秒」であることを、経路が1本しか無いグラフで固定する
  （コストのビン選択と秒の積算が別のビンを見ていれば合わない）。

**逆向き木への時刻ビンを`ValueError`で弾く**（`routing.py: build_turn_expanded_tree`）。
docstringが文章で要求していただけの制約を実装の表明にした。本番の呼び出し元
（`road_graph_engine.py`の目的地ルート後ろ向き木）は`inbound.cost_lazy`・
`travel_seconds_lazy`＝1次元の代表値を渡しており、このガードに抵触しない（実装コメントにも
「時刻ラベルを持てない後ろ向き木が使う」と書かれている）。1本のビンなら逆向きでも通ることも
テストで固定した。

**わざと壊して落ちることを確認した**（`_turn_expanded_dijkstra`のみを対象にし、A*側の同型
コードは壊していない）:

| 壊し方 | 落ちたテスト |
|---|---|
| `time_bin`を常に0へ固定（クランプごと無効化） | 経路がビンで変わる／秒の積算 の2件 |
| `arrival`から区間の秒を落とす | 秒の積算／既存の「コストと距離が経路に沿う」の2件 |

**あわせて`search_graph_cache`の2キャッシュのテストを追加した**（関連に挙がっていた穴）。
`_turn_structure_cache`はタイル集合とターン費用の組を鍵にするため、**費用を変えたときに
古い構造が返ると較正が効かないまま「効いている」ように見える**——鍵からターン費用を落とす
壊し方で3件落ちることを確認した。`_detour_ratio_cache`はfloatを持つため、偽と評価される値
（0.0）がキャッシュミスと区別できることを固定した（呼び出し元
`road_graph_engine.py:807-811`は`is not None`で判定しており、現状の実害は無い）。

`invalidate_tile_set`のdocstringが破棄対象を実際より少なく数え上げていたのを、挙動の記述へ
直した（同一コミット）。

テスト: backend 1900件（postgis除く）緑、`ruff`指摘なし。
