# T812. 時刻ビンを渡す探索経路にテストを置き、逆向き木の制約を実装で表明する

規模S。
状態: 未着手（統合レビュー第8回のP1、2026-09-13）

## 背景

[T790](T790.md)段階Dで探索を時刻ラベル対応にしたが、`build_turn_expanded_tree`のテストは
**すべて1次元コスト**（`edge_seconds=cost`、`bin_seconds`既定=inf）で呼んでおり、
**2次元コスト（時刻ビン）を渡す経路のテストが1件も無い**
（`tests/test_routing_turn_expanded.py:148-161, 226-232`）。時刻ビンのテストがあるのは
A*側だけ（274-307行）。

一方、本番の周回生成（`road_graph_engine.py:1192-1197`）と目的地ルートの前向き木
（`:1387-1391`）はどちらも`cost_bins_lazy`＋`bin_seconds`で木を張る。つまり
**T790の中核経路にテストが無い**。

`_turn_expanded_dijkstra`の`time_bin`クランプ（`routing.py:828-832`）や
`arrival[nxt] = travelled + edge_seconds[time_bin, nxt] + wait`（`:843`）を壊しても、
テストは全件緑のまま通る。実害は「風を無視した経路が返る」という値の劣化で、例外も候補0件も
起こさないため気づく契機が無い。

あわせて`build_turn_expanded_tree`は「**逆向きの木は時刻ビンを使えない**——目的地から遡るため
各状態の到達時刻が決まらない。呼び出し元は1本のビンで呼ぶこと」を`routing.py:918-919`の
docstringで**文章でだけ**要求しており、`reverse=True`かつ2次元コストを弾く表明が実装に無い。
後ろ向き木に素直に`cost_bins_lazy`を渡すと、`arrival`が「残り時間」であるためビンが逆向きに
引かれ、例外もNaNも出ないまま**時刻が反転した風で評価した経路**が返る。

## 対応方針

1. 時刻ビンを渡すDijkstraのテストを足す。ビンごとに違うコストを与え、**選ばれる経路がビンで
   変わる**ことを検証する（ラベルが効いていることを値で示す）。
2. `reverse=True`かつ2次元コストを`ValueError`で弾く。
3. **わざと壊して落ちることを確認してから完了扱いにする**（`time_bin`クランプを外す・
   `arrival`の加算を落とす、の2通りで確認する）。
