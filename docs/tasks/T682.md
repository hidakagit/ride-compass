# T682. バッチの構造的欠陥を直す

規模M。

状態: 完了（2026-09-09）

## 背景

統合レビュー第5回（[2026-09-08_all.md](../../.claude/commands/review/history/2026-09-08_all.md)）
が検出した指摘のうち、下表の11件を1つの起票単位として扱う。

ダウンロードキャッシュキーが配信版数を含まないため「データ更新時に再実行」という
文書化されたトリガーが機能せず、旧版を再パースして成功ログを出す。
kind単位ガードの欠落は`designation_attributes`の静かな全消しを招く。

## 実施内容（2026-09-09）

11件のうち10件を実施し、2-12だけを[T688](T688.md)へ分離した。

### P2（実害のある修正）

| # | 対応 |
|---|---|
| 1-11 | `_RasterSource.contains`（リングがラスタ範囲へ完全に収まるか、矩形の包含で判定）を通ったラスタでのみ割合を出す。1枚も完全には覆えないwayは行を作らず、部分的に重なるラスタがあった場合（境界またぎ）と完全に範囲外の場合をログで区別する。画素数比ではなく幾何で判定するのは、細いリング形状のラスタライズ誤差に閾値を依存させないため |
| 1-12 | `_write_matches`のスキップガードをkind単位にし、候補0件のkindはDELETEの対象から外す。完了ログへkind別の候補数・マッチ数を載せ、候補があるのにマッチ0のkindがあればWARNINGにする |
| 2-5 | バッチの自前`pg_insert`を撤去し、`RoadGraphRepository.save_edge_attribute_counts`（→`_bulk_upsert`）へ委譲。あわせて`_bulk_upsert`が1文へ載せる行数を`_bulk_chunk_rows`（`_BULK_CHUNK_ROWS`とパラメータ上限÷列数の小さい方）で決めるようにした——バインドパラメータ上限の保護が`_bulk_upsert`の全利用者へ効くようになり、`_BULK_CHUNK_ROWS`のコメントにあった「最も列数の多いテーブル（8列）」という陳腐化した根拠（レビュー6-20、[T671](T671.md)の対象）も同時に解消した |
| 2-6 | 各段の戻り値を受け取り、非0なら後続を実行せずその終了コードを返す |
| 2-7 | ZIPのローカル保存名をURL側のファイル名（`N10-15_08_GML.zip`、KSJの配信版数を含む）に変更 |

### P3

| # | 対応 |
|---|---|
| 2-9 | `_warm_tasks`/`_build_tasks`（モジュールレベルのset）でタスクへの強参照を保持し、`add_done_callback`で解放する |
| 2-10 | `reap_stale_running_import_runs`の呼び出しを`conn`を閉じる`try`の内側へ移した（`import_accidents`・`import_designations`と同じ位置）。テストは追加していない——3本とも接続リークを直接検証するテストは無く、ここだけのために`import_pbf.run()`のreap到達までを組み立てるコストが見合わないため |
| 2-11 | `count_pixels_in_ring`から`pin_bundled_proj_data()`を外した（`_RasterSource.__init__`が済ませている） |
| 10-3 | スコア行列のキャッシュmissを`"db"`ではなく`"computed"`として報告し、INFOサマリへ`computed=`を追加 |
| 10-4 | チャンク完了ログを当チャンクの件数だけにし、累計は完了サマリへ寄せた |

### 見送り

- **2-12（増分実行が「未計算」と「計算済み・値なし」を区別できない）**: 区別には
  `way_landcover`の割合列をNULL可にするmigrationと、消費者側（`domain/evaluation.py`・
  `domain/attributes.py`）のNULL対応が要る。同ファイルを対象とする[T673](T673.md)と
  競合するため、[T688](T688.md)へ分離した。
