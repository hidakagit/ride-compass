# T594: 動的way値配信へ走行速度を伝播する（dynamic_way_value_needs_speed）

状態: 完了（2026-09-05起票・同日完了、分割元は[T590](T590.md)。実機確認は末尾参照）

## 背景

二乗則材料（[T591](T591.md)）は走行速度に依存するため、`GET /api/region/dynamic-way-values`・
`WindWayService`・キャッシュキー・フロントのフェッチへ速度を通す必要がある。既存の
`dynamic_way_value_needs_time`/`needs_bearing`と同型の宣言的フラグで扱う。

## 対応方針

- `axis_definitions`へ`dynamic_way_value_needs_speed`列を追加する（DDL migration、
  `AxisDefinition`・`axis_admin`・`axis_catalog`・repository・スナップショットへ追従）。
- `region.py`のエンドポイントに`speed_kmh`クエリパラメータを追加し、`needs_speed=true`の
  材料で必須（省略422）、それ以外は無視（時刻を勾配で無視している既存の扱いと同じ）。
- `dynamic_way_value_cache.py`のキーへ速度バケット（1km/h刻み）を、`needs_speed`の
  材料でだけ含める（時刻・向きのバケット化と同じ判定経路）。
- フロントの`useDynamicWayValues`へ速度を追加で渡す。値は`page.tsx`の`assumedSpeedInput`
  （[T596](T596.md)完了後は条件バーの状態）。
- `dynamic_way_value_materials()`の戻り値へ`needs_speed`を追加する。

## 実装メモ（2026-09-05）

- `backend/migrations/0031_axis_definitions_dynamic_way_value_needs_speed.sql`（DDLのみ）、
  `AxisDefinition.dynamic_way_value_needs_speed`・ORM・repository・`axis_admin`のペイロード・
  `dynamic_way_value_materials().needs_speed`・スナップショット（全軸false）へ追従。
- `GET /api/region/dynamic-way-values/...`に`speed_kmh`を追加（`needs_speed`の材料で省略時422、
  それ以外は無視）。`dynamic_way_value_cache._key`へ速度バケット（1km/h刻み、
  `speed_bucket`）を追加し、速度に依存しない材料はNone（`-`）でキーを分割しない。
- `WindWayService.material_id`をプロパティ化: 風軸（`AXIS_DEFINITIONS["wind"]`）が
  `wind_drag_ratio`を参照していれば`wind_drag_ratio`（`speed_kmh`必須、`wind_drag_ratio()`で
  計算、小数3桁）、そうでなければ非推奨材料`wind_penalty`（従来どおり、速度は無視）。
  本番の風軸が旧材料を参照している間は挙動が変わらず、T599の切替後にコード変更なしで
  速度依存の配信へ移る。`GradientWayService`は`speed_kmh`を受け取るが無視する。
- frontend: `fetchDynamicWayValues`・`useDynamicWayValues`に`speedKmh`（デバウンス）を追加し、
  `page.tsx`がルート設定の想定速度入力（未入力・不正値は既定値）を風のレンズへ渡す。
  `AxisComposer`はフラグをpayloadへ素通し（編集UIなし、他2フラグと同じ）。
- 生成物（`openapi.json`・`api.d.ts`）はDB接続が無く`export_openapi.py`を実行できないため
  手で同期した（`dynamic_way_value_needs_speed`スキーマ・`speed_kmh`クエリ・エンドポイント
  説明文）。CIの`api-contract`ジョブがドリフトを検証する。
- テスト: `test_region_routes.py`（needs_speedの422・伝播）、`test_wind_way_service.py`
  （参照先に応じた`material_id`、速度必須、速度別の値、旧材料では速度がキャッシュキーに
  混入しない）を追加。backend全体1509 passed（`osmium`未導入の収集エラー2件は既知）。
  frontend関連テスト・eslint・tsc（`layout.tsx`の既知エラーを除く）green。
- 完了条件「想定速度を変えるとルート前の風レンズの色が変わる（実機確認）」は、本番・devの
  風軸を`wind_drag_ratio`参照＋`dynamic_way_value_needs_speed=true`へ切り替える
  [T599](T599.md)の後でないと観測できないため、T599の手順5で併せて確認する。
