# T607. 風/勾配road-value系レイヤーのデータ取得状態（読込中/データなし）可視化

状態: 完了（2026-09-05）

## 背景

T606（キキクル4種の地図上チップ化+dataStatusドット拡張）の背景調査で判明した2つの
ギャップのうち、T606ではキキクル4種（環境グループの`dynamicWeather`系レイヤー）のみを
対応した。もう1つのギャップである風/勾配のroad-value系レイヤー（`useDynamicWayValues.ts`/
`dedicatedWayValueLayer.ts`、way_id単位でsetFeatureState経由に線色分けする評価軸表現）は
未対応のまま残っている。

`useDynamicWayValues.ts`はloadingフラグ自体を持たず、「読込中」と「取得したが値が無い」の
両方を同じ`COLOR_NO_DATA`（灰色）で表示するため、ユーザーからは区別がつかない
（`docs/tasks/T606.md`背景の指摘「風とかも今は読込待ちなのか区別がつかない」の一部は
この経路を指している）。

## スコープ

- `useDynamicWayValues.ts`へloading状態を追加し、`dedicatedWayValueLayer.ts`の
  color expressionが「読込中」と「値なし」を区別して表示できるようにする。
- 表示方法（灰色のまま区別するか、T606のチップ+ドット機構に合流させるか等）は未検討。
  windAxis/gradientAxisは既に地図上チップとしては撤去されルート設定パネル
  （`RouteSettingsPanel.tsx`）経由の表示のため、T606のMapOverlayControls向けドット機構を
  そのまま流用できない可能性がある——ルート設定パネル側に別の表現を用意するか、
  `useLayerDataStatus`と同じ`LayerDataStatus`型を再利用しつつ表示先だけ変えるか、
  着手時に改めて検討する。

## 対応方針・実装内容

T606のキキクル4種向け「地図上チップ+dataStatusドット」機構はMapLibreのソース単位イベント
（`useLayerDataStatus`、T87）を前提にしており、windAxis/gradientAxisはsetFeatureState経由の
値配信でソース自体はroad_surfaceタイルと共有するため、この機構をそのまま流用できない。
代わりに、既存の`COLOR_NO_DATA`（値取得済みだが無い）と対になる`COLOR_LOADING`（フェッチ
進行中でまだ値を受け取っていない）という第3の色を導入し、地図の色分けそのもので読込中と
データなしを区別する——「他と同じく地図タイルに出す」というT606での方針をそのまま踏襲した
アプローチ。

- `hooks/useDynamicWayValues.ts`: `UseDynamicWayValuesResult`へ`loading: boolean`を追加。
  フェッチ開始時に`true`、応答（または`enabled=false`/`viewport=null`による早期リターン）で
  `false`に戻す。`values`/`byTile`は従来どおり古い値を残す設計のまま変更していない。
- `components/Map/valueScale.ts`: `COLOR_LOADING`（`COLOR_NO_DATA`より明るいグレー）を追加。
  `buildSteppedColorExpression`へ`loading`引数（既定`false`）を追加し、値がnullのとき
  `loading`に応じて`COLOR_LOADING`/`COLOR_NO_DATA`のどちらかを返す。
- `components/Map/dedicatedWayValueLayer.ts`: `buildDedicatedWayValueColorExpression`・
  `dedicatedWayValueColorExpression`へ`loading`引数（既定`false`）を追加し
  `buildSteppedColorExpression`へ渡す。
- `components/Map/gradientGridFill.ts`: `gradientFillColorExpression`へ同じく`loading`引数を
  追加（環境グループのgridFillは値を持つタイルだけをfeatureとして含むため、この分岐が
  実際の描画へ現れることは無い。評価軸グループの線と表示宣言・読込状態を対称に共有する
  契約を保つため引数自体は追加した）。
- `components/Map/MapView.tsx`: `MapViewProps`へ`dedicatedWayValueLoading?: ReadonlyMap<string,
  boolean>`を追加（`dedicatedWayValueDisplays`と同じ、design-principles.md構造仕様3
  「軸ごとにpropを新設しない」に沿う軸id→booleanの汎用Map）。`buildStaticOverlayLayers`が
  windAxis/gradientAxis/gradientFillの各`ensure`関数へ対応する`loading`値を渡す。
  レイヤーが既に存在する場合の`setPaintProperty`再適用（T587で確立済みの仕組み）が
  `loading`の変化にもそのまま効く。
- `app/page.tsx`: `dedicatedWayValueLoading`を`dedicatedWayValues`と同じ形（axisId→booleanの
  `Map`、`windAxisData.loading`/`gradientAxisData.loading`から構築）で`MapView`へ渡す。
