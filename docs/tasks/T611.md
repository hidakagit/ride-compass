# T611: T609で誤って削除したドラッグタイムラインを復元し、直接日時指定と両立させる

状態: 完了（2026-09-06）

## 背景

T609のユーザー依頼は「クイックボタン（今/1h等）の透過バグがあるくらいなら使いにくいので、
クイックボタンの代わりに直接日時指定できる手段を追加してほしい（ドラッグタイムライン自体は
そのまま残す）」だったが、実装時に「ドラッグタイムライン全体を直接日時指定入力へ置き換える」
と誤読し、`DynamicLayerTimeSlider`（目盛り・ドラッグ・現在ボタン一式）と
`departureTimeline.ts`を丸ごと削除してしまった。ユーザーから「スライダーバーまですべて
消えている」と指摘を受け発覚。

## 対応方針・実装内容（ユーザーとの確認で確定した最終形）

- クイックボタン（今/+1h/+2h/+3h）は削除する。
- `.quickButton:hover`の透過バグ修正自体は不要になった（クイックボタン自体を削除したため）。
- 削除していた`DynamicLayerTimeSlider`（コンポーネント・CSS・テスト）・
  `departureTimeline.ts`（同テスト）・embla-carousel依存（`embla-carousel-react`・
  `embla-carousel-wheel-gestures`）を復元した。
- `input[type=datetime-local]`による直接指定は削除せず、ドラッグタイムラインの**上**に
  省スペースな1行として残し、両立させる。ラベル文言は無くし`aria-label`のみとし、
  幅いっぱい（`.directInput { width: 100% }`）に配置してポップオーバー全体を小さく保つ。
- ポップオーバーのコンテナは`.timelinePopover`（背景を持たない特殊仕様、中身の
  `DynamicLayerTimeSlider`自身が不透明な`.panel`を持つ）へ戻した。ネイティブの
  datetime-local入力はブラウザ既定で不透明な背景を持つため、透過バグの再発リスクはない。
- `docs/modules/frontend/page-composition.md`の対象ファイル表へ
  `components/DynamicLayerTimeSlider`行を復元し、`RideConditionBar`の説明を最終形へ
  更新した。`docs/architecture.md`の該当箇所も同様に更新した。
