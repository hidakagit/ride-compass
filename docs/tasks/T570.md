# T570: コメント方針（T566）の機械的強制

状態: 完了（2026-09-03）

## 背景

ユーザー指示「今のコメント整理基準をより厳格に実施できるか精査してほしい」を受けた調査の
結果、以下が判明した。

- [T566](T566.md)のコメント方針は「毎タスク完了時の即時チェック」項目5（自己申告での見直し）
  のみで、機械的な歯止めが無かった。
- 既存のdocs/modules向け機械検査（`scripts/review_checks.py`の`NARRATIVE_PATTERN`）は
  ソースコード自体には未適用だった。
- その機械検査を動かす`scripts/pre-commit-docs-consistency.sh`は`.git/hooks/pre-commit`への
  手動インストールが前提だが、**このセッションでは実際にインストールされていなかった**
  （`.git/hooks/`はgit管理外のため新しいセッション・コンテナでは毎回手動作業が必要）。
  CIワークフロー（`.github/workflows/ci.yml`）でも`review_checks.py`は一度も呼ばれておらず、
  唯一の安全網が機能していなかった。

ユーザー指示「全部実施して」によりこれらをまとめて是正した。

## 対応

1. **`scripts/review_checks.py`のNARRATIVE_PATTERNをソースコードへ拡張**:
   `find_source_narrative_violations`・`comment_only`（コメント部分のみ抽出、文字列
   リテラルの誤検出を避ける）を新設し、`backend/app/**/*.py`・`frontend/src/**/*.{ts,tsx}`
   （`is_impl_file`でテスト等は除外）へ適用。既存の`--staged`（`git diff --cached`）を
   汎用化した`diff_added_lines`（`base_ref`指定で`base_ref..HEAD`にも対応）を新設し、
   `--staged`・`--since REF`のどちらでも「追加行のみ」を対象にできるようにした。
   フルスキャン（引数無し）では参考件数のみ表示し違反件数（exit code）には含めない
   （T567完了までの既存2,844件超の残存分を弾かないため）。`--since`の既存の意味論
   （記載漏れチェックの範囲限定のみ）は変更していない——新設したソースコードチェックだけが
   `--since`でも新規と同様「追加行のみ」の強制対象になる。
2. **CIへの組み込み**（`.github/workflows/docs-consistency.yml`新設）: メインの`ci.yml`は
   `docs/**`・`**/*.md`の変更でCIをスキップする設計（無償枠対策）のため、そのままでは
   docsのみのコミットでこのチェックが走らない。別ワークフローとして新設し、
   push（`github.event.before`起点）・pull_request（base branchとのmerge-base起点）
   いずれでも`--since`で新規追加分のみを対象にする（起点SHAが解決できない場合は
   `HEAD~1`へフォールバック）。**この項目は[T564](T564.md)が挙げていた
   「scripts/review_checks.py docsをCIワークフローへ組み込む」の一部を先取りして
   実施したもの**——T564には「docs/modulesに一切出現しない既存実装ファイル18件」の
   記載という別スコープが残っており、そちらは引き続きT564で対応する。
3. **`.claude/settings.json`にSessionStartフックを新設**: `.git/hooks/pre-commit`への
   `scripts/pre-commit.sh`インストールをセッション開始のたびに自動で行う（冪等・
   スクリプト不在時は何もしない設計）。実際にこのセッションでも手動トリガー相当の
   検証（パイプテスト）で正しくインストールされることを確認済み。SessionStartフックは
   本ターン内では発火を直接確認できない性質のため、次回セッション開始時の動作は
   ユーザー側でも`/hooks`から確認できる。
4. **docs/comments.mdの判定基準を「残すのがデフォルト」から「削除がデフォルト」へ反転**:
   従来は「消したら困るか？→Yesなら残す」という残す方向を既定にしていたが、「経緯の
   言い回しに一致した時点でまず削除、①非自明な理由で②docs/modules等の他の場所にまだ
   存在しない、の両方を満たした場合だけ例外的に残す」という削除優先の基準へ書き換えた。
   あわせて「型・assert・テストへ置き換えられないか」を判断時に検討する一文を追加した
   （コメントより実行時に落ちる形の方が優先度が高いため）。

## 検証結果

- `python scripts/review_checks.py docs`（フルスキャン）: 既存17件（T564スコープ、無関係）
  のみで新規ソースコード違反は「参考623件」として表示され exit code へは影響しない
  （フルスキャン設計どおり）ことを確認。
- `python scripts/review_checks.py docs --since 752e90b`（T525以降の全コミット）:
  他セッションのT557コミットが混入させた経緯コメント2件（`road_graph_engine.py`）を
  正しく検出。自分自身のT525/T565/T566/T570の変更には0件だったことも確認（自分の
  コメット衛生が方針に従っていたことの裏取りにもなった）。
- `--staged`モード: `backend/app/config.py`へ検証用の経緯コメントを一時的に追加して
  ステージし検出されることを確認、直後に完全に元へ戻した（コミットはしていない）。
- `.claude/settings.json`のSessionStartフックコマンドを`echo '{}' | sh -c '...'`で
  パイプテストし、`.git/hooks/pre-commit`が正しい内容・実行権限でインストールされる
  ことを確認。
- `jq -e`で`.claude/settings.json`のスキーマ・構文を検証。
- `.github/workflows/docs-consistency.yml`は`python3 -c "import yaml; yaml.safe_load(...)"`
  で構文確認済み。
