# T496: 重み配分バーの帯色が軸数超過時に衝突していたのを修正

状態: 完了（2026-08-31）
## 背景

ユーザー質問「帯ごとに色を変えるのはできる？」を受けて調査したところ、重み配分バー
（帯グラフ）の帯色はすでに軸ごとに変えていたが、固定7色パレット（`STACK_BAR_COLORS`）を
`index % 7`で循環させる実装だったため、軸が7件を超える（既定の公開軸構成でも8件）と
8件目以降の帯が既に使われた色と衝突していた（実機確認: 1番目「勾配」と8番目
「自転車インフラ」が同じ紫になっていた）。軸スタジオで軸数を増やせる設計である以上、
固定の色数上限を持つこと自体がこの種の破綻の元になる。

## 対応方針

固定パレット方式をやめ、実際の軸数でHSL色相環を等分して割り当てる方式へ変更した。
軸がいくつあっても色が衝突しない。indexは従来どおりcatalog.axesの表示順（フルリスト内の
位置）を使い、チェックを外した軸があっても他の軸の色は動かない（ある軸の色は表示順が
変わらない限り常に同じという安定性を維持）。

## 実装

- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.tsx`:
  `STACK_BAR_COLORS`固定配列を撤去し、`stackBarColorForIndex(index, axisCount)`が
  `hsl((index * 360/axisCount) % 360, 62%, 55%)`を返すよう変更。呼び出し側は
  `catalog.axes.length`を渡す。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.module.css`:
  該当コメントを新方式に合わせて更新。

## 検証結果

- `npx vitest run src/components/RouteSettingsPanel/ --pool=threads`: 13件全て成功
  （色の具体値を検証するテストは元々無く、既存テストへの影響は無かった）。
- `npx tsc --noEmit`: エラーなし。
- Browserペインで実機確認: 静的フォールバックカタログの8軸すべてが赤→橙→黄→緑→水色→
  青→紫→マゼンタと重複無く色分けされることを確認（修正前は1番目と8番目が同じ紫だった）。
