# T535: 「ルートをクリア」で実験スロット（地図に残る緑線）も消えるようにする

状態: 完了（2026-09-02）

- 背景: ユーザー報告「ルートをクリアしても、地図に緑の線が残る。スマホでしか
  再現しない」。調査の結果、研究モード中の生成が記録する`experimentSlots`
  （`page.tsx`、地図重ね描き・比較タブ用の履歴、最大3件）が原因と判明した。
  1件目の色が`EXPERIMENT_SLOT_COLORS[0] = "#16a34a"`（緑）。
  `handleRoutesClear`（改善計画T365）は`routes`・`selectedRouteId`・
  `generatedConditions`・`generatedRoutePreference`のみをリセットしており、
  `experimentSlots`には一切触れていなかった。リポジトリ全体を検索しても
  `setExperimentSlots`の呼び出しは生成成功時（追加）の1箇所のみで、他に空へ
  戻す経路が存在しなかった（ページ再読み込み以外に消す手段が無い状態）。
  「スマホでしか再現しない」のは、研究モードのON/OFFは`localStorage`フラグ
  （デバイスごとに独立）のため、報告した端末側でだけ研究モードがON（過去の
  検証時、または[T519](T519.md)で新設した一般公開ヘッダーメニュー経由）に
  なっていたためと考えられる。
- 対応: `handleRoutesClear`が`setExperimentSlots([])`も呼ぶよう変更
  （`frontend/src/app/page.tsx`）。実験スロット履歴を残す設計よりも「クリアしたら
  地図が本当に空になる」という一般的な期待を優先する、というユーザー判断による。
  `setExperimentSlots`は`experimentSlots`のuseState宣言（元は`handleRoutesClear`
  より後）より前から参照することになるため、`handleRoutesClear`の定義位置を
  `experimentSlots`宣言の直後へ移動した（過去に`handleRouteModeSelect`/
  `handleLayerToggle`で発生したのと同種の、宣言順に起因するeslintエラー
  `Cannot access variable before it is declared`をビルド前に検知・修正）。
- 検証: `page.test.tsx`に新規テストを追加（研究モードON→生成→クリア→再生成で、
  クリア前のスロットが残っていないことを、2回目生成後のスロット件数が1件のまま
  であることで間接的に確認——クリア直後は`routes=[]`で比較タブ自体が
  一時的にアンマウントされるため、直接「[]」を確認できない設計上の制約への対応）。
  `npx tsc --noEmit`・`npx eslint`ともクリーン。`npx vitest run src/app/page.test.tsx`
  17件green。Browserペインでの実機確認は、開発機のルート生成が[T522](T522.md)により
  数分かかる状態が続いているため簡易確認（アプリの再読み込みでランタイムエラーが
  出ないことのみ）に留めた——ロジックは単体テストで検証済み。
