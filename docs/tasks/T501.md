# T501: 軸スタジオの複製しきい値リセット・公開済み軸の表示専用フィールド直接編集

状態: 着手中（2026-08-31）

## 背景

ユーザーがAxis Studioの複製ウィザード（Step4）で、地図の色分けしきい値
（`display_thresholds_override`）が複製元の値をそのまま引き継いでいる（自動計算が
働いていないように見える）ことに気づき、記載外の改善として2点を依頼した。

1. しきい値のデフォルトを、直前のステップで入力した変化点（breakpoints）から
   自動計算できないか。
2. 軸スタジオで公開済みの軸を編集できるようにできないか。不整合はあるか。

## 対応方針（ユーザー承認済み、2026-08-31）

1. **複製時のしきい値リセット**: `derive_ramp_inputs()`（backend/app/domain/
   axis_display.py）は`display_thresholds_override`が`None`ならbreakpointsのX値から
   既に自動計算している。複製フロー（`AxisComposer.tsx: draftFromDuplicate`）が
   複製元の手動設定値をそのまま引き継いでいたため自動計算が発動しなかった。
   複製時に`displayThresholdsOverride`を`null`へリセットする。
2. **公開済み軸の表示専用フィールド直接編集**: T271の「公開済み軸は不変・複製のみ」
   原則自体は維持する（一般ユーザーの保存重み設定がaxis_idキーで再現されるため、
   評価ロジックに影響する変更は依然禁止）。ただし評価結果に一切影響しない表示専用
   フィールド（`icon_id`・`chip_label`・`panel_hint`・`show_map_icon`・
   `display_thresholds_override`）だけは、公開済みのまま（unpublishを経由せず）直接
   更新できるよう例外を設ける。全フィールド編集可能にすると元の問題（他ユーザーの
   ルート結果が意図せず変わる）が再発するため、意図的に狭いスコープに留める。

## 実装メモ

1. **複製時のしきい値リセット**: `AxisComposer.tsx: draftFromDuplicate`が
   `displayThresholdsOverride: null`を明示的に上書きするよう修正。複製元の値は
   もう引き継がず、新しい軸の変化点(breakpoints)から自動計算される。

2. **公開済み軸の表示専用フィールド直接編集**:
   - backend `domain/axis_definitions.py`: `_COSMETIC_ONLY_FIELDS`（icon_id・
     chip_label・panel_hint・show_map_icon・display_thresholds_override）と
     `is_cosmetic_only_update(existing, candidate)`を新設。`check_publish_immutability`に
     任意の`candidate`引数を追加し、`existing.is_published`かつ`candidate`が渡され
     その差分が表示専用フィールドのみなら例外的に許可する。`delete()`は`candidate`を
     渡さないため従来どおり一律拒否のまま。
   - `services/axis_registry_service.py: update()`が`definition`（更新後の内容）を
     `check_publish_immutability`の第3引数として渡すよう変更。
   - frontend `AxisComposer.tsx`: `editing.is_published`を見て`restrictedDisplayOnly`を
     判定し、trueなら4ステップのウィザードを迂回して`renderDisplayPublishStep()`のみの
     1画面フォームを表示する。この画面では`公開する`チェックボックスを非表示にし
     `is_published`自体は変更させない（切替は既存の「非公開に戻す」ボタンへ導線を
     一本化したまま）。他ステップの入力欄が無いフィールド（label・shape・
     default_weight等）は`draftFromExisting`が読み込んだ既存値のまま素通しで
     送信されるため、backend側の`is_cosmetic_only_update`判定と整合する。
   - frontend `AxisStudio.tsx`: 公開済みタブに「表示だけ編集」ボタンを追加
     （`setEditingAxisId`を呼ぶだけ、AxisComposer側が制限モードを自動判定するため
     呼び出し側の分岐は最小限）。モーダルタイトルも公開済み軸編集時は
     「表示専用フィールドを編集: {label}」に変える。

3. **ドキュメントドリフト是正（同一コミット、CLAUDE.md「既存モジュールへの修正・追加」
   節の運用に従う）**: `docs/modules/frontend/axis-studio.md`に、T404で
   `display_thresholds_override`が専用編集UIを持ったにもかかわらず「編集欄を持たない
   フィールド」の一覧に残っていた記載ミスを発見・修正した。
