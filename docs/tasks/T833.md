# T833. 停止密度の折れ線が早く飽和し、上位の段階が区別できない

規模S（較正の判断はユーザー）。
状態: 未着手（2026-09-14、[T831](T831.md)完了時に分離）

## 背景

停止密度（`axis_abdaded0be20`）の折れ線は**5回/kmで難易度100に達する**
（`[[0,0],[0.5,20],[1.5,50],[3,75],[5,100]]`）。一方その軸の段階の境界は
`[2, 4, 7, 12]`（回/km）に置かれており、**上2つ（7・12回/km）はどちらも難易度100へ写る**。

結果、地図が塗る値のスケールでは段階が5つから4つへ減る
（[T809](T809.md)の実測: `[58.3, 87.5, 100.0]`）。減った分だけ体感ラベルの件数（5件）が
段階数と合わなくなり、**ルート後の凡例ではこの軸だけラベルが出ない**
（[T831](T831.md)。ずらして添えると「83m以下で1回停止」が実際には143m以下すべてを指す嘘に
なるため、数値だけにしている）。

利用者から見ると、**7回/kmの道と12回/kmの道がルート線で同じ色になる**。停止が多い側は
実走の負担が大きく変わる範囲のはずで、そこが1色に潰れている。

## 対応方針

較正の問題なので、実データの分布を見てから決める。

- 折れ線の飽和点（現在5回/km）を、段階の境界の上端（12回/km）に見合う位置まで伸ばす。
- または段階の境界を折れ線に合わせて詰める（上限を5回/km付近にする）。

どちらもaxis_adminのAPI経由で行う（軸スタジオのGUI、公開軸なので
unpublish→PUT→republish。CLAUDE.md「コミット時の同期ルール」）。開発DBだけの反映で完了に
しないこと（[docs/deployment-sync.md](../deployment-sync.md)）。較正後は
`backend/scripts/dump_axis_definitions_snapshot.py`でスナップショットを更新する。

**較正が済めば[T831](T831.md)のテストはそのまま通る**——「ラベルが出ないのは畳まれた軸だけ」
という性質で書いてあり、飽和が解ければその軸はラベルが出る側へ移る。
