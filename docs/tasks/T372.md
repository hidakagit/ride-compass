# T372. 出発地点マーカーをドラッグ移動可能にし、現在地アイコンと統一・地図マーカーのtouch-action漏れを修正 規模S（2026-08-27完了）

状態: 完了


- 背景: T368完了直後、ユーザーから3件の指摘（2026-08-27）。(1)「マップ上スクロールが
  効かないことがある」(2)「赤ピンアイコンと実際の地図上現在地アイコンが異なる。揃えて
  ほしい」(3)「赤ピンアイコンの移動方法が分かりにくい、UI工夫案を再度提案して」。
- (1)の原因: 経由地マーカー（T364）・目的地マーカー（T365）のDOM要素に
  `touch-action`が未指定（既定`auto`）だった。`.locateButton`が同種の問題
  （2本指ピンチが地図上の浮動ボタンに乗った場合の対策）で既に`touch-action: none`を
  持っていたのと同じ理屈で、地図上に重なる小さなマーカー要素にタッチ開始点が乗ると
  ブラウザがマーカー自身の（既定の）タッチ挙動を優先し、MapLibre側のパンジェスチャーが
  確定しないことがある。T364/T365でマーカーの絶対数（経由地最大8+目的地1）が増えた
  ことで発生頻度が上がったと見られる。両マーカーの生成要素へ`touch-action: none`を
  追加して解消した。
- (2)の対応: 出発地点マーカーがmaplibregl.Markerの既定のしずく形アイコンのままで、
  「現在地に移動」ボタン（page.tsx、十字線+中心ドットのSVG）と形が揃っていなかった。
  同じSVGを白背景の円に乗せたカスタム要素へ置き換え、両者の見た目を統一した
  （しずく形と違い左右対称の形状のため、アンカーも"bottom"から"center"へ変更）。
- (3)への対応: UI再提案をAskUserQuestionで実施し、「ピンを直接ドラッグで移動」案が
  選ばれた（T366のボタン武装方式は不採用に転換）。出発地点マーカーへ
  `draggable: true`を付与し、`dragend`で`useLocation.ts: setManualLocation`を
  直接呼ぶ形にした。地図アプリで一般的な「ピンをつかんで動かす」操作そのものであり
  説明用UIが不要になったため、`LocationControl`コンポーネント自体
  （出発地点を手動指定する専用ボタン、T366/T368）を完全に削除した。「現在地に戻す」は
  既存の「現在地に移動」ボタン（`handleLocateMe`）がそのまま兼ねる。ドラッグ操作の
  結果を`location`/`locationSource`へ反映した直後に不要なカメラ移動（ズームリセットを
  含む`flyTo`）が起きないよう、ワンショットの`skipNextFlyToRef`フラグを追加した
  （ドラッグ操作自体で既にその地点は画面内に見えているため）。
- 影響範囲: `LocationControl.tsx`/`LocationControl.test.tsx`を削除、`page.tsx`から
  その呼び出し・関連state（`originArmed`等）を削除、`MapView.tsx`から`originArmed`
  propとhandleClickでの武装チェックを削除。
- テスト: frontend全体691件成功（LocationControl.test.tsx削除ぶんの6件減）、
  tsc/eslintクリーン。実機確認は、同一リポジトリを共有する並行セッションが
  devサーバーを稼働中でNext.jsの単一インスタンス制約によりこのセッションから新規に
  別ポートを立てられなかったため、コードレビューと既存の自動テストでの検証に留めた
  （次回セッションでの実機確認が望ましい）。
