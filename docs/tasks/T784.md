# T784. ルート設定パネルを「生成条件／重みづけ／除外」の3タブへ

規模M。
状態: 完了（2026-09-13）

## 背景

ルート設定パネルは、生成条件・軸の重みづけ・除外道路が1枚の縦並びに積まれており、
軸が増えるほど縦へ伸びる。走行中のスマホで扱う前提では、重みづけの調整だけで
画面を何度もスクロールすることになる。除外道路も「未舗装を除外」等を足す予定があり、
同じ面に混ぜると更に伸びる。

## 対応方針

- パネルを3タブ（生成条件／重みづけ／除外）へ分ける。
- 重みづけタブは内部で縦タブにし、左に軸の一覧（チェックで有効／無効、アイコン＋略名）、
  右に選択中の軸の重み調整と説明を置く。ルート結果パネルと同じ「左に一覧・右に中身」。
- 重み配分の帯グラフは重みづけタブの中に残す。
- 除外タブはハードフィルタの置き場とし、将来の除外条件をここへ足せるようにする。

## 決定（モックを見ながら合意した内容）

- 当初案（重みづけタブの中を軸ごとの縦タブにする）は取り下げた。**必要な軸を選んでから
  全体を見て%を配る**という使い方に対し、1軸ずつ切り替える形は相性が悪く、軸が増えると
  タブ列そのものが伸びる。
- 代わりに**帯グラフを主役**にした。全軸の取り分が高さ固定の1本に収まるため、軸が何本に
  なってもここは伸びない。区間には幅が許すぶんだけアイコンと%を入れ、入らない軸の%は
  チップ側で読む。チップは有効な軸を先頭にまとめ、領域自体に高さ上限＋内部スクロールを
  与えた（**伸びうるのはここだけ**）。
- 円グラフ案は比率の直感は強いが、390pxで184px使ううえ凡例が軸数ぶん伸びるため不採用。
- タブは横のまま（常に3つで増えないため、縦タブの利点が効かない一方、帯の横幅＝精度を
  46px削ることになる）。高さを抑えるため**タブ列は見出し行へ同居**させ、タブ専用の行を
  無くした（ラベルは2文字）。

## 実装メモ

- `Tabs.List`（見出し行）と`Tabs.Content`（本文）が離れるため、`Tabs.Root`と選択状態は
  `page.tsx`が持つ（`RouteForm`は中身だけを描く）。デスクトップの`Disclosure`・モバイルの
  `BottomSheet`をそれぞれ`Tabs.Root`で囲む。
- 除外は`HardFilterPanel.tsx`へ切り出し、`DEFAULT_HARD_FILTERS`もそこへ移した。
- 重み配分の純関数を`lib/routeWeightShare.ts`へ集約（`clampBoundaryDrag`・
  `adjustAxisShare`）。

## 検証

- 実装中に**±が常に押せない**不具合を実機計測で発見（`plusDisabled:true`）。原因は
  「比率どおりの実数を軸ごとに0.01刻みへ丸める」方式で、8軸のとき1%ぶんの端数が全軸で
  消えていたこと。刻みの整数個を最大剰余法で配る方式へ変更し、回帰テスト
  （`routeWeightShare.test.ts`「軸が多くても1%の増減が必ず1ステップ以上動く」）を追加。
- Playwright（dev server実機）で計測: 390pxのシート見出し行は`scrollWidth==clientWidth==208`
  （タブ列を同居させても溢れない）。±を5回押すと勾配11%→15%・風20%→16%で、
  有効な軸の合計は100%のまま。チップ領域は`clientHeight 106 / scrollHeight 155`
  （高さ固定＋内部スクロール）。
- `npx vitest run`（138ファイル1281件）・`tsc --noEmit`・`eslint`いずれも通過。

## 残り

- 下部シートの高さは開いた時点の中身へ合わせたまま合わせ直さないため、タブを切り替えると
  高さが中身に合わない（`BottomSheet`の既存挙動）。利用者が決めた高さを覚える話と一緒に
  [T785](T785.md)で扱う。
