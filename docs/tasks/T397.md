# T397. 軸スタジオUIの3カード再設計（なめらか/ぴったり/かけあわせ） 規模M

状態: 完了（2026-08-29）。既存4カードUIから3カードへ再設計し、実機（Playwright、開発DB接続）で
一連の操作を確認済み。

## 背景

T396（軸スタジオ合成ロジックの2プリミティブ化）に合わせ、`AxisComposer.tsx`のUIも
4枚のカード（「数値の大きさに応じて」/「はい/いいえ、または種類ごとに」/「複数の要素の
有無を数えて」/「他の軸を重みで足し合わせて」）を「なめらか評価」「ぴったり評価」
「かけあわせ評価」の3枚へ再設計した。ウィジェットもパラメータの性質に合わせて使い分ける
（係数・スコアはスライダー+数値の組み合わせ、下ごしらえ[そのまま/絶対値]はラジオボタン、
折れ点はドラッグ式曲線エディタ、かけあわせは折れ点編集UIを出さず純粋な重み付き結合のみに
絞る）方針で実装した。

## 対応方針・実装内容

### カード構成（`SHAPE_KIND_OPTIONS`）

| カード | 裏のkind | 旧カードとの対応 |
|---|---|---|
| なめらか評価 | `breakpoint_linear` | 旧「数値の大きさに応じて」＋旧「複数の要素の有無を数えて」(flag_sum)を吸収 |
| ぴったり評価 | `categorical` | 旧「はい/いいえ、または種類ごとに」のまま |
| かけあわせ評価 | `recipe_then_breakpoint_linear`（draft内部のみ、保存kindは`breakpoint_linear`） | 旧「他の軸を重みで足し合わせて」のまま、UIを簡素化 |

旧flag_sumカードは撤去した。backend側は元々boolean材料をtermsへ入れれば同じ結果
（該当時1・非該当時0として係数と掛け合わされる）が出せる設計だったため、専用の別画面を
持たせる理由が無かった（T396のFlagSumShape撤去と対応）。カードの説明文に両方の具体例
（数値の大きさ・複数要素の有無）を残し、どちらの用途で来たユーザーも迷わないようにした。

### 新規ウィジェット

- **`SliderNumberField`**（新規コンポーネント）: `<input type="range">`+`<input
  type="number">`の組み合わせ。両者は同じstateを指すため常に同期する。値の取りうる範囲は
  材料ごとに大きく異なる（傾斜の係数1.0、車線数の係数0.1、旧flag_sumの加点50等）ため、
  スライダーの範囲はあくまで目安（なめらか係数: -100〜100、かけあわせ係数: -5〜5、
  カテゴリスコア: -100〜100）とし、範囲外の値は数値入力欄から直接指定できる。
  「係数」「スコア」（true/false・値ごと）の3箇所で使用。
- **`BreakpointCurveEditor`**（新規コンポーネント）: 折れ点(breakpoints)をドラッグで
  調整できるSVG曲線エディタ。既存の数値入力行（正確な値の入力・行の追加削除、テストの
  対象でもある）はそのまま残し、この曲線はその可視化＋補助的な操作手段として上に添える
  （両者は同じ`draft.breakpoints` stateを指すため常に同期する）。横軸・縦軸とも現在の
  breakpointsの値から自動スケールする。pointer capture（`setPointerCapture`）でドラッグを
  実装、実ブラウザ（Playwright/Chromium）でドラッグ操作が実際にstateへ反映されることを
  確認済み。jsdom（vitest）ではドラッグの実機的な座標計算・pointer captureの検証が困難な
  ため、jsdomテストは「SVGが描画されること」の確認に留め、ドラッグ操作自体の検証は
  Playwright実機確認で行った（下記「検証結果」参照）。
- **下ごしらえ（preprocess）**: `<select>`（そのまま/絶対値の2択）から常時両方が見える
  ラジオボタンへ変更（選択肢が2つしかない場合はドロップダウンよりラジオボタンの方が
  迷わないという判断）。**「かけあわせ評価」ではこの項目自体を表示しない**（下記参照）。

### 「かけあわせ評価」の簡素化

ユーザー判断（「純粋な重み付き結合（nX + mY）に絞るのでよい」）に基づき、下ごしらえ・
折れ点の編集UIを一切出さない。保存時は常に`preprocess: "identity"`・
`breakpoints: [[0,0],[100,100]]`（恒等クランプ）が送信される（`renderShapeKindStep`の
カード切替ハンドラが元々このデフォルトを設定していたため、buildShape側の変更は不要
だった——UIを非表示にするだけで実現できた）。従来この画面で選べた「絶対値」前処理
オプションは撤去した（軸スコア同士の組み合わせで絶対値を取る意味のあるユースケースが
無く、「純粋な結合」という方針とも整合しないため）。

### 型・データフローの整理

- `Draft`インターフェースから`flags`/`cap`フィールドを撤去（`terms`/`breakpoints`に統合）。
- `buildShape()`: 常に`kind: "breakpoint_linear"`または`"categorical"`の2択へ正規化
  （3つ目の分岐が無くなった）。
- `draftFromExisting()`: 全termがboolean材料かの構造判定（旧flag_sum検出用）を撤去した
  （T396時点ではflag_sum相当を「なめらか評価」と区別して開くために必要だったが、T397で
  そのカード自体を統合したため不要になった）。全termが他軸参照かどうかの判定
  （「かけあわせ評価」検出用）はそのまま維持。

## 検証結果

- vitest: フロントエンド全体717件パス（`AxisComposer.test.tsx`は旧flag_sum系テストを
  「なめらか評価でboolean材料の係数をマイナスにできる」等へ書き換え、旧カード名を
  参照していた箇所を全て新カード名へ更新）。
- `tsc --noEmit`: エラー0件。
- `npm run build`（本番ビルド）: 成功（devサーバとの`.next`競合で最初1回失敗したが、
  devサーバ停止後の再実行で成功を確認——同一セッション内でdev/build/testを並行実行
  すると競合するという既知の教訓どおり）。
- **Playwright実機確認**（dev DB接続、`/admin`実ログイン）: 新規軸作成フローで
  1) 3カードの新しい文言が表示されること、2) 「なめらか評価」で係数のスライダー+数値欄・
  下ごしらえのラジオボタン（旧`<select>`が消えたこと）・曲線エディタSVGが表示されること、
  3) 曲線エディタの点を実際にドラッグすると対応する折れ点の数値入力が変化すること
  （100→69の変化を実測）、4) 「かけあわせ評価」では下ごしらえ・折れ点編集UIが一切
  表示されないこと、5) 「ぴったり評価」でtrue/falseスコアのスライダーが表示されること、
  を全て確認した。

  余地がある。

- GUIに編集欄が無い4フィールド（`priority_overrides`・`display_override`・
  `time_scope`・`supports_route_coloring`）は今回もスコープ外のまま。
