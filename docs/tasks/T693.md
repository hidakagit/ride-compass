# T693. CIの生成物ドリフト検知を回復し、静的軸カタログを再生成する 規模M

状態: 未着手（2026-09-10起票、統合レビュー第6回 I-1(a)＋I-3。**最優先**）

## 背景

CIの生成物ドリフト検知が**常に素通り**している。`.github/workflows/ci.yml:125`の
`- run: git diff --exit-code -- frontend/src/types/generated/`は、ジョブ既定の
`defaults.run.working-directory: backend`（同`:64-66`）を継承して`backend/`で実行されるため、
pathspecが`backend/frontend/src/types/generated/`へ解決され**マッチ0件＝差分なしとして常にexit 0**になる。
直前2ステップ（`npm ci`・`npm run generate:api`）は明示的に`working-directory: frontend`を
指定しているのに、この検証ステップだけ指定が無い。

原因は[T350](T350.md)（`13794155`）で独立していた`api-contract`ジョブを`backend`ジョブへ
統合したこと。旧ジョブは**ステップごとに**`working-directory`を書いており検証ステップだけ
無指定＝リポジトリルートだったが、統合先はジョブ既定で`backend`を持つため無指定の意味が変わった。

その空振りの陰で、`frontend/src/types/generated/axis-catalog.json`が本番の軸集合と乖離している。
`backend/fixtures/axis_definitions_snapshot.json`（revision 64）の公開軸は10本だが、
静的カタログは9軸で**旧`stop_density`を持ち`axis_abdaded0be20`（停止密度）・`curvature`（蛇行）を欠く**。
スナップショットは`772a9189`→`581586c9`→`509f0210`と3回更新されたが、生成物の最終更新は`45ffd36b`。

## 実施順序（**この順でないと途中でCIが赤になる**）

1. `backend/scripts/export_openapi.py`の`axis-catalog.json`書き出し（`:186-232`）へ
   `description`・`raw_value_unit`を足す。現在の`axes[]`のキーは18個で、実行時API
   （`GET /api/axis-catalog`）が返すこの2つを含まない（`map_value_unit`は書き出している）。
2. `frontend/src/lib/evaluationAxes.ts:53-64`の`PREFERENCE_AXIS_DESCRIPTIONS`（軸id→説明文の
   手書き辞書）を撤去し、生成物由来へ寄せる。
3. 生成物を再生成してコミットする。
4. `ci.yml`の検証ステップへ`working-directory: .`を付ける。
5. **ガードが実際に効くことを1回確認する**（生成物を意図的にdirtyにしてCIが落ちるのを見る）。

## 2を飛ばしてはいけない理由

`evaluationAxes.test.ts:79-82`が「全軸が説明文を持つ」ことを強制しているため、
3だけ行うと`PREFERENCE_AXES`へ`axis_abdaded0be20`・`curvature`が入り、
`PREFERENCE_AXIS_DESCRIPTIONS`にキーが無く`description===""`でテストが落ちる。
赤を消すには軸ごとの説明文をfrontendへ手書きすることになり、
docs/design-principles.md 構造仕様2（新しい軸の追加にfrontendのコード変更を要しない）を
**強制的に破らせる**状態になる。

## 影響の限定（着手時に過大評価しないための確認）

`page.tsx:1352-1357`は`axisCatalog.loaded`が偽なら`route_preference`自体を省略し
backendの既定値へ委ねる自己防衛を持つ。**重みキーの不一致による422は起きない。**
影響はフェッチ完了前・失敗時の表示層（地図レイヤー・ラベル・レンズ選択肢・重みパネル）に限られる。
