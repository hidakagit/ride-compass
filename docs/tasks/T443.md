# T443. gradientの境界値がルート確定前の表示（評価軸ライン・環境グループ塗り）に未配線

状態: 完了（2026-08-31）

- 背景: `統合レビュー第2回`（`.claude/commands/review/history/2026-08-30_all_2.md`P1-2）の
  指摘。T440 Part Cで`gradientAxisColorExpression()`・`gradientFillColorExpression()`
  （`frontend/src/components/Map/gradientAxisLayer.ts`・`gradientGridFill.ts`）へ
  `boundaries`引数を追加したが、実際の呼び出し元`MapView.tsx:1507`・`:1150`は今回も
  この引数を省略しており、既定の`GRADIENT_BOUNDARIES`（固定4値）へフォールバックする。
  ルート確定後（post-route）の色分けは`axis.display_thresholds_override`を正しく読むため、
  pre-route/post-routeで異なるしきい値を使う不整合状態になっている。
- Impact: `docs/improvement-plan.md`のT440タイトル「完全同期する」、`docs/architecture.md`の
  T440節（2580〜2630行、既知の未了項目への言及なし）が、この点で実態より完了度を高く
  見せている。軸スタジオで`display_thresholds_override`を変更しても、プレルート表示
  （評価軸ライン・環境グループの塗り）は追従しない。
- 対応方針: `page.tsx`が`useAxisCatalog()`から取得済みのgradient軸の
  `display_thresholds_override`を、`MapView.tsx`へ1〜2propsで配線する（T440.mdが既に
  設計方針を明記済み）。合わせて`docs/architecture.md`のT440節へ、配線完了までの間は
  既知の未了項目である旨を1〜2行追記する（配線完了後は削除）。
- Confidence: High（統合レビューのfrontend/Mapシャードが呼び出し元コードを直接確認）。
- 規模S。

## 実施記録（2026-08-31完了）

- **配線**: `secondaryAxes.ts: SecondaryAxisSummary`へ`displayThresholdsOverride`
  フィールドを追加（`axis.display_thresholds_override`をそのまま反映）。page.tsxが
  `axisCatalog.secondaryAxes`からgradient軸のエントリを引いて`gradientBoundaries`を
  組み立て、`MapView`へ新規propとして渡す。MapView側は`ensureGradientFillLayer`を
  `makeEnsureGradientFillLayer(boundaries)`ファクトリへ変換（windAxis/gradientAxisの
  `makeEnsureDedicatedWayValueLayer`と同型）、`buildStaticOverlayLayers`が第2引数として
  `gradientBoundaries`を受け取り`gradientAxisColorExpression`/`gradientFillColorExpression`
  両方へ渡すよう修正した。
- **T440.mdの「既知の未了項目」への解消リンクを追記**。
- **検証**: `tsc --noEmit`（frontend全体）・eslint（変更3ファイル）・vitest
  （gradientAxisLayer/gradientGridFill/secondaryAxes/MapView.overlayFilters、新規回帰
  テスト1件含め計23件）すべて通過。開発サーバー実機（backend+frontend both起動）で
  `GET /api/axis-catalog`のgradient.display_thresholds_overrideが`[-2,2,6,10]`で
  正しく取得され、コンソールエラー・ビルドエラー無しを確認した。**視覚的な差分確認は
  できていない**——現在のGRADIENT_BOUNDARIES既定値（`routeStyleModes.ts`）が偶然
  軸スタジオの現在値と同じ`[-2,2,6,10]`のため、配線前後で見た目は変わらない
  （軸スタジオでこの値を変更したときに初めて可視化される）。地図キャンバスの
  スクリーンショット確認はこのBrowserペイン環境の既知の制約（T440.md参照）で
  タイムアウトした。
