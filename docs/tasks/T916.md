# T916. 起伏の陰影が、関東平野の傾きでは出ていても気づけない

状態: 完了（2026-09-17）
規模: S

## 背景

ユーザー指摘「起伏がみにくい。確かに勾配で濃淡ついているが気づけない」。

[T914](T914.md)で入れた陰影は、MapLibreの既定の計算方法（`standard`）を使っていた。これは
傾きのsinに比例して塗るため、緩い地形では実効の不透明度が極端に小さくなる。シェーダの式
（`hillshadePrepareFrag`・`hillshadeFrag`）から、影の実効の不透明度と基礎地図の背景
（`#f8f4f0`）に対するΔE（CIE76）を計算した（z13、緯度35.7度、共通の濃さ0.55）:

| 地形の傾き | 既定（standard・倍率1） | igor・倍率3 | igor・倍率5 | igor・倍率8 |
|---|---|---|---|---|
| 1° | a=0.009 **ΔE 0.6** | 3.7 | 6.1 | 9.5 |
| 2° | a=0.018 **ΔE 1.2** | 7.3 | 11.6 | 16.9 |
| 3° | a=0.027 **ΔE 1.8** | 10.6 | 16.1 | 21.9 |
| 5° | a=0.045 ΔE 3.1 | 16.1 | 22.4 | 27.5 |
| 10° | a=0.091 ΔE 6.1 | 24.6 | 29.6 | 32.9 |
| 20° | a=0.179 ΔE 12.2 | 31.3 | 34.2 | 35.9 |

ΔE 2程度が「並べれば分かる」差。既定では3°でも1.8で、**見えないのが正しい挙動**だった。
台地の崖線（10〜20°）でも6〜12にしかならない。

## 対応

**計算方法を`igor`にする。** 傾きのarctanに比例するため、同じ傾きで`standard`の倍以上の
濃さになる。`hillshade-exaggeration`は上限の1（igorは傾きの大きさをこの値の2倍してから
角度へ直す）。

**`basic`・`multidirectional`は採れない**——シェーダを読むと、平坦な画素（`deriv`が0）でも
`cang = sin(altitude)`が0.5を超えて光を塗る。面レイヤの規則「値のある所だけ塗る」
（[T913](T913.md)）を満たさない。`combined`は平坦で0になるが、`igor`より緩い斜面に弱い。

**標高を垂直方向へ5倍して読む。** `raster-dem`のcustom encoding
（`h = r*redFactor + g*greenFactor + b*blueFactor - baseShift`）へ、mapbox encodingの係数を
5倍したものを渡す。**タイルの値は実際の標高のまま**で、読み方だけを変える——強調は表示の
選択であって、データの性質ではない。

倍率5は上の表から選んだ。3では2°が7.3で弱く、8では5°（27.5）と10°（32.9）の差が潰れる。
5なら1°から20°まで6.1→34.2と段が付く。

**暗黙の前提**: 濃さはズームにも依る（MapLibreは1画素あたりの標高差から傾きを求めるため、
拡大するほど同じ斜面の濃淡が薄くなる）。igor・倍率5での2°は z11で16.2／z13で11.6／
z15以上で8.0。倍率は広域で見るときを基準に決めている。
