# T691. 道の蛇行を軸にする（曲がりの少ないルートを選べるようにする） 規模M

状態: 実装済み・本番反映待ち（2026-09-10）

## 背景

停止密度を効かせると、静かだが**くねくね曲がる裏道**へ案内される。本番の同一起終点で
実測すると、軸に沿った候補は最短より3km遠回りした上に曲がる回数が3.6倍だった。

| 候補 | 距離 | 蛇行 | 30度以上の折れ |
|---|---|---|---|
| 最短 | 9.19km | 269度/km | 14回 |
| 候補2（軸最適） | 12.19km | 463度/km | 51回 |
| 候補3（軸最適） | 9.48km | 449度/km | 32回 |

右左折の回数そのものは連続する2本のEdgeの関係で決まるため、Edge単体の材料で表す今の
軸機構には載らない（探索も`edge_cost_fn(edge_index)`で直前のEdgeを知らない）。
edge-based化はレスポンスに響くため採らない。

## 対応方針

**道そのものの蛇行**をEdge単体の属性として持つ。折れ線の頂点ごとの方位変化を積み上げ、
距離kmで割った「度/km」。既存の`road_edges.geom`だけで計算でき、新しい取込は要らない。
静的スコア行列の列が1つ増えるだけなので探索コストは変わらない。

## 実施内容

### 蛇行の定義（`domain/geo.py: curvature_deg_per_km`）

折れ線の頂点ごとの方位変化（`bearing_between`）の絶対値を積み上げ、距離kmで割る。
直線は0、つづら折りほど大きい。連続する同一頂点は方位が定まらないため間引く。
**頂点3点未満・距離0はNoneであって0ではない**——0にすると測れない区間が「まっすぐな
良い道」として評価に混ざる（[T655](T655.md)の「未集計を0と読んだ」障害と同じ形）。

進行方向を反転しても実質同じ値になる（fwd/bwdのEdgeへ同じ値を持たせる）。厳密には
大圏航路のA→BとB→Aの方位がずれるぶん相対1e-4未満の差が出るが、度/kmの目盛りでは
無視できる。

### 保存と運搬

`build_road_graph`がsplit時に算出し`road_edges.curvature_deg_per_km`（migration 0035、
NULL可＝未計算）へ保存する。そこから
`EdgeMaterialBundle` → `metrics["geometry"]["curvature"]` → 材料
`curvature_deg_per_km`（単位`度/km`、`additive=true`）へ載る。**静的スコア行列の列が
1つ増えるだけで探索コストは変わらない**（探索の`edge_cost_fn(edge_index)`は不変）。

`EdgeMaterialTable`・`LeanRoadGraph`のpickle列が変わるため`TILE_MATERIALS_CACHE_VERSION`
を8→9、`CACHED_TABLE_SIGNATURE`を更新した（列署名の照合テストが正しく発火して気づけた）。

### 既存行のバックフィル（`precompute_edge_curvature.py`）

既存500万行は再splitされるまでNULLのままなので、列追加だけでは埋まらない。PostGISの
`ST_Azimuth`で完結させPythonへ行を持ち出さないバッチを用意した（20万件ずつ）。

**`ST_Azimuth`はgeographyへキャストして呼ぶ**。geometry（4326）のままだと経度・緯度を
そのままx/yとして扱う平面計算になり、緯度による経度の縮みを無視する。実際に検証用の
ジグザグで450.0対390.8（15%差）となり、同じ列に2つの定義が生まれかけた。キャスト後は
392.0対390.8（0.3%、球と回転楕円体の差）まで一致する。
`tests/test_precompute_edge_curvature.py`が両者の一致を許容差付きで固定する。

### 地図表示は今回入れない

タイルは`osm_raw_ways`単位で焼くのに対し蛇行はEdge単位のため、way単位の集計を別途
用意しないと焼き込めない。`tile_property=None`とし、地図レイヤーを持たない軸として
公開する（勾配・風も`axis_display_for`が`kind="none"`を返す既存の状態で、ルート探索と
ルート結果の表示には影響しない）。

## 軸スタジオで作る軸

| 欄 | 値 |
|---|---|
| 表示名 / チップ名 | 蛇行 |
| カテゴリ | 観測 |
| 計算式 | 連続演算（breakpoint_linear） |
| 材料 | `curvature_deg_per_km` × 重み1.0（required=false） |
| 折れ点 | `0→0` / `100→25` / `300→50` / `600→75` / `1000→100` |
| 既定の重み | 0.1 |

**名前は「道なり」ではなく「蛇行」**（ユーザー指摘、2026-09-10）。軸の得点は難易度
（高いほど悪い）なので、「道なり」だと高得点＝良いと逆に読める。勾配・風・事故密度・
停止密度と同じ「悪いものを名前にする」側へ揃える。

## 本番の実測（2,763km分、延長加重）

| 分位 | 度/km | 上記折れ点での得点 |
|---|---|---|
| p50 | 95 | 23.8 |
| p75 | 453 | 62.8 |
| p90 | 919 | 94.9 |

得点帯ごとの延長割合は 0〜20点=47.9% / 20〜40=14.4% / 40〜60=11.3% / 60〜80=9.8% /
80〜100=16.6%。満点への張り付きは16.6%で[T686](T686.md)の警告閾値（50%）に余裕がある。

道路種別ごとの延長加重中央値: trunk 20（4.9点）・primary 36（9.0点）・tertiary 44
（11.1点）に対し、**residential は中央値141（30.1点）でp90が1067（100点）**。同じ住宅街
でも直線的な道と蛇行した道が分かれており、「静かだけどくねくね」を分離できる。

同一起終点の3候補へこの折れ点を当てると 最短39.7点 / 候補2が55.6点 / 候補3が57.8点。
現在の総合難易度では候補2（35.2）が最良だが、蛇行軸では16点悪くなる。
