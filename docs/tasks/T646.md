# T646. MSM配信が止まったことを検知する（同期バッチの鮮度WARNING） 規模S

状態: 完了（2026-09-08）

## 背景

[T645](T645.md)で予報の取得元を気象庁MSMのローカル同期（`msm_client.py`、30分間隔の
APSchedulerジョブ）へ移した結果、**配信元が止まってもアプリ側は静かに古い予報を配り続ける**
状態になった。同期ジョブは成功・失敗どちらもINFOで「取得=N件」を出すだけで、「更新が
来ていない」ことは正常時（内容が変わらずETagで304）と区別がつかない。予報終端が現在時刻へ
追いついた瞬間に初めて風グリッドが502になり、それまで誰も気づけない。

`docs/logging.md`の「エラー・鮮度に関わる事象はdebug_modeに関わらずWARNING以上で常時出す」
という方針に対して、この経路だけ穴が空いている。

## 実測（2026-09-07、遅延が実際に起きた際の値）

配信元（Open-MeteoがAWS Open Dataへ載せるjma_msm）のrun公開が遅れ、9月7日は20時（JST）
時点で0000Z・0300Zの2本しか公開されていなかった（前日までは毎日8本すべて公開）。

- 公式仕様: 気象庁のMSMは1日8回（03,06,09,15,18,21UTCが39時間予報、00,12UTCが78時間予報）。
  Open-Meteo側のモデル諸元も「Every 3 hours」
- 通常の公開遅れはrun初期時刻から約3.5時間。このときは約5時間で、その後回復した
- 同時刻に他モデル（dwd_icon_d2・jma_gsm）は正常に更新されており、パイプライン全体の
  障害ではなくMSMの取り込みが遅れていた

## 対応方針

同期ジョブ（`main.py: _sync_msm_job`／`msm_client.refresh`）で、配信元メタ情報をもとに
以下をWARNINGで出す。閾値は上記の実測（正常な遅延＝5時間）で誤報しない値として選ぶ。

| 条件 | 閾値 | 意図 |
|---|---|---|
| 最新runが古い | 6時間以上前 | 3時間おきの更新を2本連続で落とした状態 |
| 予報が尽きかけ | 予報終端が12時間先を切った | 実害（風グリッドの502）が出る前に気づく |

あわせて、最新run時刻・予報終端を外から確認できるようにする（`/api/debug/stats`へ載せるか、
既存の鮮度台帳[`derived_data_freshness.py`]へMSMを対象として加えるかは着手時に決める。
現状MSMは鮮度台帳の対象外）。

## 完了条件（着手時に確定）

- 配信が止まった状態を再現（メタ情報を古い値に差し替える等）してWARNINGが出ること
- 通常の遅延（5時間程度）では発報しないこと

## 実施内容（2026-09-08）

対応方針の表どおりのしきい値で実装した。

| 追加したもの | 場所 |
|---|---|
| `MsmFreshness`（最新run・予報終端・経過時間・残り時間）と`freshness_from_meta()` | `msm_client.py` |
| `warn_if_stale()`（上の2条件をWARNINGで出す。メタを読めない場合も黙らずWARNING） | 同上 |
| 同期完了ログへ「残り=N時間」を追加 | `refresh()` |
| `GET /api/debug/stats`の`msm`（最新run・予報終端・経過/残り時間・healthy） | `api/routers/health.py` |
| `/admin`システム状況パネルの1行表示（滞留時は枠線を警告色にし文言を出す） | `SystemStatusPanel.tsx` |

`refresh()`は同期に使ったのと同じ時刻（`time.time()`）で鮮度を判定する。実クロックを
直接見ると、時刻を固定しているテストが実在しないrunを「古い」と誤判定する。

**APIへ載せるだけにしなかった**理由は、外から確認できる状態にしても運用で見なければ
気づけないため。既にバージョン・外部呼び出しサマリを見るために開くパネルへ並べた。
鮮度台帳（`derived_data_freshness.py`）は世代ごとの行数を数える仕組みで、ファイル同期の
MSMは形が合わないため対象にしていない。

## 検証

完了条件どおり、両方向をテストで固定した（`tests/test_msm_freshness.py` 4件、
`tests/test_msm_client.py`へ2件追加）。

- 配信が止まった状態（最新run 12時間前・予報終端が現在時刻）→ 2つのWARNINGが出る
- 通常の公開遅れ（最新run 5時間前・予報終端34時間先）→ WARNINGを1件も出さない
- メタ情報を読めない → 黙って通さずWARNINGを出す
