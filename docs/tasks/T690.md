# T690. 目的地モードで最短距離ルートを既定で出し、好みのルートとの距離差を示す 規模M

状態: 未着手（2026-09-09起票）

## 背景

目的地モードは軸の重みで作った合成コストで経路を選ぶため、返る候補はすべて「軸設定に
沿った経路」になる。利用者は好みのルートを走る**対価**（最短距離からどれだけ余分に
走るか）を知らないまま選んでいる。

「32.5kmで約26回止まる」（[T687](T687.md)）と同じ構図で、得点だけでは判断できない。
余分な距離は、軸設定を強めるかどうかを決めるための判断材料になる。

## 対応方針（未確定）

最短距離ルートを既定で1本出し、他の候補に対して「+◯km」を添える。

技術的には安い。`select_via_nodes`が使う`build_shortest_path_tree`は`edge_cost`を
引数で受けるため、軸コストの代わりに`edge_length_m`を渡せば距離最短の木が得られる。
起点からの前向き木1本で目的地までの最短経路が確定する（代替経路のためのvia-node方式は
不要）。追加コストはDijkstra 1回。

## 決めていない論点

1. 最短ルートを候補一覧の1枚として混ぜるか、比較用の基準線として別枠に置くか
2. 最短ルートが軸最良ルートと一致した場合の見せ方
3. 「+◯km」をどこへ出すか（候補タブ／ルート結果パネル）
4. 周回モードの扱い（距離が目標距離で決まるため対象外とする想定）
