# T845. 本番DBの状態が、何を母数にした何件なのか読めない

規模S〜M。
状態: 完了（2026-09-14。ユーザー指摘「表示順がよくわからない。個別表示されているテーブルと、
その他15テーブルの違いが分からない。総数なのか分からない。全体が何件で、それぞれ確認できて
その中で注意すべきものを出してほしい」から）

## 背景

`DbStatusPanel`は取込・接続・テーブル・split範囲を同じ見た目の1行へ揃えて並べるが、種別の
区切りも母数も画面に無いため、並び順の根拠（テーブルは容量の大きい順）と「その他15テーブル」
が何分の15かが読めない。畳んだ行の名前も、分けた基準（注意の有無）を名乗っていない。

## 対応方針

行の見た目を揃える判断（[T840](T840.md)）はそのまま維持し、**揃えたことで失われた情報を
見出しと母数で補う**。

1. ヘッダーへ母数を出す（テーブルの数・行数の合計・DB全体の容量）。畳んだ行の「Nテーブル」
   が何分のNかは、全体の数が同じ画面に無いと読めない。
2. 行を群へ分け、群ごとに見出しを置く。並び順に根拠がある群は根拠も見出しへ書く
   （テーブルは容量の大きい順）。
3. 畳んだ行が分けた基準を自分で名乗る（「その他N」→「注意なし Nテーブル」）。単位も上の行と
   揃える（容量だけでなく行数も出す）。

backendは変更しない——母数は既に返っている`tables`から数えられる。

## 実装メモ

- `rowsFromStatus`（平坦な行の列）を`groupsFromStatus`（`{title, rows}`の列）へ変えた。
  split済み範囲の行は地図を遅延初期化する専用コンポーネントのままで、見出し「範囲」だけを
  上に置く。
- 接続の行名を「接続」から「同時接続」へ変えた。群の見出しと行の名前が同じ文字列だと、
  どちらを指しているのか読めない（テストでも同名2要素として衝突した）。
- ヘッダーの母数は`summaryOf`として切り出した。

## 検証結果

- `npx vitest run src/components/AxisStudio/DbStatusPanel.test.tsx` → 8 passed。
  母数の文字列（`2テーブル ・ 5,182,739行 ・ 675 MB`）と4つの見出しの存在をテストで押さえた。
- 畳んだ行の名前を検証するテストは「注意なし 1テーブル」を`closest("details")`で辿り、
  注意の無いテーブルがその中にだけ在ることを確認している（隠して終わりにしていない）。
- 横幅の実描画確認は不要と判断した。ヘッダーは`.controls`（`flex-wrap: wrap`）の中の
  折り返す`<span>`で、文字列が伸びても横へはみ出さない。見出しは通常の`<li>`1行。
- `npx tsc --noEmit`は`src/app/layout.tsx`の`LayoutProps`未生成エラー1件のみ（本変更と無関係、
  `.next/types`未生成の環境由来）。`npx eslint`は0件。
