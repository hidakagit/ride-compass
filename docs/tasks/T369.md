# T369. 推定グループの軸タイルを観測グループと同じ見た目に統一・凡例パネルの画面右端はみ出しを解消 規模S（2026-08-27完了）

状態: 完了


- 背景: T367完了報告のスクリーンショットに対するユーザー指摘2件（2026-08-27）:
  「凡例が見切れる」「推定軸のアイコングループも、観測アイコングループのような
  サイズのアイコンにして。他と同じく4文字略字までアイコン含めたい」。
- 凡例見切れの原因・対応: `MapOverlayControls.tsx: toggleExpanded`が凡例パネルの
  `left`（rect.rightを起点に右へ展開）をビューポート幅で一切clampしていなかった
  （`maxWidth`側はMath.max(160, ...)で下限は設けていたが、`left`自体が既に画面右端に
  近いタイル——推定グループ末尾の軸等——では、その下限160pxぶんがそのままビューポート
  外へはみ出していた）。`left`を`Math.min(rawLeft, window.innerWidth - MIN_PANEL_WIDTH_PX
  - PANEL_GAP_PX)`でclampし、パネルが必ず画面内に収まるようにした。
- タイルサイズ不揃いの根本原因（調査で判明、T367完了報告時点では未発覚）: 二重の
  問題があった。
  1. モバイル幅限定で軸タイルをアイコンのみへ縮小し略名を隠す既存仕様
     （`MapOverlayControls.module.css: .chipRowItemAxis`の`@media (max-width: 640px)`
     ブロック）があった。ユーザー要望により全画面幅で撤去し、常に観測グループの
     メンバータイルと同じサイズ・略名表示にした。
  2. より根本的に、ramp軸駆動の地図チップ（推定グループの軸タイル・地図の見え方
     パネル）は、backendが持つ`chip_label`（4文字以下の略名、確定命名表）が
     フロント側の変換パイプラインで一切配線されておらず、常に正式名
     （`axis.label`、例:「車の圧迫感」5文字・「自転車インフラ」7文字）へ
     フォールバックし続けていた——`RampAxis`インターフェース（axisLayers.ts）に
     `chipLabel`フィールド自体が無く、`rampAxesFromCatalogAxes()`も`chip_label`を
     読んでいなかった。全ramp軸（既存6軸含む）に共通する既存バグで、T367で
     「自転車インフラ」（7文字、突出して長い）を追加したことで初めて目立った。
     `RampAxis.chipLabel`を新設し`rampAxesFromCatalogAxes()`で配線、
     `mapLayers.ts: buildMapLayers`のramp軸`MapLayerDescriptor`へも反映。
     `MapOverlayControls.tsx: renderAxisTile`の専用レイヤーを持たない軸の分岐
     （`chipLabel={axis.label}`だった箇所）も`axis.chipLabel`（`SecondaryAxisSummary`
     が元々持っていたが未使用だったフィールド）へ修正。
- 結果（実機確認、モバイル幅375px）: 推定グループの7軸タイルが「勾配・舗装・停止密度・
  圧迫感・事故密度・夜間・自転車道」という4文字以下の略名で、全て51×43pxの同一
  サイズで並ぶことを確認。凡例パネルもビューポート内（右端367px<幅375px）に収まる
  ことを確認。
- テスト: `MapOverlayControls.test.tsx`の1件（専用レイヤーの無い軸のボタン名を
  「舗装質」で問い合わせていた箇所、chip_label化で「舗装」に変わったため更新）を含め
  frontend全体697件成功、tsc/eslintクリーン。
