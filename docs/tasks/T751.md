# T751. 「未起票の残り」を検知器にする

規模S。
状態: 未着手

## 背景

[T750](T750.md)で完了前チェックを畳んだ際、旧チェック1（分割元タスクの子タスクに未起票の
フォローアップが残っていないか、`docs/tasks/Txxx.md`を「未起票」「別タスク」「スコープ外」
等の語で検索する）は、内容が完全にgrepで済むにもかかわらず自己申告のままだった。
自己申告のチェックは守られていない実績がある（T696の派生2件が本文に残ったまま`[x]`化され、
[T745](T745.md)・[T746](T746.md)として後から起票された）。

## 対応方針

`scripts/review_checks.py`へ検知器を1本足す。`docs/tasks/*.md`のうち、先送り・別扱いを表す
語（「未起票」「別タスク」「スコープ外」「今後」「後日」等）を含む段落に、起票済みタスクへの
リンク（`tasks/Txxx.md`）も、起票しない理由を表す語（「見送り」等）も無いものを違反とする。

- 語の一覧そのものを手で伸ばし続けないこと（構造仕様12）。まず現在の`docs/tasks/*.md`全件で
  どの語が実際に先送りを表しているかを数え、割合の低い語を足す前に「段落にTxxxリンクが
  あるか」という側の条件で足りるかを検討する。
- 既存分の違反が大量に出る可能性がある。その場合は`DETECTOR_ENFORCEMENT`で
  `staged`/`since`のみ強制とし、`full`は参考出力に留める（`source_narrative`と同じ扱い）。
- 導入時は`review_checks.py mutate`のプローブへこの検知器を足し、わざと違反を入れて
  実際に落ちることを確認する（T750「修正の原則」の「効いているを確認して完了にする」）。

この検知器が入れば、CLAUDE.mdに残した人手チェック2（`[x]`化時に本文へ残る未実施項目の
別Txxx起票）も大部分が機械側へ移る。
