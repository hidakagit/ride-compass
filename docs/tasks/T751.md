# T751. 「未起票の残り」を検知器にする

規模S。
状態: 完了（2026-09-11）

## 背景

[T750](T750.md)で完了前チェックを畳んだ際、旧チェック1（分割元タスクの子タスクに未起票の
フォローアップが残っていないか、`docs/tasks/Txxx.md`を「未起票」「別タスク」「スコープ外」
等の語で検索する）は、内容が完全にgrepで済むにもかかわらず自己申告のままだった。
自己申告のチェックは守られていない実績がある（T696の派生2件が本文に残ったまま`[x]`化され、
[T745](T745.md)・[T746](T746.md)として後から起票された）。

## 対応方針と、設計を変えた経過

最初に書いたのは「先送りを表す語を含む段落に、Txxxリンクも『今後もやらない』の断りも
無ければ違反」という素直な設計だった。入れる前に母集団を測った（T750で足した原則「緩和は
影響を測ってから入れる」の裏返しで、検知器も入れる前に何件鳴るかを測る）:

| 設計 | 母集団 | 鳴る件数 | 実態 |
|---|---|---|---|
| 語（未起票/別タスク/スコープ外/今後/後日）×段落 | 540タスク | 48 | 大半が実装メモの地の文 |
| 語を厳格化（未起票/スコープ外/別途起票/別タスクで） | 540タスク | 22 | それでも大半が誤検出 |
| **見出し（派生/積み残し/フォローアップ/残課題/残作業/未検討）×節** | 540タスク | 22 | 半数程度が実際の残り |

語での判定は、実装メモの散文に同じ語が現れるため区別できない。決め手は、T696が実際に
取りこぼした形を当ててみたことだった——当時のT696.mdは先送りの語を1つも使っておらず、
`## 派生（同じメソッド周辺の関連指摘）`という**見出し**の下に番号の無い箇条書きが並んで
いた。語ではなく構造（残りを置く節の見出し）で拾う設計へ変更した。

判定の単位を変えたうえで、次の3点を満たす形にした:

- **`[ ]`→`[x]`の瞬間だけを見る**（`newly_closed_task_numbers`）。機械抽出は`- [ ]`行しか
  見ないため、本文に埋もれた残りが以後拾われなくなるのはこの瞬間に確定する。差分の前から
  `[x]`だったエントリは除き、節の並べ替えで完了済みを蒸し返さない。
- **受け皿の番号は素の言及（`T901`）でも数える**。リンク形式を要求すると、本文で番号だけ
  挙げている正常なケースが鳴る。
- **節の範囲は次の見出しで止める**。止めないと、後続の「検証結果」等に出てくる無関係な
  Txxxを受け皿と誤読して黙って解消扱いになる。

**強制はしない**（`DETECTOR_ENFORCEMENT`は空集合＝参考出力）。`## フォローアップ1（…完了）`の
ように、節そのものが完了済みの記録であることがあり、残りかどうかは人にしか分からない。
ブロックすれば誤検出のたびに迂回を覚えるだけで、目的は`[x]`化の瞬間に候補を目へ入れること。

## 検証結果

- **別の入力での検証**（T750の原則2）: 実装後、T696を`[x]`化した当時のコミット
  `9f647b12`の`docs/tasks/T696.md`へ当て、`## 派生（同じメソッド周辺の関連指摘）`の
  1件が鳴ることを確認した。この検知器を書く根拠にしたのは「どの語が使われているか」の
  集計であり、T696の当時の本文はその集計に含めていない。
- `python -m pytest scripts/tests/test_review_checks.py -q` → 52 passed（本タスクで4本追加。
  受け皿が素の番号のとき・見送りと書いたとき・節が次の見出しで止まること）。
- `python scripts/review_checks.py mutate` → 全22件PASS（既存検知器への影響なし）。
- `python scripts/review_checks.py docs --since <T750のコミット>` → この検知器は0件
  （T750には残りを置く節が無い。正しい）。
