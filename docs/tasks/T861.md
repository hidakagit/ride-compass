# T861. 観測しか持たないレイヤーが、配信の遅れのぶんだけ常に時刻範囲の外にある

状態: 未着手（2026-09-15起票。[T859](T859.md)の調査中に発見。T860として起票したが並行セッションが同番号を先にpushしたためT861へ振り直した）

## 背景

雷放電位置データ（liden）は予測フレームを持たず、`trimToCurrentAndFuture`が最新の実況より
前を切り捨てるため、フレーム列は実質1件（最新の観測）になる。一方`frameIndexForTime`の
範囲判定の許容幅は1秒で、共有時刻がその1件より1秒でも後ろなら`null`を返して何も描画しない。

気象庁の配信には観測から公開までの遅れがあり、実データで確認した（2026-09-15 18:50:21 UTC
時点、`targetTimes_N3.json`）:

    liden最新フレーム 20260914184500 = 5.4分前（全37件が観測、5分刻み、予測フレームは無い）

共有時刻が「今」であるかぎり常に最新フレームより後ろにあるため、**雷放電位置データは
災害チップをONにしても描画されない**。同じ性質を持つのは、予測フレームを持たず観測だけで
構成されるレイヤー全般。降水（ナウキャストに60分先までの予測がある）や雷・竜巻
（予測フレームがある）はこの形にならない。

T859で共有時刻を5分刻みで「今」へ追従させたが、この件はそれとは独立に残る（追従後の
共有時刻も、配信の遅れのぶんだけ最新フレームより後ろになりうる）。

## 論点

「観測しか無いレイヤーにとって、共有時刻が最新観測より後ろにあることは範囲外なのか、
それとも『最新の観測を見せる』が正しいのか」を決める必要がある。範囲外で描かない現在の
規約は予測を持つレイヤーには正しく、観測だけのレイヤーには当てはまらない可能性がある。
キキクル4種は同じ理由で既に共有タイムラインから外してある（`riskMap.ts`）。
