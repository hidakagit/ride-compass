# T613: モバイルの「ルート設定」タブに周回/目的地選択（RouteForm）が入っていない問題を是正する

状態: 完了（2026-09-06）

## 背景

T597（デスクトップのサイドバーをモバイルと同じ3区分にする）の完了条件は「デスクトップと
モバイルで区分の名前・順序・中身が一致する」だったが、実際にはデスクトップの
「ルート設定」Disclosure（`renderRouteSectionBody`）が`RouteForm`（周回/目的地トグル・
距離・生成ボタン）と`RouteSettingsPanel`を続けて描画するのに対し、モバイルの
「ルート設定」BottomSheetは`renderRouteSettingsSectionBody(false)`のみで`RouteForm`を
含まない。`RouteForm`はT250由来の常時表示バー（`mobileActionBar`、天候ヘッダー直下）に
取り残されたままだった。

## 対応方針（ユーザー確認済み）

常時表示バー（`mobileActionBar`）を廃止し、モバイルも「ルート設定」タブ一本化する
（`renderRouteSectionBody()`をデスクトップ・モバイル双方から呼ぶ）。design-principles.mdの
「1つの状態は1つの場所でだけ操作する」原則に従う。生成ボタンを押すにはタブを開く必要が
生じる（T250が解消した「タブを開かないと生成できない」という遠回りさが復活するが、
3区分に統一する一貫性を優先する）。

## 実装内容

- `page.tsx`: モバイル専用の常時表示バー（`mobileActionBar`、`RouteForm`+エラー表示）を
  削除。モバイルの「ルート設定」`BottomSheet`の中身を`renderRouteSettingsSectionBody(false)`
  から`renderRouteSectionBody()`へ変更し、デスクトップと同じ`RouteForm`+
  `RouteSettingsPanel`の組を描画する。
- `renderRouteSettingsSectionBody`は`renderRouteSectionBody`からのみ呼ばれ常に見出し無しで
  よくなったため、`showHeading`引数（デフォルトtrue分岐）を撤去し常に見出し無しにした。
- `RouteForm.tsx`: `mobileActionBar`向けだった`compact`propが呼び出し元を失い完全に不要に
  なったため、prop・分岐（フォームのclassName・ラベル文言・aria-label・ボタン文言）ごと
  削除。`RouteForm.module.css`の`.formCompact`/`.labelCompact`、`RouteForm.test.tsx`の
  `describe("compact", ...)`も合わせて削除した。
- `page.module.css`: 未使用になった`.mobileActionBar`を削除。
- ドキュメント追従: `docs/architecture.md`（T303の残課題記述が、実際には生成リクエスト
  組み立て時のキー整合チェックで既に塞がれていたにもかかわらず古い記述のまま残っていたのを
  是正。加えて生成ボタンが「ルート設定」区分内に入ったことで、パネル未マウントのまま生成する
  経路自体が構造的に無くなったことを追記）、`docs/modules/frontend/page-composition.md`・
  `route-settings-and-results.md`（モバイルの`RouteForm`配置・`compact`表示の記述を是正）、
  `docs/tasks/T597.md`（完了条件未達の経緯を追記）。
