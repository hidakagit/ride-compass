# T776. ルート結果の軸チップを、ルート設定の軸チップと同じ形に揃える 規模S

状態: 完了（2026-09-12起票・完了。ユーザー指摘「ルート生成タブの軸選択と同じレイアウトに
揃えたらダメ？ 凡例を押せるか押せないかで、評価利用軸かどうかを区別する」）

## 背景

同じ軸が、ルート設定パネル（重み配分の丸チップ、重み0は薄く残す）とルート結果パネル
（[T775](T775.md)で入れた凡例チップ＋「未使用の軸 N本」の折りたたみ）で別の形をしている。
帯グラフ＋軸チップという構成は同じなのに、結果側だけ畳む行を持つ。

## 決定

チップの形（丸チップ・枠・内側の余白・無効時の薄さ）は`ui/axisLegend.module.css`へ移して
両パネルが`composes`で共有する。設定側の`legendChip`/`legendToggle`はそこへ寄せ、
結果側の凡例も同じ形を引く——同じ軸が画面によって違う形に見えると、設定した軸と結果に
出ている軸が同じものだと読み取れない。

**評価に使ったかどうかは、押せるかどうかで区別する**（ユーザー指示）。`AxisContributionBar`の
`renderDetail`が軸ごとに`null`を返せるようにし、結果パネルは重み0の軸へnullを返す。
重みが入っているのに値が来ない軸は押せるままで、詳細が「データなし」を示す。
[T775](T775.md)で入れた「未使用の軸 N本」の折りたたみと、その下のチップ行は撤去した
（折りたたみは本数しか残さないが、薄いチップなら軸の名前ごと残る）。

凡例に並べる軸は`legendAxes`で差し替える（省略時は帯グラフに出る軸だけ）。区間クリック詳細は
省略したままのため挙動が変わらない。

## 検証結果

ルート結果の本体（`RouteAxisProfile`）の実測、同じPlaywright計測:

| | デスクトップ | モバイル390px |
|---|---|---|
| [T773](T773.md)着手前 | 562px | 444px |
| [T775](T775.md)完了後 | 222px | 144px |
| 本タスク完了後 | 365px | 194px |

丸チップは枠と内側の余白のぶん幅を取り、幅225pxのサイドバーでは折り返しが増えるため
縦は戻る。それでも着手前より小さく、モバイルの結果シートはスクロールせずに読み切れる
状態を保っている（`scrollHeight`が`clientHeight`を超えない）。

テストの効きは意図的な変異2件で確認した: 重み0でも詳細を返す（押せてしまう）→2件failure、
`legendAxes`を無視して寄与のある軸だけ出す→3件failure。いずれも元へ戻して34件green。
