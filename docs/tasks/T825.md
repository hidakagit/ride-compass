# T825. 無駄な再描画・再計算を止め、再描画経路の網羅を保証する

規模S〜M。
状態: 未着手（統合レビュー第8回のP2/P3を束ねたもの、2026-09-13）

## 背景

参照が毎レンダー変わることでエフェクトが回り続ける箇所と、**再描画の対象から新設レイヤーが
落ちている**箇所。後者は[T524](T524.md)で一度直した欠陥と同じ性質が再発したもので、
`MapView.routes.test.ts:253`は「redrawAllLayers経由でも」と題しながら別関数を単体で呼んで
いるため検知できていない。

## 対象

- `Map/MapView.tsx:2865`: `redrawAllLayers`が`spliceStretches`を再描画対象に持たない。
  合成ルート（区間の乗り換え）を表示中に「地図の表示を再描画」を押すと`setStyle()`で
  `SPLICE_SOURCE_ID`/`SPLICE_LAYER_ID`が破棄され、`redrawPropsRef`（:2713）にも
  帯専用effectの依存にも入っていないため**橙色の帯が消えたまま戻らない**（復旧は別候補の
  選択などでspliceが変わるまで起きない）
- `Map/MapView.tsx:2954`: `redrawAllLayers`が無条件で`fitBoundsToRoutes`を呼び、
  3576行のeffectが明文化している「フィットは候補一覧が変わったときだけ」を破る。
  区間を拡大して見ている最中に再描画を押すとカメラが全候補の範囲へ戻る
- `app/page.tsx:804-822`: `splicePairs`/`spliceStretches`/`spliceStretchFeatures`を
  レンダー本体で毎回新規生成しており、`MapView`の`useEffect([spliceStretches, routeLayerOn])`が
  毎レンダー発火する。天候フェッチ・`onViewportChange`（moveend/zoomendごと）・デバウンス確定など
  **あらゆる**再レンダーで`drawSpliceStretches`が走り、地図パン中ずっと`setData`が繰り返される。
  `pairedStretches`は両候補の`edge_ids`（30km級で数千件）からSetを毎レンダー構築する。
  同ファイル877-880行が`roadHiddenKeysByMode`について同じ欠陥をuseMemoで直した記録を持つ
  （**再発**）
- `Map/MapView.tsx:2647`: `staticOverlayLayers`のuseMemoが`dedicatedWayValueLoading`
  （フェッチ状態のMap）に依存するため、パン/ズームのたびに全オーバーレイ層のspecを作り直し
  paint/filterを全再適用する（パン1回あたり2周、公開ramp軸が増えるほど線形に増える）
- `RouteAxisProfile/AxisContributionBar.tsx:77`: `renderDetail`が1軸あたりfilterと本体で
  2回呼ばれ、1回目のJSXは捨てられる。さらに`renderDetail`未指定の呼び出し（区間クリック詳細）
  では全チップが`data-checked="false"`になり、凡例全体が`opacity: 0.55`で描かれる
- `AxisStudio/AxisComposer.tsx:270`: 「かけあわせ評価」でも生値分布のPOSTが走るが、結果を
  描画するのは`breakpoint_linear`のブロック内だけで、取得結果・loading・errorのいずれも
  消費されない（初回Way抽選で1秒前後のリクエストが、軸や係数を変えるたびデバウンス後に発火）
- `AxisStudio/AxisComposer.tsx:776`: `MaterialRangeHint`が「かけあわせ評価」でaxis_idを持つ行にも
  `GET /admin/api/material-distribution/{axis_id}`を投げる。キャッシュは成功時しか埋めないため
  **失敗が毎マウント繰り返される**（画面には何も出ない）
- `app/page.tsx:811`: パネルの区間行は`splicePairs`全件から作るのに、地図の帯は
  `stretchCoordinateRange`がnullまたは座標2点未満の区間を落とすため、行数と帯の本数が
  一致しないことがある。パネルの(i)は「地図にオレンジの帯で出ます」と断言している

## 対応方針

1. **まず再描画対象の網羅を保証する**。`redrawAllLayers`が扱うべきレイヤーを型か1箇所の
   定義から導く形にし、新設レイヤーを足したら自動的に対象へ入る（または入れ忘れると落ちる）
   ようにする。**T524の再発を止めるのはこの1点で、個別の追加ではない。**
2. `MapView.routes.test.ts:253`を「`redrawAllLayers`を呼んで対象が再作成されること」を
   検証する形へ直す（[T823](T823.md)と対）。
3. 参照の安定化（useMemo/useCallback）は1と2が済んでから。
