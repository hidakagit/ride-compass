# T653. ディスク永続キャッシュを`diskcache`へ寄せる（自前実装の廃止） 規模M

状態: 完了（2026-09-08）

## 背景

[T644](T644.md)でプロセス内キャッシュを`cachetools`へ統一し、Redisの骨格は
`redis_json_cache`へ集約した。**残る自前実装がディスク側の`tile_persistent_cache.py`**で、
次を全部自前で書いている。

- pickleの読み書きとアトミック書き込み（一時ファイル→`replace`）
- 破損・部分書き込みのフォールバック
- 世代ディレクトリの構成（`namespace/v{version}/{z}_{x}_{y}.pkl`）
- 旧世代の掃除（[T649](T649.md)で追加した`prune_stale_generations`）

そして**容量の上限が無い**。[T649](T649.md)は「世代を上げたら旧世代を消す」までは解決したが、
現行世代が増え続けることへの歯止めは無いままである（本番は現行世代v5だけで313MB）。
上限と退避はキャッシュライブラリの標準機能であり、自前で持つ理由が無い。

方針としても、プロジェクトの既存の判断（[docs/caching.md](../caching.md)「プロセス内
キャッシュは`cachetools`に統一する」、frontend側の「定番ライブラリを優先検討する」）と揃う。

## 候補: `diskcache`（Apache-2.0、5.6.3）

| 項目 | 内容 |
|---|---|
| 実装 | SQLite＋ファイル。32KB超の値はファイルへ、以下はSQLite内へ |
| 容量制御 | `size_limit`と退避方針（`least-recently-used`等）を標準で持つ |
| プロセス安全 | 同じディレクトリを複数プロセス・スレッドから共有できる |
| 配布 | pure Python（wheel1本、aarch64・Windowsとも問題なし） |

### 性能実測（開発機、4.1MBのpickle）

| 操作 | 現行（自前ファイル） | diskcache |
|---|---|---|
| 読み出し（unpickle込み） | 70.2 ms | **58.1 ms** |
| 書き込み（pickle込み） | 65.0 ms | 67.8 ms |

読み出しはむしろ速く、書き込みは同等。**性能上の妥協は無い。**

## 対応方針

`tile_persistent_cache.py`を`diskcache.Cache`の薄い包みにする。公開APIは
`get`/`set`/`clear_namespace`/`clear_all`/`prune_stale_generations`のまま変えず、
呼び出し元（`graph_material_cache`・`tile_score_matrix_cache`）を触らない。

- キーは`(namespace, version, zoom, x, y)`のタプル
- 世代の掃除は`tag`（`f"{namespace}:{version}"`）を使い、`Cache.evict(tag)`へ寄せる
- `size_limit`は設定値にする。根拠を書くこと（本番VMのディスクは48GBで使用24%）
- 退避方針は`least-recently-used`（よく使うタイルを残す）
- 破損エントリの扱いはライブラリへ委ね、自前のフォールバックを削る

### 注意点

- **統計値の互換**: 現行の`get`は`read_ms`/`unpickle_ms`/`bytes`を`stats`へ書き、
  `graph_service`がリクエスト単位で集約してログへ出している。diskcacheは読み出しと
  unpickleを分離できないため、`read_ms`（合計）へ寄せるか、内訳を落とすかを決める
- **既存のキャッシュ実体は捨てる**（形式が変わるため）。デプロイ直後は再充填が要るが、
  失っても再計算できるキャッシュなので許容できる。旧ディレクトリの削除も行う

## 完了条件

- `tile_persistent_cache`から自前のpickle I/O・アトミック書き込み・世代ディレクトリ操作が
  無くなること
- `size_limit`を超えたときに自動で退避され、ディスクが無制限に増えないこと（テストで確認）
- 既存の呼び出し元・テストが変更なしで通ること（公開APIを変えない）

## 実装

- `tile_persistent_cache.py`を`diskcache.Cache`の包みへ置き換えた。自前のpickle I/O・
  アトミック書き込み・世代ディレクトリ操作・破損時フォールバックが無くなった
  （155行→自前ロジックはキー設計と世代掃除のみ）
- キーは`(namespace, version, zoom, x, y)`のタプル。`tag`に`namespace:v{version}`を持たせる
- 容量上限は`settings.tile_persistent_cache_size_limit_mb`（既定1024MB）、退避は
  `least-recently-used`。**上限を超えたら自動退避されることをテストで固定した**
- 統計は`read_ms`のみへ整理した（`diskcache`は読み出しとunpickleを分離できないため、
  `unpickle_ms`/`bytes`を廃止。`graph_service`のINFOサマリも追従）
- ストレージ形式が変わるため、旧`.pkl`ディレクトリはデプロイ後に手動削除する

## テストの整理

ライブラリの責務になったもの（破損ファイル・部分書き込み・一時ファイルの後始末・
アトミック上書き）は削除し、**こちらの契約**（読み出しが失敗したら例外を投げずに
キャッシュミスへ倒す）は、下位の`get`を差し替えて例外を起こす形へ書き換えた。
