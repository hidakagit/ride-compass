# T543: T533で見つかった評価パイプラインの旧設計残骸を解消する（T536完了後）

状態: 未着手（2026-09-02起票、T533の横断監査で判明。T536実装中のため意図的に保留）

## 背景

[T533](T533.md)（過去の経緯だけで保持している冗長な分割・マージ漏れの総点検）で、
`domain/evaluation.py`・`services/graph_service.py`（いずれも[T536](T536.md)が現在
実装中のファイル）に、クエリ・データ構造の統合が過去に行われた際に呼び出し側が
追従しなかった残骸が見つかった。T536と同じファイルを同時に編集すると衝突リスクが
高いため、T536完了後に着手する。

## 対応方針（T533調査結果より）

1. **`compute_edge_costs_bulk`とその周辺（`EvaluationService.evaluate_graph`
   [`services/evaluation_service.py`]・`MaterialExtractionContext`
   [`domain/material_catalog.py`]）**: `EdgeMaterialBundle`統合前の7個の個別辞書引数
   （elevation_attributes/surface_attributes/stop_counts/way_tags/intersection_counts/
   accident_counts/designated_edge_ids）構成のまま残っている。`road_graph_engine.py`の
   コメントは既にこの7辞書が`EdgeMaterialBundle`へ統合済みと明記しており、さらに
   `compute_edge_costs_bulk`自体が改善計画T529以降「本番経路では実質デッドコード」
   （`test_evaluation_bulk.py`の回帰オラクル用途のみ）と判明している。T536完了後、
   `compute_edge_costs_bulk`自体がT536でさらに置き換わる可能性が高いため、T536の
   最終形を見てから「残すなら`EdgeMaterialBundle`ベースへ引数を統合する」
   「デッドコード化するなら削除する」を判断する。
2. **`graph_service.py: _build_search_materials_uncached`の二重取得**: `surface_attributes`を
   `get_or_build_graph_with_attributes`で取得済みなのに、直後の`get_edge_materials_batch`
   （JOINでsurfaceも含む）の結果からsurface部分だけ捨てて上書きしている（コード中の
   コメントで無駄を自認済み）。低頻度パス（`is_split_up_to_date=False`のフォールバック）
   のため実害は軽微だが、T536がこのファイルの`_get_or_build_tile_materials`周辺を
   書き換える見込みのため、その完了後に整理する。
3. **`get_way_attribute_counts`の無名4要素タプル**（`road_graph_repository.py`・
   `domain/evaluation.py: axis_inspector_breakdown`）: `tuple[float, float, int, int]`
   （length_m, accident_count, stop_count, intersection_count）が3層（リポジトリ→
   ファサード→ドメイン関数）を無名タプルのまま伝播し、呼び出し側で位置アンパックして
   いる。同じ3値のうち2つを含む`EdgeAttributeCounts`が既に存在するため、名前付き型へ
   置き換えるのが自然。`domain/evaluation.py`がT536の対象ファイルのため完了後に着手。
