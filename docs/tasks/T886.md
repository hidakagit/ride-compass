# T886. 周囲の土地被覆が、どこにも表示されない

規模M。
状態: 実施中（段階1をmasterへ反映済み、残りは段階2。2026-09-16起票。[T885](T885.md)の判断材料として、ユーザー要望
「土地状況見える化するところからかな。。地図パネルにできない？」から）

## 背景

`way_landcover`（[T624](T624.md)）は道路周囲100mリングの土地被覆を8クラス分持つが、
**利用者がその内訳を見る手段が無い**。

- 地図レンズ: タイルへ焼いているのは`trees_pct`・`built_pct`の2列だけで、レンズに出るのは
  その合成（開放度軸）。「この道は何で覆われているか」は読み取れない。
- 区間インスペクタ: `_WAY_LANDCOVER_BY_OSM_WAY_ID_SQL`が**8列すべてをDBから読んでいる**のに、
  `axis_inspector_breakdown`が評価パイプラインへ配線済みの2値（trees/built）しか先へ
  渡さないため、画面には出ない。

[T885](T885.md)で「樹木と建物を分けるか」を判断するにも、まず何がどこにあるかが見えないと
決められない。

## 段階1: 区間インスペクタへ内訳を出す

データは既に取得済みで、配線が切れているだけ。`AxisInspectorResult`へ
`LandcoverPercentages`（既存モデル、8クラス＋`valid_pixels`）を足し、
`RoadInspectorPopup`へ節を1つ増やす。

表示は畳む。走行中のスマホが主用途で情報量を増やさない方針のため、既存の「その他のタグ」と
同じ`<details>`にし、閉じている間は主なクラスだけを見せる。

### 実施（2026-09-16）

`AxisInspectorResult`へ`landcover`（既存の`LandcoverPercentages`、8クラス＋
`valid_pixels`）を足し、`RoadInspectorPopup`へ`RoadLandcoverRows`を1つ増やした。

表示は「その他のタグ」と同じ`<details>`。閉じている間は最も多いクラスだけを
（例: 「周囲の土地被覆: 建物 50%」）、開くと割合の大きい順に並べる。0.5%未満の
クラスは行を作らない——8クラスは合計100%になるため、出さなくても読み手は補える。

効いていることの確認: `RoadLandcoverRows`の呼び出しを外すとテストが落ちる。

## 段階2: 地図（未着手）

**当初「主なクラスをタイルへ焼く」と書いたが、撤回する。** 土地被覆は8クラスの割合で、
樹木20%・建物50%・農地30%のような混合が普通にある。`argmax`で1色へ潰すと「建物」になり、
半分が建物でないことが消える。34/33/33のような道ではわずかな差で色が飛ぶ。
**この演算をこのデータに使ってはいけない。**

そもそもこの混合は集約の副産物である。元のラスタは10m画素の分類済みデータで、
1画素に1クラスしか入っていない。半径100mリングの数百画素をヒストグラムにして1本の道へ
畳んだ結果として混合が生まれている。

したがって段階2は**元のラスタをそのまま面で配信する**（2026-09-16ユーザー判断
「源泉の10m間隔のラスタをそのまま色塗って地図パネルには出したい」）。1画素1色になり、
混合をどう塗るかという問題自体が消える。本番VMの`/home/ubuntu/54S_2024.tif`（69MB）が
そのまま素材になる。配信方式は未調査（GDAL未導入、静的タイルへ焼くか都度生成か）。

道路の線を塗るレンズは、軸の形が決まった後の確認手段として別に考える。
## 保留することで何が起きうるか

[T885](T885.md)の選択肢A〜Dを、分布の数字だけで決めることになる。「並木道44,120本」が
実際にどこのどんな道なのかを見ずに軸の形を変えると、較正のときに同じ議論をやり直す。
