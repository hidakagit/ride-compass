# T407. 降水短時間予報（気象庁rasrf）の実装 規模M

状態: 完了（2026-08-30）

- 背景: T387「無償範囲で追加できるJMAデータの調査」（2026-08-29）で発見・実機確認済みだった
  2候補（降水短時間予報[rasrf]・線状降水帯予測マップ[sjfcstmap]）のうち、降水短時間予報を
  実装する。降水ナウキャスト（実況の外挿、60分先が上限）と延長予報（Open-Meteo、48時間先まで
  だが精度は粗い）の間を埋める、気象庁公式の数値予報モデルによる予測（最大15時間先）。

## 対応方針

既存の「降水」チップ（precipitationNowcast.ts、T183で確立した「アイコンは1つ、データ取得層で
複数ソースの差異を吸収する」設計）へ、rasrfを第3の階層として追加する。新しいチップ・新しい
MapView.tsxのレンダラースペックは不要（既存のrasterTile種別を汎用的に扱う仕組みをそのまま
再利用できる）。

- **ナウキャスト（0〜60分、5分刻み、実況の外挿）** → **降水短時間予報（60分〜15時間先、
  数値予報モデル、改善計画T407）** → **延長予報（15時間先〜約48時間先、Open-Meteo、
  1時間刻み）**の3段構成。各段は前段の最終フレームより後の時刻だけを採用する
  （近い将来の二重表示を避ける、既存のナウキャスト→延長予報の境界処理と同じ考え方）。

## 実装メモ

- **`frontend/src/components/Map/precipitationNowcast.ts`**:
  - `fetchRasrfFrames`を新設。`https://www.jma.go.jp/bosai/jmatile/data/rasrf/targetTimes.json`
    を取得する。
  - **実機確認（2026-08-30）で判明した構造**: targetTimes.jsonは`member`フィールドを持ち、
    "immed"（直近0〜6時間、高頻度更新）と"none"（7〜15時間先、毎正時更新）の2系統が混在する。
    同じmember内にも「毎正時の完全な複数validtime群」と「10分毎の中間ランが返す単発
    validtime」が混在するため、各memberごとに「異なるvalidtimeの種類数が複数ある最新の
    basetime」を選ぶ（`latestFullRunFrames`）。
  - **実機確認で発見した落とし穴（ユーザー指摘で発覚）**: 同じtargetTimes.jsonには線状降水帯
    予測マップ（sjfcstmap、T387参照）も混在し、同一(basetime, validtime, member)に対し
    rasrf無し・sjfcstmapのみのelementsを持つ行が別途存在する（実機確認: 本番相当データで
    114行中73行がelementsにrasrfを含まないsjfcstmap単体行だった）。当初は行数だけで
    「完全な予報ランか」を判定しており、この重複行を誤って複数フレームとカウントする
    バグがあった。`elements.includes("rasrf")`で絞り込んでから判定するよう修正
    （絞り込み後は同一(basetime, validtime, member)の重複が無いことを実データで確認済み、
    優先順位付けは不要）。
  - `rasrfTileUrlTemplate`を新設: `.../rasrf/{basetime}/{member}/{validtime}/surf/rasrf/{z}/{x}/{y}.png`
    （ナウキャストと異なりmemberがURLパスにそのまま入る）。
  - `PrecipitationFrameRef`へ`{source: "rasrf"; index}`を追加、`precipitationFrames`/
    `precipitationRenderPayload`を2段→3段構成へ拡張。
- **`frontend/src/hooks/useDynamicWeatherLayers.ts`**: `fetchRasrfFrames`の取得effect
  （既存の降水ナウキャストeffectと同じ`showPrecipitationNowcast`ゲート、10分間隔で再取得）
  を追加し、`precipitationFrames`/`precipitationRenderPayload`の呼び出しへ`rasrfFrames`を配線。
- **`frontend/src/components/Map/mapLayers.ts`**: 「降水」チップの`description`/`panelHint`を
  3段構成の説明へ更新。降水短時間予報は数値予報モデルによる予測（実況の外挿であるナウキャスト
  とは精度の性質が異なり、先になるほど不確実性が増す）である旨を明記。
- **MapView.tsxは無変更**: rasterTile種別を汎用的に扱う既存の仕組み
  （`DYNAMIC_WEATHER_RENDERERS.precipitationNowcast.raster`）がそのまま再利用できるため。

## 検証

- vitest: `precipitationNowcast.test.ts`25件green（fetchRasrfFramesの選定ロジック・
  sjfcstmap混入時の除外・3段マージ・rasrterTile/gridFill切替の回帰テストを含む）。
- `npx tsc --noEmit` green。
- フロントエンド全724件green（既存機能への影響なし）。
- 実機確認（Playwright的手法、Browserペイン+実際のJMA API疎通）: 開発サーバーでナウキャスト・
  降水短時間予報（immed/none両member）双方の実タイルURLが実際にリクエストされ200で
  返ることを確認。当初「noneのタイルが要求されない」ように見えた事象は、スライダー自動操作
  （高速な連続フレーム切替）によるテスト側のタイミング問題と判明——チップのOFF→ON後に
  安定状態で確認したところ、immed/none両方とも正しくタイルが要求されることを確認した。
