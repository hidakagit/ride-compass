# T899. 既定ONのレイヤーを、性質からではなく1つずつ手で書いている

規模S。
状態: 未着手（2026-09-16起票。[T422](T422.md)が「起票はまだしていない」と書いたまま
残っていた派生を、統合レビュー第10回の棚卸しで独立させたもの）

## 背景

災害レイヤーだけが既定ONで、その理由は「防災級の情報はユーザー操作を待たず表示すべき」
という**性質**にある。しかし実装は`frontend/src/app/page.tsx`の
`DEFAULT_LAYER_VISIBILITY`——レイヤーidごとにtrue/falseを手で書く辞書で、性質は
コメントにしか書かれていない。

レイヤーを1つ足すたびにこの辞書へ1行足す必要があり、**足し忘れると型が落とす**（全idを
埋める`Record`のため）のが今の安全網である。逆に言えば、足し忘れは防げても
「この新しいレイヤーは防災級か」という判断はコメントを読んだ人にしか効かない。

## 保留することで何が起きうるか

防災系のレイヤーが2つ目に増えたとき、既定ONにするかどうかが**そのとき書く人の記憶**に
なる。片方だけONという状態は、利用者から見ると「なぜこれだけ出ているのか」が説明できない。

## 対応方針（未着手）

`MapLayerDescriptor`へ`alwaysOnByDefault`のような宣言的フィールドを持たせ、
`DEFAULT_LAYER_VISIBILITY`をその宣言から導く。[T888](T888.md)が同じ`MapLayerDescriptor`へ
「描画順」「最小ズーム」を持たせる射程を持つため、**まとめて1回で入れた方がよい**
（記述子へ足すフィールドが増えるたびに消費側を作り直すことになる）。
