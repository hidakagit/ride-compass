# T982. PostGIS統合テストが、スキーマ作成の失敗を「接続できない」に化けさせる 規模S

状態: 未着手（2026-09-21起票）。

## 背景

`backend/tests/conftest.py`の`road_graph_engine`は、拡張の有効化とテーブル作成を
`try` / `except Exception` で囲み、失敗すると
`pytest.skip("ridecompass_test DBに接続できないためスキップ")` へ落とす。

接続以外の失敗——拡張の不足、型の欠落、ORM宣言とDBの食い違い——も同じ文言で
スキップになる。そのファイルのテストは1件も走らないまま、出力には「接続できない」
とだけ出る。**緑のスイートが「全部スキップ」でも見分けが付かない。**

T970で`source_features.rast`（`raster`型）を足したとき、テストDBに`postgis_raster`が
無ければ`create_all`が落ちてこの経路に入る条件が揃った。実際には別の理由で通っていたが、
通っていることを確かめるのにDBを直接覗く必要があった。

## 対応方針

- スキップしてよいのは**接続の失敗だけ**にする（`OSError`・asyncpgの接続系例外）。
  それ以外は落とす。
- スキップの文言に、実際の例外を含める。

## 完了条件

- 拡張をわざと落としたDBを指して実行し、スキップではなく失敗することを確認する
  （「実装した」ではなく「効いている」を見る）。
