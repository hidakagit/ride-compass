# T868. 区間インスペクタを、ルート結果と同じ読み方へ揃える

状態: 未着手（2026-09-15起票）
規模: M

## 背景

地図上の道をクリックして出る詳細（区間インスペクタ）が読みにくい（ユーザー指摘
「一次属性全軸の内訳表示がみにくい」）。この画面が答えようとしているのは「この道は何者で、
なぜこの評価なのか」——レンズの色の理由を確かめる窓口。読みにくさの出どころは4つ:

1. 一次属性が生タグのカンマ羅列（`Object.entries(result.tags)`をそのまま連結）。カタログ外の
   タグ（`name`・`ref`等）も混ざり、上の行の道路名が再掲される。
2. 全軸を同じ形で並べるため、**このルート設定で効いている軸がどれか分からない**
   （重み0の軸も算出不可の軸も同じ1行）。
3. 数字が全て「N/100」で軸どうしを比べられない。ルート結果は重み付き寄与度で示しており、
   同じものを別の尺度で見せている。
4. 判断に使えない数字（合成コスト＝参考値、「実際の探索コストとは一致しません」と断り書き）が
   最も目立つ位置にある。

根っこは**視覚言語が二重**であること。ポップアップはHTML文字列を`innerHTML`で差し込む方式で、
ルート結果側の共有部品（`AxisContributionBar`等）を使えない。

## 方針

- ポップアップの中身をReactで描く（PopupのDOMノードへportal）。ルート結果と同じ部品・
  同じ配色・同じ「チップを押して詳細」を共有する。
- 先頭は「この道の事実」の表（カタログ登録済みの属性をラベル付き、未登録の生タグは畳む）。
- 評価は効いている軸だけを寄与度で。合成コスト（参考値）は注記へ格下げ。
- 寄与度は**backendが返す**（`AxisInspectorAxis`へ`contribution`を追加）。フロントで
  独自に重みを掛けないというルート結果側の規約へ揃える。
