# T868. 区間インスペクタを、ルート結果と同じ読み方へ揃える

状態: 完了（2026-09-15）
規模: M

## 背景

地図上の道をクリックして出る詳細（区間インスペクタ）が読みにくい（ユーザー指摘
「一次属性全軸の内訳表示がみにくい」）。この画面が答えようとしているのは「この道は何者で、
なぜこの評価なのか」——レンズの色の理由を確かめる窓口。読みにくさの出どころは4つ:

1. 一次属性が生タグのカンマ羅列（`Object.entries(result.tags)`をそのまま連結）。カタログ外の
   タグ（`name`・`ref`等）も混ざり、上の行の道路名が再掲される。
2. 全軸を同じ形で並べるため、**このルート設定で効いている軸がどれか分からない**
   （重み0の軸も算出不可の軸も同じ1行）。
3. 数字が全て「N/100」で軸どうしを比べられない。ルート結果は重み付き寄与度で示しており、
   同じものを別の尺度で見せている。
4. 判断に使えない数字（合成コスト＝参考値、「実際の探索コストとは一致しません」と断り書き）が
   最も目立つ位置にある。

根っこは**視覚言語が二重**であること。ポップアップはHTML文字列を`innerHTML`で差し込む方式で、
ルート結果側の共有部品（`AxisContributionBar`等）を使えない。

## 方針

- ポップアップの中身をReactで描く（PopupのDOMノードへportal）。ルート結果と同じ部品・
  同じ配色・同じ「チップを押して詳細」を共有する。
- 先頭は「この道の事実」の表（カタログ登録済みの属性をラベル付き、未登録の生タグは畳む）。
- 評価は効いている軸だけを寄与度で。合成コスト（参考値）は注記へ格下げ。
- 寄与度は**backendが返す**（`AxisInspectorAxis`へ`contribution`を追加）。フロントで
  独自に重みを掛けないというルート結果側の規約へ揃える。

## 追加（ユーザー要望、同じ画面の話のため本タスクへ含める）

「クリックして詳細表示しているwayを強調表示できる？ どこのことか分かりにくい」。詳細だけ
出しても、どの線の話かが分からないと場所を取り違える。

## 実装

- backend: `AxisInspectorAxis.contribution`（重み付き寄与度）。`domain/difficulty.py:
  composite_contributions`が合成の分解を持ち、**合計が`composite_difficulty`と一致する**
  ——合成と分解が別々に正規化されると「内訳の合計が結論と合わない」表示になる。
- `Map/roadFacts.ts`（新規）: タイルのプロパティから「項目: 値」の行を作る純関数。
  該当しない項目は行ごと出さない。
- `Map/RoadInspectorPopup.tsx`（新規）: 詳細をReactで描き、MapLibreのPopupへ
  `createPortal`で差し込む。評価は`AxisContributionBar`（ルート結果と同じ部品）で出し、
  カタログ外の生タグは畳む。合成は注記へ格下げ。
- 強調: 路面タイルへ焼き込み済みの`osm_way_id`で1本へ絞る専用レイヤー
  （`ROAD_INSPECT_LAYER_ID`、`applyInspectedWay`）。ソースも取得も増えない。閉じると
  どのwayにも一致しないフィルタへ戻して消す。**feature-stateではなくfilterにした**のは、
  どのタイルが読み込まれていても同じ式で当たり、状態の後始末が要らないため。
- 旧`axisInspectorPopup.ts`（HTML文字列の組み立て）と`buildRoadSurfacePopupHtml`は撤去。
  MapViewの`axisLabels` propは`axes`＋`axisColors`へ置き換えた（ラベルだけでは
  ルート結果と同じ部品を組めない）。

## 検証

- `pytest`（`test_evaluation.py`へ寄与度の合計＝合成の検査を追加）・`tsc --noEmit`・
  `eslint`・`prettier`・`npx vitest run`
- `roadFacts.test.ts`（純関数6件）・`RoadInspectorPopup.test.tsx`（5件。事実だけ先に出す／
  ルート結果と同じ寄与度／算出できない軸は並べない／合成は注記／生値がタグとして
  解釈されない）・`MapView.layerOps.test.ts`（強調3件）
- 実機（開発サーバー、渋谷付近）:
  - 詳細は「事実の表 → 寄与度バー（アイコン＋値）→ 合成は注記」の順で出る。
  - backendの寄与度は本番と同じ計算で、合計が合成と一致する（`car_stress 46.5 +
    accident 18.6 + bicycle_infra_quality 34.9 = 100.0 = 合成`）。重み0の軸は寄与0で並ばない。
  - 強調は`visibility=visible`・`filter=["==",["get","osm_way_id"],156167860]`で
    `queryRenderedFeatures`が1件返る（＝実際に描画されている）ことを観測した。短いwayでは
    ポップアップ自身の裏に隠れるため、画面写真では見えないことがある。
