# T385. 常設天候ヘッダーに「今日の見通し」二次パネル＋天気アイコン化を追加 規模M（2026-08-28完了）

状態: 完了

- 背景: T384（Open-Meteo変数の棚卸し調査）を受け、常設ヘッダーの項目数は増やさず
  「日没時刻・今日の降水確率最大・今日の最大風速・今日の気温レンジ」をタップで開く
  二次パネルとして追加する。ユーザーへ提示したArtifact概念スケッチ（Popoverで開く
  フローティングパネル、WarningBadgeListと同じ意匠）が承認された。さらにユーザーからの
  追加確認「weather_codeベースの天気アイコン化（UV指数の置き換え）も今回に含めるか」に
  対し「今回まとめて実装する」の回答を得たため、T384提案1（天気アイコン化）も同時に
  実装した。
- 対応方針・実装:
  1. **backend（今日の見通し4項目）**: `weather_client.py: get_forecast`（単一地点、
     `/api/weather`用）へOpen-Meteoの`daily`パラメータ
     （`sunset,precipitation_probability_max,wind_speed_10m_max,temperature_2m_max,
     temperature_2m_min`）を追加。`get_forecast_many`（WindService用、複数地点一括）へは
     含めない（クォータ削減のため変数を絞る既存方針、日次見通しはルート評価に使わない）。
     `domain/weather.py: WeatherConditions`へ`sunset`・
     `precipitation_probability_max_percent`・`wind_speed_max_ms`・`temperature_max_c`・
     `temperature_min_c`を追加（いずれも`float|str|None`、get_conditions_many経路では
     常にNone）。`weather_service.py`に`_daily_index_value`（`_hourly_index_value`の
     daily版、index0=今日）を追加し、`_conditions_from_data`のat=None分岐でのみ埋める。
  2. **backend（天気アイコン用）**: `current`パラメータへ`weather_code,is_day`を追加。
     `WeatherConditions`へ`weather_code: int|None`・`is_day: int|None`を追加。判定
     ロジック（WMOコード→カテゴリ）はbackend側に持たせず、frontendの
     `weatherCode.ts`へ集約（backendは生の値を素通しするだけ）。
  3. **OpenAPI再生成**: `export_openapi.py`実行のためローカルDBのmigration未適用
     （0023、T352由来）が判明し`apply_migrations.py`で適用してから再生成。
     `frontend/src/types/generated/`のdiffは新規7フィールドぶんのみ（`axis-catalog.json`の
     無関係な差分[DB状態依存の`show_map_icon`]は除外）。
  4. **frontend（天気アイコン）**: `icons.tsx`へ`MoonIcon`・`CloudIcon`・`FogIcon`・
     `SnowflakeIcon`を追加（既存の線画スタイルに合わせる）。新設
     `WeatherPanel/weatherCode.ts: getWeatherCodeDisplay(weatherCode, isDay)`が
     WMOコード27種を6カテゴリ（快晴/くもり/霧/雨/雪/雷雨）へ丸め、「快晴」のみ昼夜で
     アイコンを出し分ける（他カテゴリは昼夜共通、アイコン数を抑える判断）。
     `WeatherPanel.tsx`のUV指数専用チップ（アイコン+数値、常時表示）をこのアイコン1個へ
     置き換え、UV指数自体はチップのtitle属性へ格下げした（夜間はUV指数が常に0.0になり
     情報価値が無いまま項目だけ残ってヘッダーを圧迫していたため、ユーザー指摘「収まり方が
     不自然」の一因と特定）。
  5. **frontend（今日の見通しパネル）**: 新設`TodayOutlook/TodayOutlook.tsx`。
     WarningBadge.tsxと同じRadix Popoverパターン（Trigger=「今日」ボタン、
     Portal+Content=フローティングパネル）。日没は`formatClockTime`（時:分）＋
     `formatRemainingUntil`（「あと3時間12分」、日本はDST無しのため単純差分で十分）。
     4項目とも値が無ければ行ごと非表示、4項目全てnullならトグル自体を出さない。
  6. **page.tsx**: `.weatherStats`（T383で新設、天候の数値を警報バッジより優先して
     常時可視にするsticky-leftラッパー）へ`<TodayOutlook>`を追加。子が2つ（WeatherPanelの
     .row＋TodayOutlookのトグルボタン）になったため`.weatherStats`へ`display:flex`を
     追加（以前は子1個のみで暗黙にblock表示のままでも問題なかった）。
  7. **docs/architecture.md**: `/api/weather`のレスポンス例を新規7フィールド分含めて
     全面更新（ついでにT172由来の既存欠落フィールドも補完）、`WeatherClient`の説明に
     `daily`取得を追記、フロントのコンポーネント一覧へ`TodayOutlook.tsx`を追加・
     `WeatherPanel.tsx`の説明を天気アイコン化に合わせて更新。
