# T385. 常設天候ヘッダーに「今日の見通し」二次パネル＋天気アイコン化を追加 規模M（2026-08-28完了）

状態: 完了

- 背景: T384（Open-Meteo変数の棚卸し調査）を受け、常設ヘッダーの項目数は増やさず
  「日没時刻・今日の降水確率最大・今日の最大風速・今日の気温レンジ」をタップで開く
  二次パネルとして追加する。ユーザーへ提示したArtifact概念スケッチ（Popoverで開く
  フローティングパネル、WarningBadgeListと同じ意匠）が承認された。さらにユーザーからの
  追加確認「weather_codeベースの天気アイコン化（UV指数の置き換え）も今回に含めるか」に
  対し「今回まとめて実装する」の回答を得たため、T384提案1（天気アイコン化）も同時に
  実装した。

  2. **backend（天気アイコン用）**: `current`パラメータへ`weather_code,is_day`を追加。

- **フォローアップ（同日、ユーザー指摘「UV指数はスマホからだとどこから見えるのか？」
  「今日の見通しでは、今日の日中の大まかな天気の流れが分かるものも欲しい」）**:
  上記本体実装完了直後、weather_codeベースのアイコン化でUV指数の表示先を天気アイコンの
  `title`属性へ格下げしたが、`title`はスマホのタップでは実質見えず「UV指数が見えなく
  なった」という新たな指摘を受けた。あわせて「今日の見通し」パネルの4項目（日没・
  降水確率最大・風最大・気温レンジ）は1日1個の集約値のみで、「日中いつ頃天気が
  崩れるか」が分からないという要望も出た。
  - **設計の変遷**: 天気の流れの表現は3段階の対話を経て決着した。①当初案「朝
    （09:00）/午後（14:00）/夜（19:00）」の3区分名称付き→ユーザー「少し荒い気が
    する。もう少し分けられないか」→②「天気・気温・降水確率を細かい粒度でスマホ
    横幅に収まる表現で」という要望を受け、名称付き区分をやめ06:00〜20:00の
    2時間おき8コマ（"HH:MM"の代表時刻そのもの）+気温+降水確率の3値セットへ変更
    →③8コマがスマホ横幅に収まりきらない懸念に対し、ユーザーから「収まらない場合、
    天気の流れのところは横スクロールがパネル内で発生してもいい」と明示許可を得た
    ため、幅を切り詰める設計圧力を外し横スクロール前提で確定。
  - **backend**: `weather_client.py: get_forecast`の`daily`パラメータへ`uv_index_max`
    （今日のUV最大値）を追加。`hourly`パラメータへ`weather_code,is_day`を追加
    （天気の流れの各コマのアイコン判定用。`is_day`は現状today_periodsでは使わない
    が、hourly自体にcurrentと対の値として持たせておく）。`domain/weather.py`へ
    `WeatherConditions.uv_index_max: float|None`と新設`WeatherPeriodOutlook`
    （`period: str`・`weather_code: int|None`・`temperature_c: float|None`・
    `precipitation_probability_percent: float|None`）+
    `WeatherConditions.today_periods: list[WeatherPeriodOutlook]`を追加。
    `weather_service.py`へ`_PERIOD_TARGET_HOURS`（"06:00"〜"20:00"の8個）と
    `_period_outlooks`classmethodを追加（`_conditions_from_data`のat=None分岐で
    呼ぶ。get_conditions_many経路は空リスト固定）。各コマは「その区間で最も荒れた
    時刻」を選ぶ重大度ランキング方式ではなく代表1時刻をそのまま採用した——重大度
    判定はweather_code→アイコン判定と同種の「意味づけ」であり、backendは生の値を
    素通しするだけという既存方針（frontend/weatherCode.tsへ判定ロジックを集約）に
    合わせたため。既存の`_nearest_hourly_index`/`_hourly_index_value`をそのまま
    再利用できる副次的な利点もある。
  - **OpenAPI再生成**: 新規`uv_index_max`・`today_periods`・`WeatherPeriodOutlook`

  - **frontend**: `types/weather.ts`へ`WeatherPeriodOutlook`型を追加。
