# T587: MapLibreレイヤーのensure関数が既存レイヤーの色式を更新しない（軸定義変更が反映されないバグ）

状態: 完了（2026-09-05）

## 背景

ユーザー報告「風の面塗りが実際の風速に見合わずオレンジ一色に見える」の調査（[T571]
(T571.md)とは別セッション、風penalty面塗り撤去の作業中）から発覚。本番の`wind`軸の
`display_thresholds_override`が異常値`[10,20,30,40,50]`になっていたことをまず発見したが
（別途DB側の是正は保留、本タスクの対象外）、理論値では風速0.1〜9.23m/s（実測範囲）は
全て最初の帯（緑）になるはずなのに、実機再現では明らかにオレンジ系の色が出ており矛盾が
あった。

## 根本原因

`makeEnsureDedicatedWayValueLayer`（windAxis/gradientAxis）・`makeEnsureGradientFillLayer`
（gradientFill）・`makeEnsureAxisRampLayer`（ramp軸全般）・`ensureDynamicWeatherLayer`
（動的気象レイヤー汎用機構）の**4つのensure関数すべて**が「レイヤーが既に存在すれば
何もしない」（`if (map.getLayer(id)) return;` 等）という設計だった。

`dedicatedWayValueBoundaries`（軸スタジオの`display_thresholds_override`由来）・
`rampAxes`（軸定義そのもの）は、`useAxisCatalog`の実行時フェッチ完了まで確定しない。
もしフェッチ未完了の間（`.get("wind")`が`undefined`等）にレイヤーが初めて作成されると、
その時点の値（フォールバック定数`WIND_AXIS_THRESHOLDS=[-6,-2,2,6]`等）で`fill-color`/
`line-color`が**固定**され、その後フェッチが完了して正しい値に更新されても、既存レイヤー
のpaintプロパティは二度と再設定されなかった。

凡例（テキスト）は`page.tsx`の別ロジック（useMemo、都度再計算）が担うため常に正しい値を
表示しており、「凡例は正しいのに実際の色が違う」という発見しづらい形でバグが顕在化
していた。

このバグは「ページ読み込み直後の一瞬に評価軸レイヤーをONにする」という、利用者からは
見えない暗黙のタイミング条件に依存しており、通常操作でも十分起こりうる。

## 対応方針・実施内容

4つのensure関数すべてを「レイヤー未作成なら`addLayer`、既存なら`setPaintProperty`で
再適用」する形へ修正した。`ensureDynamicWeatherLayer`は現時点で動的な軸スタジオ値に
依存する呼び出し元が無い（風penalty面塗りの撤去により）が、汎用機構である以上「今は
実害がない」を理由に温存すると将来同じ罠を再生産するため、raster/gridFill/gridMark/
vectorの全サブタイプを同様に修正した（ユーザー指摘「利用者側に暗黙の制限を付けない
実装を目指してほしい」）。

- `frontend/src/components/Map/MapView.tsx`:
  - `makeEnsureDedicatedWayValueLayer`: 既存レイヤーへ`line-color`を再適用
  - `makeEnsureGradientFillLayer`: 既存レイヤーへ`fill-color`を再適用
  - `makeEnsureAxisRampLayer`: 既存レイヤーへ`line-color`を再適用
  - `ensureDynamicWeatherLayer`: raster(`raster-opacity`)・gridFill(`fill-color`/
    `fill-opacity`)・gridMark(`icon-color`/`icon-halo-color`/`icon-halo-width`)・
    vector(`line-color`/`line-width`)のいずれも既存レイヤーへ再適用
- `frontend/src/components/Map/MapView.layerOps.test.ts`: 回帰テスト追加
  （windAxis/gradientAxis/gradientFillレイヤーが既存の状態でboundariesを変えると
  setPaintPropertyが呼ばれること、`ensureDynamicWeatherLayer`のgridFillも同様）
- `docs/design-principles.md`: 「関連する過去の逸脱」節へ本件を追記
- `.claude/commands/review/principles.md`: 「判断原則」16番として一般化
  （「実害が無い」を理由に構造的欠陥を放置しない）

## 検証結果

- frontend: `tsc --noEmit`・`eslint`ともにクリーン
- `npx vitest run src/components/Map/MapView.layerOps.test.ts` 16件成功（新規5件含む）

## 残課題

- 本番DBの`display_thresholds_override=[10,20,30,40,50]`という異常値自体の是正は
  本タスクの対象外（風penalty面塗り自体が撤去されたため実害は解消したが、`windAxis`
  経由の道路色分けにはまだ影響する）。1m/s単位の粒度で設定し直したいというユーザー
  意向あり、別タスクでの対応を検討。
