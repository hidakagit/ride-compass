# T628. 「ルート設定」「ルート結果」パネルのボタン系スタイルを統一する 規模M

状態: 完了（2026-09-06起票・同日実装完了）

## 背景

ユーザー指摘（2026-09-06、「ルート生成パネルとルート結果パネルで、ボタンの色味とか
不統一感がある。ルート結果パネル側にデザインやスタイルを統一させて。」）を受けた対応。
バックグラウンド調査エージェントによる監査で、両パネルのボタン・チップ系要素が
枠線色・角丸・背景・disabled表現の面で個別実装されておりバラバラであることを確認した:

- 枠線色: 「ルート設定」側（`.stepperButton`・`.modeToggle`・`.destinationChip`系・
  `.legendChip`・`.resetButton`）は`var(--color-border-strong)`、「ルート結果」側の
  `.outcomeHeaderIcon`は一段薄い`var(--color-border)`。
- 角丸: 「ルート設定」側の大半は`var(--radius-sm)`（トークン参照）に対し、
  `.outcomeHeaderIcon`だけがトークンを使わないハードコード値`4px`。
- 背景: `.resetButton`は塗り（`var(--color-surface)`）、`.outcomeHeaderIcon`は透明。
- disabled表現: `.stepperButton:disabled`は文字色・枠線色を個別に上書きする方式、
  `.outcomeHeaderIcon:disabled`は`opacity: 0.4`のみ。
- タブトリガーのpadding: `RouteForm.module.css: .tabTrigger`が`0.4rem 0.2rem`、
  `page.module.css: .outcomeTabTrigger`が`0.4rem 0.5rem`（フォントサイズ・太さ・
  active色・border-bottomの仕組みは元々同一）。

ユーザーへ対象範囲を確認（AskUserQuestion）し、「チップ/ピル型も含めて全部」を
選択。ピル形状（`border-radius: 999px`）自体は役割上（トグルチップ・セグメント
コントロール）残しつつ、色トークンだけ「ルート結果」側の値へ揃える方針とした。

## 対応内容

「ルート結果」側の値（`var(--color-border)`・`var(--radius-sm)`）を基準に、
「ルート設定」側の各要素を合わせた。角丸だけは逆方向——`.outcomeHeaderIcon`の
ハードコード`4px`が、他の全要素（`.stepperButton`・`.resetButton`・
`.legendInfoPopover`・`.hardFilters`等）が既に使っている`var(--radius-sm)`から
外れた側だったため、`.outcomeHeaderIcon`側を`var(--radius-sm)`へ合わせた
（マジックナンバーをトークン参照へ統一する意味も兼ねる）。

- `frontend/src/app/page.module.css`: `.outcomeHeaderIcon`の`border-radius: 4px`
  → `var(--radius-sm)`。
- `frontend/src/components/RouteForm/RouteForm.module.css`:
  - `.tabTrigger`のpaddingを`0.4rem 0.5rem`へ（`.outcomeTabTrigger`と同じ値）。
  - `.stepperButton`の枠線色を`var(--color-border)`へ。`:disabled`は文字色・枠線色の
    個別上書きをやめ`opacity: 0.4`のみに統一（`.outcomeHeaderIcon:disabled`と同じ
    仕組み）。
  - `.modeToggle`（周回/目的地セグメントコントロールの外枠）の枠線色を
    `var(--color-border)`へ。
  - `.destinationChip`系（基本状態のみ、Armed/Setはアクセント色の意図的な状態のため
    対象外）の枠線色を`var(--color-border)`へ。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.module.css`:
  - `.legendChip`の枠線色を`var(--color-border)`へ。
  - `.resetButton`の枠線色を`var(--color-border)`へ、背景を`transparent`へ
    （`.outcomeHeaderIcon`・同パネル内`.stepperButton`と同じ「枠線のみ・塗りなし」に
    揃える）。

対象外にしたもの（理由付き）:

- `Map/LayerChip.module.css: .chip`（「除外する道路」チップが使う）: 地図上の
  レイヤーON/OFFチップ（`MapOverlayControls`・`MapLayersPanel`）と共有する部品で、
  この2パネル以外にも表示範囲が及ぶため、今回のスコープ（2パネル間の統一）には含めない。
  `box-shadow`を持つ点がパネル内の他要素とも既に不揃いだが、これも同じ理由で見送り。
- `.hardFiltersBadge`（`border: var(--color-accent)`）・`.legendInfoButton`・
  `.legendInfoPopover`・`.stackBarDragBadge`: ボタンではない（アクセント色の意図的な
  バッジ、ポップオーバー本体の枠、押せない浮動バッジ）ため対象外。
- globals.cssの`@layer base`グローバル`<button>`リセット・`button[type="submit"]`・
  `ui/Button`（CVA）・`.modeButtonActive`のアクセント色定義が3箇所独立している点
  （監査で指摘）: 今日時点で見た目の不一致は生じておらず、直すなら
  アクセント色システム自体の再設計になり本タスクのスコープ（2パネル間の色味の
  不統一感解消）を超えるため見送り。必要になれば別タスクで扱う。
