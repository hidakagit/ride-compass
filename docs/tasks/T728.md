# T728. T718の材料内訳を本番で表示されるようにする 規模M

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 I-2＋I-3（P1））

## 背景

categorical材料の内訳表示が本番で一度も動いていない。backendの区間集約（`_merge_segment_bin`）が`material_categories`を落とし、frontendの実行時カタログ（`useAxisCatalog: buildCatalog`）が`materialBreakdown`を落とす。独立した2箇所で壊れている。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## I-2（backend）: 区間集約でcategorical材料が落ちていた

### 設計判断: 引き継ぐのではなく、畳む位置を前へ動かす

素直な修正は`_merge_segment_bin`へ`material_categories`を書き足すことだが、**ビンの代表値を
1つ選んだ時点で延長割合が500m単位へ量子化される**。正しい割合はEdge単位のsegmentsからしか
作れないため、`merge_material_category_shares`を`aggregate_segments_into_bins`の**前**へ
動かした。

区間単位の`material_categories`には消費者がいない（frontendが読むのはルート全体の
`material_category_shares`だけ）。ビンへ引き継いでも使われないうえペイロードが増えるため、
**引き継がないことを`BIN_DROPPED_DICT_FIELDS`で理由つきに宣言**し、テストがその宣言と
モデルを突き合わせる形にした。

`RouteCandidate`の生成箇所は`road_graph_engine.py`の1箇所だけ（grepで確認）なので、
そこで計算して候補へ載せれば漏れない。`route_generator._with_material_values`からは
categorical側の再計算を外した——区間側が空である以上、残すと必ず`{}`で上書きされる。

### 検知テストが見逃した理由と、その是正

`test_aggregate_segments_into_bins_carries_every_dict_field`が
`field.annotation == dict[str, float]`で母集団を絞っており、`dict[str, str]`の
`material_categories`が最初から検査対象外だった。空回り防止の`assert dict_fields`は
「0件でないこと」しか見ないため、母集団が縮んでいること自体は検知できない。

`typing.get_origin(...) is dict`で**値の型を問わない**形へ広げた。プローブ値は
フィールドの値型から作る（`str`なら`"residential"`、それ以外は数値）。

## I-3（frontend）: 同じビューモデルを3経路が別々に組み立てていた

`PreferenceAxisDef`の生成が実行時API経路・静的フォールバック2経路に分かれ、
実際に**違うフィールドを落としていた**（実行時は`materialBreakdown`、静的②は
`displayThresholdsOverride`/`displayBandLabelsOverride`）。全フィールドがoptionalのため
型検査では現れない。

`preferenceAxisFromCatalog(axis: CatalogAxis)`を唯一の変換にし、両経路がこれを通る形へ。
静的フォールバックの「SECONDARY_AXES由来」の分岐は撤去した——`SECONDARY_AXES`自体が
`axisCatalog.axes`から導出されているため、**並び順だけをそこからなぞり、中身は必ず
カタログから組み立てる**形にできる。

## 検証結果

いずれも「直す前の壊れ方で落ちること」を確認してから戻した。

別に置いた（各フィールドについて「実例が1つ以上ある」ことも併せて確認し、空回りを防ぐ）。
