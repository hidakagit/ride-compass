# T829. 動的気象タイルの切り替えで、MapLibreが「ArrayBuffer is detached」を吐く

規模S。
状態: 未着手（2026-09-13、ユーザー報告の実機ログ
`[map:error] Failed to execute 'postMessage' on 'Worker': An ArrayBuffer is detached and could not
be cloned. {"sourceId":"region-dynamic-weather-disaster-flood-vector"}`）

## 背景（調査でここまで分かっている）

- `sourceId`は`dynamicWeatherIds(id, source, "vector")`が組み立てるベクタタイルのソース
  （`MapView.tsx`）。時刻のコマを送るたびに`setTilesIfChanged`が`source.setTiles([...])`で
  タイルURLを差し替える。
- `setTiles`はソースを丸ごと再読み込みさせるため、**前のURLのタイルがまだワーカーへ飛んで
  いる最中に差し替わる**と、既に転送（transfer）済みのArrayBufferをもう一度postMessageする
  形になり、この文言で失敗する。`setTilesIfChanged`はURLが変わったときだけ呼ぶ実装で、
  同じURLの二重適用は既に防いである——つまり残っているのは**コマ送り（URLが実際に変わる）と
  取得中のタイルの競合**。
- 実害は「そのタイルの解析が1回落ちる」ところまでで、MapLibreは次の要求で取り直す。ただし
  エラーログとしては毎回出るため、本物の障害を埋もれさせる。

## 調査項目

1. どのコマ送りで出るか（自動再生・手動スライダー・レイヤーON/OFFの直後）を実機で切り分ける。
2. `setTiles`の代わりに「ソースを消して作り直す」「コマ送りをデバウンスする」「URLに時刻を
   持たせて1ソースのまま`setFilter`で切り替える」のどれが筋かを比べる。3つ目が可能なら
   再読み込み自体が消える。
3. 他のベクタ動的ソース（線状降水帯等）でも同じログが出るかを確認する（出るなら共通の機構で
   直す。出ないなら洪水だけの事情がある）。
