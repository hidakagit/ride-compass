# T842. コードの書式を機械に決めさせる（prettierの導入、段階適用）

規模M。
状態: 完了（2026-09-14、ユーザー指示「そういう議論をするなら入れたら？」から）

## 背景

frontendに**フォーマッタが無い**（prettierはdevDependencyにも設定ファイルにも無く、eslintも
行幅・改行のルールを持たない）。そのため書式は各自の手癖で決まり、既存コードの中でも揃って
いない。

[T840](T840.md)の作業中、書式を整えるつもりで`npx prettier`を一時インストールして使い、既定の
`printWidth 80`で既存と違う書式を持ち込んだ（不自然に折り返された箇所は手で戻した）。
**手で揃える議論をするより、機械に決めさせる方が筋が通る**というユーザー判断。

## 実測（2026-09-14）

- frontendの`.ts`/`.tsx`は317ファイル・48,308行。80文字超が7.3%、120文字超が**0.5%**、
  140文字超が0.1%。大半は120文字以内に収まっている。
- `printWidth: 120`で`--list-different`を取ると、**317ファイル中157ファイル**（約半分）が
  変更対象になる。

## 方針: 設定だけ入れて段階適用（ユーザー選択）

**既存157ファイルを一括整形しない。** このリポジトリは並行セッションが同じファイルを次々に
変更しており（T840の作業中だけでT837・T838・T841がpushされた）、一括適用はコンフリクトを
多発させる。本質的な変更が書式差分に埋もれてレビューもしづらくなる。

- `prettier`をdevDependencyへ追加し、`printWidth: 120`の設定を置く。
- pre-commitで**ステージしたファイルだけ**を整形する（`scripts/pre-commit-prettier.sh`を
  追加し、`pre-commit.sh`から呼ぶ）。既存の`pre-commit-ruff.sh`と同じ骨格——対象を
  ステージ済みへ絞り、prettierが見つからない環境では警告のみでコミットを止めない。
- 一括適用は、並行作業が落ち着いたタイミングで別途判断する（本タスクではやらない）。

backend側の`ruff format`も同じ議論になるが、まずfrontendだけで運用を見る。

## 実装（2026-09-14）

- `frontend/package.json`へ`prettier@3.9.6`（devDependency、バージョン固定）。
- `frontend/.prettierrc.json`は`printWidth: 120`の1項目だけ。他は既定に任せる——決める理由が
  無いものを決めると、その分だけ後から動かしにくくなる。
- `frontend/.prettierignore`で生成物（`src/types/generated/`）を外す。あれは
  `export_openapi.py`とopenapi-typescriptが書くもので、手で整える対象ではない。
- `scripts/pre-commit-prettier.sh`を追加し`pre-commit.sh`から呼ぶ。骨格は
  `pre-commit-ruff.sh`と同じ（ステージ済みだけを対象、prettier不在ならsoft-fail）。
  **`--check`ではなく`--write`で直してから`git add`し直す**——書式は人が直す価値のある指摘では
  なく、落として書き直させるのは手間だけが増える。

**CIには入れていない。** 変更分だけを`--check`する形にはできるが、pre-commitで直った状態が
コミットされる以上、CIで重ねて見る必要が今は無い。pre-commitを導入していない環境で書式が
揃わない事態が実際に起きたら、そのとき足す。

## 検証

pre-commitスクリプトを**わざと未整形のファイルで動かして確かめた**（実装しただけで終わらせない）。

| 確かめたこと | 結果 |
|---|---|
| 未整形のファイルが整形される | `export const zzzProbe   =    {a:1,b:2};` → `export const zzzProbe = { a: 1, b: 2 };` |
| 整形結果がステージへ反映される | 未ステージの差分が残らない（`git add`し直しが効いている） |
| 既存の未整形ファイルを巻き込まない | 作業ツリーの変更0件（ステージしたもの以外は触らない） |
| prettierが無い環境で止まらない | 警告のみ・終了コード0 |

既存164ファイルは未整形のまま残る（一括適用しない方針のため）。触ったファイルから順に揃う。
