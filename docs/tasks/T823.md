# T823. 契約を検証していないテスト・誤った挙動を固定するテストを是正する

規模S〜M。
状態: 完了（2026-09-14。統合レビュー第8回のP2/P3を束ねたもの、2026-09-13起票）

## 背景

「実装を変えてもテストが落ちない」箇所と、その逆に「**誤った挙動をテストが守っている**」箇所。
時刻ビン（[T812](T812.md)）・`conditionsDirty`（[T815](T815.md)）・`legendAxes`
（[T816](T816.md)）・`penalty_strength`（[T817](T817.md)）・`routeStyleModes`のスケール
（[T809](T809.md)）が扱う分を除いた残り。

## 対象

### 契約を検証していない

- `backend/tests/test_search_graph_cache.py:146-152`: T790で追加された
  `_turn_structure_cache`・`_detour_ratio_cache`を検証するテストが1件も無く
  （`grep "turn_structure\|detour"`が0ヒット）、`clear`のテストは名前・中身とも旧2キャッシュの
  ままで「全消し」を主張している。`invalidate_tile_set`から`_turn_structure_cache.pop_matching`を
  削除しても全テストが緑で通り、再split後に**旧Edge番号の遷移表と新しいCSRが組み合わさる**
- `frontend/src/components/Map/jmaTileProtocol.test.ts:70`: 「差し替えるたびに最新のものが
  使われる」というテストが`hasJmaTileIndex()===true`を2回確認するだけで、差し替えが効いたことを
  検証していない。2回目をno-opにしても緑。実害は「basetimeが進んだのに旧世代のpresent集合で
  判定し、中身のある新しいタイルを空と誤判定して危険情報が地図から消える」
- `frontend/src/components/Map/MapView.routes.test.ts:253`: 「redrawAllLayers経由でも…の
  直接的な検証」と題しながら、呼んでいるのは`applyRouteLayerVisibility`単体。
  `redrawAllLayers`が実際にそれを呼ぶことも、新設レイヤーを再描画対象に入れ忘れたことも
  検知できない（[T825](T825.md)のsplice帯の取り残しが現にこれで素通りしている）
- `frontend/src/lib/routeTabLabel.test.ts:63-66`: 「backendが付ける接頭辞と、フロントが
  組み立てるidが同じ1つの値から出る」と契約を宣言しながら、アサーションはフロント定数の
  リテラル確認のみ。backendが`"route-merged"`へ改名しても落ちず、合成ルートが一覧で
  生成候補と見分けられなくなる
- `backend/app/batch/precompute_way_attribute_counts.py:47-48`: edge版とway版の
  `ALGORITHM_VERSION`の一致を「コードレビュー時の目視確認」と明記している。**1行のテストで
  機械化できる**（CLAUDE.md「再発防止として自己申告のチェックを増やさない」）

### 誤った挙動を固定している

- `frontend/src/app/page.test.tsx:332-339`: 撤去済みサイドバーを案内する文言
  `[設定はサイドバー]`を末尾一致で固定している（[T811](T811.md)と同時に直す）
- `frontend/src/components/WeatherPanel/weatherCode.test.ts:43-48`: 本番で到達しない
  `MoonIcon`分岐を固定している（[T819](T819.md)で`isDay`を撤去するなら同時に落とす）

### 母集団の穴

- `frontend/src/components/Map/routeStyleModes.test.ts:22-205`: 動的モードの検証対象が
  gradient / wind / surface_q に限られ、「ramp軸かつ`display_thresholds_override`あり」という
  カタログ実在の組み合わせを1件も通していない（[T809](T809.md)で塞ぐ）
- `backend/tests/test_routing_turn_expanded.py`: 2次元コスト経路が無い（[T812](T812.md)で塞ぐ）

## 進め方の注記

**いずれも「わざと壊して落ちる」ことを確認してから完了扱いにする。** 上記はどれも
「テストがあるのに守れていない」型なので、直したテストが実際に欠陥を捕まえることを
示さない限り、同じ状態が名前を変えて残る。

## 実施結果

### 契約を検証していない

- **`test_search_graph_cache.py`**: 「2つとも」を見ていたテストを、**モジュールが持つ
  キャッシュを母集団として引く**形へ変えた（`vars(search_graph_cache)`から`*_cache`を
  拾う）。キャッシュを1つ足したとき、テスト側の一覧を更新し忘れても素通りしない。
  `invalidate_tile_set`が全キャッシュから落とすことも同じ形で見る。
- **`jmaTileProtocol.test.ts`**: ハンドラが実際に使う判定を`isKnownEmptyTileUrl`として
  公開し、差し替え後に**古い版で判定し続けていないこと**を見る形にした。
  `hasJmaTileIndex()`を2回見るだけでは、古いインデックスを握り続けても気づけない。
- **`routeTabLabel.test.ts`**: 接頭辞をbackendの`SPLICED_ROUTE_ID`から生成物
  （`route-generate-config.json`）経由で配り、テストは生成物と突き合わせる。フロント定数の
  リテラル確認では、backendが改名しても落ちなかった。
- **`precompute_way_attribute_counts.py`の版数一致**: 「コードレビュー時の目視確認」を
  やめ、1行のテストにした（CLAUDE.md「再発防止として自己申告のチェックを増やさない」）。
- **`MapView.routes.test.ts`**: 題が名乗っていた「`redrawAllLayers`経由でも」の検証は
  実際には行っていないため、**題を実態へ合わせた**（見ているのは
  `applyRouteLayerVisibility`単体の冪等性）。再描画の網羅そのものは[T825](T825.md)が
  担保する——題と中身がずれたままだと「検証済み」と読めて取り残しが素通りする。

### 一覧のうち、既に解消されていたもの

- `page.test.tsx`の`[設定はサイドバー]`固定は[T811](T811.md)で、`weatherCode.test.ts`の
  `MoonIcon`分岐は[T819](T819.md)で、それぞれ同時に解消した。
- `routeStyleModes.test.ts`の母集団は[T809](T809.md)、2次元コスト経路は[T812](T812.md)の
  範囲のため本タスクでは触らない。

## 検証結果

いずれも**わざと壊して落ちることを確認**した。

- `invalidate_tile_set`から`_turn_structure_cache.pop_matching`を消すと、新しいテストが
  `assert _cache_sizes() == ...`で落ちる（以前は全テストが緑のまま通っていた）。
- `setJmaTileIndex`の2回目をno-opにすると「差し替えるたびに最新のものが使われる」が落ちる。
- `pytest -q -m "not postgis"` → 1958 passed、`ruff check app tests scripts` → All checks passed。
- `npx vitest run` → 142ファイル 1339 passed、`tsc --noEmit`は既存の`LayoutProps`のみ。
