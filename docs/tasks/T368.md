# T368. 出発地点表示の文字を廃止しピンの色分けだけで伝えるよう簡素化 規模S（2026-08-27完了）

状態: 完了


- 背景: T366で出発地点の手動指定ボタンを追加した直後、ユーザーから「出発、現在地って
  表示必要？これは何のために出すのか考えて」という指摘（2026-08-27）。表示目的を
  整理したところ「(1)起点位置の確認 (2)実際のGPS位置かフォールバックかの区別」の
  2つがあり、(1)は地図上のピンで既に視覚的に分かる、(2)は文字でなくても伝えられる、
  という結論になった。続けてユーザーから「起点位置はピンで視覚的に分かる、GPS取得
  失敗かどうかは例えばピンの色がグレーになる等で区別し、なるべく文字で出さないような
  工夫はできる？」という具体的な設計方針が示された。
- 対応: `LocationControl.tsx`から「出発地点: …」の常時表示テキスト＋緯度経度を完全に
  撤去し、出発地点を手動指定するアイコンボタン（📍、T366）1つだけを残す構成にした
  （`compact`propも表示差分が無くなったため削除）。状態の説明（現在の出発地点の種別・
  座標）はaria-label/titleへ退避し、ボタン自体は常時見えるが文言は明示的に読みに
  いったときだけ見える形にした。GPS取得成否の区別は`MapView.tsx`の現在地マーカーの
  色で伝える: `locationSource==="default"`（GPS取得失敗・非対応時のフォールバック、
  初期地点=王子）だけをグレー（`#9ca3af`）にし、それ以外（実際のGPS取得・手動指定は
  どちらも「意図した位置」という点で同格）は従来どおりの赤（`#e11d48`）のまま区別しない。
  `maplibregl.Marker`は生成後に色を変更するAPIを持たないため、`appliedMarkerSourceRef`で
  直前に適用したsourceを記録し、実際に変わった場合だけremove→再生成する
  （単純化のため常に作り直すと不要な再生成・視覚的なちらつきが増えるため、位置だけの
  更新は従来どおり`setLngLat`で済ませる）。
- テスト: `LocationControl.test.tsx`を全面書き換え（常時表示テキストが無いことの検証、
  originState/source別のボタンaria-label検証、クリック配線）。frontend全体697件成功
  （T367完了後のカウントから常時表示テキストのテスト削減ぶんが反映された数値）、
  tsc/eslintクリーン。実機確認は、同一リポジトリを共有する並行セッションが別ポートで
  devサーバーを稼働中だったため新規に別ポートを立てるとNext.jsのロックで失敗し断念、
  コードレビューと既存の自動テストでの検証に留めた（次回セッションでの実機確認が望ましい）。
