# T697. 負の生値を持つ軸で分布プレビューが嘘の分布と正反対の助言を出す問題を直す 規模M

状態: 未着手（2026-09-10起票、統合レビュー第6回 I-6）

## 背景

[T686](T686.md)で作った軸スタジオの分布プレビューが、**生値が負になる軸で嘘の分布を返し、
事実と正反対の助言を出す**。

backend `services/axis_preview_service.py:128-141`:

```
upper = quantiles["p99"] * 1.2 if quantiles["p99"] > 0 else max(upper, 1.0)
i = min(HISTOGRAM_BINS - 1, int(value / width)) if width > 0 else 0
buckets[max(0, i)] += m
zero_share = sum(m for m, v in ordered if v <= 0) / total_m
```

負値のみの分布では`upper`が1.0へ倒れ、`int(value/width)`が負になる行を`max(0, i)`が
階級0へクランプするため、**全サンプルが1本の階級へ潰れ`zero_share=1.0`になる**。

負の生値を持つ公開軸は3本で、うち**2本は公開済み**:

| 軸 | 生値の範囲 | 構成 |
|---|---|---|
| `openness` | 約 -160〜0 | `trees_percent`×-1 + `built_percent`×-1 |
| `bicycle_infra_quality` | -4〜0 | terms全て負の重み |
| `night` | 負 | `lit`×-50 |

frontend `components/AxisStudio/scoreDistribution.ts:56-70`は`bins`の値域を一切検証せず
階級中央値へ折れ点を当てるため、`openness`は「**100点 100.0%**」と描画され、
`distributionWarnings`（同`:81-90`）が
**「延長の100%が満点に張り付きます。上限を高くしないと道の差が出ません。」**を出す。
実際のp50=-79は約31点で、**助言に従って上限を上げると軸が壊れる**。

しかも同一パネル内の`DistributionPreview.tsx:52-57`は正しい分位（p10=-144…）を表示しており、
**画面上で自己矛盾した2つの数字が並ぶ**。

## 対応方針

- backend: 階級の下限を`min(0, データ下端)`から取る。`zero_share`は語（「ゼロ」）と
  定義（`v <= 0`）のどちらを正とするか決める（frontend `MaterialRangeHint.tsx:23`は
  「ゼロX%」と表示している）。`ValueDistribution`のdocstring（`:45-51`）が
  `bins`を「(下限, 上限, 割合)」と述べる契約も実装へ合わせる。
- frontend: `quantiles.p10 < bins[0][0]`（ヒストグラムがデータ下端を覆っていない）を検知し、
  帯・警告を出さず「この設定では分布を表示できません」へ倒す。
- **`axis_preview_service`にはbackendテストが1件も無い**（`backend/tests/`全体で
  `axis_preview`・`value_distribution`・`_distribution`のいずれもヒットしない）。
  分位算出（`:120-127`）・階級化（`:132-140`）・`_raw_value`の`required`/`preprocess`分岐
  （`:88-107`）はいずれも純関数でテストしやすい。これが検知されなかった直接の原因なので同時に置く。

## 関連する空状態の欠落（同じパネル）

`DistributionPreview.tsx:36-40`は`sample_ways=0`を「分布あり」として扱い、
全帯0.0%のバーと「0本（0km）」という無意味なパネルを出す。
`way_scalar_materials`はルート文脈が要る材料（`gradient_percent`・`wind_drag_ratio`）を
常にNoneで返す（`axis_inspector.py:120-122`）ため、公開軸の`gradient`・`wind`を編集で開くと発生する。
分岐は`!distribution`（null）でしか空状態にならない。
