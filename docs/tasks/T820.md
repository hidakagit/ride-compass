# T820. 無言のフォールバック・失敗の握り潰しを是正する

規模M。
状態: 完了（2026-09-14。統合レビュー第8回のP2を束ねたもの、2026-09-13起票）

## 背景

例外も警告も出さずに縮退し、**結果だけが静かに変わる**箇所。どれも
`docs/logging.md`の「エラー・候補0件はWARNING以上で常時出す」に反しているか、
3値の状態を2値へ潰している。

## 対象

- `services/road_graph_engine.py:1937-1959`: `_turn_seconds_along`が経路上の1本でも
  `(from,to)`のNode対を`edge_index_by_node_pair`に見つけられないと、そこで`return 0.0`して
  **経路全体**のターンの待ちを捨てる。ログは一切出さない。`build_traced_from_edge_ids`
  （区間の乗り換え）はクライアント由来のedge_id列を受けるため、合成ルートだけ
  `estimated_duration_seconds`からターン分（都市部30kmで数分〜十数分規模）が丸ごと消え、
  元候補や基準線より不当に速く見える
- `components/RouteSplicePanel/RouteSplicePanel.tsx:76`: `stretches.length === 0`を無条件に
  「この2本は同じ道を通ります。」と表示するが、`pairedStretches`（`page.tsx:804-807`）は
  **区間の対応づけを諦めたとき**にも空配列を返す。`unavailable`ガードは`displayed.edge_ids`
  しか見ておらず`targets`側を見ていないため、**まったく別の道を通る2本に「同じ道を通る」と
  断言する**
- `Map/jmaTileProtocol.ts:68`: `response.ok`でない応答を404と5xxの区別なく空タイルへ倒す。
  MapLibreのerrorイベントも発火しないため`markSourceErrored`も走らず、キキクルは
  「平常時は透明」が正常系なので**利用者が障害を危険度ゼロと誤読しうる**
- `hooks/useDynamicWeatherLayers.ts:159-162`: 降水短時間予報（rasrf）について
  「取得失敗はnowcastと同じくエラーメッセージへ記録する」と書きながら`data`だけを取り出し
  `error`/`loading`を捨てている。rasrfだけが落ちても「降水」チップは正常表示のまま
  6時間以降の予報だけが欠ける
- `services/road_graph_engine.py:1479-1480`: via-node候補を`np.flatnonzero(within_stretch)`の
  **Node index順**で`MAX_VIA_NODE_CANDIDATES_EXAMINED`（2,000件）へ切ってから、パレート層・
  difficultyで並べる。周回側（`:1249`）は`np.lexsort(...)`で**並べてから**切っており規則が
  食い違う。しかもINFOログは打ち切り**後**の件数を`within_stretch=%d`として出すため、
  運用側から打ち切りの発生自体が見えない
- `services/road_graph_engine.py:419-421, 466-471`: 風の時別系列が無いときキャッシュキーが
  `("snapshot",)`のみのため`compose("inbound", ...)`が`compose("outbound", ...)`の
  オブジェクトをそのまま返し、`compose_leg_costs`のINFO行が1本しか出ない（labelも
  最初の呼び出しのもの）。風データが無い環境で「復路レグの合成が走っていない」と誤診する
- `infrastructure/material_coverage.py:205-228`・`derived_data_freshness.py:173-184`:
  一部の材料で欠損率の分母がバッチの対象母集団より広く、**構造的に0へ到達しない**
  （`trees_percent`/`built_percent`の分母は`osm_raw_ways`全行だがバッチ対象は
  `geom IS NOT NULL AND highway IS NOT NULL`、`curvature_deg_per_km`の分母は`road_edges`全件だが
  対象は`distance_m > 0`）。運用者は「もう一度流せば0になるはず」と読むが決してならず、
  未実行なのか対象外なのかを画面から区別できない

## 実施結果

- **`_turn_seconds_along`**: 探索グラフに無いEdgeは「そこで経路が切れた」ものとして扱い、
  **その前後の遷移だけ**を数えない形にした。経路全体を捨てない。捨てた事実はWARNINGで残す。
- **via-node候補の打ち切り**: `np.flatnonzero`のNode index順ではなく、パレート層・difficultyで
  **並べてから**切るようにした（周回の折返し点選定と同じ規則）。打ち切りが起きたこと自体も
  WARNINGで出す。INFOの`within_stretch`は打ち切り前の件数になった。
- **風のスナップショット共有**: 同じ内容を使い回すこと自体は正しい（風が時刻で変わらない
  レグは1本で足りる）ので、使い回した事実をINFOで残す形にした。合成のログがレグの数だけ
  出ないために「復路の合成が走っていない」と誤診する余地を消す。
- **rasrf（降水短時間予報）**: `error`/`loading`を捨てずに「降水」グループの状態へ合流させた。
  チップ自体は`extended`予報へフォールバックして動き続けるが、6時間以降が欠けたことを
  黙って隠さない。
- **欠損率が0へ到達しない件**: 担当バッチの対象外の行を欠損に数えないようにした
  （`trees_percent`/`built_percent`は`geom IS NOT NULL AND highway IS NOT NULL`、
  `curvature_deg_per_km`は`distance_m > 0`）。母集団（分母）は全件のままにする——
  [T849](T849.md)が鮮度台帳で採ったのと同じ扱いで、「全体のうち何件か」を読む数だから。
- **JMAタイルの404と5xx**: 区別して記録するようにした（空タイルで返すこと自体は正しい。
  例外にするとMapLibreが再試行せず、その位置が永久に空白になる）。**画面への表出は
  [T852](T852.md)へ分離した**——プロトコルハンドラはMapLibreのソースidを知らず、
  レイヤーの状態へ繋ぐには別の経路が要る。
