# T719. 停止密度の旧集計（stop_count/intersection_count）を撤去する 規模M

状態: 完了（2026-09-11起票・同日完了。[T655](T655.md)完了に伴う分離）

## 背景

[T655](T655.md)で停止密度は停止要因POIの種別別密度（`poi_*_per_km`）だけを材料にする形へ
組み直し、旧材料`stop_count_per_km`（15m近接・全種別一括の数え方）を`MATERIAL_CATALOG`から
撤去した。これで**軸スタジオの材料一覧から誤った数え方が消えた**が、その値を作っている
集計の実体は残っている。

残っている旧集計:

| 場所 | 中身 |
|---|---|
| `edge_attribute_counts.stop_count`・`way_attribute_counts.stop_count` | 15m近接・全種別一括のカウント |
| 同 `intersection_count` | 次数3以上のノードを30m以内で数えたカウント |
| `domain/attributes.py: METRIC_KEY_STOP` | `METRIC_GROUP_COUNTS`へ載せているが、消費する材料が無い |
| `road_graph_repository.py: _STOP_POI_COUNTS_SQL`・`get_stop_poi_counts` | 上記`stop_count`を計算するSQL |
| `domain/traffic.py: STOP_POI_KINDS` | 一括カウント対象の種別一覧 |
| タイルプロパティ`stop_per_km` | `_ROAD_SURFACE_TILE_MVT_SQL`が焼き込む |
| 材料`intersection_count_per_km` | カタログに残るが、これを使う公開軸は無い |

## 保留することで何が起きうるか

- バッチ`precompute_edge_attribute_counts`は誰も読まない`stop_count`を計算し続ける
  （本番319,530 Edgeぶんの集計時間とディスク）。
- 軸スタジオの材料一覧に`intersection_count_per_km`が残るため、停止密度から外したはずの
  数え方を再び軸へ組み込める。外した判断（下記）が記録としてしか残らない。
- タイルへ`stop_per_km`が焼かれ続け、タイルサイズと世代管理の対象が減らない。
- `edge_attribute_counts`へ次に列を足す/減らすとき、[T655](T655.md)「列を1つ足すで3回壊した」
  節が挙げる「列数への暗黙の依存」（pickleの並び順・バインドパラメータ上限・NULL可否）の
  対象が多いまま残る。

## なぜ[T655](T655.md)と同じコミットにしないか

`edge_attribute_counts`の列変更は、`EdgeMaterialTable`のpickle世代
（`CACHED_TABLE_SIGNATURE`）・UPSERTのバインド上限（`MAX_BIND_PARAMS_PER_STATEMENT`）・
migrationのNULL可否という3系統へ同時に波及する。材料（読み手）の撤去と列（実体）の削除を
1コミットへ混ぜると、本番で壊れたときにどちらが原因か切り分けられない。

## 決定: `intersection_count_per_km`は残す（2026-09-11）

起票時の完了条件は「使う軸が無いなら集計・タイル・材料ごと消す」としていたが、
**`stop_count`と`intersection_count`は「読み手が無い」の意味が違う**ため、同じ扱いに
しない。

| | 材料としての状態 | 判断 |
|---|---|---|
| `stop_count` | 材料`stop_count_per_km`が[T655](T655.md)で**撤去済み**。カタログに無いので軸スタジオから選べず、値を読む経路がどこにも無い | 撤去する |
| `intersection_count` | 材料`intersection_count_per_km`は**カタログにある**。使う公開軸が今は無いだけで、軸スタジオから選べば追加のコード変更なしに軸を組める | 残す |

後者は死んだ配線ではなく、「評価軸追加の1本道」（[design-principles.md](../design-principles.md)）が
通っている材料である。撤去すると、[T655](T655.md)「交差点密度の扱い」が残した選択肢
（次数4以上へ絞って「注意・減速の頻度」の軸にする）を、コード変更なしには試せなくする。
数え方自体は正しいため、撤去する側の利点が無い。

したがって本タスクの対象は`stop_count`のみとし、完了条件も下記へ改めた。

## 対応方針

1. 読み手（`METRIC_KEY_STOP`・`EdgeAttributeCounts.stop_count`・`EdgeMaterialTable`の列・
   区間インスペクタ・軸スタジオのプレビュー）を先に撤去する。
2. 集計側（`_STOP_POI_COUNTS_SQL`・`get_stop_poi_counts`・way集計SQLの`st` LATERAL・
   `STOP_POI_MATCH_MAX_DISTANCE_M`）とタイル列`stop_per_km`を撤去する。
3. **最後に**migrationで列を落とす。
4. タイル世代（`ROAD_SURFACE_TILE_VERSION`）・ディスクキャッシュ世代
   （`TILE_MATERIALS_CACHE_VERSION`）・pickle列署名（`CACHED_TABLE_SIGNATURE`）を
   同一コミットで上げる。

`STOP_POI_KINDS`は残す——停止要因POIタイルの`kind`絞り込みと`poi_counts`の集計対象を
決めており、`stop_count`専用ではない。

## 途中で見つけた穴: 未知フィールドが黙って捨てられていた

`EdgeAttributeCounts`は`extra`の既定（`ignore`）のままだったため、列を消した後も
`stop_count=2`を渡すテストが**例外にならずそのまま通り続けた**。値は捨てられ、
アサーションだけが残る形で、撤去漏れがどこにも現れない。

`model_config = ConfigDict(extra="forbid")`を足して弾くようにした。同型の穴が他の
ドメインモデルにも残っていないかの点検は本タスクの範囲外（[T721](T721.md)）。
