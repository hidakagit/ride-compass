# T729. ensureLayerFromSpecが凡例フィルタを巻き戻すのを止める 規模M

状態: 完了（2026-09-12。起票は2026-09-11、統合レビュー第7回 I-4（P1））

## 背景

specに`filter`キーが無いレイヤーで`setFilter(id, undefined)`が走り、`setStaticOverlayFilters`が外から与えた凡例の絞り込みが解除される。本日paintについて是正したのと同じ構造がfilterに残っている。

詳細な指摘（Evidence・Impact・Root Cause・Recommendation）は[history/2026-09-11_all.md](../../.claude/commands/review/history/2026-09-11_all.md)を参照。

## 対応方針: specへ畳めないものは、持ち主を宣言させる

T712がpaintについて直したのと**同じ構造**がfilterに残っていた。paintのときは
「下敷きの太さをspecの中へ畳む」（[T712](T712.md)・casingの件）で解けたが、filterは
畳めない——凡例のON/OFFという実行時の状態から`setStaticOverlayFilters`が組み立てるもので、
`ensure`側はレイヤー固有の材料関係を知らない汎用描画係のままにしておきたい。

**キーの有無から持ち主を推測していたのが誤り**だった。`filter`キーが無いことは
「自分の持ち物だが今は条件なし」（しきい値がnullへ変わった動的気象レイヤー）と
「外側が管理しているので触るな」（属性レイヤー・ramp軸）の**両方**を意味しうる。
前者のために`undefined`で明示的に外す実装にしたため、後者が巻き添えになっていた。

`ensureLayerFromSpec`へ`specOwnsFilter`を**必須引数**として足し、レイヤーを足すときに
その場で答えさせる形にした（[T748](T748.md)で`OverlayLayerEntry.interactive`へ取った形と
同じ。TypeScriptが答えを強制するため、宣言漏れという概念が消える）。

| 呼び出し | specOwnsFilter | 理由 |
|---|---|---|
| 動的気象レイヤー（raster/fill/symbol/line） | true | specが絞り込みの持ち主。外から与える経路が無い |
| 専用way値レイヤー | true | `STATIC_FILTER_AXES`の対象外で、外から与える経路が無い |
| 属性線レイヤー（指定路線・トンネル・一方通行） | false | `setStaticOverlayFilters`が凡例のON/OFFから与える |
| ramp軸レイヤー | false | 同上 |

## 検証結果

- `ensureLayerFromSpec`の単体テストへ「持ち主でないときは外側の絞り込みに一切触らない」を
  追加（paint・layoutの再適用は止めないことも併せて見る）。
- 巻き戻りそのものを見る統合テストを`MapView.overlayFilters.test.ts`へ追加した
  ——`setStaticOverlayFilters`で絞り込みを与えた後に`layer.ensure(map)`を呼び、
  `setFilter`の呼び出し履歴が増えないことを属性レイヤーとramp軸の両方で確認する。
- **`specOwnsFilter: false`の2箇所をそれぞれ`true`へ戻すと、対応するテストが落ちることを
  確認**（`expected [ { …(2) }, { …(2) } ] to deeply equal [ { …(2) } ]`）。
- `npx vitest run` → 132ファイル1,214テスト passed。`tsc --noEmit`・`eslint` → 指摘なし。
