# T515: 風の環境グループgridFill、詳細格子の取得範囲を粗格子セルへスナップして二重塗りを解消

状態: 着手中（2026-08-31）

## 背景

風の環境グループ面塗り（`windPenalty.ts`）で、粗い格子（`windGrid`、関東本土全域を
常時カバー）と詳細格子（`windDetailGrid`、ズームイン時に画面中心付近の狭いbboxを
カバー）を重ねて描画する際、両者の境界で半透明のfill-opacityが二重に重なり、色が
凡例と対応しなくなる問題が見つかった（ユーザー報告「色が二重に重なると、他の凡例と
色の区別がつきにくくなり、ユーザー体験としても違和感がある。割と致命的」）。

これまでの経緯（点ごとの近接判定→セル全体の包含判定、いずれも粗いセルの中心座標を
基準にした判定）はいずれも「詳細格子の取得範囲が粗い格子のセル境界と無関係な任意の
矩形（ビューポート中心±固定角度、`clampWindDetailBbox`）である」ことが根本原因で、
判定をどう工夫しても粗いセルの一部だけが詳細格子と重なる状況（部分重複）が起こり得た。

## 対応方針（案A、ユーザー承認済み）

詳細格子の取得範囲を「ビューポートに重なる粗格子セル＋外側1周ぶん」へスナップし、
その範囲に完全に含まれる粗格子セルだけを整数インデックスで丸ごと除外する。粗格子
セルは「詳細格子で置き換える／しない」の二択になり、部分重複（＝色の二重重なり）が
構造的に発生しなくなる。

- backend: `scripts/export_openapi.py`が`wind-grid-config.json`へ`WIND_GRID_BBOX`の
  原点（`origin_lon`/`origin_lat`）を追加で書き出す（フロント側が粗格子ラティスの
  絶対座標を計算するために必要）。
- frontend: 詳細格子のbbox計算（`clampWindDetailBbox`相当）を、ビューポートに重なる
  粗格子セルのインデックス範囲＋1周へスナップする形へ変更。除外判定
  （`coarseGridPointsOutsideDetailBounds`相当）を、粗格子点がこのインデックス範囲に
  含まれるかどうかの整数比較へ変更。

## 既知の制約

詳細格子1リクエストあたり最大900点の上限があるため、極端に横長・低ズームな画面では
「画面を覆うセル＋1周」が収まらないことがある。その場合は間隔を粗くする、またはそれでも
収まらなければ従来同様の縮退を行う——このケースに限り画面内に粗い/詳細の解像度の
継ぎ目（色の二重重なりではなく、単純なセルサイズの違いによる境界線）が残る可能性がある。
