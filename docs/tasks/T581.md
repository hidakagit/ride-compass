# T581: 基礎地図・国土地理院・JMAタイルもbackend直接配信へ（T580の適用範囲拡大）

状態: 着手（2026-09-05起票・同日実装、本番反映待ち）

## 背景

[T580](T580.md)で路面・POI・事故のベクタタイルをRenderフロントを経由せずbackend（HTTP/3）へ
直接取りに行く構成にし、約6〜8倍の高速化を確認した。基礎地図（OpenFreeMap経由のbasemap、
z14で1タイル約730KB）・国土地理院色別標高図・JMA動的タイルは引き続きRender経由で、同じ理由で
同じだけ遅い（アプリ内ブラウザでの初期表示は基礎地図の読み込みに約40秒かかった実測あり）。

## 対応方針（案）

- basemap: スタイルJSON内のタイルURLはbackendが`basemap_public_base_url`で組み立てるため、
  本番backendの環境変数`BASEMAP_PUBLIC_BASE_URL`をbackend自身のオリジンへ変更し、frontendの
  `MAP_STYLE`（`/api/basemap/styles/liberty`、相対パス）を`tileBaseUrl()`で絶対URL化する。
  スプライト・フォントも同じスタイルJSON経由で追随する。
- 国土地理院（`MapView.tsx: GSI_RELIEF_TILE_URL`）・JMA（`riskMap.ts: tileUrlTemplate`・
  `MapView.tsx`のnowcast系URL）: `tileBaseUrl()`を適用する（ラスタタイルは相対パスでも
  動くが、直接配信にするには絶対URLが要る）。
- backend側のレート制限（basemap 300/分/IP等）は直接アクセスで実IP単位になるため、
  そのままでよい。

## 影響（放置した場合）

路面タイルだけ速くなり、基礎地図の読み込みが体感のボトルネックとして残る。

## 実施内容（2026-09-05）

- frontend: `MapView.tsx`の基礎地図スタイル（`mapStyleUrl()`）・国土地理院色別標高図
  （`GSI_RELIEF_TILE_PATH`）・JMA動的タイルのプレースホルダURL、`riskMap.ts: tileUrlTemplate`
  （png/pbfとも）、`precipitationNowcast.ts`・`thunderNowcast.ts`のタイルURLテンプレートを
  `tileBaseUrl()`経由の絶対URLにした。`targetTimes`JSON・lidenのGeoJSON（アプリのfetch()で
  読む小さなデータ）は対象外。`riskMap.test.ts`の期待値を絶対URLへ更新（node環境の
  `precipitationNowcast.test.ts`等は`window`が無く`tileBaseUrl()`が空文字を返すため変更なし）。
- backend: `basemap_client.py`がスタイルJSON/TileJSONを**書き換え前の内容**で
  `basemap-raw/`接頭辞のキーにキャッシュし、`basemap_public_base_url`への書き換えを返す直前に
  行うよう変更。設定変更がキャッシュ全消去なしに反映される（docs/architecture.mdの
  「既知の制約」を解消）。回帰テスト追加。
- docs: `docs/architecture.md`（基礎地図プロキシ節・接続数上限節）、
  `docs/modules/frontend/static-map-layers.md`・`dynamic-weather-layers.md`、
  `docs/modules/backend/weather-dynamic-layers.md`（基礎地図プロキシ節を新設）。

   `/api/basemap/`要求が増えないこと。
