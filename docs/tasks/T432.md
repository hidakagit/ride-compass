# T432. 動的気象レイヤーの一般化+防災グループ再編・降水グループ拡張 規模L

状態: 完了（2026-08-30、tsc/vitest/eslint通過済み。実機確認は環境要因により未実施、下記参照）

- 背景: キキクル4種・線状降水帯予測マップの表示方針をユーザーと議論した結果、以下を決定した。
  1. キキクル3種(土砂/大雨/浸水)は「防災」カテゴリとして個別チップを撤去し、WarningBadgeと
     同様に常時マウント(常時ON・トグル無し)にする。
  2. 線状降水帯予測マップは技術的にKikikuru(risk系統)ではなくrasrf系統(降水短時間予報と
     同じ)であるため、「降水」チップへ4つ目のソースとして統合する（現在〜3時間先のみ表示）。
  3. 複数ラスタの重なり(色被り)は正確な合成を見送り、現状のまま許容する。
  4. 内訳確認は新規コンポーネントを作らず既存WarningBadgeへ統合する
     （`backend/app/domain/jma_warning.py`のCYCLING_RELEVANT_WARNING_CODESが
     土砂災害・大雨警報系コードを既に含み新規データ取得は不要と判明）。
  この過程で、`DYNAMIC_WEATHER_RENDERERS`（MapView.tsx）が「1レイヤーID=1 kind」しか
  同時表示できない制約を持ち、風のpenalty面表示（windPenaltyFill）がこの制約のせいで
  汎用機構を迂回した個別実装になっていたことが判明。今回この制約自体を解消する一般化
  （1グループ=複数の名前付きソース）を行い、防災・降水グループの新要件とwindPenaltyFillの
  bespoke実装解消を同じ機構で実現する。
- 対応方針: 実装計画は`C:\Users\h7g4b\.claude\plans\synchronous-spinning-lamport.md`に
  ユーザー承認済み（詳細はそちらを参照）。

## 実装メモ

- **並行作業との関係**: 着手直前に並行セッションがT423（勾配の第2動的材料実装＋T411の
  way_id配信層汎用化）を着地させていた。スコープは本タスクと重ならないが、T423が
  「風・勾配で実装パターンを揃えるため、環境グループのgradientFillもwindPenaltyFillと
  同じbespoke実装のまま統一する」と明記していたため、本タスクでwindPenaltyFillだけを
  汎用機構へ移すとこの一貫性の意図を壊す。検討の結果、**gradientFillは据え置き、
  コメントで前提が崩れたことのみ明記**（`MapView.tsx`のGRADIENT_FILL_SOURCE_ID直前コメント
  参照）に留めた——gradientFillPayloadは`page.tsx`側で`useDynamicWayValues`由来の別系統
  フックから計算されており、windPenaltyFillのように`useDynamicWeatherLayers`が計算する
  値ではないため、完全統合には`page.tsx`のgradient配線の作り直しが要る。これは今回の
  承認済みスコープを超えるため、将来のフォローアップ課題として残す。
- **`DYNAMIC_WEATHER_RENDERERS`一般化**: `DynamicWeatherGroupState`（ソースキー→
  `{visible, payload}`）を新設し、`ensureDynamicWeatherLayer`/`applyDynamicWeatherState`を
  ソース単位のループへ書き換えた。既存の単一ソースレイヤー（thunderNowcast等）は
  `{ main: {...} }`という1ソースのグループになるだけで、raster/gridFill/gridMark分岐
  ロジック自体は無変更（後方互換）。`windVector`グループは`arrow`（矢印gridMark）+
  `penaltyFill`（環境グループの風penalty gridFill、旧bespoke実装から統合）の2ソース、
  `precipitationNowcast`グループは`main`（ナウキャスト→rasrf→延長予報の3段、既存）+
  `linearRainband`（線状降水帯予測マップ、新規）の2ソースを持つ。
- **防災グループ（キキクル3種）**: `mapLayers.ts`のMapLayerId・`MapLayerDescriptor`から
  4件（landslideRisk/heavyRainRisk/inundationRisk/linearRainbandRisk）を削除。
  `page.tsx`のFIXED_LAYER_VISIBILITY_DEFAULTS・overlayLayers分岐・凡例定数
  （RISK_LEGEND_DETAILS/LINEAR_RAINBAND_LEGEND_DETAILS）・isDynamicGroupLayer列挙からも
  削除。`useDynamicWeatherLayers.ts`のキキクル3種のfetch effectは常時マウント（ガード撤去）
  へ、payload計算はisAtNow依存を撤去し`frames[0]`があれば常に返す形へ単純化。
  `MapOverlayControls.tsx`のLAYER_ICONSから4行削除、`icons.tsx`の未使用アイコン4つも削除。
  **既知の制約**: キキクル3種の色の意味（5段階）を確認する専用の凡例表示（旧チップの
  ▶パネル）は表示先を失ったため撤去した。地図上の色そのものは見えるが、凡例を確認する
  導線が無くなった点は将来の改善余地として残る。
- **降水グループの拡張（線状降水帯予測マップ）**: `linearRainbandFrames`のfetch effectの
  ガードを`showPrecipitationNowcast`へ変更。新設した`isWithinFutureWindow(target, now,
  windowMs)`（`dynamicWeather.ts`）で「現在〜3時間先」の範囲判定を行い、範囲外なら
  payloadをundefinedにする（visibleは「降水」チップのON/OFFのみに連動）。
  `PRECIPITATION_LEGEND_DETAILS`へ線状降水帯の凡例ブロックを追加し、専用の
  LINEAR_RAINBAND_LEGEND_DETAILSは削除（`accidents`の複数ブロックパターンを再利用）。
  `mapLayers.ts`の`precipitationNowcast`エントリのdescription/panelHintも線状降水帯を
  含む説明へ更新。DynamicLayerTimeSliderの表示条件からキキクル系変数を削除
  （線状降水帯はshowPrecipitationNowcastで既にカバーされる）。
- **WarningBadge統合**: 調査の結果、`backend/app/domain/jma_warning.py`の
  `CYCLING_RELEVANT_WARNING_CODES`が土砂災害・大雨警報系コードを既に含み、
  `useWeatherConditions.ts`の`warningBadgeItems`が既にフィルタなしで拾っていることを
  確認した。新規のデータ取得・新規コンポーネントは不要と判断し、キキクルとの対応関係を
  一言添える改修（KIKUKURU_LANDSLIDE_CODES等によるtitle注記）は**未実施**（任意扱いとして
  スコープ外に据え置いた、将来の軽微な改善候補）。
