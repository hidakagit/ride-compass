# T984. テストが本番の軸データを写経している 規模M

状態: 未着手（2026-09-21起票）。

## 背景

軸定義の正本はDBだけで、`AXIS_DEFINITIONS`のPythonリテラルはT350でアプリから撤去された。
ところが`backend/tests/realistic_axis_fixtures.py`が、同じ内容（公開軸のid・shape・材料
参照・ラベル・アイコン・panel_hint）をテストコードへ手写しで複製している。

T973で軸を1つ消したとき、`backend/app`側の修正は8ファイルで済んだのに対し、テスト側は
10ファイルに及んだ。過半はこの複製と、そこから派生した「公開軸idを数え上げた期待値」
（`PUBLISHED_AXIS_IDS`ほか3か所）が原因である。**DBを正本にした意味が、テストの側で
失われている。**

さらに、軸を組み立てるファクトリがテストごとに別々に存在する。

| ファイル | 引数 |
|---|---|
| `tests/test_axis_registry_service.py` | axis_id・default_weight・material・is_published |
| `tests/test_axis_definitions.py` | axis_id・material・is_published |
| `tests/test_axis_definition_repository.py` | axis_id・default_weight |

3つとも本体は同一（`BreakpointLinearShape`・同じbreakpoints・同じラベル書式）で、
1つ目が他2つを包含する。

## 対応方針

- 本番の軸を模した固定フィクスチャをやめる。テストが要るのは「一貫した軸システム」で
  あって「本番と同じ軸」ではない。名前も構造も本番を借りない合成軸に置き換える
  （借りると、その軸が今もそう動くという誤った仕様を伝える）。
- 軸を組み立てるファクトリを1つへ寄せる。
- 公開軸idの数え上げをやめる。増減で嘘になる。

## 完了条件

- `realistic_axis_fixtures.py`が本番の軸id・ラベル・panel_hintを持たない
- 軸を作るファクトリがテスト全体で1つ
- 軸を1つ増減しても、期待値の書き換えが要るテストが無い
