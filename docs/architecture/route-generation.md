# ルート生成の全体像

実装の正本は[ルート生成エンジン・経路探索](../modules/backend/routing-engine.md)。
ここには**全体の形と、外から見た制約**だけを置く。

## 単一構成であること

`/api/routes/generate`・`/api/routes/preview`はどちらも**自前のRoad Graph1本**で動く。
エンジンを切り替える仕組み（設定・レスポンスの識別フィールド・外部ルーティングAPIの
クライアント）は実装に無い。

- 経路探索は`domain/routing.py`がnumbaでJITしたDijkstra/A*（一対全木・2点間探索とも）。
- **出発からの経過時間をラベルとして持ち回る**ため、コストを辺の静的な属性とみなす
  汎用の経路探索ライブラリは使えない。風のように時刻で変わる材料を探索コストへ入れるには
  この形が要る。
- 外部ルーティングAPIへの依存が無いため、APIキーもクォータも持たない。

## データの前提

道路網はOSMのPBFを取り込んだPostGISが唯一の系統で、**取込範囲の外には代替経路が無い**
（外部APIへのフォールバックを持たない）。範囲外は「データ未整備」として扱い、
地図では空タイル、ルート生成では候補なしになる。

道路網・材料は取込・派生バッチが範囲全体ぶんを先に作る。リクエストが来てから作る経路は
持たない。

## 戦略

生成戦略は周回・経由地・目的地の3つで、いずれも同じエンジンへ委譲する。周回候補は
公開軸の重みから折返し点を選び復路を探索する方式で、方位を固定した探索ではない。

候補の並び順は`overall_difficulty`（公開軸すべてを重みで合成した値）の昇順。
**候補集合の中で相対化した総合スコアは持たない**——絶対基準の値だけを返し、
候補間の比較は並び順と内訳で表す。
