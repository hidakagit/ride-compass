# ドキュメント記載方針

`docs/`配下・`.claude/`配下・README・モジュールdocstringに共通する、**何を書き何を書かないか**の
方針。コードコメントについては[comments.md](comments.md)が別に定める。

## 挙動を書く。要素を数え上げない

**ドキュメントが示すべきは「何がどう振る舞うか」「なぜそうなっているか」。**
コードから数えられるものを散文へ写さない。

書かないもの:

- **個数**（「4本のバッチが参照する」「現行8軸」「5値の分類」「六つの材料」）
- **全件の一覧**（ファイル一覧・エンドポイント一覧・state一覧・定数一覧・軸id一覧）
- **組み合わせの網羅**（「①〜⑦の要素それぞれについて…」）

これらは**必ず実装より先に古くなる**。書いた時点では正しく、増減があっても文書側は
何も壊れないため、誰も気づかない。実際、統合レビューで繰り返し検出されている
（第6回で個数表現の陳腐化12件、第7回でも`_common.py`の「4バッチが参照」が実際は12本、
`page-composition.md`のstate一覧が3件不足）。

代わりに書くもの:

- その要素**群が何をするか**（「派生データを作るバッチは、対象件数を数えてからチャンク単位で
  更新し、進捗を1行INFOで出す」）
- **増えたときに何が起きるか**（「バッチを1本足しても`_STAGES`へ登録すれば順序は自動で決まる」）
- **実装を読んだだけでは分からないこと**（暗黙の前提・隠れた依存・外部システムの実際の挙動・実測値）

## 代表例は許容する。ただし「例」と分かる書き方にする

挙動を分かりやすくするために代表的な要素を挙げるのは**よい**。全件のつもりで読まれる
書き方をしないこと。

- よい: 「`_common.py`が共通ドライバ（`run_chunked_precompute`等）を提供し、
  precompute系バッチはこれに乗る」
- よい: 「タイル世代の定数（`ROAD_SURFACE_TILE_VERSION`など）」
- 避ける: 「`_common.py`は`asyncpg_dsn`・`download_to_path`を提供する。4バッチが参照する」
- 避ける: 「対象は`gradient`・`surface_q`・`stop_density`・`car_stress`・`accident`・`night`の6軸」

判断の目安は**「要素が1つ増えたときにこの文は嘘になるか」**。嘘になるなら数え上げている。

## 全件が必要なときは、生成物かコードを指す

一覧そのものが必要な場面（デバッグ・棚卸し）はある。そのときは文書へ写さず、
**生成物**（`axis-catalog.json`・`region-tile-config.json`・`material-catalog.json`）か、
**それを定義しているコード**（`MATERIAL_CATALOG`・`_STAGES`）を指す。

## 例外: 機械が完全性を保証している表

**一覧が機械的に「漏れていないこと」を検査されている場合のみ、全件の表を持ってよい。**
この場合、要素が増えたときに文書側が壊れる（CIが落ちる）ため、静かに古くならない。

現在この例外に当たるのは`docs/modules/*.md`の**対象ファイル表**だけ
（`scripts/review_checks.py: find_undocumented_files`が、実装ファイルすべてがどこかの
モジュール文書に現れることを検査する）。この表の目的は「この新規ファイルの責務はどの
モジュールが持つか」の逆引きで、コード側に等価な表現が無い。

**逆に、同じ一覧を検査の無い場所へ二重に持たない。** `docs/architecture.md`の
ファイル樹形図は`docs/modules/*.md`の対象ファイル表と重複しており、検査が無い側だけが
古くなっている。

## なぜこの方針か

ドキュメントの陳腐化は、統合レビューで一貫して最大の指摘カテゴリであり、かつ
**増え続けている型**である（8月13件→9月17件）。一方で「コードから導けない事実」を書いた
記述は古くならない（`maplibre-gl`のバージョン固定の制約は1か月後の再検証でも正しかった）。

**古くなるのは写しの側**で、写しは更新し続ける対象ではなく削る対象
（[T707](tasks/T707.md)・[T723](tasks/T723.md)・[T724](tasks/T724.md)）。
検査の母集団についての同じ原則は
[design-principles.md](design-principles.md)構造仕様12にある。
