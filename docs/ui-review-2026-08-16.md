# UI操作レビュー（一般ユーザー目線・2026-08-16）

frontend（Next.js dev）とbackendを実際に起動し、Chromium（Playwright）を操作して
ルート生成→候補比較→レイヤー切替→モバイル表示までの一連の操作を、一般ユーザー目線で確認した。
スクリーンショット付きの詳細は、確認時に作成したArtifact（[RideCompass 操作レビュー](https://claude.ai/code/artifact/e21d20d3-aa17-4496-a021-bccd02173fbf)、
Claude Code上の非公開ページ）を参照。本ファイルは改善計画へ起票するための要点のみを記録する。

## 要改善点（本ファイルからT55〜T57として起票）

1. **モバイル幅で北コンパスボタンが下部タブバーと重なる**（390px幅で確認）。
   「ルートを作る」タブの1文字目が北コンパスボタンに隠れる。タブバーはスマホでの主要導線のため
   目につきやすい。あわせて、同条件で地図本体の初期表示に6秒以上かかる場面があったが、
   ヘッドレスブラウザのタッチエミュレーション特有の遅延という可能性が残るため実機確認が必要。
2. **初回ルート生成時、地図が新しいルート範囲へズーム／パンする過程で、
   タイル表示が一瞬崩れた**（右半分だけ英語ローマ字ラベルの別スタイルタイルが矩形状に混在）。
   再実行では発生せず確度は高くないが、タイル読み込みタイミング次第の競合として記録。
3. **天候インジケータ**（現在の天候・風向風速・降水確率）**が画面最上部に小さいグレー文字で
   常時表示されており、見落としやすい**。向かい風・追い風がルート選定の判断材料になっている
   アプリの性質上、有用な情報だが主張が弱い。

## 確認できた良い点（起票不要・現状維持でよい）

- 距離入力のバリデーション（0以下・100km超・未入力）が状況に応じた具体的な日本語メッセージ。
- 「道路情報」レイヤーの「ズームインすると表示されます」というインラインヒント。
  ズーム依存レイヤーで「何も表示されない＝壊れている」という誤解を防ぐ工夫。
- モバイルのボトムシート（「ルートを作る」タブタップで開く）自体の開閉は自然。

## 訂正（重要・再検証済み）

公開直後は「候補ルートを選び直すたびに地図全体が読み込み中に戻る」という所見を最重要項目として
報告していたが、**これは誤りだった**。原因は検証スクリプト側のセレクタが、候補一覧の直前にある
説明文「おすすめ度は距離の合わせ込み・獲得標高・向かい風・舗装率を重み付けして算出」にも
「おすすめ度」という文字列がヒットしてしまい、意図した候補ではなく既に選択済みの候補を
再クリックしていたこと。ソースが安定した状態で候補一覧の実ボタン要素を正しく指定し、
異なる3候補（94点→86点→58点→56点）へ連続して切り替えたところ、いずれも200〜300ms程度で
ルート線が滑らかに描き変わり、読み込み中表示への後戻りは一度も発生しなかった。
**ルート比較のコア体験に問題はない**ため、改善計画への起票対象からは除外する。

## 訂正2（T55、2026-08-16再調査）

T55として起票した「モバイル幅で地図左下の北コンパスボタン（現在地/方位リセット）が
下部タブバーの『ルートを作る』ラベルと重なる」という所見は**誤りだった**。Playwrightで
390px幅のモバイルビューを再現しスクリーンショットで確認したところ、重なっていた黒丸「N」の
正体はアプリ自作のボタンではなく、**Next.js開発モード（`next dev`）が既定で表示するDev Tools
インジケータ**（`next.config.ts`の`devIndicators.position`、既定値`bottom-left`）だった。
これは公式ドキュメント（`node_modules/next/dist/docs/.../devIndicators.md`）にも
「開発時のみ表示され、本番ビルドには現れない」と明記されている、開発専用の別レイヤーのUI。
実際の地図コントロール（`maplibregl-ctrl-compass`）はコード上も実測（`.maplibregl-ctrl-top-right`の
座標取得）でも右上に配置されており、タブバーとは無関係。**アプリ側の実装に修正の必要はない**ため
起票対象から除外する。T55の残り所見（同条件での初期表示6秒超）は実機未検証のまま据え置き。
