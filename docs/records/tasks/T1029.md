# T1029. sceneの入力語彙を、上位のReactコンポーネントのpropsから切り離す

状態: 未完了

## 背景

T1001段階Aで`features/map/scene/**`を新設し、`MapView.tsx`は3,382行から1,608行へ減った。
残った1,608行は「MapLibreの命令的な世界との境界（マーカー・ポップアップ・イベント）」
という単一の変更理由に収まっており、**この分割自体は今周期で最大の改善**である。

一方で、新しい層が旧居へ依存し返している。

- `features/map/scene/applyToMap.ts`が`MapView.tsx`から`MapViewProps`型をimportし、
  `MapView.tsx`が`applyToMap.ts`をimportする——**本番コードのimport循環**（型のみ）。
  直接の原因は、sceneの入力型を`Pick<MapViewProps, …>`で組み立てていること。
  **sceneの入力語彙を、上位のReactコンポーネントのpropsが定義している。**
- `features/map/**` → `@/components/**` のimportは26本、逆向きは11本。
- `mapSceneGroups.ts`は「見た目の値はこのファイルが持つ（呼び出し側は埋めない）」と
  宣言しているが、実際の値（分類外の色・降水と風のカラーストップ・危険度の色・
  凡例の欠損キー）は旧居の`components/Map/*`にあり、そこから借りている。
  **適用の機構だけが移り、宣言は移っていない。**
- `components/Map/axisLayers.ts`には「循環import回避のため値を複製している」という
  コメントが残っている（直下は生成物を読んでおり、実際には複製ではない）。

結果として`features/map/scene`は`components/Map`の下でも上でもなく横に並び、
**次に地図の部品を足す人が、どちらへ置くかの基準を得られない**。

## 対応方針

**2段に分ける。第2段を同じタスクに含めない**（含めると、循環を切るだけの小さな修正が
26本の設計判断に引きずられて止まる）。

1. **第1段（このタスク）**: `applyToMap.ts`の入力型を`MapViewProps`から切り離す。
   sceneが必要とする入力を、sceneの側で宣言する。これで循環が消える。
   `MapView.tsx`の単一責務は壊れない（型の向きが変わるだけ）。
2. **第2段（別タスクへ切り出す。切り出す先の中身を、第1段の完了時に具体化する）**:
   26本の依存について「どの値がsceneの持ち物か」の基準を決めてから移す。
   CLAUDE.md「段階を別タスクへ切り出すときは、切り出す先の中身を具体化してから
   切り出す」に従い、**基準を決めずに『あとは移すだけ』として切り出さない**。

  実行時には消えるが、読む側と道具から見た循環は残る）。
