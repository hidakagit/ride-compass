# T545: ルート結果パネルの再設計（ルートごとのタブ化・説明文整理・切り替えUI統一）

状態: 完了（2026-09-02）

## 背景

ユーザーが本番サイト（モバイル実機）でルート結果を確認中、以下4点の改善要望を受けた:

1. ルート確認をもっとやりやすくしたい
2. ルートごとにタブを分けてほしい（ルートクリアするとタブが消える）
3. 冗長な説明文は消すか情報アイコンにする
4. 総合難易度と軸の切り替えを、ルート設定タブの軸チップ列と同じ見た目・操作性にする

現状は候補一覧（`RouteList.tsx`、縦積みボタン）→選択中候補の内訳（`RouteAxisProfile.tsx`）が
同じスクロール領域に縦に並ぶ構成で、候補を比較するには選択→スクロールして内訳確認→
また上へ戻って選び直す、という往復操作が必要だった。

## 対応方針（ユーザー承認済み）

- `RouteList`をRadix Tabsベースの候補ごとタブへ再構成（page.tsxの「ルート選択/比較」タブと
  同じパターン）。タブラベルは短縮表示（例:「南東 22.9km」）。「ルートをクリア」で
  `routes`が空になりタブごと消える。
- `RouteAxisProfile.tsx`の常時表示テキスト（おすすめ度/総合難易度の説明段落）を、
  `RouteList.tsx`の「おすすめ度について ⓘ」と同じ`FieldLabel`パターンへ変更。
- 総合難易度・各軸の選択チップを上部に1行の折り返しチップ列（ルート設定タブの
  `chipRow`と同じ見た目）としてまとめ、選んだ軸の棒グラフをその下へ表示する形へ変更。

## 実装（2026-09-02）

- `RouteList.tsx`: 縦積みボタン一覧をRadix Tabs（`Tabs.List`/`Tabs.Trigger`、
  `aria-label="ルート候補"`、`Tabs.Content`は使わない純粋な選択UI）へ再構成。タブ自体に
  「おすすめ度」・方向・距離を残し、切り替えずに候補間のおすすめ度を比較できるようにした
  （下のRouteAxisProfileは選択中1件だけの表示のため）。候補数が画面幅を超える場合は
  タブ列自身が横スクロールする。`RouteList.module.css`をタブ用スタイル（`.tabList`
  `overflow-x:auto`、`.tab[data-state="active"]`の選択枠）へ全面書き換え。
- `RouteAxisProfile.tsx`: 「総合難易度」単独行＋内訳の各行に埋め込まれていたチップを、
  `RouteSettingsPanel`の軸チップ列と同じ`chipRow`（折り返す1行）へ統合。内訳
  （`.breakdown`）側は選択操作を持たない色ドット＋ラベルの読み取り専用表示に変更
  （`.rowLabel`新設、`legendChip`ボタンから置き換え）。常時表示していた説明段落
  （`.scoreHint`）を`FieldLabel`（情報アイコン→ポップオーバー、`RouteList`の
  「おすすめ度について」と同じパターン）へ変更し、`.scoreHint`CSSクラスを削除。
- `docs/modules/frontend/route-settings-and-results.md`のRouteList.tsx/RouteAxisProfile.tsx
  節を実装に合わせて更新。

## フォローアップ3（2026-09-02、タブ名の再簡略化・色分けチップの無反応バグ修正・
「ルートをクリア」のヘッダ移設）

ユーザーから3件同時に指摘を受けた。

1. 「タブ名はもっと簡潔にして。おすすめ度はタブ内にもあるし。」
2. 「タブ内の地図の色分けが切り替えられない。」
3. 「ルートをクリアもルート結果ヘッダの右上小さくでいい。」

### 1. タブ名の再簡略化

フォローアップ1で「{点数}点 おすすめ度」→「{点数}点」へ縮めていたが、おすすめ度の点数
自体がタブの中身（`RouteAxisProfile`のスコア行）に既に出ているため、タブからは点数を
完全に外し方向・距離のみにした（`app/page.tsx`の`Tabs.Trigger`、`page.module.css`の
`.outcomeTabTrigger`をflex-column2行レイアウトから単純な1行表示へ戻し、不要になった
`.outcomeRouteTabScore`/`.outcomeRouteTabMeta`を削除）。

### 2. 色分けチップの無反応バグ修正

`RouteAxisProfile.tsx`の「地図の色分け」チップ列は、`routeStyleModes`
（`supports_route_coloring===true`の軸だけから生成、`car_stress`・`accident`・`night`・
`bicycle_infra_quality`等は対象外）に対応モードが無い軸も、非活性チップ
（`cursor:default`のみで区別、クリックしても無反応）として同じ行に並べていた
（T518時点の意図的な設計）。実機で確認すると、色分け対応チップと見た目がほぼ同じで
「クリックしても反応しない壊れたボタン」に見え、これが「タブ内の地図の色分けが
切り替えられない」という報告の原因だった（実際に色分け対応の軸チップ同士を
切り替える動作自体にバグは無かった——Browserペインでの検証時、プログラムからの
連続クリックをスクリプト内の同期処理で直後に読み取ると、Reactの状態コミット前の
古いDOMを読んでしまい誤って「切り替わっていない」ように見えるハーネス起因の
誤検知を経由したため、切り分けに時間を要した。実際のユーザー操作のような離散的な
クリック1回ごとには正しく切り替わることを個別に確認済み）。

対応: チップ列自体を色分け対応軸だけへ絞り込む（`rows.filter(axis =>
routeStyleModes.some(mode => mode.id === axis.axisId))`）よう変更し、非活性表示の
分岐を撤去した。`AxisChip`は常にクリック可能な`<button>`のみを描画する単純な形へ
戻した（`onSelect`・`pressed`を必須propへ変更、`title`propを削除）。色分けに対応しない
軸の存在自体は、下の「内訳（重み付き寄与度）」一覧（読み取り専用、全評価軸を表示）に
引き続き表示されるため情報は失われない。`RouteAxisProfile.module.css`の`.axisLabel`
（非活性表示用）を削除。

### 3. 「ルートをクリア」のヘッダ移設

「ルートをクリア」ボタンをタブ列脇から「ルート結果」ヘッダの右側へ移設した。情報アイコン
（`FieldLabel`）と合わせて`renderRouteResultHeaderActions()`という1つのヘルパー関数へ
まとめ、デスクトップ（`renderRouteOutcomeSectionBody`の見出し行、`justify-content:
space-between`でh2と対になる）・モバイル（`BottomSheet`の`headerAction`prop）の両方から
同じ中身を呼ぶ。`BottomSheet.tsx`の`headerAction`の差し込み位置を、タイトル直後（左側）
から閉じるボタンの手前（右側、`.headerActions`新設）へ変更した——「ヘッダの右上」という
指摘に合わせるため（以前のフォローアップ2で追加した際は「タイトルと並べる」だけの設計
だったが、右上という配置意図までは満たしていなかった）。
