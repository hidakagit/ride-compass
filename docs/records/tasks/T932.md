# T932: 道の急さを、方位に依存しない表示として持つ

状態: 完了

見送り（2026-09-18起票・同日に見送りを決定）

## 背景

「基礎地図に崖の影をつけた感じで、方角を指定せずに『この道は坂か』を見たい」という要望から
検討した。既存の「起伏」レイヤー（国土地理院DEMのhillshade）は**道路の下に入る**ため
（`mapStyleOps.ts: areaLayerAnchorId`、面レイヤーは道路網の描画開始位置の直前へ差し込む）、
道そのものには陰影が付かない。地形の傾きは道の勾配とも別物で、等高線に沿ってトラバースする
道は地形が急でも道は緩い——hillshadeはその区別ができない（傾きをどの方向で取るかという
情報を持たないため）。

## 検討した置き場所

| 案 | 判断 |
|---|---|
| hillshadeへ吸収 | 不可。地形の傾きは道の勾配ではない |
| 軸スタジオのramp軸（レンズ） | レンズは1本しか選べず、背景にならない |
| 道路グループのチップ（`roadSurface`等と同じ静的属性レイヤー） | 実現可能。`\|average_grade\|`をタイルへ焼き、記述子1件と`STATIC_FILTER_AXES`の軸1本を足す |

置き場所としてはチップが素直だと整理できた（「坂の急さ」は評価ではなく測った事実で、
`roadSurface`チップと`surface_q`レンズ軸が同じ元データから別々に存在するのと同じ形）。

## 見送りの理由（2026-09-18、ユーザー判断）

**評価軸としては、向きを含む既存のレンズの勾配で足りる。** 方位に依存しない「急さ」を別に
持つほどの必要が現時点で無い。

承知のうえで残る制約: 「起伏」をONにしても道の急さは読めないため、道の勾配を地図で見る
手段はレンズで勾配軸を選ぶことだけになる。

必要になったときは、上の表の3案目（道路グループのチップ）から再開できる。その場合の論点は
「色の重なり（チップとレンズが同じ線に乗る）」「焼き込む値（`\|average_grade\|`か`max_grade`も
併せるか）」「way単位ズームの代表（[T931](T931.md)の結論に従う）」の3つ。
