# T721. ドメインモデルが未知フィールドを黙って捨てていないか点検する 規模S

状態: 完了（2026-09-11起票・同日完了。[T719](T719.md)実施中の発見）

## 背景

[T719](T719.md)で`EdgeAttributeCounts`から`stop_count`列を撤去したあと、
`EdgeAttributeCounts(accident_count=..., stop_count=2, intersection_count=...)`と
書いたままのテストが**例外にならずそのまま通り続けた**。Pydanticの`extra`の既定は
`ignore`で、未知のフィールドは黙って捨てられる。値は消え、アサーションだけが残るため、
撤去漏れがどこにも現れない。

[T719](T719.md)では`EdgeAttributeCounts`へ`model_config = ConfigDict(extra="forbid")`を
足して塞いだが、**同じ既定のまま残っているドメインモデルが他にもある**かは見ていない。

## 保留することで何が起きうるか

- フィールドを増減させたときの取り残しが、次もまた「テストが通るのに値が入っていない」
  という無言の形で残る。[T655](T655.md)「列を1つ足すで3回壊した」節の3件と同じ
  「機械が検証しない依存」の一種で、症状がエラーではなく**もっともらしい既定値**に
  なるため気づきにくい。
- 外部入力（APIリクエストのPydanticモデル）側にこの穴があると、typoしたフィールドが
  黙って無視され、利用者から見て「指定したのに効かない」になる。

## 点検の結果

`backend/app`配下のPydanticモデルは**75件**あり、内訳は次のとおりだった。

| `extra` | 件数 |
|---|---:|
| 未設定（既定=`ignore`） | 66 |
| `model_config`はあるが`extra`未指定（`frozen=True`のみ） | 7 |
| `extra="ignore"`（明示、`config.py: Settings`） | 1 |
| `extra="forbid"`（[T719](T719.md)で追加した`EdgeAttributeCounts`） | 1 |

### 一律に`forbid`でよいと判断した根拠

起票時は「外部APIのレスポンスを受けるモデルは`ignore`のままでないと壊れる」ことを
懸念していたが、**外部ペイロードを直接モデルへ流し込んでいる経路が1つも無かった**。
JMA（アメダス・警報・河川氾濫）もOSMも、レスポンスを一度dictで受けてから必要な値だけを
明示キーワードで詰め替えている（`services/jma_amedas_service.py`等）。
`model_validate`を使う唯一の箇所は`axis_definitions_snapshot.py`で、読む相手は自前の
スナップショットファイル。

提供側がフィールドを増やしてもモデルには届かないため、`forbid`で一律に締められる。

### 一律に決めた以上、個別宣言では持たない

66件へ`model_config`を書き足すと、新しいモデルを足すたびに同じ1行を書く運用になり、
書き忘れが次の穴になる。共通の基底`app/domain/strict_model.py: StrictModel`を1つ置き、
全モデルがこれを継承する形にした。Pydantic v2は親子の`model_config`をマージするため、
`frozen=True`を持つ7件は`frozen`だけを書けばよく、`extra`は基底から引き継がれる。

例外は`config.py: Settings`のみ（プロセスの環境変数には無関係なものが常に含まれるため
`extra="ignore"`でなければ起動しない）。

## 完了条件

- [x] `extra`未設定のドメインモデルが「`forbid`へ寄せた」か「`ignore`のままにする理由が
  書いてある」かのどちらかになっていること
- [x] 新しいモデルを足したときに同じ穴が空かない導線があること
  （`review_checks.py: find_bare_basemodel_violations`。pre-commitとCIが素の`BaseModel`
  継承を検出する）

## API契約への影響

リクエストモデルが`forbid`になったことで、OpenAPIのスキーマへ
`additionalProperties: false`が入り、**未知のフィールドを含むリクエストは422になる**。
これは本タスクが狙った挙動そのもの（typoしたフィールドが黙って無視されるのをやめる）で、
frontendは生成された型からリクエストを組み立てるため影響しない。生成物は同一コミットへ
含めた。
