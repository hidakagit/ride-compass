# T767. vitestのsetupFilesがDOM不要のテストにも課金している

規模S。
状態: 完了（2026-09-12）

## 背景

ユーザー指摘「UIテストが非常に時間がかかりネック」から。frontendのテスト全体は
壁時計で約265秒かかっており、内訳のsetupが488秒（ワーカー合算）と、テスト本体の
実行（335秒）を上回っていた。

`vitest.setup.ts`は`@testing-library/jest-dom`と`@testing-library/react`を無条件に
importしていたため、`// @vitest-environment node`を付けた純ロジックのテスト
（全133ファイルのうち59ファイル）も、使わないTesting Libraryの読み込み代を毎回払っていた。

## 対応

DOMがあるときだけ動的importする形へ変える。node環境ではsetupが実質何もしない。

## 検証

同一機・同一条件（`npx vitest run --pool=threads`、8論理CPU）での実測:

| | 変更前 | 変更後 |
|---|---|---|
| 全体（133ファイル/1225件） | 264.97s（setup 488.31s） | 220.03s（setup 281.70s） |
| node環境のテスト10本のみ | 7.92s（setup 26.37s） | 4.00s（setup 1.92s） |

全1225件が緑のまま＝DOM側のmatcher（jest-dom）と`cleanup`も従来どおり効いている。

## 残り

壁時計の最大要因は`environment`（happy-domの構築、合算447秒）へ移った。DOMを使わない
のに既定環境のままのファイルを`node`へ倒す余地と、単体で52秒かかる`page.test.tsx`の
ような重いファイルの分割は測ってから判断する。
