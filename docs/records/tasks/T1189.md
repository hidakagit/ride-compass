# T1189. 実DBとコードのテーブル宣言の差を出す検査を、自前の比較から alembic の比較機能へ置き換える

状態: 未完了（2026-09-27起票）

## 背景

起票案 proposal-std-schema-gap-alembic（2026-09-27承認。標準の道具の棚卸し・T1152の担当から）。規模S（根拠: 変わると見込むファイルは schema_gap.py・requirements-dev.txt の2本）

■ 背景（画面に出ない、DB運用の道具の話）
backend/scripts/schema_gap.py は、実DBの表・列・NULL可否・外部キーを読み、コードの宣言（ORM）との集合の差を取る。外部キーは PostgreSQL が返す定義の文字列を手で分解している。型・インデックス・一意制約・既定値は比べていない。alembic の compare_metadata は同じ比較を部品として持ち、migration のファイルを作らずに比較だけに使える。このプロジェクトは「積み上げ式の migration を持たない」（road_graph_repository.py のコメント）方針で、この置き換えはその方針と両立する。比較を自前で書く理由はどこにも書かれていない。

■ やること
比較の部分を compare_metadata へ置き換える（取込が作る子パーティションや PostGIS の spatial_ref_sys は include_name／include_object で外し、PostGIS の型は geoalchemy2 の alembic 用の補助で扱う）。alembic は開発用の依存に足す（run_probe.py の既定は手元の Python で動くため。--in-container で使うならイメージにも入れる）。比べる項目が増えるので初回は差が増える見込みで、その差を1件ずつ見る。見込み 約−75〜−90行。

■ なぜ既存のタスクに入らないか
スキーマの差を扱う未完了のタスクは無い（T970・T973 は完了済み）。
