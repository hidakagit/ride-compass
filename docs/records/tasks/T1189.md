# T1189. 実DBとコードのテーブル宣言の差を出す検査を、自前の比較から alembic の比較機能へ置き換える

状態: 完了（2026-09-27）

## 背景

起票案 proposal-std-schema-gap-alembic（2026-09-27承認。標準の道具の棚卸し・T1152の担当から）。規模S（根拠: 変わると見込むファイルは schema_gap.py・requirements-dev.txt の2本）

■ 背景（画面に出ない、DB運用の道具の話）
backend/scripts/schema_gap.py は、実DBの表・列・NULL可否・外部キーを読み、コードの宣言（ORM）との集合の差を取る。外部キーは PostgreSQL が返す定義の文字列を手で分解している。型・インデックス・一意制約・既定値は比べていない。alembic の compare_metadata は同じ比較を部品として持ち、migration のファイルを作らずに比較だけに使える。このプロジェクトは「積み上げ式の migration を持たない」（road_graph_repository.py のコメント）方針で、この置き換えはその方針と両立する。比較を自前で書く理由はどこにも書かれていない。

■ やること
比較の部分を compare_metadata へ置き換える（取込が作る子パーティションや PostGIS の spatial_ref_sys は include_name／include_object で外し、PostGIS の型は geoalchemy2 の alembic 用の補助で扱う）。alembic は開発用の依存に足す（run_probe.py の既定は手元の Python で動くため。--in-container で使うならイメージにも入れる）。比べる項目が増えるので初回は差が増える見込みで、その差を1件ずつ見る。見込み 約−75〜−90行。

■ なぜ既存のタスクに入らないか
スキーマの差を扱う未完了のタスクは無い（T970・T973 は完了済み）。

## 実施（2026-09-27、担当 A-alembic）

### 依存
- `alembic==1.20.0`を`requirements-dev.txt`へ足した。ライセンスはMIT（wheelのメタデータ`License-Expression: MIT`。
  依存のMakoもMIT）で商用に使える。要求は`SQLAlchemy>=2.0`・`Python>=3.10`で、このリポジトリの
  SQLAlchemy 2.0.36・Python 3.12に収まる。`docs/architecture/tech-stack.md`に版の制約の記述は無い。
- 本番のイメージには入れない。`schema_gap.py`を本番へ当てるのは`run_probe.py`の手元実行（既定）で、
  `--in-container`では使わない。

### 比較の置き換え
- 表・列・NULL許容・外部キーの自前の比較と、外部キーの定義文字列の分解を消し、`MigrationContext`＋
  `compare_metadata`へ置き換えた（型・既定値〈`compare_server_default=True`〉・インデックス・一意制約も比べる）。
- 母集団から外す表は、名前ではなく実DBのカタログから引く: 拡張の持ち物（`pg_depend`の`deptype='e'`。
  `spatial_ref_sys`等）と子パーティション（`relispartition`）。起票案の書いた`geoalchemy2.alembic_helpers.include_object`は
  表名の接頭辞（`spatial_ref_sys`・`idx_`・`gpkg_`等）で外す関数で、同じ接頭辞の自前の表まで黙って外すため使わない。
- PostGISの型は、`geoalchemy2`のimport（ORMのモデルが行う）で反映（reflection）が型を読めるようになり、
  `alembic_helpers`無しで比べられる（下の「壊して確かめた」でSRIDの差が出る）。`alembic_helpers`の残りは
  migrationのファイルを書くための描画・操作で、比較には要らない。
- 片側にしか無い表について、alembicはその表のインデックスも1件ずつ出す。表の1行で足りるので畳んだ。

### 初回の差（1件ずつの判定）
| DB | 置き換え前 | 置き換え後 |
|---|---|---|
| 本番（`run_probe.py scripts/schema_gap.py`） | GAP 5件（`source_features_*`の子パーティション） | GAP 1件: `axis_definitions.updated_at`の既定値が`'2026-09-20 20:33:35…'::timestamptz`（ORMは`now()`） |
| 開発DB（`schema_gap.py`） | GAP 16件 | GAP 19件 |
| 作業ツリーのテストDB（ORMの宣言から`create_tables()`で作ったDB） | — | GAP 2件: 同じ既定値の差（`'2026-09-24 04:52…'`）と、テストが作る`axis_registry_meta` |

- **本番の既定値は欠陥で、原因はORMの宣言**: `server_default="now()"`は文字列なので、SQLAlchemyは
  `DEFAULT 'now()'`（文字列の定数）を出し、PostgreSQLは表を作った時点でそれを時刻へ変換して固める。
  本番（2026-09-20作成）とテストDB（09-24作成）が、それぞれ作った時刻に固まっていることが裏づけ。
  `func.now()`へ直した（`tuning_overrides.updated_at`と同じ形。コンパイルしたDDLが`DEFAULT now() NOT NULL`に
  なることを確認）。アプリは`updated_at`を常に明示して書く（`axis_definition_repository.py`）ため、今の利用者への
  影響は無い。他の文字列の`server_default`は定数（`"true"`・`"0"`・`"[]"`等）で、関数を文字列で書いたのはこの1件だけ
  （`backend`全体の`server_default`をgrepして確認）。
- **本番の表は宣言を直しても変わらない**（`create_tables()`は既にある表を作り直さない）。本番の既定値を`now()`へ
  戻すのは本番への書き込みなので担当は行わず、ダッシュボードに操作（`T1189-prod-updated-at-default`）として置いた。
- 開発DBの差はすべて開発DBの側のずれで、コードの側は本番と一致している: `TEXT`と`VARCHAR`（`axis_definitions`の5列・
  `tuning_overrides.param_id`・`way_materials.direction`。本番は宣言どおり`VARCHAR`）、`idx_source_features_rast`が無い
  （本番にはある）、`road_edges.reverse_bearing_deg`のNULL許容（置き換え前から出ていた）、宣言に無い表
  （`t970_before_*`・`traffic_*`・`schema_migrations`・`axis_registry_meta`）。置き換え前の16件のうち子パーティション5件以外の
  11件は、置き換え後もすべて出る。
- 置き換え後、ORMから作ったテストDBで型・インデックス・外部キーの誤検知は出ない（Geometry・Raster・JSONB等を含む）。

### 壊して確かめた（作業ツリーを書き換えず、宣言をメモリ上で崩して開発DBへ当てた）
`road_edges`の外部キー1本を外す・`distance_m`のNULL許容と型を変える・`geom`のSRIDを3857にする、の4つが、それぞれ
「実DBにあるがORMが宣言していない外部キー」「NULL許容が違う」「型が違う（REAL/INTEGER）」「型が違う
（geometry(LINESTRING,4326)/geometry(LINESTRING,3857)）」として出た。

### 見積もりとのずれ
起票案は約−75〜−90行と見込んだが、実装は +71/−72（ほぼ差し引き0）。自前の比較（カタログへの問い合わせ3本・外部キーの定義文字列の分解・集合の差）は消えたが、
alembicの差の形（操作名つきのタプル・`Column`や`DefaultClause`のオブジェクト）を人が読める1行へ直す部分と、
カタログから母集団外の表を引く問い合わせ・表ごとのインデックスを畳む処理が同じくらい増えた。比べる項目は
表・列・NULL許容・外部キーから、型・既定値・インデックス・一意制約まで増えた。

### 本番の既定値を戻した操作（2026-09-27、司令塔）

ダッシュボードの操作`T1189-prod-updated-at-default`は、ユーザーの依頼（「あなたが実施して」）で司令塔が本番VMで行った。
- 前: `pg_get_expr`で`'2026-09-20 20:33:35.405067+00'::timestamp with time zone`
- 実行: `ALTER TABLE axis_definitions ALTER COLUMN updated_at SET DEFAULT now()`（`ALTER TABLE`）
- 後: `now()`
- 確かめ: `python scripts/run_probe.py scripts/schema_gap.py` → 「GAP なし（実DBとORMの宣言が一致している）」
