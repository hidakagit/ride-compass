# T1067. 並行実行の見込み超過の予算を、記録に残した所要の実績から計算する

状態: 未完了（2026-09-23起票）

## 背景

並行実行の見込み超過の予算を、規模札の定義（CLAUDE.md: S=1時間・M=半日・L=1日以上。人が作業する前提の見立て）から流用していた（M=240分）。ユーザー指摘「Mが4時間は明らかに長すぎる。妥当な範囲に収束させていくプロセスは無い？」。2026-09-23の担当の報告の時刻から見た実時間（振り出し〜報告）: S は T1029 約10分・T1024 約25分・T999 約20分、S〜M は T1004 約45分・T993 約75分、M は T1061 約105分・T1054 約35分・T1056 約25分・T1058 約30分＋CI待ち、段階 T1014 A 約60分・B 約110分。機械の飽和中の参考値: T1023（S）約160分・T1027（M）約260分。飽和を除くと S 10〜45分・M 30〜105分で、M=240分では止まったタスクの検知に4時間かかる。

合意した置き場（2026-09-23）: 所要の実績は、担当が完了のコミットで Txxx.md の末尾へ1行残す（規約 docs/conventions/orchestration.md「完了とpush」の書式: 所要（並行実行）: 依頼 … → 完了 …（N分）、うち枠待ちN分・CI待ちN分、規模札X。超過時は理由を1つ）。状態の表には実時間・予算・差を写さない（T1065 で task_log と scale_budget_min を外す）。

対応方針:
1. 予算を読むときに計算する: docs/records/tasks/*.md から「所要（並行実行）:」の行を集め、規模札ごとに「実時間 − 枠待ち − CI待ち」（作業そのものの時間）と実時間の両方の80パーセンタイルを出す。見込み超過の検査（orchestrate.py check・gate）はこの値を使う。値はどこにも保存しない。件数が少ない規模札（例: 5件未満）の扱いを決める（例: 隣の規模札の倍率で補う）。
2. 今日の実績（上の表）を、各タスクの Txxx.md へ所要の行として書き足し、最初のデータにする（担当の報告の時刻が出典。分からない待ちの内訳は「不明」と書く）。
3. 超過の理由の集計を出す（規模札ごとに「見立てより中身が大きい／環境の待ち／進め方」の件数）。「見立てより中身が大きい」が続く規模札は、起票の書き方（CLAUDE.md の規模の目安の運用）を見直す材料としてユーザーへ示す。
4. /orchestrate:status か check の出力に、今の予算（規模札ごとの80パーセンタイルと件数）を1行出す。

前提: T1065（状態の表から写しを外す）が master に入っていること。

完了条件: 所要の行を1件足すと予算が変わること、飽和中の外れ値1件が予算を大きく動かさないこと（作業そのものの時間で見る側）を、壊した入力で確かめる。今日の実績から計算した S・M の予算が記録にあること。
