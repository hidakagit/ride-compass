# T1088. 回の目的と母集団を状態の表で持ち、進め方の指示を記録へ書かない

状態: 未完了（2026-09-23、門で閉じる直しのために開け直した）

## 背景

ユーザー指摘（2026-09-23）: 回の進め方の指示（T1078を待つ・改善系を続ける等）を、司令塔がT1049の記録へ「ユーザー決定」として書きmasterへコミットしていた（7c943494・40617cba）。回の目的と母集団は「今どう動いているか」という状態で、記録（維持しない）ではなく状態の表に置くべきもの。指示のたびにコミットとCIが走り、記録が会話の写しで膨らみ、決定と進め方の指示の見分けが付かなくなる。やること: (1) 状態の表（board.json）の run に、回の目的（文）と母集団（タスク番号の並び、派生元つき）を持たせ、orchestrate.py に設定・追加・一覧のコマンドを足す（例: board run goal / board run add Txxx from=Tyyy）。表は他が源泉の事実を写さない原則（規約「状態の表」）に従い、母集団の各タスクの状態は記録と台帳から導いて出す。(2) status と check が、回の目的・母集団の残り（未完了のもの）・終わりの条件（規約「回の始まりと終わり」）に当たっているかを出す。(3) 規約「回の始まりと終わり」を、目的と母集団は表に置き、回の記録には終わりにまとめを1回だけ書く、に直す。進め方の指示は記録にもコミットにもしない、と書く。完了条件: 第1回の目的（T1001の前提を0にする）と母集団を表に入れ、status に残り（T1014・T1078・T1079・T1077・T1086・T1087・T1057等）が出ることを見る。

## 対応方針

- **回（`run`）の形**: `{"name", "started", "goal", "population": [{"task", "from", "added"}]}`。持つのは表にしか
  無い事実（回の名前・目的の文・母集団のタスク番号と派生元）だけで、各タスクの状態・残り・終わりの条件は
  読むたびにorigin/masterの記録の`状態:`と台帳の行から導く（`population_view`）。名前だけを文字列で持つ今の
  表（`"run": "2026-09-23 第1回"`）は名前だけの回として読み、最初の`board run`の書き込みで形を直す（移行の
  手順は要らない）。
- **コマンド**: `board run start <名前>`（新しい回。前の回を表示してから置き換える）・`goal <文>`・
  `add <Txxx>... [from=<Tyyy>]`・`remove <Txxx>...`・`list`（引数無しも同じ）。従来の`board run k=v`
  （`limits.concurrent`等）はそのまま。
- **状態の導き方**: `完了`=記録が完了、`トリガー待ち`=未完了で台帳の行に`— トリガー:`があり、その条件が
  母集団のタスクを名指ししていない（ユーザーの判断で先送り）、`残り`=それ以外の未完了、`記録なし`=
  origin/masterに記録が無い。条件が母集団のタスクを名指しするもの（T1014・T1079の「T1078の完了」）は回の
  中の順番なので残りに数える。母集団の外のタスクを名指す条件は、完了を待つのか利用実績を待つのか
  （T207「T204だけでは見通しが不足するという利用実績」・T636）を文から決められないので先送りのまま——
  はじめは「名指し先が全部完了なら条件が満たされた」とも数えたが、T207・T636を誤って残りにするので外した。
  終わりの条件1は「母集団が空でなく、残りと記録なしが0件」。
- **写しのキーの拒否**: `board run k=v`で`run`を丸ごと書く・`run.population`を書く・`run.`の下に
  `RUN_KEYS`（name・started・goal・population）以外を書く、を拒否する（`nested_key_reason`）。回の下は
  拒否の一覧ではなく許す一覧にした——状態・残り・メモ・指示の文のどれを書かれても写しになり、名前を
  予想して並べると漏れる。手で書かれた写し（表を直接編集したもの）は`check`が`board_copy_keys`で出す
  （既存の`FORBIDDEN_KEYS`の全区分と、回・母集団の1件の許す一覧の外）。
- **status**: 先頭に回の名前・目的・母集団の件数（完了・トリガー待ち・残り）・終わりの条件1に当たって
  いるか・残りの一覧（担当・振り出し待ち・「T1078待ち」の注記つき）を出す。担当の現在のタスクが母集団の
  外なら`?`の印。
- **check**: 同じ要約の行を出し、異常として①担当が稼働しているのに目的・母集団が無い、②母集団のタスクの
  記録が無い、③終わりの条件1に当たった（新しいタスクは振り出さない）、④表に写しのキーがある、を出す。
  門が開いたときの「振り出し待ちを拾う」は、母集団があればその中だけにし、終わりに入ったら拾わない
  （母集団の外は次の回の候補、規約どおり）。門（`gate`）は変えていない（指示の範囲は run・status・check）。
- **規約「回の始まりと終わり」**: 目的と母集団は表に置く（コマンドつき）・各タスクの状態は導く・
  **進め方の指示は記録にもコミットにもしない**（待つ=振り出し待ちの前提、順番=優先度、足す外す=
  `board run add/remove`、目的の言い直し=`board run goal`で表す）・回の記録に書くのは終わりのまとめ1回だけ・
  終わりの条件1の機械の導き方、を書いた。CLAUDE.md（b657f236）の「進め方の指示は記録にもコミットにも
  しない（並行実行では状態の表が持つ）」と同じ向き。「状態の表」節の持つものの一覧と場面の表にも回の
  目的と母集団を足した。
