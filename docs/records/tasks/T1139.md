# T1139. 気象庁タイルの事前取得が、backend自身が持つ読み方の宣言を使わず、画面と違う時刻を温めうる

状態: 完了（2026-09-26起票、2026-09-27完了）

## 背景

周期レビュー第13回（2026-09-26）の指摘。性質: 同じ計算の重複（同じ判断の正本が2つ）。domain/jma_tile_specs.py:120-132 JMA_TARGET_TIMES_READERS（nowcast/latestFullRun/latest）は生成物経由でfrontendへ届き、features/map/layers/jmaDelivery.ts:213-265がその通りに読む。一方jma_tile_prewarm_service.py:84-125は読み方を見ず「段の先頭か」で_pick_current_entryと_pick_stage_entryを選び分ける。reader=latestの要素（sjfcstmap等5つ）でfrontendのreadLatestは「basetime最大の行」、backendは「実況の行を優先」。ずれると在否インデックスのフレームが画面と一致せず画面は全タイルを取りに行く（jma_tile.py:104-106。表示は壊れず黙って遅くなる）。:108の参照先precipitationNowcast.ts: latestFullRunFramesはT1001で消えた。事前取得をreaderの宣言で振り分け、選び方をdomainの関数1つへ寄せる。

## 着手時の確認（origin/master d5a3f6bf）

記録の前提は今のコードでも成り立っていた。読み方の宣言（`JMA_TARGET_TIMES_READERS`）を読むのは
`weather_elements.weather_element_deliveries`（生成物の`jmaElements[].reader`）だけで、プリウォームは
読んでいなかった。画面との食い違いを、画面の手順（`jmaDelivery.ts: READERS`→`weatherSources.ts:
sourceTimeline`）と1つずつ突き合わせて数えると、記録にある1件のほかに次があった:

- `latest`（キキクル4種・線状降水帯予測）: 画面は最新basetimeの行、プリウォームは実況の行を優先（記録の指摘）。
- 先頭の段が`nowcast`で実況が1件も無いとき: 画面は時系列の最初（最も早いvalidtime）、プリウォームは最新basetime。
- 前の段が取れないとき: 画面は後の段を最初から継ぐ（`sourceTimeline`）、プリウォームは後の段を温めなかった。
- 段の境目: 画面は前の段の読み方で残したコマの最後、プリウォームはその要素の全行の最後（`nowcast`では一致する）。
- 系列の衝突: `latestFullRun`で系列どうしのvalidtimeが重なると、画面は新しいランを採るが、プリウォームは区別しなかった。
- `member`: 画面は行の`member`（無ければ"none"）、プリウォームはnowc系だけ固定で"none"。

## 対応

- `domain/jma_tile_specs.py`: 時刻一覧の行をコマにする`read_target_times(reader, rows, element_id)`と、コマの型
  `JmaFrame`を足した。3つの読み方は画面の`READERS`と同じ手順（並べ替えの安定性・同じbasetimeの行の選び方まで）。
  `match`の`assert_never`で、読み方の種類を足したときの足し忘れをmypyが止める。
- `domain/weather_elements.py`: 段をつないだとき各段が最初に描くコマを返す`stage_first_frames`を足した（画面の
  `sourceTimeline`と同じつなぎ方）。
- `services/jma_tile_prewarm_service.py`: 要素ごとの段を`weather_element_deliveries`（画面へ配るのと同じ宣言）から作り、
  上の2つでフレームを選ぶ。`_pick_current_entry`・`_pick_stage_entry`・段の境目を持つ辞書・nowcの`member`の
  特別扱いを消した。
- 画面側（`jmaDelivery.ts`・`weatherSources.ts`）には、backendが同じ手順を持つことを1行ずつ書いた（言語が違うため
  手順は2本あり、片方だけ変えると在否インデックスが黙って効かなくなる）。
- 文書: `docs/modules/backend/weather-dynamic-layers.md`の対象ファイル表と「定期プリウォーム」、
  `docs/modules/frontend/dynamic-weather-layers.md`の「新しい動的要素を追加する1本道」4.を今の手順に合わせた。
