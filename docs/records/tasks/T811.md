# T811. 撤去済みMapLayersPanelへの参照を一掃し、地図チップの案内文を実際の入口へ向ける

規模S〜M。
状態: 完了（2026-09-14。統合レビュー第8回のP1、2026-09-13起票）

## 背景

[T769](T769.md)で`MapLayersPanel`を削除しサイドバーを3区分へ再編したが、それを名指しする記述を
消していない。実装ファイルのgrepヒットは0件（`find frontend/src -iname "*MapLayersPanel*"`も
import検索も0件）なのに、十数箇所が現存物として参照している。

`Map/mapLayers.ts:3,7,15,85,89,103,108,141,541`／`legendFilter.ts:21,72,81`／`LayerChip.tsx:19,23`／
`LegendCheckboxList.tsx:20`／`axisLayers.ts:468,492`／`mapColorLegend.ts:6`／
`staticAttributeLayers.ts:341,370`／`recipeControls.tsx:9`／`ui/Card/Card.tsx:5`／
`app/page.tsx:890`／`docs/architecture.md:135,2018,2349`／`docs/modules/frontend/frontend-design-system.md:171`。

とくに`mapLayers.ts:7`は「3. MapLayersPanelにそのレイヤーの設定セクションの中身を足す」と
**実行不能な手順**をレイヤー追加の必須ステップとして書いている。実際の追加先は
`MapOverlayControls`（▶パネル）と`LensControl`。

**利用者に見える害もある**。`app/page.tsx:1202`の静的レイヤーチップのtooltipが
`[設定はサイドバー]`と案内するが、指示どおりサイドバーを開いても該当する絞り込み設定が
1つも無い。しかも`page.test.tsx:332-339`がこの文言を末尾一致の回帰テストとして固定しており、
直そうとするとテストが赤くなる（＝誤った案内が検査に守られている）。

## 対応方針と結果

1. 実装側の参照を一掃した（31箇所）。「地図上チップとサイドバーの2箇所が同じカタログを読む」
   という**対比の構図そのものが無くなっている**ため、名前の置換ではなく文ごと書き換えた。
   手順書（`mapLayers.ts`）の3番目のステップは実際の追加先（`MapOverlayControls`の▶パネル）
   を指す。
2. tooltipは`[設定はサイドバー]`→`[設定は▶から]`。
3. テストは文言の末尾一致をやめ、「レイヤーカタログの`description`の後ろに案内が付いている」
   ことを見る形にした。案内の文言は入口が変われば変わるのが正しく、固定すると**誤った案内を
   検査が守る**ことになる。`description`はカタログから引くので、文言を二重に持たない。
4. `docs/architecture.md`の現状記述3箇所と`frontend-design-system.md`の例示を直した。
   導入時の経緯を語る段落（「新規」と断っているもの）はそのまま残している。

## 作業中に見つけた検知器の穴（同一コミットで修正）

[T810](T810.md)で入れた`source_comment_dead_identifier_refs`が、この`MapLayersPanel`を
1件も拾えていなかった。母集団（コメントを除いた本文）に**コメントの取りこぼし**があったため:

- Pythonのdocstringを「モジュール・クラス・関数の先頭」に限って切り出していた。属性の説明
  として直後へ置く文字列文が本文側に残っていた。
- TS/CSSのブロックコメントを行頭の記号だけで判定していた。`/* ... */`の途中行は日本語で
  始まることがあり、本文側に残っていた。

前者は「値として使われない文字列文すべて」、後者は開始から終了までを状態として追う形へ直した。
これで`legendFilter.ts`・`MapOverlayControls.tsx`のバッククォート付きの参照を検知する。
なお**バッククォートの無い記述は対象外**（プロセ中のCamelCaseを識別子と見なすと誤検知が
爆発する）。今回の31箇所のうち検知器が拾えたのは2箇所で、残りは手作業のgrepで一掃した。
