# T752. 周期レビューの個票を、起票したタスクが参照できる形で残す

規模S。
状態: 完了（2026-09-12）

## 背景

統合レビュー第7回は、P2（28件）・P3（40件）について「件数が多いため分類のみを示し、
個票は各シャードの出力に残る」と書いた。しかしシャードの出力はAgentの実行結果で、
ファイルとして残っていない。結果として、起票した束ねタスク
（[T735](T735.md)〜[T742](T742.md)）の**対象を後から復元できない**——全体の要約に名前が
挙がった数件だけが手掛かりで、残りは件数しか分からない。

「何件ある」と書いてあるのに中身が無い状態は、タスクを閉じるときに「全部やった」と
言えるかどうかを判定できないという形で効く。

## 対応: 手順を直し、欠けたときに何が起きるかを手順の中へ書いた

- `principles.md`の「集約」項: **severityに関わらず全Findingの個票を`history/`のファイルへ
  残す**。分量が理由ならシャードの出力をそのまま`history/YYYY-MM-DD_<種別>_shards.md`へ
  連結して保存し、結果ファイルからリンクする（読み物として整える必要は無い。起票した
  タスクが「対象はこの節」と指せれば足りる）。
- `all.md`の「出力」節: 分類と件数だけを示して個票を省略しないこと、分量が理由なら
  `_all_shards.md`へ連結すること、そして**これを守らなかった実際の結果**
  （第7回でT735が対象を確定できないまま残った）を名指しで書いた。

## 検知器にしなかった理由（測ってから）

素直な機械検査は「`history/*_all.md`には対になる`_all_shards.md`が存在すること」だが、
`history/`には既に10本以上の`*_all.md`があり、どれも当時の記録として書き換えない対象。
全件へ空の対ファイルを作ることになり、検査のために記録を汚す。

語による検査（「個票は…シャードの出力に残る」のような言い回しを禁止する）も検討したが、
自由記述の言い回しに依存するため、書き方を変えれば静かに素通りする。

代わりに**リンクの存在だけは既存の検知器が見る**形にした——手順どおりに
`_all_shards.md`へのリンクを書けば、`dead_doc_links`（pre-commit・CIで強制）が
「リンク先のファイルが無い」を検出する。リンクを書き忘れた場合は捕まらないため、
ここは手順側の記述に頼る。

## 第7回の個票について

復元できない。T735の残り5件は対象を確定できないため、**件数を追うのをやめ、同じ型の
母集団をコードから導出する方針へ切り替えた**（[T735](T735.md)参照）。
[T740](T740.md)・[T741](T741.md)・[T742](T742.md)も同じやり方で閉じており、
いずれもレビューが挙げた件数より多い対象を実測している。
