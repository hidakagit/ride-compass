# T431. RouteCandidateのレガシー個別フィールド（stop_density等9個）を末端消費者ゼロ化後に廃止するか検討

状態: 完了（2026-08-30）

- 背景: [T421](T421.md)でRouteList.tsx、本タスクの起票と同時にComparisonPanel.tsxが
  `axis_difficulties`駆動へ移行すると、`backend/app/domain/route.py: RouteCandidate`の
  `elevation_gain_m`・`wind_score`・`road_score`・`stop_density`・`car_stress_score`・
  `bicycle_infra_score`・`intersection_density`・`accident_density`の8フィールド
  （＋関連する`total_score`・`score_breakdown`）は、**フロントエンドの表示消費者がゼロになる**
  見込み（route.py自身のdocstringも「旧来の軸1対1固定設計の名残...軸増減に追従しない」と
  明記済み）。
- 書き込み側（値の計算元）は`backend/app/infrastructure/road_graph_repository.py`・
  `backend/app/services/road_graph_engine.py`に残っている——これらの計算自体を止めるか、
  APIレスポンス（`RouteCandidate`のPydanticモデル、OpenAPI契約）からフィールドを完全に
  除去するかは、外部消費者（研究モード用に直接API呼び出ししているスクリプト等が無いか）の
  洗い出しが必要な、T421より大きな話。
- 対応方針（未検討）: ComparisonPanel.tsx移行後に改めてフィールドの読み取り消費者を
  全件grepし、本当にゼロになったことを確認してから着手判断する。除去する場合は
  OpenAPI再生成・型生成物の追従が必要（CLAUDE.md「コミット時の同期ルール」）。
- **2026-08-30追記**: [T421](T421.md)でComparisonPanel.tsxのaxis_difficulties駆動への
  移行が完了した。移行後にフロントエンド全体で`\.フィールド名\b`のプロパティアクセス形で
  grepした結果、`stop_density`・`car_stress_score`・`bicycle_infra_score`・
  `intersection_density`・`accident_density`の5フィールドへの消費者はゼロになったことを
  確認した（詳細はT421.md「検証結果（2026-08-30、ComparisonPanel.tsx追加対応）」節）。
  一方`elevation_gain_m`・`wind_score`・`road_score`の3フィールドは、ComparisonPanel.tsxが
  「生の物理量として研究モードで見たい」という設計判断（RouteListとは異なりそのまま残す、
  T421.md参照）により意図的に残しており、末端消費者ゼロにはなっていない。本タスクの
  「除去するか検討」に着手する場合、この3フィールドは書き込み側（`road_graph_engine.py`・
  `domain/attributes.py`）だけでなく上記の設計判断とも整合させる必要がある点に注意
  （ComparisonPanel.tsx自体の役割を変えない限り、8フィールド一括ではなく5+3で扱いが
  分かれる）。フロントエンドの消費者調査は完了したが、除去するかどうかの意思決定・外部
  消費者（API直接呼び出しスクリプト等）の洗い出しは依然未着手のまま。

## 対応方針・実装（2026-08-30、着手）

- **外部消費者の洗い出し**: リポジトリ内に本番APIを直接叩く研究用スクリプト・ノートブック
  等は存在しないことを確認した（`backend/scripts/`配下は全てDB直接操作かCLIバッチで、
  `/api/routes/generate`のレスポンスをHTTP経由で消費するものはフロントエンド以外に無い）。
  外部（リポジトリ外）の消費者は原理的に確認できないが、CLAUDE.mdの運用（OpenAPI契約は
  frontend/src/types/generated/への追従を必須とする以外の後方互換保証を明示的に謳って
  いない）とT421での「末端消費者ゼロ確認」の前例に倣い、この5フィールドは撤去する判断とした。
  `elevation_gain_m`・`wind_score`・`road_score`の3フィールドはComparisonPanel.tsxが
  意図的に使い続けているため、本タスクのスコープ外のまま維持する。
- **撤去した範囲**:
  - `backend/app/domain/route.py`: `RouteCandidate`から5フィールド削除、docstring更新
  - `backend/app/domain/traffic.py`: `_density_per_km`・`distance_weighted_stop_density`・
    `distance_weighted_intersection_density`・`is_dedicated_bicycle_infra`・
    `distance_weighted_bicycle_infra_score`を削除（5フィールドへ値を渡すためだけの関数
    だったため）。`STOP_POI_MATCH_MAX_DISTANCE_M`等の定数・`classify_stop_poi`等の分類
    関数は区間ごとの評価軸材料収集（`compute_edge_axis_scores`）に引き続き使うため維持
  - `backend/app/domain/accident.py`: `distance_weighted_accident_density`を削除
    （`ACCIDENT_MATCH_MAX_DISTANCE_M`等の定数は維持）
  - `backend/app/services/road_graph_engine.py`・`openrouteservice_engine.py`: 上記5
    フィールドへ値を渡すためだけの集約計算・`_build_segment_details`の
    `bicycle_infra_dedicated`並列リスト返却を削除。区間ごとの`stop_count`・
    `intersection_count`・`accident_count`（`compute_edge_axis_scores`が使う）は維持
  - バックエンドテスト: `test_traffic.py`・`test_accident.py`の対応するテストクラスを削除。
    `test_road_graph_engine.py`・`test_openrouteservice_engine.py`は、削除フィールドへの
    アサーションを、同じ挙動を検証できる`axis_difficulties`ベースのアサーションへ置き換え
    （例: `candidate.stop_density == 0.0`→`segments[].axis_difficulties["stop_density"] == 0.0`）。
    完全に重複するテスト（`test_intersection_density_is_none_without_repository`が
    `test_stop_density_is_none_without_repository`と同一の検証になったもの）は削除
  - フロントエンド: `RouteCandidate`型（OpenAPI再生成）から5フィールドが消えたことに伴い、
    各テストファイルの手書きフィクスチャ（`ComparisonPanel.test.tsx`・`routeApi.test.ts`・
    `page.test.tsx`・`RouteList.test.tsx`・`MapView.bench.ts`・`MapView.routes.test.ts`・
    `e2e/fixtures.ts`）から該当キーを削除。`ComparisonPanel.test.tsx`の
    「旧レガシーフィールドへ値を入れても直接参照されない」回帰テストは、フィールド自体が
    型から消え構造的に再現不可能になったため削除
  - `docs/architecture.md`: RouteCandidateのJSON例・TypeScript型定義・関連する各節
    （自転車インフラ独立公開軸化・交差点密度・事故密度）の「現状」記述を追従させた
- **検証結果**: `pytest -m "not postgis"`は1200 passed / 4 failed（失敗はnumpy 2.4.6
  環境起因の既知の浮動小数点差異、T441/T442と同じ`test_evaluation_bulk.py`の事前確認済み
  失敗で本タスクの変更とは無関係）。フロントエンドは`npx vitest run`が837 passed、
  `npx tsc --noEmit`・`npx eslint .`ともにエラー無し。OpenAPI再生成
  （`export_openapi.py`→`npm run generate:api`）を実行し、`openapi.json`・`api.d.ts`は
  5フィールド削除分のみの差分、`axis-catalog.json`等その他の生成物はクリーン（差分無し）
  であることを確認した。
