# T1106. 難易度で塗るレンズの段の配色を、隣の段が見分けられる形にする（緑→黄→橙→赤、明度も動かす）

状態: 完了（2026-09-26）

## 背景

ユーザー指摘（2026-09-25）: 風に逆らって走っているのにルートの線が緑色。風の軸（本番DB、axis_id wind）は材料wind_drag_ratioを折れ線(-1.2→0, 0→15, 5→100)で難易度へ写し、段の境界20/40/60/80の5段で塗る。計算は定義どおりだが、段の配色（frontend/src/lib/mapDisplay/valueScale.ts: bandColorsFor の difficulty、evaluation_good→evaluation_bad をHSLの色相だけで補間）で下の2段がどちらも緑になる（#16a34a・#3bb219、3段目も黄緑#a3c11d）。時速20kmでは正面の向かい風およそ4.5m/sまで緑系に見える。承認時の決定（案1）: 段の数は変えず（本番DBの軸の設定に触らない）、配色だけを、符号付き材料の上り側と同じ作り（中継点を置き、色相とともに明度も動かす）にして隣の段が見分けられるようにする。総合難易度など難易度で塗るレンズすべてに効く。色の正本はbackend（palette.json・SEMANTIC_COLORS）なので、中継点の色を足すならbackendで足して生成物を作り直す。規模の根拠: valueScale.tsとそのテスト、必要ならdisplay_palette.py・palette.json・設計書で7ファイル以下。

## 比べた配色（2026-09-26）

`valueScale.ts`と同じHSLの補間をpythonで再現し、段の数2〜7で隣どうしのΔE（CIE76）と色相を出した。
- 今（緑→赤の2色）: 5段は #16a34a・#3bb219・#a3c11d・#d08820・#dc2626、隣の最小ΔE 25.2。2段目の色相107°で、1段目（142°）と同じ緑に見える。
- 緑→黄→赤（起票時の見立て）: 5段の最小ΔE 27.3で、2段目は #5fc510（色相94°）とまだ黄緑。**見立てほど変わらなかった**。
- 緑→黄→赤→暗赤（勾配の上り側と同じ中継点）: 5段は #16a34a・#b7d70c・#e56415・#c52323・#7f1d1d、最小ΔE 28.9、2段目の色相69°（黄）。これを採った。
  段が6・7段でも最小ΔE 18.9・19.1で、今（19.3・12.1）以上。

## 変更

- 評価の配色の中継点を`SEMANTIC_COLORS`に`evaluation_mid`・`evaluation_extreme`として置いた（それまでの`signed_climb_mid`・`signed_climb_extreme`は
  同じ色で、勾配の上り側だけの名前だった）。難易度の段と勾配の上り側が`valueScale.ts: EVALUATION_ANCHORS`を共有する。最も難しい段は暗赤になる。
- 風の軸（5段）の例: 時速20kmで正面の向かい風1m/s以下が緑、1〜3m/sが黄、3〜4.5m/sが橙、4.5〜6m/sが赤、それより強いと暗赤。
