# T999. ジョブの保持時間とフロントの待機上限が、コメントだけで結ばれている

状態: 完了（2026-09-23）

## 背景

ルート生成の非同期ジョブは、backendが`_JOB_TTL_SECONDS`（`app/infrastructure/job_registry.py`）
のあいだ結果を持ち、frontendが`MAX_POLL_DURATION_MS`（`src/services/routeApi.ts`）まで
ポーリングする。**前者は後者以上でなければならない**——短いと、まだ待っているフロントが
掃除済みのjob_idを引き、10分待った末に結果ではなく「ジョブが見つかりません」を見る。

いまは両方600秒で、ちょうど境界に立っている。この制約は`job_registry.py`のコメントに
1行あるだけで、frontend側には何も書かれておらず、検査も無い。frontend側だけを
延ばす変更は、何も落とさずに通る。

## 対応方針の候補

- frontendの待機上限を、ビルド時生成物（`route-generate-config.json`の`client_tuning`）
  経由でbackendの宣言から受け取る。既に`splice.min_stretch_km`が同じ経路を通っており、
  新しい仕組みを足さずに済む（`frontend/src/hooks/useAxisCatalog.ts`の`CLIENT_TUNING_IDS`）。
- そこまでせず、backend側のテストで`_JOB_TTL_SECONDS`と生成物の値の関係だけを固定する。

どちらにするかは着手時に決める。**両方に数字を書いたまま「揃えること」とコメントで
書くのは対象外**——いまと同じ状態になる。

## 完了条件

frontendの待機上限を延ばす変更を1つ書いてみて、**検査が落ちる**ことを確認する
（CLAUDE.md「修正の原則」——効いていることを見てから完了にする）。

規模S。

## 実施内容（2026-09-23）

1つ目の候補（生成物経由で受け取る）を採った。frontendが数字を持たない限り、片側だけを
延ばす変更そのものが書けなくなるため、2つ目（関係だけを固定するテスト）より強い。

- backendの保持時間を公開名`JOB_TTL_SECONDS`（`infrastructure/job_registry.py`）にし、
  `scripts/export_openapi.py`が生成物`route-generate-config.json`へ`job_result_ttl_seconds`
  として書く。`client_tuning`は通さない——あれは管理画面から実行時に変えられる較正値で、
  保持時間はコードの宣言でしか変わらない。
- frontendの`MAX_POLL_DURATION_MS`はこの値そのもの（`* 1000`）。値の根拠（冷パスの
  最悪ケース）への参照はbackendの宣言側へ移した。
- `routeApi.test.ts`のタイムアウトのテストを「保持時間＋ポーリング間隔2回分を過ぎた時点で
  rejectしている」に書き換えた。以前は`650000`を直書きしていたため、待機上限を延ばしても
  650秒以内なら通っていた。
- `docs/modules/backend/cross-cutting-infrastructure.md`・
  `docs/modules/frontend/route-settings-and-results.md`を実装へ合わせた。

## 検証

- 完了条件: frontendの待機上限を`job_result_ttl_seconds * 1000 + 60000`へ延ばすと、
  `vitest run src/services/routeApi.test.ts`が1 failed（`expected undefined to be an instance
  of Error`——保持時間を過ぎてもまだ待っている）になることを見てから戻した。
  生成物の`job_result_ttl_seconds`を手で書き換える変更は、OpenAPI生成物のずれの検査
  （pre-push・CI）が落とす。
- `tsc --noEmit`・`prettier --check`・`eslint`（変更した2ファイル）通過。
- `vitest run src/services/routeApi.test.ts` → 14 passed。
- `pytest tests/test_job_registry.py -q` → 11 passed。

本番DBへの影響は無い（ジョブ台帳はプロセス内メモリだけで、値も600秒のまま）。
