## 背景

### 兄弟の一部にしか無いガード・二重定義

- `RouteSettingsPanel.tsx:301,427,429` — `DEFAULT_HARD_FILTERS`を生成物から導出する形に直したのに、
  `hardFilterCustomized`と表示側・トグルは既定値を`true`固定でハードコード。
  backendが既定OFFのフィルタを追加すると、何も操作していないのに「変更あり」バッジが出る。
- `BackendLogsPanel.tsx:48-59` — 追加された`.catch()`はPromiseの拒否しか捕まえない。
  Clipboard APIは`[SecureContext]`のため非セキュアコンテキストでは`navigator.clipboard`自体が
  undefinedになり**同期TypeErrorを投げcatchに入らない**——コメントが対策したと述べる当のケースで
  ボタンが無反応になる。catchの書き込み先が`error` stateなのも誤解を招く（「取得失敗:」と表示される）。
- `dependencies.py:268-276` — 新設の`get_road_graph_repository`が`get_session_factory()`
  （command_timeout=20、タイル配信と共有）を使うが、利用者2件はいずれも全表走査寄りの管理APIで、
  同種の管理APIは明示的に180秒の`get_route_generation_session_factory()`を選んでいる。
- `axis_display.py:240` — `raw_value_unit`が「単位一致・重みが正・2項以上ならadditive」の3条件のみで
  **重みの大きさを見ない**。生値は`Σ(材料値×weight)`なのでweight≠1だと材料の単位のスケールでなくなる。
  本番の公開軸`axis_abdaded0be20`は`signal×1.0 + level_crossing×1.5 + stop×0.3 + crossing×0.0`で
  「回/km」を返すが、**実際に1kmあたりに存在する停止要因の回数ではない**
  （`tests/test_axis_display.py:737`がこの挙動を期待値として固定している）。
- `road_graph_repository.py:2607-2610` — `AttributeRepository.get_poi_counts_by_kind`の
  第3引数`on_edge_tolerance_m`をファサードが受け取らず既定値で固定して委譲している。
- `road_graph_repository.py:2185-2199` — `sample_way_rows`がSQLAlchemyの生`Row`を`list[Any]`のまま
  infrastructureの外へ返し、`axis_preview_service.py:61-83`が列別名で直接属性アクセスする。
  他の読み出しは全てドメイン型へ詰め替えており、ここだけ流儀が崩れている。
- `domain/material_catalog.py:104-107` — `tile_property_direction_dependent`の説明が
  「現行MATERIAL_CATALOGに該当する材料は無い…将来の型的な安全弁」と述べるが、
  同ファイルの`gradient_percent`（`:549`）と`wind_drag_ratio`（`:569`）が既に`True`を設定している。

### 実装を直したもの（挙動が変わる）

| `RouteSettingsPanel.tsx` | `hardFilterCustomized`とチップの表示・トグルが未設定キーの既定値を`?? true`で埋めていたのを`DEFAULT_HARD_FILTERS`（生成物由来）へ。backendが既定OFFのフィルタを足すと、何も操作していないのに「変更あり」になりチップもONで表示されていた |

| `dependencies.py: get_road_graph_repository` | `get_session_factory()`（command_timeout=20、タイル配信と共有）→`get_route_generation_session_factory()`（180秒）。利用者2件はいずれも全表走査寄りの管理API |
