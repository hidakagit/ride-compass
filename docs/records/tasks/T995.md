# T995. 欠損の意味が2か所に宣言されていて、一致を誰も守っていない 規模S

状態: 完了

未着手（2026-09-21起票。[T961](T961.md)の後、「根拠のないデフォルト値」の洗い出しで見つけた）。

## 背景

材料カタログは、欠損の意味を**2か所**に持っている。

- `MaterialSpec.bool_default`（`Literal["false","nan"]`、**型の既定値が`"false"`**）。
  値の経路が読む。`"false"`は「欠損＝確定で偽」、`"nan"`は「欠損＝真に不明」
- `coverage.missing_semantics`（`"definite"`／`"unknown"`）。報告（材料カバレッジの
  管理API・軸スタジオの表示）が読む

測ったもの（2026-09-21、材料34件）:

- `bool_default`を**明示している材料は1件だけ**（`surface_good`の`"nan"`）。残りは型の
  既定値`"false"`のまま。コード自身が「唯一の例外（他のboolean材料は既定の"false"のまま）」
  と書いている
- 今日は全件で2つの宣言が一致している（`"false"`↔`"definite"`、`"nan"`↔`"unknown"`）。
  **一致を強制する仕組みは無い**

## 問題

**新しいboolean材料を足すと、「このデータが無い＝その性質は無い」が誰にも問われずに確定する。**
型の既定値に判断が埋まっているため、妥当かどうかを考える機会が無い。

さらに片方だけ書き換えると、画面は「不明」と言いながら評価は「確定で偽」として扱う。
どちらが正しいかを誰も保証していない。

## 対応方針

**宣言を1つにする。** `coverage`（`missing_semantics`／`CoverageExcluded`）を唯一の宣言とし、
`bool_default`はそこから導く。

| coverage | 導く値 |
|---|---|
| `missing_semantics="definite"` | `"false"`（欠損＝確定で偽） |
| `missing_semantics="unknown"` | `"nan"`（欠損＝真に不明） |
| `CoverageExcluded` | `"false"`（欠損の概念が無く、値が必ずある） |

`coverage`は既に全材料で必須（3つの型のいずれかを持たないと作れない）なので、
**決めないと作れない**状態は保たれる。

現在の全材料でこの導出は今の値と一致する（確認済み）。したがって挙動は変わらない。

## 実施（2026-09-21）

`bool_default`をフィールドから`coverage`由来の導出プロパティへ変えた（+12/−11）。
`dtype != "boolean"`では参照されないため`"false"`を返す。

確認: 全34材料で導出前後の値が一致（変化0件）／ruff通過／関連134テスト通過。

## 完了条件

- `MaterialSpec.bool_default`がフィールドではなく`coverage`からの導出になっている。
- 導出前後で全材料の`bool_default`が変わらないことを確認する。
- `bool_default`を説明していた記述（`material_catalog.py`のコメント、
  `docs/modules/backend/evaluation-scoring.md`等）が新しい形に合っている。
