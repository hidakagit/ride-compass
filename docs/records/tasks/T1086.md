# T1086. 台帳の行は担当に消させず、監査の取り込みの後に司令塔がまとめて消す

状態: 未完了（2026-09-23起票）

## 背景

T1049の改善提案（ユーザー承認 2026-09-23）。担当がタスクを閉じるとき台帳（docs/improvement-plan.md）の自分の行を消すため、並行した担当が隣り合った行を消すと取り込み（cherry-pick）で衝突した（第1回で3回。解き方は毎回「両方消す」）。やること: (1) 規約 docs/conventions/orchestration.md の担当の完了の手順を「Txxx.mdの状態:だけを完了にし、台帳の行は消さない」に変え、司令塔が監査の取り込みの後、状態が完了の記録に対応する台帳の行をまとめて消す手順を「監査の結果」節に入れる。(2) scripts/review_checks.py docs の台帳と状態の整合の検査（task_state）が、担当の作業ブランチでは「状態: 完了なのに台帳に行が残る」を許し、masterでは許さない形にする（どう区別するかを決めて書く。許可リストを足さない）。(3) 司令塔が行を消す操作を orchestrate.py の1コマンドにする（board unpushed の手順に組み込む等）。完了条件: 2つの作業ブランチが隣り合った台帳の行のタスクを閉じても、取り込みが衝突しないことを使い捨てのリポジトリで1回見る。
