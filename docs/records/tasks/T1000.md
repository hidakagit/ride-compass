# T1000. OpenAPI生成物が、契約だけでなく散文まで運んでいる

状態: 完了（2026-09-22）

## 背景

`frontend/src/types/generated/openapi.json`・`api.d.ts`はPydanticモデルと
ルート関数のdocstringを`description`として運んでいた。そのため**コメントを直しただけで
生成物が動き**、CIとpre-pushのドリフト検知が追従コミットを要求していた。

[T996](T996.md)でbackendのdocstringを整理した際に実際に起きた（生成物が653行ぶん
ずれ、pre-pushが止めた）。[T846](T846.md)でも同じことが起きており、そのときは
「docstringはOpenAPIのdescriptionになるため生成物を同一コミットで更新した」と
記録されている——つまり繰り返している。

これは[T969](T969.md)の点検0が「生成タイミング・再生成の責務は未定義」として
挙げていた穴の、具体的な1つ。

## 検討した選択肢

**生成物をコミットしない（ビルド時生成）は採らない。** `export_openapi.py`は
`app.main`を読むため、生成にはbackendの実行環境一式（numpy・rasterio/GDAL・asyncpg・
redis）が要る。frontendはRenderでビルドされるので、コミットをやめるとRenderのfrontend
ビルドへbackend依存一式を入れることになる。`export_openapi.py`のdocstringが挙げている
「frontendのビルドがbackendの起動なしで完結する」という理由は今も成り立つ。

## 対応

`export_openapi.py`に`_strip_prose`を入れ、`description`・`summary`を落としてから
書き出す。生成物が運ぶのは**名前・型・required・enum**だけになる。

散文は失われない——実行中のアプリの`/docs`・`/openapi.json`が配る。
`Field(description=...)`は0件のため、落ちるのはすべてdocstring由来。

落とさないもの:

- **応答オブジェクトの`description`**。OpenAPIが必須にしており、落とすと生成物が
  仕様を満たさなくなる（FastAPIが入れる"Successful Response"等の定型で、docstringとは無関係）。
- **`properties`直下のキー**。ここはキーワードではなく**フィールド名**で、
  `description`という名前のフィールドを持つモデルが5つある（`AxisCatalogEntry`・
  `AxisDefinitionPayload`・`AxisDefinitionResponse`・`MaterialCatalogEntry`・
  `TuningParameterView`）。最初の実装はこれを落としており、`tsc --noEmit`が10件の
  型エラーで捕まえた。

## 検証結果

効いていることを両方向で確認した。

- **docstringを変える**（`AmedasObservation`の1行目を書き換え）→ 再生成しても
  `git diff frontend/src/types/generated/`は**空**。
- **契約を変える**（`AmedasObservation`へフィールドを1つ足す）→ 生成物が10行動く。
  門は生きている。
- `./node_modules/.bin/tsc --noEmit` 0件。
- 生成物に残る`description`は74件で、**全件が`responses`配下**。
  `components.schemas`直下は0件。

生成物 −653行（api.d.ts −487 / openapi.json −166）。実装 +20行。
