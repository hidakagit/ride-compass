# T484. 動的気象レイヤーのfilter未設定時にMapLibre style検証エラーが起動時毎回出る不具合を修正

状態: 完了（2026-08-31）

- 背景: ユーザー報告。ブラウザコンソールに起動のたびに
  `layers.region-dynamic-weather-windVector-penaltyFill-fill-main.filter: array expected,
  undefined found`という警告が出続けていた。
- 原因: `MapView.tsx: ensureDynamicWeatherLayer`が`map.addLayer(...)`のレイヤー定義オブジェクトへ
  `filter: spec.gridFill.minValueToShow != null ? [...] : undefined`という形で、
  `minValueToShow`未設定時に`filter`キーを**キー自体は残したまま値をundefinedにする**形で
  組み立てていた。MapLibreのstyle検証はキーの有無ではなく値の型で判定するため、
  `{filter: undefined}`は「filterキーはあるが配列ではない」というエラーになる。
  `windVector.penaltyFill`のgridFillスペックは`minValueToShow`を設定していない
  （`precipitationNowcast.main`のgridFillのみ設定）ため、このレイヤーだけで毎回発生していた。
- 対応: 3箇所（gridFillの`filter`、gridMarkのhalo層・main層それぞれの`filter`）を、
  オブジェクトスプレッドで「`minValueToShow`が無い場合はfilterキー自体を省略する」形へ
  書き換えた。gridMarkの2箇所は現状すべての要素が`minValueToShow`を設定済みで実害は
  出ていなかったが、同型の再発を防ぐため同じ修正を適用した。
- 検証: `npx vitest run src/components/Map/`330件・`tsc --noEmit`・`eslint`通過。
  Browserペインでdevサーバーを起動し、コンソールに`map:error`が一切出ないことを確認
  （Fast Refreshによる複数回のマップ再初期化でも再現せず）。
- 規模: S
