# T987. 検知器が守っていたものを、実装側の道具へ移す 規模M

状態: 未完了

未着手（2026-09-21起票）。

## 背景

[T986](T986.md)で検知器を32本から2本へ削った。要件（どの文脈でも絶対に正しいと保証できる
事実だけを見る）を満たさないものを落としたが、**そのうち9本は実在する害を防いでいた**。
移す先は決まっているが移していないので、**現在は守りが外れている**。

検知器として不適格だった理由は共通していて、**実装そのものを検査対象にしていた**こと。
実装の姿を知るために写し（定数表・パターン一覧・許可リスト）を抱え、実装が動くと黙って
ずれる。同じ検査でも、実装と同じ場所にある道具（lint・型検査・テスト）なら、ずれない。

## 移すもの

| 元の検知器 | 防いでいた害 | 移す先 |
|---|---|---|
| `map_redraw_coverage` | 地図のスタイル切替後にレイヤーが再追加されず消える | frontendのテスト（追加されるレイヤーid集合 == 再描画で再追加される集合） |
| `undefined_css_tokens` | 未定義トークンで色が出ない | stylelint |
| `web_layer_batch_import` | web層が`app.batch`を読み込み、起動時に重い副作用が走る | importの静的検査（import-linter相当）かテスト |
| `bare_basemodel` | 素の`BaseModel`が未知フィールドを黙って捨てる | lintかテスト |
| `undeclared_fixed_values` | 評価の宣言に無い数値がコードへ直書きされる | テスト |
| `redis_skeleton` | Redisキャッシュの骨格を各所へ写経する | lintかテスト |
| `vacuous_test_loops` | 母集団が空でも通るテスト | テスト側の仕組み |
| `cross_file_env_writes` | テストが書き換える環境変数を実装も読み、テスト間が干渉する | テスト側の仕組み |
| `call_arity` | 引数の個数不一致 | 型検査（[T985](T985.md)が扱う。本タスクでは扱わない） |

`module_redefinition`は移さない——ruffが`F`（pyflakes）を選んでおり**F811が既に同じ穴を
見ている**。

## 進め方

1件ずつ、次の順で行う。**まとめて仕組みを増やさない。**

1. 移す先の道具で、**わざと壊した入力を1件通して落ちることを見る**
2. 現行コードに対して走らせ、既存の違反が何件あるかを数える
3. 既存分を直すか、直せないなら理由を書いて起票する

## 完了条件

- 上の表の8本（`call_arity`を除く）が、それぞれの道具で「効いている」ことを確認済み
- 確認に使ったコマンドと観測値をコミットメッセージへ残す
- 移した先で効くようになった道具の名前を、該当する規約・モジュール文書へ書き直す
  （検知器を削った時点で「機械的に検出する仕組みは無い」へ直してある。
  `docs/conventions/testing.md`・`caching.md`・`documentation.md`、
  `docs/modules/frontend/static-map-layers.md`・`frontend-design-system.md`、
  `docs/modules/backend/cross-cutting-infrastructure.md`・`routing-engine.md`）
- 移せないと判断したものは、**防いでいた害と、代わりに何が起きるか**を書いて見送る
