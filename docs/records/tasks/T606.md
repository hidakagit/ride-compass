# T606. キキクル4種・風/勾配road-value系レイヤーのデータ取得状態（読込中/データなし/失敗）可視化

状態: 完了（2026-09-05、キキクル4種のみ。風/勾配road-value系レイヤーは[T607](T607.md)へ分離）

## 背景

T603・T605でJMAタイル/色別標高図タイルの404を「珍しくない正常系」として扱うよう
バックエンド側を是正した過程で、ユーザーから「今エラーになっているもの以外も同じ思想が
必要かチェックして」「ユーザー向けにその地点は欠損だったことを示せる？　風とかもそうなん
だけど、今は読込待ちなのか区別がつかない」との指摘。

調査の結果、フロントエンド側に以下2つの独立したギャップがあると判明した。

1. キキクル4種（landslideRisk/heavyRainRisk/inundationRisk/floodRisk）は改善計画T432で
   「防災カテゴリとして常時マウント・チップ無し」とした経緯があり、他の環境グループ
   （降水ナウキャスト・風・雷等）が持つ`useLayerDataStatus`（T87）の読込中/データなし/
   エラー追跡から意図的に除外されている。ユーザーへ「読込中なのか欠損なのか」を示す手段が
   無い。
2. 風/勾配のroad-value系レイヤー（`useDynamicWayValues.ts`/`dedicatedWayValueLayer.ts`）は
   loadingフラグ自体を持たず、「読込中」と「取得したが値が無い」の両方を同じ
   `COLOR_NO_DATA`（灰色）で表示している。

ユーザーへ「①（キキクル）は地図タイルに出そうか、環境グループはまとめて同じ仕組みに」との
方針提示を受け、AskUserQuestionで確認した結果、**キキクル4種にも他の環境グループ
（降水ナウキャスト・風・雷等）と同じ「地図上チップ」を持たせ、T432の「チップ無し常時表示」
方針を撤回する**方針で合意した。あわせてLayerChipのdataStatusドット機構を地図上チップ
（MapOverlayControls.tsx）へ拡張し、環境グループの全レイヤー（キキクル含む）が同じ
チップ+ドットで読込中/データなし/エラーを示せるようにする。

## 対応方針・実装内容

上記2ギャップのうち1（キキクル4種）のみを本タスクで実施した。2（風/勾配road-value系
レイヤー）は`useDynamicWayValues.ts`/`dedicatedWayValueLayer.ts`という別系統の実装で、
表示先も地図上チップではなくルート設定パネル（`RouteSettingsPanel.tsx`）側にあるため、
表示方法自体の検討が別途必要と判断し[T607](T607.md)へ分離した。

- `mapLayers.ts`: `MapLayerId`へ`landslideRisk`/`heavyRainRisk`/`inundationRisk`/
  `floodRisk`の4つを追加し、他のweatherレイヤー（thunderNowcast等）と同じ
  `category="weather"`・`dataNature="dynamic"`の`MapLayerDescriptor`を持たせた。
- `dynamicWeather.ts`: キキクル4種を`CHIP_DYNAMIC_WEATHER_LAYER_IDS`へ加え、
  `ALWAYS_ON_DYNAMIC_WEATHER_LAYER_IDS`（常時マウント用の別リスト）を撤去。
  `DYNAMIC_WEATHER_LAYER_IDS`は`CHIP_DYNAMIC_WEATHER_LAYER_IDS`そのものへ単純化した。
- `useDynamicWeatherLayers.ts`: キキクル4種それぞれに`showXxx`オプションを追加し、
  4種のいずれかがONの間だけ`fetchCurrentRiskFrames`を呼ぶ（他の要素と同じ「表示中のものだけ
  叩く」方針に統一）。`dynamicWeather`オブジェクトの`visible`もshow*変数へ差し替えた。
- `MapView.tsx`: `PRIMARY_DYNAMIC_WEATHER_SOURCE`へキキクル4種を追加（型がRecordの全キー
  必須にするため自動的に強制される）。あわせて`primaryDynamicWeatherSourceId`の
  `vector` kind（floodRiskが使う）分岐漏れを修正した（既存バグ、`gridMark`用の`mark`
  分岐へ誤って落ちていた）。
- `page.tsx`: `FIXED_LAYER_VISIBILITY_DEFAULTS`へキキクル4種を追加し、既定値は`true`にした
  （他のweatherレイヤーは既定OFFだが、防災級の情報はユーザー操作を待たず表示すべきという
  T432由来の安全上の理由をチップ化後も維持するため）。`overlayLayers`の`useMemo`から
  `layerDataStatus`を各チップへ渡すようにした。
- `MapOverlayControls.tsx`: `OverlayLayerChip`へ`dataStatus?: LayerDataStatus`を追加し、
  `ChipButton`が`LayerChip.tsx`と同じ「on && dataStatus != null」の間だけ状態ドットを
  アイコン右上へ描画するようにした（`MapOverlayControls.module.css`に
  `.iconStatusDot`/`.iconStatusDot_loading`等を追加、`LayerChip.module.css`の
  `.statusDot`系と同じ設計）。キキクル4種のアイコンは専用アイコンを新設せず`ShieldIcon`を
  4つとも流用した（windAxis/gradientAxisが既存アイコンを流用するのと同じパターン）。
