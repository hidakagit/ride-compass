# T598: 軸スタジオの折れ点編集を参考点・自動生成・効き目プレビューで省力化する

状態: 完了（1〜4番実装済み、2026-09-05。分割元は[T590](T590.md)。5番の解釈は実装メモ参照）

## 背景

折れ点はほぼ全て手入力で、曲線エディタ（`AxisComposer.tsx: BreakpointCurveEditor`）は
軸が現在の折れ点だけから自動スケールし、目盛り・格子線・スナップ・ドラッグ中の値表示が
無い。「折れ点を追加」は末尾に`[0,0]`を足すだけで昇順制約に即座に違反する。材料の値域の
情報が画面に無く、二乗則材料（[T591](T591.md)）のように単位が直感的でない場合は換算表を
外部で持たなければ編集できない。

## 対応方針

1. 材料カタログに参考点（ラベル＋値の一覧）を持たせ`GET /api/material-catalog`で配信する。
   風の新材料なら「時速20km・向かい風2m/s → 0.85」「向かい風8m/s → 4.95」「追い風で速度と
   同じ → -1.0」、勾配なら「緩い坂3%」「きつい坂9%」等。換算式はbackendだけが持つ
   （設計原則1）。
2. 範囲と形から折れ点を自動生成する入力方式。「0点にする値」「100点にする値」「形
   （一定／後半で急／前半で急／S字）」の3入力から5〜7点を生成し、通常の折れ点として保存する
   （backendのshape契約は不変）。0点・100点の値は参考点から選べる。生成後の個別調整
   （既存の数値行）は残す。
3. 効き目プレビュー表。折れ点を変えるたびに各参考点が何点になるかを表で即時表示する。
4. エディタ操作改善。目盛りと格子線、ドラッグ中の値ラベル、参考範囲に基づく固定の軸レンジ、
   刻み幅スナップ、矢印キー微調整、追加時は隣接点の中間へ挿入して自動ソート。
5. 参考点はT592の区間詳細の参考換算、T593の凡例補助にも同じ配信を使う。

## 対象ファイル

`backend/app/domain/material_catalog.py`（`reference_points`・`unit`）・
`api/routers/material_catalog.py`・`frontend/src/components/AxisStudio/AxisComposer.tsx`・
`lib/axisMaterialsCatalog.ts`・`docs/modules/backend/`材料カタログ該当モジュール・
`docs/modules/frontend/axis-studio`該当モジュール。

## 実装メモ（1番backend）

`MaterialSpec.reference_points: list[MaterialReferencePoint]`（`label: str`, `value: float`、
既定空list）を追加し、`GET /api/material-catalog`の`MaterialCatalogEntry.reference_points`
として配信する（`MaterialReferencePointEntry`、`tile_property`等と異なりこちらは公開
フィールド）。値を持たせたのは`wind_drag_ratio`（風、時速20km基準の6点、
`domain/wind.py: wind_drag_ratio`の計算値を小数2桁丸め。非推奨エイリアス`wind_penalty`には
持たせない）・`gradient_percent`（勾配、4点）・`stop_count_per_km`・`intersection_count_per_km`・
`accident_count_per_km_year`・`maxspeed_kmh`・`lanes_count`（各2〜4点、常識的な目安の静的値）。
真偽値・categorical材料は空リストのまま。frontendは`useMaterialCatalog`・静的フォールバックの
型に`referencePoints`を任意フィールドとして持つのみで、表示（2〜5番）は未実装。

## 完了条件

- 風軸を「0点=無風」「100点=向かい風8m/s」「後半で急」の3操作で作り直せる（実機確認）。
- 参考点が材料カタログの1エントリ追加だけで増やせる（軸スタジオ側のコード変更なし）。
- 「折れ点を追加」で昇順制約に違反した状態が作られない。

## 実装メモ（2〜4番、2026-09-05）

- `components/AxisStudio/breakpointTools.ts`（新規、DOM非依存の純粋関数）に集約:
  `generateBreakpoints`（3入力→6点、`zeroValue > hundredValue`でも常にx昇順で返す）・
  `interpolateBreakpointScore`（backend: `evaluate_breakpoint_linear`と同じ区分線形補間・
  丸め）・`insertBreakpointAtLargestGap`（「+ 折れ点を追加」の挿入位置）・
  `niceStep`/`snapToStep`（ドラッグスナップ）。
- `AxisComposer.tsx`: `draft.terms.length===1`かつ他軸参照でない場合のみ、その材料の
  `referencePoints`から「自動生成フォーム（0点/100点/形の3入力＋参考点クイック選択
  ボタン）」「効き目プレビュー表（今の折れ点で各参考点が何点になるか、折れ点を
  変えると追従）」を表示する（`primaryMaterial`、複数term・他軸参照は対象外——完了条件
  検証もT592第1段の判断点と同じく単一材料の軸で行う）。参考点の生値は`toBreakpointX`
  （weight×preprocess）で折れ点の横軸へ変換してから使う。
- `BreakpointCurveEditor`: `referenceRange`（参考点の値域＋10%余白）を渡すと横軸を
  固定し、ドラッグ中に見た目のスケールが動かなくなるようにした（参考点が無い材料は
  従来どおり自動スケール）。目盛り線・ドラッグ中の値ラベル・矢印キー微調整
  （Shift併用で10倍刻み、`role="slider"`＋`tabIndex`でキーボード到達可能）を追加。
- 「+ 折れ点を追加」を`insertBreakpointAtLargestGap`へ差し替え、常に昇順を保つ
  （完了条件3）。既存の`AxisComposer.test.tsx`にあった「追加すると非昇順になりエラーが
  出る」という旧仕様の回帰テストは、新しい正しい挙動（追加してもエラーにならない）の
  確認と、手入力でのみ再現できる非昇順エラーの確認との2本へ分けて更新した。
- 5番（T592の区間詳細・T593の凡例補助への参考点再利用）は、`reference_points`が
  `GET /api/material-catalog`という単一の配信経路から出ている時点で構造的には満たして
  いると判断し、T592の区間詳細・T593の凡例に参考点ベースの換算表示を新設する追加UI実装は
  今回の対応に含めていない（必要であれば別途起票する）。
