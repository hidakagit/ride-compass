# T766. RouteCandidateのテストフィクスチャを1箇所へ寄せる 規模S

状態: 完了（2026-09-13、[T621](T621.md)で`edge_ids`を足したときに露見）

## 背景

フロントの`RouteCandidate`は`Omit<Required<...>>`で型付けされているため、
**全フィールドが必須**で、候補を組み立てるテストは全フィールドを書く。その構築が
8箇所に散っており、フィールドを1つ足すたびに8箇所を直すことになる。

`edge_ids`（T621）の追加で実際に8箇所が同時に落ちた。tscが機械的に全件を挙げるため
取り残しは起きないが、毎回8ファイルを触る差分が出る。

[T650](T650.md)がテストのフェイクを`frontend/src/testing`へ集約した先例があり、
同じ置き場へ寄せられる見込み（`e2e/fixtures.ts`は別のビルド対象のため要確認）。

## 対応

`frontend/src/testing/routeFixtures.ts`の`makeRouteCandidate(overrides)`を唯一の置き場にし、
散っていた構築をすべてそこへ寄せた（`page.test.tsx`・`ComparisonPanel.test.tsx`・
`MapView.routes.test.ts`［2箇所］・`RouteSplicePanel.test.tsx`・`gpxExport.test.ts`・
`routeApi.test.ts`・`MapView.bench.ts`・`e2e/fixtures.ts`）。呼び出し側は変えたい
フィールドだけ渡す。`e2e/fixtures.ts`はPlaywright側のビルド対象だが、`@/`エイリアスが
そのまま効くため同じ置き場を共有できた。

既定値と違う値に意味があるものは呼び出し側に残した（GPXの出力を見るテストの座標列、
ベンチの区間数・geometry生成、乗り換えのedge_ids等）。

## 検証

`RouteCandidate`へ試しにフィールドを1つ足して`tsc --noEmit`を通したところ、**落ちたのは
`src/testing/routeFixtures.ts`の1ファイルだけ**だった（T621の`edge_ids`追加時は8箇所が
同時に落ちていた）。プローブは確認後に戻し、`npx vitest run`は137ファイル1269件green。
