# T988. 消した検知器が見ていたものを、/review の観点として書き下ろす 規模M

状態: 未完了

2026-09-21起票。

## 背景

[T986](T986.md)で検知器を32本から3本へ削った。落とした29本のうち、**許可リストが要る
ために機械化できないもの**は「周期レビューで人が見る」へ移したことにしたが、
**`/review` にその観点が名指しされていない**。見る対象が書かれていなければ、実際には
見られない。

移したつもりになっているもの:

- `dead_file_refs`・`dead_identifier_refs` — `docs/modules` が名指しするファイル・識別子が
  実在するか
- `source_comment_dead_identifier_refs`・`source_narrative` — コードのコメントが名指しする
  死んだ識別子と、経緯コメントの混入
- `narrative` — `docs/modules` の記載粒度
- `doc_constant_drift` — 文書が書いた定数値と実装のずれ
- `review_doc_dead_refs` — 手順書の死んだ識別子参照
- `undocumented_files` — 実装ファイルの `docs/modules` 記載漏れ
- 参考表示だった8本（個数の書き方・相手レイヤーの断定・重複したテスト足場ほか）
- `undeclared_fixed_values` — 較正値にすべき数値がコードへ直書きされていないか
  （宣言`FIXED_VALUES`ごと消えたため、機械で見る手段は無い。[T987](T987.md)の見送り節参照）

## 測ったこと（2026-09-21）

- `.claude/commands/review.md` がこれらの概念に触れているのは**3箇所**だけ
- 検査の頻度が**毎コミット → 14日または実装2万行ごと**へ変わった。その窓に何が溜まるかは
  同日に実証済みで、`architecture.md` を章へ分割したところ**約2,000行が「modules側に
  同じ内容があり、architecture側が古い写し」**として出てきた

## やること

`/review` の「整合性」の観点へ、上記を**何を読むか分かる形で**書く。

**観点を並べるだけにしない。** 読む量は前回タグ以降の変更に比例し、今その差分は
57,161行ある（閾値20,000を大きく超えて溜めた結果）。観点ごとに「どこを読むか」
（変更ファイル全文／計測の出力／発火したファイルだけ）を決めて書く。

## 完了条件

- `/review` を読んだだけで、消した検知器が見ていたものを再現して見られる
- 観点ごとに読む対象が書かれていて、全件を読む指示になっていない
- トリガーの閾値（14日・2万行）が、その読む量に対して妥当かを実測して判断する
  ——溜めすぎると1回のレビューが終わらない

## 消した宣言から引き継いだもの（2026-09-21、[T968](T968.md)段階2）

`domain/tuning.py`の`FIXED_VALUES`を削除した。**検知器`undeclared_fixed_values`の対象範囲を
宣言するテーブル**だったが、その検知器は既に無く、本番からもテストからも読まれていなかった
（到達可能性の調査で孤立点として出た）。

消した内容は「モジュール → 定数名 → 種別（PHYSICAL/NUMERICAL/RESOURCE等）」の対応表で、
14モジュール・数十個の定数を挙げていた。挙げていたのは例えば`domain/geo.py`の
`EARTH_RADIUS_KM`・`KM_PER_DEGREE_LATITUDE`（物理）、`domain/routing.py`の
`DEFAULT_NODE_INDEX_CELL_SIZE_DEG`（数値）、`domain/cycling_speed.py`の
`AIR_DENSITY_KG_M3`・`GRAVITY_M_S2`（物理）。

**この検知器が見ていたのは「較正値でも固定値でもない、どちらの宣言にも無い数値定数が
モジュール直下に置かれていないか」**。つまり「この値はどこで決まっていて、変えられるのか」
の答えが1箇所にある状態を機械で保っていた。観点として書き下ろすときの材料にする。
削除前の全文は`0129a18d`より後の`domain/tuning.py`の履歴から取れる。
