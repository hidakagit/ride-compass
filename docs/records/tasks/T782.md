# T782. 軸チップをアイコン主体にして内訳の縦を詰める

規模S。
状態: 完了（2026-09-13、ユーザー指摘「ルート結果パネルの各軸表示、ルート生成パネルと
合わせるために丸ボタンにしたけどデッドスペースが多い。再考したい」から）

## 背景

[T776](T776.md)で両パネルのチップを同じ丸ボタンへ揃えたが、狭い右カラム（202px）では
軸名が長く1〜2個ずつ折り返し、内訳だけで196pxを使っていた。行末にも余白が残る。

## 決定（モックを見て判断、2026-09-13）

390px幅の実寸モックで4案を比べた。高さの実測は 現状196px／枠なし・行いっぱい176px／
アイコン＋略名170px／**アイコン＋値だけ111px**。

- **ルート結果**: アイコン＋値（名前なし）。軸の名前は押して開く説明（ⓘ）が持つ
  ——「名前は情報アイコンで確認する」（ユーザー判断）。
- **ルート設定**: アイコン＋略名（`chip_label`、地図チップと同じ最大4文字）。
  こちらは「どの軸を使うか選ぶ」画面のため名前が要る。
- チップの形（枠なしの薄い塗り・行いっぱいに伸びる）とアイコン・色は両パネルで共有する。

## 対応

- `PreferenceAxisDef`へ`iconId`・`chipLabel`を通し、両パネルが`axisIconFor`で地図チップと
  同じ意匠を引く。
- 結果側の凡例は色ドット→軸アイコンへ置き換え、ラベルを出さない。押せないチップは
  `role="img"`＋`aria-label`で軸名を持つ（押せるチップは詳細ボタンのaria-labelが持つ）。
- 共有CSS（`ui/axisLegend.module.css`）で丸い枠をやめ、薄い塗り＋角丸小・内側余白を詰め、
  チップが行の余りを分け合って伸びるようにした。

## 検証

- ルート結果の凡例の実測: **196px → 116px**（390x812、公開軸10本・うち3本は値なし）
- 両パネルのスクリーンショットで、同じ軸が同じアイコン・同じ色で並ぶことを確認
- `npx vitest run` 137ファイル1269件green。軸名を文字で探していたテストは、アクセシブル名
  （`getByLabelText`）で探す形へ移した——表示から名前が消えても軸の同定はできる必要がある
- e2eの`installApiMocks`へ軸カタログを足した（「重みづけ」タブがこれまで軸一覧を引けず
  エラー表示のままで、設定側の見た目を実機確認できなかった）
