# T835. CIだけが実行するテストの赤に、次のCIログを開くまで気づけない

規模S。
状態: 完了（2026-09-14、[T834](T834.md)の再発防止として）

## 背景

`@postgis`マークのテストはローカルの既定実行（`pytest -q -m "not postgis"`、CLAUDE.md
「テスト方針」・docs/conventions/testing.md）から外れ、CIだけが実行する。そのため実装変更にテストが
追随していなくても、手元では緑のまま気づけない。

2026-09-12に**独立した2つのタスクが同じ型で赤を作り**、2026-09-14にユーザーがCIのログを
開くまで2日間気づかれなかった（詳細は[T834](T834.md)）。

- `c6693c15`（T731、09/12 03:53）— 読み出し時の列構成検証を追加、テスト未追随
- `650e060a`（T753、09/12 23:26）— 戻り値を4要素化、テスト未追随

## 3回目（2026-09-14）

起票の当日に同じ型がもう1件出た。`T571`（派生データ鮮度台帳）が`DerivedDataFreshnessCounts`
から`road_edges_total`・`elevation_uncalculated_count`を廃し、ラベル付きの`completeness`へ

**手元の既定実行では@postgisが走らないため、ここでも緑に見えていた。**

## 影響（放置した場合に次に起きること）

**既に赤いCIには、新しい赤が埋もれる。** 赤が常態になると「CIが通ったこと」を完了の根拠に
できなくなり、`docs/workflow.md`の完了条件・`/review`系の「検査器が正」という前提が
実質的に空洞になる。2日間に入った変更はすべてこの状態で載っている。

## 対応方針（着手時に選ぶ。検知器を第一候補にする）

CLAUDE.md「修正の原則」に従い、**自己申告のチェックを増やす案は最後に回す**。

1. **第一候補: masterのCIが赤いことを手元で知らせる。** pre-commit（`scripts/pre-commit.sh`）
   またはコミット後のフックで`gh run list --branch master --limit 1`相当を引き、直近の
   結論がfailureなら参考表示する。`@postgis`に限らず「CIの赤に気づかない」という型そのものを
   捕まえる。ネットワークに触れるため、失敗時は黙って素通しにする（コミットを止めない）。
2. **第二候補: postgisテストを手元の既定へ戻せないかを測る。** 現在の分離は実行時間と
   DB可用性が理由。実測では`pytest -m postgis -q`が285件55秒で、反復のたびに払うには重いが
   完了前の1回なら許容できる可能性がある。既定を変えるのではなく、`scripts/`に
   「完了前に1回通す」入口を1本用意する形も含めて検討する。
3. **最後の選択肢: docs/conventions/testing.mdへ「完了前に`-m postgis`を1回通す」と書く。** 上の2つが
   どちらも成立しない場合のみ。文章のルールは守られたかどうかを機械が見られないため、
   同じ型の3回目を止められない。

## 実装（2026-09-14）

**第一候補（masterのCIの赤を手元へ出す）を採った。** `@postgis`に限らず「CIの赤に気づかない」
という型そのものを捕まえられるため。

- `gh`はこの環境に入っていなかった（`command not found`）。代わりにGitHubの公開REST APIを
  直接読む——このリポジトリは公開で、認証なしに`actions/runs`を参照できることを確認した。
  pre-pushフックが認証情報を扱わずに済む。
- **pushの直前に見る**（`scripts/pre-push.sh`）。「赤いCIへ新しい変更を積む」のを避けたいので
  masterへ出す直前が正しい。毎コミットでネットワークを叩くとコミットが遅くなる。
- **pushは止めない。** 赤の原因が自分の変更とは限らず（他セッションのpushで赤いこともある）、
  止めると無関係な作業がブロックされる。
- 判定の単位は**masterの最新コミットに対する結論**。古いコミットの失敗で鳴り続けると、警告
  そのものが無視されるようになる。実行中（結論が出ていない）も赤として扱わない。

## 検証

**わざと赤い状態を通して、実際に出ることを確認した**（完了条件）。

| 確かめたこと | 結果 |
|---|---|
| 実際のmaster（全green）で黙る | 出力なし・終了コード0 |
| 赤い応答（Docs Consistency: failure）で出る | ワークフロー名・結論・実行URL・対象コミットが出る |
| 取得できない環境で止まらない | 到達しないホストで`fetch_runs`→None、`main()`は0.2秒で終了コード0 |
| フック経由でも同じ | `sh scripts/pre-push.sh`が終了コード0 |

判定は`backend/tests/test_check_master_ci.py`が9件で固定する（古いコミットの失敗を鳴らさない・
実行中を赤としない・再実行で直った場合・cancelled/timed_outは赤・skippedは赤でない、ほか）。

## 有効化

他のフックと同じく手動で導入する（他のworktree・clone・CI環境には影響しない）:

```bash
cp scripts/pre-push.sh .git/hooks/pre-push && chmod +x .git/hooks/pre-push
```
