# T1205. 事故密度の数え上げが、T970段階Cの作り直しで「自転車が関わった事故だけ」「道から30m以内」の条件を失い、全事故を最大約77m先の区間へ付けている

状態: 未完了（2026-09-27起票）

## 背景

周期レビュー第14回（2026-09-27）の起票案（ダッシュボード proposal-accident-count-regression、承認済み）。

規模L（根拠: 本番で派生の作り直しが要る。コードは derive_counts.py の1定数とテスト）

■ 背景
性質: 作り直しで落ちた条件（新語）。backend/app/batch/derive_counts.py の _EDGE_ACCIDENTS は `WHERE a.source = 'accident'` だけで、BICYCLE_SQL（involves_bicycle）も ST_DWithin も無い。距離は ST_Expand の箱だけ（南北60m・東西約49m、角で約77m）。旧実装（b260ac19^ の road_graph_repository.py:951-952）は `ST_DWithin(..., :accident_distance_m)` と `(:bicycle_only = false OR a.involves_bicycle)`（既定 True）を持っていた。設計書（static-road-attributes.md:247）と domain（material_catalog.py:590・accident.py:7-11）は今も「自転車の事故だけ・30m以内」と書く。司令塔が実物のコードで確認した。T1172 で6年分に広げた取込も、この数え方のまま件数を増やしている。件数の差は未計測。

■ やること
1. _EDGE_ACCIDENTS に自転車の絞り込み（domain の BICYCLE_SQL）と ST_DWithin(ACCIDENT_MATCH_MAX_DISTANCE_M) を戻し、期待値のテストを足す。
2. 母集団: T970段階Cの作り直しコミット（b260ac19・f87d2956・91bc3832）で消えた旧SQL定数を `git show <c>^:<旧ファイル>` で列挙し、WHERE の述語（絞り込み・半径・既定の引数）が新SQLにあるかを1件ずつ突き合わせる（事故以外は未確認。停止要因は T1171、構造物は T931 で意図して変えた）。
3. 本番で派生を作り直し、直す前後の事故のある道の割合を測る。
4. その後に T856 の事故密度の折れ点を測り直す（今の測定は母集団が違う）。

■ なぜ既存のタスクに入らないか
T970 はユーザーの手動のタスクで、T1172・T1203 は取込と分母の話。数え上げの条件の退行はどれにも属さない。
