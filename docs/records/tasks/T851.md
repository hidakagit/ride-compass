# T851. 「DBの世代とディスクの記録を突き合わせて捨てる」仕組みが2つある

## 背景

同じ機構が2箇所に別々に書かれている。片方は[T847](T847.md)で今日足したもので、既にある側を
一般化せず隣に同型のものを作った。

| | 軸定義 | 派生データ（T847） |
|---|---|---|
| DBの単調カウンタ | `axis_registry_meta.revision` | `derived_data_meta.revision` |
| ディスクの記録 | zoom=-1の予約タイル | 同じ方式で別に1つ |
| 突き合わせ | `sync_disk_cache_with_axis_revision` | `sync_disk_cache_with_derived_data_revision` |
| 判定 | 一致なら温存／不一致なら消す／Noneは安全側 | 同じ |

1行テーブルの形も、マーカーの持ち方も、判定の分岐も同じ。片方だけ直すと静かにずれる。

## 対応方針

判断だけを持つ`infrastructure/cache_generation.py`を1本用意し、軸定義と派生データの両方が
そこを通る。比較の対象（どのカウンタか）と、食い違ったとき何を捨てるかは呼び出し側が渡す。
共通側が持つのは「一致なら温存・不一致なら捨てて記録し直す・読めなければ安全側へ倒す」だけ。

軸側だけが持つ差（温存のときもメモリLRUは空にする）は呼び出し側に残す——起動のたびに呼ばれる
経路のため、ディスクを温存しつつメモリは作り直したい。

## 実装メモ

- 予約タイル座標（zoom=-1）とマーカーの読み書きは共通側へ移した。両キャッシュから重複した
  分岐・ヘルパが消え、行数は48行→18行。共通側は47行なので**総行数はわずかに増える**が、
  同じ判断が2箇所にある状態は解消する（片方だけ直してずれる余地を無くすのが目的）。
- テストが触っていた内部名（`_read_persisted_axis_revision`・`_read_persisted_revision`）は、
  診断用の公開関数として1本ずつ残した。
