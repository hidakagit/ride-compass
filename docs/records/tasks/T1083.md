# T1083. 監査と定期確認に、作業ブランチのCIのジョブごとの所要をmasterの直近と比べる項目を足す

状態: 未完了（2026-09-23起票）

## 背景

T1049の改善提案をユーザーが承認（2026-09-23）: 全体へ波及する変更（T1014段階Dで作業ブランチのCIのe2eが約8分に伸びた）を司令塔が波及を判断せずに監査で通し、その後の各担当のCI待ちに気づかなかった。規約 docs/conventions/orchestration.md「監査の項目と合格の基準」に項目10（共有資源への波及）を入れた: 作業ブランチのCIで、いずれかのジョブの所要が、masterの直近5回の成功した実行の同じジョブの最大値より60秒以上長ければ、司令塔は通さずユーザー確認に上げる。やること: (1) orchestrate.py audit の機械項目に、報告のshaのCIのジョブごとの所要と、masterの直近5回の成功の同じジョブの最大値を並べて出し、60秒以上長いジョブがあれば「ユーザー確認」と出す（masterでだけ走る段——今は全状態の走査——は作業ブランチに出ないので比べられないことも出す）。(2) orchestrate.py check（定期確認）に、直近の orch/** のCIのジョブごとの所要がmasterの基準より60秒以上長いものを異常として出す。GitHubへの問い合わせは scripts/orchestration/github.py に寄せ、問い合わせ回数が1時間5,000回の枠を圧迫しないようにする。完了条件: T1014段階Dの作業ブランチのCI（run 35842502347、e2e 535秒）を当てると audit が「ユーザー確認」を出し、T1017の作業ブランチのCI（run 35853040357）では出ないことを見る。
