# T899. 既定ONのレイヤーを、性質からではなく1つずつ手で書いている

規模S。
状態: 完了（2026-09-16。[T422](T422.md)が「起票はまだしていない」と書いたまま
残っていた派生を、統合レビュー第10回の棚卸しで独立させたもの）

## 背景

災害レイヤーだけが既定ONで、その理由は「防災級の情報はユーザー操作を待たず表示すべき」
という**性質**にある。しかし実装は`frontend/src/app/page.tsx`の
`DEFAULT_LAYER_VISIBILITY`——レイヤーidごとにtrue/falseを手で書く辞書で、性質は
コメントにしか書かれていない。

レイヤーを1つ足すたびにこの辞書へ1行足す必要があり、**足し忘れると型が落とす**（全idを
埋める`Record`のため）のが今の安全網である。逆に言えば、足し忘れは防げても
「この新しいレイヤーは防災級か」という判断はコメントを読んだ人にしか効かない。

## 保留することで何が起きうるか

防災系のレイヤーが2つ目に増えたとき、既定ONにするかどうかが**そのとき書く人の記憶**に
なる。片方だけONという状態は、利用者から見ると「なぜこれだけ出ているのか」が説明できない。

## 対応方針（未着手）

`MapLayerDescriptor`へ`alwaysOnByDefault`のような宣言的フィールドを持たせ、
`DEFAULT_LAYER_VISIBILITY`をその宣言から導く。[T888](T888.md)が同じ`MapLayerDescriptor`へ
「描画順」「最小ズーム」を持たせる射程を持つため、**まとめて1回で入れた方がよい**
（記述子へ足すフィールドが増えるたびに消費側を作り直すことになる）。

## 実施（2026-09-16、[T888](T888.md)段階1と同じコミット）

`MapLayerDescriptor`へ`defaultOn?: boolean`を足し、`buildDefaultLayerVisibility()`が
記述子から初期値を導く形にした。`page.tsx`の`DEFAULT_LAYER_VISIBILITY`は
1行（この関数の呼び出し）になり、レイヤーを足したときに書き足す場所が無くなった。

既定ONの根拠（防災級の情報は予兆が出てからONにするのでは手遅れ／危険度が出ている間は
他の面レイヤーが完全に覆われるが、そのときは防災を優先する）は、辞書のコメントから
`disaster`の記述子へ移した。判断の根拠は、判断そのものと同じ場所に置く。

`Record<MapLayerId, boolean>`の型が「キーを足し忘れると落ちる」という安全網は失われるが、
導出になったので**忘れる余地そのものが無い**。省略時はOFF（明示的にONにして初めて出る、
という地図レイヤーの原則）のため、宣言を書くのは既定ONにしたいときだけになる。

## 検証（わざと壊して落ちることを見た）

- `landcover`へ`defaultOn: true`を足す → 新設した
  「地図を覆う静的レイヤーで既定ONなのは防災級のものだけ」が落ちた（性質の側で縛っているため、
  防災系が2つ目に増えたときに片方だけONという状態も同じ形で落ちる）。
- `disaster`から`defaultOn`を外す → `page.test.tsx`が58件中3件落ちた（既存の
  end-to-endの確認が効いている）。
- 復元後、frontend全1,397件green・`tsc --noEmit`・`eslint src`とも通過。
