# T1066. 並行実行の作業ツリーを固定数にし、消さずに使い回す

状態: 未完了（2026-09-23起票）

## 背景

並行実行では、エージェントを isolation: "worktree" で起動するたびに Claude Code が新しい作業ツリーを作り、タスクが終わっても消えない（2026-09-23 時点で28本、C: の空き11.9GB）。作るたびに npm ci（実測136〜194秒、うち89〜96%が32,880ファイルの書き込み。T1063）と、共有の core.hooksPath の書き換え（anthropics/claude-code#66993、not planned）を払い、自動の片付けは追跡対象の .claude/settings.local.json が必ず書き換わるため発火しない（T1042）。ユーザー決定（2026-09-23）:「作業ツリーは総数を決めて使いまわす。その作業ツリーの枠以上の作業はできない規約にして、毎回コピーせず保持する」「案2から確かめて進めて」。これにより T1063（npm ci の短縮）の残り（種からのコピー）は不要になり、T1042 の「自動で片付かない」は片付けない設計へ形が変わる。

対応方針:
1. 案2を公式文書で確かめる: Claude Code の hooks の WorktreeCreate（と WorktreeRemove があればそれも）の入力・出力・失敗時の扱い（https://code.claude.com/docs/en/hooks#worktreecreate、https://code.claude.com/docs/en/worktrees）。既定の作成を置き換えたとき、既存の作業ツリーのパスを返してよいか、Claude Code が作業ツリーへ書く目印・実行中のロック・終了時の自動削除がどう振る舞うか（使い回す作業ツリーが終了時に消されないこと）を、書かれた文と、実際に1回エージェントを起動した観測の両方で確かめる。
2. 案2が使えるなら: WorktreeCreate フックで、固定の作業ツリー（スロット）のうち空いているものを返す。スロットの数は同時実行の上限と同じ（既定3）。空きが無ければ作成を失敗させ、エージェントは起動しない（上限を仕組みで守る）。使えないなら案1: 作業ツリーを持つ担当を固定数にし、タスクは常にその担当を再開して渡す。担当の会話が膨らんだときに同じスロットを新しい担当へ引き継ぐ手順を決める。
3. スロットの初期化（渡すたび）: 最新の origin/master から作業用の枝を作り直す。前のタスクの未コミットの変更が残っていたら止めて報告する（黙って消さない。副産物の .claude/settings.local.json の扱いを決める）。package-lock.json が前回の npm ci から変わっていたときだけ npm ci（heavy の枠で）。空き・使用中の管理は、状態の表に書かず事実から導く（規約「表に持つのは表にしか無い事実だけ」）——例えばスロットの使用中は実行中のロックや目印の有無から。
4. 規約（docs/conventions/orchestration.md「起動のしかた」「依頼は1件ずつ、依存は表で」）と CLAUDE.md「作業ツリーの安全」を、固定数のスロットを使い回す形へ書き換える。CLAUDE.md の「バックグラウンドAgentへ実装タスクを委任するときは isolation: worktree を必ず指定する」との関係を明記する。
5. 移行: 既存の作業ツリーのうち成果が master に入り未コミットが副産物だけのものは削除の対象としてユーザーへ手順を渡す（作業ツリーの削除は司令塔からは実行しない。rd /s 相当で消す——T1042 の落とし穴）。スロットは新しく作るか既存を転用するかを決める。
6. T1063 と T1042 は本タスクへ畳む（T1063 は分かったことを記録して閉じ、T1042 の未解決分のうち本タスクで解けないものが残れば本タスクの記録へ移す）。

完了条件: 案2（または案1）で、エージェントを3本続けて起動・完了させても作業ツリーの総数が増えないこと（git worktree list の件数で確かめる）、4本目の同時起動が拒否されること、スロットを渡し直したときに npm ci が走らないこと（package-lock.json が同じ場合）と走ること（変えた場合）、core.hooksPath が書き換わらないこと（または書き換わっても相対へ戻ること）を、それぞれ実測で示す。
