# T1078. E2Eの全状態の走査を、状態ごとに開き直さず画面の木をたどる形にして、CIのe2eの所要を縮める

状態: 未完了（2026-09-23起票。設計は下の「設計（2026-09-23、ユーザーと確定）」節で確定、実装前）

## 背景

T1014段階Dの全状態の走査（frontend/e2e/all-states.spec.ts）で、CIのe2eジョブが75秒→535秒に伸びた（内訳はT1014.md「CIのe2eの所要の内訳」節）。伸びはすべて全状態の走査の4本（計768ワーカー秒、311状態、1状態あたり約2.5秒）で、状態ごとにreopen()——localStorageを戻してpage.goto('/')から開き直し、生成後ならルート生成をやり直し、1段目のスイッチを押し直す——を払っている。ユーザー提案（2026-09-23）:「A→Bと操作した先の画面で、C、D、さらにそこからE→Fと見たいものがある場合、A→Bで止めて、CとD、E→Fはいっぺんにやる」「操作を効率的にできるスクリプトで、移動作業はショートカットする」。方針: (1) 開き直しをやめ、親の状態で止めて子のスイッチを押す→検査→閉じる（元へ戻す）で木をたどる。戻せたかは親の状態の指紋（DOMの開閉の宣言・localStorage）で確かめ、戻らなかったときだけ開き直す（黙って別の状態を検査しない）。(2) 生成後の段階は、ルート生成を状態ごとにやり直さず1回の生成を使い回す。(3) 画面から導いた状態の母集団（states.ts）は変えない——速くするために見る状態を減らさない。完了条件: 同じ311状態（または同じ導出で出る全状態）を検査していることを件数で示し、直前・直後のCIのe2eジョブの所要を並べる。壊した入力（T1014段階Dと同じ2種）で今も落ちることを1回見る。T1069（P-pinch）がall-states.spec.tsへscanPinchを足すので、その後に着手する。

## 設計（2026-09-23、ユーザーと確定）

### 人の判断で決めたもの（機械的でない前提。この3つだけ）

| 前提 | 内容 | 根拠 |
|---|---|---|
| 幅は2通り | モバイル・デスクトップ。幅の分岐はCSSの`--breakpoint-mobile`だけなので、その両側に1つずつ置き、両側にあることを実行時に検算する（具体値は両側にあれば何でもよい） | ユーザー判断 |
| 段階は2通り | ルート生成の前と後。辿り方は開閉の部品しか押さないので、生成後にしか現れない部品（候補一覧・比較タブ・GPX出力等）へ届くには生成を1回押す必要がある。「開閉以外で画面に部品を足す操作は生成だけ」は機械では導けない（開閉以外のボタンを全部押すと、ダウンロード・クリア等の破壊的な操作が混ざる） | ユーザー判断「ページ要素が大きく変わるのはルート生成前と後の2パターンだけ」 |
| 研究モードは省く | どのモードのチェックボックスも押さない（既定の状態のまま）。今の走査はモードなし・研究モードの2通りで同じ木を巡っていた | ユーザー判断 |

### 合否（すべて機械的に判定する）

| 検査 | 基準 |
|---|---|
| ページが横にスクロールしない | `document.scrollingElement.scrollWidth ≦ innerWidth + 1`（+1は`scrollWidth`が整数へ丸められる——CSSOM View——ことの誤差） |
| 押せる部品が画面幅からはみ出さない | 部品の矩形が`left ≧ -1`かつ`right ≦ innerWidth + 1`。「押せる部品」は**ブラウザが計算したロール**（CDPの`Accessibility.getFullAXTree`）が**WAI-ARIAの widget ロール**（操作できる部品の分類。一覧は実装時に公式の仕様から取り、出典をコードに書く）に当たるもの。矩形の面積が0のもの・`checkVisibility()`が偽のものは対象外。祖先のどれかの計算後の`overflow-x`が`auto`か`scroll`なら除く（スクロールで届く）。今の手書きのセレクタ（`button`・`a[href]`・`role="tab"`等）は廃止する |
| 余白ユーティリティがリセットに潰されない | 今と同じ（試しの要素へ値を`!important`で与え、ブラウザの計算値と要素の計算値を比べる）。**変種付き（`sm:`等）は、今の画面で条件が成り立つものだけ見る**（幅の変種は`matchMedia`で判定、`hover:`等の操作の変種はその操作をしていないので対象外）。今は変種付きを一律に除いている |
| ピンチでページが拡大しない | 2本指で開いたあと`visualViewport.scale === 1`。**モバイルだけ**（タッチを持つ文脈＝`hasTouch`でしか指の入力を送れない） |
| ピンチの対象 | 見えている要素のうち、**自分の中心点でヒットテストすると自分（か子孫）が返るもの**。地図のcanvasは除く（地図の上のピンチは`map-runtime.spec.ts`が見る）。今の8px格子は廃止する（間隔が選んだ数字だったため） |
| ピンチの操作 | 指は**画面の端まで開く**（今の8px×12歩は選んだ数字だったため）。開いたあと、**連続する2フレームで倍率が変わらなくなるまで**待ってから読む（今の固定200msは廃止） |
| 同じ部品へのピンチは1回 | **同じDOMノード**（JSのオブジェクトとして同一）なら省く。1枚のページで辿るので、状態をまたいで残る部品は同じノードになる。描画し直されたノードは別物として扱い、もう一度当てる（安全側） |
| 閉じたら元に戻る | 下の「戻す」のあと、指紋が押す前と一致しなければ**違反として落とす**（通り直さない。ユーザー判断） |
| 開いた状態が1件以上ある | 辿った状態（土台を除く）が各幅・各段階で1件以上（パターン6）。今の「『ルート結果』シートと『比較』タブに届いたか」は、届くべき状態を手で名指ししているので外す |

### 辿り方（遷移は各状態へ1回だけ）

- **幅ごとに1枚のページ**で、開く → 生成前の木を辿る → 「ルート生成」を1回押す → 生成後の木を辿る。
  テストは幅ごとの2本（今の幅×段階の4本をまとめる。CIのワーカー2本で並ぶ）。
- **「開くもの」**は`aria-expanded="false"`の部品と、`role="tab"`かつ`aria-selected="false"`の部品。
  矩形の面積が0のもの・見えていないものは除く。
- **押せるものだけ押す**: 部品の中心点が画面内にあり、そこで`elementFromPoint`が部品自身か子孫を返すこと
  （上に重なっている順番はブラウザのヒットテストが決める）。押せないものは押さない（違反にもしない）。
  中心点を使うのは、Playwrightが押す点と同じだから（約束事として記録する）。押す前に判定するので、
  押せない部品に3秒のタイムアウトを払うことも無くなる。
- **押せる限り奥まで辿る**（今の「2段まで」の上限は無くす）。祖先の状態に**同じDOMノード**がある部品は押さない
  （兄弟のシートを行き来して回り続けることを防ぐ。今の「名前の数字を伏せて比べる」工夫は要らなくなる）。
- **戻す**: `aria-expanded`の部品は、押せるならもう一度押し、押せない（開いたものが上を覆っている）ならEscape。
  タブは、押す前に同じタブ列で選ばれていたタブを押す。
- **指紋**: ARIAの開閉の値（`aria-expanded`・`aria-selected`）をノードごとに集めたもの・localStorageの全項目・
  `visualViewport.scale`。
- **押したあとの待ち**: 固定の300msをやめ、フレームを単位にして「開くもの」の一覧と指紋が連続2フレームで
  変わらなくなるまで待つ。カタログのように非同期に後から届くものがあるので、その間の通信が終わるまで
  （Playwrightの`networkidle`相当）も待つ。

### アプリ側の変更（同じ変更に含める）

- モバイルの下部タブ（`page.tsx`の`nav[aria-label="パネル切り替え"]`の2つのボタン）は、シートを開閉するのに
  `aria-pressed`で宣言している。**`aria-expanded`へ直す**（ユーザー判断）。これで「開くもの」の基準から
  ナビゲーションの名前で絞る部分（今の`states.ts`の`nav[aria-label="パネル切り替え"] [aria-pressed="false"]`）が消える。
  `aria-controls`でシートを指すかは実装時にARIAの公式の記述を読んで決める。
  vitest側で`aria-pressed`を前提にしている箇所は、実装時に`git grep`で数えて同じ変更で直す。
