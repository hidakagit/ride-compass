# T1015. テストからのみ参照されるexport 72本を、1件ずつ判定して片付ける

状態: 完了（2026-09-23）

## 背景

`frontend/src`のexport 656本のうち、**72本が「実装の他ファイルからは参照されず、
テストからのみ参照される」**（[T1001](T1001.md)の段階Eで、どこからも参照されない87本を
1本へ絞った際に残った分）。

設計原則 構造仕様15は「appは**テストの都合を意識した口を持たない**。テスト専用の関数・
引数をappへ足さない」と定めており、この72本はその候補である。

## 母集団（再現できる形で）

```
frontend/src/**/*.ts(x)（types/generated/ を除く）のトップレベル export 宣言のうち、
宣言したファイル以外の「実装ファイル」に同名識別子が現れず、
「テストファイル」（.test.・__fixtures__・testing/）には現れるもの
```
＝**72本**（2026-09-22、対象 eb8610c7）。構文で分けると値16・道具52・型4。

## **構文で判定してはいけない**（測って分かったこと）

「値をimportしているテストは写経だろう」と見込んで4件を読んだところ、**4件とも
正当だった**。

| 実例 | していること |
|---|---|
| `MOBILE_BREAKPOINT_PX` | `globals.css`の`@media`の値と突き合わせる（別々に持つものの一致） |
| `TILE_KINDS` | 源泉`region-tile-config.json`と突き合わせる（同上） |
| `MAX_GPX_TRACK_POINTS` | `toBeLessThanOrEqual`で上限を超えないことを見る（値ではなく性質） |
| `MIN_SHEET_HEIGHT_VH` | `clampSheetHeightVh(0)`が下限へ丸まるか（境界の振る舞い） |

したがって**1件ずつ読む**。名前・構文・参照数からは判定できない
（CLAUDE.md「機械の出力をそのまま処置へ繋げない」）。

## 判定の基準

| 判定 | 中身 | 処置 |
|---|---|---|
| **守っている** | 別々に持つものの一致を見る／純関数の境界・性質を見る | export を残す。理由を1行書く |
| **口が要らない** | 公開の入口があるのに、途中の手順を直接呼んでいる | テストを入口＋代役（fake/mock）経由へ書き直し、export を閉じる |
| **テスト専用の口** | 本番から呼ばれない、テストのためだけの関数 | 口の**原因**を直す。口だけ塞ぐと別の形で再発する |

## 分かっている1件

`hooks/useAxisCatalog.ts: __resetAxisCatalogStoreForTests` は、構造仕様15が名指しで
禁じる形そのもの。**ただし口が原因ではない**——同モジュールが`sharedCatalog`・
`inFlightCatalogFetch`という**プロセス全体で1つの可変状態**を持つため、テストが
互いの状態を引き継ぐ。口だけ閉じるとテストが落ちる。

直すなら可変の共有状態を無くす側で、3つのテスト（`app/page.test.tsx`・
`RouteSettingsPanel.test.tsx`・`useAxisCatalog.test.ts`）が影響を受ける。

## 完了条件

- 72本すべてが3つの判定のどれかに分類され、**未判定が0**
- 「口が要らない」と判定したものは、テストが入口経由へ書き直され、export が閉じている
- 「守っている」と判定したものは、**なぜ実装が使わないのに公開なのか**が1行書かれている
- 再測定して、テストからのみ参照される export の件数を記録する

## 結果（2026-09-23）

**126 → 8本**（着手時点の再測定は126本。起票時の72本は、当時まだ死んだimportに
参照されていて「実装から使われている」ように見えていたものを含まない数字だった——
`MapView.tsx`の死んだimport48件を落とした時点で、隠れていた分が出てきた）。

### 処置の内訳

| 処置 | 中身 |
|---|---|
| **撤去** | 本番のどこからも呼ばれていなかったもの。`spliceEdgeIds`・`targetStretchEdgeIds`・`spliceEdgeIdsFromAlternatives`（`buildSplicedShape`に置き換えられた側）、`polylineLengthKm`、`tileBoundsLonLat`、`axisLineLayerId`、`dedicatedWayValueOpacityExpression`、`mergeFrameTimes`、`LANDCOVER_TILE_MAX_ZOOM`、jmaTileProtocolの「テスト用」3本 |
| **入口経由へ** | 途中の手順を直接呼んでいたもの。テストを入口＋代役へ書き直して口を閉じた（`escapeHtml`→`labelOrEscapedRaw`、`interpolateColors`→`bandColorsFor`、`isAreaLayerType`ほか→`prepareBasemapForAreaLayers`、`simplifyCoordinates`ほか→`downloadGpx`、`parseJmaTileUrl`→`isKnownEmptyTile`、`generateAxisId`→`emptyDraft` ほか） |
| **源泉へ移す／源泉から読む** | 画面が持っていた値。`SIGNED_MATERIAL_BOUNDARIES`（さらに軸の折れ線からの導出へ）、`DYNAMIC_WEATHER_LAYER_IDS`（backendの`WEATHER_LAYER_GROUPS`の写しだった）、`MOBILE_BREAKPOINT_PX`（CSSの`@media`の写し。CSS側が`--is-mobile`を立て、JSはそれを読む） |
| **構造で解く** | `WIND_DETAIL_MAX_BBOX_SPAN_SIDE_INTERVALS`は`Math.min`で上限を超えられない形にし、見張る検査ごと撤去 |
| **置き場を直す** | `scoreForValue`は`breakpointScore`の別名で、本体に検査が無く別名側にだけあった。本体の側へ移してから閉じた |

### 上限・下限を借りるテストの直し方（横断的に効いた形）

`LOAD_BAR_MAX_HEIGHT_RATIO`・`MIN`/`MAX_AXIS_WEIGHT`・`MAX_GPX_TRACK_POINTS`・
`MIN`/`MAX_SHEET_HEIGHT_VH`は、いずれもテストが**上限の値そのものを借りて**いた。
借りると、上限を変えたときテストも一緒に動いて「頭打ちになる」ことを誰も見なくなる。
**さらに押しても同じ値で張り付くこと**を見る形へ直した（起票時に「正当」と見えていた
`MAX_GPX_TRACK_POINTS`・`MIN_SHEET_HEIGHT_VH`も、この観点では直す対象だった）。

### 残した8本と、その理由

| export | 理由 |
|---|---|
| `MapSceneTarget`・`DataStatusMapLike`・`LayerDataSourceEntry`・`WeatherRenderKind` | **型だけ**。型が変わればコンパイルが先に落ちるので「自分以外の変更で黙って壊れる」性質を持たない。閉じるとテストが同じ形を写すことになる |
| `WEATHER_ELEMENTS` | 契約テストが**母集団として回す**（設計原則 構造仕様12）。名指しへ戻すと、要素が増えても対象にならない |
| `weatherElementRole` | レイヤー・ソースidの綴りを決める唯一の場所。閉じるとテストが`${group}-${source}-${kind}`を書き写す |
| `resolveTileBaseUrl`・`resolveAdminBasicAuth` | docs/conventions/testing.md パターン7そのもの（`pool: "vmThreads"`で`process.env`がテストファイル間で共有されるため、判断を純関数へ出しテストは環境変数に触らない） |

### 起票時の見立てとのずれ

- **件数**: 72 → 実測126（死んだimportに隠れていた分）
- **`__resetAxisCatalogStoreForTests`**: 「口だけ閉じるとテストが落ちる」という見立ては
  当たっていた。導出（応答→カタログ）を`lib/axisCatalog.ts`へ分け、部品のテストは
  共有ストアを持たない代役（`testing/fakeAxisCatalogHook.ts`）を当てる形で解いた
- **「構文で判定してはいけない」**: 正しかったが、**逆向きにも効いた**——「正当」と
  見えた4件のうち3件は、見る角度を変えると直す対象だった（上限の値を借りていた・
  源泉の写しだった）
