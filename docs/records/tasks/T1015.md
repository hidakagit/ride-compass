# T1015. テストからのみ参照されるexport 72本を、1件ずつ判定して片付ける

状態: 未完了（2026-09-22起票）

## 背景

`frontend/src`のexport 656本のうち、**72本が「実装の他ファイルからは参照されず、
テストからのみ参照される」**（[T1001](T1001.md)の段階Eで、どこからも参照されない87本を
1本へ絞った際に残った分）。

設計原則 構造仕様15は「appは**テストの都合を意識した口を持たない**。テスト専用の関数・
引数をappへ足さない」と定めており、この72本はその候補である。

## 母集団（再現できる形で）

```
frontend/src/**/*.ts(x)（types/generated/ を除く）のトップレベル export 宣言のうち、
宣言したファイル以外の「実装ファイル」に同名識別子が現れず、
「テストファイル」（.test.・__fixtures__・testing/）には現れるもの
```
＝**72本**（2026-09-22、対象 eb8610c7）。構文で分けると値16・道具52・型4。

## **構文で判定してはいけない**（測って分かったこと）

「値をimportしているテストは写経だろう」と見込んで4件を読んだところ、**4件とも
正当だった**。

| 実例 | していること |
|---|---|
| `MOBILE_BREAKPOINT_PX` | `globals.css`の`@media`の値と突き合わせる（別々に持つものの一致） |
| `TILE_KINDS` | 源泉`region-tile-config.json`と突き合わせる（同上） |
| `MAX_GPX_TRACK_POINTS` | `toBeLessThanOrEqual`で上限を超えないことを見る（値ではなく性質） |
| `MIN_SHEET_HEIGHT_VH` | `clampSheetHeightVh(0)`が下限へ丸まるか（境界の振る舞い） |

したがって**1件ずつ読む**。名前・構文・参照数からは判定できない
（CLAUDE.md「機械の出力をそのまま処置へ繋げない」）。

## 判定の基準

| 判定 | 中身 | 処置 |
|---|---|---|
| **守っている** | 別々に持つものの一致を見る／純関数の境界・性質を見る | export を残す。理由を1行書く |
| **口が要らない** | 公開の入口があるのに、途中の手順を直接呼んでいる | テストを入口＋代役（fake/mock）経由へ書き直し、export を閉じる |
| **テスト専用の口** | 本番から呼ばれない、テストのためだけの関数 | 口の**原因**を直す。口だけ塞ぐと別の形で再発する |

## 分かっている1件

`hooks/useAxisCatalog.ts: __resetAxisCatalogStoreForTests` は、構造仕様15が名指しで
禁じる形そのもの。**ただし口が原因ではない**——同モジュールが`sharedCatalog`・
`inFlightCatalogFetch`という**プロセス全体で1つの可変状態**を持つため、テストが
互いの状態を引き継ぐ。口だけ閉じるとテストが落ちる。

直すなら可変の共有状態を無くす側で、3つのテスト（`app/page.test.tsx`・
`RouteSettingsPanel.test.tsx`・`useAxisCatalog.test.ts`）が影響を受ける。

## 完了条件

- 72本すべてが3つの判定のどれかに分類され、**未判定が0**
- 「口が要らない」と判定したものは、テストが入口経由へ書き直され、export が閉じている
- 「守っている」と判定したものは、**なぜ実装が使わないのに公開なのか**が1行書かれている
- 再測定して、テストからのみ参照される export の件数を記録する
