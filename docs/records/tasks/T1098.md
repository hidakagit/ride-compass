# T1098. 管理APIの口ごとの「認証なしで401」のテストを、全ルート走査（test_admin_route_authorization.py）へ寄せて消す

状態: 完了（2026-09-25起票、同日完了）

## 背景

T1021群4の担当が、test_axis_admin_routes.py・test_db_status_routes.py・test_derived_data_freshness_routes.pyが口ごとに「認証なしで401」を確かめていて、test_admin_route_authorization.pyの全ルート走査と同じことを見ていると報告した（1本目はT1021の対象だったが起こし直しで残った）。全ルート走査は口が増えたときに自動で対象になるので、口ごとの書き写しは何も足さない。消す前に、全ルート走査がその3つの口を実際に拾っていることを確かめる。規模の根拠: 変わると見込むファイルはテスト3本。起票案 kihyoan-admin-401-test-overlap として2026-09-25承認。

## 実施内容（2026-09-25）

**消す前の確認**: 全ルート走査（`_admin_routes()`）の対象は20口で、依存を持たない口は0。
対象3本のルーター（`axis_admin`・`db_status`・`derived_data_freshness`）と、下の範囲拡大で足した
`debug_admin`・`basemap`・`material_catalog`の`/api/admin/`配下の口は、すべて走査の対象に入っていた
（各ルーターの`router.routes`から`/api/admin/`で始まる口を出し、走査の(メソッド, パス)の集合との差を取って0件）。

**走査に無いもの**: 走査は「依存を持つか」だけを見て、依存が実際に401を返すかは見ていない。
それを見ていたのは`test_debug_admin_routes.py`の3件（資格情報なし＋`WWW-Authenticate`・不一致・
未設定なら何を送っても拒否）だけで、これは`api/admin_auth.py`の責務なので
`test_admin_route_authorization.py`へそのまま移した（testing.md「そのテストは要るか」3問目の「別の
モジュールの責務→移す」）。これで同ファイルが「全口が依存を持つ」と「依存が拒む」の組を持つ。

**範囲**: 対象3本に限らず、`backend/tests`で`status_code == 401`を確かめるテスト（走査のファイルを除く）を
grepで列挙した。14件:

| ファイル | 件数 | 判定 |
|---|---|---|
| test_axis_admin_routes.py | 1（全口のparametrize） | 消す。3問目（走査＋依存の拒否で足りる）。併せて見ていた「サービスが呼ばれない」はFastAPIが依存の解決後に本体を呼ぶことの言い換えで、1問目（フレームワークの結線） |
| test_db_status_routes.py | 1（同） | 消す。3問目 |

| test_basemap_routes.py | 1（口ごと＋キャッシュが残る） | 消す。3問目・1問目（上と同じ） |
| test_debug_admin_routes.py | 4 | 口ごとの1件は消す（3問目）。依存の振る舞いの3件は移す |
| test_material_catalog_routes.py | 4（2口×なし・不一致） | 消す。依存の振る舞いは移した3件と重複、口の保護は走査と重複 |

消したテストのコメント2件（basemapの「全利用者のキャッシュを消すので認可の外に置けない」、
material_catalogの「coverageと同じ理由でadminパスへ置く」）は、理由がどちらも実装のdocstring
（`basemap.py`・`material_catalog.py`）と`docs/modules/backend/`（cross-cutting-infrastructure.md・
evaluation-scoring.md）にあるため、昇格せずに消した。
