# T1073. ユーザーへの確認待ち（判断と操作）を1つのコマンドで記録から出す

状態: 未完了（2026-09-23起票）

## 背景

並行実行で司令塔がユーザーへ出したお願い（確認・承認・実施）が会話にしか無く、ログに流れてユーザーが全部を読み返さないと拾えない。ユーザー指摘（2026-09-23）「ユーザ確認や承認依頼、実施依頼が今はすべてログに流れていて、私が全部読み返さないといけない。それは漏れるので避けたい」「確認が要る操作やコマンドも取りまとめておいて」。規約 docs/conventions/orchestration.md「ユーザーへのお願いは記録に置く」節で、お願いは頼んだその場で該当タスクの記録へ決まった書き方で置くことにした（判断は保留の節と「**ユーザー決定（日付）**:」、操作は見出し「## ユーザー操作（待ち）: …（日付 依頼）」→済んだら「## ユーザー操作（済 日付）: …」）。当日の5件（T1064・T973・T1066×2・T1062）は記録へ移した。

対応方針: 確認待ちの一覧を1つのコマンドにする。python scripts/orchestrate.py asks（と /orchestrate:decisions の置き換え、または /orchestrate:asks）が、origin/master のタスク記録から (1) 未決の判断（decision list と同じ規則）と (2) 見出しが「## ユーザー操作（待ち）」の節（見出し・なぜユーザーか・実行する場所とコマンドの要点）を集め、タスクごとにまとめて出す。閉じたタスク（台帳に行が無い）でも操作待ちが残っていれば出す。状態の表には写さない。

完了条件: 当日の5件の操作待ちと、未決の判断が1回のコマンドで出ること。操作の見出しを「済」へ変えると一覧から消えることを、一時の記録で確かめる。書き方から外れた見出し（例: 「ユーザー操作待ち」）を拾わないこと・拾えないことを明記し、既知の1件で検算する。

## 範囲の追加（2026-09-23、ユーザー指摘）

ユーザー「改善も同じ。改善して標準にするか承認依頼するものも集めておいて。根はすべて同じ、統一して
集めて、1つのコマンドでまとめて出したい」。確認待ちは3種類——**判断**（保留の節と`**ユーザー決定
（日付）**:`）・**実施**（`## ユーザー操作（待ち）: …`）・**改善の承認**（`## 改善提案（承認待ち）: …`）——で、
どれも「ユーザーの手を待っているもの」という同じ根を持つ。1つのコマンド（`orchestrate.py asks`と
`/orchestrate:asks`。既存の`decision list`と`/orchestrate:decisions`はこれに統合し、二重に残さない）が、
origin/masterのタスク記録から3種類を集め、種類ごと・タスクごとにまとめて出す。閉じたタスクの記録に
残った待ちも出す。完了条件に「改善提案の見出しを『承認』へ変えると一覧から消える」を加える。
