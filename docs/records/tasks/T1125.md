# T1125. 地図で押した道の詳細を、見切れず短く読める形にし、評価を利用者がいま設定している重みで出す

状態: 完了（2026-09-25起票・2026-09-26完了）

## 背景

ユーザー報告（2026-09-26、スマホ）: wayの詳細画面が使いにくい。画面上で見切れる。折りたたみをもっと積極的に使ってシンプルにしてほしい。バーが重みと連動していない。調べた結果: ①評価（POST /api/region/axis-inspector）はbackendが既定の重み（region_service.py: RoutePreference()）で計算し、frontendも今の重みを送っていない——重みタブで0にした軸も効いて見える。②詳細はMapLibreのPopupで、開いた後に「この道の評価を見る」で中身が伸びても位置を決め直さない（popup._updateは地図が動いたときだけ）ため上へはみ出す。③地図のタイルから出す事実（道路名・路面・一方通行等）と、backendのタグの行（道路の種類・路面・一方通行等）が同じ項目を二重に出す（スクリーンショットで「道路の種類 primary」が2回）。規模の根拠: backendのルーター・サービスとそのテスト、frontendのRoadInspectorPopup・MapView・regionApi・そのテスト、生成物・設計書で、変わるファイルは8〜10（③20以下）。

## 実施（2026-09-26、T1112のクラウドのセッション）

- 重み: `POST /api/region/axis-inspector`の要求へ`route_preference`（ルート生成と同じ`RoutePreferenceWeights`。公開軸を
  すべて明示・非負）を足し、送られたら合成をその重みで計算する（省略時は既定）。frontendはルート生成へ送るのと同じ
  `routePreferenceToSend`の値を送る（重みを上書きしていない間はnull＝既定。生成と同じ）。取った評価は取ったときの重みと
  組で持ち、重みが変わったら前の評価を見せずに「この道の評価を見る」へ戻す。
- 形: 開いたときは名前と評価だけ。属性（タイルの事実＋評価で届くタグ）は「この道の属性」に畳み、同じ名前の項目は1度だけ
  出す。登録外の生タグはその中でさらに畳む。土地被覆は評価の後に畳んで出す。デバッグ時の way id は最後。
- 見切れ: 中身へ高さの上限（min(22rem, 45vh)）を付けて中でスクロールさせる。器（MapLibreのPopup）は、中身の大きさが
  変わるたびに`setLngLat`で置く向きを決め直す（MapLibreは地図が動いたときにしか決め直さない。`popup.ts: _update`）。
