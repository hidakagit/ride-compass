# T1056. 並行実行のキューをタスク単位にし、手動タスクの前提一覧と優先度をコマンドにする

状態: 完了（2026-09-23）

## 背景

2026-09-23、ユーザー依頼: T1001の前提（残り件数）を出すコマンド・キューの優先度を設定するコマンド・前提をまとめて優先度を上げる組み合わせ。T1049の機械化を1担当に集めて範囲が膨らんだため分割（ユーザー「管理に必須の作業と、依頼を受けての作業を一緒にするとこうなる」）。管理の核（scripts/orchestration/core.py、T1049）の状態の表を読み書きする別モジュールとして作る（依存は本機能→核だけ）。中身: 状態の表のキュー（いまはエージェント単位の文章の配列）をqueue:[{task,agent,priority,state,note}]とmanual:{Txxx:{prereqs}}へ移行（原子的・変換前の写しを残す）、/orchestrate:prereqs Txxx（前提ごとの状態をorigin/masterの記録と突き合わせ、残り0なら開始してよいと出す）、/orchestrate:priority Txxx... 高|中|低 と --prereqs-of Txxx。着手条件: 核がmasterに入ったあと。

振り出し時に司令塔が加えた範囲: 4. 見込み超過をタスク単位で測る（エージェントごとに着手時刻が
1つしかなく、キューの途中のタスクの超過——規模SのT1023に約2時間40分——を検知できなかった。
司令塔の管理の欠陥）。1〜3は依頼による機能として核とは別のモジュール、4は管理に必須として核へ。

## 実施内容

- **核（`scripts/orchestration/core.py`）——4.タスク単位の見込み超過**: 担当の現在のタスク
  （`current_task`）と着手時刻（`task_first_started`）を、振り出し（`board add`の担当キューの先頭、
  `board set ... current_task=Txxx`）で切り替え、報告の受領（`reported=now`）で閉じて`task_log`へ
  実時間・規模札の予算・差を残す。差し戻しで同じタスクを渡し直すと最初の着手時刻を引き継ぐ。
  新しいタスクへ切り替えたとき、規模札を添えなければ前のタスクの予算を持ち越さない（予算未設定と
  知らせる）。見込み超過の文言にタスク番号を出す。
- **核——1.振り出し待ちの前提**: `after`を1件の文字列でも配列でも読む（`prereqs_of_item`・
  `done_tasks`）。`board dispatch list`に「前提: 済／前提待ち: Txxx」、`board dispatch pop`は前提が
  済んだ行だけを優先度の順に取り出す（前提は読むだけの核の関数なので核に置いた）。
- **`scripts/orchestration/queue.py`（核をimportする側）**: 行の正式な項目（`task`・`after`・`agent`
  等）の定義、`queue migrate`（`task`の付与、`manual`の文字列を`{note, prereqs, waiting_decision}`へ、
  自由記述の`t1001_prereqs_remaining`・`t1001_prereqs_waiting_decision`を`manual.T1001`へ。
  変換前の写しを同じディレクトリへ残し、書き込みは核の原子的な置き換え。2回目は変更なし）、
  `prereqs Txxx [--add/--remove]`（前提ごとに 完了／稼働中／判断待ち／振り出し待ち／停止中／未着手、
  残り0なら「開始してよい」。完了は記録の`状態: 完了`かつ台帳に行が無いこと）、
  `priority Txxx... 高|中|低|数`と`--prereqs-of Txxx`（高=4・中=5・低=6。振り出し待ちに無いものは
  そう出して終了コード1）。`after`は既存の核（master）が1件の文字列しか読めないため、移行では
  配列へ変えない。
- 入口`scripts/orchestrate.py`が`queue`・`prereqs`・`priority`を`queue.py`へ振り分ける。
- コマンド`/orchestrate:prereqs`・`/orchestrate:priority`、規約`orchestration.md`（依存の表・状態の表の
  場面・手動タスクの前提・見込み超過の定義）。
