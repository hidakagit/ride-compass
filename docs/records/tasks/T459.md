# T459. car_stress_display_level()がAXIS_DEFINITIONS["car_stress"]を直接ハードコードしている

状態: 完了（2026-08-31）

- 背景: モジュール設計書作成のため`backend/app/domain/axis_definitions.py`を実コードで
  確認したところ、`car_stress_display_level(difficulty)`関数が`AXIS_DEFINITIONS
  ["car_stress"]`という軸idの直接ハードコードで、difficulty(0-100)を旧来の1-5段階表示
  （`RouteSegmentDetail.car_stress`向け）へ逆変換している。
- Impact: `docs/design-principles.md`構造仕様2・3への違反（動的材料
  [T458・DYNAMIC_WAY_VALUE_MATERIALS]と同一カテゴリの違反——軸idの直接ハードコードは、
  対象が動的材料か静的な表示変換かに関わらず一律で違反として扱う、というユーザー方針に
  基づく）。`difficulty`（軸ではなく合成スコア自体という唯一の明文化された例外、
  design-principles.md構造仕様3）とは異なり、car_stressは軸スタジオが管理する軸そのもの
  であり、除外理由に該当しない。
- 対応方針（未検討）: `RouteSegmentDetail.car_stress`という1-5段階の専用フィールド自体を
  廃止し汎用の`axis_difficulties["car_stress"]`（0-100）へ一本化するか、もしくは
  1-5段階への逆変換ロジック自体を軸スタジオのデータ（`display_thresholds_override`等）
  から汎用に導出できる形にするか、着手時に検討する。フロント側でこのレガシーフィールドを
  参照している箇所の洗い出しが前提。
- Confidence: High（`axis_definitions.py`の実コードで直接確認済み）。
- 規模S〜M（フロント参照箇所の調査次第）。

## 実施記録（2026-08-31完了）

フロント参照箇所を調査したところ、`RouteSegmentDetail.car_stress`（1-5生値）は
frontend本番コードのどこからも読まれておらず（テストのモックデータにのみ存在）、
T431が撤去した`RouteCandidate`の旧5フィールドと同じ「末端消費者ゼロ」の状態だった。
そのため対応方針の選択肢1（専用フィールド自体を廃止し汎用`axis_difficulties["car_stress"]`
へ一本化）を採用し、以下を撤去した:

- `domain/route.py`: `RouteSegmentDetail.car_stress`フィールド、`_merge_segment_bin`の
  集約ロジック（未使用になった`import math`も削除）。
- `domain/axis_definitions.py`: `car_stress_display_level()`関数全体（未使用になった
  `import math`も削除）。
- `services/road_graph_engine.py`: `car_stress_display_level`のimport・呼び出し・
  `RouteSegmentDetail`構築時の`car_stress=`引数。
- `services/axis_registry_service.py`: `_CODE_COUPLED_AXIS_IDS`から`"car_stress"`を除去
  （残るのは`gradient`のみ、[T458](T458.md)参照）。
- テスト: `test_axis_definitions.py`（`car_stress_display_level`関連5件削除）・
  `test_route.py`（car_stress集約テスト1件削除）・`test_axis_registry_service.py`
  （`car_stress`を「削除拒否」parametrizeから外し「削除許可」parametrizeへ追加、
  T352汎用化と同型の回帰テストとして扱う）。
- OpenAPI: `export_openapi.py`→`npm run generate:api`を実行し
  `frontend/src/types/generated/`から`car_stress`フィールドが消えたことを確認。
  フロント側のモックデータ3箇所（MapView.segments.test.ts・MapView.bench.ts・
  routeSegmentChartPopup.test.ts）から`car_stress`raw値を削除（`axis_difficulties`内の
  `car_stress`キーは軸自体が存続するため変更なし）。
- docs: `docs/architecture.md`（表示用0-4生値の記述を撤去済みへ更新）・
  `docs/modules/backend/axis-studio.md`（`_CODE_COUPLED_AXIS_IDS`のcar_stress該当を削除）を
  同期。
