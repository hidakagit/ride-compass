# T695. 一次属性の手書き対応表を整理する（略名表は本番の消費者ゼロ） 規模S

状態: 完了（2026-09-10起票、統合レビュー第6回。[T694](T694.md)の後。2026-09-10完了）

## 背景

一次属性を1つ増やすと`frontend/src/components/Map/primaryAttributes.ts`の手書き対応表への
追記が必須になる。[T691](T691.md)/[T692](T692.md)はこれを踏まずにpushされ、CIが赤になった。

消費者をリポジトリ全体でgrepした結果:

| 表 | 本番の消費者 | 判定 |
|---|---|---|
| `PRIMARY_ATTRIBUTES`（`:31`） | 生成物`axis-catalog.json: primary_attributes[]`から片側import | 手書きではない |
| `PRIMARY_ATTRIBUTE_LABELS`（`:36`） | `axisInspectorPopup.ts:11` | 生成物から導出。手書きではない |
| `PRIMARY_ATTRIBUTE_CHIP_LABELS`（`:44`） | **ゼロ**（参照は自身のテストと`secondaryAxes.ts:36`のコメントのみ） | **死んでいる** |
| `PRIMARY_ATTRIBUTE_LAYER_IDS`（`:70`） | `primaryAttributeIdsToLayerIds`経由で`page.tsx:39` | 生きている |
| `PRIMARY_ATTRIBUTES_WITHOUT_LAYER`（`:93`） | テストのみ | **設計どおり** |

`PRIMARY_ATTRIBUTE_CHIP_LABELS`のdocstringは「材料一覧表示で薄字ラベルとして使うため
全一次属性ぶんを持つ」と述べるが、その消費者は存在しない——**表の存在理由がdocstringの中にしか無い**
状態で、一次属性を足すたびに「4文字以下・一意」という制約付きの更新をCIが強制している。

## 対応方針

1. `PRIMARY_ATTRIBUTE_CHIP_LABELS`と対応するテスト（`primaryAttributes.test.ts:17-29`）を**削除する**。
2. 残る`PRIMARY_ATTRIBUTE_LAYER_IDS`/`PRIMARY_ATTRIBUTES_WITHOUT_LAYER`は**維持する**。
   値域`MapLayerId`は`mapLayers.ts:36-75`で定義されるフロント固有の概念で、backendは
   自分のレイヤーIDを知らないため生成物からは導出できない。
   `PRIMARY_ATTRIBUTES_WITHOUT_LAYER`がテスト専用なのは「キーが無い＝漏れ」と
   「意図的にレイヤー無し」を区別する明示集合という設計意図どおり。

## 検討して棄却した案

「軸と同じように略名をbackendの一次属性カタログ（`domain/registry_defaults.py`）へ移して
片側importにする」——消費者がゼロである以上、**負債を保存したうえで移設コストも払う**選択になる
（判断原則9「将来のための過剰設計を避ける」）。

## 実装メモ

対応方針どおり`PRIMARY_ATTRIBUTE_CHIP_LABELS`（19件の手書き対訳表）と、それを検証する
2つのテスト（略名の存在・略名の一意性）を削除した。併せて:

- `primaryAttributes.ts`冒頭の責務説明から「地図チップの略名」を外した
  （このファイルが独自に持つのは表示レイヤーIDの対応だけになった）。
- `secondaryAxes.ts`の`primaryAttributeIds`のdocstringが名前空間の説明として
  この表を挙げていたため、実在する`PRIMARY_ATTRIBUTE_LAYER_IDS`だけの記述にした。

`mapLayers.ts`・`axisLayers.ts`が持つ「地図チップの略名」は**評価軸**のchip_label
（`CatalogAxis.chip_label`由来、実際に描画されている）で別物のため触っていない。

一次属性を1件足したときに更新が必要な手書き表は、
`PRIMARY_ATTRIBUTE_LAYER_IDS`か`PRIMARY_ATTRIBUTES_WITHOUT_LAYER`のどちらか1箇所だけになった。
