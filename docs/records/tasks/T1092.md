# T1092. ルートの割増の強さ（P）の既定と、軸ごとの寄与度の計算を、それぞれ1つにする（地点確認のAPIもルート生成と同じPで探す）

状態: 未完了（2026-09-24起票）

## 背景

背景（T965 段階Bの点検で見つけた崩れ2件）:
1. T805・T817は「好みの割増を時間へ換算する強さ（P）の既定は較正値1つ（今0.7）」とした。段階Aで計算関数の引数の既定1.0は外したが、エンジン（RoadGraphEngine.__init__）にも既定1.0が残っている。ルート生成は必ず較正値を渡すので影響しないが、地点確認のAPI（POST /api/routes/preview、get_preview_builder）はPを渡さないため、P=1.0で探している。docstringは「生成と同じ評価を使う」と書いているが食い違う。ベンチも1.0で測っている。frontendからこのAPIを呼ぶ箇所は0件。
2. T550は「軸ごとの寄与度はbackendで1回だけ計算する」とした。今は、全区間ぶんを作る配列版（compose_costs_from_axis_matrix の with_contributions の枝と AxisComposition.contributions）と、1区間ぶんを作る版（axis_contributions_at_row）の2つがある。本番で使うのは後者だけで、配列版を読む箇所は0件（唯一の本番の呼び出しは with_contributions=False を渡す）。

直し方: 1はエンジンの既定を外し、previewとベンチで resolve_penalty_strength(None) を渡す。2は with_contributions 引数・配列版の枝・contributions フィールドを消す。どちらもテストの偽物・組み立て（test_road_graph_engine.py の fake_compose_costs と make_engine）の引数を直す必要がある。

振る舞いの差: 1は /api/routes/preview の探索がP=1.0から較正値（今0.7）へ変わる（利用者の画面からは呼ばれていない）。2は変わらない。

なぜ既存のタスクに入らないか: T805・T817・T550は完了済み。T965では backend/tests を触らない決まり（T1021が作り直し中）のため、テストの直しを伴うこの2件は切り出した。test_road_graph_engine.py はT1021の対象24ファイルの外。
