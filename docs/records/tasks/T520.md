# T520: nowcグループ（targetTimes_N3.json）の未使用element調査（liden・slmcs系）

状態: 調査完了（2026-09-02、Browserペインでjma.go.jp本体へ直接アクセスし技術仕様を確定。
実装要否はプロダクト判断待ちのため未着手のまま残す）

## 背景

T514/T510フォローアップの雷・竜巻ナウキャストのbasetime選択バグ調査中、
`bosai/jmatile/data/nowc/targetTimes_N3.json`の各エントリの`elements`配列に、
RideCompassが現在使っていない要素が含まれることが分かった。

- `liden`: 雷放電位置データ（実際の落雷地点そのものを点として示すデータ。現在の
  `thns`は活動度をエリア単位のラスタタイルで示すのみで、個々の地点は扱っていない）
- `amds_rain10m`: アメダス10分雨量（`jma_amedas_service.py`経由の既存アメダス実況と
  重複する可能性が高い、要確認）
- `slmcs`/`slmcs_fcst`/`slmcs_unify`/`slmcs_unifyfcst`: Web検索で「線状降水帯直前予測の
  運用開始について」（気象庁、2026年3月の報道発表）がヒットした。既存の「線状降水帯
  予測マップ」（`sjfcstmap`、rasrfグループ、T410）とは別物で、より切迫したタイミングの
  予測を扱う可能性がある。

**確証度が低い（起票時点）**: 上記はWeb検索結果からの推測であり、`jma.go.jp`公式ページへ
直接アクセスして確認できていない（調査時点でサンドボックスから同ドメインへの
アクセスがブロックされていた）。着手前に気象庁公式のドキュメント・報道発表で
正確な仕様（更新頻度・提供形式・利用条件）を確認すること。

## 追加調査結果（2026-09-01、WebSearch経由。`jma.go.jp`本体への直接WebFetchは
依然EGRESS_BLOCKEDで不可、検索結果スニペット・第三者記事からの間接確認に留まる）

- **`liden`（確証度: 中）**: 気象庁公式ページ「雷監視システムによる観測」がヒットし、
  LIDEN（LIghtning DEtection Network system、全国30箇所の検知局＋中央処理局）による
  雷放電の緯度経度・発生時刻の標定システムと確認できた
  （[雷監視システムによる観測 | 気象庁](https://www.jma.go.jp/jma/kishou/know/kouku/2_kannsoku/25_liden/25_liden.html)、
  本文への直接WebFetchはブロックされたためタイトル・要約のみ）。検索結果には配信URLの
  形も見つかった: 時刻一覧は既存で使っている`targetTimes_N3.json`と共通、個々の観測は
  `https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/liden/data.geojson?id=liden`
  という**GeoJSON**（`thns`/`trns`のようなラスタタイルではなく点データ）で提供される
  との記述があった（出典: 検索結果スニペット、一次ページ本文は未直接確認）。事実なら
  現行の`JmaTileClient`（z/x/yのラスタタイルパスを前提にした設計）をそのまま流用できず、
  別経路のfetch・別のレンダリング方式（MapLibreの点マーカー等、既存の面塗り/ラスタタイル
  系レイヤーとは異質）が必要になる。
- **`amds_rain10m`（確証度: 中、既存機能との重複を裏付け）**: 気象庁「統合地図ページ」の
  URL（`elem=precipitation10m&contents=amedas&interval=10`）がヒットし、アメダス
  10分雨量は同ページの「アメダス」レイヤー（点データ）の一部と確認できた
  （[気象庁｜統合地図ページ](https://www.jma.go.jp/bosai/map.html#9/42.946/142.828/&elem=precipitation10m&contents=amedas&interval=10)）。
  RideCompassは既に`jma_amedas_service.py`経由でアメダス実況（降水量含む）を独自に
  取得済みであり、起票時点の「重複する可能性が高い」という推測を裏付ける方向の結果。
  新規導入の動機が薄い。
- **`slmcs`系（確証度: 中、機能の実在は確認。配信形式は未確認）**: 気象庁の報道発表
  （[20260310 SLMCS](https://www.jma.go.jp/jma/press/2603/10b/20260310_SLMCS.html)、
  本文は直接WebFetch不可のためタイトルのみ確認、第三者記事
  [気象庁「線状降水帯直前予測」の使い方完全ガイド](https://vegcale.com/2026/05/19/jma-senjo-kousuitai-chokuzen-yosoku-guide/)
  経由で要約を取得）により、「線状降水帯直前予測」が2026年5月に正式運用開始したことを
  確認。発生2〜3時間前を目標に、都道府県内の主要な地域区分（例:「◯◯県北部」）単位で
  通知、適中率は目安50%程度、既存の警報・注意報を補完する「防災気象情報（線状降水帯
  直前予測）」という位置づけ。**この粒度感（県内地域区分単位のテキスト警報）は、
  ラスタタイル(thns/trns型)よりも既存の気象警報・注意報バッジ（T205実装済み、
  `WarningBadge.tsx`）の配信形態に近い可能性が高いが、タイル/GeoJSON/テキストAPIの
  いずれで配信されるかという技術仕様までは確認できていない**（jmamap等の非公式ライブラリ
  ソースを検索したが、slmcs/lidenへの言及は見つからなかった——T521調査時のように既存の
  非公式実装で裏取りする手段は今回使えない）。

## 技術仕様の確定（2026-09-02、Browserペインでjma.go.jp本体・実配信データへ直接アクセス）

これまでWebFetch/WebSearch経由ではjma.go.jp本体がEGRESS_BLOCKEDで確認できなかったが、
Browserペイン（実ブラウザ）経由では通常にアクセスでき、公式ページ本文・実際の
配信JSON/GeoJSONを直接取得できた。3要素それぞれ着手判断に足る確証度に到達した。

- **`amds_rain10m`（結論: 導入不要、確定）**: 気象庁「統合地図ページ」のアメダス
  10分雨量レイヤーの一部（[前回セッションで確認済み](https://www.jma.go.jp/bosai/map.html#9/42.946/142.828/&elem=precipitation10m&contents=amedas&interval=10)）。
  今回`backend/app/services/jma_amedas_service.py`を確認したところ、`precipitation_10min_mm`
  フィールド（アメダス応答の`precipitation10m`を変換）を既に取得・保持しており、
  **コードレベルで重複を確認**（3〜137〜229行目）。新規導入の動機なし。
- **`liden`（結論: 技術仕様確定、実装要否はプロダクト判断）**: 気象庁公式ページ
  「[雷監視システムによる観測](https://www.jma.go.jp/jma/kishou/know/kouku/2_kannsoku/25_liden/25_liden.html)」
  （全国30空港の検知局＋中央処理局によるLIDEN=LIghtning DEtection Network system、
  雲放電・対地放電の発生位置を電磁波受信で標定）を本文まで確認。配信URLと実データを
  直接取得し形式を確定した:
  `https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/liden/data.geojson?id=liden`
  → **GeoJSON `FeatureCollection`、`geometry.type=Point`**（緯度経度）、
  `properties`は`id`（例: `nowc_{basetime}_{validtime}_liden_0`）・`obstimeJST`
  （観測時刻、ミリ秒精度）・`type`（数値、実データで0/1/4を観測——雲放電/対地放電等の
  種別と推測されるが対応表は未確認）。現行`JmaTileClient`はz/x/yのラスタタイル
  （`thns`/`trns`等）専用設計のため、`liden`を導入する場合はこれとは別の
  fetch経路・別のレンダリング（MapLibreの点マーカー等）が必要になる（起票時点の
  見立てのとおり）。導入の要否（既存の`thns`エリア表示に対し、個々の落雷地点まで
  出す価値があるか）はプロダクト判断。
- **`slmcs`系（結論: 技術仕様確定、既存sjfcstmapとの関係も判明、実装要否はプロダクト
  判断）**: 気象庁公式ページ「[線状降水帯に関する情報](https://www.jma.go.jp/jma/kishou/know/bosai/kishojoho_senjoukousuitai.html)」
  を本文まで確認。線状降水帯には「半日前予測」「直前予測」「発生情報」（いずれも
  府県・地方単位のテキスト速報、既存の`WarningBadge.tsx`と同種の配信形態）と、
  地図に領域を示す「線状降水帯予測マップ」の計4情報があると判明。このうち
  地図表示系を2つ確認した:
  - `sjfcstmap`（**既存実装、T410で対応済み**）: `rasrf`グループ
    （`/bosai/jmatile/data/rasrf/...`、z/x/yラスタタイル）から配信。3時間先までの
    20km格子予測を赤色表示（適中率10%程度・捕捉率ほぼ100%の「見逃さない」設計）。
    実際にPlaywrightで`https://www.jma.go.jp/bosai/kaikotan/#elements:sjfcstmap`
    を開き、ネットワークリクエストで配信元グループを直接確認した。
  - `slmcs`/`slmcs_fcst`/`slmcs_unify`/`slmcs_unifyfcst`（**nowcグループの別レイヤー、
    未実装**）: JMA公式の「雨雲の動き」ナウキャストページ（`/bosai/nowc/`）内の
    「線状降水帯予測マップ」ボタンが`#elements:slmcs&slmcs_fcst&sjfcstmap`という
    3要素セットへリンクしており、**sjfcstmapを補完する形でnowcグループ側にも
    同名の機能がある**と判明。実際にこのURLを開いてネットワークリクエストを
    確認したところ、UIが実際にfetchするのは`slmcs_unify`・`slmcs_unifyfcst`
    （素の`slmcs`/`slmcs_fcst`ではなく統合版）で、配信形式は
    `https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/{element}/data.geojson?id={element}`
    という**GeoJSON**（liden同様、ラスタタイルではない）。取得時点で線状降水帯が
    発生していなかったため中身は`{"type":"FeatureCollection","features":[]}`と空で、
    実際のgeometry種別（公式説明の「赤い楕円」がPolygon近似かLineStringかは）は
    未検証のまま。公式ページの「発生情報を補足する『線状降水帯の雨域』の表示」
    説明（`liden`調査ページと同じ`kishojoho_senjoukousuitai.html`より）によれば、
    「雨雲の動き」「今後の雨」上に赤い楕円（発生情報に連動、実況は実線・
    10〜30分先予測は破線）として重ねる機能。sjfcstmapが3時間先までの粗い20km格子
    見逃し防止表示であるのに対し、slmcs系はより即時的（nowcastの5分刻み更新に
    同期）かつ高精度な線状降水帯領域そのものの表示という位置づけと考えられる。
    導入の要否（sjfcstmapで足りるか、より即時的な領域表示を追加する価値があるか）は
    プロダクト判断。

## 対応方針

3要素とも配信形式・既存機能との関係は確定した。実装するかどうかは技術的な障壁の
問題ではなくプロダクト判断（`amds_rain10m`は明確に不要、`liden`・`slmcs`系は
「既存表示で足りるか、追加の価値があるか」という判断）のため、本タスクとしては
ここで一旦クローズし、着手する場合は個別に新規タスクとして起票する。
