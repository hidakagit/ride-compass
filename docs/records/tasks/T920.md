# T920: レンズ凡例の段階ごと表示ON/OFFを、ルート確定前の全道路の塗りにも効かせる

状態: 完了（2026-09-17起票・同日完了）

## 背景

レンズの凡例に付くチェックボックス（段階ごとの表示ON/OFF）はルート確定後のルート線に
しか効かない。ルート確定前の全道路の塗りは専用way値レイヤー（feature-state経由）で、
MapLibreの`filter`がfeature-stateを読めないため同じ機構を流用できない。
利用者は「極端な上り下りだけを見たい・ほぼ平坦な道を消したい」という絞り込みを
ルート確定前にこそ必要としている。

## 対応方針

- **絞り込みの手段はレンズの種類ごとに違い、状態の持ち方は1つ**にする。非表示キーの保存先は
  既存の`page.tsx: hiddenLegendKeysByMode[軸id]`のまま（地図上チップの▶パネル・
  「絞り込みをすべて解除する」と同じ場所）で、効かせ方だけが分かれる。
  - 専用way値配信軸（ルート前）: 色式で該当段階を`COLOR_HIDDEN`（透明）にする。
  - ramp軸（ルート前）: 既存の`staticFilterAxes`経由のfilterがそのまま効く（配線不要）。
  - ルート線（ルート後）: 既存の`hiddenRouteLegendKeys`。
- **段階キーを1箇所へ**（`mapColorLegend.ts: legendBandKey`/`LEGEND_NO_DATA_KEY`）。
  専用way値配信軸はルート前後で同じ`map_value_thresholds`・同じ並びの段階を塗るため、
  同じキーにしておくとルート生成をまたいで絞り込みが引き継がれる。
- MapViewへ渡すのは`dedicatedWayValueHiddenBands`（axisId→非表示キーの汎用Map）1つ。
  `dedicatedWayValueLoading`と同型で、軸ごとのpropを新設しない
  （design-principles.md構造仕様3）。

## 実装メモ

- `MapColorLegendBand`が`key`・`isFallback`を持つようになり、ルート前の凡例にも
  「データなし」段階が並ぶ（ルート後の凡例と段階の並び・キーが揃う）。
- `LensControl`の`hiddenLegendKeys`/`onToggleLegendKey`は必須propにした。ルート確定前だけ
  読み取り専用の凡例へ落ちる分岐（`undefined`を渡す経路）を消したため、ルート前に
  絞り込みを外す変更を入れると型エラーになる。
- フェッチ進行中の色（`COLOR_LOADING`）は「データなし」を非表示にしても残す。消すと
  「まだ来ていない」と「隠した」が地図上で区別できなくなる。

## 凡例が縦に伸びる問題（省スペース化）

段階の細かい軸ではポップオーバーが縦に伸び、地図・下部シートを覆う。次の2つで畳んだ。

- 軸の一覧・凡例をどちらも`repeat(auto-fill, minmax(9rem, 1fr))`のグリッドにして列へ流す
  （幅は18rem→24rem）。段階数は軸スタジオのしきい値の個数で決まるため、列数を固定しない。
- 凡例の見出し自体をチェックボックスにして「全段階の表示/非表示」を兼ねさせる
  （`MapOverlayControls`の▶パネルと同じ、ボタン行を足さずに一括操作を持たせる形）。
  「極端な上りだけ見たい」を1段階ずつ外させないため。

## 検証結果

- ローカル（`next dev`、しきい値を仮投入したフォールバックカタログ）でポップオーバーを
  実測: 1%刻み14段階＋データなしで384×539px（1列のままなら約900pxで`max-height: 70vh`を
  超える）。
- `npx vitest run`（フロントエンド全体）1441件パス、`npx eslint src`・`npx tsc --noEmit`
  ともに新規の指摘なし。
- わざと壊して検知できることを確認: `buildSteppedColorExpression`から非表示段階の透明化を
  外し、符号付き材料の配色を2色補間へ戻すと、新規テストを含む8件が落ちる
  （`valueScale.test.ts`4件・`dedicatedWayValueLayer.test.ts`3件・
  `MapView.layerOps.test.ts`1件）。

## 台帳にあった補足

- 2026-09-17完了。feature-state経由の値はMapLibreのfilterから読めないため、線を間引くのではなく該当段階の色を透明にする。段階キーをルート前後で共通にし、ルート生成をまたいでも同じ段階が隠れたままになる
