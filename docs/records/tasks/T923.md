# T923: 確定した軸定義を差分付きで開発DB・本番DBへ配るスクリプトを作る

状態: 見送り（2026-09-17起票・同日クローズ）

## 背景

軸定義の変更経路の分担
（[decisions/axis-definition-maintenance-split.md](../decisions/axis-definition-maintenance-split.md)）
のうち、「決めたものを配る」側の手段が無い。今はcurlを手で組み立てるしかなく、
何を変えたかがリポジトリに残らず、開発DB・本番DB・スナップショットの同期も人の記憶頼みになる。

## 見送りの理由（2026-09-17）

**本番の軸スタジオで変更すれば、その時点で本番DBが更新される。** 追加の配布手段は要らない。
開発DBは検証用に分かれており、本番と内容を揃える対象ではないため、環境間で内容を転送する
仕組み（DB間コピー・ファイルを正本にした適用）はどちらも不要だと判断した——正本のDBに
対して第2の入力経路を増やすだけになる。

`deployment-sync.md`が記録している反映漏れは「開発DBだけ直して本番を忘れた」ことであり、
本番のGUIで直接変える運用ならその隙間自体が生まれない。fresh bootstrap用スナップショットの
再ダンプだけが残るが、これは既存スクリプト1本で足りる。

分担の決定は[decisions/axis-definition-maintenance-split.md](../decisions/axis-definition-maintenance-split.md)。

## 台帳にあった補足

- 2026-09-17見送り。本番の軸スタジオで変えればその時点で本番DBが更新され、開発DBは検証用の別物で揃える対象ではないため、環境間の転送手段そのものが要らない
