# T518: ルート結果パネルの再構成（「ルート選択」への統合＋重み反映＋表示トグル修正）

状態: 完了（2026-09-01）

- 背景: ユーザーから連続する指摘。「生成したルートの色分け」「凡例の表示設定」が
  ルート結果パネルの全タブ（ルート選択/全体プロファイル/比較）に重複表示され続ける、
  色分け対象の選択肢がルート設定パネルと連動せずパネルを跨ぐ操作になる、UIが
  RouteSettingsPanelの凡例チップパターンと揃っていない、全体プロファイルの軸別内訳が
  重み（route_preference）を無視した絶対値のため総合スコアとの見た目の整合が取れない、
  等。Plan Modeでのモックアップのやり取りを経て、「全体プロファイル」タブ自体を廃止し
  「ルート選択」タブへ統合する方向へ発展した（詳細はPlan承認済みの設計を参照）。
- 対応方針の要点: (1) タブを「ルート選択」「比較」の2つへ統合、(2) 総合難易度を内訳の
  合計として分離し「おすすめ度」と並記、(3) 軸別内訳バーを距離×重みの寄与度で表示、
  (4) RouteSettingsPanelの凡例チップパターンを流用、(5) 比較タブもOFF軸を除外、
  (6) 地図上「ルート」チップの重複解消・完全非表示への修正。
- 詳細な設計判断・検証結果は実装完了後にこのファイルへ追記する。

## 実装内容（2026-09-01完了）

- `RouteAxisProfile.tsx`: 「ルート選択」タブ内、選択中候補の直後へ「地図の色分け」
  （`RouteSettingsPanel.module.css`の`legendChip`パターンを流用したチップ列）・
  「合計」（おすすめ度＋総合難易度の並記、総合難易度は内訳の1項目ではなく別枠）・
  「内訳（重み付き寄与度）」（`domain/difficulty.py: composite_difficulty`と同じ考え方で
  軸の重みを反映した寄与度をバー長に、生のdifficulty値をバー色に使う）・凡例の表示設定
  （`stackBarLegendTrigger`パターン）を統合。
- `page.tsx`: `Tabs.Trigger value="profile"`とその`Tabs.Content`を削除しタブを
  「ルート選択」「比較」の2つへ。`renderRouteColorSectionBody`（旧・独立ブロック）を削除。
  `ComparisonPanel`へ渡す`axes`をルート設定の重み>0の軸のみへ絞り込み、`RouteAxisProfile`
  と表示ルールを統一。
- `MapView.tsx`: 「ルート」チップ（`layerVisibility.route`）OFF時に、候補線
  （`drawBaseRoutes`）・選択中候補のハロー・方向矢印（`drawSelectedOutline`）も
  含めた3レイヤーグループすべてを非表示にするよう修正（従来は色分けレイヤー
  `route-detail-segments-line`のみが対象で、候補線・ハローは常時表示のままという
  不整合があった）。
- **実機確認中に発見・修正した実バグ**: 内訳の軸チップは、`routeStyleModes`
  （軸カタログの`supports_route_coloring`フラグから動的生成）に対応するモードが
  無い軸（車の圧迫感・事故密度・自転車インフラ・停止密度・夜間、いずれも
  `is_published: true`だが地図色分けには未対応）をクリックしても、page.tsx側の
  フォールバックeffectが選択を即座に巻き戻すため無反応に見えるバグがあった。
  対応するモードが無い軸は非活性表示（クリック不可）にする修正を行い、専用テストを追加。
  これらの軸自体は内訳リストから削除していない（ユーザー判断: 公開軸で重みが
  設定されていれば残す）。
