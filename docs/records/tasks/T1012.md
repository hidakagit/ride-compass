# T1012. 補正後の手順で、外部クライアント6本のテストを起こし直す

状態: 完了（2026-09-23）

## 背景

[T998](T998.md)の段階1やり直しで、外部APIクライアント6本のテストを「起こし直した」が、
手順を守っていなかった。起こし直しは「要るものだけ書く」から減るはずのところ、
段階1全体で+18%に膨らんだ。その後（[85d59304](../../../)）さらに編集を重ねている。

同じファイル群を、補正後の手順で**もう一度、ファイルごと置き換える**必要がある。

対象（`backend/app/infrastructure/`）:

- `simple_api_client.py`
- `jma_warning_client.py`
- `wbgt_client.py`
- `gsi_tile_client.py`
- `basemap_client.py`
- `jma_tile_client.py`

## 何を守るか

`docs/conventions/testing.md`の「既存テストを直さず、実装から起こし直す」。
T998で分かった、守れていなかった点は次のとおり。**ここを外すと同じ結果になる。**

- **既存のテストファイルを開かずに書き始める。** 旧版を開いてよいのは手順4以降で、
  目的は「今のソースからは導けない過去の事情」（回帰・実データ由来）だけ。
  構造を写すために開かない
- **旧版を物差しにしない。** diffしない／「落とした」と言わない／旧版にあったからという
  理由で足さない／一致率で出来を語らない
- **対象ファイル以外の実装を読まない。** 他モジュールの型・例外・定数はテストへ直接
  importせず、対象モジュールの名前空間経由で触る
- **列挙の母集団を機械で導いて件数を書く。**「実装を全部読んだ」は列挙ではない
- **分岐カバレッジは検出器であって母集団ではない。** 未到達を埋める前に3問を通し、
  埋めなかったものは理由を1行ずつ残す

## 完了の条件

1. 6ファイルそれぞれについて、テストファイルを**新規に置き換えた**こと
   （部分編集でないこと）
2. 列挙の母集団と件数が、コミットメッセージに書かれていること
3. 行カバレッジと分岐カバレッジが、前後の値つきで書かれていること
4. 埋めなかった未到達について、理由が1行ずつ残っていること
5. 手順4で旧版から取り込んだものがあれば、4分類のどれかと理由が書かれていること

## 測り方

- 母集団の導出: 対象ファイルをASTで数える（数え方は着手時点の
  `docs/conventions/testing.md`に従う）
- カバレッジ: `pytest tests/test_<名前>.py -q -m "not postgis"
  --cov=app.infrastructure.<名前> --cov-branch --cov-report=term-missing`
  （モジュール指定はドット記法。パス記法は無報告になる）
- 前の値は、置き換える前の版を**実行して**取る

それ以上かかっている）

## 結果（2026-09-23）

汚染されていない2つのセッションが、既存テストを開かずに実装だけを読んで書いた。
群Aは`cached_fetch`を共有する3本、群Bはタイル配信の3本。完了条件の5項目は
コミット a18a0e72 のメッセージにある（列挙の母集団と件数・カバレッジ前後・
埋めなかった未到達の理由・4分類）。

  テスト 70件 → 75件、行 900 → 1,120（+24%）
  行カバレッジ 291/295 → 295/295、分岐 43/46 → 46/46

**「起こし直すと減る」は成り立たなかった。** [T998](T998.md)で同じ前提が誤りと
判明しており、これで3件目である。増分の大半は`jma_tile_client`（185→364行）で、
「`app.*`の直接importは対象1本だけ」の制約に従い、共有キャッシュとログの差し替えを
対象モジュールの名前空間で行うフェイクを自前で持つため。

得られたのは小ささではなく、**依存の切り方**（他モジュールの型が撤去されても
道連れにならない）と**欠陥の検出**である。

## 欠陥の判定

報告9件のうち2件は事実確認で誤検知だった（暑さ指数の予測キャッシュが検索範囲を鍵に
含まない件は、範囲が毎秒動くため鍵へ入れるとキャッシュが一度も効かない。地理院タイルの
404記憶がプロセス寿命な件は、docstringが対比しているのが永続ファイルの側）。

当てた2件は 71c7ad39。残りの判定:

| 件 | 判定 |
|---|---|
| 地域マスタの取得に形の検査が無く、上流が形を変えると要求ごと失敗する | **見送り**（古い警報が出るより止まる方がよい） |
| 取得失敗の「なし」と該当なしの「なし」を区別できない | **見送り**（モジュールdocstringに明記の既知トレードオフ） |
| 地点マスタの読み飛ばしが黙っている | [T1019](T1019.md)へ |
| 上流への秒間上限が単一プロセス前提 | [T1020](T1020.md)へ |
