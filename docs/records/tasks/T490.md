# T490. MapView.tsxの並列トラック分離・二次軸下敷き・setStyle後再適用ガードをexportして単体テスト化する

状態: 完了（2026-08-31）

- 背景: ユーザー依頼のテスト有効性・カバレッジ監査（2026-08-31）で、`frontend/src/
  components/Map/MapView.tsx`（756文）の行カバレッジが18.8%しかなく、frontend全体の
  未カバー分（762文）のうち614文（約8割）がこの1ファイルに集中していることが実測
  （`@vitest/coverage-v8`導入）で判明した。既存の`MapView.*.test.ts`群（dataStatus/
  overlayFilters/routes/segments）はそれぞれ狭い範囲しかカバーしておらず、以下の
  `docs/modules/frontend/static-map-layers.md`・`map-axis-coloring.md`が「暗黙の前提」
  として明記する重要ロジックが`export`されておらずテスト対象から漏れている
  （担当エージェント調査で確認済み）:
  - `applyRoadMaterialTrackOffsets`（`MapView.tsx:1377`付近）: 並列トラック分離の
    オフセット計算（1件→0、2件→±1.5、3件→-3/0/+3）
  - `applySecondaryAxisCasingStyles`（`MapView.tsx:1629`付近）: 二次軸の下敷き表現
    （材料が同時表示のときだけ太く半透明にする条件分岐）
  - `clearRoadTileFeatureState`（`MapView.tsx:1263`付近）とそれを呼ぶ「風・勾配が
    両方OFFになるまで待つガード」
  - `redrawAllLayers`内での`applyAxisFeatureStateValues`明示的再呼び出し
    （`map.setStyle()`後に評価軸レイヤーが無色のまま残る事故を防ぐ設計書記載の前提）
- 対応方針: 既に`MapView.overlayFilters.test.ts`が使う`fakeMap()`パターン（MapLibre
  `Map`インスタンスの必要メソッドだけを持つフェイク）を流用し、上記関数を`export`した
  上で単体テストを追加する。`export`自体は内部実装の可視化のみで、呼び出し元・挙動は
  変更しない。既存テストファイル（`MapView.dataStatus.test.ts`等）への追加、または
  新規`MapView.layerOps.test.ts`のような専用ファイル新設は実装時に判断する。
- 規模: M

## 実施内容（2026-08-31完了）

新規`frontend/src/components/Map/MapView.layerOps.test.ts`（13件）を追加し、
`MapView.overlayFilters.test.ts`と同じ「実際のMapLibre Mapが必要とするメソッドだけを
持つフェイク」パターンを流用した。`export`のみを行い呼び出し元・挙動は変更していない
（`GRADIENT_FILL_LAYER_ID`/`buildInteractiveLayerIds`の前例[改善計画T478]と同じ方針）。

- `applyRoadMaterialTrackOffsets`・`applySecondaryAxisCasingStyles`・
  `clearRoadTileFeatureState`・`applyAxisFeatureStateValues`を`export`。
  併せて`ROAD_TILE_SOURCE_ID`・`ROAD_TILE_LAYER_ID`・`TUNNEL_LAYER_ID`・
  `ONEWAY_LAYER_ID`・`ROAD_MATERIAL_TRACK_LAYER_IDS`・`MATERIAL_TRACK_OFFSET_STEP`・
  `SECONDARY_AXIS_CASING_WIDTH`・`SECONDARY_AXIS_CASING_OPACITY`・
  `DEFAULT_ROAD_LINE_WIDTH`もテスト用に`export`した。
- 「風・勾配が両方OFFになるまで待つガード」（元は`useEffect`内のif文にインライン化
  されていた）を`shouldClearDedicatedWayValueFeatureState(showWindAxis,
  showGradientAxis): boolean`という純粋関数として切り出し、単体テスト化した
  （effect自体はこの関数を呼ぶだけの形へ書き換え、判定ロジックは変更なし）。
- **`redrawAllLayers`内での`applyAxisFeatureStateValues`明示的再呼び出し自体は
  未着手のまま**: `redrawAllLayers`は`redrawPropsRef`・`mapRef`等コンポーネント内部の
  多数のrefに依存する`useCallback`で、単体テスト化には引数として外部化する大掛かりな
  リファクタが必要（「関数をexportする」という他3件と同じ軽量な対応では済まない）。
  代わりに`applyAxisFeatureStateValues`自体（この再呼び出しが実際に何をするかという
  核心ロジック）を直接export・単体テストし、`redrawAllLayers`がこれを無条件に呼ぶという
  配線自体はコードレビュー・目視確認の対象として残した（実施しなかった理由を明記）。
