# T883. 同じ名前をモジュール直下で2回定義しても、どの検査にも引っかからない

規模S。
状態: 完了（2026-09-16起票・同日実装。[T881](T881.md)の撤去で実際に作り込んだ欠陥が、
テスト1,981件・`-m postgis` 278件・`ruff`・`review_checks.py docs`のどれも通過した）

## 背景

撤去の切り出しが広すぎた箇所を`git show HEAD:`から貼り直したとき、既に残っていた部分へ
重ねて貼り、同じ塊が2組並ぶ状態になった。後の定義が前を**同じ値で**上書きするため、
観測できる違いが何も出ない。

- `ruff`は`--select ALL`でも拾わない（モジュール直下の変数再代入は正当なPythonのため。
  F811は未使用の関数・クラス・importの再定義しか見ない）。実際に試して確認した。
- `review_checks.py duplication`（jscpd）は、当該ファイルが100KB超で走査外
  （[T882](T882.md)）。仮に走査されても`cmd_duplication`は同一ファイル内の重複を
  捨てるため表には出ない。
- テストは、値が同じである以上どう書いても落ちない。

## 保留することで何が起きうるか

貼り直しは撤去・分割のたびに起きる操作で、同じ形の残骸が今後も入る。値が同じなら無害だが、
**2組が別々に編集されると、後の定義だけが効いて前の編集が静かに巻き戻る**。

## 対応（2026-09-16）

`scripts/review_checks.py`の検知器`module_redefinition`にした。`ast`でモジュールの
`body`直下だけを見て、`Assign`（Name代入）・`AnnAssign`・`FunctionDef`・
`AsyncFunctionDef`・`ClassDef`の名前を集め、2回以上現れるものを行番号つきで出す。
`staged`/`since`/`full`の3経路で強制する。

`if`/`try`の下の定義は見ない。環境ごとに片方だけが走る正当な形のため。

対象はPythonだけにした。TypeScriptの`const`/`let`は同じスコープで再宣言すると
コンパイルエラーになり、この形の欠陥が成立しない。

### 効いていること

- 既存の340ファイルに対して**誤検知0件**。
- `backend/app`へ同じ名前を2回定義したファイルを1つ置いて`docs --staged`を回すと、
  行番号つきで1件出る。
- [T881](T881.md)の修正前のコミット（`92cf0978^`）の`road_graph_repository.py`を
  そのまま食わせると、実際に作り込んだ5件をすべて拾う
  （`_WAY_TRAVEL_BEARING_SQL`・`_ANTIPARALLEL_SQL`・`_sample_fractions_sql`・
  `_named_prefilter_deg`・`_geometric_prefilter_deg`）。
- `guard_probe_mutations`へ違反の作り方を足したため、`mutate`の監査にも載る。
