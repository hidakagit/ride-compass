# T1009. 撤去済みのsplit工程が、docs/modulesに現行仕様として残っている

状態: 未完了（2026-09-22起票）

## 背景

`road_graph_tiles`（タイル取込済みマーカー）・`is_split_up_to_date`（split鮮度判定）・
`presplit_road_graph.py`（事前split バッチ）・`RoadGraphTileRow` は、T970段階C
（`91bc38328` 「読み出しを新しい表へ移し、遅延構築を撤去する」）で撤去済みで、
`grep -rn "road_graph_tiles\|is_split_up_to_date\|presplit\|RoadGraphTileRow" backend/`
は**0件**である。

にもかかわらず docs/modules は、これらを現行の仕組みとして現在形で記述し続けている
（14行／2ファイル、2026-09-22 実測）:

- `docs/modules/backend/routing-engine.md` 10行。うち**対象ファイル表（18行目）が
  `presplit_road_graph.py` を載せ**、**`## batch: presplit_road_graph.py` という節
  （951行目〜）が丸ごと**存在しないバッチの挙動を説明している。他はカバレッジ判定・
  split鮮度判定・キャッシュしない理由の根拠として `road_graph_tiles` を名指しする記述。
- `docs/modules/backend/batch-pipeline-dependencies.md` 4行。**バッチ依存表の段「④」
  として presplit_road_graph.py が1行を占め**、再実行条件・冪等性・「未split範囲への
  リクエストでその場で交差点分割する経路」（＝撤去された遅延構築）を説明している。

実際の現在の姿は、カバレッジ判定が MVT 生成と同じ1クエリへ畳み込まれた形
（`services/region_service.py`、「取込の宣言した範囲か」）であり、batch は
`ingest.py`・`derive_*.py` の系である。

害: docs/modules は実装作業者が着手前に精読する前提の文書で（CLAUDE.md）、存在しない
バッチの再実行を完了条件に含めた計画や、存在しないマーカーを前提にした設計が起票されうる。
とくに batch-pipeline-dependencies.md の④は「この段を再実行しないと評価軸が欠損する」
という運用上の警告の形を取っており、実在しない段に対する警告として読まれる。

frontend側に残ったsplit撤去の残骸（`DbStatusPanel.test.tsx`の存在しない
モック）を落とす作業のなかで、同じシンボルをリポジトリ全体へ grep した際に検出。

## 対応方針

「現行仕様の記述」として残っているものを、実装に合わせて落とす／書き換える。**撤去では
なく置き換えになる箇所（カバレッジ判定・バッチ依存表）は、実装を読んで現在の姿へ
書き直す**——行を消すだけだと、カバレッジ判定という機能自体が無くなったように読める。

docs/architecture/setup.md と docker-compose.yml にも `road_graph_tiles` を Redis
cache-aside 層の対象として挙げる記述があるが（各1箇所）、これは architecture 側の
「外部の制約・構成」の記述であり、同一タスクで扱うか分けるかは着手時に判断する。
docs/records/ は対象外（維持しない方針）。

## 母集団の導出

対象は次のコマンドの出力とする（記述の言い換えを拾うため、シンボル名だけでなく
「split済み」も母集団へ入れる）:

```
grep -rn "road_graph_tiles\|is_split_up_to_date\|presplit\|RoadGraphTileRow\|split済み" docs/modules/
```

## 完了条件

- 上記 grep が docs/modules に対して0件

  batch-pipeline-dependencies.md の段番号（④以降の繰り上げ）が整合していること
- カバレッジ判定・バッチ依存の記述が、実装（`region_service.py`・`backend/app/batch/`）
  を読んで書き直されており、単なる行削除になっていないこと
- `python scripts/review_checks.py docs` が違反なし
