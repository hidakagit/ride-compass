# T1123. ルート結果パネルで、候補一覧だけを縦スクロールできるようにし、操作ボタンを低くし、最速の候補は所要時間と印で示す

## 背景

ユーザー要望（2026-09-26、スマホ）: ①ルート結果パネルで左の候補一覧だけスクロールできる仕様を復活してほしい（候補が増えると不便）。T1001段階C（8fd5e98）でCSS Modulesを共通部品へ移したとき、スマホ幅で候補一覧へ付けていたoverflow-y: auto・min-height: 0が移し漏れた。②ルート生成・ルート結果まわりのアイコン付きボタン（生成・全消去・合成・GPX、Button size=iconLabel）の縦幅を低くする。③最速の候補は「最速」の文字ではなく所要時間を出し、最速は簡易な印で示す。規模の根拠: page.tsx・Button.tsx・そのテスト・設計書で、変わるファイルは3〜4（③7以下）。

## 実施（2026-09-26、T1112のクラウドのセッション）

- 候補一覧のスクロール: スマホ幅で候補一覧（`TabsList`）へ`overflow-y: auto`・`min-height: 0`を戻した。T1001段階C（8fd5e98）の
  前は`page.module.css`の`.outcomeTabList`が狭幅でこれを持っていた。シートの本文はスクロール容器なので、中の2カラムはシートの
  高さに収まり、はみ出す候補は一覧の中だけが縦スクロールする。
- 操作ボタン: `Button`の`size="iconLabel"`をアイコンの横に名前を置く形にした（縦に積む形から）。高さは28px。パネルの
  操作（生成・全消去・合成・GPX・編集面の4つ）はすべてこの形なので一緒に変わる。
- 最速の候補: 「最速」の文字の代わりに、時計の印（読み上げ名「最速」）と所要時間（`formatDurationShort`、例「1時間5分」）。
  所要時間が入ると幅160pxの列では行が「…」で切れたため、列を192px（w-48）へ広げた。
- 設計書: page-composition.md（最速の表記・候補一覧の縦スクロール。横スクロールの古い記述も直した）、frontend-design-system.md
  （パネルの操作ボタンの形）、route-settings-and-results.md（編集面の操作の形）。
