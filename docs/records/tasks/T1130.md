## 母集団と判定

母集団は2つの機械的な列挙の和とした。①`git grep -i road_graph_use_repository`（`docs/records`を除く）
②フラグが外した口を受ける形——`git grep -E "(RoadGraphRepository|AccidentTileQuery) \| None|repository is None|
repository is not None|_repository is None"`と、口を渡さない構築`RegionService()`・`AccidentService()`・
`repository=None`・`factory(None`（テストを含む）。①は実装が`config.py`・`dependencies.py`、設定が2本の
`.env.example`・`docker-compose.yml`のコメント、文書が`cross-cutting-infrastructure.md`。②は記録の挙げた
実装の箇所と一致し（`dependencies.py`の型注釈・`get_road_graph_repository`を受ける2つのルーターを含む）、
テストは11ファイル。DBの口を`| None`や既定値`None`で受ける引数が他に無いことは
`git grep -E "(repository|query|session)[a-z_]*: [A-Za-z_.]+ \| None|Optional\["`（backend/app）が0件で確かめた。

本番の設定: リポジトリの宣言（`.github/workflows/deploy-backend.yml`）はこのフラグを渡さず、環境変数は
VM上の`/home/ubuntu/ridecompass-backend.env`から読む。既定値は`True`だった。`Settings`は`extra="ignore"`
のため、VMのファイルにこの行が残っていても起動は変わらない（撤去後は常に口ありで動く）。本番の環境変数を
変える操作は要らない。

## 実施内容

- `config.py`の`road_graph_use_repository`を消し、`dependencies.py`のDI工場（`get_road_graph_repository`・
  `get_region_service`・`get_dedicated_way_value_service`・`directional_materials`・`get_accident_service`）を
  常にセッションを開いて口を渡す形にした。
- `RegionService`・`AccidentService`・`WindWayService`・`GradientWayService`は口を必須にし、`None`の分岐を
  消した。`tile_version_service.current_tile_versions`の`None`分岐、軸管理の分布プレビューの「DB未接続」503、
  材料の分布の`available=false`（DB未接続）も消した。DBに届かないときの扱いは、読み取りで上がる例外
  （`DB_UNAVAILABLE_ERRORS`・`DBAPIError`）の経路がこれまでどおり持つ。
- ルート直下の`.env.example`は、composeで効く行だけにした。Docker公式の優先順位
  （https://docs.docker.com/compose/how-tos/environment-variables/envvars-precedence/ ——`environment`属性が
  `env_file`属性より優先）により、`DATABASE_URL`・`CORS_ALLOWED_ORIGINS`は`docker-compose.yml`の
  `environment:`が上書きし、`POSTGRES_*`・`NEXT_PUBLIC_API_URL`はどのサービスにも届かない（composeファイルに
  変数の埋め込みが無く、frontend・postgresは`env_file`を持たない）。存在しない`frontend/.env.example`への
  案内も消した。`backend/.env.example`はフラグの節と、フラグしか持たなかったプロファイル表を消した。
- 撤去で参照0になったテスト（口なしで空タイル・空dict・None・503を返すことを見ていたもの）を消した。
  口なしの経路を通して別の性質を見ていたテストは、DBの代役へ差し替えた: 材料の値一覧の「出せなかった」は
  DB障害で、世代の読めない状態は世代の行が無いDBで、軸カタログのルートとway値配信の材料での引き当ては
  代役の口で確かめる。路面・POIタイルは、取込範囲外（ブラウザが持ってよい空タイル）とDB障害（持たせない
  空タイル）をサービスの入口で確かめるテストを置いた（これまでは口なしの経路でしか通っていなかった）。
- 消した関数・分岐の中のコメントは、どれもフラグ（口を外す設定）の説明で、撤去後に成り立たないため消した。
  「口が無い状態を持たない」という判断は`cross-cutting-infrastructure.md`の設定の節へ書いた。
- 文書は`cross-cutting-infrastructure.md`・`static-road-attributes.md`・`dynamic-way-values.md`・
  `evaluation-scoring.md`を実装へ合わせた。frontendの`useMaterialValues.ts`のコメントの「DB未接続」も外した。
