# T986. レビュー基盤を、監査する対象と産出物から定義し直す 規模M

状態: 設計確定（2026-09-21起票。T979①の続きとして、ユーザーと②を確定）。

## 背景

レビュー基盤が何を対象に、何を基準に見ているのかが定義されないまま積み上がっていた。
T979①で文書を性質（規範／記述／台帳／記録）へ分け直した結果、レビューが記録まで
監査していたことが見えた。

測ったもの（2026-09-21）:

- レビューは8種類（`all`・`overall`・`consistency`・`complexity`・`ui`・`metrics`・
  `improve`・`context`）＋共通ルール `principles.md` 276行
- 台帳773件のうち、由来にレビューが書かれているのは**55件（7%）**。うち**48件が統合
  レビュー(`all`)**。個別のレンズが名指しで挙がるのは各0〜2件。ただし `all` は内部で
  レンズごとにシャード実行するため、レンズが使われていないのではなく成果が `all` へ
  帰属している
- 周期レビューのトリガーは、前回レビューの日付と対象コミットを `history/` の
  ファイル名から読んでいた。T979でその記録を捨てたため**現在は発火しない**

## 決めたこと

### ① 監査の対象

**維持する対象（正本・台帳・手順書）＋実コード**だけ。記録（`docs/records/`）は対象外。
記録は記録時点で嘘がなければよく、訂正は新しい記録で行うため、後から現在の実装と
食い違っても欠陥ではない。

### ② レビューのコマンドは1本にする

使い分けが説明できない状態で8本に分かれていた。`/review` 1本に畳み、観点（アーキテクチャ
全体・設計↔実装の一貫性・複雑度・UI）はその中の節として残す。`all` は元々これらを
シャード実行していたので、実行の中身は変わらない。

| 今 | どうするか |
|---|---|
| `all` | `/review` として残す |
| `overall`・`consistency`・`complexity`・`ui` | コマンドを畳み、観点として `/review` の節にする |
| `metrics` | 畳む。`scripts/review_checks.py metrics`（3秒）が同じことをしている |
| `improve` | 畳む。レビュー基盤の改善は普通にタスクとして起票する |
| `context` | 畳む。`/review` の内部手順として吸収 |

複雑度の観点が持つ固有の制約（**常に単独Agentで実施する**）は `/review` の中の一文として残す。

### ③ レビューの産出物

**起票したタスクと、見送り判断の行だけ。生の記録は残さない。** 記録を残しても、指している
のは記録どうしで、生きた仕組みからはほとんど参照されなかった（T979で実測）。

見送り（やらないと決めた判断）は、台帳が `- [ ]` / `- [x]` しか持たないため従来どこにも
残らなかった。`Txxx.md` の `状態: 見送り` として起票する（既に6件がこの形で存在する）。

### ④ トリガーの状態はgitタグに持つ

「前回いつ・どのコミットをレビューしたか」は導き直せない状態だが、ファイルとして
コミットすると「状態をコミットしない」という方針と衝突する。**レビューした対象コミットへ
`periodic-review/YYYY-MM-DD` のタグを打つ**——refの名前空間に載るのでドキュメント木を
汚さず、`git tag --list 'periodic-review/*'` で最新と対象コミットの両方が引ける。

名前は用途が読めるものにする。`review/` だけだとブランチ名やリリースタグと紛れる。
このリポジトリはタグを1つも持っていないため（2026-09-21時点で0件）、ここで規約を作る。

`cmd_trigger` の `latest_history_date()` / `latest_target_commit()` を、このタグを読む形へ
置き換える。

## 実施すること

## 残る論点（③として別に決める）

**検知する対象の定義。** 走査集合＝維持する対象だけ／実在判定＝全追跡ファイル（T979で
実装済み）。そのうえで、32本の検知器それぞれが「言語・ディレクトリをまたぐ整合」を
見ているか、「単一モジュールの不変条件」を見ているかで仕分ける。後者はそのモジュールの
テストか既存のlint/型検査の仕事で、検知器から外す。

実測済みの候補（`--since` 実行、30本で合計55.5秒）:

| 秒 | 検知器 | 疑い |
|---|---|---|
| 20.17 | `map_redraw_coverage` | frontend 1モジュールの不変条件。vitestで直接突き合わせられる |
| 3.91 | `count_narrative` | ブロックしない（表示のみ） |
| 2.59 | `cross_layer_claim` | ブロックしない |
| 1.33 | `module_redefinition` | ruffが `F`（pyflakes）を選んでおり F811 と重なる |
| 0.92 | `call_arity` | 型検査の仕事。[T985](T985.md)が未着手のまま |
| 1.58 | `plan_vs_tasks` | 状態の正本を台帳へ一本化すれば照合相手が消える |

ブロックしない検知器は7本あり、うち計測できた3本で7.2秒（全体の13%）を占める。
