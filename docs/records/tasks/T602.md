# T602: 目的地ルート生成が起点に一番近いNodeへスナップした結果アクセス不能になる不具合の是正と、アクセス可能な最寄りNodeへの自動補正

状態: 完了（2026-09-05起票・同日完了）

## 背景

ユーザー報告「目的地検討が動かなくなった」を調査した結果、経由地なしの目的地ルート
（via-node方式、`RoadGraphEngine.select_via_nodes`）が本番で常に
「指定した目的地までの経路が見つかりませんでした」になっていた。診断ログ強化
（`select_via_nodes reachable=0 forward_reached=... backward_reached=...`）で、
起点からの前向き探索はグラフの97%（159013/163972ノード）へ到達しているのに対し、
目的地に最も近いとしてスナップされたNodeからの後ろ向き探索はわずか4ノードしか
到達できていないことが判明した。前向き探索から見ても目的地Node自体には到達できて
いない（`destination_reached_by_forward=False`）ため、道路網や逆探索の実装自体は
壊れておらず、目的地に一番近いNode（`find_nearest_node_indexed`、次数1以上のみを
候補にする[T256]）が、メインの道路網から孤立した小さな塊（歩道橋・私有地内通路等、
自転車ルートの探索対象から外れる道にしか繋がっていない地点）へスナップされていた
と結論づけた。

ユーザー判断: 自動で最寄りのアクセス可能な地点へ補正し、その旨を表示する。

## 対応方針・実施内容（2026-09-05）

- `domain/routing.py: find_nearest_node_indexed`に`predicate`引数を追加（Nodeを動的な
  条件で絞り込めるようにする、既存の索引構築時固定の`node_ids`絞り込みとは別軸）。
- `road_graph_engine.py: RoadGraphEngine.select_via_nodes`: 起点からの前向き木を求めた
  直後に、スナップ済みの目的地Nodeがその前向き木で到達可能かを確認する。到達不能なら
  「前向き木が届くNode」だけに絞ってfind_nearest_node_indexedへ`predicate`を渡し
  再スナップする。再スナップも失敗した場合は候補0件（WARNING、内訳ログ付き）のまま。
  補正した実際の座標は`_RoadGraphContext.destination_correction`に残す
  （`RouteGenerator.last_no_candidates_reason`と同じside channel設計）。
  後ろ向き木の構築は「（補正後の）目的地」に対して行うため、無駄な逆探索を避けられる
  （元の孤立Nodeに対する逆探索は行わない）。
- `route_generator.py: RouteGenerator`: `last_destination_correction`属性を追加し、
  `_generate_destination_routes`が`select_via_nodes`呼び出し後にcontextから引き継ぐ。
- `api/routers/routes.py`: `GenerationConditions.corrected_destination`
  （`Coordinates | None`）を追加し、`_run_generate_job`が
  `setup.generator.last_destination_correction`をそのままエコーする。
- `export_openapi.py`→`npm run generate:api`で生成物（openapi.json/api.d.ts）を同期
  （このタイミングで、無関係な既存の乖離——`RouteGenerateRequest.lens_axis_id`/
  `start_time`・`GenerationConditions.start_time`のdescriptionが実際のソース
  [プレーンな`#`コメントのみ、`Field(description=)`無し]と食い違って残っていた
  ——も合わせて正しい状態へ揃った）。
- frontend（`page.tsx`）: `handleGenerate`が`conditions.corrected_destination`を受け取ると
  地図上の目的地ピンをその地点へ動かし（`setDestination`）、`generatedConditions.
  destinationCorrected`を立てる。「ルート結果」タブの`conditionsDirty`ヒントと同じ場所に
  「指定した地点は自転車で行けない場所だったため、近くのアクセス可能な地点へ補正しました。」
  という案内を表示する（新規コンポーネント無し、既存の`dirtyHint`スタイルを再利用）。
- テスト: `test_routing.py`（predicate）・`test_road_graph_engine.py`（孤立地点→補正の
  一気通貫、`context.destination_correction`検証）・`test_route_generator.py`
  （`last_destination_correction`の伝播とリセット）・`test_routes_generate.py`
  （APIレスポンスへのエコー）・`page.test.tsx`（案内表示・補正後座標での再生成）。
- docs: `docs/modules/backend/routing-engine.md`（`select_via_nodes`節）・
  `docs/modules/frontend/page-composition.md`（`renderRouteOutcomeSectionBody`節）。
