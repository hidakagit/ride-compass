## 実施内容

新しい依存は足していない。使った部品はどれも既に入っているもの（coverage.py は pytest-cov の依存、python-dotenv は
pydantic-settings の依存で、`backend/scripts/serve_e2e_live.py` が既に `dotenv_values` を使っている。Playwright の CLI は
`@playwright/test` が持つ。git と tarfile は標準）。

- **audit_test_rewrite.py**: `.coverage` の SQLite 直読み（`line_bits`・`arc` の表の結合）を `CoverageData.read()`・
  `measured_files()`・`contexts_by_lineno()` へ。分岐ありの記録（arc）の扱いは coverage.py 側が持つので、その差を説明する
  コメントも消えた（coverage 7.16.0 の `sqldata.py` で、`has_arcs()` のとき arc の両端の行へ文脈を割り当てることを読んで確かめた）。
- **deploy_backend_gate.py**: GitHub の `paths` を真似た自前の glob→正規表現（`_pattern_regex`・`matches`）を消し、
  `git diff --name-only <本番> <対象> -- :(top,glob)… :(top,glob,exclude)…` に当てさせる。一覧は `DEPLOY_PATHS`（含める）と
  `NOT_DEPLOYED`（外す）の2つに分けた——pathspec には「上から当てて最後が勝つ」順序が無く、「含むどれかに当たり、外すどれにも
  当たらない」で決まるため、`!` の混ざった1本の並びのままだと並びの意味が嘘になる。今の一覧に「外したものの中を
  含め直す」行は無く、判定は変わらない。`:(top)` で作業ディレクトリによらずリポジトリの根から当てる。差分の起点を本番で
  動いているコミットに取る判定（`_relation`）はそのまま。`backend/tests/structure/test_deploy_exclusions.py` も外したファイルの
  展開を pathlib の glob（`**` がファイルに当たらない差を補う分岐があった）から、ゲートと同じ pathspec での `git ls-files` へ。
- **smoke-check.mjs**: 消した。代わりは `playwright screenshot --viewport-size="390,844" <URL> <出力先>`（README に書いた。
  PowerShell では `,` が配列になるため引用符が要る——引用符なしで実際に `Invalid viewport size format` で落ちた）。これで
  `playwright` の直接の devDependency は読み手が無くなったので外した（`@playwright/test` が同じ版を依存に持つので
  lock の中身は根の宣言1行だけが変わる。`npm uninstall playwright --package-lock-only`）。knip.json の入口と .gitignore の
  スクリーンショットの行も消した。
- **check-oracle-cloud.sh**: 使われていないと判断して消した（置き換えない）。根拠: 追加（2026-08-20、e24c1cc4c）以降変更が無い、
  リポジトリのどこからも（docs・workflow・.claude・他のスクリプト）参照されていない、Claude の定期タスクにも無い
  （`list_scheduled_tasks` は pending-backup の1件だけ）、記録にも走らせた跡が無い。消したファイルの中の文は
  comments.md の判定木へ通した: 2026-08-15 の誤生成の事故と影響額は経緯で、この記録の外に残す先は無い。本番の構成の
  基準（A1.Flex のインスタンス1台・ブートボリューム1個・データ用ブロックボリューム1個・予約済みパブリックIP 0）と、OCI CLI の
  癖（stderr へ定型の警告を出す・`public-ip list --scope REGION` が0件のとき標準出力が空）は、読み手がこのスクリプトだけ
  だったので一緒に消えた（リポジトリに OCI を扱うコードは残らない。書き留めておくのはここだけ）。
- **launch.py の export_tools**: 1ファイル1回の `git show`（道具の本数ぶんのプロセス）を `git archive` の1回と `tarfile` の
  展開（`filter="data"`。システムの Python 3.12.0 で使える）へ。`.py`・`.sh` だけに絞る分岐は、道具の置き場に他の追跡ファイルが
  無いので外した。
- **run_probe.py**: `.env` の自前の行読みを `dotenv_values` へ。コンテナへの受け渡しを、base64 にして VM の /tmp へ書き
  `docker cp` して後で消す形から、`ssh … sudo docker exec -i … python -` の標準入力へ流す形へ（VM にもコンテナにもファイルが
  残らない）。
