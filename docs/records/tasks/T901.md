# T901. 外縁のケースが母集団の内側に書かれても、初日からCOVEREDに見える

規模S。
状態: 完了（2026-09-16。[T890](T890.md)・[T891](T891.md)の実施後に、同じ型が
もう1段外側に残っていないかを点検して見つけた）

## 背景

[T890](T890.md)は「検知器が取りこぼしていないこと」を測るために、検知器ごとの**外縁の
ケース**（拾うべきなのに母集団へ入らない位置）を`guard_probe_edges`へ1件ずつ置いた。
**ケースを足し忘れることは機械的に防げている**——強制検知器に外縁が無ければ
`scripts/tests/test_review_checks.py`が落ち、`mutate`も`NO-EDGE`を違反として出す
（検知器キーを1つ足して実験し、両方が名指しで報告することを確認した）。

防げていないのは**中身**である。外縁のケースを母集団の**内側**へ書いてしまうと、その行は
初日から`COVERED`になり、穴が無いのと同じ見た目になる。いまの23件のうち21件は
「一度は`GAP`だった」ことが記録の代わりになっている（17件は今も`GAP`、4件は
[T891](T891.md)で`GAP`→`COVERED`へ変わった）が、**これから足す行にはその裏付けが無い**。

## 保留することで何が起きうるか

次の周期レビューが「検知器は取りこぼしていない」と報告するとき、その根拠は
「外縁が全件COVERED」になる。内側に書かれた外縁ケースが混じっていると、**母集団に穴が
あっても報告の見た目は同じ**になり、レビューの結論からその区別が消える。第9回→第10回で
起きた「検知器の母集団が1段メタな層で再発した」のと、層が1つ増えただけの同じ型である。

## 起票時の2案と、実際に採った形

起票時は次の2案を並べ、案2を「案1より強い」と書いていた。

- 案1: 新しく足す外縁は`detected=False`から始めることを規約にし、`COVERED`で生まれた行を
  `mutate`が参考出力する。
- 案2: 同じ違反を母集団の**内側**へ置いた対照ケースも一緒に走らせ、「内側は検知・外縁は
  見逃し」の両方が成り立つときだけその外縁を正当とみなす。

**案2はこのタスクが問題にしている失敗を塞がない。** 案2の判定条件は「外縁は見逃し」を
含むため、`COVERED`の行——まさに本タスクの対象——では条件そのものが成り立たず、判定不能に
なる。案2が検算できるのは`GAP`の行、すなわち「違反が成立していないだけで見逃されている」
方の失敗である。これは実在する別の欠陥なので[T911](T911.md)として独立させた。

採ったのは**案1を、参考出力ではなく記録として機械化した形**である。`detected=True`は
「いま検知される」としか言えず、その位置が母集団の**外**だったことは、一度`GAP`として
観測されていなければ確かめようがない。そこで観測そのものを記録に残す。

- `.claude/commands/review/history/guard_edges.json`——検知器キー → その外縁が実際に
  見逃されると観測されたコミット。既存の`size_watch.json`・`duplication.json`と同じ流儀。
- 記録を足せるのは`mutate --update`だけ（観測した結果を書く。宣言では足せない）。
- `detected=True`なのに記録が無い外縁は`unproven_edges`が拾い、`mutate`は`UNPROVEN`として
  落とす。
- 記録へ先回りしてキーを書く抜け道は`stale_edge_gap_records`で塞ぐ（実在する`EdgeProbe`の
  ものだけを許す）。
- どちらも`test_review_checks.py`に置いたので、`mutate`（全件86秒）を待たずCIの毎回の
  pytestで落ちる。

## 記録の初回投入（履歴から導出した。手で並べていない）

コミットを拾った。**現在`COVERED`の7件を含む全21件が、一度は`detected=False`だった**。

## 検証

- 記録から`map_redraw_coverage`を1件外す → `test_covered_edges_were_once_observed_as_a_real_hole`
  が落ち、`mutate --case map_redraw_coverage`が`UNPROVEN`を出して違反に数えた。
- 実在しないキー`zzz_not_a_detector`を記録へ書く → `test_edge_gap_records_only_name_existing_edges`
  が落ちた。
- 記録から`narrative`（`GAP`の1件）を外して`mutate --case narrative --update` →
  観測した`GAP`を今回のコミットで記録へ書き戻した。
- 復元後、`test_review_checks.py`は133件green（1件の失敗は`symlink`作成権限が要る
  Windows固有の既存失敗で、本変更とは無関係）。

## 残る抜け道

記録ファイルを手で編集すれば`UNPROVEN`は回避できる。実在する外縁のキーであることまでは
機械が縛るが、「そのキーが本当に観測されたか」は縛れない。`--update`以外の経路で記録が
増えたかどうかは差分に現れるため、そこはレビューで見る。
