# T1016. 設計書が名指しする識別子のうち、実装に存在しないものを直す

状態: 完了（2026-09-23）

## 背景

設計書（`docs/modules/**`）は実装の識別子をバッククォートで名指しする。撤去・改名のとき
コード側は参照が0になれば気づけるが、**文の中の名前は誰も検査していない**。T1001 段階Aの
撤去で消えた適用機構（`buildStaticOverlayLayers`・`drawSpliceStretches`・
`MAP_LAYER_PAINT_TIER_ORDER`等）が、設計書には現行仕様として残っていた。

frontend側は同タスクで直した（34件 → 15件。残りは下記）。**backend側は未着手で70件ある。**

## 母集団の出し方（再現手順）

1. `frontend/src`・`frontend/e2e`・`backend/app`・`backend/scripts`・`backend/tests`・
   `backend/benchmarks`・`scripts` 配下の `.ts/.tsx/.py/.json/.css/.sql/.mjs` から
   `[A-Za-z_][A-Za-z0-9_]*` を全部集めて語彙にする
2. `docs/modules/**/*.md` のバッククォート内から `^[A-Za-z_][A-Za-z0-9_]{4,}$` に当たる
   トークンを取り出す（末尾の `()` は落とす）
3. 語彙に無いものが母集団

この手順で2026-09-22時点の母集団は105件（frontend 15・backend 90）。

**この手順には穴がある**（2026-09-23に実際に見逃した）。語彙に**テストファイルを含めている**ため、
実装から消えてテストヘルパーとしてだけ生き残った名前は「実装にある」と数えられる
（`dynamic-weather-layers.md`の`dynamicWeatherIds`がこれで、設計書は実装に無い命名規約を
書き続けていた）。**実装だけの語彙**でも1度通し、差分を見ること。

## 残っているもの

backend側（`routing-engine.md` 40・`batch-pipeline-dependencies.md` 11・
`static-road-attributes.md` 7・`evaluation-scoring.md` 7 ほか）と、frontendの軸スタジオ周り:

- `axis-studio.md`: `GENERATION_FRESHNESS_SPECS`・`COMPLETENESS_SPECS`（backendにも無い）、
  `AXIS_MATERIAL_OPTIONS`（`lib/axisMaterialsCatalog.ts`は在るが、この静的フォールバックは
  撤去済みで、いまは`useMaterialCatalog`が配る。**設計書は今も「静的フォールバックがある」と
  書いており、これは挙動の誤り**）
- `route-settings-and-results.md`・`batch-pipeline-dependencies.md`ほか: `save_graph`

## 判定の基準（誤検知を処置へ繋げないため）

トークンが語彙に無くても、次は**直さない**——外部ライブラリ・DOM・MapLibreのオプション値・
DBのテーブル/列名・SQLの設定名は、この語彙に入らないだけで誤りではない
（例: `onWheel`・`multidirectional`・`road_node`・`work_mem`・`heapq`）。
**「このプロジェクトが定義した名前か」を1件ずつ見てから直す。**

## 完了条件

- 母集団の全件が「直した」か「誤検知（理由を1行）」に分類されている
- 直した件は、後継の名前が実在することを上の手順で再度確認している

## この検査を検知器にしない理由

誤検知を外すには許可リストが要る（外部語彙・DB列名）。CLAUDE.mdの検知器の基準
「許可リストが要るものは足さない」に当たるため、**周期的に人が回す**ものとして置く。

## 実施内容（2026-09-23）

### 導出の穴を2つ塞いでから回した

上の手順（語彙＝識別子集合、バッククォートの中身がまるごと識別子のものだけ）には、
「テストを語彙に含める」穴のほかに2つ穴があった。どちらも既知の1件で検算した。

1. **`path: name`・`Name.attr`の形を拾わない**。`domain/attributes.py: compute_elevation_values`
   のように書かれた名前は、バッククォートの中身が識別子1つではないため母集団に入らない。
   コロンの右側・ドットの両側（右側がファイル拡張子のものは除く）も取り出すようにした。
2. **語彙にコメントを含めている**。`build_road_graph`は実装から消えているが、
   `frontend/src/components/Map/mapLayers.ts`のコメントに名前が残っているため「実装にある」と
   数えられていた。語彙からコメント・docstringを落とした版（Pythonは`#`以降と行頭から
   始まる三重引用符の文字列、TSは`//`・`/* */`）でも通した。検算: この版で`build_road_graph`が
   候補に出ることを確認した。この版はSQLを包む`text(f"""...""")`の中身まで落とすため、
   SQLに埋め込んだ名前（`_POI_TILE_KIND_EXPR`）が誤って候補に出る——候補を増やす側の
   誤りなので、1件ずつ見る前提なら害は無い。

使ったスクリプトは使い捨てでリポジトリに置いていない。手順は次のとおり:
語彙の対象は上の「母集団の出し方」1と同じディレクトリ・拡張子。`--impl`はテスト（`tests/`・
`e2e/`・`benchmarks/`・`*.test.*`・`conftest.py`）を除く。
