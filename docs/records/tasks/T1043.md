# T1043. routing-engine.mdを、読む人の入口ごとに分割する

状態: 未完了

## 背景

周期レビュー第12回の規模ウォッチで`docs/modules/backend/routing-engine.md`が1,000行を
越えて発火し、「分割を提案」と分類された（分類の記録は[T1030](T1030.md)）。実装側は
`services/`・`domain/`・`infrastructure/`・`batch/`に分かれているのに文書だけが1本で、
探索アルゴリズムを触る人とバッチを触る人が同じ文書を入口にしている。

T1030で`review_checks.py size`を「1,000行以上で個別閾値の無いファイルは毎回発火する」
へ直したため、このファイルは分割するか閾値を置くまで毎回発火する。

同じ周期で`road_graph_engine.py`のコード分割は見送った（[T1037](T1037.md)）。
見送りの理由の1つが「文書の分割と同時に動かすと両方が中途半端になる」なので、
このタスクは**コードに触れず、文書だけを分ける**。

## 対応方針

1. 分ける軸は**読む人の入口**（どのファイルを触るときに開くか）。節の見出しが名指す
   実装ファイルのパス（`services/`・`domain/`・`infrastructure/`・`batch/`・`api/`）で
   節を仕分け、同じ変更理由で一緒に読まれる節の組を1文書にする。とくに`batch:`節群は
   探索を触る人が読まないので、切り出しの第一候補。
2. 切り出した文書へ、対象ファイル表の該当行を**移す**（元に残さない。同じ一覧を二重に
   持たない——CLAUDE.md「ドキュメント記載方針」の例外は対象ファイル表1つだけ）。
3. `routing-engine.md`を指すリンクを`grep -rn "routing-engine.md" --include=*.md . |
   grep -v docs/records`で全件出し、移した節を指しているものは移転先へ張り替える。
   `docs/modules/README.md`の索引へ新しい文書を足す。
4. 「暗黙の前提のまとめ」節は、各前提がどの節の話かで移転先を決める。

## 完了条件

- `python scripts/review_checks.py size`で`routing-engine.md`と、切り出した文書の
  どれもが発火していない。
- `python scripts/review_checks.py docs`が違反0件（リンクの張り替え漏れが無い）。
- 分割前の`routing-engine.md`の節見出しがすべて、分割後のどれか1つの文書にある
  （`grep -n "^#"`の出力を分割前後で突き合わせ、落ちた節が0件）。
