# T1094. 経路探索のテストが持つ道路グラフのデータ型の偽物（FakeNode・FakeEdge・FakeGraph）を、本物の型で作る形へ置き換える

状態: 完了（2026-09-24）

## 背景

T1021（24ファイルのテストの起こし直し）の方針は自分が持つデータ型の代役を0にすることで、記録の「何を守るか」が test_routing.py・test_road_graph_engine.py の FakeNode・FakeEdge・FakeGraph（LeanNode/LeanEdge をまねた偽物）を悪い例として名指ししているが、この2ファイルは24ファイルの外なので段階Fの測り直し（2026-09-24）でも残っていた。本物の型が変わっても偽物は黙って古い形のまま通り続ける。起票案 kihyoan-routing-fake-lean-types として2026-09-24に承認。規模の根拠: 変わると見込むファイルはテスト2本と共有の作り方を足すなら1本（7以下だが、テスト2本で合わせて数百行を作り直す見込みのためM）。実装は変えない。

## 方針

担当W-fakes。origin/master 9909e6dc の上で行った。

- **範囲**: 題名の3つに、同じ性質（対象の公開シグネチャが要求する値の型を、読む属性だけ持つ偽のdataclassで代用している）で
  座標の偽物2つを加えた——`test_routing.py`の`FakePoint`（T1021 段階Fが`FakeNode`と本体の一致する偽物として並べて挙げたもの）と、
  `test_road_graph_engine.py`の`FakeCoordinates`（同じ本体）。どちらも本物は`domain/route.py`の`Coordinates`で、`routing`・
  `road_graph_engine`の公開シグネチャ（`find_nearest_node_indexed`・`prepare`等）が要求する。
  同じファイルに残る探索構造の偽物（`FakeLazyGraph`・`FakeCsr`等7種）は題名の範囲の外として直さず、起票案にした（下の「範囲外」）。
- **作り方の置き場**: 2ファイルとも自分のファイルに持つ。`make_graph`の入力の形が2ファイルで違い（`test_routing.py`は
  Nodeの位置と`(始点, 終点, 距離, 方位)`、エンジン側はedge_idの並びとNodeの並び）、testing.md「共有フェイクへ出すのは3箇所目から」
  にも当たらないため、共有モジュールは置かない。
- **本物の型で作り直した入力**: frozenな本物へは後から代入できないため、偽物へ代入していた4箇所（区間の`highway`・Nodeの位置・
  探索用グラフの区間への`geometry`の書き込み）を、作る時点で値を渡す形にした。探索用グラフの区間へ`geometry`を書き込んでいた
  `preview_segment`のテストは、本番と同じく「探索用グラフの区間は空のプレースホルダで、取り直しが形を返す」形
  （`hydrate_with_geometry`）へ移した。区間の形状点列は本物の型どおり`list[list[float]]`（偽物ではタプル）。
  偽物の既定値（`osm_way_id=1`・`highway="residential"`・`bearing_deg=0.0`）は持ち込まず本物の既定（`None`）にしたが、
  落ちたテストは無かった——その既定値に寄りかかったテストは無かった。
- **偽物にしか無い形**: 見つからなかった（本物で作れない入力でしか成り立たないテストは0件）。保留は無い。

## 効いていることの確認

本物の型を実行時に差し替えるpytestプラグイン（`-p`で読み込み、`app.domain.graph`の`LeanEdge`・`LeanNode`を作り直した型へ
入れ替える）で、置き換え前（`git show HEAD:`で書き出した旧版）と置き換え後のテストを流した。

| 差し替え | 置き換え前 test_routing / engine | 置き換え後 test_routing / engine |
|---|---|---|
| `LeanEdge.distance_m`を`length_m`へ改名 | 86 passed / 1 failed・172 passed | 45 failed・41 passed / 25 failed・103 errors・45 passed |
| `LeanNode`へ既定値の無いフィールドを追加 | 86 passed / 173 passed | 収集時に1 error / 20 failed・103 errors・50 passed |
| `LeanEdge`へ既定値付きのフィールドを追加 | 86 passed / 173 passed | 86 passed / 173 passed |

置き換え前は、実装が読むフィールドを改名しても偽物が古い名前を持ち続けるため`test_routing.py`は全件通っていた（engine側で落ちた
1件がどのテストかは記録していない。実装自身が`LeanEdge`を組み立てるのは`_reverse_traced_edges`の1箇所）。既定値付きのフィールドの追加はどちらも検知しないが、既存の組み立ても
実装の読み方も変わらないので検知しなくてよい。

## 範囲外

- `test_road_graph_engine.py`に、`domain/routing.py`・`domain/attributes.py`の型をまねた偽物が7種残る（`FakeLazyGraph`・`FakeCsr`・
  `FakeStatics`・`FakeTurnStructure`・`FakeTree`・`FakeJunction`・`FakeElevation`。組み立て30箇所）。本物は素のdataclassか
  Pydanticで作るコストが無く、偽物は既に形がずれている（`FakeCsr`は本物の必須フィールド`indices`を持たず、`FakeTree`は
  `state_cost`等5つを持たない）。起票案 kihyoan-engine-test-search-structure-fakes としてダッシュボードに置いた。
