## 提案5: シェルへ送るコマンドの長さ（**根拠が不確定。ここが退避の主因**）

**出来事**: 約200行のPythonファイルを`cat > ... <<'EOF'`で書こうとして落ちた。
エラーは`unexpected EOF while looking for matching '`で、**引用符の壊れに見える**ため
クォートを疑って時間を落とした。同型の失敗はセッションをまたいで繰り返しており、
リポジトリ内にこの注意は無い（[T1021](T1021.md)本文の1行だけで、タスク記録は
「維持しない」層）。

**測れたこと**:

| 送ったコマンド全体 | 結果 |
|---|---|
| 約3.7KB（32行のヒアドキュメント） | 通る。内容も無傷 |
| 約8.2KB（72行のヒアドキュメント） | **1つも実行されない**（手前の`rm -f`も動かない） |
| 212バイト（105行のヒアドキュメント） | 通る |

**要因は長さで、技法でも行数でもない。** 短いヒアドキュメントは日常的に通っている。
落ちたときに部分ファイルは残らない。

**測れていないこと（これが不確定）**:

- **正確な閾値**。3.7KBと8.2KBの間としか言えない。`cmd.exe`の引数長上限8,191文字が
  有力だが未検証で、機構を確かめていない
- **マルチバイトの扱い**。実測はASCIIのパディングで、落ちた実例はUTF-8の日本語を含む。
  文字数で切れるのかバイト数で切れるのかを分けていない
- **他の環境でも同じか**。この開発機のGit Bashでしか測っていない

**当てる前の裏取り**: 上の3点を埋める。閾値は、自分の長さを報告する1行コマンド
（`A='<パディング>'; echo ${#A}`）を二分探索で送れば数回で挟み込める。マルチバイトは
同じ文字数の日本語とASCIIで比べる。**埋まるまで標準へ書かない**——「長いと落ちる」
だけの注意は、読んだ人が自分の状況に当てはめられず、結局同じ時間を落とす。

**当て先（埋まってから）**: `CLAUDE.md`のツール運用のまとまり
（「同じ操作を3回やったら仕組み化を検討する」「その作業に必要な最小の情報量で動く」の
あたり）へ1項目。

### 提案5: 当てた（不確定だった3点を、公式の報告と実測で埋めた）

**経緯の訂正**: 最初は実測の閾値（7,899文字は通り8,101文字は落ちる）がcmd.exeの上限
8,191文字（Microsoft Learn「Command prompt line string limitation」KB830473）に近いことから
cmd.exeが原因と推定した。**プロセスを辿ると誤りだった**——Bashツールの実行経路は
`claude.exe → C:\Program Files\Git\bin\bash.exe → usr\bin\bash.exe`で、cmd.exeを経由しない
（`/proc/$$/winpid`から`Win32_Process`の親をたどって確認）。この経験を受け、ユーザーの指示で
「外部の仕様について何か言う前に、公式を読む」を`CLAUDE.md`へ足した（下記）。

**公式の報告**: Claude Code公式リポジトリの
[anthropics/claude-code#92543](https://github.com/anthropics/claude-code/issues/92543)・
[#93915](https://github.com/anthropics/claude-code/issues/93915)（いずれもOpen、メンテナ回答なし）。
#93915は原因を「MSYS2ランタイムの`build_argv()`（`dcrt0.cc`）が`glob()`を呼び、`glob()`が
スタック上の8,192文字固定バッファを使う。引き金は引数に`?*["'(){}`を含むこと」と説明し、
`\\`が`\`へ半減する別症状も報告している。

**この開発機での実測**（Pythonから`bash.exe -c <本文>`を直接起動。スクリプトはセッションの
スクラッチ）:

| 観測 | 結果 |
|---|---|
| `Git\bin\bash.exe`・`Git\usr\bin\bash.exe`とも、`-c`の本文8,187〜32,700文字 | 受信は常に**8,186文字**。エラーも終了コードも出ない（rc=0） |
| 本文32,766文字 | CreateProcess自体が`WinError 206`で拒否（こちらはWindowsの32,767文字上限） |
| 日本語（3バイト文字）8,187〜9,000文字 | 受信8,186**文字**——バイトではなく文字で切れる |
| 空白・改行・`?*["'(){}`を一切含まない1語の本文 | 32,000文字まで**切られない** |
| 同じ本文に`'`または`*`を1個足す | 8,186文字で切られる——#93915の`glob()`経路の説明と一致 |
| Bashツールで`printf '%s\n' 'A\\B' 'G\\\\H' 'C:\Users'` | `A\B`・`G\\H`・`C:\Users`——**`\\`は長さに関係なく半減**、単独の`\`は保たれる |

**実行環境の包み**: Bashツールは自分のコマンドを
`export TEMP=… && shopt -u extglob … && eval '<コマンド>' < /dev/null && pwd -P >| <cwd記録ファイル>`
で包んで1引数として渡す（`$BASH_EXECUTION_STRING`で確認）。前側（`eval '`まで）233文字、
後ろ側（閉じ引用符から）76文字。包みは必ず`'`を含むので、上の`glob()`経路を常に通る。
したがって自分のコマンドの予算は **8,186 − 233 − 1 = 7,952文字**で、`eval '…'`の中では
単一引用符が1個5文字（`'"'"'`）に膨らむ。

- 7,952文字を超える → 閉じ引用符が失われ、`unexpected EOF while looking for matching`で
  **1行も実行されない**（8,101文字＋引用符2個で再現）
- 約7,877〜7,952文字 → 実行はされるが、後ろ側の記録先パスが途中で切れる。7,899文字＋引用符
  2個の実行で`C:\Users\h7g4b\AppD`という断片名のファイルが作られ、中身は作業ディレクトリ
  だった（計測後に削除）

**他の環境**: `glob()`経路はMSYS2ランタイム固有なので、Windows＋Git for Windowsの
Bashツールの話である。PowerShellツールは経路が別で、測っていない。

**回避策**: 長い本文はWriteツールでファイルに書き、`bash <file>`・`python <file>`で
実行する（#93915はstdin経由でも259KBまでバイト同一と報告）。`CLAUDE.md`の
ツール運用のまとまりへ当てた（+8行）。
