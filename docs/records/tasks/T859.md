# T859. 動的気象レイヤーの共有時刻が「今」に追従せず、降水が黙って消える

状態: 完了（2026-09-15）

## 背景

本番で「雨が降っている地域があるのに、降水レイヤに何も描画されない」という報告があった。
時刻スライダーを動かすと描画される。

共有時刻`dynamicLayerTargetTime`は画面を開いた時刻で固定され、時間の経過で進まない。
一方、降水ナウキャストのフレーム列は`trimToCurrentAndFuture`で先頭を最新の実況フレームへ
切り詰めており、5分ごとの再取得でその先頭が前進する。`frameIndexForTime`は範囲外で`null`を
返す設計のため、開いてから最初の再取得で共有時刻がフレーム列の過去側へ落ち、降水レイヤーは
何も描かなくなる。利用者からは「雨が降っていない」と区別がつかない。

同じ性質を持つのは実況由来のフレーム列を使う要素（降水ナウキャスト・雷・竜巻・雷放電）。
線状降水帯は`isWithinFutureWindow(target, new Date(), ...)`の`new Date()`がuseMemoの内側に
あり依存が`[dynamicLayerTargetTime]`だけのため、比較相手の「今」も一緒に凍結して常に可視に
なる——向きは逆だが同じ欠陥。本番VMのnginxログで、同じ「降水」チップ配下の
sjfcstmapがタイルを要求し続ける一方hrpnsがほぼ要求していなかったのはこの非対称による。

## 対応

共有時刻を「今（5分刻み）」と「利用者が選んだ時刻」の2本立てにした。利用者が選ぶまでは
前者へ張り付き、時間の経過とともに進む。選んだ後はその時刻を保ち（意図して決めた値を
勝手に動かさない、docs/design-principles.md）、「今」ボタンで張り付きへ戻る。

`isWithinFutureWindow`へ渡していた「今」も同じstateへ寄せた。ここは`new Date()`が
`useMemo`の内側にあり依存が`[dynamicLayerTargetTime]`だけだったため、比較相手の「今」も
マウント時刻で一緒に凍結し、線状降水帯予測マップが逆に**消えなくなっていた**。
このフックが持つ「今」は1つだけになった。

進める刻みは5分にした。出発時刻として選べる値そのものが5分刻みのため
（`RideConditionBar/departureTimeline.ts`）、これより細かく進めてもどのレイヤーが選ぶ
フレームも変わらないまま、共有時刻をキーに持つ取得（`useDedicatedWayValues`は
`at.toISOString()`をキーへ入れる）だけが無効化される。表示層は`setTilesIfChanged`/
`setDataIfChanged`で差分を見ているため、刻みが変わらない限りタイルの取り直しも起きない。

## 検証

本番VMのnginxアクセスログ（当日00:08→18:30 UTC）で、同じ「降水」チップ配下の非対称が
この欠陥の形をそのまま示していた:

    24 surf/sjfcstmap/   線状降水帯（凍結した「今」と比べるため消えない）
     1 surf/rasrf/
     1 surf/hrpns/       降水ナウキャスト（範囲外へ落ちて要求が止まる）

`targetTimes.json`/`_N1`/`_N2`はいずれも200で、在否インデックスに`hrpns`のエントリは
無い（＝インデックスによる抑止ではない、`jmaTileProtocol.ts`は該当が無ければ素通し）。

回帰テストは`useDynamicWeatherLayers.test.ts`へ追加し、追従を外すと症状で落ちることを
確認した:

    npx vitest run src/hooks/useDynamicWeatherLayers.test.ts
    （追従のuseEffectを外した状態）
    × 時間が経つと共有時刻も進む（進まないと降水が範囲外になり黙って消える）
      AssertionError: expected undefined to be defined   ← 降水ペイロードが消える
    × 「今」ボタンで追従へ戻る
    Tests  2 failed | 15 passed (17)
    （戻した状態）Tests  17 passed (17)

既存の雷放電位置データのテストは、任意の秒を持つvalidtimeでフレームを組み立てていた。
気象庁の実データ（`targetTimes_N3.json`）のlidenは全件5分刻みでこの形は存在しないため、
共有時刻そのものへ置き換えた。この確認の過程で、観測しか持たないレイヤーが配信の
遅れのぶんだけ常に範囲外になることが分かり、[T861](T861.md)として分けて起票した。
