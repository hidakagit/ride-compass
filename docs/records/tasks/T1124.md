# T1124. ルート結果に、道のりに沿った難易度のグラフ（横軸が距離、縦が区間ごとの難易度、塗った面積が負荷）を出す

状態: 完了（2026-09-25起票・2026-09-26完了）

## 背景

ユーザー要望（2026-09-26）: ルート結果の負荷と難易度の横グラフで、もう少し視覚的に情報量を増やしたい。今は1本の帯（長さ＝総合難易度、高さ＝距離、面積＝負荷、色＝軸）で、1軸だけ効くルートでは1色の短い帯にしか見えない。ユーザー決定: 横軸を距離（0〜全長km）、縦を区間ごとの難易度にした山形のグラフにする。どこが難所かが読め、塗った面積がそのまま負荷になる（今の「面積＝負荷」の読み方と同じ）。色は区間で効いている軸。区間ごとの値は既にAPIが返している（segmentsのaxis_contributions等）。まず区間の値と負荷の定義（負荷＝総合難易度×距離）がグラフの面積と一致するかを調べる段階を切る（①）。規模の根拠: 部品の新設・RouteAxisProfile・候補一覧の行・テスト・設計書で、変わるファイルは8〜12（③20以下）。

ユーザーの追加（2026-09-26）: グラフ上にバーを出し、動かすと地図の対応する場所を出したい。場所の単位を問われ、「場所は点単位、
値はedge単位」で合意した（区間の値はedgeごとに一定で、それより細かい値は無い。地図の印は区間の道なりの形の上を距離の割合で動かす）。

## 段階①の調べ

- 区間（`RouteCandidate.segments`）はルートが通るedge 1本につき1つ（`road_graph_engine.py`が`RouteSegmentDetail`を作る）。
  区間ごとに`difficulty`（0〜100、値が無ければnull）と、合計がdifficultyになる軸別の`axis_contributions`、道なりの形・累積距離を持つ。
- 負荷は「値のある区間の距離加重平均（`overall_difficulty`）× 値の無い区間も含めた全長」（`domain/difficulty.py: difficulty_load`）。
  値の無い区間を飛ばして面積を足すと負荷より小さくなる。**値の無い区間を平均の高さで描けば、面積は負荷に一致する**。
- 1ルートあたりの区間数・edge1本の長さは未計測（クラウドの開発DBに道路網が無い）。描画は軸ごとに1本のpathへまとめるので、
  区間数が増えても要素数は軸の数で決まる。

## 実施

- `features/route/DifficultyProfile/`（新設）: 形の計算（区間の柱・軸ごとに積んだ長方形・距離→区間と割合・区間の形の上の点）と
  グラフの部品（SVG。押したまま動かす／矢印・Home・Endで地点を選ぶ）。横軸の右端は一覧の中で最も長い候補の距離。
- 選択は地図で区間を押したときと同じ`selectedRouteSegment`へ入れるので、地図の印と下の区間の詳細は既存の経路で出る。
  グラフは候補の中身の先頭に置き、区間を選んでいる間も残す。
- パネルの内訳バー（`AxisContributionBar`）の高さの倍率（距離）は外した——面積＝負荷はグラフが持つ。一覧の行の小さな帯は
  候補を見比べるために残した。負荷の(i)の説明と設計書（route-settings-and-results.md・page-composition.md）を直した。
