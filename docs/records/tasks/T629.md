# T629. ボタン系CSSの共有コンポーネント化（「地図の見え方」パネル再編と合わせて） 規模L

状態: 起票（2026-09-06）・実装未着手・トリガー待ち

## 背景

T628（「ルート設定」「ルート結果」パネルのボタン系スタイル統一）の対応中、ユーザーから
「ルート結果パネルのCSSを汎化して、下部パネル共通のスタイルにするのはどう？」という
提案があった。検討の結果、`.outcomeHeaderIcon`のような正方形アイコンボタンは共有クラス化
しやすい一方、`.stepperButton`（幅可変+テキスト）・`.legendChip`/`.destinationChip`
（ピル型・複合要素）・`.modeToggle`（セグメントコントロール）は構造自体が異なり、
1つの共通クラスへ寄せようとすると`ui/Button`のような多バリアント部品を新設する規模Lの
リファクタになると判断し、T628では見送った（トークン値[`var(--color-border)`・
`var(--radius-sm)`]の統一のみで済ませた）。

ユーザーの指示: この汎化は単独では行わず、当時3つ目の下部区分だった「地図の見え方」
パネルの再編と合わせて実施すること。単独では今後どう再編されるか未確定なため、
ボタン系CSSの共有コンポーネント化もその再編の一部として一緒に設計する方が手戻りが
少ないという判断だった。

**その再編は既に済み、パネル自体が無くなった**（2026-09-19時点）。役割はレンズが
`LensControl`（地図上部中央のピル）へ、レイヤーのON/OFF・凡例が地図上のチップ
（`MapOverlayControls`）へ移り、下部区分は「ルート設定 / ルート結果」の2つになっている
（`docs/modules/frontend/page-composition.md`参照）。**待っていた出来事はもう起きない**
ため、下のトリガーを書き直した。汎化の必要そのもの（同じ役割の要素が複数ファイルへ
重複している）は残っている。

## 対応方針（未確定、着手時に検討）

- 下部2区分（ルート設定・ルート結果）と地図上のチップ・ピル（`MapOverlayControls`・
  `LensControl`）が使うボタン・チップ系要素を洗い出し、どこまでを共有コンポーネント/
  共有CSSクラスに寄せるか（正方形アイコンボタンのみか、ピル型・セグメントコントロールも
  含めるか）を決める。
- 既存の`ui/Button`（CVA、現状「ルート生成」ボタンのみが使用）を土台に広げるか、
  新しい軽量な共有CSS Modulesにとどめるかは未定。

## トリガー

下部2区分（ルート設定・ルート結果）のどちらかを再編するとき、または同じ役割のボタン・
チップのスタイルが**4ファイル目**へ増えたとき。それまでは着手しない。

当初のトリガー（「地図の見え方」パネルの再編）は、そのパネルが撤去されたことで永久に
発火しなくなっていた（[T943](T943.md)で是正）。

## 保留した場合の影響

着手しない間、T628で揃えたのはトークン値（枠線色・角丸）のみで、実装自体は
`page.module.css`・`RouteForm.module.css`・`RouteSettingsPanel.module.css`の3ファイルに
同じ値が重複したまま残る。将来いずれかのファイルだけトークン値を変更すると、
T628以前と同種の「同じ役割の要素なのに見た目がずれる」不統一が再発しうる
（ただし全箇所がデザイントークン参照になっているため、トークン自体の値を変える限りは
自動的に追従し、今回のような「トークンを使わないハードコード値」由来のずれは起きない）。
