# T850. 標高が、何度作り直しても48件だけ埋まらない

規模M。
状態: 完了（2026-09-14。ユーザー報告「鮮度台帳をつくり直しても未計算が残っている」から）

## 背景

本番で`elevation_attributes`の未生成が5,047,354件中48件残る。`precompute_elevation_
attributes`は行が無いEdgeを毎回すべて対象にする（anti-join）ため、回し直しても残るという
ことは、そのEdgeについて計算しても値が出ていないことを意味する。DEMタイルが無い範囲
（離島・海上にかかる線）か取得失敗が疑わしいが、**原因は未特定**。

「試したが値が出なかった」を記録しないと「まだ試していない」と区別できないため、
[T849](T849.md)のように判定をバッチの対象集合と揃えるだけでは消せない。まず48件が何かを
本番DBで特定するところから。

## 48件の正体（本番DBで特定）

48件は35本のwayに属し、**すべてジオメトリは有効・長さも正**（長さ0のEdgeは1件も無い）。
場所は関東に散らばる（lat 35.12〜35.92 / lon 139.48〜140.72）ため、単一の離島や
未整備地域という説明は当たらなかった。

GSIへ実際に問い合わせたところ、**154点中42点しか標高が返らず、48件のEdgeはどれも
有効点が1点以下**だった（返った値は1.0〜6.6mで、いずれも海抜の低い場所）。
橋・河口・海沿いの線で、**DEMの側に値が無い**（欠測画素`"e"`、または整備区域外の404）。

`compute_elevation_attribute`は有効点が2点未満だと全フィールドNoneのAttributeを返し、
`ElevationAttributeService`はそれを**永続化しない**（[T469](T469.md)。GSIの一時障害を
記録してしまうと、復旧後も二度と再問い合わせされなくなるため）。結果、この48件は
毎回の対象に残り続け、鮮度台帳も「未計算」と数え続けていた。

**行き止まりの構造**: 一時障害と恒久的な欠損が区別できないため、「記録すると障害まで
記録してしまう／記録しないと永久に未計算」のどちらかを選ぶしかなかった。

## 対応と結果

区別できるようにした。`ElevationClient.get_elevations_with_coverage`が地点ごとに
`(標高, 読み切ったか)`を返す——**「読み切った」は、その地点が必要とするタイルをDEMの側から
確かに得たこと**を表し、欠測画素も整備区域外の404も含む。タイルを読めなかった地点だけが
Falseになる。判定は`_tile_grid_cache`に記録があるかで行う（整備区域外は`_CoverageGap`が
Noneとして**記録する**ため、記録の有無で一時障害と分かれる。既にある仕組みを呼び出し側まで
通しただけで、新しい状態は持たない）。

`ElevationAttributeService`は、標高が1つも得られなかったEdgeを:

- 形状点を1点でも読み切れなければ**永続化しない**（T469の挙動をそのまま維持）
- すべて読み切ったうえで値が無ければ`data_source="gsi-dem:no-coverage"`で**永続化する**

ルート生成への影響は無い（値は全てNoneのままで、標高情報無しを許容する既存の設計）。
変わるのは「毎回測り直さなくなる」ことと、鮮度台帳が0になることの2点。

## 検証結果

- **本番で0件になったこと**: バッチ実行後、`elevation_attributes`が無いEdgeは48件→**0件**。
  `data_source`の内訳は`gsi-dem` 5,047,306件 / `gsi-dem:no-coverage` **48件**で、
  「試したが値が無い」ぶんが記録のうえで見分けられる。
- **効いていることの確認**: 「読み切ったか」を常にTrueへ倒す（＝区別しない、直す前と同じ）
  実装に戻すと、`test_coverage_flag_is_false_when_the_tile_could_not_be_read`が落ちる。
  一時障害のEdgeを永続化しない側は`test_one_unreadable_point_keeps_the_edge_out_of_the_records`
  が守る。
- `cd backend && pytest tests -q`（postgis込み）→ 2253 passed、
  `ruff check app scripts benchmarks tests` → All checks passed。

## 残り

本番のbackendは旧コードが動いている（この変更のpushで自動デプロイされる）。既に48件の行は
あるため挙動は変わらないが、**今後新しく取り込んだ道に同じ形のEdgeが現れたときに記録される
のは、デプロイ後**である。
