# T1101. 風の詳細格子の間隔を決まった段階だけに限る許可リストをやめ、下限つきの範囲で受け付ける

状態: 未完了（2026-09-25起票）

## 背景

T1099で、間隔を段階に限る理由として注記が挙げていた「キャッシュ共有」はMSMへの移行（T645）で消えていたと分かった。段階に限る目的を問うたところ（ダッシュボード T1099-spacing-purpose）、答えは「(3) 理由は無い——許可リストをやめ、下限つきの範囲で受け付ける」（2026-09-25）。いま段階に依っているものが3つある: (1)画面はズームの段ごとに宣言の並びから添字で間隔を選ぶ (2)画面は間隔が変わった回だけ前回の値で補うのをやめる (3)backendの許可リスト（WIND_GRID_DETAIL_ALLOWED_SPACINGS_DEG）が間隔の下限になっている。(3)の下限は範囲の検査として残す（点数の上限はT1100で点を作る前に見る形になった）。(1)(2)のfrontend側（windLayer.ts・useWeatherGrid.ts）が段階を前提にしているので、frontendの宣言も合わせて扱う。このタスクのコミットでT1099-spacing-purposeの問いと答えをT1099.mdへ移し、T1099を閉じる（T1099には残りの作業が無い）。規模の根拠: backend 2本とテスト、frontendの読む側2本とそのテストで7以下だが、契約（API・生成物）が変わるので読む側を数えてM。起票案 kihyoan-wind-grid-spacing-range として2026-09-25承認。
