# T1072. 定期確認のフックが本体のチェックアウトの古い道具を動かし、古い判定を黙って出す

状態: 未完了（2026-09-23起票）

## 背景

定期確認のフック（.claude/settings.json の PostToolUse → scripts/orchestration/hook.sh → orchestrate.py check --if-due）は、$CLAUDE_PROJECT_DIR（セッションを始めたディレクトリ＝本体のチェックアウト）の道具を動かす。本体のチェックアウトは master が進んでも手で早送りしない限り古いままで、2026-09-23 17:11 には T1065（状態の表の写しの除去）以前の古い core が走り、移行後の表を読めずに「例: None」と誤表示した。司令塔が本体を手で早送りし続けるのは、同じ道具を本体と master の二か所に持つ二重持ちで、忘れた時点で定期確認が黙って古い判定をする。

対応方針: フックが常に最新の道具で判定する形を設計する。候補（公式文書と実測で確かめてから選ぶ）: (a) フックが司令塔の作業ツリー（状態の表に記録した司令塔のセッションの作業ディレクトリ）の道具を動かす、(b) フックが origin/master の版の道具を読んで動かす（git show で一時ファイルへ、または worktree を使わず git の中から読む）、(c) 本体のチェックアウトが origin/master より古いとき、定期確認が異常として出す（最低限の検知）。本体のチェックアウトを自動で書き換える案は採らない（ユーザーの作業ツリーであり、並行セッションが触りうる）。フック自体（hook.sh）が古い場合の扱いも決める。

完了条件: 本体のチェックアウトを古い版に置いたまま、定期確認が最新の判定を返すこと（または古いことを異常として出すこと）を、壊した入力で確かめる。
