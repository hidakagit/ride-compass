# T1010. 地図の宣言に対する取り決めを決め、検査で固定する

状態: 未完了（2026-09-22起票）

## 背景

[T1007](T1007.md)の全履歴洗い出しで、**文の復旧ではなく「仕様として何を採るか」の判断が
要る**ものが4件出た。いずれも撤去前のコードにだけ根拠があり、現行の宣言
（`frontend/src/features/map/scene/groups/`）はその判断を持たないまま動いている。
判断を決めずに放置すると、次に宣言を足す人が別々の答えを採る。

## 決めること（4件）

**項目2・4はT1001段階Bへ移した（2026-09-23）**。中身は[T1001](T1001.md)「段階Bの進め方」の
「寄せた項目」B-3・B-4にあり、そちらで決める。本タスクに残るのは項目1・3（sceneの宣言
`features/map/scene/groups/`に対する取り決め）。

### 1. 同じ画面に並ぶ点レイヤーで、色を使い回してよいか

撤去前の根拠: 「各カテゴリ群は互いに独立した凡例・レイヤーのため、色の使い回しは
問題にならない（同じ画面で並べて比較されることが無い）」。

現状: `groups/points.ts`の停止要因POIと補給POIが`COLOR_INDIGO`/`COLOR_STONE`/
`COLOR_BLUE`/`COLOR_TEAL`を再利用している。**この2レイヤーは同時にONにでき、同じ画面に
並ぶ**ため、前提が崩れている可能性がある。

判断: (a) 前提は今も成り立つ（同時ONは想定内で、凡例が別なら混同しない）として現状維持、
(b) 同時に出るレイヤー間では色を重複させないルールにして色を割り直す。
(b)なら`groups/declarations.test.ts`へ「同時にONにできるレイヤー間で色が重複しない」を足す。

### 2. レンズ軸を凡例で1カテゴリまで絞れることを許すか（T1001段階Bへ移した）

撤去前の根拠: 「絞り込みで1カテゴリまで狭めた軸を色分けに選べてしまうと単色になり
情報量が無くなる、という混乱があった」。

現状: `page.tsx`のレンズ軸の凡例絞り込みは同一軸に対して効き、1カテゴリまで絞れる。
**あえて許す設計に見える**が、根拠が残っていない。

判断: 許すなら`docs/modules/frontend/static-map-layers.md`へ「許す」と理由を書く。
許さないなら、レンズに選ばれている軸の凡例は最後の1件を落とせないようにする。

### 3. 宣言全体に対する不変条件の検査を、どこまで再設置するか

撤去された`roadStyleModes.test.ts`が持っていた母集団全体への不変条件のうち、
**「全モードの全凡例キーがフィルタ述語を持つ」が復活していない**（色・キーの重複は
`groups/declarations.test.ts`で復活済み）。

判断: 現行の宣言（`ROAD_TRACKS`・`POINT_LAYERS`・軸の段）に対して、
「凡例に出す鍵はすべて、その鍵だけを通す/落とす述語を組み立てられる」を検査するか。
検査するなら`declarations.test.ts`へ足す。**わざと1件落として落ちることを確認してから
完了扱いにする。**

### 4. 同じ判定を2か所へ出すときの入口を一本化するか（T1001段階Bへ移した）

撤去前の根拠: 「この判定を共有する単一の入口にすることで、片方だけ抑制し忘れる
食い違いを防ぐ」（案内文とヘッダーのドットが同じ「ズームが広すぎる」判定を別々に見ていた）。

現状: 「宣言は1つ」という原則は`static-map-layers.md`にあるが、**出し先が2つあるときに
入口を1つにする**という話は別の事実で、どこにも無い。現行に同じ形（同じ判定を案内文と
ドットの両方が別々に評価する）が残っていないかを機械的に列挙してから決める。

## 完了条件

- 残る2件（項目1・3）が「採る／採らない」のどちらかに決まり、採ったものは実装と検査に反映されている
- 採らなかったものは、理由を`docs/modules/frontend/static-map-layers.md`へ現在形で残す
  （「許す」も設計の一部で、書かないと次に同じ議論が起きる）
- 3で検査を足したなら、わざと壊した入力で落ちることを確認した観測値をコミットメッセージへ書く
