# T1010. 標準を「操作別」に見直す（撤去・移設の手順が無い穴を塞ぐ）

状態: 未完了（撤去の手順は追記済み・他の規約の操作別レビューが残り。採番衝突のためT1006から振り直した）

## 背景

[T1001](T1001.md)の段階Aで、`staticAttributeLayers.ts`を丸ごと撤去した際に、そのファイル冒頭にしか
無かった判断基準（「1次の分類は中立色、2次の評価は緑〜赤。混同させない」）が一緒に消えた。
`docs/conventions/comments.md`には削除時の判定木（①経緯か ②他で強制されているか →
該当しなければ`docs/modules/*.md`へ昇格してから削除）が既にあったが、通していない。

実測（`git diff origin/master -- frontend/src`、2026-09-22）: 削除した実装6,142行のうち
コメント1,215行、追加側は3,856行中516行。判断・理由を含む言い回しの行は削除側24・追加側3。

## この穴の性質（列挙して分かったこと）

ルールは**内容別**（コメント・テスト・ログ・キャッシュ・ドキュメント）に並んでいるが、
**操作別**（書く・直す・撤去する・移設する）にどのルールが効くかが定義されていない。
`CLAUDE.md`の「必読」方針と各規約のトリガーを列挙すると、偏りは系統的だった。

| 方針・規約 | 書いてあるトリガー | 撤去を名指ししているか |
|---|---|---|
| ログ方針（logging.md） | コードを追加・変更するとき | していない |
| コメント方針（comments.md） | 新規に書く/変更するコメント | **していなかった**（本タスクで追加） |
| テスト方針（testing.md） | 新しいテストを追加するとき | 「消すべきテストの型」節がある |
| キャッシュ方針（caching.md） | キャッシュを新設・変更するとき | していない |
| ドキュメント記載方針（documentation.md） | 文書を書くとき | していない |
| 修正の原則（CLAUDE.md） | 指摘・不具合を直すとき | **削除を促す規則が4本**（置き換えでなく削除を既定に／死んだものは同じコミットで消す／消したものを見張るテストを足さない／置き換えた側のテストも同時に消す） |

**押す力が4本あって、撤去時に守る手順が0本**という非対称が、この事故の構造である
（例外はtesting.mdだけで、テストにはあるがコード・文には無かった）。

## 塞いだもの（2026-09-22）

1. `CLAUDE.md`コメント方針へ1項目: **撤去のときも同じ方針に従う。コードの撤去と文の撤去は
   別の操作**で、同じスクリプト・同じ一括置換でまとめて落とさない。
2. `docs/conventions/comments.md`の判定木の見出しへ「コードを撤去するとき」を追加し、
   その場で「コードと文を別工程で判定する」理由を1段落で置いた。
3. `CLAUDE.md`「検査器にできず人が見るしかないもの」を2つ→3つへ。3件目として
   「関数・ファイルを撤去するとき、そこにしか無い判断が一緒に消えないか」を追加し、
   母集団の出し方（`git diff`の削除行のうちコメント行）まで書いた。

## 残っている検討（この中で塞がなかったもの）

- **logging.md・caching.md・documentation.md の撤去トリガー**: 同型の事故は今回観測して
  いない。観測なしにルールを足すと「思いつきの規則」になるため、候補として記録に留める。
  同型の損失（消した文書節にしか無い判断が失われる等）を1件でも観測したら、その時点で
  comments.mdと同じ形の項目を足す。
- **検知器にできるか**: 差分（そのコミットで消えた行）を見る検査になるため、
  「検知器は走査範囲を選べない・どの文脈でも同じ答えになる事実だけ扱う」という
  `CLAUDE.md`の条件に合わない。人が見る項目として置いた。

## T1001側でやること（本タスクの範囲外）

段階Aで削除した1,215行のコメントを、上記の判定木へ1件ずつ通して昇格・削除を判定する。
1件目（1次の分類は中立色・2次は評価配色）は`docs/modules/frontend/map-axis-coloring.md`へ
昇格する。
