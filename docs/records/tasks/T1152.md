## 背景

周期レビュー第13回（2026-09-26）の指摘。性質: 検知器の母集団の穴（再発。前回は検査器の新設で直した性質が別の穴から出た）・文書の追従漏れ。backend/tests/structure/test_vacuous_loops.pyはforと絞り込んだ反復対象の組だけ、frontend/src/structure/vacuousLoops.test.tsは.filterを経たfor...ofだけを見る。すり抜け: test_primary_attribute_display.py:119-122、test_derived_data_freshness.py:141-145、test_material_coverage.py:184-187（ループの中のifの下にしかアサーションが無い）、breakpointTools.test.ts:59-60（.filter().every()）、AxisScoringSection.test.tsx:534-536。testing.md:989-1016の共有部品の表にfake_external_log.py・fake_tile_cache.py（2fc880ceで新設）・frontend/src/testing/mapTrace/recordingMap.tsが無い。export_openapi.py:241-243はもう無い手書きの突き合わせを指す。方針: 検査器の条件を「反復対象を絞った後にしか届かないアサーション」へ一般化するか、形の列挙に頼る方式そのものを見直すかを決める。共有部品の表は全件一覧をやめ「tests直下のtest_で始まらないモジュールが共有部品で、用途は各docstring」という導き方にする。

## 対応方針（2026-09-27）

- **一般化を採った**。形の列挙をやめて実行時に数える方式（pytestの`pytest_assertion_pass`・vitestの`expect.hasAssertions()`）は、
  テスト1本の中にアサーションが1つでも走れば通るため、ループ1本が空振りしたことを見分けられない。静的に読む方式のまま、
  条件を「絞り込んだ後の要素にしか届かないアサーション」という性質で書き直した:
  - 要素ごとの検査の母集団を広げた: 本体にアサーションがあるループ（Python `for`、TS `for...of`・`.forEach`）に加え、
    空なら真になる量化（`assert all(...)`・`assert not any(...)`、`expect(xs.every(...)).toBe(true)`・`expect(xs.some(...)).toBe(false)`等）。
  - 絞り込みの読み方を広げた: 反復対象の`filter`・`if`付き内包表記に加え、ループ本体の制御の流れ（`if`の片側だけにアサーション・
    `continue`/`break`/`return`で抜ける）で、ある要素がアサーションへ届かないまま1周を終えられるなら絞り込みとみなす。
    入れ子のループは自分の母集団として別に数える。
  - TSは、母集団を返す引数なしの関数（`const rows = () => xs.filter(...)`）の呼び出しも名前として読む。
- 共有部品の表は全件一覧をやめ、「`backend/tests/`直下の`test_`で始まらないモジュール（`conftest.py`を除く）・
  `frontend/src/testing/`配下が共有部品で、用途は各先頭のdocstring」という導き方にした（全モジュールにdocstringがあることを確認）。
- `export_openapi.py`の古いコメントを、画面がJSONを直接読む今の形へ書き直した。
