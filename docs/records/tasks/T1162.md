## 承認された改善案（段階Bで入れたもの。ダッシュボードから移した。2026-09-26承認）

- **見込み超過で門が閉じたまま**（T1162-gate-overrun）: 18:41、T1143の担当が規模Sの予算19分を超えた（画面のビルド1回5分を含む）。
  問い合わせ（是正の段1）で進んでいると確かめた後も門は閉じたままで、slot-1が空いたのに次（T1165）を振り出せず、門を上書きした
  （18:45、ユーザー承認）。案: ①問い合わせて進みを確かめた担当に「是正済み」の印を付け、その担当の見込み超過では門を閉じない
  ②予算を規模札だけでなく種別（画面のビルドを含む作業）でも分ける。入れないと、画面系の担当がいるたびに空いた枠が数十分遊ぶか、
  司令塔が門を手で上書きする。
- **閉じたタスクの後始末を取り出せない**（T1162-dispatch-reopen）: 18:42、T1124（完了済み）の後始末を振り出し待ちへ積んだが、
  board dispatch pop は記録が「完了」のタスクを取り出さないため、手で振り出した。案: 振り出し待ちの行に「後始末」の印を付けられる
  ようにし、印がある行は記録が完了でも取り出す。
- **sent_at を問いを置く側が書いた**（T1162-dashboard-sent-at）: 19:30、司令塔が先回りの問いを置く担当に「sent_atに書いた時刻を

  （答えかコメントがある件だけを取り込み待ちにする）と pending.py の awaiting_take（sent_atだけでも含む）の定義も食い違っていた。
  また、ArtifactDataのqueryで「answerが空」を条件にすると、answerの項目自体が無い件を拾わず、司令塔が回答待ちの件数をユーザーへ

  そろえ、回答待ちの件数を出す口を足す（手でqueryを組まない）。
- **担当が毎回数分ずつ失う**（T1162-agent-tooling）: 隔離の検査が複合コマンド（cd && git、$(git …)、ヒアドキュメント＋git add）を
  拒否し、担当6人が2〜5分ずつ書き直した。ジョブのログ取得で、GitHubのリダイレクト先へ認証ヘッダが渡り401（github.pyにログを取る口が
  無い）。ディレクトリ単位のeslintを枠の外で回した（Bashの120秒で裏へ回された）。CIを待つスクリプトに短いshaを渡し、ActionsのAPIが
  実行を返さず張り直した（2人）。案: ①github.py にジョブのログを取る関数と、完全なshaでCIを待つ関数を足し、規約で「自前で組み立て

  ③隔離の検査に拒否されにくい書き方を規約の例に足す。

  手で台帳を書く経路は残る（CIはダッシュボードを読めない）ことも規約に書く。承認時にチャットで「番号は今の方式＝承認時にmasterの

## 段階B（道具）で入れたもの

- **是正済みの印**（core.py）: 担当の行に`overrun_ack`（`board set <名前> overrun_ack=now`）。印は現在のタスクの着手より後に付けた
  もので、付けてから同じタスクの予算の分数が経つまでだけ効き、その間はその担当の見込み超過で門を閉じない。`check`は異常に数えず
  「是正済み HH:MM。門は閉じない」と別の行に出す。タスクが替わる（`start_task`）か監査を通すと外れる。付け方・外れ方の根拠:
  問い合わせで確かめたのはその時点の進みだけなので、同じ長さが経ったら確かめ直す。
- **予算の種別分けは見送った**（改善案①の②）。origin/masterの所要の行125件を、記録に「next build・playwright・e2e・本番ビルド」の
  語を含むタスクかで分けると、規模Sは作業p80が語あり44分（8件）・語なし14分（17件）と差があるが、規模Mは語あり37分（6件）・
  語なし34分（10件）で差が無い。語の有無は作業に画面のビルドが入ったかと一致せず（記録が経緯でe2eに触れるだけの件を含む）、
  所要の行には種別の印が無いので、分けた予算は当面実績0件で規模札の予算に戻る。確かめた担当のために空いた枠が遊ぶ問題は是正済みの印で解けるので、
  種別で分けるのは、画面系の担当に是正済みの印を付ける回が続いたとき（所要の行に種別の印を足して測る）に見直す。
  （測り方: scratchpadのスクリプトで `git grep ^所要（並行実行） origin/master -- docs/records/tasks/*.md` を core.parse_effort で読み、
  各タスクの記録を`git show origin/master:...`して語で分け、規模札ごとに80パーセンタイル）
- **後始末の印**（core.py）: 振り出し待ちの行に`cleanup`（`board dispatch push <Txxx> cleanup=true`）。印の行は記録が完了でも
  `board dispatch pop`・`check`の「振り出し待ち」で取り出す（`dispatchable`）。`board dispatch list`は完了の行に
  「後始末なら cleanup=true を付けて積み直す」と添える。`board todo push`の既定の順位を7→8へ（段階Aで順位7に司令塔の準備を入れた）。
- **取り込み待ちの定義**（pending.py）: `needs_take`・`staged`・`awaiting_take`をページのソース（`inIntake`・`isStaged`）と同じ定義へ
  そろえた（答えかコメントが付いていて取り込みがそれより前か無い件。決定はコメントだけ）。`answered_untaken`は置き換えて消した。
  `pending-waiting`を足した（タブごとの件数と、回答待ちの件を優先度の順に。`answer`の項目が無い件も数える）。
- **github.py**: `job_log`（転送先へ認証の見出しを渡さない`request_bytes`で読む）・`failed_job_logs`・`wait_for_ci`（完全な40桁の
  shaだけを受け付け、全ワークフローが終わるまで90秒おきに読み直す）と、`github.py wait|log <sha>`の入口。改善案②（枠の外の重い段を
  監査で見る）は今回の依頼の範囲外（依頼は①③）なので入れていない。
- **new_task.py**: 各件に`--proposal <起票案のdoc_id>`（必須）。最新の`pending-backup`でkind 起票案・answer「承認」を確かめてから
  番号を振り、1件でも確かめられなければfetchもpushもせずに止まる。確保したら「ダッシュボードから消す起票案」を出す。
- CLAUDE.md「作業ツリーの安全」の`new_task.py`の使い方の例に`--proposal`が無い。CLAUDE.mdは担当が書き換えないので、ダッシュボードに
  kind 操作（T1162-claude-md-new-task）として置いた。
