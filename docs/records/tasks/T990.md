## 背景

最大は`docs/modules/backend/routing-engine.md`の33件で、996行のうち594〜930行が、

## 対応方針

母集団は手で持たず、下のスクリプトで導出する（許可リストを持たない。出た件を1件ずつ
実装と突き合わせて判断する）。

```python
# 対象: docs/modules/**/*.md・docs/architecture/**/*.md
# 判定: バッククォートで囲まれた識別子（`_`を含むか CamelCase）のうち、
#        backend/app・backend/scripts・backend/tests・backend/migrations・
#        frontend/src・frontend/e2e・scripts 配下の実ファイル全文に1度も現れないもの
```

1件ごとに、①実装が改名されただけなら新しい名前へ直す、②その仕組み自体が無くなって
いるなら節ごと落とす、③説明として残す価値があるなら識別子を外して挙動の記述にする。

## 母集団の拡張（2026-09-23・周期レビュー第12回で判明）

**`docs/conventions/`・`CLAUDE.md`・`.claude/commands/`を、死んだ識別子の観点で見ている
タスクが1つも無い。** 本タスクの母集団は`docs/modules`＋`docs/architecture`、
[T1016](T1016.md)は`docs/modules`のみで、上の3つはどちらにも入っていない。

第12回で同じ導出を当てたところ、外部語彙を除いて実際に該当するものがあった。分布は
`docs/conventions/caching.md`（撤去済みの遅延構築の関数を、いまも通る経路として説明）、
`docs/conventions/documentation.md`（実例として挙げる定数名・ヘルパ名が実装と違う綴り）、
`docs/conventions/testing.md`（存在しないテスト足場のファイルと関数、存在しないテストの
ヘルパ、現存しないガードの名前を現在形で説明）。

`docs/conventions/`は**規約＝仕事のやり方の取り決め**であり、実装作業者がそのとおりに
動こうとする文書である。存在しないヘルパを「これを使え」と書いている状態は、
`docs/modules`の説明が古いことより直接的に手を止める。

### 母集団（差し替え）

導出スクリプトの対象を次へ広げる:

```
docs/modules/**/*.md・docs/architecture/**/*.md
  ＋ docs/conventions/**/*.md ・ CLAUDE.md ・ .claude/commands/**/*.md
```

判定（バッククォート内の識別子のうち実ファイル全文に1度も現れないもの）と、
1件ごとの処置（①改名なら直す ②仕組みごと無いなら節を落とす ③識別子を外して挙動の
記述にする）は変えない。

**別タスクを立てずに母集団を広げる**のは、判断基準も手順も同じだからである。分けると、
同じ導出スクリプトを2つのタスクが別々に持つことになる。
