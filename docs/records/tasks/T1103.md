# T1103. 地図でルートの線を押しても候補を切り替えない（候補の切り替えは一覧のタブだけ）

状態: 完了（2026-09-25）

## 背景

ユーザー指摘（2026-09-25）: ルート生成後に道を押すと、複数の候補が同じ道を通る所では区間の詳細を見たくても別の候補へ切り替わり使いにくい。承認時の決定: 候補の切り替えは一覧のタブだけにする。選んでいない候補の灰色の線の当たり判定ごと消し、その上を押したときも他の道と同じく下の道の詳細を開く。消す対象の目安: features/map/scene/groups/routes.tsのcandidateHitレイヤーとROUTE_HIT_TARGET_CANDIDATE、MapView.tsxのhandleCandidateClickとonRouteSelectのprop、app/page.tsxのhandleRouteSelectFromMap、それらを使うテスト（page.test.tsx等）と設計書の記述。

## 変更（2026-09-25）

- 未選択候補の線の当たり判定（役割`candidateHit`・`ROUTE_HIT_TARGET_CANDIDATE`）と、押したときの処理（`MapView`の
  `handleCandidateClick`・`onRouteSelect`のprop、`page.tsx`の`handleRouteSelectFromMap`）を消した。候補の線の地物に載せていた
  `routeId`は当たり判定だけが読んでいたので一緒に消した。灰色の線の上を押すと、一般道路網のポップアップ（下の道の詳細）が開く
  ——`MapView`の`handleClick`はルートの当たり判定に当たったときだけ道の詳細を開かないため、当たり判定が無くなれば道へ届く。
- 範囲の出し方: `onRouteSelect`・`ROUTE_HIT_TARGET_CANDIDATE`・`candidateHit`・`handleCandidateClick`・`handleRouteSelectFromMap`・
  `CANDIDATE_HIT`を`frontend/src`・`frontend/e2e`・`docs/modules`・`docs/architecture`でgrepし、変更後は0件。
- テスト: 地図から候補を選ぶことだけを見ていたテスト（`page.test.tsx`の1件と、区間の選択が外れる操作の表の1行、編集中の1組）は消した。
  「見ているパネルの間だけ地図で扱える」の2件（モバイルのシート・デスクトップの畳んだパネル）は、候補の選択の代わりに区間の選択で
  同じ判定（`routeOutcomeActive`）を確かめる形に書き直した。判定を`isMobile ? true : outcomeOpen`へ壊すと、その2件だけが落ちることを見た。
- 撤去したコメント（`候補線を押したらその候補を選ぶ…`・`地図上の候補線を押したときの候補切り替え。`）は、消した挙動そのものの説明で、
  ほかに残す判断は含まない。設計書は`map-axis-coloring.md`（候補は地図では選ばない）と`page-composition.md`（地図で扱えるのは地点・区間）を
  今の挙動へ直した。
