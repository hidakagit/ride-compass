## 背景

## 範囲の導出

性質は「0次条件で決まるはずの値を、条件を通さずに出している経路」。条件を読む入口と地図が塗る値の出所を列挙した（`grep -rn "priority_overrides\|evaluate_axis_scalar\|evaluate_axis_array\|map_value_kind\|_derive_ramp_inputs" backend/app`）。

| 経路 | 対処前 | 対処 |
|---|---|---|
| 区間の内訳・専用way値配信（スカラー） | 一致判定2本のうちスカラー版 | 配列版の判定へ長さ1の配列で通す |
| ルート選び・ルート線・動的軸（配列） | 配列版（不明を持つ真偽の材料で常に偽、真偽の材料に"yes"等で偽の行すべてが一致） | 1本の判定`_priority_override_mask`（`equals`は対応表のキーと同じ`flag_or_value_name`で読む） |
| 地図のramp（タイルの式） | 条件を無視して塗る。畳む参照先の軸の条件も無視 | 0次条件を持つ軸・畳む参照先が持つ軸は`kind="none"` |
| 専用way値配信（難易度） | 配信する材料以外に置いた条件は、材料が無いため常に不一致として塗る | その軸は全道路を落とす（「評価できない値は落とす」既存の規約へそろえる） |
| 符号付き材料の生値（専用配信・ルート線） | 条件を無視して生値を塗る | 0次条件を持つ軸は`difficulty`で塗る（ルート線は`axis_difficulties`を読む） |

書き込み時にも、どの道にも当たらない条件を拒む（`axis_admin.py`）: 数値の材料・軸の点数（値の名前で当たる値が無い）、真偽の材料に"true"/"false"以外、分類の材料に"true"/"false"。これまで受け入れていた「0次条件が軸を参照する」は、軸の点数（数値）と文字列の比較でどの道にも当たらない条件だったため拒む側へ移した。管理画面（軸スタジオ）は0次条件を編集せず素通しするだけなので、画面の操作で新たに拒まれるものは無い。

大文字の"True"・前後の空白を真偽と読む寛容さ（旧実装の`strip().lower()`）はやめ、対応表のキーと同じ読み方1つにした。本番に0次条件を持つ軸は無く、書き込み時に弾くため、読み方の違いで黙って外れる条件は残らない。

範囲外として残したもの:
- 生値（`axis_raw_value_array`）と材料の内訳は0次条件を通さない。これは材料の量そのもので得点ではないため、食い違いではないと判断した。
- 軸スタジオの注記（`frontend/src/features/admin/AxisStudio/AxisMapDisplaySection.tsx`の「材料の一部は、まだ地図表示用のデータ取得経路が用意されていません」）は`kind="none"`の理由を材料の側に決め打ちしている。0次条件で地図に出ない軸（および以前からある符号を畳む軸・13項以上の真偽の軸）では文が事実と合わない。0次条件は画面から編集できず本番に0件のため、ここでは直さない。
