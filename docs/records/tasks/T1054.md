# T1054. 評価軸の表示名を、内部名で画面に出ない形へ一本化する（風の直書きを消す）

状態: 完了（2026-09-23）

## 背景

2026-09-23、T1023で、ルート比較パネルの重み表示だけ風の軸の表示名「風」がコードに直書きされ（理由のコメントは事実と違っていた）、消すと非公開の間は内部名「wind」が出ると分かった。ユーザー指示「直書きを消し、軸定義を参照。かつ、他もwindと物理名で出ないよう、ほかの仕組みと合わせて出なくしてほしい」。表示名を引く経路を列挙し、公開・非公開にかかわらず軸定義の表示名を使う形へ揃える。

## 結果（2026-09-23）

### 母集団と列挙のしかた

**性質**: 「表示名を引けなかったとき、引くのに使った値そのもの（識別子・生の値）で画面の文字を
埋める式」。

**列挙**: `frontend/src`の非テストファイル（`*.test.*`・`__fixtures__/`・`testing/`・
`structure/`・`types/generated/`を除く）を TypeScript の AST で走査し、次の4形を拾った。

1. `M[k] ?? k`・`M[k] || k`（要素アクセスで引き、引いた鍵で埋める）
2. `….label ?? X`・`….name ?? X`（`label`・`name`・`displayName`・`chipLabel`・`title`で終わる
   プロパティで引き、文字列リテラル以外で埋める）
3. `M.get(k) ?? k`（`Map`で引き、引いた鍵で埋める）
4. `c ? M[k] : k`・`c ? M.get(k) : k`（三項演算子で、引けなかった側を鍵で埋める）

3・4は0件だったため、合成した入力（3形それぞれ1件ずつ）を同じ列挙器に通し、3件とも拾うことを
確かめた。backend（`backend/app`）は同じ性質の形（`d.get(k, k)`・`… or <…id>`）をgrepして
利用者向けの表示名の経路に0件（`axis_admin.py`等の例外文言に軸idが入るのは管理APIの
エラーで、管理画面の外へは出ない）。

着手時 17件。

### 何を「内部名」とし、何を外したか（判定の基準）

| 区分 | 基準 | 件数 | 処置 |
|---|---|---|---|
| **内部名** | このアプリが名付け、表示名の宣言と対になるべき識別子（軸id・材料id・一次属性id・分類器が付ける種別・0次フィルタの名前） | 7 | 識別子で埋めない形へ直す（下表） |
| **データ値** | 語彙を外部（OSMの編集者）が決め、対訳表で閉じられない値。対訳が無ければ生値を見せるのが「その値がある」ことを伝える唯一の方法 | 3 | 対象外（`roadFacts.ts`の路面状態・`axisRawValue.ts`の分類材料の値・`AxisScoringSection.tsx`の分類材料の値） |
| **表示名→表示名** | 引けなかったときに埋めるのも表示名（`chipLabel ?? label`） | 5 | 対象外 |
| **埋めない** | 右辺が`null` | 1 | 対象外（`roadFacts.ts`の道路名） |
| **管理画面** | 軸スタジオは物理名を見せるのが目的の画面 | 1 | 対象外（`AxisStudio.tsx`の材料名。実体は`materialCatalogLabel`） |

`materialCatalogLabel`（「論理名 - 物理名」）は、一般の画面の呼び出し（区間クリック詳細）を
論理名だけの`materialCatalogName`へ移し、軸スタジオ専用にした。

### 内部名の7件の処置

| 箇所 | 何が出うるか | 処置 |
|---|---|---|
| `axisLayers.ts: axisLabelsFromCatalogAxes` | 地図表示を持たない軸（`display`がnull）で軸id。`wind: "風"`の直書き | 名前は軸定義の`label`（常にある）から引く。直書きを消した |
| `ComparisonPanel.tsx`の重み表示 | その回の後に非公開になった軸・カタログを取れていない間の軸id | 名前を引けない軸は出さず「ほかN軸」と件数だけ出す |
| `MapView.tsx`の点のポップアップ見出し | 一次属性id | 点の宣言（生成物の一次属性）が持つ`label`を直接使う（引く辞書を経由しない） |
| `pointPopup.ts`の種別 | 分類器が付ける種別（内部名） | 対訳が無ければ「不明」 |
| `HardFilterPanel.tsx`の0次フィルタ名 | フィルタ名（backendが足したが名前をフロントへ書き足していないもの） | 名前をbackendのフィルタの宣言（`domain/hard_filters.py`）と同じ行へ移し、生成物`route-generate-config.json`でキーと一緒に配る。フロントは名前を持たない |
| `axisMaterialsCatalog.ts: materialCatalogName` | 材料id | カタログに無いidは`undefined`を返し、呼び出し側（比較表の行・区間クリック詳細）はその材料を出さない |
| `axisMaterialsCatalog.ts: materialCatalogLabel` | 材料id | 軸スタジオ専用にした（上記） |

0次フィルタの「幹線道路(trunk)」は、名前の中に物理名（OSMのタグ値`trunk`）を含んでいたため
「幹線道路」にした。

**原則を設計書へ置いた**: `design-principles.md` UI仕様「内部名を画面に出さない」。

### 壊した入力での確認（テスト）

| 壊した入力 | テスト |
|---|---|
| 地図表示を持たない軸（`display: null`） | `axisLayers.test.ts`: 名前は軸定義の`label`で、軸idが値に現れない |
| 名前を引けない軸を含む重み | `ComparisonPanel.test.tsx`: 軸idが出ず「ほか1軸」 |
| カタログに無い材料id | `ComparisonPanel.test.tsx`: その行が出ない。`page.test.tsx`: 区間クリック詳細が材料idではなく名前で出る |
| 対訳の無い種別 | `pointPopup.test.ts`: 「不明」 |

0次フィルタは、名前の無いフィルタを宣言できない形（`HighwayHardFilter`・`TagHardFilter`が
`label`を必須で持つ）にしたため、壊した入力を作れない——テストではなく型が守る。

### 見積もりとのずれ

台帳の見立ては規模S（1時間以内）。依頼時に規模Mへ引き上げられた。0次フィルタの名前をbackendの宣言へ移す分と、一般の画面の材料名を論理名だけへ寄せる分が、起票時の見立て（風の直書きと比較表）より広い。所要は計測していない。
