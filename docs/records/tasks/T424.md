# T424. 材料カタログ0件時にAxisComposer（軸スタジオ）がクラッシュする不具合を修正 規模S

状態: 完了（2026-08-30）

- 背景: 2026-08-30に実施したゼロベース網羅レビュー（`review-zero-base`ワークツリー、
  masterのfull-tree 839ファイル・約14万行を9領域へ分割し各領域を専用エージェントが
  8観点でレビュー、全指摘は[docs/zero-base-review-2026-08-30.md](../zero-base-review-2026-08-30.md)
  §9参照）で検出。唯一のP0（重大）指摘。他の指摘（P1×12件・P2/P3×72件）は
  [T425](T425.md)・[T426](T426.md)を参照。
- 指摘内容: `frontend/src/components/AxisStudio/AxisComposer.tsx`の`emptyDraft()`・
  `draftFromExisting()`（321・328・351-352・806-807・924行目）が`materialOptions[0].id`を
  無条件参照しており、`materialOptions`が空配列のときマウント直後に`TypeError`で
  クラッシュする。918-926行目の「材料を追加」ボタンのフォールバック
  （`termOptions[0]?.id ?? materialOptions[0].id`）にも同じ無ガード参照が残っている。
- 発生条件: 呼び出し元`useMaterialCatalog()`（`frontend/src/hooks/useMaterialCatalog.ts`）は
  2026-08-25の修正で「取得成功したがmaterialsが0件」の場合、静的フォールバックへ留まらず
  **空配列をそのままsetMaterials**するよう仕様変更済み。backend側`material_catalog.py`が
  運用上の何らかの理由（材料レジストリ空・DB接続不調時の空応答等）で0件を返すと即座に発生する。
- 影響: 軸スタジオ（`/admin`）の新規作成・既存軸の編集モーダルどちらも開けなくなる。
  エラー表示すら出ないため原因特定が難しい。
- 対応方針（未検討）: `materialOptions`が空の場合は早期にエラー/空状態UIへフォールバックし、
  `materialOptions[0].id`への無条件アクセスを排除する。918-926行目のフォールバックも
  合わせて修正すること。修正後、`useMaterialCatalog`が空配列を返すケースを再現するテストを
  追加する。

## 実装内容（2026-08-30）

- `frontend/src/components/AxisStudio/AxisComposer.tsx`の4箇所すべてで
  `materialOptions[0].id`の無条件アクセスを`materialOptions[0]?.id ?? ""`（optional
  chaining + 空文字列フォールバック）へ置き換えた:
  - `emptyDraft()`内の`firstBoolean`算出（旧321行目）
  - `emptyDraft()`内の`terms`初期値（旧328行目）
  - シェイプ種別カード切り替え時の`firstMaterial`算出（旧806-807行目、
    「かけあわせ評価」→「なめらか評価」へ戻したときの材料フォールバック）
  - 「材料を追加」ボタンの`fallback`算出（旧924行目）
  - `draftFromExisting()`は内部で`emptyDraft()`を呼ぶ構造のため、上記の修正で
    連鎖的に安全になる（旧351-352行目自体に無条件アクセスは無かった）。
- 上記の空文字列フォールバックは「クラッシュしないための最終防御線」であり、実際に
  空文字列のmaterial idを含むdraftをユーザーに見せることは意図していない。
  `AxisComposer`本体（全フックの呼び出し後、Rules of Hooksに反しない位置）に
  `materialOptions.length === 0`の早期リターンを追加し、この場合はウィザード本体の
  代わりに「材料カタログを取得できませんでした（0件の応答）。時間をおいて再度開くか、
  backend側の材料カタログ（material_catalog.py）の状態を確認してください。」という
  エラーメッセージと「閉じる」ボタン（`onCancelEdit`を呼ぶ）だけを表示するフォールバック
  UIへ切り替えるようにした。
- テスト: `frontend/src/components/AxisStudio/AxisComposer.emptyMaterialCatalog.test.tsx`
  を新規追加（既存の`AxisComposer.test.tsx`・`AxisComposer.materialValues.test.tsx`と
  同じ「ファイルごとにgetMaterialCatalogのモック方針を変える」流儀で分離）。
  `getMaterialCatalog`を`{ materials: [] }`で解決するようモックし、(1)新規作成モード・
  (2)編集モード(`draftFromExisting`経由)のどちらでもマウント直後にクラッシュせず
  空状態エラーメッセージへフォールバックすること、(3)「閉じる」ボタンで`onCancelEdit`が
  呼ばれることを検証する3件のテストを追加した。
