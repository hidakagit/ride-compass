# T786. GPX出力の間引きで細かい曲がりが消える

規模S。
状態: 完了（2026-09-13）

## 背景

実走後のユーザー報告「gpx出力して他ナビに読み込ませたところ、道が繋がっていないように
見える場所があった。出力点と点の間隔よりも狭い曲道が無視されて、道もないのに直線に
つながれていた」。

`frontend/src/lib/gpxExport.ts: decimateCoordinates`は`stride = ceil(点数 / 上限)`の
等間隔ストライドでn点ごとに拾っていた。残す点を折れ線の形から選ばないため、ストライドより
短い区間に収まった曲がりは前後の点ごと落ち、直線で結ばれる。

## 対応

`simplifyCoordinates`（Ramer–Douglas–Peucker）へ置き換えた。両端を結んだ線分から許容ずれ
以上離れる点を残し、その点で区間を割って繰り返す。許容ずれは3mから始め、`MAX_GPX_TRACK_
POINTS`（1000点、Suunto互換のため維持）に収まるまで倍にする。

垂線距離は緯度経度のままでは測れない（日本では経度1度が緯度1度の約0.81倍で、東西の
曲がりだけが過大評価される）ため、座標列の中央緯度を基準にした局所平面へ落としてから測る。

simplify-jsのような既成ライブラリも検討したが、いずれも平面座標が前提で上記の射影を
呼び出し側で用意する必要があり、残りは20行程度のため依存を増やさず自前で書いた。

## 検証

**実データ**（dev DB・都心bbox内のroad_edgesをランダムに拾って25.2km相当＝1453点、
平均点間隔23.6mに連結したもの）で、元の折れ線からの最大ずれを測った:

| 方式 | 間引き後の点数 | 最大ずれ |
|---|---|---|
| 旧（等間隔ストライド） | 727 | **116.6m** |
| 新（形状ベース） | 846 | 3.0m |

旧方式は`stride`が整数のため1453点を727点まで落としており、上限1000点に対して削りすぎでも
あった。116.6mのずれが報告された「道もないのに直線につながれている」状態にあたる。

**回帰テスト**（`gpxExport.test.ts`）を2件足した。どちらも旧実装で落ちることを確認して
から実装を差し替えた（旧実装での実測値: 張り出しの頂点が結果に含まれない／最大ずれ33.4m）。

- 残る点の間隔より短い区間に収まった曲がりを潰さない（張り出しの頂点が結果に残る）
- 間引き後の折れ線が元の折れ線から大きく離れない（最大ずれ10m未満）

2件目の最大ずれは、実装と同じ計算を共有すると実装の誤りごと通ってしまうため、テスト側で
独立に測っている。
