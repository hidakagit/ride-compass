# T816. 設計原則「消さずに薄くする」の適用範囲を、T783のユーザー判断に合わせる

規模S。
状態: 完了（2026-09-14。統合レビュー第8回のP1、2026-09-13起票）

## 背景

`docs/design-principles.md:135`が「消さずに薄くする……重み0の軸は薄いチップとして同じ並びに
残し、詳細を開く操作だけを持たせない」と書いているが、実装は重み0の軸をチップごと落とす
（`components/RouteAxisProfile/AxisContributionBar.tsx:77`のfilter）。

[T783](T783.md)が「評価に使っていない軸（重み0＝詳細を持たない軸）のチップは**出さない**。
薄く残す扱い（[T776](T776.md)）は**ユーザー判断で撤回した**」と明記しており、
`RouteAxisProfile.test.tsx:63`が現行挙動を固定している。つまり**実装とテストが正で、
正本のドキュメントだけが撤回前のまま**。

同じ古い主張が`docs/modules/frontend/route-settings-and-results.md:235-240`・
`AxisContributionBar.tsx:25`（`legendAxes`・`renderDetail`のprop説明）・
`RouteAxisProfile.tsx:79-81`にも残っている。

CLAUDE.mdが`docs/design-principles.md`を「設計原則の唯一の正本（常に最新）」と指定している
ため、実害は**次に軸まわりのUIを作る人がユーザーが撤回した挙動を復活させる**こと。

## 対応と結果

**ユーザー判断: 原則そのものは残し、適用範囲からルート結果の軸内訳を外す**（2026-09-14）。
「消さずに薄くする」はレンズの一覧（未使用の軸も選べる形で並べる）・ルート設定の重み配分
（重み0の軸もチップとして残す）では現に生きており、撤回されたのはルート結果の内訳に
ついてだけ、という実態に合わせた。

`design-principles.md`へ例外を明記した——**内訳は候補ごとに縦へ伸びるため、使っていない軸まで
並べると狭い幅で「このルートで何が効いたか」が読めなくなる**。軸の全体像は設定側が持ち、
結果側は絞った一覧を出す。

撤回前の主張が残っていた`page-composition.md`・`RouteAxisProfile.tsx`・
`AxisContributionBar.tsx`（`legendAxes`・`renderDetail`のprop説明）を揃えた
（`route-settings-and-results.md`の分は[T822](T822.md)で先に直している）。

### `legendAxes`の存在理由をテストで固定した

「重み0の軸は出さない」（[T783](T783.md)）と「寄与が0・欠損の軸は残す」は別の話で、後者の
ためだけに`legendAxes`がある。効くはずの軸が効かなかったことも判断材料のため、帯グラフ
（`axes`）には出ない軸を凡例には残す。呼び出し側（`RouteAxisProfile`）と部品側
（`AxisContributionBar`）の両方へテストを足した。

## 検証結果

- **テストが効いていること**: `RouteAxisProfile`から`legendAxes`の受け渡しを外すと、
  新しい「重みはあるが寄与が0・欠損の軸もチップに残す」と既存の「重みが入っていれば、
  寄与の値が来ない軸のチップも押せる」が落ちる。
- `npx vitest run src/components/RouteAxisProfile/` → 39 passed。
- `python scripts/review_checks.py docs --staged` → 違反なし。
