# T950. 検知器基盤の残り（T936の射程の外） 規模S〜M

状態: 完了（2026-09-19起票・完了、統合レビュー第11回のP2/P3）

## 背景

[T936](T936.md)が扱う母集団・記法・GAPの強制以外の残り。対象は[history/2026-09-19_all.md](../../../.claude/commands/review/history/2026-09-19_all.md)「Findings（P2）」の
「検知器・レビュー基盤」節のうち41〜45と、P3の「参考表示7検知器がmutateの対象外」。

- `cmd_metrics`が`scripts/`を除外したまま（`cmd_size`だけ直っている）。リポジトリ最大の単一ファイルが
  メトリクス履歴に一切現れない
- `docs/modules/README.md`が`scripts/`を「扱わない領域」にも挙げておらず、3,952行が設計書の担当を
  持たない宙吊り状態
- `check_task_numbering`と`check_plan_vs_tasks`が見出し番号照合の**完全に同一のコード**を持ち、
  片方を直してもう片方を直し忘れても全テストが緑のまま通る
- `deploy-backend.yml`のbenchmarkガード主張が実態と違う（`require_current_revision()`を呼ぶのは
  `run_all.py`だけで、個別実行のベンチには効かない）
- `traffic.py`の経緯コメントがMarkdownリンク形式で`source_narrative`をすり抜ける

## 対応（2026-09-19）

### 41: `metrics`と`size`が別の母集団を見ていた

`measured_line_counts()`を唯一の定義元にし、両方がそこから取る形へ変えた。`metrics`側には
「レビュー基盤（行）」の1行を足している。**`review_checks.py`は4,265行でリポジトリ最大の
単一ファイル**（次点は`MapView.tsx`の3,406行）でありながら、メトリクス履歴に一度も
現れていなかった。

### 42: `scripts/`が設計書の担当を持たない

`docs/modules/README.md`「このディレクトリが扱わない領域」へ1行足し、正本
（`review/README.md`と`DETECTOR_ENFORCEMENT`）を示した。対象ファイル表の母集団にも
入らないこと（アプリではなくアプリを検査する側であること）を併せて書いている。

### 43: 見出し番号照合の二重実装

`task_heading_violations()`へ抽出し、呼ぶのは`check_task_numbering`だけにした
（`check_plan_vs_tasks`の写しは削除。そちらの担当は台帳の`[x]`と「状態:」行の照合）。

### 44: ベンチのガード主張が実態と違う

止めていたのは`run_all`だけで、タスクエントリへ「実測」として引かれる数字の多くは個別の
`bench_*`から出ている。個別実行の口すべてに`announce_revision()`を入れ、**どのコードを
測ったかは必ず出力へ残す**形にした。止めはしない——個別モジュールは手元の反復でも使うため、
配信元と違うコミットなら警告に留める（まとめて走らせる`run_all`の hard stop はそのまま）。

母集団は`benchmarks/`の実行口（`__main__`を持つモジュール）から導き、素性を出さない口が
1つでもあればテストが落ちる（`tests/test_benchmark_revision.py`）。実行口が0件のときも
落とす——導出が空振りしても静かに通るため。

### 45: Markdownリンク形式の経緯コメント

`tasks/Txxx.md`を指すだけのコメントも、指した先が実態と食い違ったときに追従されない
（docs/conventions/comments.md「書いてはいけないコメント」②）。**ソース専用の**
`SOURCE_NARRATIVE_PATTERN`へこの綴りを足した。docs/modules側と共有する
`NARRATIVE_PATTERN`へは足さない——README「記載粒度」節がリンクを1本まで許容しており、
足すとその許容が記載粒度違反に化ける。

広げた影響の実測（`find_source_narrative_violations`を新旧のパターンで走らせた結果）:

| | 母集団内（`is_impl_file`） | 母集団外（scripts/・backend/scripts/・backend/tests/・backend/benchmarks/・frontend/e2e/の226ファイル） |
|---|---:|---:|
| 旧 | 60件 | 767件 |
| 新 | 105件 | 829件 |

増えた45件は**すべて既存分**で、全件スキャンの参考表示に載るだけ（強制は`--staged`/`--since`
の追加行のみ）。既存分の一掃は[T567](T567.md)の担当という切り分けを変えていない。
`EDGE_GAP_NOTES`の比率（12.75倍→7.9倍）も測り直して更新した。`traffic.py`の当該コメントは
経緯を落とし、現在も成り立つ制約（自転車道・歩道は階級表に無く0になる）だけを残した。

### P3: 参考表示のみの検知器が`mutate`の対象外

参考表示は件数0でもexit 0のため、強制する検知器と同じ「落ちるか」では試せない。
**違反を1件作り、その1件が出力へ現れるか**を見る形にした（`guard_probe_reference_mutations`・
`probe_reference_detector`）。目印はその1件だけが持つ綴りにする——件数の比較では、既存の
参考件数に紛れて検知器が黙っていても通る。配線されている経路は検知器ごとに違うため、
節がある最初の経路（pre-commit→CI→全件）で判定する。

レビューは7件と数えていたが、[T943](T943.md)の`stale_task_premises`が加わって8件になっていた。

**この仕組みを入れて最初に分かったのは、既にあった`undeclared_dead_refs_exempted`の
違反の作り方が一度も成立していなかったこと。** 撤去の断りと断られていない名前を1行へ
書いており、その行自体が「断りの行」として母集団から除かれていた。`--case`でしか
試せない状態だったため、書いた時点から誰も回していなかった。

## 検証

| わざと戻した内容 | 落ちた/鳴ったもの |
|---|---|
| `cmd_metrics`が自前で母集団を組み立てる | `test_size_and_metrics_look_at_the_same_population` |
| タスクの見出し番号をファイル名とずらす | `task_numbering`（共有関数経由で鳴る） |
| コメントへ`docs/records/tasks/T800.md`へのMarkdownリンクを書く | `source_narrative` |
| ベンチ1本から`announce_revision()`を外す | `test_every_benchmark_entry_states_which_revision_it_measured` |

`python scripts/review_checks.py mutate` 全件: 正例58件すべてPASS・外縁25件すべて期待どおり・
参考表示8件すべてREF-PASS、exit 0。所要は開発機（Windows）で11分39秒。参考表示のぶんの増加は
約1.5分で、その大半は`stale_task_premises`（全件スキャンにしか無く、pickaxeで25秒かかる
検知器）が占める。1検知器につき1回の実行で済ませる（件数比較ではなく目印で見る）設計に
したのはこのため。

`python scripts/review_checks.py docs` 違反なし（`--staged`も違反なし）。backend
`ruff check app scripts benchmarks tests`クリーン、`pytest -q -m "not postgis"` 2,122 passed。

`pytest -m postgis`は323 passed / 4 failed だったが、**4件とも共有テストDBの競合**で、
単独実行では4件とも7秒でパスした（全体実行時は6分15秒かかっており、別プロセスがDBを
掴んでいた）。落ちたのは軸レジストリ2件・事故取込1件・道路ノード次数1件で、本タスクが
触った範囲（`scripts/`・`backend/benchmarks/`・`traffic.py`のコメント1行）とは接点が無い。

`scripts/tests/test_review_checks.py` 152 passed / 1 failed——
`test_npx_cli_path_finds_it_next_to_the_resolved_npm_cli`はWindowsのシンボリックリンク権限で
落ちる既存の環境依存で、本タスクの変更とは無関係。frontendは変更なし。
