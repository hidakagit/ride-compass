# T1084. 軸スタジオの段階プレビューの「N段階になります」が、地図で落ちる値も段として数えている

状態: 完了（2026-09-23起票、2026-09-23完了）

## 背景

T957（ユーザー決定: しきい値の入力欄の横に地図では効かない値を名指しする。26f55215）の担当が挙げた範囲外の不一致1（ユーザー決定 2026-09-23: 起票する）。折れ線が同じ難易度へ写す境界は地図で段にならない（backend/app/domain/axis_display.py の _map_band_thresholds、T939）。軸スタジオの段階プレビューの見出し「N段階になります」はこの落ちる値も数えるため、印は出ても段数は地図より多いまま表示される。やること: 見出しの段数を、T957で新設した判定（thresholds_the_map_drops、POST /api/admin/axis-definitions/preview-display-thresholds）の結果から数え直し、地図の段数と一致させる。フロントに判定を写さない。完了条件: 落ちる値を含むしきい値で、見出しの段数が地図の凡例の段数と一致することを、入力に対するあるべき値のテストで示す。frontend/e2e/ と playwright.config.ts はユーザーの別セッション（T1078）が作り直し中なので触らない。

## 実施内容（2026-09-23）

### 方針

段階プレビュー（`AxisMapDisplaySection.tsx: renderBandPreview`）の見出しだけでなく、並び・色・
aria-labelもまとめて、**地図が段として作る境界**（入力から、T957の判定
`thresholds_the_map_drops`が返した値を除いたもの）で組み立てる。見出しだけ数え直すと、
見出しは5段階・並びは7行という別の食い違いが画面の中にできるため。規則はフロントへ写さず、
backendが返した「落ちる値」を入力から除くだけの`axisDraft.ts: thresholdsKeptOnMap`を置いた。
[T1085](T1085.md)（体感ラベルの件数）も同じ「地図が作る境界」から段数を数えれば揃うため、
置き場を`resizeBandLabels`の隣にした。

判定の結果が届くまで（デバウンス中・取得失敗時）は、印と同じく「落ちる値なし」として入力
どおりの段で出る。ⓘの説明文は「下の段階は地図ではこの値の分だけ減ります」から「下の段階は
この値を除いた地図の段で出しています」へ直した。

### 副作用（T1085の範囲、直していない）

プレビューの体感ラベルは地図と同じ`bandLabelsForBandCount`を通すため、値が落ちると
ラベルの件数（入力の件数+1）が段数と合わず、プレビューからもラベルが消える。これまでは
プレビューにだけラベルが出て地図では消えていたので、プレビューが地図と同じ見え方になった
ことになる。ラベルが残るようにするのは[T1085](T1085.md)。
