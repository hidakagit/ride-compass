# T1186. 画面から backend を呼ぶ部分を openapi-fetch へ置き換え、応答の型を API の定義から自動で決める

状態: 完了（2026-09-27起票、2026-09-27完了）

## 背景

起票案 proposal-std-openapi-fetch（2026-09-27承認。標準の道具の棚卸し・T1152の担当から）。規模M（根拠: API を呼ぶ本番のファイルが12本（grepで実測）、テストを足して20本以下の見込み）

■ 背景（画面に出ない、画面側の内部の話）
画面側は backend の API 定義から型を生成している（openapi-typescript）。パスの綴りは lib/apiPath.ts で API 定義と突き合わせているが、応答の型は呼び出しごとに手で書いている（例: 管理画面の API 呼び出しだけで22か所）。backend の応答の形が変わっても、手で書いた型は追従せず、型検査で気づけない。openapi-fetch は openapi-typescript と対になる部品で、パス・メソッド・クエリ・応答の型を API 定義から推論する。比べた記録はどこにも無い。

■ やること
lib/fetchJson.ts の骨格（通信のログ・x-request-id・タイムアウトと通信エラーの区別・日本語の文言・422 の詳細の整形）は openapi-fetch の middleware として残し、呼び出し側を置き換える。apiPath.ts とそのテストは要らなくなる。摩擦: 既定値のある項目が任意扱いになる型の補正（types/route.ts の Required<>）を、推論した型にも掛ける必要がある。管理画面の接頭辞の差し替えは middleware で行う。見込み 実装 約−100〜−150行、テスト 約−30〜−60行。依存が1本増える。
データ取得の骨格を TanStack Query へ置き換える起票案と同じ呼び出し口を触るので、両方承認されたら順番を決める（こちらを先にすると、TanStack Query 側は型付きの呼び出しをそのまま使える）。

■ なぜ既存のタスクに入らないか
T1145 は写しの型（軸カタログの行を手書きの型4つへ写している）を含むが、範囲はその4つで、API 呼び出しの型付けの方式は含まない。

## 判断（品質で決めたもの）

- **openapi-fetchは0.16系に留める**（`^0.16.0`）。0.17.0で入れて`tsc --noEmit`を回すと、`AxisStudio.tsx`・
  `useMaterialDistribution.ts`・`useAxisCatalog.ts`等で落ちた。0.17.0の型の変換（`openapi-typescript-helpers`の
  `Readable`）が配列の要素を取り出して配列へ戻すため、契約のタプル（`[number, number][]`）が`number[][]`になる。
  上流の報告は[#2632](https://github.com/openapi-ts/openapi-typescript/issues/2632)（2026-02-19起票、直すPR #2673・#2842は未取り込み）。
  0.16.0はこの変換を持たず、実行時の実装の差は長さ0の応答の判定1行だけ（配布物の`dist/index.mjs`を比べた）。
  上げられない理由は`docs/architecture/tech-stack.md`へ書いた。
- **ライセンスと保守**: openapi-fetch・openapi-typescript-helpersともMIT（npmの`package.json`）。リポジトリは
  openapi-ts/openapi-typescript（スター8.4k、commit 1,679、openapi-typescriptと同じリポジトリ）。上の型の後退が7か月
  取り込まれていないので、保守は「動いているが速くはない」。実行時の実装は小さく（`dist/index.mjs`531行）、このアプリが
  頼るのは`createClient`・middleware・既定の直列化だけ。
- **管理画面の接頭辞は、実行時に書き換えず型で外す**（記録の「middlewareで差し替える」から変えた）。openapi-fetchの
  middlewareが要求を差し替えるには新しい`Request`を作り直すしかなく、本文をストリームのまま渡し直すと`duplex`の扱いが
  実行環境で揃わない。代わりに`paths`から`/api/admin`で始まるものを抜いて接頭辞を外した型（`AdminPaths`）で
  `baseUrl: "/admin/api"`のクライアントを作った。backendのパスが変われば型検査で落ちる点は同じで、実行時の書き換えが無い。
- **骨格は呼び出しを包む関数（`requestApi`）＋呼び出しごとのmiddleware**。待ち時間・カテゴリ・文言は呼び出しごとに違うので、
  クライアント全体のmiddlewareではなく、呼び出しの第2引数に`signal`とmiddlewareを渡す。通信の失敗は`onError`で日本語へ
  包み直し、`onResponse`で応答が届いたことを記録して、その後の例外を本文の解析の失敗として見分ける。HTTPの失敗は
  openapi-fetchが例外にせず`error`で返すので、骨格が`detail`から文言を作って投げる。
- **応答の形が契約に無い口は`fetchJson(url)`に残す**（中身は同じ骨格を型の無いクライアントで通す）。
- **`Required<>`の補正**: 生成のジョブの状態だけが補正した型（`types/route.ts`）を読むので、`routeApi.ts`で推論した応答を
  その型へ当てはめる1か所にした。他の呼び出しは推論した型をそのまま返す。
- **問い合わせの空文字**: 旧`apiQuery`は空文字の項目を落としていたが、openapi-fetchは付ける。空文字を渡していた呼ぶ側は
  無かった（ログの絞り込みは呼ぶ側が`trim() || undefined`にしている）ので、落とす処理は持たない。
- **テストの`fetch`**: openapi-fetchは作った時点の`globalThis.fetch`を握るので、呼ぶたびに引く関数を渡した（テストの
  `vi.stubGlobal`が届く）。相対パスの口（管理API・`/api/version`）を呼ぶ`app/admin/adminApi.test.ts`は、ブラウザと同じく
  相対パスを解決できるDOMの環境（happy-dom）で回すよう`@vitest-environment node`を外した。

## 実施

- 依存: `openapi-fetch@^0.16.0`（推移で`openapi-typescript-helpers@0.0.15`）。`package-lock.json`が変わる。
- `lib/fetchJson.ts`→`lib/apiClient.ts`: 呼び出し口（`backendApi`・`adminApiClient`）と骨格（`requestApi`・`getOptions`・`fetchJson`）。
  `requestJson`・`requestOk`は消した。
- 呼び出し側（`features/admin/adminApi.ts`・`services/weatherApi.ts`・`services/regionApi.ts`・`services/axisCatalogApi.ts`・
  `features/route/routeApi.ts`・`features/map/layers/jmaDelivery.ts`）: パスと応答の型の手書きを消し、推論に任せた。
  管理画面の区間の値の`encodeURIComponent`はopenapi-fetchが持つので消した。
- `lib/apiPath.ts`: `apiQuery`・`ApiQuery`・`DeclaredApiPath`・`ApiPath`を消し、アプリ自身が呼ばないURLの組み立てだけにした。
- 推論で型が絞れたもの: 分布の取得の形（`useAxisValueDistribution`の`shapeForRequest`）を`unknown`から`AxisShape`にした。
- 参照が0になったもの: `types/weather.ts`の`WeatherWarnings`・`WbgtStatus`・`FloodForecasts`、`types/route.ts`の
  `RouteGenerateJobCreatedResponse`、`testing/fetchMocks.ts`（テストは本物の`Response`を返す）。
- 文書: `docs/modules/frontend/page-composition.md`（呼び出しの節を書き直し）・`axis-studio.md`・`docs/conventions/logging.md`・
  `docs/architecture/tech-stack.md`（採用の表と0.16系に留める理由）。

## 範囲外で見つけたもの

- `types/route.ts`の`Required<>`は、backendが出すOpenAPIで既定値付きの項目が任意になることの補正。pydanticの
  `json_schema_serialization_defaults_required`等で出力側のスキーマを必須にすれば、補正と`routeApi.ts`の当てはめが消える。
  backendの契約の出し方の変更で、このタスクの範囲外。直さずに最終報告で司令塔へ渡した（起票するかは司令塔が決める）。
