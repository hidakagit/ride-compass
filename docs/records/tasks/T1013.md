# T1013. 撤去で根拠を失った5つの制約を、現行に照らして残すか外すか決める

状態: 未完了（2026-09-22起票）

## 背景

[T1011](T1011.md)の全履歴洗い出しで、**制約の文だけが現行に残り、それを成立させていた
機構・検査が撤去済み**というものが5件出た。文を戻す／捨てるの判断ではなく、
「その制約が今も成り立つか」を現行コードで確かめないと決まらない。

放置するとどちらへも転ぶ: 成り立たない制約を守り続けて無駄な形を保つか、
生きている制約を「残骸だ」と見なして外し、静かに壊すか。

## 判定するもの（5件）

各件とも手順は同じ——**①その制約が守られている箇所を機械的に列挙する → ②守らなかったら
何が起きるかを現行のコードで確かめる → ③生きているなら現在形の1文へ、死んでいるなら
文ごと外す**。③で「生きている」と判断したものは、可能なら検査で固定する。

### 1. `lib/evaluationAxes.ts` のキー照合ガード

現行コメントは「index signature型のためコンパイル時のキー照合はできず、代わりに
テストが`axis-catalog.json`の`preference_defaults`とキー集合を突き合わせる」と書いていたが、
そのテストは撤去済み（名指しは[T1011](T1011.md)で外した）。制約（型で照合できない）自体は
今も真。**ガードを置き直すか、照合が要らない形へ変えるか**。

### 2. 上書きOFF時の送信契約

撤去前の記述: 「実際にリクエストへ乗るのは上書きONの間だけで、OFFの間は
`scoring_weights`/`route_preference`を省略しbackendのYAML既定値が使われる」。
フロント側のミラー定数は消えたが、**契約自体は今も生きているはず**。
どこまでフロントに残す価値があるか（契約を書くか、テストで固定するか、何もしないか）。

### 3. `mapStyleOps.ts` の「レイヤーを1枚も足していない時点で呼ぶ」制約

現行docstringは「後から呼ぶと、自分で足した線レイヤーが最長の連なりを伸ばし、差し込み位置が
地名側へずれる」と書くが、**現在の`areaLayerAnchorId`は並び順ではなく
`source-layer === "transportation"`の最初のレイヤーを返す実装**で、同じファイルが
「並び順から導いてはいけない」と明記している。アプリ側レイヤーの`source-layer`は
`transportation`を名乗らない。理由が旧方式の残骸に見える。
**呼ぶタイミングの制約自体が今も要るのか、要るなら理由は何か。**

### 4. 「線のレイヤーを先に積めない」理由

撤去前の記述: 「線のレイヤーは路面ソースを共有するため、先に積むと`source not found`になる」。
現行は各レイヤーが自分でソースを用意する設計（順序に頼らない）へ変わっており、
**設計変更で無効化された可能性が高い**。成り立たないなら、順序の話が残っている箇所を
機械的に列挙して外す。

### 5. `Disclosure`（Radix Accordion）のクリック方法

現行`Disclosure.tsx`のdocstringは生DOMの`.click()`を勧め、**撤去されたテストのコメントは
逆に`fireEvent.click`（`act()`で包まれる）を使えと書いていた**。しかもdocstringが挙げる
参照先テストは現存しない。どちらが正しいかを現行のテストで確かめ、docstringを直す。
（`docs/modules/frontend/frontend-design-system.md`「6. テストパターン」が正本側。）

## 完了条件

- 5件それぞれについて、**列挙したコマンドと観測値**が本ファイルに残っている
- 生きている制約は現在形の1文になり、可能なものは検査で固定されている
- 死んでいる制約は、それを述べた文と、それに従うためだけに残っていた形の両方が消えている
