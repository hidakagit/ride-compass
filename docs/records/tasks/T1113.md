# T1113. クラウドのセッションを再開したとき、前の回の古いpidファイルに邪魔されずにDBが起動する

状態: 未完了（2026-09-26起票）

## 背景

T989の後片付け中（2026-09-25）、クラウドのセッションの再開で開始時のフックが db=失敗(49s)。/var/run/docker/containerd/containerd.pid が前の回の古いファイルのまま残り、dockerdがcontainerdは動いていると思い込んで待ち、時間切れで止まった。scripts/remote_dev/lib.sh の rc_ensure_dockerd が起動前にpidファイルを確かめていない。dockerd起動前に /var/run/docker.pid と containerd.pid が指すプロセスが実際にdockerd/containerdでなければファイルを消す。わざと古いpidファイルを置いて起動しDBが上がることを確かめて完了。起票案 proposal-remote-dockerd-stale-pid（担当 D-compose、2026-09-26 承認）。T989の派生
