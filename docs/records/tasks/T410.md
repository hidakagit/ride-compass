# T410. キキクル（危険度分布）+線状降水帯予測マップの実装 規模M

状態: 完了（2026-08-30）

- 背景: T387「無償範囲で追加できるJMAデータの調査」の続き（T407でrasrf実装、T408でsjfcstmapを
  単独機能としては見送り）を受け、JMA公式コンテンツカタログ
  （`https://www.jma.go.jp/bosai/common/const/contents.json`）を再走査した結果発見。
  「キキクル」（危険度分布、`risk_map`）は土砂・大雨・浸水・洪水の4種類の災害リスクを
  10分おきに配信するJMAの主力防災製品。sjfcstmap（線状降水帯予測マップ、T408で調査済み）と
  同じ「未来方向の複数フレームを持たない、現在のスナップショットのみ」という性質を共有する。
- ユーザー判断（2026-08-30）: sjfcstmapを「現在の防災リスク」という括りでキキクルと
  合わせて実装する（単独では時系列スライダー設計に乗らないため見送っていたが、
  同種の現在時刻スナップショット系レイヤーとしてまとめて扱えば意味を持つ）。
- データ表現の確認（着手前に検証）: キキクルの実データ（land/heavyrain/inund/flood）は
  `risk.properties.xml`で`type="tile"`と定義されており、rasrf・ナウキャストと同じ
  **ラスタタイル（PNG画像）**。GeoJSON/面データの独自描画は不要（既存のrasterTile仕組みを
  そのまま再利用できる）。

## 実装メモ

- 対象4レイヤー: 土砂キキクル（`land`）・大雨キキクル・浸水キキクル・線状降水帯予測マップ
  （`sjfcstmap`）。洪水キキクル（`flood`）は`.pbf`（Mapbox Vector Tile）でラスタではない
  ため別方式が必要になり、本タスクのスコープ外（別タスク起票が必要なら追って検討）。
- 要素コードの実機確認: `https://www.jma.go.jp/bosai/risk/`をBrowserペインで実際に操作し
  `read_network_requests`で実タイルURLを確認した。`properties.xml`上の製品コードは
  `heavyrain`だが、実際のラスタ`imageType`のパスは`rain_mesh`（土砂は`land`、浸水は`inund`
  で一致）。プロパティ定義とタイルパスが食い違う実例のため、今後同様のJMAレイヤーを追加
  する際は必ず実機のネットワークログで裏取りすること（curlで座標を推測するとz/x/yの
  カバレッジ不一致で404を誤検出しやすい。実際に404を連発してから気付いた）。
- キキクル・線状降水帯予測マップは`validtime === basetime`（未来フレームを一切持たない
  「現在のみ」のスナップショット）で、`member`は`immed0/immed1/immed2`（直近3回の10分毎
  更新）+`none`（それより古い履歴）。`riskMap.ts`の`latestEntry`は`elements.includes(id)`
  で対象要素を含む行だけに絞ってから最新basetimeを1件選ぶ（T407で発見したsjfcstmap
  混入バグと同じ轍を踏まないため、最初からelements絞り込みを組み込んだ）。
- **設計上の不具合を実機検証で発見・修正**: 当初`frameIndexForTime`（他レイヤーと共通の、
  共有タイムライン上で選択中時刻に最も近いフレームを探す関数）にそのまま乗せたところ、
  同関数の`FRAME_RANGE_EPSILON_MS`（1秒）という許容誤差が「常に1枚だけの現在値」を扱う
  には狭すぎ（フレームのvalidtimeは実際の「今」から最大10分ほど遅れるのが常態）、実機で
  一切描画されなかった。加えて実機フィードバック「12時間後の雷が常時マップに警告されて
  いるのは嫌」を受け、単に無条件で最新1枚を出す設計も却下: スライダーを未来へ動かした
  状態で「現在のスナップショット」を出し続けると、あたかもその未来時刻の危険度であるかの
  ように誤解を招く。最終設計は、キキクル系4レイヤーを共有タイムライン
  （`activeFrameLists`/`frameIndexForTime`）から完全に外し、代わりに
  `sliderIndex === sliderCurrentIndex`（スライダーのつまみ位置が「現在」ボタンの
  ジャンプ先indexと一致するか）を「現在位置にいるか」の判定に使い、一致する間だけ
  `frames[0]`（フェッチ直後の最新1枚）を描画、未来側へ動かした間はundefined（非表示）に
  する。「現在」へ戻せば即座に再表示される。
- 実機検証（Browserペイン、Turbopack dev server）: 土砂キキクルをON→
  `risk/targetTimes.json`取得後、`.../surf/land/{z}/{x}/{y}.png`タイルが実際に要求される
  ことを確認。スライダーを最遠未来（8/31 23:00）へ動かすと新規タイル要求が発生しなくなり、
  「現在」ボタンで戻すとスライダーが「現在」位置に復帰することを確認。
- `npx tsc --noEmit`・`npx vitest run`（743件、riskMap.test.tsの11件含む）とも成功
  （並行するワーカー起動タイムアウト1件は既知のWindows環境フレークで無関係）。
