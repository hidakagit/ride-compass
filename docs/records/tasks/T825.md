# T825. 無駄な再描画・再計算を止め、再描画経路の網羅を保証する

規模S〜M。
状態: 完了（2026-09-14。統合レビュー第8回のP2/P3を束ねたもの、2026-09-13起票）

## 背景

参照が毎レンダー変わることでエフェクトが回り続ける箇所と、**再描画の対象から新設レイヤーが
落ちている**箇所。後者は[T524](T524.md)で一度直した欠陥と同じ性質が再発したもので、
`MapView.routes.test.ts:253`は「redrawAllLayers経由でも」と題しながら別関数を単体で呼んで
いるため検知できていない。

## 対象

- `Map/MapView.tsx:2865`: `redrawAllLayers`が`spliceStretches`を再描画対象に持たない。
  合成ルート（区間の乗り換え）を表示中に「地図の表示を再描画」を押すと`setStyle()`で
  `SPLICE_SOURCE_ID`/`SPLICE_LAYER_ID`が破棄され、`redrawPropsRef`（:2713）にも
  帯専用effectの依存にも入っていないため**橙色の帯が消えたまま戻らない**（復旧は別候補の
  選択などでspliceが変わるまで起きない）
- `Map/MapView.tsx:2954`: `redrawAllLayers`が無条件で`fitBoundsToRoutes`を呼び、
  3576行のeffectが明文化している「フィットは候補一覧が変わったときだけ」を破る。
  区間を拡大して見ている最中に再描画を押すとカメラが全候補の範囲へ戻る
- `app/page.tsx:804-822`: `splicePairs`/`spliceStretches`/`spliceStretchFeatures`を
  レンダー本体で毎回新規生成しており、`MapView`の`useEffect([spliceStretches, routeLayerOn])`が
  毎レンダー発火する。天候フェッチ・`onViewportChange`（moveend/zoomendごと）・デバウンス確定など
  **あらゆる**再レンダーで`drawSpliceStretches`が走り、地図パン中ずっと`setData`が繰り返される。
  `pairedStretches`は両候補の`edge_ids`（30km級で数千件）からSetを毎レンダー構築する。
  同ファイル877-880行が`roadHiddenKeysByMode`について同じ欠陥をuseMemoで直した記録を持つ
  （**再発**）
- `Map/MapView.tsx:2647`: `staticOverlayLayers`のuseMemoが`dedicatedWayValueLoading`
  （フェッチ状態のMap）に依存するため、パン/ズームのたびに全オーバーレイ層のspecを作り直し
  paint/filterを全再適用する（パン1回あたり2周、公開ramp軸が増えるほど線形に増える）
- `RouteAxisProfile/AxisContributionBar.tsx:77`: `renderDetail`が1軸あたりfilterと本体で
  2回呼ばれ、1回目のJSXは捨てられる。さらに`renderDetail`未指定の呼び出し（区間クリック詳細）
  では全チップが`data-checked="false"`になり、凡例全体が`opacity: 0.55`で描かれる
- `AxisStudio/AxisComposer.tsx:270`: 「かけあわせ評価」でも生値分布のPOSTが走るが、結果を
  描画するのは`breakpoint_linear`のブロック内だけで、取得結果・loading・errorのいずれも
  消費されない（初回Way抽選で1秒前後のリクエストが、軸や係数を変えるたびデバウンス後に発火）
- `AxisStudio/AxisComposer.tsx:776`: `MaterialRangeHint`が「かけあわせ評価」でaxis_idを持つ行にも
  `GET /admin/api/material-distribution/{axis_id}`を投げる。キャッシュは成功時しか埋めないため
  **失敗が毎マウント繰り返される**（画面には何も出ない）
- `app/page.tsx:811`: パネルの区間行は`splicePairs`全件から作るのに、地図の帯は
  `stretchCoordinateRange`がnullまたは座標2点未満の区間を落とすため、行数と帯の本数が
  一致しないことがある。パネルの(i)は「地図にオレンジの帯で出ます」と断言している

## 対応方針

1. **まず再描画対象の網羅を保証する**。`redrawAllLayers`が扱うべきレイヤーを型か1箇所の
   定義から導く形にし、新設レイヤーを足したら自動的に対象へ入る（または入れ忘れると落ちる）
   ようにする。**T524の再発を止めるのはこの1点で、個別の追加ではない。**
2. `MapView.routes.test.ts:253`を「`redrawAllLayers`を呼んで対象が再作成されること」を
   検証する形へ直す（[T823](T823.md)と対）。
3. 参照の安定化（useMemo/useCallback）は1と2が済んでから。

## 実装メモ

### 1. 網羅の保証（`map_redraw_coverage`）

`redrawAllLayers`をコンポーネント内の`useCallback`からモジュールレベルの関数へ出し、
表示状態を引数で受け取る形にした（テストから実物を呼べるようにするため。コンポーネント
側はrefが持つ最新値を渡すだけの薄い包みになる）。

そのうえで**辿れるかどうかを機械が見る**。`scripts/review_checks.py`の
`map_redraw_coverage`が`MapView.tsx`を読み、`map.addSource(`を持つトップレベル宣言が
`redrawAllLayers`から辿れるかを判定する。到達は「トップレベル宣言の本文にその名前が
現れるか」で見る——呼び出しに限らずコールバックとして渡す形も辿れるようにするため。
コメントと文字列は空白へ潰してから見る（コメントで名前に触れただけで「辿れる」ことに
なると検知器が黙る）。

`redrawAllLayers`という入口の名前は検知器が知っている。入口が見つからないときは
0件ではなく1件の違反として出す（黙って何も守らない状態を作らない）。

### 緩和と、その影響

オーバーレイ登録表の`ensure`は名前で呼ばれない（`layer.ensure(map)`）ため、そのままでは
標高・路面タイル・事故・POIの4つが辿れないと出る。`.ensure(`を呼ぶ経路からは
`ensure:`の値として表に載る名前すべてへ辿れるものとして扱う、という1つの規則を足した。
この緩和で到達扱いになるのは`ensure:`へ書かれた名前だけで、そこに載らない描画は
従来どおり検知される。

### 2. 直した欠陥

- **帯が戻らない**: 乗り換えられる区間の帯と編集中の合成ルートを、専用effectと
  `redrawAllLayers`が共有する`applySpliceLayerVisibility`へ寄せた（`applyRouteLayerVisibility`
  と同じ形）。あわせて`redrawPropsRef`へ`spliceStretches`/`splicedRoute`を足した。
- **カメラが戻る**: `redrawAllLayers`から`fitBoundsToRoutes`を外した。再描画は見た目を
  作り直すだけで、表示範囲は利用者の操作に属する。
- **帯の導出が毎レンダー**: `page.tsx`の`candidateShapes`/`splicedShape`/`spliceGroups`/
  `spliceStretchFeatures`をuseMemoへ。参照が毎レンダー変わるため、天候フェッチ・
  パン確定・デバウンス確定などあらゆる再レンダーで地図の帯のeffectが走っていた。
  `handleSpliceStretchSelect`の依存も`spliceGroups`そのものにできたため、
  `eslint-disable`を外した。
- **オーバーレイ層specの作り直し**: フェッチ状態のMap（`dedicatedWayValueLoading`）は
  値が同じでもフェッチのたびに作り直されて届く。`useStableMap`で中身が同じ間は同じ参照を
  返すようにし、`staticOverlayLayers`の組み直しを中身が変わったときだけにした。
- **凡例が理由なく薄い**: `AxisContributionBar`が`renderDetail`を絞り込みと本体で2回
  呼んでいた（1回目のJSXは捨てられる）のを1回にし、`data-checked`は詳細を出す契約が
  ある呼び出しでだけ付けるようにした。契約の無い区間クリック詳細では全チップが
  「押せない」印になり、凡例全体が`opacity: 0.55`で描かれていた。
- **使われない分布POST**: 生値分布を描くのは「値ごとのスコア」の折れ点エディタだけ
  だが、取得は「かけあわせ評価」でも走っていた。取得条件を描画条件へ揃えた。
- **失敗が毎マウント繰り返される**: `useMaterialDistribution`のキャッシュが成功時しか
  埋まらず、値を持たない材料へマウントのたびに同じ失敗リクエストを投げていた。取得
  できなかったことも覚える。あわせて「かけあわせ評価」の行が持つのは軸idで材料の分位を
  引けないため、その場合は`MaterialRangeHint`自体を出さないようにした。

### 一覧のうち、状況が変わっていたもの

`app/page.tsx:811`（パネルの区間行と地図の帯の本数が食い違う）は、[T843](T843.md)で
パネルが区間を行で並べなくなったため、行と帯のずれは無くなっていた。残っていたのは
同じ性質の別の形——パネルの案内文「地図の破線をタップして乗り換えます」を
`spliceGroups.length > 0`（乗り換え先の候補があるか）で出しており、座標を取れず帯が
1本も描かれない場合も断言していた。実際に描かれる帯（`spliceStretchFeatures`）の
有無で出すように変えた。

## 検証結果

- **検知器が効いていること**: `redrawAllLayers`から`applySpliceLayerVisibility`の行を
  抜くと`map_redraw_coverage`が`drawSpliceStretches`（MapView.tsx:591）・
  `drawSplicedRoute`（同629）の2件を出す。戻すと0件。到達扱いの宣言数も135→117へ
  減り、全件が到達扱いになる（何も検知できない）状態ではないことを確認した。
- **テストが効いていること**: 同じ行を抜いた状態で
  `MapView.routes.test.ts`の「合成ルートを表示中に作り直すと、乗り換え区間の帯と
  編集中の線も戻る」が落ちる。`AxisContributionBar`の2件も、直す前の実装へ戻すと落ちる
  （`renderDetail`の呼び出し回数・`data-checked="false"`の件数）。
- `python scripts/review_checks.py docs` → `map_redraw_coverage` 0件。
  `pytest scripts/tests/test_review_checks.py -q -k "not npx"` → 88 passed。
- `npx vitest run` → 142ファイル・1344件 passed、`tsc --noEmit`は既存の`LayoutProps`のみ、
  `eslint src`は既存の警告1件のみ。
- `page.test.tsx`の編集面のテストは、帯が1本も出ない候補（座標もEdge境界も空）で
  「地図の破線をタップして乗り換えます」を期待していた。上の修正で落ちたため、
  座標とEdge境界を持つ現実的な候補へ直した。
