# T894. 冷パスで作ったグラフに交差点属性が載らない

規模M。
状態: 完了（2026-09-16）

## 背景

[T800](T800.md)が足した「信号のある交差点では横断待ちを足さない」という二重計上の除外が、
探索グラフを作るもう一方の経路を通ったリクエストでだけ効かない。
`domain/graph.py`の`build_road_graph`は`LeanNode`を既定値（`has_traffic_signals=False`・
`max_highway_rank=0`）のまま作り、DBから読む経路（`road_graph_repository.py`）だけが
両方を設定している。属性の供給元は`graph.nodes`に一本化されているのに、グラフを作る経路が
2つあって片方だけが属性を知っている。

PBF再取込直後・未split地点への最初のリクエストで、信号のある幹線交差点すべてに待ちが
上乗せされる。2回目以降と候補の並び・到着予想が変わり、利用者からは再現しない揺らぎに見える。
警告は出ない。docstringと`docs/modules/backend/routing-engine.md`は、既定値になる条件を
「バッチ未実行のDB」とだけ説明しているが、実際にはバッチ実行済みでも構築経路によって既定値になる。

統合レビュー第10回のP1 F-3（[2026-09-16_all.md](../../../.claude/commands/review/history/2026-09-16_all.md)）。

## 完了条件

- 冷パスでも`road_nodes`の2列が載る。
- **どちらの構築経路で作ったグラフでも同じ`turn_seconds`になる**ことをテストで固定する
  （現在の`test_routing_turn_expanded.py`は構築経路を跨いだ検証を持たない）。
- docs側の「バッチ未実行のDBでは」も同一コミットで是正する。

## 対応方針

冷パス側でDBから読み直すのではなく、**穴が空いている原因の方**を直す。この2列は
`road_nodes`のノード単位の事前集計で、埋めるのは事前集計バッチだけだった——ところが
**交差点分割は新しいノードを作る**ので、分割した直後のノードはDBの行も既定値のままになる。
つまり欠けていたのはメモリ上のグラフだけではなく、永続化した行の方も同じだった
（バッチが次に走るまで、その地点は2回目以降のリクエストでも既定値で評価される）。

分割した側が自分の作ったノードを埋める形にする。1本道の追加点は「ノードを作る場所」で、
読む側（`_node_intersection_attributes`）はグラフだけを見るまま変えない。

## 実装メモ

- `DerivedGraphRepository.recompute_node_intersection_attributes(node_ids)`を新設し、
  `GraphService`の再構築経路が`save_graph`の直後（同じトランザクション）で呼ぶ。
  そのまま`get_node_intersection_attributes`で読み戻し、返すグラフのノードへ載せる。
- `recompute_node_max_highway_rank`に**ノードを限定する版**を足した。全件版は
  `road_edges`全行を走査するためリクエストの経路では使えない。全件版と限定版は
  対象の絞り方だけが違うため、1つのSQLテンプレートから組み立てる。
- 信号の再計算は既存の`recompute_node_traffic_signals`をそのまま使う（半径での空間結合の
  ためチャンクに割る点も、バッチと同じ大きさで揃えた）。
- `FakeRoadGraphRepository`も同じ契約へ揃えた。**読み出し側（`get_graph_in_bbox`）が
  road_nodesの列を載せて返す**ところまで再現しないと、「DBから読む経路だけ属性が付く」
  という実装との差がテストから消える。

## 検証結果

- **経路を跨いだ同値をテストで固定した**:
  `test_intersection_attributes_are_the_same_whichever_path_built_the_graph`。
  分割で作ったグラフと、2回目の呼び出し（省略パス＝DBから読む側）のグラフで、
  全ノードの（信号の有無, 最大階級）が一致することを見る。
- **効いていることの確認**: `GraphService`の穴埋め1行を外すと、backend全件
  （`-m "not postgis"`、2,000件）のうち**このテストだけ**が
  `has_traffic_signals=False`で落ちる。戻すと全件緑。
- 実SQLはpostgisテスト2件で通した（ノード限定の再計算が指定したノードだけを埋め、
  指定しなかったノードを触らないこと／信号と最大階級の両方がまとめて埋まること）。
- backend全件: `-m "not postgis"` 1,999件・`-m postgis` 280件ともに緑。`ruff check app`緑。
- docs側の「バッチ未実行のDBでは既定値」も是正した（実際には**埋める経路が2つ**あり、
  どちらも通っていないノードだけが既定値になる）。
