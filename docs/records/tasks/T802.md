# T802. 時刻ビンが1本のときに2点間探索の手間を省く

規模S。
状態: 完了（2026-09-14。**見送り**——測ったら直す対象が無かった。2026-09-13起票、[T790](T790.md)の本番計測から）

## 背景

[T790](T790.md)段階Dで、探索は出発からの経過時間をラベルとして持ち回り、`(時刻ビン, 状態)`の
2次元コスト配列からその時刻の行を引くようになった。

本番計測（東京駅・目標30km・温パス）で、2点間探索（`trace`）が**179ms→704ms**になっている。
目標30kmの周回はレグ0.75時間で**時刻ビンが1本に収まる**ため、この増分は
「ビンが1本でもラベルの持ち回りと2次元の添字アクセスを通っている」ぶんの手間になる。

## 切り分けの結果（本番DB・ターン展開A*、`benchmarks/bench_t802_time_bins.py`）

起点=東京駅／目的地=池袋、半径30kmのcontextで、**同じコスト値をビンの本数だけ変えて複製**し
（値が同じなので経路は変わらず、2次元の添字を引く手間だけが出る）壁時計を測った。

```
ノード 78,227 / 状態（有向区間） 201,391（2.6倍）
実データのビン本数: 1（bin_seconds=inf）

ビン  1本: elapsed_ms=  25.6  区間数=167  経路一致
ビン  2本: elapsed_ms=  25.9  区間数=167  経路一致
ビン  4本: elapsed_ms=  26.0  区間数=167  経路一致
ビン  8本: elapsed_ms=  25.9  区間数=167  経路一致
ビン 16本: elapsed_ms=  25.4  区間数=167  経路一致
```

**ビンの本数は壁時計に出ない**（1本と16本で差が無く、繰り返し間のばらつきの方が大きい）。
起票時の前提「ビンが1本でもラベルの持ち回りと2次元の添字アクセスを通っているぶんの手間」は、
測った範囲では存在しない。

あわせて、**2点間探索1回は25ms**だった。`trace_ms`が704msなのは1回の探索が重いからではなく、
**`trace_ms`が折返し点候補ごとの探索をまとめた区間だから**（`route_generator.py`の
`trace_started`〜`trace_ms`は候補のループ全体を囲む）。25msの探索を数十回通せば704msになる。

## 結論: ビン1本専用の経路は作らない（見送り）

カーネルを2つ持つ代償（同じ探索の実装が2箇所になり、片方だけ直したときに静かに食い違う）に
対して、得られるものが測定限界以下。**直す対象が無い**ため実装しない。

残る増分の出どころは本タスクの担当ではない:

- **1回あたりの手間**: 状態空間がノード78,227から有向区間201,391へ2.6倍になった分。
  訪問する状態を減らす話で[T792](T792.md)（A*のヒューリスティックが効いていない）の担当。
- **探索の回数**: `trace_ms`は折返し点候補ごとに探索する。候補数を減らす／早期に打ち切る話。

## この測定の射程

ビンの本数を変えても**値は同じ**にしてある（経路を変えずに添字の手間だけを見るため）。
実データでビンごとに値が違う場合のキャッシュの当たり方までは見ていない——ただし目標30kmの
周回は実際にビン1本に収まっており（上記`実データのビン本数: 1`）、本タスクが問うていた
「ビン1本のときの手間」はこの測り方で足りる。
