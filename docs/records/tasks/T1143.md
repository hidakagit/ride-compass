# T1143. 重みタブの軸の説明ⓘが枠の外へ押し出されて押せず、既存の全画面の走査も切り取られた部品を拾えない

状態: 完了（2026-09-26起票、同日完了）

## 背景

周期レビュー第13回（2026-09-26）の指摘。性質: 状態が画面に届かない（T1001の作り直しで入った退行）。軸6本のカタログで「…の説明を表示」ボタンを実測すると、1280pxでも390pxでも6本すべてが中心点のヒットテストで自分を返さない（1280pxでチップ16〜179px、ボタン179〜207px）。原因はcomponents/ui/AxisLegend/axisLegend.tsのlegendChipBodyClassがw-full、本体のToggleがshrink-0（Toggle.tsx:15）、外側のlegendChipClassがoverflow-hiddenの組み合わせ（8fd5e9825、T1001段階C。masterでもw-fullのまま）。生成前に軸の説明を読める唯一の場所。LensOption.description（view/lens.ts:65で詰める）はLensControl.tsxで一度も描かれない参照0のフィールド。設計書route-settings-and-results.md 45-47行の図は(i)があると書く。e2e/scans.tsの横幅検査は最も近いスクロール容器しか見ないため、祖先のoverflow:hiddenで切り取られた操作部品を拾えない（検知器の母集団の穴）。e2e/fixtures.ts:247 MobileSheetNameの「ルート編集」も残骸。チップのクラスを直し、参照0のフィールドを消し、scansに「操作部品が押せる位置にあるか」を足すかを同じタスクで決める。

## 実施内容

- 軸チップの本体（`legendChipBodyClass`）を`w-full`から`grow`にした。本体は余りだけを取って伸びるので、隣の(i)が枠の外へ押し出されない。ルート結果の内訳も同じクラスを共有しているが、そちらのチップは子が1つなので見た目は変わらない。
- 参照0の`LensOption.description`を消した。数え方: `lensOptions`の呼び手をgrepすると`useMapView.ts`の1か所で、その`axisOptions`は`LensControl`にしか渡らない。`LensControl`が読むのは`id`・`label`・`color`・`unused`・`routeOnly`だけ。フィールドを消したあとの`tsc --noEmit`で、新しい型エラーは0件だった。
- `e2e/fixtures.ts`の`MobileSheetName`から「ルート編集」を消した。`openMobileSheet(`の呼び出し（e2e・e2e-live）は8件あり、すべて「ルート設定」か「ルート結果」の文字列だった。変数で渡す呼び出しは無い。画面の下部タブもこの2つしか持たない（`page.tsx`）。
- 走査へ「押す点の切り取り」を足すと決め、足した（`e2e/scans.ts: scanLayout`）。操作できる部品の中心点が、スクロールしない祖先（`overflow`が`hidden`・`clip`）の外にあれば違反にする。その軸でスクロールする祖先より外側は、スクロールすれば届くので見ない。絶対配置・固定配置の部品は、包含ブロックより内側の祖先には切り取られないので飛ばす。
- 走査が「重み」タブを一度も開いていなかった穴を塞いだ（`e2e/states.ts`）。同じタブ列のタブは部品の見分けが同じになる。そのため選ばれたタブが移っても指紋の多重集合が変わらず、辿り方は「押しても開かなかった」と扱っていた。指紋へタブ列の中の位置を添えた。旧い辿り方では、PC幅の生成前の20状態のどれでも「重み」の中身は見えていなかった（ボタンの矩形が0）。
