# T792. A*のヒューリスティックが実データで効いていない

規模S〜M。
状態: 完了（2026-09-13。**見送り**。本番で下界の強さを振って実測し、短縮余地が小さいことを
確かめた。理由は下記「実測」）

## 背景

[T790](T790.md)段階1の実測で、2点間探索が訪れるNodeの割合が**68.4%**だった（dev DB・
蒲田付近→王子・経路25.5km、nodes=76,960のうち52,639をpop）。`domain/routing.py:
LazyRoadGraph`のdocstringにある「A*は全Edgeの2.79%しか評価せずに済む」は**合成グリッド
グラフでの値**で、実データの20km級では桁が違う。

T790でコストの単位が秒になった後は、下界も秒（直線距離 ÷ `MAX_DESCENT_SPEED_KMH`）になった。
実際の走行はその半分以下の速度のため、下界はさらに緩んでいるはずだった。

## 実測（2026-09-13、本番Oracle VM・柏→王子・443,368状態）

`benchmarks/bench_t792_heuristic.py`で、**同じ起点・目的地・同じコスト配列**に対して下界の
作り方だけを変え、壁時計と得られた経路を比べた。

| 下界 | 現行比の強さ | elapsed_ms | 経路 |
|---|---|---|---|
| 0（＝ダイクストラ） | — | 96 | 一致 |
| **直線距離 ÷ 下り上限（現行）** | 1.0 | **90** | 一致 |
| 直線距離 ÷ bbox内の実測最速 | 1.00 | 91 | 一致 |
| 現行×1.5（admissibleでない） | 1.5 | 88 | 一致 |
| 直線距離 ÷ 巡航速度（同上） | 2.25 | 77 | 一致 |
| 巡航速度×1.5（同上） | 3.4 | 65 | 一致 |

**A*は効いているが、効き幅が小さい**（ダイクストラ96ms→現行90ms、6%）。admissibilityを
捨てて3.4倍きつくしても65ms（32%減）にしかならない。

### なぜ効かないのか

**探索するグラフが既に経路の広がりへ切り詰められているため、A*が刈る余地が残っていない。**
bboxは起点・目的地（周回なら折返し半径）から作られるので、目的地は常にbboxの端付近にある。
A*が効くのは「広いグラフの中で目的地が近い」ときで、この使い方では条件が揃わない。

### データ由来の下界も効かない

「bbox内の区間から実測した最速の秒/m」は、現行の下界（下り上限45km/h）と**完全に一致した**
（どちらも0.0800秒/m）。下り上限に張り付く区間が実データに存在するため、全体の最小を取る
やり方では下界が1mmも縮まらない。

## 見送りの判断

仮にALT（ランドマーク）等で理想に近い下界を得ても、2点間探索は本番の生成時間5,483ms
（周回30km・温パス、[T790](T790.md)に内訳）のうち704ms＝13%で、その3割を削っても**全体の
4%**にとどまる。支配項は合成（prepare 3,112ms・select 1,199ms）であり、そちらを削る方が
桁違いに効く。

同じ区間数あたりの手間を減らす話は[T802](T802.md)（時刻ビンが1本のときの手間）に残す。
