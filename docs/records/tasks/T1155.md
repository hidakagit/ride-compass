# T1155. 取込の設定ファイルに書いた欄のうち3つが効かず、OSMのPBFは既定の設定では取得スクリプトが何も取りに行かない

状態: 未完了（2026-09-26起票）

## 背景

周期レビュー第13回（2026-09-26）の指摘。性質: 黙った既定値・片側だけの修正（再発）。取込はrows.fileが無ければ"kanto-latest.osm.pbf"を使う（osm_pbf.py:103）が、取得スクリプトはspec.rows.fileがあるものしか取らない（fetch_osm_pbf.py:387-393）。source_profile.yamlのosm_wayにfileは無く、fetch_osm_pbf.pyは「指定がありません」で0終了する。土地被覆のLulcGrid.product・year（yaml 249-250行）はnatural_key・attrs・originのラベルにしか使われず（io_lulc_tile.py:163,180-184）、どのラスタを読むかはsettings.lulc_raster_paths（landcover_raster.py:99）で決まるので、yearを変えても同じラスタを別の年として記録する。標高のproductはT978。母集団: register_adapterで宣言したrows/gridのdataclassのフィールドを、取得と取込の両方で読み手まで追う（9個中3個）。既定のファイル名をOsmWayRows.fileの既定値へ移し取得と取込で1つにする。lulcのyear・productはラスタの指定から導くか欄を消す。
