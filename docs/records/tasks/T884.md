状態: 完了（2026-09-17、段階1・2をmasterへ反映済み。2026-09-16起票。[T882](T882.md)で走査対象を広げたときに初めて見えた）

## 背景

[T882](T882.md)までコピペ検出は1,000行超のファイルを走査していなかった。上限を外して
見えるようになった重複は、**ほぼすべてテストの足場**だった。

同一ファイル内の重複が大きいもの:

    924行 / 35件  frontend/src/components/AxisStudio/AxisComposer.test.tsx
    451行 / 36件  frontend/src/app/page.test.tsx
    281行 / 23件  backend/tests/test_road_graph_engine.py
    153行 / 18件  backend/tests/test_road_graph_repository.py
    117行 / 12件  frontend/src/components/AxisStudio/AxisStudio.test.tsx

ファイルをまたぐぶんも、10件のうち8件が`AxisStudio`のテスト群どうしである。最大の
クローンは`page.test.tsx`と`RouteSettingsPanel.test.tsx`の間の20行。

中身は、軸スタジオのウィザードを歩く手順（表示名を入力→次へ→評価の形を選ぶ→次へ→
材料を選ぶ→係数を入れる）が、テストケースごとにそのまま書き写されている形。

## 対象から外すもの

`frontend/src/components/Map/icons.tsx`（757行・1件）は外す。51個のアイコンが同じSVGの殻
（`<svg width={size} height={size}>`＋`stroke="currentColor"`・`strokeWidth="1.6"`）を
共有しているために1つの大きなクローンとして出るもので、各アイコンは`d`だけが違う。
殻を共通化することはできるが、1件ずつ独立して読めることの方が価値が高い。

## 保留することで何が起きうるか

- ウィザードの手順が1つ変わるたびに、書き写した数だけ直すことになる。直し漏れたテストは
  古い手順のまま緑になり続ける（通らなくなって初めて気づく形ですらない）。
- [T882](T882.md)で前回比の起点を27件へ置き直したばかりで、ここを畳まないと「増えたか」の
  判断がテストの足場の増減に埋もれる。

## 見送ったもの: `vi.mock`の前置きの共有（2026-09-17判断）

`AxisStudio`のテスト5ファイルが`axisPreviewApi`・`materialCatalogApi`・`axisAdminApi`の
モックを同じ形で書いている。**いまのクローン21件のうち6件がこれ**で、寄せれば30行あまり減る。
それでも見送る。

- `vi.mock`はホイストされるため工場を外へ出せず、各ファイルは
  `vi.mock(path, async () => (await import(...)).factory())`の形になる。**そのファイルを
  読んでもモックが何を返すか分からなくなる**——テストが落ちたときに最初に見たいのがそこ。
- 写経の害は「手順が変わったとき、直し漏れたテストが古いまま緑になり続ける」ことだが、
  この前置きが変わるのはサービス側のAPIが変わったときで、**そのときは型検査とテストが
  全ファイルで落ちる**。黙って緑にならない。

つまりここは、畳まないことの損（30行）が、畳むことの損（読めなさ・静かな失敗にならない
ものへの間接化）より小さい。
## 対応方針

ケースごとに書き写されている手順を、テストごとのヘルパーへ寄せる。**足場の共通化であって、
テストが確かめている中身は変えない**——1件ずつ独立して読めることは保つ。

`review_checks.py`には既に`duplicate_test_scaffold`（同じ名前のテスト足場が複数ファイルに
ある、参考表示）があり、ファイルをまたぐぶんはそこにも現れる。
