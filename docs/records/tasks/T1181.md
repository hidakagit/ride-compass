# T1181. 材料の欠損率の「担当バッチが処理できる行だけを数える」条件を、どの材料も使っていないので撤去するか決める

状態: 完了（2026-09-27）

## 背景

起票案 proposal-material-coverage-in-scope-unused（2026-09-27承認。標準の道具の棚卸し・T1152の担当から）。規模S（根拠: 変わると見込むファイルは material_catalog.py・material_coverage.py・test_material_coverage.py の3本。7以下）。

背景: 材料カバレッジ（管理画面の欠損率）の道の材料の宣言 WayMaterialCoverageSpec は in_scope（担当バッチが処理できる行の条件。既定 "TRUE"）を持ち、欠損の数え方 build_way_coverage_sql がそれを FILTER に掛ける。2026-09-21 の T961 で土地被覆の材料が区間側へ移って以降、in_scope を既定以外にしている材料は1つも無い（grep で in_scope の代入は既定値の1か所だけ）。この仕組みを確かめるテスト test_way_coverage_counts_only_rows_the_batch_can_process は、実在する材料の中から in_scope を持つものを選んでループしていたため、T961 以降は1件も確かめずに通っていた（T1152 で一般化した「空でも通るテスト」の検査器が見つけた）。T1152 ではテストを、in_scope を持つ宣言をテストの中で組み立てて渡す形へ直した（仕組みそのものは残した）。

決めてほしいこと: ①撤去する（in_scope・FILTER の (TRUE) AND・上のテストを消す。将来また要る材料が出たら足し直す）／②残す（道の材料で担当バッチが一部の行しか処理しないものが近く入る見込みがある場合）。CLAUDE.md「本番から外れたものを残す判断を自分でしない」により、担当では決めずにここへ置いた。

なぜ既存のタスクに入らないか: T1152 はテストの検査器の母集団の穴が範囲で、本番コードの宣言の撤去は含まない。material_catalog.py を触っている T1157 は路面の対訳・土地被覆の材料の導出が範囲で、欠損率の数え方とは別。

## 判断

①撤去を採った。CLAUDE.md「置き換えではなく削除を既定にする」「本番から外れたものを残す判断を自分でしない」に従い、
残す理由（担当バッチが一部の行しか処理しない道の材料が近く入る見込み）が言えるかを確かめ、言えなかった:

- `in_scope`の参照（`backend/`・`frontend/`・`docs/modules/`・`docs/architecture/`をgrep）: 宣言の既定値
  `"TRUE"`・`build_way_coverage_sql`のFILTER・T1152で直したテストの組み立ての3か所だけ。既定以外を渡す材料は0件。
- 台帳の未完了タスク78件の記録を`WayMaterialCoverageSpec|missing_condition|欠損率|欠損割合|material_coverage|build_way_coverage_sql|in_scope`
  でgrep: 当たったのはT970（規模の集計表の1行）とT1181自身だけで、道の材料で対象行を絞る予定を書いたタスクは無い。
- ダッシュボードにT1181の件は無く、起票案の件も承認で消えていた（答え・決定は無い）。

## 実施

- `WayMaterialCoverageSpec.in_scope`を撤去し、`build_way_coverage_sql`のFILTERを`WHERE {missing_condition}`だけにした。
- テスト`test_way_coverage_counts_only_rows_the_batch_can_process`（撤去した条件だけを確かめていた）を消した。
  FILTER列の組み立ては`test_build_way_coverage_sql_has_one_filter_column_per_way_material`が引き続き見る。
- 撤去したdocstringの文（対象外の行を欠損に数えると欠損率が0へ到達しない）は、条件が消えても道の材料を足す人が踏む罠
  （comments.md「残すと決めたものの行き先」(a)）なので、`WayMaterialCoverageSpec`のdocstringに、全行を数えることと
  その帰結として残した。`derived_data_freshness.py`との対比は、比べる相手（`in_scope`）がもう無いので落とした。
- `docs/modules/backend/evaluation-scoring.md`は`in_scope`に触れておらず、乖離は無かった。
- OpenAPI: `WayMaterialCoverageSpec`はAPIの応答モデルに出ない（`frontend/`に`in_scope`は0件）ので生成物は動かない。
