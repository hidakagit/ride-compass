# T489. ルート設定パネル（モバイル）のスライダー整列・ネストスクロール・部品サイズを是正

状態: 完了（2026-08-31）

- 背景: T487デプロイ後、ユーザーから本番モバイル実機のスクリーンショットで3点の指摘。
  「スライドバーの起点、終点の位置（長さ）は揃えて」「モバイルだと全体的にボタン
  はじめ部品がやや大きい印象」「重み配分エリアが独自でスクロールして全体スクロール
  できないことがあるのを直して」。
- 対応:
  1. **スライダー不揃い**: T487のモバイル1行レイアウトで`.rowLabel`を`max-width`
     （可変）にしていたため、ラベル文字数に応じてスライダーの開始位置が行ごとに
     バラついていた。`width`（固定4.4rem）へ変更し、全行でスライダーの開始・終了
     位置を一致させた（実機375px幅で全8軸left=121px/right=256pxに揃うことを
     `getBoundingClientRect()`で確認）。
  2. **重み配分エリアの独自スクロール**: T486で`.group`（軸一覧）へ追加した
     `max-height: 40dvh; overflow-y: auto`が、外側の`.app-sidebar`（デスクトップ、
     `overflow-y: auto`を既に持つ）・`.app-bottom-sheet .body`（モバイル、同様）と
     二重のスクロール領域を作り、タッチスクロールがこの内側領域で止まる「ネストした
     スクロールコンテナ」のアンチパターンになっていた。「軸数に比例してパネルが
     際限なく伸びる」というT486の元の懸念は外側のスクロール（サイドバーは
     ビューポートに収まる高さ、BottomSheetはheightVhで高さ固定）で既に解決済み
     だったため、内側のmax-height/overflow-yを撤去した。
  3. **部品サイズ**: globals.cssのモバイル一律ルール（`.app-bottom-sheet
     [role="checkbox"] { 1.4rem }`、行全体を`<label>`で包む構成向けの意図）が、
     `<label>`で包まない本パネルの構成（コンポーネント側の既存コメント参照）には
     過大だったため、`.group .checkboxCell [role="checkbox"]`で1.1rem角へ個別に
     戻した（詳細度をglobals.cssの規則より1段上げて確実に上書き）。「色分け」
     チップ（LayerChip共通部品、min-height 36px）も`.mapColorToggle button`経由で
     28pxへ縮小（LayerChip.module.css自体は変更せず、他の利用箇所には影響しない）。
- 検証: Browserペインで375px幅（実機で最も狭い部類）を再現し、上記3点すべてを
  `getBoundingClientRect()`/`getComputedStyle()`で数値確認（スライダー8本の
  left/rightが完全一致、`.group`のoverflow-y=visible・max-height=none、
  チェックボックス実寸17.6px・チップ実寸28px）。`tsc --noEmit`・
  `RouteSettingsPanel.test.tsx`10件通過。
- 規模: S
