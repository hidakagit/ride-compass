# T1100. 風の詳細格子の問い合わせが、点数の上限で断る前に全点を作り、1回で十数秒サーバーを止めるのを直す

状態: 完了（2026-09-25起票、2026-09-25完了）

## 背景

/api/weather/wind-grid-detail は範囲と間隔から格子点を全部作ってから、点数が上限（900点）を超えるかを見て400で断る（api/routers/weather.py: get_wind_grid_detail）。点を作る関数は同期で、asyncのハンドラの中から直に呼ばれるため、作っている間はイベントループが止まる。許された最小の間隔（0.0025度）で関東全域（WIND_GRID_BBOX）の範囲を渡すと978,640点を作り、開発機で13.18秒かかった（0.02度なら15,340点・0.19秒。2026-09-25、generate_wind_grid_detail_pointsを直に呼んで計測）。レート制限（1IPあたり30回/分）の内で、1つの接続元がbackend全体の応答を止め続けられる。画面は範囲を間隔×25へ切り詰めて送るので通常の利用では起きない。直し方の見込み: 点を作る前に索引の範囲から点数を計算して上限と比べる。T1099の調査で見つかった。規模の根拠: 変わると見込むファイルは domain/wind_grid.py・api/routers/weather.py とテスト1〜2本。起票案 kihyoan-wind-grid-detail-count-before-build として2026-09-25承認。

## 着手時の確認（2026-09-25、担当 W-windcount）

master（a9eb8129）で、ルーターが`generate_wind_grid_detail_points`で全点を作ってから`len(points)`を上限と比べていること、
ハンドラ（async）から同期で呼んでいることをコードで確かめた。計測を1回再現した（`lockrun`のheavy枠、待ち0秒）:
関数を直に呼んで978,640点・5.59秒（記録の13.18秒より短いが、点数は一致。機械の負荷の差と見る）。利用者の単位として
`TestClient`で同じ問い合わせ（関東全域・0.0025度）を送ると、400が返るまで8.50秒（アクセスログ`-> 400 in 8203ms`）。

## 対応

- `domain/wind_grid.py`: クリップ・原点・境目の計算を`_detail_index_ranges`（緯度・経度方向の索引の`range`）へ移し、
  点を作る`generate_wind_grid_detail_points`と、点を作らずに数える`count_wind_grid_detail_points`（`len(rows) * len(columns)`）の
  両方がそれに従う形にした。範囲の計算式は元のまま（結果は変わらない）。
- `api/routers/weather.py: get_wind_grid_detail`: 数えた点数で上限を確かめてから点を作る。400の応答と文言は同じ。
  ログは足していない——400はアクセスログ（`ridecompass.access`、4xxはWARNING）が1行出し、他のルーターの400も同じ扱い。
- 設計書`weather-dynamic-layers.md`「詳細格子の座標と間隔」節へ、上限を作る前に数えて確かめる理由と、数える側と作る側が
  同じ索引の範囲に従うことを書いた。

## 検証

- 修正後、同じ問い合わせ（関東全域・0.0025度）は0.024秒で400（アクセスログ`-> 400 in 16ms`）。修正前は8.50秒。
- テスト: `test_wind_grid.py`へ数と実物の一致（範囲の内側・縁が格子線ちょうど・南西/北東でクリップ・全体を覆う・縁に接するだけ
  ×許された間隔すべて、と範囲の外の0点）、`test_weather_route.py`へ上限を超える範囲で点を作る関数が呼ばれないこと
  （本物の関数を包んで呼び出しを記録）と、上限ちょうどで200・上限+1で400（上限を実際に作った点数へ差し替え、200のときは
  サービスへ渡る点数も見る）。
- わざと壊して落ちることを見た: 数える式を`(len(rows) + 1) * len(columns)` → 数と実物の一致が20件落ちる（4件残るのは点0の範囲）。
  ルーターを作ってから数える形へ戻す → 作らずに断るテストが落ちる。比較を`>=`にする → 境界のテストが落ちる。
- `ruff check`（変更4ファイル）緑、`mypy` 195ファイル問題なし、`review_checks.py docs`違反なし、`export_openapi.py`→
  openapi-typescriptの再生成で`frontend/src/types/generated/`に差分なし。
  `pytest tests/test_wind_grid.py tests/test_weather_route.py tests/test_wind_way_service.py` 90 passed。
