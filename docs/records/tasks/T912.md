# T912. 面レイヤーの薄い色が、基礎地図を読ませるための不透明度に潰される

状態: 完了（2026-09-17）
規模: M

## 背景

ユーザー指摘「降雨等の面レイヤの表示透明度を上げた結果、基礎地図は見やすくなったが、
少雨等のもともと薄めの色が見えにくくなった」。

[T860](T860.md)・[T886](T886.md)で面レイヤー共通の不透明度を0.65→0.4→0.32と下げてきたが、
この値は「面の下にある道路・地名を読めるようにする」ためのもので、同時に「面そのものが
見えるか」も決めてしまっている。濃い色（警戒レベルのキキクル・強雨）が下を潰さない値まで
下げると、薄い色（少雨）は背景と区別が付かなくなる。

欠陥は値ではなく**面が地図の情報すべての上に積まれていること**にある。`addLayer`を
beforeId無しで呼ぶと最上位へ積まれるため、基礎地図の道路・地名も、このアプリ自身の
路面・軸の線も、面の下へ回っていた。その状態では不透明度が下を守る唯一の手段になり、
最も濃い色に合わせて下げるほかない。

## 対応

**1. 面は基礎地図の線・記号の下へ差し込む。** `mapStyleOps.ts`が、スタイルの並びから
「基礎地図が最後に面を描いたレイヤーの次」を求めて差し込み位置にする
（`areaLayerAnchorId`）。基礎地図のレイヤーidを名指ししないのは、配信元がidを変えても
「面の上・線と記号の下」という関係だけは変わらないため。判断は`ensureLayerFromSpec`
1箇所にあり、`type`が面の種別（raster/fill等）かだけで決まる——レイヤーごとの指定を
持たないので、面を足す側は何も意識しなくてよい。

位置は**スタイル読み込み直後（このアプリのレイヤーを1枚も足していない時点）に一度だけ**
求めて記録する。足すたびに探し直すと、自分が足した線レイヤーが先に見つかって面が一段ずつ
下がる。求まらないスタイルでは面が最前面へ戻る＝この欠陥そのものへ落ちるため、黙って
続けずWARNとしてデバッグログへ残す。

標高・土地被覆ラスタも`addLayer`直呼びから`ensureLayerFromSpec`経由へ寄せた（差し込み
位置の判断を2つ持たないため）。

**2. 不透明度を0.32→0.7へ。** 下の道路・地名は1で守られるため、この値は面そのものが
背景と区別できるかだけを決める。値は「最も薄い階級が基礎地図の背景に対してΔE（CIE76）
15以上」から選んだ（下記「測った値」）。**この下限だけを見たのは誤りで、上限もある**
——面が基礎地図の土地の塗りより上に来るため、上げるほどその違いが潰れる。実機で
全面を覆うレイヤーが一様な色になり、0.55へ下げた（[T913](T913.md)「面の濃さの再調整」）。

**3. 自前の降水ランプの薄い端を、背景と区別できる濃さへ。** 1と2をやっても`#e0f2fe`は
ΔE 7.9で読めない。薄い4段を背景ΔE 16/23/31/39（隣接段どうし約8、現行ランプの
8.1/12.2/11.7と同程度）へ配り直した。10mm/h以上は変えていない。

### 測った値

基礎地図の背景（`#f8f4f0`）に対するΔE（CIE76）。ΔE 2程度が「並べれば分かる」差で、
地図の面として一目で読むには15前後が要る。

| 面へ塗る色 | a=0.32（変更前） | a=0.7（変更後） |
|---|---|---|
| 降水ランプ最薄 `#e0f2fe` | 3.6 | 7.9 |
| 同 `#bae6fd` | 7.3 | 15.7 |
| JMAナウキャストの最も薄い階級（淡い青、近似値） | 6.9 | 14.8 |
| 土地被覆「草地」`#C3B78F` | 9.2 | 20.4 |
| 猛烈な雨 `#9333ea` | 37.9 | 84.2 |

**JMAの淡い青は近似値である**——気象庁はタイル配色のカラーコードを公開しておらず、
タイル画像もCORS設定が無くピクセルを読めない（`precipitationNowcast.ts`冒頭）。
2で選んだ値の根拠のうち、この行だけは実測ではなく見積もりに立っている。

変更後のランプ（a=0.7で背景ΔE／直前の段とのΔE）:
`#b8e6fd` 16.0／- 、`#93dafc` 23.4／7.5、`#68ccfb` 31.5／8.2、`#38bdf8` 39.3／7.8。

### 効いていることの確認

- 差し込みを外す（`addLayer(spec)`へ戻す）と、面と線・記号の重なり順を固定したテストが
  1件だけ落ちる。戻すと7件とも通る。
- `areaLayerAnchorId`は、途中に線を挟んでその後ろに面が続く並び（基礎地図では
  waterway→water/buildingがこの形）でも、最後の面の次を返す。面しか無いスタイル・空の
  スタイルでは例外にせずundefinedを返す。
- フロント全体: vitest 1,412件・eslint・tscいずれも変更由来の失敗なし
  （`src/app/layout.tsx`の`LayoutProps`未定義は`.next`が無い環境で変更前から出る）。

**実機の基礎地図での確認は未実施**。このセッションの実行環境からは`tiles.openfreemap.org`
へもCDNへも出られず、Libertyスタイルの実レイヤー構成を取得できなかった。差し込み位置が
実際にどのレイヤーになったかはデバッグモードのログ（`map:lifecycle`「面レイヤーの
差し込み位置」）で確認できるようにしてある。

## 範囲に入れなかったもの

`AxisStudio/SplitCoverageMap.tsx`の被覆プレビュー（fill、不透明度0.25）は面だが、
z7の全国表示で読む対象がポリゴン自身であり、下の道路・地名を読む場面が無い。共通の
不透明度も共有していないため、この欠陥の性質に当てはまらない。
