# T1068. 地図の上の操作部品でピンチするとページ全体が拡大する

状態: 完了

## 背景

スマホで地図の上の一部の部品に2本指を置いてピンチすると、地図ではなくページ全体が拡大する（利用者に届いている欠陥）。T1014段階Cで、E2Eから Input.dispatchTouchEvent で2本指を送る形でヘッドレスで再現した（Input.synthesizePinchGesture では再現しない）。地図の範囲を8px格子で走査し最前面の部品28件へピンチを送ったところ、今のコードで6か所がページを2.17倍にした（CI run 35827419550、e2e 1 failed）: レンズのボタン「レンズ: 総合難易度（タップで変更）」とその中身、MapLibreのズームボタン「Zoom in」「Zoom out」とその枠、帰属表示の開閉「Toggle attribution」。チップや下部タブバーのように touch-action: none を明示している部品は拡大しない。テスト本体はR7の作業ツリーの手元の枝 r7-pinch-test（fab22e5c、未push）にある。

対応方針: 地図の上に重なる操作部品すべてが、ピンチをページへ渡さない（touch-action: none）ことを、部品ごとの指定ではなく「地図の上に重なる操作部品」という性質で1か所に持つ形で直す（MapLibreの既定の操作部品も含む。どの要素に掛けるかは MapLibre の公式文書と実際のDOMで確かめる）。直したあと r7-pinch-test の spec を master へ入れ、touch-action を外した入力で落ちることを作業ブランチのCIで確かめる。T1014の観点2はこれで閉じる。

完了条件: 上のspecが今のコードで緑、touch-actionを外した入力で赤（どちらもCIのrunのURL）。地図そのもののピンチでの拡大縮小が今までどおり効くこと（同じspecか既存のテストで）。

## 実施（2026-09-23）

`frontend/src/app/globals.css`に1つの規則を置いた（地図ペインのMapLibre上書きが並ぶ節）:

```css
.app-map-pane > :not(:has(> .maplibregl-map)),
.app-map-pane :is(.maplibregl-ctrl, .maplibregl-popup) {
  touch-action: none;
}
```

- **性質で選ぶ**: 「地図ペイン（`.app-map-pane`）の直下に重なる要素」と「MapLibreが地図の中へ置く
  操作部品・ポップアップ」。地図を包むMapViewの要素（直下に`.maplibregl-map`を持つ）だけを除く——
  地図のcanvasとその容器の`touch-action`はMapLibre自身が決める（`maplibregl-touch-zoom-rotate`・
  `maplibregl-touch-drag-pan`の組み合わせで`none`/`pan-x pan-y`/`pinch-zoom`を切り替える）。
- **MapLibreの操作部品の見分け方**: 公式のスタイルシート（`maplibre-gl/dist/maplibre-gl.css`）は
  操作部品の外枠を`.maplibregl-ctrl`（`pointer-events: auto`を持つ）で扱い、`touch-action`を与えて
  いるのはコンパスボタンだけ。ズーム・帰属表示等は既定のautoのまま。実際のDOMでも、落ちた
  「Zoom in」「Zoom out」「Toggle attribution」はどれも`.maplibregl-ctrl`の中にある
  （[run 35827419550](https://github.com/hidakagit/ride-compass/actions/runs/35827419550)の走査結果）。
  独自のIControlも`maplibregl-ctrl`を付けるのがMapLibreの慣例なので、足した操作部品もこの規則に入る。
- **直下だけで足りる理由**: ピンチの許可は祖先の`touch-action`との積で決まり、Chromiumでは
  スクロール容器を越えても受け継がれる（スクロール容器が戻すのはパンだけ）。直下の要素に
  `none`を掛ければ、その中の部品全部でピンチがページへ渡らない。部品が個別に持つ
  `touch-action`（チップの`none`・パネルの`pan-y`等）は、ドラッグを地図とスクロールの
  どちらへ渡すかのためのもので、この規則とは役割が別なので消していない。
- 規則の範囲外: Radixのポータルで`body`直下へ出るポップオーバー（レンズの選択肢等）は地図ペインの
  外にある。開いている間の2本指の扱いは今回のテストの母集団（初期表示で地図の範囲の最前面に
  ある部品）に入っておらず、未検査——[T1069](T1069.md)へ起票した。
- `docs/modules/frontend/frontend-design-system.md`に「地図の上に重なる操作部品は、ピンチをページへ
  渡さない」の節を足した。

テスト（`frontend/e2e/map-runtime.spec.ts`の「タッチ端末」）:

- 「地図の上に重なる部品から始めたピンチは、ページ全体の拡大にならない」: T1014段階Cで書いた
  もの（`r7-pinch-test`＝`fab22e5c`）を入れた。地図の範囲を8px格子で走査し、最前面に当たった
  部品（押せる要素ごとに1点、地図のcanvasは除く）へ2本指のピンチを`Input.dispatchTouchEvent`で
  送り、`visualViewport.scale`が1のままであることを見る。
- 「地図の上で始めたピンチは、ページではなく地図を拡大する」（足した）: canvasだけが当たる点で
  同じピンチを送り、地図の`zoomend`（デバッグログ）が出て、ページの倍率が1のままであることを見る。

## 検証

- 規則を外した入力（`40ce72b6`、masterへは入れない）:
  [run 35828944862](https://github.com/hidakagit/ride-compass/actions/runs/35828944862) で e2e が
  **1 failed / 8 passed**。落ちたのは部品のピンチの1本で、段階Cと同じ6か所（レンズのボタンと中身、
  Zoom in／Zoom outとその枠、Toggle attribution）がページを×2.17に拡大した。地図のピンチの1本は
  この入力でも緑（地図そのもののピンチは規則に依らず地図へ届く）。
- 規則を入れた側は、このコミットのCIが持つ（報告に添える）。
- 手元: `lockrun heavy`で`eslint e2e/map-runtime.spec.ts && tsc --noEmit`→通過、
  `prettier --check`→整形済み、`python scripts/review_checks.py docs`→違反なし。
