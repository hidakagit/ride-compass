# T984. テストが本番の軸データを写経している 規模M

状態: 未完了

未着手（2026-09-21起票）。

## 背景

軸定義の正本はDBだけで、`AXIS_DEFINITIONS`のPythonリテラルはT350でアプリから撤去された。
ところが`backend/tests/realistic_axis_fixtures.py`が、同じ内容（公開軸のid・shape・材料
参照・ラベル・アイコン・panel_hint）をテストコードへ手写しで複製している。

T973で軸を1つ消したとき、`backend/app`側の修正は8ファイルで済んだのに対し、テスト側は
10ファイルに及んだ。過半はこの複製と、そこから派生した「公開軸idを数え上げた期待値」
（`PUBLISHED_AXIS_IDS`ほか3か所）が原因である。**DBを正本にした意味が、テストの側で
失われている。**

さらに、軸を組み立てるファクトリがテストごとに別々に存在する。

| ファイル | 引数 |
|---|---|
| `tests/test_axis_registry_service.py` | axis_id・default_weight・material・is_published |
| `tests/test_axis_definitions.py` | axis_id・material・is_published |
| `tests/test_axis_definition_repository.py` | axis_id・default_weight |

3つとも本体は同一（`BreakpointLinearShape`・同じbreakpoints・同じラベル書式）で、
1つ目が他2つを包含する。

## 対応方針

- 本番の軸を模した固定フィクスチャをやめる。テストが要るのは「一貫した軸システム」で
  あって「本番と同じ軸」ではない。名前も構造も本番を借りない合成軸に置き換える
  （借りると、その軸が今もそう動くという誤った仕様を伝える）。
- 軸を組み立てるファクトリを1つへ寄せる。
- 公開軸idの数え上げをやめる。増減で嘘になる。

## 着手時の測定（2026-09-22）

| 測ったもの | 値 |
|---|---|
| フィクスチャが配る軸 | 8（`conftest.py`ほか3ファイルは「14軸」と書いており、既に嘘） |
| 本番の軸idを名指しするテスト | 13ファイル |
| うちappが名前を知っている軸 | `wind`・`gradient`のみ |

**`wind`・`gradient`はidを変えられない。** `WindWayService.axis_id = "wind"`のように
実装が担当軸を名前で宣言しており、テスト側だけ合成軸にはできない。名前で結ぶのを
やめる作業は[T1002](T1002.md)へ切り出した。残り6軸（`surface_q`・`stop_density`・
`accident`・`night`・`bicycle_infra_quality`・`openness`）は**appが一切名指ししておらず**
（`accident`のapp内6件はすべてデータ源名`source='accident'`、`night`の1件は
「ハードコードではない」と書いたコメント）、合成軸へ置き換えられる。

その前段として、`api/dependencies.py`が持っていた軸名リテラルの登録辞書を、
サービスクラスの宣言から導く形へ直した（api層から軸名が消えた）。

## やったこと

`tests/realistic_axis_fixtures.py`を`tests/axis_system_fixture.py`へ置き換えた。
配るのは軸の**性質**であって本番の軸ではない:

- shapeの種類（区分線形・分類）
- 必須でない項／重み0の項／負の重み
- 時間帯限定（`time_scope="night_only"`）
- 表示の上書き（しきい値・段ラベル）
- 地図アイコン無し（`show_map_icon=False`）
- 実行時スケールを要する材料（`accident_count_per_km_year`）
- 土地被覆由来の材料（外すとその配線が外れていても全経路が同じ「欠損」で一致する）
- 専用way値配信の`needs_*`の組み合わせ違い2本

ラベルは`軸ウ`のような中身を持たない文字列にし、`description`は空、本番由来の
調整値（折れ点・しきい値）は使わない。

## 完了条件

- 軸を作るファクトリがテスト全体で1つ
- 軸を1つ増減しても、期待値の書き換えが要るテストが無い
