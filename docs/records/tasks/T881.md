# T881. 蛇行軸を、ターン費用ができた今の前提で見直す（存廃を含む）

規模M。
状態: 完了（2026-09-15起票・同日に廃止を決定・撤去完了。設計原則13を書いた流れで、蛇行が原則に
合っているかを点検して発覚）

## 背景

[T691](T691.md)が蛇行軸を作った理由は「右左折の回数を数えられないから、道の形で代理する」
だった。本文にこう書かれている:

> 右左折の回数そのものは連続する2本のEdgeの関係で決まるため、Edge単体の材料で表す今の
> 軸機構には載らない（探索も`edge_cost_fn(edge_index)`で直前のEdgeを知らない）。

**その後[T790](T790.md)が探索を有向区間の状態へ変え、`TurnCostSpec`が進入・退出の方位差から
秒を足すようになった**（左2秒・右12秒・Uターン60秒、上位道路の横断8秒・右左折15秒）。
T691が「載らない」と言った当のものが、いま走行モデルに載っている。蛇行の存在理由だった
前提は崩れている。

## 原則13に照らして何が問題か

`docs/design-principles.md`構造仕様13は「軸が測るのは暴露1単位あたりの主観的な負担であり、
時間損失そのものではない。時間損失を写した材料で軸を組むと、走行モデルが既に数えた物理を
割増として二重に数える」と定める。蛇行は**折れの回数の代理**として作られており、その回数は
いまターン費用が秒で数えている。既定重み0.1は二重計上になっている可能性がある。

完全な重複ではない。測っている場所が違う:

- `TurnCostSpec` = 交差点での旋回（区間と区間の**間**）
- `curvature_deg_per_km` = 区間の**中**の道の形（河川沿いの蛇行、つづら折れ）

ただし**この境界はwayの分割位置で動く**。同じ曲がり角でも、交差点でwayが切れていれば
ターンに、1本のwayの中の折れ点なら蛇行に計上される。

## 材料そのものへの疑い

`domain/geo.py: curvature_deg_per_km`は隣り合う方位の差の絶対値を素朴に積み上げ、距離kmで
割る。**角度の閾値もスムージングも無く、除くのは重複頂点だけ**。このため:

- **緩やかなワインディングと鋭い折れを区別しない**。500mかけて緩く90度曲がる道と、1箇所で
  鋭く90度折れる道が同じ90度として積まれる。自転車にとっての意味は正反対でありうる
  （前者は快適、後者は減速と再加速）
- **直線でも頂点のノイズが積み上がる**。GPSトレース由来の細かく打たれたwayほど蛇行が
  高く出る。道の性質ではなく測量の細かさを測っている疑いがある
- **物理の減速を担わせるには使えない**。カーブの減速量は曲率半径と横加速度の上限で決まるが、
  この材料は半径を持たない

## 実測: 材料の識別力（本番、2026-09-15）

都心・多摩それぞれで長さ100〜5,000mのway 3,000本を取り、`domain/geo.py:
curvature_deg_per_km`（実関数）で蛇行を求め、累積角の内訳を見た。

| | 都心 | 多摩 |
|---|---|---|
| 蛇行の中央値 | 40度/km | 119度/km |
| 上位1割の累積角のうち30度以上の折れ由来 | 63.5% | 63.7% |
| 同 10度未満（緩い曲がり）由来 | 9.9% | 8.6% |
| 上位1割のうち30度以上の折れが1回も無いway | 47/300本 | 23/300本 |

上位の蛇行は6割強が鋭い折れ由来で、「緩い曲がりの積み重ね」が主因ではない。

### 測量ノイズではない

「鋭い折れが無いのに上位1割」のwayについて、連続する方位差の**符号の入れ替わり率**を見た
（実際のカーブは同じ向きへ曲がり続けて符号が揃い、頂点のノイズは左右へ振れて交互になる）。

- 都心: 入れ替わり率の中央値0.25、0.5超は47本中**4本**、正味の方位変化÷累積の中央値0.68
- 多摩: 中央値0.11、0.5超は23本中**2本**、正味÷累積の中央値0.73

ノイズではなく本物の一方向カーブである。頂点密度との相関（都心0.36・多摩0.57）も、
曲がった道は表現に頂点を多く要するため、それだけではノイズの証拠にならない。

### 決定的な反例: 自転車のために作られた周回コースが最悪値になる

多摩の上位に`highway=cycleway`の周回路が並ぶ。

    cycleway  第3サークル  蛇行 1898度/km  符号入替 0.00  正味÷累積 1.00
    cycleway  第2サークル  蛇行 1883度/km  符号入替 0.00  正味÷累積 1.00

半径30m程度の円がそのまま約1,900度/kmになる（円の蛇行＝57296÷半径m）。**自転車のために
用意された走りやすい道が、地域で最も「蛇行が酷い道」として採点されている。**

### 欠陥の要約

距離で割って平均するため、**「1箇所の鋭い角」と「持続する緩いカーブ」が同じ値になる**。
この2つは物理的にも主観的にも意味が正反対で、前者は減速と再加速を強い、後者は何も奪わない。
[T691](T691.md)が欲しかったのは前者（折れの回数）であり、それはいま`TurnCostSpec`が秒で
数えている。

## 判断: 廃止する（2026-09-15、ユーザー決定）

軸・材料（`curvature_deg_per_km`）・算出（`domain/geo.py`）・事前計算バッチ（⑪⑪⑫）・
タイル焼き込み・DDLの列まで撤去する。

根拠は上の実測。**この材料は「1箇所の鋭い角」と「持続する緩いカーブ」を区別できない**——
距離で割って平均するため、意味が正反対の2つが同じ値になる。その帰結が、自転車のために
作られた周回コースが地域最悪値になるという反例である。定義し直す道（鋭い折れの回数/km、
曲率半径ベース）は残っているが、[T691](T691.md)が欲しかった「折れの回数」は
`TurnCostSpec`が秒で数えており、作り直す先が既にある。

**ルート比較（二重計上の実測）は行わずに廃止する。** 残すかどうかの判断に必要な
「この材料が測れているもの」が既に崩れており、二重計上の程度を測っても結論は変わらない
（重複が小さくても、周回コースを最悪と採点する軸は残せない）。測らなかったことを
根拠の欠落として残さないため、ここに理由を書く。

## 撤去の順序（本番の起動失敗を避けるため崩さない）

1. **DBの行データを先に消す** — 本番・開発の両方で`curvature`軸をunpublish→DELETE
   （`axis_admin` API）。コードを先に消すと、新コードが「存在しない材料を参照する軸」を
   DBに見つけて`refresh_axis_definitions`のfail-fastで**本番が起動失敗する**
   （[T396](T396.md)の実績）
2. **コードを消す** — 材料・一次属性・domain関数・バッチ2本・タイル焼き込み・テスト・docs。
   生成物（`axis-catalog.json`・`material-catalog.json`・`region-tile-config.json`）を再生成
3. **DDLの列を消す** — `road_edges`の曲率列・`way_geometry`の曲率列。**2の反映が本番へ
   出てから**別コミットで行う（列を読むコードが動いている間に落とさない）

タイルの焼き込みプロパティを削る変更は、対応するfrontendのデプロイより先に本番へ出さない
（`cache_identity.py`: 旧フロントの凡例フィルタが全地物に一致し、対象レイヤーが一時的に
「不明・他」になる）。

## [T801](T801.md)との関係

T801は**物理の較正**（ターン1回あたり何秒か）で、本タスクは**主観の軸が物理を二重に
数えていないか**の判断。片方へ寄せない——秒数が正しくても軸が重複していれば二重計上は
残り、軸を廃止しても秒数が暫定値なら曲がりの費用は不正確なままになる。

## 保留することで何が起きうるか

蛇行の重みを上げた利用者は、ターン費用が既に数えた曲がりを掛け算でもう一度払う。どちらも
既定では効かない（蛇行0.1・ターンは所要時間へ常時）ため気づきにくく、「重みを上げると
不自然に遠回りする」という形でだけ現れる。
