# T403. ルート区間クリック内訳（小型チャート、既存axis-inspectorとは別経路）

状態: 完了（2026-08-30）

- 背景: 詳細はT400.md「3. ルートクリック内訳の拡張（新規バックエンド不要）」参照。ルート線に
  専用のクリックハンドラを追加し、既にフェッチ済みの`RouteSegmentDetail.axis_difficulties`を
  クライアント側だけで小型レーダー/ドーナツチャートとしてポップアップ表示する（サーバー往復
  不要）。既存の区間インスペクタ（`axis-inspector`）は一般道路網向けとして残す。
- 実装内容（フロントエンドのみ、バックエンド変更なし）:
  - `frontend/src/components/Map/routeSegmentChartPopup.ts`（新設）: ルート線クリック専用の
    ポップアップHTML生成。`RouteSegmentDetail.axis_difficulties`（geometryを除いた
    feature.properties）とaxisLabels（`useAxisCatalog`経由、軸スタジオの公開軸増減へ自動
    追従）だけを引数に取る純粋関数群で、サーバーへの新規リクエストは一切発生しない。
    チャート形式はレーダー（多角形プロット）を採用——8軸それぞれが独立した0-100の
    難易度スコアを持ち合計が100%になる構成比ではないため、構成比表現であるドーナツより
    「多軸の相対的な高低パターンを一目で見る」レーダーが適切と判断した（ライブラリは
    package.jsonを確認のうえ既存のNo-dependency SVGベースの手書きパターン
    [icons.tsx・windArrowIcon.ts・axisInspectorPopup.ts]を踏襲し、8頂点程度の単純な多角形
    描画のために新規依存を追加するメリットが薄いと判断して見送った）。頂点の色は
    `axisLayers.ts: rampColorForValue`（統一パレットRAMP_COLOR_ANCHORSの連続版、新設）で
    地図のramp軸と同じ緑→赤のグラデーションに揃える。3軸未満（多角形として意味を持たない）は
    凡例リストのみへフォールバックし、0軸（算出不可）は「算出できませんでした」を表示する。
  - `frontend/src/components/Map/axisLayers.ts`: `rampColorForBand`（段階index/bandCountから
    離散色）の内部ロジックを`rampColorForRatio`（0〜1の比率→色、非export）へ切り出し、
    新設の`rampColorForValue`（0-100の連続値→色）が同じアンカー定義
    （RAMP_COLOR_ANCHORS）を共有する形にした（設計原則2: 定数の片側import。アンカー4点を
    2箇所に手書きしない）。
  - `frontend/src/components/Map/MapView.tsx`: ルート線（`DETAIL_LAYER_ID =
    "route-detail-segments-line"`）に対し、MapLibreのlayer-scoped listener
    （`map.on("click", DETAIL_LAYER_ID, handleRouteSegmentClick)`）を新設。既存の一般道路網
    向け`handleClick`（複数レイヤーを`queryRenderedFeatures`で横断判定する汎用
    ディスパッチャ）とは完全に別関数・別登録。MapLibreはmap全体のgenericな"click"と
    layer-scopedな"click"を互いに独立して両方発火する仕様のため（`_createDelegatedListener`
    実装をnode_modules/maplibre-gl/dist/maplibre-gl-dev.jsで確認）、`handleClick`側の冒頭へ
    「クリック地点にDETAIL_LAYER_IDのフィーチャーがあれば即return」というガードを追加し、
    ルート線ヒット時に一般道路網側のポップアップが同時に開く二重発火を防いだ（ルート線は
    常にroad_surfaceタイルより上に重ねて描画されるため、この優先順位付けは実際の描画順序と
    一致する）。DETAIL_LAYER_IDがまだstyleに追加されていない（ルート未生成）間の先読み登録は
    安全（MapLibre側がレイヤー不在時は例外を投げず単に発火しないことをソースで確認済み）。
    旧`buildSegmentPopupHtml`（勾配/風/路面のみのテキスト箇条書き、`formatTime`/`formatWind`
    含む）は撤去し、`routeSegmentChartPopup.ts`のチャートベースの表示へ置き換えた
    （`formatRoad`はbuildRoadSurfacePopupHtmlと共有のため残置）。
  - テスト: `routeSegmentChartPopup.test.ts`（新設、`@vitest-environment node`——DOM操作を
    行わない純粋なHTML文字列生成のみのため）で、一次情報（距離/到達時刻/勾配/風/路面）・
    全軸ぶんのレーダーチャート＋凡例・axisLabels未登録軸のフォールバック・0/2軸時の
    フォールバック表示・欠測値の表記を検証。`axisLayers.test.ts`に`rampColorForValue`の
    テスト（両端一致・クランプ・比率不変・16進形式）を追加。
- 検証結果: `npx tsc --noEmit`クリーン（Next.js 16の`.next/types`未生成による無関係な
  `LayoutProps`エラーは`npx next typegen`で解消してから確認）。
  `npx eslint`（変更ファイルのみ指定）クリーン。フロントエンドのvitest全体
  713件通過・83ファイル通過（1ファイル[`AxisStudio.test.tsx`]は`@vitest-environment jsdom`
  指定に対し`jsdom`パッケージが未インストールのため起動時エラーで実行不能——本タスクとは
  無関係の既存環境ギャップ、別タスクとして起票済み）。
  実機確認: レーダーチャートのSVG生成ロジック（axisLayers.tsのrampColorForValue・
  routeSegmentChartPopup.tsのbuildAxisDifficultyRadarSvgと同一のジオメトリ計算式）を
  スタンドアロンHTMLへ複製し、Browserペインで8軸サンプルデータを描画して目視確認した
  （リング・スポーク・データ多角形・頂点色分けドット・凡例が意図どおり表示されることを
  確認）。ルート生成→実際のルート線クリックまでの本番相当エンドツーエンド確認は、
  本番/dev DBに接続したbackend起動が必要でこの作業ツリー（`.env`未設定の専用worktree）
  では実施しなかった（並行セッションの作業ツリーへ影響を与えないための隔離方針、
  CLAUDE.md「作業ツリーの安全」）。
