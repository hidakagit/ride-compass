# T1182. 軸の分布の分位点・ヒストグラムと軸の依存順の計算を、自前のループから numpy と標準ライブラリへ置き換える

状態: 未完了（2026-09-27起票）

## 背景

起票案 proposal-std-axis-numeric（2026-09-27承認。標準の道具の棚卸し・T1152の担当から）。規模S（根拠: 変わると見込むファイルは axis_preview_service.py・axis_definitions.py・measure_axis_saturation.py とそのテスト3本の計6本）

■ 背景（管理画面の軸スタジオの分布表示と、軸の評価順の内部の話。数値の結果は変えない前提）
- services/axis_preview_service.py の、延長で重み付けた分位点（weighted_quantiles）とヒストグラム（_distribution）は Python のループで書かれている。分位点の定義（累積の重み÷合計が q 以上になる最初の値）は numpy 2.x の np.quantile(weights=, method="inverted_cdf") と同じで、ヒストグラムは np.histogram(weights=) で書ける（範囲外を端の階級へ寄せる今の挙動は np.clip で保つ）。測定スクリプト measure_axis_saturation.py も同じ関数を使う。
- domain/axis_definitions.py の topological_axis_order は、深さ優先の自前のトポロジカルソートと循環検出。標準ライブラリの graphlib.TopologicalSorter が同じことをし、循環の経路も返す。ただし並びが変わる（今は深さ優先、graphlib は幅優先）。docstring は「挿入順を保つ（合成の加算のビット一致の要件）」を求めているので、並びが評価結果に効くかを先に確かめる。
どちらも、自前にした理由は書かれていない。

■ やること
分位点とヒストグラムを numpy へ置き換える（既存の振る舞いのテストはそのまま使える）。依存順は、並びの変化が結果に効かないと確かめられたら graphlib へ置き換え、効くなら残す理由を docstring へ書く。見込み 実装 約−35〜−55行。
