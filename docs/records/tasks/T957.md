# T957. 軸スタジオで刻んだしきい値が、地図では黙って減ることがある 規模S

状態: 完了（2026-09-19起票、T939から分離。2026-09-23完了）

## 背景

[T939](T939.md)で、**折れ線が同じ難易度へ写す境界は段として作らない**ことにした
（`domain/axis_display.py: ramp_band_thresholds`）。評価が区別できない差に色の境界を引くと、
色だけが変わって評価は同じ、という見分けを地図が見せることになり、しかもルート線側は難易度を
塗るためその段を作れない（前後で段の数が食い違う）。

この畳み込みは`display_thresholds_override`——**人が軸スタジオのGUIで指定した値**——にも効く。
テストのフィクスチャでは、4つ刻んだ上書き`[2.0, 4.0, 7.0, 12.0]`が、折れ線が5.0で100へ達する
ため`[2.0, 4.0, 7.0]`になる。**画面はこれを何も伝えない**——保存はできるのに、地図の段は
指定より少ない。

## 対応方針（着手時に確定）

軸スタジオのしきい値編集で、折れ線が飽和して効かない境界をその場で示す。どの形にするかは
未定（入力欄の脇に印を出す／保存時に知らせる／分布プレビューへ重ねる等）。

## 保留した場合の影響

刻んだ数と地図の段数が合わない理由が画面から辿れない。較正のたびに「効かない値」を
手探りで見つけることになり、`ramp_band_thresholds`の存在を知っている人にしか説明が付かない。

**ユーザー決定（2026-09-23）**: A——しきい値の入力欄の横に「この値は地図では効かない」という印を出す（刻んでいる
その場で分かるため）。保存時に知らせる案・分布プレビューへ重ねる案は採らない。効かない境界の判定は
`domain/axis_display.py: ramp_band_thresholds`と同じ規則から導き、画面側で判定を写さない。

## 実施内容（2026-09-23）

### 判定をどこに置くか——APIが判定結果を返す形にした

背景に書いた`ramp_band_thresholds`は着手時点で既に無く、規則は`axis_display_for`の中
（`_drop_thresholds_that_share_a_score`）にあった。これを`_map_band_thresholds`へ切り出し、
`axis_display_for`と新設の`thresholds_the_map_drops`の両方がそこを通す。

「源泉から配る」形（判定に要る材料をフロントへ配り、フロントで判定する）は採らなかった:

- design-principles 構造仕様1・4は、しきい値に関わる判断をbackend domainの1か所に置き、
  frontendに判断ロジックを持たせないことを求める。フロントには`interpolateBreakpointScore`
  という`evaluate_breakpoint_linear`の写しが既にあるが、「同じ点数なら段を作らない」を
  そこへ足すと、規則そのもの（丸め桁・比較・ramp表示を持つかの判定）を二重に持つことになる。
- 段が落ちるかは折れ線だけでは決まらず、**その軸がramp表示を持つか**（材料がタイルへ
  焼き込まれているか・専用way値配信か・参照先の軸を畳めるか）にも依存する。専用way値配信の
  軸（風等、`preprocess="abs"`）では上書きは落ちないが、折れ線だけで判定すると
  `-1`と`1`を同じ点数として誤って「効かない」と出す。この判定を写すのは現実的でない。

APIは`POST /api/admin/axis-definitions/preview-display-thresholds`。入力は段を決めるのに
要るもの（`axis_id`・`shape`・`priority_overrides`・しきい値）だけにした。保存用のpayloadを
そのまま受ける形にすると、表示名が空・略称が未設定といった書きかけの下書きで422になり、
印が出なくなる。`_derive_ramp_inputs`は`AxisDefinition`ではなくこの3つを受ける形へ変えた
（下書きには表示名も重みもまだ無いため）。しきい値の昇順の検証は`AxisDefinition`の検証を
静的メソッドへ出して両方から呼ぶ。

### 画面

`AxisComposer`が`useThresholdsDroppedOnMap`で下書き（`buildShape`の結果を含む）を
デバウンスして問い合わせ、`AxisMapDisplaySection`はpropで受けた値を入力欄のすぐ下に
「地図では効かない: 15, 20」と出す。理由と対処（点数の決め方を先に広げる）はⓘの奥。
取得に失敗したときは印を出さない。
