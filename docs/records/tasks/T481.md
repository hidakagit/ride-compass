# T481. debugStatsApi.tsの手書き型をbackend側Pydanticモデル化してOpenAPI生成物経由へ統一する

状態: 完了（2026-08-31）

- 背景: [T470](T470.md)項目7（ゼロベース網羅レビュー§8対応）で発見し、backend/frontend
  両方にまたがるためバックグラウンドタスクとして切り出すとされていた指摘の正式起票。
- 現状: `backend/app/api/routers/health.py: debug_stats()`（`GET /api/debug/stats`）が
  `-> dict`という型無しの戻り値注釈のまま実装されている。そのためOpenAPI生成物
  （`frontend/src/types/generated/openapi.json`）でもこのエンドポイントのレスポンス
  スキーマが`{"type": "object", "additionalProperties": true}`という完全に無型のものに
  なっている（確認済み）。結果として`frontend/src/services/debugStatsApi.ts`が
  `ExternalCallStats`/`DebugStats`という手書きTypeScript interfaceを独自に持って型を
  代替しており、CLAUDE.md「定数の片側import」原則から見ると望ましくない状態（backend側の
  実装が変わってもfrontend側の手書き型が自動的に追従しない二重管理）。
- 対応方針:
  1. `backend/app/infrastructure/debug_log.py: get_stats()`の戻り値の実際の構造
     （`health.py: debug_stats()`が組み立てるdict、`commit`/`started_at`/`engine`/
     `debug_mode`/`external`[ExternalCallStats相当]/`rate_limit_rejections`の
     フィールド構成）に対応するPydanticモデル（例: `ExternalCallStatsResponse`/
     `DebugStatsResponse`）を新設する。
  2. `debug_stats()`の戻り値型注釈を`-> DebugStatsResponse`へ変更する。
  3. `backend/scripts/export_openapi.py`→`cd frontend && npm run generate:api`を実行し、
     `git diff --exit-code -- frontend/src/types/generated/`がクリーンであることを確認する
     （CLAUDE.md「コミット時の同期ルール」）。
  4. `frontend/src/services/debugStatsApi.ts`の手書き`ExternalCallStats`/`DebugStats`
     interfaceを削除し、生成された型（`frontend/src/types/generated/api.d.ts`由来）を
     使うよう書き換える。
  5. `getDebugStats()`の戻り値型も生成型へ揃える。
- 優先度: 低（現状の手書き型は正しく機能しており実害は無い、あくまで型の二重管理という
  設計上の綺麗さの問題）。着手する場合はbackend/frontend両方の変更が必要な点に注意。
  規模S〜M。
- 実施結果（2026-08-31）:
  1. `backend/app/api/routers/health.py`に`ExternalCallStatsResponse`/
     `DebugStatsResponse`（Pydantic `BaseModel`）を新設し、`debug_stats()`の戻り値型注釈を
     `-> DebugStatsResponse`へ変更（`response_model`も指定）。戻り値も辞書リテラルから
     `DebugStatsResponse(...)`の明示構築へ変更した。
  2. `export_openapi.py`→`npm run generate:api`を実行し、`git diff --exit-code -- frontend/
     src/types/generated/`で他の生成物（axis-catalog.json等）に差分が無いこと・
     `api.d.ts`/`openapi.json`へ新スキーマ2件のみが追加されたことを確認した。
  3. `frontend/src/services/debugStatsApi.ts`の手書き`ExternalCallStats`/`DebugStats`
     interfaceを削除し、`components["schemas"]["ExternalCallStatsResponse"]`/
     `["DebugStatsResponse"]`の再エクスポート（`types/route.ts`と同じパターン）へ置き換えた。
     呼び出し側（`SystemStatusPanel.tsx`等）は型名を変えていないため無修正で済んだ。
  4. 検証: `pytest tests/test_health.py tests/test_debug_stats_route.py
     tests/test_debug_log.py -q`（全green）・`npx vitest run
     src/services/debugStatsApi.test.ts src/components/SystemStatusPanel/
     SystemStatusPanel.test.tsx --pool=threads`（10件green）・`npx tsc --noEmit`・
     `npx eslint src/services/debugStatsApi.ts`いずれもエラー無し。
