# T1108. ルートの風を地点ごとの予報で引く（今は出発地点1か所の予報を全区間に使う）

状態: 未完了（2026-09-25起票）

## 背景

ユーザー質問（2026-09-25）への回答で判明: ルートの風は出発地点1か所の時別予報を全Edgeへ使う（docs/modules/backend/routing-engine.md「暗黙の前提のまとめ」、road_graph_engine.py の get_wind_forecast_series(wind_and_night_origin)）。承認時の決定: 地点ごとの風を使う方向で起票し、まず計測する。段階1（計測、S）: 本番で、ルートのbbox内の風の地点差（同じ時刻の予報格子点どうしの風速・風向・向かい風成分のばらつき）と、格子の読み出し（WeatherService.get_wind_grid）とEdgeへの割り当てにかかる時間を測る。段階2以降は計測の結果で決める（ユーザーへ報告して判断を仰ぐ）。

## T1107からの引き継ぎ（2026-09-26）

区間の風は`RouteSegmentDetail.wind`で配り、frontendの区間の詳細（`features/route/SegmentWind/SegmentWind.tsx`）の(i)は「出発地点の風の予報」と
書いている。地点ごとの予報にしたら、この文と`docs/modules/backend/routing-engine.md`「暗黙の前提のまとめ」の風の1文を直す。区間の値の合成し直し
（`_LegCostComposer.values_at_rows`）は`DynamicAxisRequestContext`を行で切って作るので、地点ごとの風を入れるときは行ごとの風の入力も同じ行で切る。
