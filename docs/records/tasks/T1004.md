# T1004. E2Eが、地図が描けたかを見ていない 規模S〜M

状態: 未完了

未着手（2026-09-22起票。[T1003](T1003.md)でmaplibre-glをv6へ上げる際、Workerを壊した状態で
E2E 9本が全て通ったため判明）。

## 何が起きたか

Workerのスクリプトが404になり地図が**一切描かれない**状態（canvasは残るが中身が空、
`Failed to load module script: ... non-JavaScript MIME type of "text/html"`）で、
`npm run test:e2e`の9本がすべて緑になった。E2Eはチップの開閉・候補一覧・シートの表示という
**DOMの状態だけ**を見ており、地図が描けたかを見ていない。

**害**: 地図アプリの回帰のうち最も重いもの（何も描かれない）をCIが通す。利用者からは
「真っ白な地図」として届く。

## 完了条件

- 地図が描けたことを見る検査が1つ入っていること。**壊れた入力を1件通して落ちることを確認する**
  （`configureMaplibreWorker()`の呼び出しを外してビルドすると落ちる、が再現手順。手順の詳細は
  [T1003](T1003.md)「確認の手順」）。
- 何を見れば「描けた」と言えるかを決めて書くこと。候補: canvasのピクセルが一様でないこと
  （`toDataURL`の分散）・タイル要求が200で返ること・`maplibregl-canvas`のサイズが
  コンテナと一致すること。**どれを採るかは、上の「壊して落ちる」を満たすかで決める**
  ——満たさないものを入れても、いまと同じく緑のまま通る。
- 1本だけにすること。全specへ足すと、遅いうえに同じことを9回確かめる。
