# T954. 勾配レンズで、値を示せない道が濃いグレーで地図を覆う 規模S

状態: 完了（2026-09-19。2026-09-19起票）

## 背景

ユーザー指摘: 勾配レンズをONにして方位0度を指定すると、東西に伸びる道が勾配の計測対象外に
なるのは想定どおりだが、**すべてグレーになって見にくい**。

調べると、専用way値レイヤー（勾配・風）だけが地図全体の読み方から取り残されていた。
`roadFilterAxes.ts`は「不明・他」について**「薄い＝対象外、濃い＝分類あり」という読み方を
地図全体で統一する**と定め、`FALLBACK_LINE_OPACITY = 0.15` / `KNOWN_LINE_OPACITY = 0.8`を
置いている。`staticAttributeLayers.ts`（自転車インフラ・指定路線）もこれを共有している。
ところが専用way値レイヤーの`paint`は`line-color`と`line-width`しか持たず、
**MapLibreの既定値（`line-opacity` = 1）で塗られていた**。

backend（`services/gradient_way_service.py`）は指定方位に対して直角に近いwayを値から外すため
（`domain/gradient.py: shows_gradient`）、フロントにはnullが届き`COLOR_NO_DATA`が全不透明で
塗られる。方位を1つ指定すると、街区の半分近くがこの状態になる。

## 対応

`dedicatedWayValueLayer.ts`へ`buildDedicatedWayValueOpacityExpression`を足し、
`MapView.tsx`の`paint`へ`line-opacity`として渡した。**新しい表現を作らず、既にある規約へ
このレイヤーを合わせただけ**である。`ensureLayerFromSpec`は既存レイヤーへ全paintプロパティを
`setPaintProperty`で再適用するため、追加の配線は要らなかった。

取得中（`loading`）のあいだは薄くしない——`COLOR_LOADING`が見えなくなり、「取得中」と
「対象外」の区別が付かなくなるため。

## 検討したが採らなかったもの

- **直角の道だけ破線にする**: MapLibreの`line-dasharray`はデータ駆動にできず、値は
  feature-state経由で入るため`filter`からも読めない。**技術的に不可**。
- **「この向きでは測れない」を「データなし」と別の状態にする**: 配信側が種類を持つ契約変更が
  要り、凡例も1行増える。どちらも利用者にとっては「いま見ている条件の対象外」で、走行中の
  スマホで情報量を増やす価値に見合わないと判断した（2026-09-19ユーザー判断）。
- **描かない**: `docs/design-principles.md`「消さずに薄くする」に反する。

## 検証

- `dedicatedWayValueLayer.test.ts`（式の形）と`MapView.layerOps.test.ts`（**paintへ実際に
  届くか**）を追加。後者は`addLayer`のspecと`setPaintProperty`の呼び出しを見る。
- **わざと`line-opacity`をpaintから外して、追加した2件が落ちることを確認した**
  （外すとMapLibreの既定値1で塗られ、症状がそのまま戻る）。
- frontend全体: `npx vitest run` / `tsc --noEmit` / `eslint`。

## 残り
