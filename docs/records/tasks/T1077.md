### 何を守るか——母集団は「モックが置き換えている入力」から導く

`frontend/e2e/`（モック・CI）が見られないものは、**`e2e/fixtures.ts`の`installApiMocks`が本物の代わりに
返しているもの**そのものである。そこで母集団を手で考えず、モックが置き換えている入力を1つずつ取り、
「そこに本物が来たときにだけ起きる壊れ方」を類にまとめた。モックの置き換え方（2026-09-23時点の`installApiMocks`）:

| モックが置き換えているもの | モックでの中身 | 本物が来ると通る経路 |
|---|---|---|
| 基礎地図のスタイル（`/api/basemap/**`） | 空のスタイル（ソース・レイヤー無し） | backendが書き換えたタイル・スプライト・グリフのURL |
| 路面・POI・事故・土地被覆・気象庁・地理院のタイル（`next.config.ts`のrewritesの経路） | 204・中身無し | `features/map/scene/`の式へ実データの値が入る |
| 軸カタログ（`/api/axis-catalog`） | 1軸だけ・`tile_versions`空 | 開発DBの公開軸すべて・世代・動的値の配信（`dedicated_way_value_layer`） |
| ルート生成（`/api/routes/generate`） | 1回目から完了・固定の候補 | 実グラフでの探索・区間ごとの軸の値 |
| 気象（風・アメダス・警報・WBGT・洪水予報・気象庁の時刻一覧） | 固定値・空配列 | 実行した時刻で中身が変わる入力 |

この5つから、壊れ方の類を次の5つに分けた。**実例はすべてリポジトリの記録から取った**（下の「根拠の拾い方」）。

| 類 | 壊れ方 | 記録にある実例 |
|---|---|---|
| K1 実データでしか出ない描画 | 実際の値・型・組み合わせが式や部品に入って初めて壊れる | [T367](T367.md)（公開軸の材料がタイルへ焼かれておらず、地図に一切出ない）・[T886](T886.md)（DBから読んでいる土地被覆の内訳が画面へ渡らない）・[T485](T485.md)（MapLibreが区間のオブジェクト値を文字列にし、ルート線を押すとポップアップが例外で開かない。単体テストはオブジェクトを直接渡すので通っていた） |
| K2 実backendとの契約（形は型が守るが、意味と組み合わせは守らない） | カタログ・タイル・動的値の宣言どうしが食い違う | [T672](T672.md)（3つ目の専用レイヤー軸を公開すると地図に出ず、既存軸をOFFにすると巻き添えで消える）・[T643](T643.md)（取得の失敗が「200＋空タイル」で返り、画面は「道が無い」と区別できない） |
| K3 キャッシュ・世代 | 古い値・空の値を掴んだまま出し続ける | [T643](T643.md)（その空タイルがブラウザに1時間残る）・[T574](T574.md)（ディスクから古いタイルが復元され続け、未訪問のタイルだけ新しくなる）・[T691](T691.md)（修正前に焼いた材料キャッシュが同じ世代番号で残り、修正のデプロイ後も値が来ない） |
| K4 時刻・天候・外部配信の仕様で変わる入力 | 実行した時刻・ズームで出たり消えたりする | [T619](T619.md)（日本時間0〜8時台だけ時刻が9時間ずれ、風のレンズが全て灰色）・[T637](T637.md)（気象庁のキキクルは偶数ズームにしか実データが無く、奇数ズームで危険度が消える） |
| K5 実グラフでしか出ない探索の欠陥 | 実データの形（並行する道・取込範囲の端）で生成が落ちる | [T790](T790.md)（並行するEdgeがあると探索用グラフとスコア行列の行が食い違い、ルート生成が丸ごと落ちる。開発DBの実行で見つかった）・[T236](T236.md)（取込範囲の外周で生成が失敗する） |

**対象にしないもの**（e2e-liveに入れない）:

- 見た目・色・読みやすさ（パターン4の観点4と同じ。人が見る）。
- 性能・所要。開発DBは本番と規模が違い、計測は本番で行っている（例: [T531](T531.md)・[T538](T538.md)の本番計測）。
- 本番DBにしか無い軸・データ。e2e-liveが見るのは開発DBにある公開軸で、軸の正本は本番DB（CLAUDE.md）。
- backend内部のキャッシュが**正しい値か**（K3の原因そのもの）。データを書き換えないと観測できない。e2e-liveは
  症状（値が来ない・空で返る）だけを見る。
- 画面の全状態の走査。状態の木を辿るのはモックのe2e（T1078）の仕事で、実データでは状態の数が決まらない。

**根拠の拾い方**（再現用）: `git grep -n -E "モックでは(出|見え|通)|実データでしか|本番でしか|地図に出ない|真っ白|灰色になる|描かれない|表示されない" -- docs/records/tasks`
と`git grep -n -E "起動直後|デプロイ直後|キャッシュに効かない|取込範囲外|深夜|実データでしか" -- docs/records/tasks`
の該当から、原因が「実データ・実backend・実時刻が来たときだけ起きる」ものを選び、記録の本文で原因を確かめた。
モックのe2eでも捕まえられた形のもの（Workerの404で地図が真っ白＝[T1003](T1003.md)・[T1004](T1004.md)。
`map-runtime.spec.ts`が画素で見ている）は除いた。

### シナリオの選び方の基準

1. **類（K1〜K5）ごとに、その壊れ方が画面に出る最短の経路を選ぶ。** 各シナリオは、上の表の実例のうち少なくとも
   1件を「壊した入力」として再現し、落ちることを確かめてから入れる（CLAUDE.md「修正の原則」・パターン4の書き方6）。
2. **当てる相手（軸・レイヤー・気象の種類）は手で名指ししない。** 軸は`GET /api/axis-catalog`の公開軸すべて、
   レイヤーは`mapDisplay.layerIds`すべて（`map-runtime.spec.ts`の全レイヤーONと同じ出どころ）、気象はbackendが
   宣言する描き方（[T1017](T1017.md)）すべて。時刻を入力に取る軸は、カタログの`dedicated_way_value_layer`が真の軸。
   軸が1つ増えれば、何も書き足さずに検査の相手に入る。
3. **モックのe2eで見られるものは置かない。** 同じことを実データで遅く確かめるだけになる。
4. **離散の入力（時刻・ズーム）は、実例の欠陥の境界から代表点を導く。** 時刻は「日本時間とUTCで日付が
   異なる時間帯（日本時間0〜8時台）」と「同じ時間帯」の1点ずつ（T619）。ズームは偶数と奇数の1段ずつ（T637）。
   実行した時刻に任せない——任せると、壊れていても昼に回せば緑になる。
5. **幅はモバイルだけ。** 主用途はスマホで（[T1027](T1027.md)）、幅の分岐そのものはモックのe2eが両側で見ている。
   e2e-liveが幅で見るのは、実データの長さ（実際の軸名・道路名）で観点1が崩れないかだけ。

### シナリオの組み方（ユーザー提案「A→Bで止めてC、D、E→Fをまとめて見る。移動はショートカットする」）

**1シナリオ＝1枚のページ＝1本の幹。** 幹（A→B）で重い段取り——実backendでの起動・地点への移動・ルート生成——を
1回だけ払い、幹の終点で互いに独立な枝（C、D、E→F）をまとめて見る。枝は見終えたら幹の終点へ戻す。

- **戻す・戻せたかの確かめ**は、T1078で確定した仕組み（押したものをもう一度押す／Escape、タブは元のタブを押す、
  ARIAの開閉値・localStorage・`visualViewport.scale`の指紋が押す前と一致するか）をそのまま使う。
  戻らなければ違反として落とし、黙って別の状態で次の枝を見ない（T1078と同じ判断）。
- **枝の失敗で他の枝を止めない**（`expect.soft`）。実データの1回の段取りは重いので、1回で全部の結果を持ち帰る。
- **移動のショートカット**: 利用者の操作を真似ず、アプリが既に持っている入口で状態を与える——地点は
  ブラウザの現在地（Playwrightの`geolocation`。アプリは`navigator.geolocation`から起点を取る）、レイヤーの
  ON/OFFは保存状態（`seedStoredState`でlocalStorageへ。`map-runtime.spec.ts`と同じ）。**入口が無いもの**
  （地図の拡大率・出発時刻等）は段階Bで入口の有無を調べ、無ければ画面の操作で行う（テストのためにアプリへ
  入口を足すかは、そのとき別に諮る）。
- **T1078との関係**: T1078はモックの画面で状態の木を全部辿る。e2e-liveは木を辿らず、実例から導いた枝だけを
  見る。「押せるものだけ押す」「戻す＋指紋」「フレーム単位の待ち」はT1078の実装を共用する。共用の部品の置き場
  （`e2e/`から読むか、共通の置き場へ出すか）は、T1078がmasterへ入って形が決まってから段階Bで決める。

（外部呼び出し・キャッシュのカテゴリ別の呼び出し数・エラー数・429拒否数。常時公開）をシナリオの前後で取り、
**自前の処理のエラー・429拒否が増えていない**ことを見る。外部のカテゴリ（気象庁・地理院・基礎地図の元等）の
エラーは合否に入れないが、報告に「外部要因」として必ず出す（黙って緑にしない）。カテゴリが自前か外部かの
分け方は段階Bで`log_external_call`の呼び出し元から確かめる。

### 期待値の書き方——値ではなく性質で書く

実データは取込・軸の調整・天候で変わるので、**特定の値・件数・色・画素の写しは書かない**（写しと比べるのは
CLAUDE.mdが検知器へ禁じている「保存した過去の値と比べる」と同じ形になる）。書いてよい性質は次の4種類:

| 性質 | 形 | 例 |
|---|---|---|
| 存在 | 1件以上（パターン6の「空でない」主張を**同じテストの中に**置く） | 路面タイルに道が1件以上・候補が1件以上 |
| 整合 | 独立な2つの出どころが食い違わない | カタログが読むと言う材料 ⇔ タイルに焼かれた材料、偶数ズーム ⇔ 奇数ズーム |
| 不在 | エラー・例外が0件 | `[map:error]`・ページの例外・backendの自前のエラー |
| 要求への応答 | 利用者が入れた条件と結果の関係 | 候補の距離と、指定した距離・許容幅の関係（backendが許容幅を保証しているかを段階Bで仕様から確かめてから入れる。保証していなければ書かない） |

**実世界で「無い」のが正当なもの**（警報が出ていない・危険度が無い・時刻一覧が空）は、別の出どころが「ある」と
言うときだけ判定し、判定しなかったときは「該当なし（理由）」をログへ出す。黙って空振りで緑にしない
（パターン6と同じ理由）。

**失敗を2種類に分ける**: 前提の不成立（backendが動いていない・地点が取込範囲外・基礎地図のURLのずれ・外部の停止）
は`globalSetup`で最初に確かめて「前提不成立: 何を直せばよいか」で止め、個々のテストの失敗として出さない。
テストの失敗は壊れ方の検知だけにする——そうしないと、回した人が環境の問題を欠陥として追うことになる。

### 前提

1. **backend**: 開発DBへ向いたbackendが手元で動いていること（既定`http://localhost:8000`。作業ツリーには`.venv`が
   無いので本体のチェックアウトの`backend/.venv`を使う——orchestration.md「重い処理は機械全体で1本ずつ」）。
   設定がbackendを起動することはしない（DBの向け先・`.env`は人ごとに違い、設定ファイルが向け先を決めることになる
   ため）。`globalSetup`が`/health`で確かめる。
2. **開発DBのデータ範囲**: **リポジトリに記録が無い**（`backend/app/batch/source_profile.yaml`の`bbox`はラスタ系の
   範囲で、道路の取込範囲ではない）。そこで起点を範囲から推測せず、環境変数（例: `E2E_LIVE_POINT`）で与え、
   既定はアプリの既定地点（`useLocation.ts`。`docs/architecture/setup.md`の確認用の地点と同じ）にする。
   `globalSetup`がその地点の路面タイルに道があることを確かめ、無ければ「前提不成立: 取込範囲外」で止める。
3. **基礎地図のURL**: backendは基礎地図のスタイル内のURLを`basemap_public_base_url`（既定
   `http://localhost:3000/api/basemap`）で組み立てる。E2Eは専用ポートで起動する（`frontend/e2e/`は3100）ので、
   合わせないと基礎地図のタイルが別のポートへ飛ぶ。backendを`BASEMAP_PUBLIC_BASE_URL`をE2Eのオリジンに合わせて
   起動すること。`globalSetup`がスタイルJSONのタイルURLのオリジンを確かめる。
4. **frontend**: `frontend/e2e/`と同じく本番ビルド（standalone）を起動する。`NEXT_PUBLIC_API_URL`はビルド時に
   埋め込まれるので、backendの向け先を変えたらビルドし直す。**開発機では`webServer.env`に`HOSTNAME: "localhost"`
   が要る**（[T1014](T1014.md)「開発機での実行」: Git Bashの`/etc/profile`が`HOSTNAME`へ機械名を入れてexportし、
   standaloneのサーバーがIPv6のグローバルアドレスでしか待ち受けず、`localhost`への接続が拒否される）。
   `playwright.live.config.ts`は新しいファイルなので最初から入れる（`playwright.config.ts`への同じ修正はT1078の側）。
5. **外部**: backendが気象庁・国土地理院・基礎地図の元へ取りに行くので、ネットワークが要る。予報（MSM）の
   鮮度は`/api/debug/stats`の`msm.healthy`で`globalSetup`が確かめ、古ければS3の該当の枝を「前提不成立」にする。
6. **直列**: workers=1。開発DBと手元のbackendは1つなので、ルート生成の同時実行・レート制限（429）を避ける。
   ルート生成の初回は、タイル材料のキャッシュが冷えていると数十秒以上かかる（`setup.md`の記述。実測ではない）。

### 走らせ方と所要

- 手順（開発機、並行実行中は段ごとに`heavy`の枠を通す）:
  `python scripts/lockrun.py heavy -- 'cd frontend && npm run build'` →
  `python scripts/lockrun.py heavy -- 'cd frontend && ./node_modules/.bin/playwright test -c playwright.live.config.ts <spec>'`
  をシナリオ（spec）ごとに1回。枠の上限（10分）に1シナリオが収まることを段階Bの完了条件にする。
- CIには載せない（D-017。CIのランナーには開発DBも手元のbackendも無い）。
- **所要は未計測。** 分かっている部品は、本番ビルド221秒（T1014「開発機での実行」の実測）と、冷えたキャッシュでの
  初回のルート生成が数十秒以上（`setup.md`、実測ではない）だけ。シナリオごとの所要は段階Bで測って書く。

### 誰がいつ回すか（案。決めるのはユーザー、下の保留）

## 保留（ユーザー判断）: 定義案を採るか（2026-09-23 依頼）

利用者への約束: 本番に近いデータで地図・ルート・気象が「出る」こと（何も描かれない・値が来ない・押すと例外で
開かない、を出さないこと）。いまのE2E（CIで毎回回るもの）は、道・軸・気象をすべて作り物の応答へ差し替えて
いるので、たとえば「軸スタジオで公開した軸が地図に一切出ない」「深夜に開くと風の地図が全部灰色」
「ルート線を押すとチャートが例外で開かない」は、過去に実際に起き、どれもCIを緑のまま通った。
起きない場面: 画面の部品が幅からはみ出す・ピンチで拡大する等の見た目の崩れは、作り物のデータでも出るので
今のE2Eが見ている（この案の対象外）。

案の中身は上の「段階A: 定義案」節——開発DBと手元のbackendへ向けて、(S1) 全レイヤーを出した地図・
(S2) 1回のルート生成の結果・(S3) 時刻で変わる風と気象、を1枚のページで幹を1回だけ辿り、その先でまとめて見る。
値そのものは見ず、「1件以上ある」「宣言と実物が食い違わない」「エラーが0件」で判定する。CIには載せない。

1. **案どおり採る（推奨）**。段階Bで設定・前提の確かめ・S1から作る（T1078がmasterへ入ってから着手）。
   過去の実例が一番多い地図の描画から守りが付く。
2. **S1だけ採る**。ルート生成（S2）と時刻（S3）は、S1を回して所要と手間を見てから改めて決める。
3. **採らない**。e2e-liveの置き場は空のまま残し、今の回し方（人が画面で確かめる）を続ける。

## 保留（ユーザー判断）: e2e-liveを誰がいつ回すか（2026-09-23 依頼）

利用者への約束は上と同じ。CIに載せないので、**回す約束を決めないと誰も回さない**（置き場だけ作って中身が
使われない状態になる）。一方で、1回に本番ビルド（約4分）と実backendでのルート生成が要り、毎回の変更で
回すと作業が遅くなる。

1. **地図の描き方・タイルへ焼く値・軸カタログ・気象の描き方・ルート生成の応答に触る変更のとき、その担当が
   作業ブランチを出す前に1回（推奨）**。壊した変更がmasterへ入る前に捕まる。触らない変更では回さない。
2. **周期レビュー（2週間ごと等）のときにまとめて1回**。担当の手間は増えないが、壊れてから見つかるまで最大で
   1周期かかる（その間、本番の利用者に出うる）。
3. **ユーザーが必要と思ったときだけ**。仕組みとして回す約束はしない。
