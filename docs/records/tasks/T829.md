# T829. 動的気象タイルの切り替えで、MapLibreが「ArrayBuffer is detached」を吐く

規模S。
状態: 完了（2026-09-13。ユーザー報告の実機ログ
`[map:error] Failed to execute 'postMessage' on 'Worker': An ArrayBuffer is detached and could not
be cloned. {"sourceId":"region-dynamic-weather-disaster-flood-vector"}`）

## 原因

`Map/jmaTileProtocol.ts`が、空タイルの中身をモジュール定数（透明PNGと0バイトのMVT）で
持ち、要求のたびに**同じインスタンスを返していた**。MapLibreはタイルのデータをWorkerへ
transferして渡すため、一度返したArrayBufferはdetachedになる。2回目以降のpostMessageが
`An ArrayBuffer is detached and could not be cloned`で失敗し、そのタイルが描画されない。

報告されたログの`sourceId`がベクタ（`...-flood-vector`）なのはこのため——ラスタは
`createImageBitmap`を経由しtransferされない。空タイルは在否インデックスで空と分かっている
場合だけでなく**404（疎な格子状タイルでは正常系）でも返る**ため、一度でも空タイルが出れば
以後その経路は必ず失敗する。起票時に書いた「コマ送りのsetTilesと取得中タイルの競合」は
誤りで、コマ送りとは無関係だった。

## 実装

空タイルの中身を返す`emptyTileBytes(realUrl)`を置き、呼ぶたびに新しいバッファを作る
（ベクタは`new Uint8Array(0)`、ラスタは透明PNGの`slice()`）。

検証:

- 同じURLで2回続けて要求し、返るバッファが別インスタンスであること・1つ目をtransferで
  detachedにしても2つ目が健全であることを回帰テスト化（`jmaTileProtocol.test.ts`）
- 修正前の実装（共有インスタンス）へ戻すとこのテストが落ちることを確認してから直した
- `npx vitest run src/components/Map/jmaTileProtocol.test.ts` → 8 passed、
  `tsc --noEmit`・`eslint`ともにクリーン
