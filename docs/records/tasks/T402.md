# T402. Route.axis_difficulties新設とBottomSheetルート全体プロファイル

状態: 完了（2026-08-30）

- 背景: 詳細はT400.md「4. ルート全体プロファイル（BottomSheet）」参照。`Route`にルート全体の
  `axis_difficulties: dict[str, float]`を新設（既存の`_merge_axis_difficulties`をルート全区間へ
  適用するだけ）。BottomSheetで軸ごとの横棒グラフ一覧として表示する。
- 実装内容:
  - `backend/app/domain/route.py`: `RouteCandidate`へ`axis_difficulties: dict[str, float] =
    Field(default_factory=dict)`を新設。既存の`_merge_axis_difficulties`（ビン集約
    `_merge_segment_bin`専用の私有関数だった）を`merge_axis_difficulties`へ改名して公開関数化し、
    `RouteCandidate.axis_difficulties`側からも同じ関数を再利用する（新しい計算式は追加していない）。
  - `backend/app/services/route_generator.py`: `_with_overall_difficulty`と対になる新規
    staticmethod `_with_axis_difficulties`を追加し、`generate_loops`・`generate_via_waypoints`
    両方の呼び出し元で`_with_overall_difficulty`のすぐ後に適用する（segments欠損時は空dictの
    まま、overall_difficultyと同じ空振り規約）。
  - OpenAPI再生成（`export_openapi.py`→`npm run generate:api`）。`RouteCandidate`スキーマへ
    `axis_difficulties`フィールドが追加され、`git diff --exit-code -- frontend/src/types/
    generated/`はapi.d.ts/openapi.jsonの2件のみ（他の生成物は差分無し）。
  - フロント: 新規コンポーネント`frontend/src/components/RouteAxisProfile/RouteAxisProfile.tsx`
    （軸ごとの横棒グラフ一覧、レーダーチャートは不採用[T400確定方針]）。軸の並び順・ラベルは
    `useAxisCatalog().axes`から取得しハードコード辞書は新設していない。バーの色は
    `axisLayers.ts`の`rampColorForBand(index, bandCount)`を`bandCount=101・
    index=Math.round(difficulty)`で呼ぶことで、difficulty(0-100)の連続値を地図の段階配色
    （`RAMP_COLOR_ANCHORS`、緑→黄→橙→赤）と完全に同じ配色系統へ写像する（新しい配色ロジックは
    追加していない）。
  - 導線: 既存の`frontend/src/components/BottomSheet/BottomSheet.tsx`をそのまま流用（自前シート
    実装なし）。`page.tsx`の`renderRouteOutcomeSectionBody`（デスクトップの「ルートを作る」
    ブロック・モバイルの「ルート結果」タブの両方から呼ばれる共通関数）へ「ルート全体
    プロファイルを見る」ボタンと専用BottomSheetを追加した。開閉状態（`routeProfileOpen`）は
    既存の`mobileSheet`（ルート設定/ルート結果/地図の見え方の3タブ排他）とは独立させ、
    デスクトップでも開けるようにした（この判断はUI設計として未確定だったため、page.tsx側に
    コメントで理由を残してある）。高さは既存3シートと同じ`mobileSheetHeightVh`を共有する
    （BottomSheet.tsxの既存方針どおり）。
  - `RouteCandidate`が必須フィールドになったことに伴い、フロントの既存フィクスチャ
    （`page.test.tsx`・`routeApi.test.ts`・`ComparisonPanel.test.tsx`・`RouteList.test.tsx`・
    `MapView.bench.ts`・`MapView.routes.test.ts`・`e2e/fixtures.ts`の`makeCandidate`等）へ
    `axis_difficulties: {}`を追加。
- テスト:
  - backend: `backend/tests/test_route_generator.py`へ
    `test_axis_difficulties_is_distance_weighted_average_of_segments`・
    `test_axis_difficulties_is_empty_dict_when_segments_missing`・
    `test_generate_via_waypoints_also_aggregates_axis_difficulties`の3件を追加
    （`_with_overall_difficulty`の既存テストと対になる形）。
  - frontend: `frontend/src/components/RouteAxisProfile/RouteAxisProfile.test.tsx`を新規作成
    （軸カタログ順で値を持つ軸だけ表示・空dict時の案内文の2ケース）。
- 検証結果:
  - backend: `pytest -q -m "not postgis"` 1389件全通過。
  - frontend: `tsc --noEmit`クリーン、変更ファイルへの`eslint`クリーン、`vitest run`
    720件全通過（RouteAxisProfile単体2件を含む）。
  - `git diff --exit-code -- frontend/src/types/generated/`はapi.d.ts/openapi.jsonの生成差分
    以外クリーン（同期ルール確認済み）。
