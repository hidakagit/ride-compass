# T1053. 利用条件を公式で確定できなかった外部ソース（逆ジオコーダ・MSMと気象業務法・WBGTの予測値API）の扱いを決める

状態: 未完了（2026-09-23起票）

## 背景

T975でdocs/architecture/data-sources.mdを作った際、3件は提供元の公式ページから商用利用の可否を確定できず「要確認」とした。

## 何が確定していないか（2026-09-23時点、提供元の公式ページで読めた範囲）

[data-sources.md](../../architecture/data-sources.md)で「要確認」とした行。どれも現状の
機能は動いており、**止まるのは商用化の判断**である。

1. **国土地理院 逆ジオコーダ**（`mreversegeocoder`、`backend/app/infrastructure/jma_warning_client.py`
   が警報の区域を引くのに使う）: 公開APIとしての利用条件が無い。国土地理院は
   [gsimaps README](https://github.com/gsi-cyberjapan/gsimaps)で、地理院地図から呼ぶ
   サーバ側動的機能は「主に地理院地図からの利用を想定」し、継続提供も仕様も保証しないと
   書いている。許諾の問題に加え、**予告なく止まりうる**。
2. **気象庁MSMと気象業務法第17条**（予報業務の許可）: 配布物（Open-Meteo）はCC BY 4.0だが、
   気象庁の利用条件は気象業務法の制約を別に挙げる（[気象庁 copyright](https://www.jma.go.jp/jma/en/copyright.html)）。
   RideCompassはMSMの格子値を補間し、出発時刻・区間ごとの風として画面とルート計算に使う。
   これが「予報業務」に当たるかは読めていない。
3. **環境省WBGTの予測値API**（`backend/app/infrastructure/wbgt_client.py`の
   `api/v1/getForecastData`・地点マスタCSV）: サイトはPDL1.0準拠だが、「電子情報提供サービス」は
   同規約の適用外と明記されている（[ご利用にあたって](https://www.wbgt.env.go.jp/tos.php)）。
   使っているAPIがどちらの条件に当たるかが読めていない。

## やること

各項目について、公式の文書（規約本文・FAQ・問い合わせへの回答）で条件を確定し、
data-sources.mdの行を「要確認」から確定値へ書き換える。観測や第三者の記事で埋めない。

- 1: 国土地理院の問い合わせ窓口への確認、または代替（区域の判定を自前のデータで行う等）の
  検討。代替に使うデータもdata-sources.mdの手順に従う。
- 2: 気象庁の「予報業務の許可」に関する公式の説明を読み、数値予報の格子値を加工して
  表示・利用することの扱いを確かめる。公式文書で決まらなければ気象庁へ照会する。
- 3: 電子情報提供サービスの利用規約本文（data_service.phpから辿れるもの）を読み、使っている
  エンドポイントがどれに当たるかを確かめる。

### 3. 環境省WBGT（確定: 商用可）

- [ご利用にあたって](https://www.wbgt.env.go.jp/tos.php): コンテンツは特記が無い限りPDL1.0準拠。
  「本利用ルールが適用されないコンテンツ」はロゴ等・別ルールを明示したもの・メール配信サービス・
  「暑さ指数（WBGT）電子情報提供サービス」。
- [電子情報提供サービス](https://www.wbgt.env.go.jp/data_service.php): 予測値・実況値・アラートを
  事業者向けにCSVファイル（`yohou_<地点番号>.csv`等）で出すサービス。夏期だけの提供。
- [実況値・予測値ダウンロード](https://www.wbgt.env.go.jp/wbgt_data_download.php)と
  [API仕様書 第1.1版](https://www.wbgt.env.go.jp/man15NH/wbgt_data_api_service_manual.pdf):
  使っている`api/v1/getForecastData`はこちらのWebAPI。地点マスタCSVもAPI仕様書が指す。サイトの
  案内（メニュー）でも電子情報提供サービスとは別の項目。
- [よくある質問 A7-15](https://www.wbgt.env.go.jp/faq2.php): アプリで使うならこのWebAPIを案内している。
- 結論: 使っているAPIは適用外の列挙に入っておらず、PDL1.0の条件（出典、加工した旨）で商用可。
  data-sources.mdの行を確定値へ書き換えた。出典が画面に出ていないことは既に[T1052](T1052.md)が持つ
  （表記の例はサイトの記載例「出典：環境省熱中症予防情報サイト（当該ページのURL）」）。

### 2. 気象庁MSMと気象業務法（公式の文書で決まる所と、照会が要る所が分かれる）

- [予報業務許可Q&A（気象等・路面状況を含む）](https://www.jma.go.jp/jma/kishou/minkan/q_a_m.html)・
  [予報業務を行うためのガイドブック](https://www.jma.go.jp/jma/kishou/minkan/pamphlet.pdf)・
  [根拠規定（気象業務法 抄録、令和8年5月29日施行）](https://www.jma.go.jp/jma/kishou/minkan/hourei.pdf)・
  [予報業務の許可について](https://www.jma.go.jp/jma/kishou/minkan/kyoka.html)。
- 書いてあること・書いていないことはdata-sources.md「気象業務法の予報業務許可」節へ書いた（常に最新の
  正本はそちら）。要点: GPVをそのまま描画・提供するのは許可不要（予報ではなくモデルの結果と明示するよう
  推奨）。空間内挿等の加工は「独自の予報とみなされる可能性」（Q&A）、ガイドブックは「独自の加工を行ったり、
  予報と称して提供する場合は許可が必要」。「予報」と称すれば加工が無くても独自の予報。降水等による
  地面の状態の変化（乾燥・ぬかるみ等）の予報は地象の予報業務許可が要る。
- 今の画面との突き合わせ（記録時点）: 風の矢印・降水の延長はMSMの格子の値を表示用の格子点へ双一次補間して
  描き（`domain/msm.py: MsmWindow.interpolate`）、レイヤーの説明は「気象庁MSMの風向・風速予報」と呼んでいる
  （`frontend/src/features/map/layers/mapLayers.ts`）。ルートは同じ補間（`msm_client.read_series`）で作った格子点の風から、
  通過予定時刻ごとの値を取り出して所要時間・難易度に使う。どれも上のQ&A・ガイドブックの記述が触れる形（補間・「予報」の呼び方）なので、商用化の判断には
  照会の答えが要る。今は非商用のため、照会の答えまで止めるものは無い（止まるのは商用化の判断と、T1173の
  「出発時刻まで予報で延ばす」段）。
- T1173に関わる事実: 「出発時刻まで予報で延ばして路面の状態を示す」は、Q&Aの「降水や降雪、気温の影響による
  地面の状態の変化（乾燥、ぬかるみ…）の予報」に書かれた形そのもので、地象の予報業務許可が要ると書かれている。
  観測だけから今の路面の状態を示すことについては書かれていない（定義は今後生じる現象の予想）。
- 照会: 送り先と文面をダッシュボードに置いた（`T1053-jma-inquiry`、kind 操作）。

### 1. 国土地理院 逆ジオコーダ（公式の文書では決まらない）

- [gsimaps README](https://github.com/gsi-cyberjapan/gsimaps)と、国土地理院の担当（`johofukyu`、MEMBER）が
  「よくあるご質問」ラベルで答えた[issue #29](https://github.com/gsi-cyberjapan/gsimaps/issues/29)
  （「地名検索APIを独自システムに組み入れてよいか」、2015-03-23）: 禁止はせず、主に地理院地図からの利用を想定・
  常に長期に提供するとは限らない・仕様は予告なく変更、と答え、代わりにCSISシンプルジオコーディングを挙げる。
  商用には触れていない。[地理院地図 利用規約](https://maps.gsi.go.jp/help/termsofuse.html)は地理院タイルに
  コンテンツ利用規約を当てるだけで、逆ジオコーダの条件は無い（標高APIには専用の注意書きのページがあるが、
  逆ジオコーダには無い）。
- 代わりの候補: 気象庁が「市町村等（気象警報等）」の区域の境界データを
  [予報区等GISデータ](https://www.data.jma.go.jp/developer/gis.html)で配っている（利用は気象庁ホームページの
  利用規約に従う、と明記）。手元へ入れれば区域の判定に外部の呼び出しが要らなくなる。
- 使い続けるか・置き換えるか・問い合わせるかはユーザーの判断としてダッシュボードに置いた
  （`T1053-gsi-reverse-geocoder`、kind 保留。問い合わせの文面も同じ件に入れた）。
