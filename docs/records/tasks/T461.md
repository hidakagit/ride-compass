# T461. GRADIENT_FILL_LAYER_IDにWIND_PENALTY_FILL_LAYER_IDと同型のクリックガードが無い

状態: 完了（2026-08-31）

- 背景: モジュール設計書再検証（背景Agent経由）で`MapView.tsx`を確認したところ、
  `WIND_PENALTY_FILL_LAYER_ID`（環境グループの風penalty gridFill）はT425で
  `handleClick`冒頭に「ヒットしたら何もしない」早期returnガードが追加されているが、
  同型の`GRADIENT_FILL_LAYER_ID`（環境グループの勾配gridFill）には無い。
- 症状: `GRADIENT_FILL_LAYER_ID`は`STATIC_OVERLAY_LAYERS`経由で`buildInteractiveLayerIds`に
  含まれる（`"elevation"`と`"axis:"`prefixしか除外されないため）。この地物
  （`GradientGridCellProperties`、`{gradientValue}`のみで`osm_way_id`等の道路属性を
  持たない）をクリックすると、一般道路網向けの`buildRoadSurfacePopupHtml`が
  `roadSurfaceProperties.surface_good`等の未定義値のまま呼ばれ、「路面: 不明」という
  実態と無関係なポップアップが表示される。
- Impact: 設計原則違反ではなく機能面の不整合（UXバグ）。勾配の環境グループ面をクリックした
  ユーザーに誤解を与える。
- 対応方針（未検討）: `handleClick`冒頭のガード条件へ`GRADIENT_FILL_LAYER_ID`も追加する
  （`WIND_PENALTY_FILL_LAYER_ID`と同型の1行追加）。
- Confidence: High（`MapView.tsx`の実際のガード条件・`buildInteractiveLayerIds`の除外条件を
  背景Agent経由で直接確認済み）。
- 規模S（既存ガードと同型の1行追加）。

## 実施記録（2026-08-31完了）

- **対応**: `MapView.tsx`の`handleClick`冒頭、`WIND_PENALTY_FILL_LAYER_ID`ガード直後に
  `GRADIENT_FILL_LAYER_ID`向けの同型ガード（`map.getLayer(...)`かつ
  `queryRenderedFeatures`がヒットしたら早期return）を追加した。
- **検証**: `tsc --noEmit`・eslint・vitest（Map/配下31ファイル327件）すべて通過。
  `handleClick`の内部ロジック自体はこのコードベースに単体テストの前例が無く
  （T425の同型のwindガード追加時も同様）、MapLibreのクリックイベント発火を伴う実機
  確認は、本Browserペイン環境のWebGLキャンバス制約で座標を狙ったクリック判定の
  厳密な視覚確認ができないため、既存の動作するWIND_PENALTY_FILL_LAYER_IDガードと
  完全に同型のコード構造であることをもって正しさの根拠とした。
