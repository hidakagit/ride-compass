# T1224. 使うツールは公式を先に確認する規則を CLAUDE.md に入れる

状態: 完了（2026-09-28）

## 背景

T1196 で GitHub Projects を使う設計とボード作成の手順を、公式を読まずに記憶で書き、メニュー名・状態名を誤り、GitHub 標準の機能（閉じた理由等）と同じものを自前の欄で二重に作った（2026-09-28）。CLAUDE.md の既存の規則「外部の仕様について何か言う前に、公式を読む」は「言う前」だけが対象で、設計する前・手順を渡す前・標準機能を使うことが書かれていない。ユーザーの指示「使うツールは公式をまず確認することを徹底して」「メモリじゃなくて、他セッションでも厳守して」。

## 対応

CLAUDE.md「テスト方針」節の同じ項目を書き換えた（新しい項目は足さない。毎回全文が読まれる場所なので、既存の1項目の範囲を広げる）。

- 対象: 「言う前」だけだったのを「言う・設計する・手順を渡す」前へ広げ、外部サービス（GitHub・Cloudflare 等）を名指しした。「記憶や観測から」推測しない。
- 設計: それを使う設計を書く前に、公式で標準の機能を洗い出し、標準で済むものは自前で作らない。自前で持つものは理由を設計に書く。
- 手順: ユーザーへ渡す画面の操作手順は公式のメニュー名をそのまま使う。

文面はユーザーがチャットで承認した案のとおり。T1196 の設計はこの規則に沿って作り直す（T1196 の記録で扱う）。

## 範囲外で見つけたもの

- 1段落の規則の変更にも、起票案の書き込み→書き出し→控え→採番→作業の順の手続きが要り、ユーザーから「作業のための作業になっていないか」と指摘された。行き先: T1196（番号を GitHub の issue の番号に任せる等、手続きを標準へ寄せる作り直しの中で扱う）。
