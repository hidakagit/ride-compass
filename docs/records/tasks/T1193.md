# T1193. 本番の読み取り調査の道具 run_probe.py が素の asyncpg で接続できず、本番 backend の直接の宛先がどこにも書かれていない

状態: 完了（2026-09-27）

## 背景

起票案 proposal-run-probe-ssl-and-backend-origin（2026-09-27承認）。規模S（根拠: 変わるのは run_probe.py とそのテスト・文書1本の見込み）。

■ 起きたこと
T918 の本番確認（読み取りのみ）で、確認係が2つの回り道をした。
1. backend/scripts/run_probe.py がプローブへ渡す接続文字列のクエリに ssl があり、素の asyncpg がそれを受け付けない（CantChangeRuntimeParamError）。プローブ側でクエリを外して ssl= 引数で渡し直す必要があった。CLAUDE.md は本番DBの調査を run_probe.py へ寄せると書いているので、この道具が素の接続で使えないのは欠陥。
2. 本番 backend の直接の宛先（sslip.io のホスト）が docs/architecture に書かれておらず、本番フロントの JS から拾って特定した。フロント経由ではタイル類しか転送されず、dynamic-way-values・axis-catalog は 404 になる。

■ 直すこと（案）
① run_probe.py が、素の asyncpg で使える形（ssl を引数に分けた接続情報）もプローブへ渡す。
② 本番 backend の直接の宛先と、フロント経由で届く API・届かない API の区別を docs/architecture の該当箇所に書く。

## 前提の確かめ（着手時、origin/master 40ae72c9）

- 本番の接続文字列（`backend/.env.oracle.local` の `DATABASE_URL`）は `postgresql+asyncpg://…?ssl=require`。run_probe.py はこれをそのまま `PROBE_DATABASE_URL` として渡していた。
- asyncpg の `connect_utils.py`（手元の venv に入っている版のソース） の DSN の読みは `sslmode` 等の既知のキーだけを接続オプションとして取り、残りのクエリを
  `server_settings`（サーバーの実行時パラメータ）へ回す。`ssl` は既知のキーではないので実行時パラメータとして送られ、
  サーバーが「変更できない」と拒否する——これが CantChangeRuntimeParamError の経路。
- 同じ変換（`+asyncpg` を外し `ssl=` を `sslmode=` へ）は `app/batch/_common.py: asyncpg_dsn` に既にあり、取込バッチ・
  テストの conftest・`drop_orphan_test_databases.py` が本番・テストDBへ素の asyncpg で繋ぐのに使っている。
- 本番の宛先は `docs/records/` の過去の記録（T263・T580・T581 等）にしか無く、docs/architecture には無かった。

## 対応方針

- ①は案の「ssl を引数に分ける」形ではなく、既存の `asyncpg_dsn` を通した DSN（`sslmode=require` をクエリに持つ）を
  `PROBE_ASYNCPG_DSN` として渡す。理由: asyncpg は DSN の `sslmode` を公式に解すので引数へ分ける必要が無く、変換を
  もう1本書くと、同じ事実（SQLAlchemy の形を asyncpg の形へ直す規則）を2か所で保守することになる。
  `PROBE_DATABASE_URL` は残す（`schema_gap.py` が `create_async_engine` へそのまま渡している）。
- ②は docs/architecture/tech-stack.md に節「本番の宛先」を足す。frontend 経由で届く API は一覧にせず、正本の
  `frontend/next.config.ts` の rewrites と管理画面の転送（`/admin/api/…`）を指す（要素を数え上げない）。
- 途中で T1192（74d4c11c）が master に入り、`.env.oracle.local` の読み方が `backend/scripts/_prod_env.py` へ移り、
  本番backendの宛先を同じファイルの鍵 `BACKEND_ORIGIN` から読む形（`axis_apply.py`）ができた。その上へ rebase し、
  宛先の置き場をこの鍵に揃えた: 文書の節は宛先の値（事実。リポジトリの中ではここだけ）と、道具はコードに宛先を
  書かず `BACKEND_ORIGIN` から読むこと、の両方を持つ。
