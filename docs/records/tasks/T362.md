# T362. 本番DBで6公開軸がis_published=falseになっていた不整合の発見・修正 規模S（完了）

状態: 完了


- 背景: T353/T359/T360の本番反映作業中（2026-08-27）に、本番`GET /api/axis-catalog`
  （一般ユーザー向け軸カタログ）を実際に叩いて検証したところ、本来公開されているべき
  8軸のうち`wind`・`bicycle_infra_quality`の2軸しか返らず、`gradient`/`surface_q`/
  `stop_density`/`car_stress`/`accident`/`night`の6軸が`is_published=false`（下書き
  扱い）になっていたことが発覚した。原因発生時期は未特定（今回のデプロイで新規に
  発生したものではなく、ユーザー判断により「元々あった」ものとして扱い、原因の
  遡及調査は行わず是正のみ実施）。実害は大きく、一般ユーザーが実際に選択・重み
  調整できる評価軸が2つしか無い状態が本番で継続していたことになる。
- 対応内容: 6軸それぞれに対し、SSH経由でOracle VM内から`axis_admin`のPUT APIを叩き、
  `is_published`のみ`true`へ修正（他のフィールドは変更なし）。修正後、
  `GET /api/axis-catalog`が正しく8軸を返すことを確認済み。
- 教訓（ユーザー指摘、2026-08-27）: 本番への変更を計画する際、「開発DBと本番DBは
  同じ状態である」という前提を検証せずに進めたことが、この発見の遅れと作業全体の
  長時間化の主因だった。今後、本番への反映を伴う作業では、着手前に必ず本番の
  実際の状態を読み取ってから計画を立てる（メモリにも教訓として記録）。
- 優先度: P0（実害あり、発見時点で即修正）。
