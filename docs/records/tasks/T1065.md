# T1065. 状態の表から他に正本のある写しを外し、読むときに正本から導く

状態: 未完了（2026-09-23起票）

## 背景

並行実行の状態の表（<gitの共通ディレクトリ>/orchestration/board.json）が、他に正本のある事実を写して持っている。ユーザー指摘「管理系の仕組みは、二重持ちした瞬間に破綻する」。実例: 司令塔が判断D-016・D-017の回答をタスクの記録（T1046.md）だけに書き、表の判断は未回答のまま、表の「前提の判断待ち」の写しにも決着済みのT1046が残り、のちの移行がその古い値を正式な形へ運んだ（2026-09-23）。規約 docs/conventions/orchestration.md「状態の表」節に原則（表に持つのは表にしか無い事実だけ）を置いた。

2026-09-23 15:40 時点の表の全キーを列挙して分類した（python で board.json の最上位・agents・decisions・queue・coordinator_queue・manual のキーを出現数つきで出した）:
A. 表にしか無い（残す）: run・limits.concurrent・check_interval_min・last_check／agents の id・name・where・current_task・task_first_started・started・expected_min・監査の記録（reported・reported_sha・audit_started・audit_done・audit_result・audit_log）／queue の task・after・agent・priority・added／coordinator_queue。
B. 他に正本がある写し（外して、読むときに導く）: queue の what（題名・規模・判断番号の文。正本は台帳の行とTxxx.md）／agents の scale_budget_min（正本は台帳の規模札。手入力で当日3回誤った）／agents の queue（1件ずつの依頼にしたので current_task と二重）／manual.T1001 の prereqs・waiting_decision・note（前提の関係の正本は T1001.md、判断待ちは判断の回答から導く）／decisions の question・options・answer（正本は各タスクの記録の保留節と「ユーザー決定」）／audited_unpushed の「未push」（masterに入ったかは git。cherry-pick で sha が変わるので patch-id で比べる）／last_master_push・last_master_push_at（origin/master の履歴）／agents の state のうち稼働か否か（正本は実行環境と作業ツリーの動き。今は status が突き合わせて印を出すだけ）。
C. 規則・記録の文（表から出す）: resume_policy・decision_policy・check_rule・limits.note（規約の写し。すでに規約と食い違う）／incidents・hookspath_reverts・audit_findings・notes（回の記録 T1049.md の持ち物）／pending_cleanup（台帳の T1042）／agents の note。

対応方針:
1. B の各項目を正本から導く読み出しを scripts/orchestration/ に作り、gate・check・status・dispatch list・prereqs・decision list がそれを使う形にする。題名・規模は docs/improvement-plan.md の行、前提は手動タスクの Txxx.md の「前提」節（無ければ作る。書き方を決めて規約へ）、判断は記録の保留節、push 済みかは origin/master と patch-id、稼働かは作業ツリーの最新の変更時刻と実行環境の報告。
2. 外す前に、今の表の値と正本を突き合わせ、食い違いの件数と中身を記録する（それが今までに起きていた破綻の件数）。
3. C を表から消す。記録として残す価値のあるものは T1049.md へ移す（同じ内容が既にあれば移さない）。
4. 表の書き込みは orchestrate.py のコマンド経由だけにし、B・C のキーを書こうとしたら拒否する（写しを再び作らせない）。
5. 表の移行は1回で、変換前の写しを残す。移行後に gate・check・status・prereqs T1001・decision list が同じ答え（または正本から見て正しい答え）を返すことを確かめる。

完了条件: 表のキーが A だけになっている（キーの列挙で確かめる）。B の各項目を、正本を1か所だけ変えると表示が変わることを壊した入力で1件ずつ確かめる（例: 台帳の規模札を変えると予算が変わる、Txxx.md の保留にユーザー決定を書くと判断待ちから消える、master に入れると未push から消える）。

## 追加（2026-09-23）: task_log も写しとして外す

T1056 で入った状態の表の`task_log`（報告の受領時に実時間・規模札の予算・差を残す）は、
3つとも導ける値の写しで、しかも表はリポジトリに入らず履歴が残らない。ユーザーと合意した形:
実行中は表に「今のタスクと振り出した時刻」だけを持ち、完了時は担当が完了のコミットで
`Txxx.md`へ所要を1行書き（規約「完了とpush」）、監査を通ったら表からその行を消す——所有が
表から記録へ移るだけで、同じ事実を同時に二か所に持たない。本タスクで`task_log`と
`scale_budget_min`を表から外し、予算を記録の所要の行から読むときに計算する側（別タスク）へ渡す。
