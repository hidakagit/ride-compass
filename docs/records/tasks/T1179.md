# T1179. 並行作業の道具が読むプロセス一覧とCPU使用率を、OSのAPIの直接呼び出しから psutil へ置き換えるか、標準ライブラリだけで書く方針を文書にする

状態: 未完了（2026-09-27起票）

## 背景

起票案 proposal-std-procs-psutil（2026-09-27承認。標準の道具の棚卸しから）。規模S（根拠: 変わると見込むファイルは procs.py・core.py・lockrun.py・slots.py の4本）

■ 背景（画面に出ない、並行作業の道具の話）
scripts/orchestration/procs.py（121行）は Windows の API（プロセスのスナップショット・コマンドラインの読み取り）を ctypes で直接呼び、Linux では /proc を自前で解析する。core.py の cpu_percent（31行）も同様。書かれている理由は「飽和した機械へプロセスを足さないため、外部コマンドを起こさない」だが、psutil はプロセス内で動くのでこの理由は当たらない。「scripts/ は標準ライブラリだけで書く」という方針は記録（T560。review_checks について）にしか無く、生きた文書には無い。

■ 決めてほしいこと
①psutil へ置き換える（約−130行。代わりに、道具を動かすシステムの Python と、クラウドのセッションの両方へ psutil を入れる手順が要る）／②標準ライブラリだけで書く方針を残す（方針と理由を docs/conventions/orchestration.md へ書き、procs.py はそのまま）。

■ なぜ既存のタスクに入らないか
T1148 は procs.py がどの文書にも名前が出ないことを1件含むが、範囲は書式と依存の向きで、実装の置き換えは含まない。ロックをOSのファイルロックへ置き換える起票案が先に入ると、procs.py の使い道のうち「ロックの破棄の記録」が無くなる。
