# T830. タスク番号の衝突を検知器にする

規模S。
状態: 完了（2026-09-13）

## 背景

`CLAUDE.md`「作業ツリーの安全」節は番号衝突を「複数回実績あり」と書き、衝突しうる時間窓を
縮める手順（`git fetch`→スタブだけ先にpush→衝突が分かったら自分の側を振り直す）を持つ。
しかし**衝突したことに機械的に気づく経路が無く**、気づけるかは人が台帳を目で見るかどうかに
依っていた。

T810で実際に起きた。統合レビュー第8回のP0/P1起票（`8f51d9d5`、18:32）がT810を使い、その37分後
に別のセッションが同じT810で起票した（`32eb902c`、19:09）。後者が`docs/records/tasks/T810.md`を自分の
本文で上書きしたため、**先に載っていたエントリは本文を失ったまま台帳に並んだ**。

既存の`plan_vs_tasks`はこれを通す。見るのがリンク先ファイルの存在と「状態:」行だけで、
どちらの条件も衝突後の状態で満たされるためである。番号は台帳のラベル・そのリンク先・タスク
ファイルの見出しの3箇所に散っており、揃っていることを誰も確かめていなかった。

## 対応

`scripts/review_checks.py`へ`task_numbering`検知器を新設した（`check_task_numbering`）。
台帳の中で同じ番号が二度使われていないか、ラベルとリンク先の番号が一致しているか、タスク
ファイルの見出しの番号がファイル名と一致しているかを突き合わせる。最後のものは、振り直しの
置換漏れと、別タスクの本文でファイルを上書きした状態の両方を拾う。

`plan_vs_tasks`へ相乗りさせず別キーにしたのは、`mutate`（ガードの実効性監査）が検知器キー
ごとに違反の作り方を1つ持つ設計のため。相乗りさせると新しい照合が自動監査の射程から外れ、
鳴らなくなっても0件のまま静かに素通りする。`mutate`のcaseには「既にある未完了エントリと同じ
番号の行をもう1本足す」を登録した。

## 検証

- **実際に衝突していた状態で鳴る**: 振り直し前のコミット`a64f9d7e`の台帳へかけて
  `docs/improvement-plan.md:1257: T810 は1219行目でも使われている`を検知。振り直し後の
  `be982aeb`では0件。
- **健全な入力では鳴らない**: 番号の揃った最小の台帳で0件。ラベル/リンク先のずれ・見出しの
  不一致もそれぞれ単体で作って鳴ることを確認した。
- **緩和・除外は入れていない**: 母集団（タスクファイル617件・台帳エントリ614件）に対する
  既存違反が0件だったため、許可リストを持たずに導入できた。
