# T778. 下部シートの既定の高さを中身へ合わせる 規模S

状態: 完了（2026-09-12起票・完了、[T769](T769.md)の実測から）

## 背景

`BottomSheet`は`DEFAULT_SHEET_HEIGHT_VH = 50`で高さを固定しており（ドラッグで20〜80vhへ
変えられ、値は保存される）、**中身の量に依らない**。390×812での実測では「ルート結果」の
中身は302pxなのにシートは406pxで、104px＝画面の13%が空いたまま地図を覆っている。

[T773](T773.md)〜[T776](T776.md)で中身を444px→194pxまで削ったが、**画面上は何も変わって
いない**（空白が増えただけ）。中身を減らす作業は、この既定値を中身へ合わせない限り
利用者に届かない。

## 保留することで何が起きうる

- 中身を減らすタスク（[T760](T760.md)等）の効果が、実機では一切見えないまま積み上がる。

## 対応

**開いた時点の中身に合わせ、開いている間は合わせ直さない**を選んだ。中身へ常時追従させると
候補の切り替え・区間クリックのたびに地図の見える範囲が動き、地図を見ながらの操作が落ち着か
ない。静的に下げるだけでは、シートごとに中身の量が違う（ルート結果とルート編集で2倍以上
違う）ぶんを拾えない。合わせた結果はドラッグで上書きでき、その値は次に開くまで有効。

**中身なりの高さの測り方**が実装上の肝だった。次の2つはどちらも使えない:

- `scrollHeight`は中身が箱より低いと**箱の高さをそのまま返す**（縮める判断に使えない。
  最初の実装がこれで、実機で高さが1pxも変わらなかった）
- 子要素の合算も、中身側のflexが引き伸ばされていると箱の高さに一致する（2番目の実装。
  実機では逆に406→414pxへ増えた）

最終的に、高さ指定を一時的に`auto`へ外して`getBoundingClientRect()`で実測し、すぐ戻す形に
した（`naturalHeightOf`）。読み書きは同じレイアウト処理の中で完結するため、途中の高さが
描画されることはない。

## 検証結果

390×812・候補2件での実測（Playwright）:

| シート | 高さ | 地図が見える高さ |
|---|---|---|
| ルート結果（従来） | 406px | 350px |
| ルート結果（本タスク後） | **309px**（中身302px） | **447px** |
| ルート編集（従来） | 406px | 334px |
| ルート編集（本タスク後） | **162px**（下限20vh、中身100px） | **594px** |

[T773](T773.md)〜[T776](T776.md)で削った中身が、ここで初めて画面へ効いた。

テストの効きは意図的な変異2件で確認した: 高さ指定を`auto`へ外す行を消す→3件failure、
上下限のクランプを外す→2件failure。いずれも元へ戻して21件green。

## 残り

ドラッグで変えた高さはlocalStorageへ保存されるが、次に開いたときは中身へ合わせ直すため
**開き直すと元に戻る**。ドラッグは「いま少し広げて見る」ための操作になった。保存自体は
実寸が取れない実行のフォールバックとして残している。
