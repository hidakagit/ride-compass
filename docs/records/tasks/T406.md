# T406. パネル構成再編（道路/評価軸/環境/スポットの4チップ・3排他ドメイン）

状態: 完了（2026-08-30）

- 背景: 詳細はT400.md「1. パネルの最上位グルーピングを『道路』『評価軸』『環境』『スポット』
  の4チップ・3排他ドメインへ再編」参照。旧「観測/推定/動的」グルーピングを廃止し、対象ベースの
  4チップへ再編する。「道路」と「評価軸」は幾何が線のため選択の排他ドメインを共有。UIは新規
  発明せず既存のチップ＋ⓘ設定パネル（T169・T216）を流用し、選択方式をチェックボックスから
  ラジオボタンへ変更する。T405（風の評価軸表示）と合わせて検討すると手戻りが少ない可能性あり。

## 実装準備調査（2026-08-30、Explore調査済み。着手前に必ず現状のdiffを再確認すること）

**重要**: T405（別セッションで並行実装中）がここに挙げたファイル（`mapLayers.ts`等）に
触れている可能性が高い。着手前に必ず最新の状態を`git fetch`・実ファイルの読み直しで
確認すること（この節は調査時点のスナップショット）。

### 現行カタログは4分類へ機械的に再分類可能

`frontend/src/components/Map/mapLayers.ts: buildMapLayers`（166-418行目）の既存フィールド
（`category`・`dataNature`）だけで、追加のデータモデル変更なしに4グループへ分類できることを
確認した:

- **道路**（線）: `category==="roadCondition"`（roadType/roadSurface/designation/tunnel/oneway）
- **評価軸**（線）: `dataNature==="composite"`（`axis:${axisId}`、`RAMP_AXES`/`useAxisCatalog`から
  動的生成済み）
- **環境**（面）: `category==="terrain"||"weather"`（elevation/precipitationNowcast/windVector/
  thunderNowcast/tornadoNowcast）
- **スポット**（点）: `category==="trafficSafety"||"amenity"`のうち`dataNature`が`composite`でない
  もの（stopPoi/supplyPoi/accidents。`axis:accident`等のramp軸とは別物なので要区別）
- `route`（生成されたルート本体）は`category`未指定で単独チップのまま、排他ルール対象外
  （T400方針どおり）

### 変更が必要な箇所（5系統、具体的な行番号つき）

1. **`frontend/src/app/page.tsx: handleLayerToggle`（645-650行目）** — 中心的な変更点。現状は
   `setLayerVisibility((prev) => ({ ...prev, [id]: on }))`のみで排他制御が一切無い。ONにした際、
   同一排他ドメイン（道路↔評価軸の共有ドメイン／環境単独／スポット単独）に属する他の全レイヤーIDを
   OFFにするロジックを追加する。ドメイン判定には新しい「排他ドメインID」導出関数が要る
   （`category`/`dataNature`だけでは道路と評価軸が別カテゴリ値のため同一ドメインと判定できない）。
2. **`frontend/src/components/Map/MapOverlayControls.tsx: buildChipGroups`（103-117行目）** —
   「観測/推定/動的」3分類ロジックを4分類（道路/評価軸/環境/スポット）へ置き換え。
3. **`MapOverlayControls.tsx`のチップ描画3ブランチ**（`group:composite`1149-1254行目、
   `group:raw`1262-1323行目、`group:dynamic`1328-1381行目）— 4分岐への書き換え、または汎用化。
   `DATA_NATURE_ICONS`（139-143行目）・`MAP_LAYER_DATA_NATURE_LABELS`等（mapLayers.ts 96-117行目）
   も新4グループ用のラベル・アイコン辞書へ置き換え。
4. **`renderVisibilitySettings`（910-1013行目）** — 引数`scope: "raw"|"composite"|"dynamic"`の型を
   新4スコープへ変更。**要確認事項（下記参照）**。
5. **localStorageキーの名前空間**: `MAP_OVERLAY_HIDDEN_IDS_STORAGE_KEY`（178行目）のキー形式
   `${scope}:${id}`のprefix語彙、`GROUP_VISIBILITY_KEYS`（170行目、`group:composite`等3値）を
   新4キーへ。旧prefixのゴミが残ることは実害なしとして許容する既存方針（646行目コメント）を踏襲。

### 要確認事項（実装着手時に最初に解決すること）

調査の結果、**「チェックボックス→ラジオボタン化」の対象が2つのUI層のどちらを指すか、
T400.mdの文言だけでは一意に決まらない**ことが判明した:

- (A) グループ内メンバーのON/OFF本体（`ChipButton`の`onTap`→`onToggle(member.id, !member.on)`、
  実際に地図にレイヤーが出るかどうかを決める主選択）
- (B) ⓘボタンで開く「表示する項目を選ぶ」設定パネル内の表示/非表示チェックボックス
  （`renderVisibilitySettings`、943-1013行目。これは「そのチップ自体を選択肢一覧に出すか
  隠すか」というメタ設定で、地図の表示ON/OFFとは別の状態軸）

T400.md本文の意図（「各グループ内は完全な排他選択、1つだけ選べる」）およびT400.md冒頭の
ユーザーとの合意経緯から判断すると、**排他化すべきは(A)（実際にどのレイヤーが地図に出るか）
である可能性が高い**——(B)はあくまで「選択肢一覧に何を並べるか」というフィルタで、
排他とは別次元の設定として現状のまま残せる。ただし断定はできないため、実装着手時に
この解釈で進めてよいかユーザーへ確認すること。

**【2026-08-30、実装セッションで決着】** 実装着手指示の時点でユーザーから(A)の解釈で
進めてよいと確認済み（ⓘボタンの「表示する項目を選ぶ」設定パネルは今回変更しない）。
実装は下記「実装結果（2026-08-30完了）」参照。

## 実装結果（2026-08-30完了）

調査時点（節冒頭の実装準備調査）から`MapOverlayControls.tsx`は
`frontend/src/components/MapOverlayControls/MapOverlayControls.tsx`（別セッションにより
専用ディレクトリへ移設済み）へ変わっていた等、複数の並行セッションの影響で行番号・
ファイル構成は調査時点からずれていたが、5系統の変更箇所自体の見立ては妥当だった。
排他化の対象は上記のとおり(A)（チップ本体のON/OFF）で確定し、(B)の「表示する項目を選ぶ」
設定パネルは変更していない。

- **`frontend/src/components/Map/mapLayers.ts`**: 新しい「排他ドメインID」導出のため、
  `MapOverlayGroup`（`"road"|"axis"|"environment"|"spot"`）・`MAP_OVERLAY_GROUP_LABELS`・
  `MAP_OVERLAY_GROUP_CHIP_LABELS`・`MAP_OVERLAY_GROUP_ORDER`・`MapOverlayExclusiveDomain`
  （`"line"|"area"|"point"`）・`mapOverlayGroupFor()`・`mapOverlayExclusiveDomainFor()`を
  新設した。判定規則は`category`/`dataNature`の機械的な変換（道路=`roadCondition`、
  評価軸=`dataNature==="composite"`、環境=`terrain`/`weather`、スポット=`trafficSafety`/
  `amenity`のうちcomposite以外）に、`windAxis`（改善計画T405の暫定チップ）だけをidで
  特別扱いする例外を1つ加えた形（`category`/`dataNature`の値自体は変えていない。windAxisは
  category="weather"のままだが、評価軸グループへ判定する）。旧`MapLayerDataNature`
  （raw/composite/dynamic）・`MAP_LAYER_DATA_NATURE_LABELS`等は削除せず残した——
  `MapLayersPanel.tsx`（サイドバー「地図の見え方」パネル）が独立した設計判断として
  「観測/推定」の2見出しを引き続き使うため（下記「積み残し」参照）。
- **`frontend/src/app/page.tsx: handleLayerToggle`**: ONにする操作のときだけ、
  `mapOverlayExclusiveDomainFor`で同じ排他ドメインと判定された他の全レイヤーIDを
  まとめてOFFにするロジックを追加した。`mapLayers`（レイヤーカタログのuseMemo）を
  `handleLayerToggle`より前へ定義位置を前倒しする必要があった（排他ドメイン判定に
  カタログ全体の参照が要るため）。OFFにする操作自体・ルート等どの排他ドメインにも
  属さないレイヤーは従来どおり無条件で許可する。
- **`MapOverlayControls.tsx`**: `buildChipGroups`を`mapOverlayGroupFor`ベースの4分類へ
  書き換え、チップ描画の3ブランチ（`group:composite`/`group:raw`/`group:dynamic`）は
  「評価軸（旧composite、横並び・SECONDARY_AXES駆動）」＋「道路/環境/スポット（旧raw/
  dynamicと同型の縦並び・`renderObservedMemberRows`共通化）」の2パターンへ整理した
  （旧実装は観測/動的の2つがほぼ同じ内容の別ブロックだったため、4グループ化にあたり
  1つの分岐へ統合し重複を解消）。`windAxis`はSECONDARY_AXES（backendの`wind`軸自身は
  `category="動的"`のため`secondaryAxesFromCatalogAxes`の除外対象、`secondaryAxes.ts`
  参照）に現れない特殊メンバーのため、`renderAxisTile`とは別に`renderWindAxisTile`を
  新設し、評価軸グループの軸タイル列の末尾へ追加。`DATA_NATURE_ICONS`は
  `MAP_OVERLAY_GROUP_ICONS`（`road`=`RoadIcon`流用、`axis`=`EstimatedIndexIcon`流用
  [意味が一致するため]、`environment`/`spot`は新規アイコン）へ置き換えた。
- **`renderVisibilitySettings`**: `scope`引数の型を`"raw"|"composite"|"dynamic"`から
  `MapOverlayGroup`へ変更。
- **localStorageキー**: `GROUP_VISIBILITY_KEYS`を`group:road`/`group:axis`/
  `group:environment`/`group:spot`の4値へ、`hiddenIds`のprefix語彙（`${scope}:${id}`の
  scope）も同じ4値へ変更した。旧prefix（`raw:`/`composite:`/`dynamic:`）のゴミが
  localStorageに残ることは実害なしとして許容する既存方針（旧646行目コメント）を踏襲し、
  移行処理は書いていない。
- **CSS**: `globals.css`の`--color-group-raw/composite/dynamic`系トークンを
  `--color-group-road/axis/environment/spot`の4トークンへ改名（道路=旧raw流用、
  評価軸=旧composite流用、環境=旧dynamic流用、スポット=新規追加の桃色系）。
  `MapOverlayControls.module.css`のクラス名（`.iconChipGroupRaw`等）も同様に4クラスへ
  改名した。
- **新規アイコン**（`frontend/src/components/Map/icons.tsx`）: `EnvironmentDataIcon`
  （雲、terrain+weatherを併せて表す）・`SpotDataIcon`（地図ピン）を追加。

### 積み残し（意図的にスコープ外とした事項）

- **`frontend/src/components/MapLayersPanel/MapLayersPanel.tsx`（サイドバー「地図の見え方」
  パネル）は変更していない**。T406.mdの実装準備調査（5系統の変更箇所）に元々含まれておらず、
  独立したUI surfaceとして「観測/推定」の2見出し・独自の表示順（パネル内は「観測→推定」、
  チップ側は「道路→評価軸→環境→スポット」）を意図的に保つ既存設計判断（`mapLayers.ts`の
  `MAP_LAYER_DATA_NATURE_LABELS`コメント参照）を尊重した。結果として、チップ側の語彙
  （道路/評価軸/環境/スポット）とサイドバー側の語彙（観測/推定）が異なったままになり、
  UI語彙のカタログ集約（設計原則8）の観点では不整合が残る。実害は「サイドバーとチップで
  見出し語が違う」という表示上の違和感のみで機能的な破綻はないため、影響範囲を明記した
  別タスクとして起票する候補として残す（本実装セッションでは`spawn_task`で提案済み）。
