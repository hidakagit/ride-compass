# T500: 走行方位コンパスのタッチ判定をリング全周へ拡大

状態: 完了（2026-08-31）
## 背景

ユーザー指摘「走行方位を設定、のところのコンパス、スマホだと円形の軸のタッチ判定が
細かくて使いにくい」。`WindBearingSlider`（`@fseehawer/react-circular-slider`ベース）は
既定で、ドラッグの開始点として拾えるのが18px四方のノブ自身だけだった。ノブは値が
変わるたびにリング上の別の位置へ移動するため、モバイルでは狙って掴み直すのが難しい。

## 対応方針

ライブラリが提供する`trackDraggable`プロパティ（既定false）を有効化する。ライブラリの
実装（`node_modules/@fseehawer/react-circular-slider/dist/index.mjs`）を確認したところ、
`trackDraggable={true}`にすると、リング（トラック、`<circle>`要素）自体にも
`onMouseDown`/`onTouchStart`ハンドラが付き、中心からの距離が
`bounds.width / (isDragging ? 4 : 2) - trackSize`という閾値以上であればドラッグ開始と
判定される（=リング全周のどこを触ってもよい）。既存のノブ限定ドラッグ
（`knobDraggable`、既定true）はそのまま維持されるため、両方の入り口が併存する形になる。

## 実装

- `frontend/src/components/WindBearingSlider/WindBearingSlider.tsx`: `CircularSlider`に
  `trackDraggable`を追加。

## 検証結果

- `npx vitest run src/components/WindBearingSlider/`: 既存テスト全て成功（`trackDraggable`
  はライブラリの内部インタラクション追加のみで、`cardinalLabel`等の既存の純粋関数の
  入出力には影響しない）。
- `npx tsc --noEmit`・`npx eslint`: エラーなし。
- ライブラリのソースコード確認により、`trackDraggable`がリング全周からのドラッグ開始を
  正しく受け付けるよう設計されていることを確認した。Browserペインでの実機確認では、
  リング上（ノブの現在位置から離れた場所）へのtouchstartディスパッチで
  `isDragging`状態（`userSelect: none`の副作用で確認）が正しく開始されることを確認した
  ——これはドラッグ開始判定（今回の修正が対象とする箇所）が機能している直接証拠である。
  一方、ドラッグ継続中の値更新（pointermove相当）については、本セッションの自動化
  ツール（Browserペインでの合成TouchEvent/MouseEvent送出）では、ライブラリ内部の
  window単位イベントリスナーとオフセット計算の再現が難しく、continuous-drag部分までは
  確認しきれなかった。実際のタッチデバイスでの動作確認が可能であれば、改めて確認する
  ことが望ましい。

## 残課題

- ドラッグ継続中の値更新について、実タッチデバイスでの最終確認が未実施のまま残っている
  （上記「検証結果」参照）。再度使いにくさが報告される場合は、まずこの継続ドラッグ部分を
  実機で確認すること。
