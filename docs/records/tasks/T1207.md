## 背景

周期レビュー第14回（2026-09-27）の起票案（ダッシュボード proposal-layer-contract-falls、承認済み）。

規模M（根拠: 構造テスト3〜4本と、違反の移設。段に切る）

■ 背景
性質: 境界が落ちる形でない／層の越境（再発: 第13回 T1131・T1132）。T1131 は契約を書いたが、機械で落ちるのは import の向きだけ。今回、各層で同じ形が出た。
- batch の SQL が業務判断を持つ: 構造物の判定（derive_raster_materials.py:42-43 は tunnel/bridge の yes 以外も真。材料の bridge・has_tunnel は yes だけが真→ bridge=viaduct の道が地図では「橋」でないのに勾配だけ構造物として抜かれる。件数未計測）、停止要因の端の分け持ち（derive_counts.py:92）、交差点×0.5（:122）、上下線分離の3条件（derive_way_materials.py:215-282）、infra の oneway の定義（road_graph_repository.py:277）。
- domain が外部の書式を解く: msm.py:19 parse_bbox、accident.py:24-59 度分秒、terrain_rgb.py:29 PNG（読み手はどれも1層だけ）。
- api が複数の部品を束ねる判断を持つ: dependencies.py の directional_materials・get_preview_builder、jma_tile.py の要求時補間、region.py:149-163、axis_catalog.py:235 が印 tile_property_needs_runtime_scale を読まず材料名で係数を出す、axis_admin.py:285 が domain の式を1項写す。
- services が Redis のキー・ハッシュの配置と上流 URL の時刻書式を持つ（jma_amedas_service・wbgt_service）。
- domain の概念の判断が services に残る（WBGT の発表回の選び方・警報の区域フォールバック・RAIN_HISTORY_MAX_AGE・今日のコマ割り・逆回りの標高の代数・「最寄りの観測点」3実装・難易度の同点の粒度4か所）。

■ やること
段1: directory-layout.md に domain「外部の書式を解かない」・batch/infra「判断のリテラルを持たない（domain の *_sql() を読む）」・「caching.md の呼び出し元は infrastructure」を書く。
段2: 構造テスト（backend/tests/structure、test_vacuous_loops.py と同じくソースを読む形）: batch/infra の SQL 定数に domain 由来でない判断のリテラルがあれば落とす、domain が PIL・io を import したら落とす、dependencies.py の公開関数は Depends か main から参照されるものに限る。
段3: 違反を移す（構造物の述語を domain に1つ置き、標高と材料の両方が読む。viaduct 等を材料でも真にするかはユーザーへの問い）。

■ 判断（観点どうしの矛盾の解消）
domain 担当は domain の4関数（tag_kind_sql・direction_sql・elevation_values_sql・class_percentages_sql）を「SQL文の全文」として移す提案をしたが、司令塔が確かめると FROM/JOIN の先は CTE の別名と渡された関係だけで、DB の表を名指さない。T1131 段階Eの判断（規則の表を当てる純関数）どおり domain に残す。これを落とす検査は許可リストが要るので作らない。
