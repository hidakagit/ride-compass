# T370. 推定グループを横スクロールへ変更・chipRow/estimatedFlatRowのスクロールバーを非表示化 規模S（2026-08-27完了）

状態: 完了


- 背景: T369完了後、ユーザーから2件の指摘（2026-08-27）。
  1. 「推定グループは横にスクロールするようにできる？　観測、動的グループは縦に
     スクロース」——T367で軸が7個に増えたことで`.estimatedFlatRow`（`flex-wrap: wrap`）
     が2行に折り返し、地図の縦幅を圧迫して観測/動的グループを押し下げていた
     （画面キャプチャで確認）。
  2. 「背景が変になる、スクロールバーが出る等は避けたい。これは縦スクロールも同じ」。
- 対応:
  1. `.estimatedFlatRow`を`flex-wrap: wrap`から`flex-wrap: nowrap`＋
     `overflow-x: auto`（横1行固定・収まらない分は横スクロール）へ変更。以前は
     「横スクロールは指では扱いにくい」という判断で意図的に折り返しにしていたが
     （コード内コメント参照）、軸が増えるたびに縦幅を圧迫する副作用がユーザー体験を
     上回ると判断し撤回。`min-width: 0`を付け、flexアイテムの既定の縮小抑制を
     打ち消して実際にスクロール可能にした。観測/動的グループが依拠する`.chipRow`の
     縦スクロール（`overflow-y: auto`）と対称な設計。
  2. `.chipRow`（縦、既存）・`.estimatedFlatRow`（横、上記で新設）の両方へ
     `scrollbar-width: none`（Firefox）・`-ms-overflow-style: none`（旧Edge/IE）・
     `::-webkit-scrollbar { display: none; }`（Chrome/Safari/新Edge）を追加し、
     スクロール自体は残したままネイティブのスクロールバー描画だけを消した
     （マウスホイール・タッチスワイプ・`scrollLeft`/`scrollTop`直接操作のいずれでも
     引き続きスクロールできることを実機で確認）。
- 検証（実機、モバイル幅375px）: `.estimatedFlatRow`が高さ約70px（1行ぶん）に収まり
  `scrollWidth(466px) > clientWidth(303px)`で横スクロール可能なことを確認。観測見出し
  の上端が推定行の下端から約8px（gapのみ）に近接し、折り返しによる押し下げが解消した
  ことを確認。`scrollbar-width: none`が両要素へ適用されていることも確認。
  frontend全体697件成功、tsc/eslintクリーン。
