# T989. docker composeで立てた環境は、手順どおりにしても使える状態にならない 規模S〜M

状態: 未完了

未着手（2026-09-21起票、[T982](T982.md)でテストDBの拡張不足を追ったときに同じ穴が
compose側にもあると分かった）。

## 背景

[docs/architecture/setup.md](../../architecture/setup.md)は開発環境の立ち上げとして
`cp .env.example .env` → `docker compose up --build` を案内している。だが2026-09-21に
静的に調べた範囲では、この手順だけでは**使える状態にならない**。

- **スキーマを作る導線がcomposeに無い**。`create_tables()`を呼ぶのは
  `scripts/bootstrap_database.py`とテストのconftestだけで、`main.py`のlifespanは呼ばない。
  `docker compose up`は空のPostGISに対してbackendを起動する。
- **`postgis_raster`が入らない**。`postgis/postgis:16-3.4`が初期化で入れるのはpostgis系で、
  rasterは別拡張。`bootstrap_database.py`を流すと`create_tables()`が拡張不足で止まる
  （composeのDBユーザーは`POSTGRES_USER`＝スーパーユーザーなので、手でCREATE EXTENSIONすれば
  通る見込み）。
- **バージョンが本番とずれている**。composeはPG16・PostGIS 3.4、本番はPG18・PostGIS 3.6.4。
  `source_features.rast`（raster型、T970で追加）を3.4で扱えるかは未検証。

**この開発機にdockerが入っていないため、どこで止まるかを実行して確かめていない。** 上は
ファイルとイメージの仕様から導いた見込みであり、実測ではない。

## やること

1. dockerのある環境で`cp .env.example .env` → `docker compose up --build`を実行し、
   **どこで止まるかを実測する**（上の見込みと違う可能性を残す）。
2. 実測に基づき、次のどちらかを選ぶ:
   - **維持する**: 足りない導線（スキーマ作成・拡張）をcomposeかsetup.mdへ足し、イメージの
     バージョンを本番へ寄せるかを決める。`CREATE EXTENSION`をcomposeへ書くと
     `road_graph_repository.py: REQUIRED_EXTENSIONS`の写経になるため、書き写さずに済む形
     （初期化でbootstrapを通す等）を選ぶ。
   - **畳む**: 実際の開発はネイティブ（backend/.venv＋ローカルPostgreSQL＋next dev）で
     行っており、composeを使っている人がいないなら消す。案内されているのに動かない手順は、
     読んだ人の時間を確実に奪う。
3. 選んだ側に合わせて`docs/architecture/setup.md`・`docs/architecture/tech-stack.md`を直す。

## 完了条件

- 実測の結果（どのコマンドがどこで止まったか）をこのエントリへ書く。
- 維持するなら、まっさらな環境で手順どおりに実行して`/health`が通り、地図が出ることを
  確認する。畳むなら、composeとその案内がリポジトリから消えている。
