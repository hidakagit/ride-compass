## 背景

[docs/architecture/setup.md](../../architecture/setup.md)は開発環境の立ち上げとして
`cp .env.example .env` → `docker compose up --build` を案内している。だが2026-09-21に
静的に調べた範囲では、この手順だけでは**使える状態にならない**。

- **スキーマを作る導線がcomposeに無い**。`create_tables()`を呼ぶのは
  `scripts/bootstrap_database.py`とテストのconftestだけで、`main.py`のlifespanは呼ばない。
  `docker compose up`は空のPostGISに対してbackendを起動する。
- **`postgis_raster`が入らない**。`postgis/postgis:16-3.4`が初期化で入れるのはpostgis系で、
  rasterは別拡張。`bootstrap_database.py`を流すと`create_tables()`が拡張不足で止まる
  （composeのDBユーザーは`POSTGRES_USER`＝スーパーユーザーなので、手でCREATE EXTENSIONすれば
  通る見込み）。
- **バージョンが本番とずれている**。composeはPG16・PostGIS 3.4、本番はPG18・PostGIS 3.6.4。
  `source_features.rast`（raster型、T970で追加）を3.4で扱えるかは未検証。

**この開発機にdockerが入っていないため、どこで止まるかを実行して確かめていない。** 上は
ファイルとイメージの仕様から導いた見込みであり、実測ではない。

2. 実測に基づき、次のどちらかを選ぶ:

## 追加の依頼（2026-09-23、ユーザー）: リモート（クラウド）の開発環境を毎回作り直さない

背景: 並行実行（[T1049](T1049.md)）でリモートのエージェントを多数動かしたところ、毎回
依存の導入からやり直し、PostGIS統合テストも回せなかった。ユーザー「リモート上で毎回環境を
作り直して始めるのは大変。docker-composeを整備したら楽になる？」。

**上の「維持する／畳む」はこの用途により「維持する」に決まる**（リモートの開発環境として使う）。

公式文書（https://code.claude.com/docs/en/cloud-environments 、2026-09-23に読んだ）で確かめた前提:
- クラウドのVMには Docker・docker compose・PostgreSQL 16・Redis 7 が最初から入っている
  （DBは起動していない）。PostGISの有無は書かれていない——実測で確かめる。
- **セットアップスクリプト**（claude.aiの環境設定に書く。ユーザーの設定作業）は最初の1回だけ
  走り、終了時のファイルシステムが保存され、以後のセッションはそこから始まる（スクリプトの
  変更時と約7日ごとに作り直し）。5分以内に終える。動いているプロセス（起動したDB・コンテナ）は
  保存されない。
- リポジトリの`.claude/settings.json`の**SessionStartフック**は毎セッション開始時に走り、
  ローカルでも走る。リモートだけにするには`CLAUDE_CODE_REMOTE`が`true`かを見る。

### やること（追加）

4. セットアップスクリプトの本体をリポジトリに置く（claude.aiの設定欄にはそれを呼ぶ1行だけを

## 段階A: 実測と、クラウドのセッションの用意（2026-09-25、担当 D-compose）

クラウドのセッション（Ubuntu 24.04・x86_64・4コア、Docker 29.3.1・Compose v5.1.1）で実測した。
着手時点の`docker-compose.yml`は既にpostgres `postgis/postgis:18-3.6`（起票時の見込み「PG16・PostGIS 3.4」は
その後の変更で解消済み）。

### 実測: 手順どおりの`cp .env.example .env` → `docker compose up --build`

| どこで | 何が起きたか |
|---|---|
| backendのイメージ | `RUN apt-get update`が`403 Forbidden`（deb.debian.org）で止まり、`docker compose up`全体が終了コード1 |
| frontendのイメージ（単独で`docker compose build frontend`） | `RUN npm ci`が約72秒後に`npm error Exit handler never called!`で止まる |
| postgres・redisのイメージ | Docker Hubから取れた（別の時刻には`429 Too Many Requests`が出た。取得上限は接続元ごと） |

ビルドの2つは**クラウドの環境の性質**で、composeの欠陥ではない: 外への通信はホストのプロキシ
経由でしか通らず、コンテナの中からは直接出られない（ホストの`curl`・`pip`・`npm`は通る）。
イメージの取得はdockerdが行うので通る。以下はpostgres・redisだけを`docker compose up -d postgres redis`で
起動し、backendは同じコードから作ったイメージ（T1059の観測用の写し）とネイティブのvenvで確かめた。

- **版**: `SELECT version()`→PostgreSQL 18.6、`postgis_full_version()`→PostGIS 3.6.4・GEOS 3.14.1・
  PROJ 9.8.1。本番（18・3.6）とメジャーまで揃っている。
- **拡張**: 初期化で入るのは`postgis`・`postgis_topology`・`postgis_tiger_geocoder`・`fuzzystrmatch`で、
  **`postgis_raster`は入らない**（`pg_available_extensions`には3.6.4がある）。見込みどおり。
- **スキーマ**: 空のDBでbackendを起動すると、lifespanが
  `relation "axis_definitions" does not exist`（`AxisDefinitionSyncError`）で止まる。
  `create_tables()`を流すと`このDBに拡張 postgis_raster が入っていません`で止まる。見込みどおり。
- **スキーマを作っても起動しない**（見込みに無かった）: 拡張とスキーマを作ったあとも、
  `axis_definitionsテーブルが空です`で止まる。軸の行はリポジトリに写しが無く、足す管理APIは
  起動したbackendにしか無い。`docs/modules/backend/axis-studio.md`の「軸を1つ以上APIで登録するまで
  アプリが起動しない」の登録の手段が無い。→ 仕掛中のダッシュボードに問い（`T989-fresh-axes`）を置いた。
- **`.env`が無いと`docker compose exec`が止まる**（見込みに無かった）: `up -d postgres redis`は通るが、
  `exec`はbackendの`env_file: .env`を読みに行き`env file … not found`で止まる。
- **postgresのhealthcheckが初期化の途中でhealthyになる**（見込みに無かった）: `pg_isready -U ridecompass`
  （Unixソケット）は、初期化用の一時サーバーの時点（`postgis`拡張がまだ0件）で成功した。
  `-h 127.0.0.1`（TCP）は本起動のあとにだけ成功した。0.1秒おきに打った時系列:
  `socket=S tcp=- postgis=0` → `socket=S tcp=- postgis=1` → （一時サーバー停止）→ `socket=S tcp=T postgis=1`。

### 方針（維持する）

決定済みの用途（リモートの開発環境）に合わせ、composeは**postgres・redisの供給元**として使い、
backend・frontendはネイティブで動かす。

- `docker-compose.yml`: `env_file`を`required: false`に。healthcheckをTCPに。
- `backend/scripts/bootstrap_database.py`: `--create-extensions`（`REQUIRED_EXTENSIONS`を読んで
  `CREATE EXTENSION IF NOT EXISTS`する。一覧を書き写さない）と`--to`（その段で止める）。composeの
  DBには`--create-extensions --to schema`でスキーマまで作れる。
- `scripts/remote_dev/`（新設）: `setup.sh`（claude.aiの環境のセットアップスクリプトの本体）・
  `session_start.sh`（SessionStartフックの本体）・`lib.sh`（共通）。依存はlockfileのダイジェストごとに
  リポジトリの外（`/opt/ridecompass-dev`）へ作り、`backend/.venv`はそこへのリンク、`frontend/node_modules`は
  ハードリンクの写しにする（セッションはリポジトリを新しくcloneして始まるため、リポジトリの中に置いた
  ものが引き継がれる保証が無い）。Docker Hubが429を返したときは`mirror.gcr.io`の同じイメージを取り、
  元の名前を付け直す。
- `.claude/settings.json`: SessionStart（`startup|resume`）へ`session_start.sh`を登録。
- `.gitignore`: `.venv/`を`.venv`に（`/`付きはディレクトリにしか当たらず、リンクにした`backend/.venv`が
  `git status`に未追跡として出た）。
- 文書: `docs/architecture/setup.md`（composeのスキーマの作り方・軸が0行では起動しないこと・
  「クラウドのセッション」節）、`tech-stack.md`（版の表の行・Docker構成）、`directory-layout.md`
  （`scripts/`の説明）、`docs/conventions/orchestration.md`（「手元かクラウドか」節。記録が指していた
  「ローカルかリモートか」節は今の文書に無かったので新設した）。

セットアップスクリプトが最初の1回だけ走り、終了時のファイルシステムが保存され、プロセスは残らないこと・
SessionStartフックが毎回（resumeを含む）走り`CLAUDE_CODE_REMOTE`で絞ることは、公式文書
（https://code.claude.com/docs/en/cloud-environments 「Setup scripts」「Environment caching」
「Setup scripts vs. SessionStart hooks」、2026-09-25に読んだ）で確かめた。セットアップの時点で
リポジトリがどこにcloneされているかは書かれていないため、claude.aiの欄の1行は位置に依存しない形
（masterを一時ディレクトリへ浅くcloneして`setup.sh`を流す）にした。

### 検証（この機械で1回目・2回目を再現した）

claude.aiの環境設定はユーザーの操作なので、同じ状態をこの機械で作って測った。

| 場面 | 状態 | 所要 |
|---|---|---|
| 1回目（セットアップ） | キャッシュ・venv・node_modules・イメージ無し、dockerd停止 → `bash scripts/remote_dev/setup.sh` | 51秒（backend 50秒・frontend 30秒・イメージ24秒を並行） |
| 2回目（フックだけ） | キャッシュあり、`backend/.venv`・`frontend/node_modules`無し（新しいclone）、dockerd停止 → `CLAUDE_CODE_REMOTE=true bash scripts/remote_dev/session_start.sh` | 9秒（backend 0秒・frontend 1秒・DB 9秒）。開始から`pytest tests/test_derive_node_materials.py`（`postgis`マーカー、2 passed）が終わるまで11秒 |
| セットアップの欄が空のとき | キャッシュも無し、イメージはあり → フックだけ | 44秒（backend 44秒・frontend 24秒・DB 9秒） |

- `-m postgis`の統合テスト: 上の2回目で`2 passed`。conftestが作業ツリー専用のテストDB
  （`ridecompass_test_ride_compass_dc1965ee`）をcomposeのDBに作った。
- frontend: `./node_modules/.bin/vitest run src/components/ui/icons/axisIconPalette.test.ts`→3 passed
  （`node_modules`はハードリンク。`stat -c %h node_modules/next/package.json`→2）。
- 手元でフックが何もしないこと: `CLAUDE_CODE_REMOTE`が未設定・`false`・`1`のそれぞれで、
  `session_start.sh`は出力なし・終了コード0・7ms。`.claude/settings.json`のコマンド文字列をそのまま
  `sh -c`で流しても同じ（スクリプトが無い場合も終了コード0）。
- `bootstrap_database.py`: 引数なしの`--to schema`→`拡張 postgis_raster が入っていません`で止まる。
  `--create-extensions --to schema`→schemaだけ流れ、拡張に`postgis_raster`が入り公開スキーマの表11個。
  `--from derive --to schema`→`ValueError`。そのあとbackendを起動すると`axis_definitionsテーブルが空です`で止まる。
- 静的検査: `ruff check scripts/bootstrap_database.py`→All checks passed、`mypy scripts/bootstrap_database.py`→
  no issues、`bash -n`（3本）→通過、`python3.12 scripts/review_checks.py docs`→違反なし。
