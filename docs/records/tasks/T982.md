# T982. PostGIS統合テストが、スキーマ作成の失敗を「接続できない」に化けさせる 規模S

状態: 完了（2026-09-21起票・完了）

## 背景

`backend/tests/conftest.py`の`road_graph_engine`は、拡張の有効化とテーブル作成を
`try` / `except Exception` で囲み、失敗すると
`pytest.skip("ridecompass_test DBに接続できないためスキップ")` へ落とす。

接続以外の失敗——拡張の不足、型の欠落、ORM宣言とDBの食い違い——も同じ文言で
スキップになる。そのファイルのテストは1件も走らないまま、出力には「接続できない」
とだけ出る。**緑のスイートが「全部スキップ」でも見分けが付かない。**

T970で`source_features.rast`（`raster`型）を足したとき、テストDBに`postgis_raster`が
無ければ`create_all`が落ちてこの経路に入る条件が揃った。実際には別の理由で通っていたが、
通っていることを確かめるのにDBを直接覗く必要があった。

## 対応方針

- スキップしてよいのは**接続の失敗だけ**にする（`OSError`・asyncpgの接続系例外）。
  それ以外は落とす。
- スキップの文言に、実際の例外を含める。

## 完了条件

- 拡張をわざと落としたDBを指して実行し、スキップではなく失敗することを確認する
  （「実装した」ではなく「効いている」を見る）。

## 対応（2026-09-21）

**接続の確認と、用意そのものを分けた。** 接続は`SELECT 1`で確かめ、ここで落ちたときだけ
スキップする。用意（拡張・テーブル）はその後に行い、失敗は例外のまま落とす。

**用意の中身はアプリの`create_tables()`へ寄せた。** conftestは`CREATE EXTENSION postgis`と
`Base.metadata.create_all`を自前で書いており、スキーマが要求する拡張の一覧
（`road_graph_repository.py: REQUIRED_EXTENSIONS`）を知らなかった。そのため`postgis_raster`が
無いDBでは「型"raster"は存在しません」という読めない失敗になる（本来は何を実行すればよいかを
告げて止まる設計がアプリ側にある）。拡張は同じ一覧から`CREATE EXTENSION IF NOT EXISTS`を
試み、入れられない権限のときは握って進み、不足は`create_tables()`に言わせる。

スキップの文言はDB名を出す（URLはパスワードを含むため出さない）。

## 効いていることの確認（2026-09-21）

直した直後、`tests/test_axis_definition_repository.py`の20件が**スキップではなくエラー**に
なった。理由は開発機のテストDBに`postgis_raster`が無いこと:

```
asyncpg.exceptions.UndefinedObjectError: 型"raster"は存在しません
[SQL: CREATE TABLE source_features (...)]
```

`create_tables()`へ寄せた後は、同じ状態がこう出る:

```
RuntimeError: このDBに拡張 postgis_raster が入っていません。
スーパーユーザーで先に実行してください: CREATE EXTENSION postgis_raster;
```

**変更前は、この状態が「接続できないためスキップ」になっていた。** わざと壊した入力を作る
までもなく、手元のDBが既にその状態だった。

## 副作用（意図したもの）

`create_tables()`は必要なモジュールを自分でimportするため、テストDBに**全テーブル**が
作られるようになった（従来はconftestがimportした範囲だけ）。これがraster列を持つ
`source_features`を作らせ、上の失敗を表に出した。

## 開発機の後始末

テストDB6つ（共有・複製元・作業ツリー専用4つ）へ`postgis_raster`を入れた。複製元
（`ridecompass_test` / `ridecompass_test_template`）に入れたので、以後の作業ツリー専用DBは
複製で引き継ぐ。開発機で一度だけ必要な作業として
[docs/conventions/testing.md](../../conventions/testing.md)の表へ追記した。

## 検証

- `pytest -m postgis -q -n 0` → 149 passed（回帰なし）
- CIは`postgis/postgis:16-3.4`が`postgis_raster`を入れないが、DBユーザーが
  スーパーユーザーのため`road_graph_engine`が入れる。

## 扱わなかったもの

`docker-compose.yml`のpostgresサービスも同じイメージで`postgis_raster`が入らない。ただし
これは本変更以前からで、`create_tables()`が「拡張を入れずに要求する」という既存の設計判断
（`scripts/bootstrap_database.py`のdocstring）とセットになっている。composeへ
`CREATE EXTENSION`を書くと`REQUIRED_EXTENSIONS`の写経になるため、ここでは触らない。
