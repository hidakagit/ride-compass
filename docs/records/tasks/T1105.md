# T1105. 不明・データなしを、地図と凡例で不明らしく見せる（区分の分からない道を破線にする等）

状態: 完了（2026-09-25）

## 背景

ユーザー指摘（2026-09-25）: 凡例の「不明・他」だけ線種を変えられないか（破線等）。データが不明なのと、データはあってその種類なのとは違う。全般的に不明を不明らしくしたい。承認時の方針: 最初の段階（S）で、地図と凡例で「不明・他」「データなし」を出している所（道路の線の区分の不明・他、ルートのレンズのデータなし等）をコードから機械的に列挙し、同じ見せ方（破線・薄い灰色）にそろえる。MapLibre GL JS は line-dasharray の値ごとの切り替えに5.8.0から対応（node_modules/@maplibre/maplibre-gl-style-spec の latest.json、使っている版は6.10）なので、線の図層を分けずに済む見込み。凡例の見本（MapOverlayControlsの見本、LegendEntryのline）も破線にする。

## 段階1: 不明・データなしを出している所の列挙（2026-09-25）

母集団: `frontend/src`（テスト・生成物を除く）で`UNKNOWN_ENTRY`・`LEGEND_NO_DATA_KEY`・`COLOR_NO_DATA`・`COLOR_UNKNOWN`・
`isFallback`・`no_data`・「不明」「データなし」「不明・他」をgrepし、地図と凡例に出る所だけを残した。
- 道路の線（一次属性、`scene/groups/roadLines.ts`・凡例`scene/legends.ts`の「不明・他」）
- ルート確定前の評価軸の線（`scene/groups/axisLines.ts`、凡例`view/lens.ts`の「不明」「データなし」）
- ルート確定後のルートの区間の線（`lib/mapDisplay/routeStyleModes.ts`の「データなし」→`scene/groups/routes.ts`の`detailLine`）
- 凡例の見本（チップの▶`MapOverlayControls`・一覧`LegendCheckboxList`・レンズのピル`LensControl`）
- 扱わなかったもの: 点（スポット）の分類の外の値は`COLOR_UNKNOWN`の灰で描くが、凡例に行が無く値が無いわけでもない（点は破線にできない）。
  風の凡例の「無風・矢印なし」は`no_data`の色を使うが、無風は観測された値で「不明」ではない。ポップアップの「不明」は文字で既に書いてある。

## 決定（ユーザー 2026-09-25、会話）

- 道路の「不明・他」は2種類を1行にまとめていた（タグが無い道と、タグはあるが分類の外の値の道）。**分ける**: 前者は「不明」（値が無い、
  灰の薄い破線）、後者は「その他」（値はある、灰の薄い実線）。タイルにOSMの生の値が入っているのでfrontendで分けられる。
- 設計書の「線種が運んでよいのは操作の状態だけ」を**「操作の状態と、値が無いこと」へ広げる**。値が無いことは分類ではなく、どの属性・軸でも
  同じ意味なので、線を重ねても混ざらない。

## 変更

- 破線の刻みの正本をbackendに置いた（`domain/map_display.py: NO_DATA_DASH`、生成物`mapDisplay.noDataDash`）。乗り換え帯の破線より細かく刻む。
  frontendは`sceneBuilders.ts: noDataDashExpression`（値が無い地物だけ破線、他は実線）を道・評価軸・ルートの線で共有する。
- 道の線: タグが無い道だけを破線にし、凡例を「その他」「不明」の2行に分けた。凡例で隠す操作もそれぞれに効く——**分ける前は「不明・他」を
  隠しても地図が変わらなかった**（絞り込みが分類の行しか見ていなかった）。
- 実装の途中で見つけたこと: トンネル・一方通行はタグの不在を「該当しない」(false)としてタイルへ載せる（材料の欠け方`missing_semantics`が
  `definite`）。値の無い道が現れない属性に「不明」の行と破線を出すと嘘になり、falseを「その他」と呼ぶのも合わない。そこで、表示の軸ごとの欠け方を
  **backendの宣言から配る**ようにした（`material_catalog.py: display_axis_missing_semantics`がその値を載せる材料の宣言を引き、
  `export_openapi.py`が`primaryAttributes.ts`の軸へ`missing_semantics`として書く）。`unknown`の属性（道路種別・路面）だけが「不明」の行と破線を持ち、
  `definite`の属性（トンネル・一方通行）は分類の外の行を「該当なし」と呼ぶ。
- 評価軸の線（ルート前）: 評価できない道を破線にした。取得中は破線にしない（値が無いとは決まっていない）。
- ルートの線（ルート後）: モードが「値が無い」の判定（`noDataExpression`）を持ち、区間の線がそれで破線になる。レンズ「なし」は持たない。
- 凡例の見本: 値が無い行（`isFallback`）は途切れた見本（`legendFilter.ts: legendSwatchBackground`）。チップの▶・レンズの一覧とピルが同じ関数を通る。
- 路面の説明（ⓘ）を「不明」「その他」の見え方へ直した。設計書（`static-map-layers.md`の決まり・`map-axis-coloring.md`）と、「不明・他」と書いていた
  `static-road-attributes.md`・`tech-stack.md`を直した。
