# T690. 目的地モードで最短距離ルートを既定で出し、好みのルートとの距離差を示す 規模M

状態: 完了（2026-09-09）

## 背景

目的地モードは軸の重みで作った合成コストで経路を選ぶため、返る候補はすべて「軸設定に
沿った経路」になる。利用者は好みのルートを走る**対価**（最短距離からどれだけ余分に
走るか）を知らないまま選んでいる。

「32.5kmで約26回止まる」（[T687](T687.md)）と同じ構図で、得点だけでは判断できない。
余分な距離は、軸設定を強めるかどうかを決めるための判断材料になる。

## 実施内容

### 距離だけで選ぶ経路（`road_graph_engine.py: select_shortest_distance_route`）

`select_via_nodes`と同じ前向き木・後ろ向き木の合成だが、`build_shortest_path_tree`の
コスト配列に`edge_length_m`をそのまま渡す。軸の重みを一切通らないため、得られるのは
距離最短の経路になる。追加コストはDijkstra 2回で、逆向きstaticsは`select_via_nodes`が
既に構築・キャッシュしたものに乗る。

経由Nodeは最短経路上のどのNodeでも同じ経路を表す（`len_f + len_b`が同値で並ぶ）ため、
そのうち**往路長が全長の半分に最も近いもの**を選ぶ。他の候補と同じく往路レグ・復路レグへ
概ね半分ずつ割れ、レグごとに時刻の異なる風の評価が候補間で揃う——ここを素朴に
`argmin`で決めると経路の端が選ばれて全区間が片方のレグへ寄り、比較したい当の数字が
別の時刻基準で出てしまう。

### 候補への合流（`route_generator.py: _generate_destination_routes`）

最短経路を`RouteCandidate.is_shortest_distance=True`で1本必ず含め、**難易度順の外へ
出して先頭へ固定**する。基準線が難易度順に沈むと基準として使えないため。

| 状況 | 扱い |
|---|---|
| 軸最良の候補と別経路 | 候補へ1本足す |
| 軸最良の候補と同じ経路 | 候補を増やさず、その1本へ印を付ける（同じ経路のタブが2枚並ぶのを避ける） |
| 件数が`max_routes`を超える | 末尾（最も難易度の高い候補）を切る。先頭の最短経路は必ず残る |
| 最短経路を求められなかった | 印を付けずに従来どおり返す（基準線が無いだけ） |

### 表示（`lib/routeTabLabel.ts`・`page.tsx`）

候補タブは順位番号の代わりに「最短」と示し、他の候補には距離の後ろへ超過kmを添える。

```
最短 18.0 km   |   2 22.0 km +4.0   |   3 24.5 km +6.5
```

タブに出すのは、ここが候補を見比べる場所だから。タブの中身に置くと比較のたびに開き直す
ことになる。差が丸めて0.0kmなら何も出さない（0を並べても判断材料にならない）。

## 適用範囲

目的地モード（経由地の無い起点→目的地）のみ。周回モードは目標距離が距離を決めるため
「最短」という概念を持たず、`is_shortest_distance`は常にFalseで表示も出ない。経由地を
伴う目的地ルートは`trace_loop`の単一経路生成のため対象外。
