# T785. 下部シートの高さを、利用者が決めた高さとして覚える

規模S。
状態: 完了（2026-09-13）

## 背景

[T778](T778.md)で下部シートの既定の高さを中身へ合わせるようにしたが、その結果、
利用者が自分で低くしたシートも「中身が全部見える高さ」へ戻されるようになった。
ルート結果は[T759](T759.md)・[T780](T780.md)で低い高さでも使える形になっており、
地図を広く見るためにわざと低くしておきたい場面がある。

## 対応方針

利用者がシートの高さを操作したら、それ以降はその高さを優先し、中身に合わせた
自動調整で上書きしない。

- 覚える単位は従来どおりシート共通の1つ（`ridecompass:mobile-sheet-height-vh`）。保持範囲も
  従来どおりlocalStorageで、次回起動でも有効。
- 「決めた」の判定に新しい保存値を足さない——自動調整は`onHeightChange`までで保存しないため、
  **保存値があること自体が利用者の確定操作の証跡**になる。`page.tsx`がマウント時に保存値の
  有無を読み、`BottomSheet`へ`autoFitHeight`として渡す。
- 自動調整する側（まだ決めていない利用者）にも欠けがあったので併せて直した:
  タブを切り替えても開いた時点の高さのままで、切替先の中身が収まらない。`fitKey`が変わった
  ときだけ合わせ直す仕組みを足し、「ルート設定」シートは[T784](T784.md)のタブを渡す。

## 検証

Playwright（dev実機・390px）で計測:

- 保存値35vh: 開いた直後295px／「重み」タブへ切替後も295px（中身に合わせて動かされない）
- 保存値なし: 開いた直後177px（「条件」の中身なり）→「重み」へ切替で388pxへ合わせ直し
  （本文 clientHeight 334 = scrollHeight 334でスクロール不要）

単体テストは`BottomSheet.test.tsx`へ2件追加（`autoFitHeight=false`なら合わせない・
`fitKey`が変わると合わせ直す）。
