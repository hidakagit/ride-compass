# T770. ルート線が面レイヤーの上で読めない（縁取りが無い）

規模S。
状態: 完了（2026-09-12）

## 背景

区間の色分け線（`MapView.tsx: DETAIL_LAYER_ID`）は幅6px・不透明度1の単線で、色は
レンズ配色（総合難易度なら易しい＝緑）。縁取り（ケーシング）を持たないため、同系色の
面レイヤーが背景に来ると線の輪郭が消える。研究モードの比較スロット線（`drawExperimentSlots`、
緑・橙・紫）も同じ。

[T754](T754.md)の症状（地図全面が緑）は空タイル用PNGが不透明だったことが原因で、そちらは
別に直る。ただし「面が何色でも線が読める」という性質は`route-detail-segments-line`側に
無いままで、降水・標高図・キキクルの実データなど他の面でも同じことが起きる。

## 調査項目

- ケーシングを足す場所（`DETAIL_LAYER_ID`の直下にもう1本置く／`line-gap-width`を使う）と、
  比較スロット線への同じ扱いの適用範囲
- 縁取りの色を固定色にするか、ライト/ダークで変えるか（地図は常にライト配色）
- 矢印ハロー（`ROUTE_ARROW_HALO_LAYER_ID`）が既に持つハローとの重複・整合

起票時はT769だったが、同番号を別セッションが先にmasterへ載せたため振り直した。

## 対応

色分け線の下へ縁取り（`DETAIL_CASING_LAYER_ID`、幅10px）を1本敷く。色
（`ROUTE_LINE_CASING_COLOR`）はレンズ配色にも背景にも依存しない一定の暗色にする——
どちらかに依存させると、依存先が変わったときに同じ問題が戻る。凡例で非表示にした
カテゴリの縁だけが残らないよう、色分け線と同じfilterを適用し、表示・非表示も揃える。
比較スロット線（`SLOTS_CASING_LAYER_ID`、幅7px）にも同じ扱いを入れた。

未選択の候補線（`ROUTES_LAYER_ID`、細い・半透明の参考線）には入れない——「選択中候補を
主役にする脇役」という既存の意図的な見た目を壊すため。選択中候補の下地線は
`OUTLINE_LAYER_ID`（幅10px・不透明度0.25）が既に担っている。

## 検証

- `MapView.layerOps.test.ts`に回帰テスト3件（縁取りが色分け線より先に追加される＝下に来る、
  色分け線より太く線色に依存しない一定色、同じfilterが適用される）
- Playwright（1280x800、地図の下地を緑一色にして撮影）で前後比較。縁取りを無効にした状態
  では線の輪郭が無く、有効にすると暗い輪郭が出て面から分離する
