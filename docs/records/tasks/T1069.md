# T1069. 地図の上に開くポップオーバーから始めたピンチが、ページを拡大するかを確かめる

状態: 未完了（2026-09-23起票）

## 背景

T1068で地図ペインの直下と MapLibre の操作部品には touch-action: none を1つの規則で掛けたが、Radix のポータルで body 直下へ出るポップオーバー（レンズの選択肢・チップの▶パネル等、地図の上に開くもの）はこの規則の外にある。E2E の母集団（初期表示で地図の範囲の最前面にある部品）にも入っておらず、開いた状態で2本指を置いたときにページが拡大するかは未検査。map-runtime.spec.ts のピンチの検査を開いた状態へ広げて測り、拡大するなら同じ性質の規則で直す。

## 測った結果（2026-09-23、T1014段階Dの実験）

T1014段階Dで、画面の全状態（幅 × モード × 段階 × 開いたシート・パネル、`e2e/states.ts`が画面から導く）へ
ピンチの走査（`e2e/scans.ts: scanPinch`）を当てた。[CI run 35834277290](https://github.com/hidakagit/ride-compass/actions/runs/35834277290)
（masterへは入れていない実験）で、モバイル幅の開いた状態から始めたピンチがページを×2.17（一部×2.67）に拡大した。
拡大した部品は、どれも地図ペインの外の要素だった:

- 下部シート（「ルート設定」「ルート結果」）の中身: タブ（条件・重み・除外・比較）、ボタン（ルート生成・目的地・周回・
  候補数の増減・除外の各項目・GPX出力・ルートをクリア等）、入力欄（距離・想定速度・出発日時）、見出しや本文の`div`
- ポータルで出るポップオーバーの中身: レンズの選択肢（`ul "レンズ"`・各軸のボタン・凡例の各段階のラベル）、
  ヘッダーのメニュー（研究モードのチェックボックス）

**決めること**: 下部シートは地図の上に重なるが、中身は読む・入力する画面でもある。ここで始めたピンチを
ページの拡大へ渡す（読みやすさのために拡大できる）か、止める（地図の上で2本指を置いたときに画面ごと
拡大しない）かは、UIの判断になる。止めるなら、T1068と同じく「地図の上に開くもの」という性質で1か所の
規則にし、`e2e/all-states.spec.ts`の走査へピンチ（`scanPinch`）を足して全状態で確かめる。

**ユーザー決定（2026-09-23）**: 拡大しないようにする。「ページ全体で拡大させないように統一はできる？」
——地図の上に開くものだけでなく、ページ全体で拡大させない1つの規則にできるかを、ブラウザ（とくにiOS Safari・
Android Chrome）の公式の文書で確かめてから決める。できるなら、T1068の`touch-action`の規則もそれへ1本化する。
**ユーザー決定（2026-09-23、追加）**: 地図はピンチで拡大させる。「地図の拡大意図でほぼユーザはピンチするはずで、
それ以外の要素が拡大されることを防ぎたい意図」。切り分け: 地図の上で始めたピンチは地図を拡大する（ページは
拡大しない）。それ以外の要素で始めたピンチは、ページも要素も拡大しない。
