# T445. WindWayService/GradientWayServiceのbearing_deg型シグネチャがルーター層とOptional不一致

状態: 完了（2026-08-31）

- 背景: `統合レビュー第2回`（`.claude/commands/review/history/2026-08-30_all_2.md`P2-1）の
  指摘。`WindWayService`/`GradientWayService.get_way_values`の`bearing_deg: float`
  （非Optional）が、`backend/app/api/routers/region.py`ルーター層の
  `bearing_deg: float | None = None`と型シグネチャが不一致。
- 影響: 現状は両材料（wind/gradient）とも`needs_bearing=True`のため実害はないが、将来
  `needs_bearing=False`の材料が増えた際に、型チェッカーが検出できない不整合（Noneが
  渡る経路があるのにfloat非Optionalとして扱われる）を生む型安全性の穴。
- 対応方針: `bearing_deg: float | None = None`へ揃えるか、`needs_bearing=True`の材料しか
  呼ばないことをコード上で保証する形（型レベルで表現するか、呼び出し元でのassert等）に
  する。
- Confidence: High（backendシャードがシグネチャを直接比較）。
- 規模S。

## 実施記録（2026-08-31完了）

- **採用した方針**: `bearing_deg: float | None = None`へ揃える（対応方針(a)）。
  `at: datetime | None`が既に同じ理由（router側の材料非依存インターフェースとの統一、
  gradient_way_service.pyのdocstring参照）でOptionalとして受け取られている既存パターンと
  一貫させた。
  - `WindWayService.get_way_values`・`GradientWayService.get_way_values`双方の
    `bearing_deg`をOptional化。
  - 型を緩めただけで終わらせず、両メソッド冒頭に`if bearing_deg is None: raise
    ValueError(...)`を追加（fail-fast）。風・勾配は自身の材料として常にbearing_degを
    必須とする（`needs_bearing=True`が変わらない事実）ため、router側の422検証を
    すり抜けて呼ばれた場合でも、Noneを計算式へ無音で渡さず即座に失敗させる。
  - router（`api/routers/region.py`）側の呼び出しコードは変更不要
    （既に`bearing_deg: float | None`のまま渡していた）。
- **検証**: 各サービスへNoneガードの回帰テストを1件ずつ追加
  （`test_bearing_deg_none_raises_value_error`）。
  `pytest tests/test_wind_way_service.py tests/test_gradient_way_service.py
  tests/test_region.py tests/test_region_routes.py`59件すべて通過。この変更は
  backend Pythonファイルのみが対象（frontendへの影響なし）のためブラウザでの実機確認は
  対象外と判断した。
