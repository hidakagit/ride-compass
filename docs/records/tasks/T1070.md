# T1070. 判断待ちの一覧が、保留の選択肢を別々の保留として数え、節の後ろのユーザー決定を認識しない

状態: 未完了（2026-09-23起票）

## 背景

判断待ちの一覧（python scripts/orchestrate.py decision list、scripts/orchestration/decisions.py）がタスク記録の保留を集めるとき、2つの穴がある。(1) 保留の節の中の選択肢（番号付きの項目）を別々の保留として数える——1件の保留が選択肢の数だけ判断待ちに見える。(2) 節の後ろ（同じ見出しの下の末尾や直後）に書いた「ユーザー決定（日付）」を、その節の決定として認識しない——決着済みの保留が判断待ちに残る。実例（2026-09-23）: T958 は「T955の判定……着手の可否はユーザー判断で保留」の節1件が3件に見え、D-007のユーザー決定をファイル末尾へ書いても3件とも消えなかった。規約「ユーザーの判断待ち」は、判断待ちかどうかを記録の保留から導く（状態の表に写さない、T1065）ので、集め方の誤りはそのまま判断待ちの誤表示になる。

対応方針: 保留の単位を「保留を宣言した段落（見出しに保留を含む節なら節全体、『保留:』で始まる段落ならその段落）」とし、中の選択肢は1件の保留の選択肢として扱う。決定の書き方を規約に1つ決める（例: 保留の節の中に『**ユーザー決定（日付）**:』の段落を置く）——書き方を決めずに位置の推測で拾わない。既存の記録で今日決まったもの（T958）をその書き方へ直す。

完了条件: T958 が判断待ちに1件として出て、ユーザー決定を決めた書き方で書くと0件になることを、壊した入力（選択肢3つの保留を持つ一時の記録）で確かめる。decision list の全体の件数が変わる場合は、変わった分の内訳を記録する。
