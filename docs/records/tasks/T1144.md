## 段階A: 名指しされた5件（2026-09-27）

1件ずつ「知らせる・断る・そのまま」を決めた。(1)(2)はダッシュボードの答えどおり。(3)〜(5)は選択が記録に残っていなかったため、
正しさ（利用者が当てにして裏切られないか）で決めた。

- **(1) 軸カタログの取得失敗 → 知らせる**（答え(1)）。常設ヘッダーの「未取得」の印（警報・暑さ指数・河川の取得失敗と同じ置き場、
  `features/conditions/WarningBadge`）に「軸一覧」を並べ、何が起きているか（地図の道路・スポット・事故が出ない・重み配分が反映されない・
  合成が使えない）と再試行をポップオーバーに出す。印の項目は`effect`（取れない間に何が起きているか）と`onRetry`を持つ形にし、
  警報の「出ていてもバッジは表示されません」も項目ごとの`effect`へ移した。重みを上書きしていたのに送れずに作った候補には
  「ルート結果」の先頭に「重み配分を反映できず、既定の配分で作りました。」を出す（`app/page.tsx: weightsNotApplied`）。
  **上書きしていない生成には出さない**——元から既定の配分で、反映できなかったものが無い（答えの文言は「重み配分を反映できず」で、
  反映すべき配分が無い生成に出すと嘘になる）。重みタブの告知は残した（重みを触っている人へ、その場で理由を見せる）。
  設計書（route-settings-and-results.md）の「失敗時は既存軸の静的フォールバック」は、着手時点で既に「軸0件。ビルド時の写しへは倒さない」に
  直っていた（前提の食い違いではなく、起票後に別タスクで直った）。
- **(2) 位置が取れないときの既定の地点 → 断る**（答え(1)）。出発地が仮の地点（`locationSource === "default"`）のまま「生成」を押すと、
  どちらのモードでも「現在地が分かりません。位置情報を許可するか、地図で出発地を選んでください。」を「ルート結果」に出して生成しない
  （`useRouteFormSubmit`の`originKnown`）。目的地モードの出発地の行は「現在地を取得できていません」と出す。仮の地点は地図の最初の中心と
  天候の取得の位置には今も使う（天候の件は段階Bの候補）。e2e（モック）は位置情報を許可していなかったため、`e2e/fixtures.ts: installApiMocks`で
  候補の線の始点の位置を渡す。
- **(3) 軸カタログが取れないときの乗り換えの区間の長さ → 断る**。`EMPTY_CATALOG.clientTuning`をビルド時生成物の値から空へ変え、
  区間を割る下限を引けない間は「合成」の入口を出さない（`canSpliceDisplayedRoute`）。知らせる（生成物の値で動かし注記）でなく断るのは、
  管理画面で較正した値と違う切り方の乗り換え先が並び、それが較正と違うことを利用者が確かめる手段が無いため。取れていないことは
  (1)のヘッダーの印が言う（`effect`に「ルートの合成も使えません」）。生成物`route-generate-config.json`の`client_tuning`は、フロントが
  引くidが宣言に在ることの突き合わせ（`useAxisCatalog.test.ts`）にだけ使う形で残した——backendの宣言をフロントの静的な検査から
  見る経路はこの生成物しか無い。値そのものは読み手がいない（id一覧だけを書き出す形へ変えるかは、生成物の書き出しに触る変更になるため
  ここでは行わない）。
- **(4) 材料の換算係数が届かないとき → 知らせる（地図で「データなし」）**。係数（`material_runtime_scales`、いまは事故の収録年数から
  作る）が届かない材料を使うramp軸は、どの道も「データなし」の色の破線で塗り、凡例も「データなし」だけに当てはまる
  （`axisLayers.ts`が入力に`scaleMissing`を付け、`axisLines.ts: buildAxisRampUnknownExpression`が真を返す）。寄与0で塗ると、事故の件数が
  無いのに最良側の色になる。係数が届かないのは、事故データを取り込んでいないときと、backendが収録年の読み取りに失敗して空へ倒したとき
  （`RegionService.get_accident_years`）で、後者でもタイルには事故の値がある——前者と区別しない（どちらも「換算できない」）。
- **(5) 道路網の配列の組み立てで端点の無い区間を落とす → 知らせる（ログで件数）**。落とすこと自体は正しい（端点の無い区間は
  探索に使えない。取込範囲の境界で起きる）ので断らず、落とした有向の行の数を組み立ての要約ログ
  「道路網のつながりを読みました … 端点のノードが無く落とした有向の区間=N」に出す（INFO。境界で起きる想定内の減り方で、
  ログ方針の「中間結果の減り方を1行INFOサマリにする」に当たる）。本番の件数は次の道路網の組み立て（デプロイの前処理
  `scripts/build_road_network.py`か派生の作り直し）のログで分かる。
