■ 背景
「自前で作るのは、標準の道具では足りない理由を書けるときだけ」を既存コードへ当てた棚卸し（2026-09-27）で、自前が妥当と判定したものの、その理由が記録（docs/records）にしか無い、またはどこにも無いものが見つかった。記録は維持されず現在の仕様を表さないので、そこにしか無い理由は書かれていないのと同じとして扱う（CLAUDE.md コメント方針）。放っておくと、次に読んだ人が同じ置き換えを検討し直す。

■ やること（それぞれ、今も成り立つかを確かめてから置き場へ書く）
- 下から出る画面（BottomSheet）に vaul を使わない理由: 暗幕なし・部分表示のときに画面全体が押せなくなる上流の不具合（記録 T255 にだけある）。上流の issue が今も開いているかを公式で確かめてから docs/modules/frontend/frontend-design-system.md へ。
- 地図の表示の差分適用を、依存に既にある maplibre-gl-style-spec の diff() で済ませない理由（状態を持つ地物の表示・基礎地図の道路の下への差し込み・大きな GeoJSON を毎回比べる費用。どこにも無い）→ static-map-layers.md。
- 経路探索に pgRouting を使わない理由（評価の定義が SQL へ二重になる。記録にだけある）→ routing-engine.md。
- 取込のラスタを raster2pgsql で入れない理由（どこにも無い）→ 取込の設計書。
- ジョブの管理に arq を使わない理由（別のワーカーと Redis が要り、1プロセスの前提と合わない。どこにも無い）→ cross-cutting-infrastructure.md。
- e2e の「画面が落ち着いた」の判定を networkidle で済ませない理由（どこにも無い）→ testing.md か e2e のコメント。
- GPX 書き出しの間引き（RDP）を自前にする理由（記録 T786 にだけある）→ 該当の docs/modules。
あわせて、同じ棚卸しで見つけた文書のずれを直す: backend/Dockerfile の --forwarded-allow-ips のコメントが、もう使っていない以前のホスティング先の前提のまま。

## 範囲外で見つけたもの

- `--forwarded-allow-ips='*'`そのものの妥当性: 本番のbackendは`--network=host`で動き、前段はVMのnginx（deploy-backend.ymlのコメント）。前段が同じVMからloopbackで繋いでいるなら、uvicornの既定（127.0.0.1）で足りて`'*'`は要らない。8000番がVMの外から直接届くなら、X-Forwarded-Forを偽ってレート制限のキーを選べる。どちらもVM側の設定（nginx・セキュリティリスト）で決まり、リポジトリからは確かめられなかった。直していない（本タスクは文書だけ）。最終報告で司令塔へ渡した。
- `backend/Dockerfile`は`deploy_backend_gate.py`の配備対象（`backend/**`）に入るので、コメントだけのこの変更でもmasterへ入るとbackendのコンテナが入れ替わる。最終報告で司令塔へ渡した。
