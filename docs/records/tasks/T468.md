# T468. ゼロベース網羅レビュー§6(frontend/app)の残指摘5件対応

状態: 完了（2026-08-31）

- 背景: [T426](T426.md)棚卸し結果の§6（frontend/src/app/）、有効5件。元は
  [zero-base-review-2026-08-30.md](../zero-base-review-2026-08-30.md)の§6。
- 補足: 同じ§6にあった「風(評価軸)チップのon状態残留」指摘はT418で評価軸チップ自体が
  地図UIから撤去され陳腐化済みのため、本タスクの対象外。
- 対象5件（severity・file:line・要旨。全てpage.tsx）:
  1. L1046-1053（`conditionsDirty`） P2: 目的地モードの`waypoints`/`destination`の
     変更を検知しない（比較対象がlatitude/longitude/routeMode等のみ）。
  2. L1433-1445 P2: モバイル操作バー用の`RouteForm`呼び出しにだけ`progressLabel`
     propが渡されていない。
  3. L889-897（`isDynamicGroupLayer`） P2: `mapLayers.ts`の`dataNature==="dynamic"`と
     同じ情報をレイヤーIDの手書き列挙で再実装、`windAxis`だけ暗黙に除外。
  4. L852-879 P3: `summary`/`legendDetails`の組み立てがレイヤーIDごとに5〜8段
     ネストした三項演算子チェーン。
  5. L647-661（`handleRoadAxisSetHidden`/`handleStaticFilterAxisSetHidden`） P3:
     実装が完全に同一な2関数。
- 対応方針・実装メモ:
  1. `generatedConditions`へ`waypointsKey`（`JSON.stringify({ waypoints, destination })`）を
     追加し、`conditionsDirty`が目的地モード生成後の経由地・目的地の追加/削除/移動を
     検知できるようにした（loopモードのdistanceKm比較と同じ「該当routeModeのときだけ
     比較」のゲート方式）。
  2. モバイル操作バーの`RouteForm`（compact）に`progressLabel`が渡っていない件は
     対応不要と判断。`RouteForm.tsx`の実装（L161）は`compact`時に`progressLabel`の値を
     見ず常に固定文言「…」を表示する設計（docstring「未指定時は従来どおり…（compact時）を
     使う」も、実際にはcompact時は常にこの値になり`progressLabel`自体が無視される）ため、
     propを渡しても表示結果は変わらない。コンポーネント自体の設計（省スペースのため
     terseな固定文言にする）と矛盾しない。
  3. `isDynamicGroupLayer`のlayer.idハードコード列挙を`layer.dataNature === "dynamic"`
     （mapLayers.ts側の単一ソース）へ置き換え。調査の結果、windAxis/gradientAxisは
     `isAxisStudioLayer`により別途チップとして描画されない（実害なし）が、**gradientFillは
     環境グループの実チップとして表示されており**、列挙漏れにより「[設定はサイドバー]」が
     誤表示されていた実害のあるバグだった（T426棚卸し時点では気づかれていなかった追加の
     実害）。
  4. `summary`/`legendDetails`組み立ての5〜8段ネスト三項演算子チェーンを、layer.id→値の
     ルックアップオブジェクト（`summaryByLayerId`/`legendDetailsByLayerId`）へ置き換えた。
     フォールバック（`staticFilterSummaries[layer.id]`）は従来どおり最後に見る。
  5. `handleRoadAxisSetHidden`/`handleStaticFilterAxisSetHidden`の重複実装を、共通の
     `setHiddenLegendKeysForAxis`（string引数）へ集約し、2つの薄いラッパーが型
     （RoadFilterAxisId/StaticFilterAxisId）だけを持つ形にした。既存コメントが明言していた
     「型を分けて誤った軸idの取り違えを防ぐ」目的は維持したまま実装の重複を解消。
- 検証: `tsc --noEmit`・`eslint src/app/page.tsx`・`vitest run src/app/page.test.tsx`
  （既存14件すべて成功）。項目1（conditionsDirtyの経由地検知）は、page.test.tsxが
  MapView/RouteFormを軽量スタブへ差し替える設計のため経由地追加操作をUI経由で駆動する
  専用テストの追加は見送り、ロジックの妥当性はtsc型チェックとコードレビューで確認した。
