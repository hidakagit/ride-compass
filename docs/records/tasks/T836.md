# T836. 「鮮度」タブが、読めない・押すまで何も無い・直した後にどうすればよいか分からない

規模M。
状態: 完了（2026-09-14、本番実機のユーザー指摘「文字がずらっと書いてあってよくわからない、
以下のテーブルって言ってもボタン押すまで何もない、この画面で不整合なら何すればいいか
わからない」「uiは省スペース化してシンプル直感的にして」から）

## 背景

`/admin`「鮮度」タブ（`DerivedDataFreshnessPanel.tsx`）の3つの問題。いずれも
[design-principles.md](../../design-principles.md)「冗長なものは削る」（説明文をベタ書きで画面へ
置かずⓘの奥へ）・「1画面の情報量を増やさない」に反している。

1. **説明文を8行ベタ書きしている。** 読むのは1度きりなのに場所は常に取り続ける。
2. **集計前から「下の表に並ぶ各テーブルが…」と表の話をしている。** ボタンを押すまで表は
   無いため、最初に開いた人は存在しないものの説明を読まされる。
3. **不整合と分かっても次の行動が画面に無い。** [T832](T832.md)で完成度の枠にだけ
   「どのバッチを再実行するか」を入れ、世代比較の枠には入れなかった。
4. モバイル実機では表が横に切れ、「比較対象」の列だけが見えて肝心の数字が読めない。

## 対応方針

ユーザー選択（2026-09-14）は**「状態だけ＋必要時に詳細」**。

- 説明はⓘ（`InfoPopover`）の奥へ。見出しの隣に置く。
- 集計前はボタンだけ（表の話をしない）。
- 集計後は上部に1行のまとめ（何件が古い・何件に未計算があるか）と、**再構築の単一コマンド**
  （`app/batch/refresh_derived.py`が依存順に全段を回す唯一の入口）をコピーできる形で置く。
- 一覧は1件1行（状態・名前・規模）にし、run番号などの数字はタップで開く。世代比較と完成度を
  同じ見た目の行にする——読み手にとっては「古いかどうか」が知りたいことで、判定方式の違いは
  開いた先に書けばよい。
- 表（`<table>`）をやめる。横スクロールを前提にしない。

## 実装（2026-09-14）

- 説明文8行を`InfoPopover`（ⓘ）の奥へ。集計前はボタンだけを出す。
- 集計後の先頭に**作り直しが要る件数と、次に打つ1コマンド**（`refresh_derived.py`）を置き、
  コピーできるようにした。行ごとにバッチ名を散らさない——古い理由がどれでも打つのは同じ
  1コマンドのため（担当バッチは開いた先に残してある）。
- `generations`と`completeness`を同じ見た目の1行へ揃えた（`rowsFromReport`が両方を
  `FreshnessRow`へ写す）。数字は`<details>`の中。
- **表をやめた。** 列を横に並べると、モバイルでは横スクロールの中へ数字が隠れ「比較対象」の
  列だけが見える状態になっていた（ユーザーのスクリーンショットがその状態）。
- 描画を`FreshnessReportView`として取得と分けた。認証の要る画面を通さずに見え方を確かめ
  られるようにするため。

## 検証

**390px幅（モバイル）で実際に描画して確かめた。** `/admin`はBasic認証のため、実描画のHTMLを
テストから取り出し、実CSS（CSS変数・パネル固有）を当てて撮影する形で確認した。

- 横スクロールなし（`scrollWidth 390 === clientWidth 390`）。畳んだ状態・全て開いた状態の
  どちらでも、8件すべてが幅に収まる。
- 上部の「コピー」だけが折り返して枠が崩れていたのを、状態とコマンド行を分けて直した
  （撮り直して確認）。
- テスト: frontend 1312件緑、`tsc --noEmit`・`eslint`とも新規の指摘なし。

**devサーバーでの確認はできなかった。** `preview_start`が起動する`next dev`は、worktreeを
カレントにしても**本体のチェックアウト**を参照する（worktreeに置いたページが404になり、
本体に置いたプローブが200を返すことで確認）。worktreeで作業する限りこの経路は使えない。
