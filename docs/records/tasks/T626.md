# T626. GPX出力機能の実装 規模S

状態: 完了（2026-09-06）

## 背景

ユーザー要望「GPX出力機能は追加できる？」。「ルート結果」ヘッダの「GPX出力」ボタンは
T597（分割元T590）で「保存・GPX出力は実装までグレー（disabled）で位置だけ見せる」
「機能自体は別途起票する」という前提で占位のまま置かれていた。

Garmin・Suuntoへの取り込みを想定し、事前に互換性を調査した:
- Suuntoアプリは`<trk>`（トラック）以外（`<rte>`・単独の`<wpt>`）を取り込めない。
  Garminは`<rte>`を「コース」としてのみ、`<trk>`は「コース」「アクティビティ」両方に
  取り込める。→ `<trk>`固定にする。
- Suuntoは1000点を超えるGPXの取り込みで問題が起きることがある。RideCompassの
  ルートは最大100kmまで生成でき、OSM道なり形状の頂点は密になりうるため、間引きが
  実用上必要と判断した。
- Garminの「ClimbPro」（登坂検知）は標高データが入ったコースが要るが、
  `RouteCandidate`は点ごとの標高を持たない（候補全体の集約値のみ）ため、v1では
  標高・時刻タグを含めない素のトラックとする（既知の制限として許容）。

## 対応内容

新規ファイル`frontend/src/lib/gpxExport.ts`:
- `decimateCoordinates(coordinates, maxPoints = MAX_GPX_TRACK_POINTS)`: 座標列を
  先頭・末尾を残したまま等間隔に間引く純関数。`MAX_GPX_TRACK_POINTS = 1000`
  （Suuntoの実用上限に合わせる）。
- `buildGpxDocument(candidate)`: `candidate.geometry`（区間分割前の連続した
  LineString、`RouteCandidate`の必須フィールド）を`decimateCoordinates`してから
  `<trk><trkseg><trkpt>`形式のGPX 1.1 XML文字列を組み立てる純関数。`<name>`に
  `direction_label`・`distance_km`を使う。
- `downloadGpx(candidate)`: Blob + Object URL経由でブラウザダウンロードを発火する
  （リポジトリ初のクライアントサイドファイルダウンロード）。

`page.tsx`: 「GPX出力」ボタンの`disabled`を外し、`onClick`で
`downloadGpx(selectedCandidate)`を呼ぶ。`selectedCandidate`がnullの間（候補未選択）は
disabledのまま。「保存」ボタンは対象外（別タスク、disabledのまま残す）。

## テスト

- `gpxExport.test.ts`（新規）: 間引きの境界値（上限以下でそのまま・上限超過で
  先頭末尾を保ったまま間引く）、GPX出力が`<trk>`のみで`<rte>`/`<wpt>`を含まないこと
  （Suunto互換性の直接検証）、GeoJSONの`[lon, lat]`順からGPXの`lat`/`lon`属性への
  入れ替え、`downloadGpx`のBlob/Object URL/後始末（`revokeObjectURL`）。
- `page.test.tsx`: 「GPX出力」ボタンが選択中候補を`downloadGpx`へ渡すことを検証する
  テストを追加（`@/lib/gpxExport`をモック）。
