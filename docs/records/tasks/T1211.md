# T1211. 暑さ指数の「取れなかった（None）」と「提供されていない（空）」を分け、提供期間を日付で判定する

状態: 未完了（2026-09-27起票）

## 背景

周期レビュー第14回（2026-09-27）の起票案（ダッシュボード proposal-wbgt-empty-vs-failed、承認済み）。

規模S（根拠: wbgt_service.py・domain/wbgt.py とテスト、3〜4ファイル）

■ 背景
性質: 失敗と空の混同（再発: 第13回 T1141、今回は向きが逆で空が失敗扱い）。T1144 段階Dで wbgt_service.py:57 の `if not forecasts: return None` が 502 へつながった。fetch_forecast は None（失敗）と []（値なし）を返し分けるのに、`if not` が同じ分岐へ畳む。提供期間の判定（domain/wbgt.py:40-46）は月単位で、実際は例年4月第4水曜〜10月第3水曜。4月上旬〜下旬・10月中旬〜下旬に配信元が値を返さないと画面上部に「暑さ指数: 取得できませんでした」が出る。配信元が期間外に [] を返すか HTTP のエラーを返すかは未計測。

■ やること
1. `is None` で失敗、[] で空の段に分ける。
2. 提供期間を日付（第4水曜・第3水曜）で判定するか、配信元の応答の実態を確かめて決める。
3. 規則: 母集団は services で `X | None` を返す取得の直後の `if not x:`（今は4件、意味が分かれるのはこの1件）。規約（logging.md の外部 API 節）に「取得の直後は is None で分ける」を1行足すかを決める。
