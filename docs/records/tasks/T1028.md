# T1028. 台帳の未完了タスクのうち、前提そのものが消えているものを棚卸しする

状態: 未完了

## 背景

周期レビュー第12回で、台帳のトリガー付き`- [ ]`を全件再評価したところ、**タスクが
指している対象がリポジトリに存在しないもの**が複数見つかった。`/task:next`は
トリガー付きを既定で除外するため、周期レビューで見なければ誰も見ない。放置すると、
実行できない計画が候補に並び続ける。

読んで確かめたもの（各綴りを個別にgrepして確認済み）:

| タスク | 判定 | 根拠 |
|---|---|---|
| T479 クールダウン付きトリガーの共通化 | 前提が消えた | 対象の2箇所が`backend/app`に0件。T970段階Cの遅延構築撤去で消滅 |
| T480 動的材料のクリックガード汎用化 | 別タスクで解決済み | 名指しのレイヤーIDが0件。クリック対象はscene宣言から導出する汎用形になった（T1001段階A） |
| T714 precompute系バッチの長時間トランザクション観測 | 前提が消えた | 根拠にしている共通ヘルパが0件。precompute系バッチ自体が無い |
| T287 `road_nodes`/`road_edges`のtext型PKの再評価 | 前提が消えた | `road_nodes`表が無く、`road_edges`のPKはtextでない |
| T629 ボタン系CSSの共有化 | トリガーが永久に発火しない | トリガーが名指しするパネルの綴りがfrontendに0件 |
| T953 汎用フック2本の切り出し | **発火** | 条件のT945は完了済みで、対象ファイルは現在1,100行超 |
| T826 経緯コメントの一掃（2ファイル） | **発火** | 「実装目的で次に編集するとき」に対し、本範囲で複数のコミットが両ファイルを編集した |
| T958 評価が要求する形で読める区間テーブル | 半分成立 | 条件のT956は完了。**冷パスの再測定が未実施**で、誰が測るのかが台帳から読めない |
| T994 地図へ状態を当てる経路の一本化 | 背景が変わった | 背景の「2本の経路」がT1001段階Aで1本へ畳まれている。規模Lのまま残すと、既に無い前提の計画が候補に並ぶ |

## 対応方針

1. 前提が消えた4件（T479・T480・T714・T287）は`状態: 完了`としてクローズし、**本文に
   「何が消えたか」を1〜2行で残す**。理由を残さないと、次に同じ着想が起票される。
2. T629はトリガーの書き換え（名指しの部品が無いので、現行の部品名か別の条件へ）。
3. T953・T826は発火済みとして`/task:next`の候補に上げられる状態にする。
4. T958は「誰が冷パスを測るのか」を決める。測る担当が決まらないタスクは、条件が
   永久に判定されない。
5. T994は背景を現行に照らして測り直し、**残っている差分だけを残す**。全部解消して
   いれば`状態: 完了`。

## 完了条件

- 台帳のトリガー付き`- [ ]`**全件**について、「発火」「未発火（根拠1行）」
  「別タスクで解決済み」「前提が変わった」のいずれかに分類されている。
- **未発火には根拠が残っている**（これが無いと次回も同じ再評価コストを払う）。
- クローズしたものは`状態: 完了`かつ台帳から行が消えている
  （`python scripts/review_checks.py docs`が違反0件）。
- `[x]`化はしない——現行運用は「行を消す」。CLAUDE.mdの`[x]`化前提の記述は
  [T1022](T1022.md)が直す。

## 対象の導出

上の表は第12回時点のもので、**実行時には再導出する**。導出方法:
`docs/improvement-plan.md`の`- [ ]`行のうち「トリガー:」を含むものを全件挙げ、
各タスクについて順に ①条件は成立したか（数えられるものはその場で数える）、
②**その問題は別のタスクで既に解決されていないか**（最も見落とされる）、
③タスクの前提（名指ししている関数・ファイル・テーブル）はまだ存在するか、を見る。
③は綴りをgrepして0件かで機械的に判定できる。
