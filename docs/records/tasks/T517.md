# T517: 「開発者」タブからバックエンドの直近ログを見られるようにする

状態: 完了（2026-09-01）

## 背景

`GET /api/admin/debug/logs`（T379）はHTTP Basic認証必須のAPIとして既に存在するが、
フロントエンドに一切配線されておらず、確認するたびに毎回curl等で認証情報を渡して
手動で叩く必要があった（ユーザー指摘「バックエンドのログを見るのに、サーバに毎回
入らないとだめなのはキツい」）。

`/admin`（軸スタジオ・研究/開発者ツール）はブラウザの標準Basic認証で既に保護されており、
軸CRUD管理API（`axis-definitions`）は`adminApiProxy.ts`経由でこのブラウザセッションを
再利用し、二重ログイン無しでbackendのadmin APIを叩けている。同じ仕組みをログ取得にも
使う。

追加で、ユーザーから2点の要望を受けた:
- 「デバッグレベルだけでいい？　エラーだけとかログレベルによる汎化もできない？」
  → `contains`（部分一致）とは別の軸として、ログレベル（DEBUG/INFO/WARNING/ERROR/
  CRITICAL）で「このレベル以上」に絞り込めるようにする。
- 「フロントのログ画面と統一して、色で区別でもOK」
  → フロント側のDebugConsole（`lib/debugLog.ts`のinfo/warn/errorレベル）と同じ配色
  （エラー=赤、警告=黄）で行を色分けする。

## 対応方針

- `lib/adminApiProxy.ts`: `proxyToAxisAdmin`を軸CRUD専用ではない汎用名
  （`proxyToBackendAdmin`）へ改名し、クエリ文字列（`limit`/`contains`/`min_level`）も
  転送するよう拡張する（呼び出し元4箇所を追従）。
- `infrastructure/debug_control.py`: リングバッファが整形済み文字列だけでなく
  `record.levelno`も保持するようにし、`get_recent_logs`へ`min_level`（数値、
  「このレベル以上」）フィルタを追加する。
- `api/routers/debug_admin.py`: `GET /logs`へ`min_level`クエリ（`Literal["DEBUG",
  "INFO", "WARNING", "ERROR", "CRITICAL"]`、未知の値は422）を追加。
- `app/admin/api/debug/logs/route.ts`（新設）: `proxyToBackendAdmin`経由で
  `GET /api/admin/debug/logs`を中継する。
- `services/debugAdminApi.ts`（新設）: `/admin/api/debug/logs`を叩くクライアント
  （`limit`/`contains`/`minLevel`）。backendのレスポンス（`list[str]`、Pydanticモデル
  無し）はOpenAPI生成型を経由せず`string[]`を直接使う（`axisAdminApi.ts`と同じ判断）。
- `components/BackendLogsPanel/BackendLogsPanel.tsx`（新設）: 「開発者」タブへ追加する
  パネル。最小レベルのプルダウン（既定WARNING以上）・`contains`絞り込み・件数指定・
  取得ボタン。各行は整形済み文字列から`[LEVELNAME]`を正規表現で取り出し、
  DebugConsole.module.cssと同じ配色（エラー=赤`#f87171`、警告=黄`#fbbf24`）でハイライトする。

## 既知の制約

`backend/scripts/export_openapi.py`はDB接続が必要で、このセッションのサンドボックスには
PostgreSQLが無く実行できなかった。`debug_admin.py`のクエリパラメータ変更（`min_level`
追加）は`frontend/src/types/generated/openapi.json`のスキーマにも影響するはずだが、
今回のフロント実装は`axisAdminApi.ts`と同じく生成型を経由しない手書きの型
（`debugAdminApi.ts`）を使っているため、生成物が古いままでも型エラー・実行時エラーは
起きない。ただし`git diff --exit-code -- frontend/src/types/generated/`のクリーン確認
（コミット時の同期ルール）はこの理由により未実施——DBが使える環境で
`export_openapi.py`→`npm run generate:api`を実行し、想定通り軽微な差分（`min_level`
パラメータの追加のみ）であることを確認することが望ましい。
