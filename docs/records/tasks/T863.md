# T863. ベンチマークの起動は明示的にし、測ったコミットを記録する

状態: 完了（2026-09-15）
規模: S

## 背景

[T793](T793.md)は「ベンチマークを押しただけで本番のビルドとコンテナ入れ替えが走る」無駄を、
ワークフローの中で振り分ける形（`paths`は`backend/**`のまま、イメージに入る変更が無ければ
ビルドをしない）で解いた。ユーザーの意図は別の形——**押しただけで起動しない**ようにし、
VMの作業コピーを新しくしたいときは明示的に起動すればよい、というもの。

明示起動にするとワークフローの振り分けを丸ごと削れるが、穴が1つある:
`backend/benchmarks/run_all.py`は**どのコミットを測っているかを記録も検査もしない**。
起動を忘れたときに出るのはエラーではなく、古いコードのもっともらしい数字で、その数字は
後からタスクエントリへ「本番実測」として引用される。

## 方針

1. `run_all.py`が実行時の作業コピーのHEADを測定結果へ添え、`origin/master`と乖離していたら
   止める（測る前に気づける）。
2. `deploy-backend.yml`の`paths`から`backend/benchmarks/**`を外し、中の振り分けを削る。
   VMの作業コピーを更新したいときは`workflow_dispatch`で明示的に起動する。

## 実装

- `backend/benchmarks/_revision.py`（新規）: 作業コピーのHEAD・未コミットの有無を1行で出し、
  配信元（`git ls-remote origin refs/heads/master`）と違うコミットなら止める。`run_all.py`が
  計測の前に呼ぶ。配信元を引けないとき（ネットワーク断・gitが無い）は止めない——測れるのに
  測らせない害の方が大きく、素性は出力へ残るため。意図した計測は
  `BENCH_SKIP_REVISION_CHECK=1`で通す（そのときも警告を出す）。
  **手元で`origin/master`と比べない**のは、手元の`origin/master`はfetchするまで動かず、
  古いまま測っていることを検出できないため。
- `deploy-backend.yml`: `paths`へ`"!backend/benchmarks/**"`を足し、スクリプト内の
  振り分け（`NEEDS_REBUILD`・`git diff`の除外リスト）と`--depth 50`を撤去した。

## 検証

- `pytest tests/test_benchmark_revision.py`（新規5件）。素性の1行・未コミットの表示・
  乖離時に両方のコミットを名指しすること・配信元を引けないときは止めないことを見る。
- ワークフローは`yaml.safe_load`で解釈を確認（`paths`が
  `['backend/**', '!backend/benchmarks/**', '.github/workflows/deploy-backend.yml']`）。
- 効いていること（2026-09-15、masterへの連続した2つのpushで観測）:

| push | 変更したもの | Deploy Backend to Oracle VM |
|---|---|---|
| `bdad045d` | `deploy-backend.yml`・`backend/benchmarks/`・`backend/tests/` | **起動（run 393、success）** |
| `e435e253` | `backend/benchmarks/`のみ | **起動せず**（CIとDocs Consistencyのみ） |

  前者は、振り分けを撤去した後の単純な形でも本番デプロイが成立することの確認も兼ねる。
