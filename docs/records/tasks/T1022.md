# T1022. 周期レビュー第12回で判明した「機械が見ている」という嘘を一掃する

状態: 完了

## 背景

T986の棚卸しで検知器を32本から3本へ減らしたとき、**その検知器を根拠にしていた文書を
直さなかった**。結果として、正本が「機械が見ているから人は見なくてよい」と保証している
検査が実在しない状態が複数ある。

読んで確かめたもの:

- **CLAUDE.md「コミット時の同期ルール」節**は「`scripts/review_checks.py docs`が機械的に
  ブロックする。push直前（`.githooks/pre-push`）とCI（`docs-consistency.yml`）が自動実行する」
  と書く。`.githooks/`内に`review_checks`の参照は0件で、
  `git log -S "review_checks" -- .githooks/pre-push`が**空**——消えたのではなく一度も
  入っていない。実際に走るのは`docs-consistency.yml`だけで、そのトリガは
  `push: branches: [master]`と`pull_request`。**作業ブランチへのpushでは何も発火しない。**
- 同じ文が検知内容として挙げる「記載漏れ・経緯記述・写経」はT986で撤去済み。現行の
  `cmd_docs`が持つのは`dead_doc_links`・`plan_entries`・`task_state`の3本。
- **`docs/architecture/directory-layout.md`**は、対象ファイル表について
  「`scripts/review_checks.py`が『実装ファイルがどこにも載っていない』状態を機械的に
  検出するため、ファイルが増えても静かに古くならない」と書く。**その検知器は無い。**
- **`.claude/commands/review.md`**は見送り判断を「`状態: 見送り`のタスクとして起票する」と
  指示するが、`review_checks.py`の`STATE_RE`は`完了|未完了`しか受け付けない。この綴りを
  持つ記録は0件で、**一度も実行できていない**。
- **CLAUDE.md「検査器にできず、人が見るしかないのは次の3つだけ」節**は「タスクを`[x]`化
  するとき…検知器が`[x]`化の瞬間に候補を参考出力する」と書くが、`docs/improvement-plan.md`の
  `- [x]`は0件で、現行運用は「行を消す」。参考出力する検知器も無い。

**実害は既に出ている。** 上記の保証を根拠に置かれた一覧が、誰にも見られないまま古くなった
（周期レビュー第12回で、docs/modulesの対象ファイル表が指す実在しない綴りと、どの表にも
載っていない実装ファイルの両方が実測で見つかった。件数はここへ書かない——直す頃には
変わっている）。

## 対応方針

**順序が重要**: 先に「門をどうするか」を決め、決めてから文を直す。文だけ実態へ寄せると、
検査が無い状態を追認して終わる。

1. **門の方針を決める**（このタスクで判断が要る唯一の点）。選択肢は
   (a) `.githooks/pre-push`から`review_checks.py docs`を実際に呼ぶ、
   (b) 呼ばないと決めてCLAUDE.mdの記述を実態へ直す、の2つ。
   (a)を採るなら、現在のpre-pushが「docs・markdownだけの変更では何も動かさない」で
   早期`exit 0`する分岐より**前**に置く必要がある（docs専用のpushこそ、この検査が要る）。
2. 決定に合わせて CLAUDE.md・`directory-layout.md`・`.claude/commands/review.md` の
   記述を、その時点の`scripts/review_checks.py`の実装と一致させる。
3. 見送りタスクの表記を明文化する。第12回では`状態: 完了`＋台帳に載せない形を採り、
   `python scripts/review_checks.py docs`が違反0件になることを確認済み。この形を
   `review.md`へ書く（または`STATE_RE`側を変える）。
4. 一覧のずれを解消する。

## 実施（2026-09-23）

### 1. 門の方針: (a) pre-pushから`review_checks.py docs`を呼ぶ

新しい検知器ではなく、既にある3本（CLAUDE.mdの基準を満たすとして残したもの）を呼ぶ場所を
足すだけなので、「検知器を足す条件」の対象外と判断した。docs専用の早期`exit 0`より**前**に
置いた——台帳・タスク記録の変更はdocsだけのpushで入るのが普通で、そこが一番要る。
所要は開発機で約9秒（`Measure-Command`で9.7秒・8.6秒）。

全件を見るため、masterに既に入った違反でも止まる。masterへのpushは同じ門とCIの両方を
通るので、止まったなら直前に入った違反で、CIも赤になっている——`check_master_ci.py`
（原因が自分とは限らないので止めない）とは扱いを分けた。

**門が実際に効くかは設定次第**（ユーザー確認事項）: 本体の`core.hooksPath`は
`C:\...\RideCompass\.githooks`という**絶対パス**で、pre-push自身のコメントが避けるよう
書いている形になっている。全worktreeが本体チェックアウトの作業ツリーにあるフックを
実行するため、この変更は本体チェックアウトがこのコミット以降を持つまで効かない。
設定の変更は恒久設定のため行っていない。

### 2. 文書の修正（その時点の`scripts/review_checks.py`と一致させた）

- CLAUDE.md「完了扱いにする前に検査器を通す」: 検知内容の例示（撤去済みの記載漏れ・
  経緯記述・写経）を落とし、正本は`review_checks.py`とだけ書く。pre-pushはdocsだけの
  pushでも走ること、CIはmasterへのpush・PRで走ることを書いた。
- CLAUDE.md「検知器を足す条件は厳しい」: 存在しない`--staged`・`--since`を落とした。
- CLAUDE.md「人が見るしかない」2: `[x]`化の記述を「閉じる（`状態: 完了`＋台帳の行を
  消す）」へ。存在しない参考出力の文を落とした。冒頭の「完了したらチェックを更新」も同様。
- CLAUDE.md階層表・`review.md`の禁止事項とAPI契約の項: 「検知器にする」を勧める文へ、
  足す条件（「検知器を足す条件は厳しい」節）への参照を付けた。`review.md`の禁止事項は
  CLAUDE.mdの「思いつきは起票して人が見る」と逆のことを言っていたので揃えた。
- `review.md`「機械的に出せるもの（規模・コピペ・docsの整合）」: コピペ検出は無いので落とした。
- `directory-layout.md`: 存在しない検知器の記述を、「機械では検査していない。足した人が
  同じコミットで載せ、漏れは周期レビューで人が見る」へ。

### 3. 見送りの表記

`STATE_RE`は変えず、第12回で使った形を`review.md`へ書いた: `状態: 完了`＋
`## 判断: 見送り`見出し＋台帳に行を置かない。`STATE_RE`の2語は「片付いたかどうか」
だけを管理する設計（`find_task_state_problems`のdocstring）で、見送りは片付いた判断。
過去の見送りを引く手段として`grep -l "^## 判断: 見送り" docs/records/tasks/*.md`を
書いた（現時点で該当5件、T1036〜T1040）。
