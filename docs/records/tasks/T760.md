# T760. ルート結果パネルの表記品質（単位の二重表示・意味の無い合計・はみ出し・説明の矛盾）

規模S〜M。
状態: 完了（2026-09-14。2026-09-12起票）

## 背景

本番の結果パネルで観測した表記の崩れ:

- **単位の二重表示**: 「制限速度(km/h) 35km/h」「踏切の密度(回/km) 0回/km・信号の密度(回/km) 1.2回/km」。材料ラベルが単位を含み、`axisRawValue.ts: formatMaterialBreakdown`が単位を足す
- **意味の無い合計**: 「蛇行 151度/km・約3322度」。`formatAxisRawValue`が「/km」で終わる単位に一律で距離を掛けるが、角度の総量は行動を変えない
- **はみ出し**: 生値行（`.axisRawValue`）が`white-space: nowrap`のため280px幅からはみ出し、「…制限速度(km/h) 35km/h」「…自転車道(track)を併設 0%」が右端で切れる
- **説明の矛盾**: 総合難易度の(i)「距離・軸重みを反映した絶対値」と、負荷の(i)「総合難易度は距離で割った平均のため」が矛盾して読める
- **読み方が分からない値**: 「舗装質 0」（0か欠損か）、「夜間 未使用 44」（評価に使っていない軸に値が出る）
- **占位ボタン**: 「保存（準備中）」のdisabledアイコンが常時見え、説明は`title`のみ
- **区間詳細**: 「0.5 km地点 到達予想 15:41」と寄与度バーだけで、どの道かを示す情報が無い（道路名は[T725](T725.md)で路面タイルへ焼き込み済み）

個票は[history/2026-09-12_ui.md](../../../.claude/commands/review/history/2026-09-12_ui.md)のF-11〜F-14・F-16。

## 対応と結果

起票後の棚卸し（下記）で残っていた4件を直した。

### 単位の二重表示 — 単位は`unit`が唯一の正、ラベルには入れない

**実測**: 単位を持つnumeric材料14件のうち、**10件がラベルにも単位を書いていた**
（「交差点密度(回/km)」「制限速度(km/h)」等）。`formatMaterialBreakdown`は
`ラベル + 値 + unit`で組み立てるため、この10件がそのまま「制限速度(km/h) 35km/h」になる。

`MaterialSpec.unit`は元から「frontendは単位を持たない（唯一の正）」と宣言している。
ラベル側の重複を落とし、**単位が要る画面は表示のときに添える**形へ揃えた
（軸スタジオの材料セレクトは`materialOptionText`で`ラベル（単位）`と組み立てる——
ラベルへ埋め戻すと、単位を別に足す画面でまた二重になる）。修正後は10件→0件。

### 意味の無い合計 — 「距離を掛けられるか」と「掛けた値が読めるか」を分ける

`totalUnitFor`が単位の綴り（「/km」で終わるか）だけで総量の可否を決めていたため、
蛇行が「151度/km・**約3322度**」になっていた。距離を掛けられること（度/km）と、掛けた値が
読み手の判断を変えること（回・件）は別の問い。

判断を材料側へ移した。`MaterialSpec.total_unit`（総量を出すときの単位。出す意味が無ければ
None）を新設し、`axis_display.raw_value_total_unit`が軸まで持ち上げ、軸カタログが
`raw_value_total_unit`として配る。フロントは単位の綴りを解釈しなくなった
（`totalUnitFor`は撤去）。

**`additive`では代用できない**: 蛇行は`additive=True`（足し合わせて意味を持つ）である。
「足せるか」と「総量が読めるか」が食い違う実例がこれ。

現時点で`total_unit`を持つのは`回/km`の材料（交差点密度・停止要因POIの各種別）だけで、
**本番の公開軸で総量が出るものは無い**（停止密度は重みが1でないため生値の単位自体が
定まらない）。つまりこの経路は今まで蛇行の1件にしか効いておらず、その1件が誤りだった。

### 2つの(i)の矛盾

- 総合難易度: 「**距離**・軸重みを反映した絶対値」
- 負荷: 「総合難易度は**距離で割った平均**のため」

実装は`distance_weighted_difficulty`＝距離加重平均で、負荷側が正しい。総合難易度の説明を
「区間ごとの難しさを距離で重みづけて平均した値。長く走っても難しさが同じなら増えない」へ
書き直し、負荷側を「総合難易度に距離を掛けた総量」から始まる形へ揃えた。

### 「保存（準備中）」の占位ボタン

押しても何もできない入口は残さない（`docs/design-principles.md`「UI仕様」）ため撤去した。
機能そのものの要否は[T854](T854.md)へ引き取った——黙って消すと、位置を先に確保した意図
（[T597](T597.md)）ごと落ちるため。

  含むもの 10件 → **0件**。
- **総量の判断が効いていること**: `raw_value_total_unit`を「単位が/kmで終わるか」で決める
  実装へ戻すと、`test_raw_value_total_unit_is_none_when_the_total_cannot_be_read`
  （蛇行）が落ちる。フロント側も

## 完了条件に対する差分

起票時の完了条件は「同じ8候補でスクリーンショットを示す」だったが、**単位の二重表示と
意味の無い合計は生成物と単体テストで機械的に確かめられる**（上記）ため、そちらで代えた。
右端の切れは棚卸しの時点で前提が変わっており（下記）、対象が残っていない。

## 起票時の調査項目（記録）

1. 単位をラベルと値のどちらに持つか。材料カタログ（backend）のラベルが単位を含む前提なら、フロントは足さない。逆ならbackendのラベルから外す。どちらか一方に決めて全材料を機械的に確認する（単位が二重になる材料の件数を実測してから直す）
2. 合計を出す単位を「回」「件」のような回数系に限定するか、軸カタログ側に「合計を出す」フラグを持たせるか（軸ごとの対応表をフロントに持たない方針）
3. 2段目の折り返し／省略記号。折り返すと行数が増えるため、走行中の情報量との兼ね合い
4. 総合難易度・負荷の説明を1文ずつ書き直し、互いに矛盾しないことを並べて確認する
5. 0と欠損の区別（backendが欠損時にキーを持たないため区別は可能）を表示へどう出すか
6. 保存ボタンは実装まで非表示にするか

## 起票時の完了条件（記録）

- 同じ8候補で、単位の二重表示・意味の無い合計・右端の切れが無いことをスクリーンショットで示す
- 2つの(i)の文言を並べて矛盾が無いこと
