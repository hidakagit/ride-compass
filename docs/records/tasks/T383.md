# T383. 常設天候ヘッダーで、天候の数値を警報バッジより優先して常時可視にする 規模S（2026-08-28完了）

状態: 完了

- 背景: ユーザー指摘（スクリーンショット付き）「上部バーで、固定部分がなるべく見切れないように
  表現工夫できない？バッジ部分以降はスクロールで消えるのは許容」。
- 原因: `.weatherHeader`（page.module.css）は横幅が足りないとき`overflow-x: auto`で
  横スクロールへ逃がす設計だったが、優先度が逆だった。警報バッジ・デバッグアイコンの
  グループ（`.headerActions`）だけに`position: sticky; right: 0`を付けて常時可視にし、
  天候の数値（WeatherPanel）側は既定の`flex-shrink: 1`のまま残り幅へ押し込まれ、
  入り切らない分はWeatherPanel自身の内部`overflow-x: auto`（`scrollbar-width: none`で
  視覚的な手がかりも無い）へ静かに逃げていた。風向・風速はルート評価の起点
  （`.weatherHeader`自身のtitle属性が示す本来の主目的）であり、警報バッジより
  優先して常に見えるべき情報だった。
- 対応:
  1. `page.tsx`: `<WeatherPanel>`を新設の`<div className={styles.weatherStats}>`で包む。
  2. `page.module.css`: `.weatherStats`を新設し`flex-shrink: 0`（常に自然幅を保つ）＋
     `position: sticky; left: 0`（横スクロールしても左端に固定）を付与。
  3. `.headerActions`からは`position: sticky; right: 0`を撤去し、`flex-shrink: 0`は維持
     （文字が潰れるのではなくグループごとスクロールで隠れる挙動にする）。
- 検証（2026-08-28）: frontend tsc/eslint/vitest（`page.test.tsx`8件）green。
  Playwrightでヘッダー幅を人為的に縮め、①`.weatherStats`が`position: sticky; left: 0px;
  flex-shrink: 0`、`.headerActions`が`position: static; flex-shrink: 0`であることを
  computed styleで確認、②`.headerActions`側にダミーの長い文字列を注入してオーバーフローを
  再現したところ、`.weatherStats`はスクロール位置0のままヘッダー可視領域内に完全に収まり、
  `.headerActions`は可視領域を超えて配置される（スクロールしないと見えない）ことを実測確認した。
