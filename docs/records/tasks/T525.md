# T525: 凡例UI（ポップオーバー・チェックボックス行）の共通化

状態: 完了（2026-09-03）

- 背景: T524（T518コードレビュー対応）のreuse角度で、以下2点の重複が指摘された。
  1. `RouteAxisProfile.tsx`の「地図の色分け」凡例ポップオーバー（`Popover.Root`＋
     `Checkbox`一覧）が、`RouteSettingsPanel.tsx`の「重み配分」凡例ポップオーバーと
     構造・クラス名までほぼ同一（違いは中身が%表示かチェックボックスかのみ）。
  2. `RouteAxisProfile.tsx`の凡例チェックボックス行が、`MapLayersPanel.tsx:
     renderLegendCheckboxes`（既存の汎用関数）の3実装目になっている
     （`WidthSwatch`対応等、MapLayersPanel側は道路幅表示という別要件も持つ）。
- 見送った理由: 両方とも視覚的な見た目に関わる共通化で、T524実施時点はT522/T523
  （ルート生成が3〜6分かかる・フロントのポーリングがタイムアウトする）によりBrowser
  ペインでの実機確認が非常に困難な状況が続いており、ピクセルレベルの差分を検証
  できないまま変更するリスクを避けた。
- 対応方針（見送り時点の見立て、着手時に再検討可）: (1)ポップオーバー外枠
  （trigger button＋Popover.Root/Content/Portal＋`legendInfoPopover`スタイル）を
  共通コンポーネント化し、中身（行レンダラー）だけ呼び出し側が渡す
  render-props/children形式にする。(2)チェックボックス行は`MapLayersPanel.tsx`の
  `renderLegendCheckboxes`を独立コンポーネントへ切り出し、`WidthSwatch`対応の
  有無をpropで切り替えられるようにしたうえで`RouteAxisProfile.tsx`からも使う。
- 着手前提: T522（ルート生成の遅延）が改善し、Browserペインで実機確認しながら
  進められる状態になっていることが望ましい。

## 実装（2026-09-03）

着手時点でT522由来の遅延はT536〜T546で解消済みだったため、着手前提は満たされていた。

- **ポップオーバー外枠**: `components/Map/InfoPopover.tsx`を新設。トリガー（アイコン
  ボタン、className/aria-labelを呼び出し側から受け取る）+`Popover.Root/Trigger/Portal/
  Content`（className/side/align/sideOffsetも呼び出し側から）を担い、中身はchildrenで
  渡す。以下4箇所を置き換えた（`legendInfoPopover`のcontent classはいずれも共通のため
  そのまま維持、side（"bottom"既定/"left"）のみ呼び出し側で使い分け）:
  1. `RouteAxisProfile.tsx: AxisChip`の軸説明ポップオーバー
  2. `RouteAxisProfile.tsx`の「凡例の表示設定」ポップオーバー
  3. `RouteSettingsPanel.tsx: renderLegendChip`の軸説明ポップオーバー
  4. `RouteSettingsPanel.tsx`の「重み配分」凡例ポップオーバー（中身は読み取り専用の
     %表示のまま、外枠だけ共通化）
- **凡例チェックボックス行**: `components/Map/LegendCheckboxList.tsx`を新設。
  `MapLayersPanel.tsx: renderLegendCheckboxes`（チェックボックス+スウォッチ/
  `WidthSwatch`+ラベル、`LegendEntry.isFallback`行への追加class）をそのまま移植し、
  `RouteAxisProfile.tsx`の「凡例の表示設定」ポップオーバー内の手書きチェックボックス
  一覧（`RouteStyleMode.legend`も同じ`LegendEntry`型だったため型変換不要だった）を
  置き換えた。リスト/行自体の見た目（サイドバーの2列グリッド vs ポップオーバー内の
  単列）は呼び出し側がclassNameで指定する形にし、当初の見立て（WidthSwatch対応の
  有無をpropで切り替え）は不要と判明した——既存の`renderLegendCheckboxes`が
  `entry.width !== undefined`で既に汎用的に分岐していたため、そのまま移植すれば
  両方の呼び出し元に対応できた。
- 対応の副次効果として、`RouteAxisProfile.tsx`の凡例行を`<li>`（クリック領域は
  チェックボックスのみ）から`MapLayersPanel`と同じ`<label>`ラップ（ボタン全体が
  labelable要素のため、行のどこをクリックしてもトグルされる）へ統一した——見た目の
  実装統一に伴う意図した副次効果であり、退行ではない。
- 新設ファイル2件を`docs/modules/frontend/static-map-layers.md`の対象ファイル表へ
  追記（`Map/LayerChip.tsx`と同じ「複数パネルで共用するMap/直下の共通部品は
  static-map-layers.mdで一元管理する」既存の置き場所規約に従った。`route-settings-
  and-results.md`側への重複記載はしていない）。

## 検証結果

`npx vitest run`（変更・新規ファイル対象分＋フルスイート）・`npx tsc --noEmit`・
`npx eslint`（対象ファイル）すべてgreen。新設2ファイルにそれぞれ`.test.tsx`を追加
（InfoPopoverの開閉・LegendCheckboxListのチェック状態/onToggle呼び出し/isFallback行
class/width有無によるWidthSwatch出し分け）。

Playwright（`/opt/pw-browsers/chromium`、backend未接続のためAPIエラー・地図タイル
読み込み失敗は出るが本タスクの変更とは無関係）で実機確認: (1)「重み配分の凡例を表示」
ポップオーバー（読み取り専用%表示、InfoPopoverのみ適用）、(2)軸の説明ポップオーバー
（「勾配」の説明「登り坂の急さが小さいほど易しい」）、(3)「路面の種類」の凡例
チェックボックス（色スウォッチ、6項目・「不明・他」の区切り表示を含む）、(4)「道路の
種類」の凡例チェックボックス（WidthSwatchの太さバー表示）——いずれも表示・チェック状態
とも正しく描画された。コンソールエラーはネットワーク系（backend未接続）のみで、
本変更由来のエラーは無し。
