## 変数カタログと表示要否の判定

凡例: 【表示】常時表示を推奨 /【バッジ】既存のWarningBadgeList方式（該当時のみ自動出現）を推奨 /
【詳細】タップで開く「今日の見通し」的な二次表示に推奨 /【不要】ロードバイク走行への価値が
低く追加しない

### A. 現在地点の瞬間値（`current`）

| 変数 | 内容 | 判定 | 根拠 |
|---|---|---|---|
| `temperature_2m` | 気温 | 【表示】(実装済み) | 走行判断の基礎情報 |
| `apparent_temperature` | 体感温度 | 【表示】(実装済み、tooltip) | 現状維持で十分 |
| `wind_speed_10m`/`wind_direction_10m` | 風速・風向 | 【表示】(実装済み) | ルート評価の起点、最重要項目の1つ |
| `wind_gusts_10m` | 突風 | 【表示】(実装済み、tooltip) | 現状維持で十分 |
| `precipitation` | 降水量(mm/h) | 【表示】(実装済み、tooltip) | 現状維持で十分 |
| `precipitation_probability`※1 | 降水確率 | 【表示】(実装済み) | 走行可否判断の主要項目 |
| `uv_index` | UV指数 | 【表示】(実装済みだが要再検討) | 下記「UV指数の再検討」参照 |
| `relative_humidity_2m` | 相対湿度 | 【不要】 | 熱中症リスクはWBGT（環境省の公式指針、既存のWarningBadge）が
  気温・湿度・輻射熱を合成した専用指標として既にカバー済み。湿度単体を並べても
  判断材料としての上乗せ価値が薄く、項目数だけ増える |
| `dew_point_2m` | 露点温度 | 【不要】 | 発汗の蒸散しやすさを測る専門的指標。一般的なロードバイク走行判断には
  体感温度で代替できており、露点を読み解くには気象の専門知識を要する |
| `pressure_msl`/`surface_pressure` | 気圧 | 【不要】 | 気圧の低下傾向は「天気が崩れる予兆」として気にする層もいるが、
  本アプリは走行**時点**の実況・直近予報を見せる設計（context.md「動的天候は走行時点の
  実予報を取得済み」）であり、傾向読み取りは別の関心事。参考記録程度の価値しかない |
| `cloud_cover`（total/low/mid/high） | 雲量 | 【不要】(単独では) | 下記「UV指数の再検討」の`weather_code`アイコン化に
  吸収される（`weather_code`自体が雲量・降水種別から算出される複合指標のため、雲量を
  別途数値で出すのは冗長） |
| `is_day` | 昼夜フラグ | 【不要】(単独では) | 単独表示価値は無いが、下記`weather_code`アイコンの
  昼/夜バリエーション切替に使う補助データとしてのみ利用する |
| `weather_code` | WMO天気コード（快晴/曇り/霧/雨/雪/雷雨等） | **【表示】新規推奨（優先度: 高）** | 下記詳述 |

※1 `precipitation_probability`は本来hourly専用変数（currentには無い）。既存実装もhourlyから
取得して現在時刻の値を表示している想定で、現状の分類を変えるものではない。

**UV指数の再検討（現状の「収まり方が不自然」問題とも関連）**: 今回のスクリーンショットで
「☀0.0」が警報バッジと詰まって見えた一因は、**夜間はuv_indexが常に0.0になり、数値としての
情報価値がゼロなのに項目自体は表示され続ける**ことにある。`weather_code`＋`is_day`から
「快晴/くもり/霧/雨/雪/雷雨」＋昼夜を判定した**天気アイコン1個**へ差し替える（またはUVは
昼間のみ表示に切替、夜間はアイコンが月/曇天等へ自動的に変わることで「情報がない」ことを
伝える）ことを提案する。これは表示価値の向上とヘッダーの省スペース化を同時に満たす
（数値1つ→アイコン1個で「ぱっと見の天気」が伝わり、UVが必要な人はtitle属性の補足へ回す）。

### B. 位置・季節限定の警戒情報（既にトリガー付きタスクとして起票済み、T206〜T209）

| 変数 | 内容 | 判定 | 根拠 |
|---|---|---|---|
| `snowfall`/`snow_depth` | 降雪量・積雪深 | **【バッジ】** | T206（実機取得確認済み）。関東平野では
  ほぼ一年中「該当なし」のため、常時表示の数値ではなく**該当時のみ自動出現するバッジ**が
  最適（後述「ユーザーが選べる方がいいか」への回答参照） |
| `freezing_level_height` | 凍結高度 | **【バッジ】** | T206に同じ。山間部ロングライドでの
  路面凍結危険の警戒に使う |
| `cape` | 対流有効位置エネルギー(雷ポテンシャル) | **【バッジ】** | T207（実機取得値2040 J/kg
  確認済み）。T204の雷ナウキャスト（実況〜60分）で足りない「60分より先」を補う延長予報用途、
  閾値設計が固まってから着手 |
| `visibility` | 視程 | **【バッジ】** | T208（実機取得値29,340m確認済み）。関東平野中心の
  現状ユーザー像では優先度は低いが、霧発生時のみ警告バッジとして出す設計であれば
  平常時のヘッダーを圧迫しない |
| PM2.5・黄砂(dust) | 大気質（別ドメインの大気質API） | **【バッジ】** | T209（調査完了・
  実装可能と判定済み、Open-Meteo大気質API採用推奨）。春季中心の黄砂・通年のPM2.5いずれも
  「該当閾値超過時のみ」バッジ化が既存のWBGT・河川氾濫バッジと同じ設計で自然 |

これらB群はいずれも「地域・季節限定」という共通の性質を持ち、既存の`WarningBadgeList`
（JMA警報・WBGT・河川氾濫予報が共有する「該当時のみ自動で出現し、非該当時は完全に
何も表示しない」コンポーネント）へ乗せることで、**ユーザーが個別にON/OFFを選ぶ設定
UIを作らなくても「場所によって見えたり見えなかったりする」を実現できる**（次項で詳述）。

### C. 日単位の見通し（`daily`、新規候補）

| 変数 | 内容 | 判定 | 根拠 |
|---|---|---|---|
| `sunset`（`sunrise`も参考） | 日没時刻 | **【詳細】新規推奨（優先度: 高）** | ロングライドの
  「帰りが暗くなる前に戻れるか」という走行計画に直結する、現状アプリに欠けている
  数少ない**能動的に走行計画へ使える**情報。地図の推定軸に既に「夜間」軸があることとも
  親和性が高い。ただし瞬間値ではなく1日1回の値のため、常設ヘッダーではなく
  ルート設定バー付近か「今日の見通し」的な二次表示に置くのが適切 |
| `precipitation_sum`/`precipitation_probability_max`/`precipitation_hours` | 今日の降水量・
  最大降水確率・降水が続く時間数 | **【詳細】** | 「今のところ降っていないが、今日はいつ
  降るか」という出発前の判断に有用。現在値（precipitation_probability、A群）と役割が異なる
  （今 vs 今日） |
| `wind_speed_10m_max`/`wind_gusts_10m_max` | 今日の最大風速・突風 | **【詳細】** | 長時間の
  ライドでは午後に風が強まる等の変化があり得るため、現在値だけでは見えない情報 |
| `temperature_2m_max`/`temperature_2m_min` | 今日の気温レンジ | **【詳細】** | 服装選びの
  判断材料。現在値と乖離しうる（早朝出発・気温上昇後帰着等） |
| `uv_index_max` | 今日のUV最大値 | **【詳細】** | 現在値（夜間は常に0）と異なり、
  日中いつがピークかの目安になる |
| `shortwave_radiation_sum` | 今日の日射量合計 | 【不要】 | UV最大値で概ね代替できる、
  専門的すぎて一般ユーザーには解釈しづらい |
| `evapotranspiration`/`et0_fao_evapotranspiration` | 蒸発散量 | 【不要】 | 農業向け指標、
  ロードバイク走行との関連が薄い |
| `soil_temperature_*`/`soil_moisture_*` | 地中温度・土壌水分 | 【不要】 | 道路走行に
  地中の状態は無関係 |
| 高度80m/120m/180mの風速・風向 | 上空の風 | 【不要】 | ロードバイクは地表付近
  （既存の10m基準で十分）を走行するため無関係 |
| `rain`/`showers`（`precipitation`の内訳） | 降水種別の内訳 | 【不要】 | 合計値
  （`precipitation`、実装済み）で走行判断には足りる。雪との区別はT206の`snowfall`が別途担う |
| `vapour_pressure_deficit` | 飽差 | 【不要】 | 農業・生理学向けの専門指標、一般利用者には
  解釈不能 |

## 「気候バーは表示するものをユーザーが選べる方がいいか」への回答

**個別トグルのUIを新設するより、既存の2つの表示形式へ性質ごとに振り分ける方が
このプロジェクトの設計と整合的**、という結論に至った。

1. **B群（雪・雷ポテンシャル・視程・大気質）**: 「場所・季節によって出たり出なかったり
   してほしい」という要望は、**ユーザーが手動でON/OFFを選ぶ設定より、条件に該当する
   ときだけ自動的に現れるバッジの方が正確に応える**（JMA警報・WBGT・河川氾濫予報が
   既にこの方式で、非該当地域・非該当シーズンは何も設定しなくても完全に無表示になる）。
   手動トグルだと「関東平野在住だから雪はOFFにしていたが、たまたま志賀高原まで
   遠征したら積雪注意報が出ていたのに見えない」という事故が起こりうる——バッジ方式は
   場所を問わず常時ON（表示ロジック自体が該当判定を内包）にしておいて安全側に倒せる。
2. **C群（日単位の見通し）**: 「常設ヘッダーに出すか出さないか」の二択ではなく、
   **常設ヘッダーには出さずタップで開く二次パネルに集約**すれば、個別のON/OFF設定は
   そもそも不要になる（地図オーバーレイの「▶で凡例を開く」と同じ、地図UIの既存方針
   `MapOverlayControls.module.css`冒頭コメント「絞り込みの編集…はすべてサイドバーで行う。
   地図上の▶はあくまで確認用」と同じ思想をヘッダーにも適用する）。
3. **A群（常時表示のコア項目、気温・風・降水確率・天気アイコン）**は、どの季節・
   どの地域でも常に意味を持つ情報のため、そもそも個別に隠す動機が薄い。

以上より、**新規の「表示項目を選ぶ設定」UIは追加せず**、(a) B群はWarningBadgeList方式で
実装、(b) C群はヘッダーとは別の二次パネル（新設が必要）へ集約、という既存パターンの
拡張で「場所限定の情報が常に出しゃばらない」を実現することを推奨する。
