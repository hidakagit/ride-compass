# T1165. 司令塔の登録（board claim）が、引用符を含むコマンドから呼ぶと黙って失敗し、定期確認が走らない

状態: 完了（2026-09-26起票、同日完了）

## 背景

2026-09-26の第3回で、司令塔が `cd "<本体のパス>" && git fetch ... && python scripts/orchestrate.py board claim; ...` の1行で登録したところ、coordinator_session は前の司令塔（09-25 22:55）のまま変わらず、next_check も04:55のままで、約1時間半、道具を使うたびの定期確認が一度も走らなかった（司令塔が気づいたのは18:35、単独の `python scripts/orchestrate.py board claim` で登録し直して直った）。原因は hook.sh の orch_string_value が JSON の値の中の `\"`（エスケープした引用符）を値の終わりとみなすため、tool_input.command が `cd \` で切れ、`board claim` の語に届かないこと。登録に失敗しても `board claim` は「記録する」と出力するだけで、失敗を知らせない。直す方向: 引用符を含むコマンドでも登録できる（エスケープを読み飛ばす等）、登録できたかを `board claim` 自身か直後の確認が確かめて、できていなければ失敗として出す。わざと引用符付きのコマンドで呼んで登録されること・登録されないときに失敗が出ることを確かめてから閉じる。第3回の改善（派生元 T1162）。

## 方針（どこで確かめるか）

公式（https://code.claude.com/docs/en/hooks）で次を確かめた:

- PostToolUseは「道具の呼び出しが成功した後」にだけ走る（失敗はPostToolUseFailureという別の出来事）。したがって
  `board claim`を含む1行のコマンドが0以外で終わると、エスケープの読み違いとは別に、直後のフックがそもそも走らない。
- 道具の側へセッションの識別子を渡す環境変数は公式に無い（入力のJSONの`session_id`だけ）。`board claim`自身は
  自分のセッションを知れないので、自分で登録も確認もできない。手元の道具の環境には`CLAUDE_CODE_SESSION_ID`が
  見えたが、公式に書かれていないので頼らない。

このため、確かめる役は「`board claim`の後に来るフック」に置いた:

- `board claim`は頼み（`<gitの共通ディレクトリ>/orchestration/claim_pending`）を置いて終わる。
- hook.shは`claim_pending`の有無をシェルの組み込み（`[ -f ]`）だけで見て、あればpython（`check --if-due`）を起こす。
  コマンドの文字列はhook.shで読まず、pythonが入力をJSONとして読んで判定する——エスケープの読み違いの元（hook.shでの
  コマンドの切り出し）ごと消した。
- pythonは、この呼び出しが`board claim`（Bash・PowerShellで`orchestrate.py board claim`を含む）なら`coordinator_session`を
  書いてから頼みを消し「記録した」と知らせる。違えば（claimの呼び出しのフックが走らなかった・書けずに落ちた・
  サブエージェントの中で呼んだ）頼みを消して「記録されていない（coordinator_sessionは◯◯のまま）。単独のコマンドで
  実行し直す」と知らせる。
- 残る穴: 頼みが残った直後に次に道具を使ったのが司令塔でない別のセッション（サブエージェントは除く）なら、知らせは
  そちらへ出る。claimの呼び出しの後は司令塔がすぐ次の道具を使うので実際に起きる幅は小さく、司令塔の側も「記録した」が
  出なかったことで気づける（規約にそう書いた）。

`board.json`・`coordinator_session`の形は変えていない。本体のhook.shが古いまま（早送り前）でも、origin/masterの版の
`check --if-due`は頼みの有無に関わらず`board claim`の呼び出しを記録するので、引用符の無い単独の`board claim`は
これまでどおり登録できる。

## 実施内容

- `scripts/orchestration/hook.sh`: コマンドの切り出し（`tool_name`・`command`を`orch_string_value`で読む分岐）を消し、
  `claim_pending`があれば起こす1行に置き換えた。`orch_string_value`はエスケープを含まない`session_id`にだけ使う。
- `scripts/orchestration/core.py`: `board claim`が`claim_pending`を置く。`check_if_due`が上の記録・知らせを持つ。
  頼みを見て起こされたが先に別の呼び出しが消していたとき（司令塔でないセッション）は確認を走らせない。
- `docs/conventions/orchestration.md`「管理のループ」、`.claude/commands/orchestrate.md`: 「記録した」が出なければ
  登録されていないこと、そのときの知らせと実行し直し方。
