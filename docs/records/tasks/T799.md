# T799. 評価基準の較正（物理を写した軸の重み・主観のレート・路面）

規模M。
状態: 完了（2026-09-13。本番DB・開発DB・スナップショットへ反映済み。暫定値を管理画面から
変えられるようにする話は[T805](T805.md)へ切り出した）

## 背景

T790で探索のコストを「所要時間 × (1 + P × difficulty/100)」＝体感の所要時間にした。
風・勾配・停止は走行モデル（物理）へ入り、軸には「遅くなる以上に避けたい」という主観だけが
残る設計になった。**構造は入ったが、値がその設計に合っていない。**

## 直すべきこと

### 1. 物理を写した軸の既定重みが走行モデルと二重に効く

本番スナップショットの既定重みは風0.26・停止密度0.20・勾配0.15・舗装0.19で、**配分の8割が
走行モデルと同じ現象を見ている**。設計上は「実際に遅くなる（走行モデル）」と「遅くなる以上に
避けたい（軸）」の別物だが、既定値が0でない限り利用者は一度の意図で二重に払う。

停止密度はずれの大きさも分かっている。[T787](T787.md)が測った現行の実効値は停止1回＝
200〜400m相当の迂回で、走行モデル側の信号21秒は20km/h巡航で約117m相当——**軸側が1.7〜3.4倍**。

既定重みの変更は`axis_definitions`のDB行データ操作（軸スタジオAPI＋本番反映）のため、
コードの変更とは切り離してある。

### 2. 主観と時間の換算レート（`penalty_strength`）の既定値

P=1は「difficulty 100の道は体感で所要時間2倍」の意味になった。距離ベースだった頃の1.0を
そのまま引き継いでいるだけで、時間ベースでの妥当性は確かめていない。
フロントは`penaltyStrength: 1.0`をベタ書きで送っている。

### 3. 路面が走行モデルへ繋がっていない

`domain/cycling_speed.py: speed_ms`は`crr`（転がり抵抗）を区間ごとに受け取れるが、呼び出し側が
渡していない。未舗装で実際に遅くなることが所要時間に出ない。繋ぐには路面区分ごとのCrrを
決める必要があり、値決めと一体のためここで判断する。

### 4. 停止密度の軸を残すか

待ち時間は走行モデルへ移った。軸として残すなら「待ち時間以上に止まりたくない」の意味になる。
残す・廃止するをここで決める。

## 進め方

値は実際に生成された候補を見て決める（主観のため実測はできない）。実走での確認も要る。
DB行データの変更は[docs/conventions/deployment-sync.md](../../conventions/deployment-sync.md)の完了条件に従う。

## 実施内容（2026-09-13）

### 1. 路面を走行モデルへ繋いだ

`domain/cycling_speed.py`へ`UNPAVED_CRR`（0.015＝舗装路の3倍、砂利・締固めの一般的な
値域0.012〜0.020の中ほど）と`crr_for_surface`を足し、`_travel_time_seconds`が路面ごとの
転がり抵抗を渡すようにした。平地・無風で巡航20km/hの人が未舗装では**13.7km/h**になる。

路面タグが無い区間は舗装路として扱う——「タグが無い」を「路面が悪い」と読み替えないための
既定（`surface_good`が`bool_default="nan"`を持つのはこの区別のためだけ）。

材料は`route_facing_material_ids`が軸の構成と無関係に常に運ぶ（停止の材料と同じ扱い、
[T790](T790.md)で直した欠陥と同じ型を作らないため）。

### 2. 物理を写した軸の既定重みを0にした

風0.26・停止密度0.20・勾配0.15・舗装0.19 → **すべて0**。本番はaxis_admin API経由
（unpublish→PUT→republish）、開発DBは本番から取り直したスナップショットで置き換え。
`axis_registry_meta`のrevisionは64→72。

### 3. 主観と時間の換算レートを0.7にした

重みを0にすると、残った主観軸だけで難易度が再正規化され**値が1.5〜1.8倍**になる。難易度は
`penalty_strength`を通じて時間と釣り合うため、1.0のままだと主観が効きすぎる。本番実測:

| | 周回30kmの先頭候補 | 目的地の先頭候補 |
|---|---|---|
| 変更前（物理の軸あり・P=1.0） | 29.4km 102分 難23 | 29.5km 126分 難36 |
| 物理=0・P=1.0 | 31.9km **125分** 難35 | 29.5km 126分 難66 |
| **物理=0・P=0.7（採用）** | 30.1km **105分** 難43 | 29.5km 126分 難66 |
| 物理=0・P=0.5 | 30.1km 105分 難43 | 29.5km 126分 難66 |

既定値の正本は`domain/evaluation.py: DEFAULT_PENALTY_STRENGTH`。frontendは値をベタ書き
せず生成物（`route-generate-config.json`）から読む——openapi-typescriptは既定値を持つ項目も
必須として出すため「送らない」選択ができず、手書きするとbackend側で調整しても効かない。

### 4. 総合難易度の表示値

**そのまま出す**（ユーザー判断）。値の意味が「純粋に主観的な不快さ」へ変わったことの帰結で、
経路が悪化したわけではない。既存利用者が過去の値と比べると悪化して見える。

### 停止密度の軸を残すか

**残す**。待ち時間は走行モデルへ移ったが、軸としては「待つ以上に止まりたくない」を表せる。
既定重みは0のため、上げたい利用者だけが上げる形になった。
