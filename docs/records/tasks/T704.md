# T704. 軸カタログ取得失敗を利用者に見せる（重み設定が無言で捨てられる） 規模S〜M

状態: 完了（2026-09-10起票、統合レビュー第6回 I-10／2026-09-10完了）

## 背景

`hooks/useAxisCatalog.ts:214-229` — 軸カタログの実行時フェッチは**マウント時1回きり**で、
失敗しても再試行せず`loaded=false`のまま固定される（`catch`が共有ストアを書き換えない）。
`CATALOG_API_TIMEOUT_MS=10000`（`lib/apiTimeouts.ts:17`）に対しbackendのコールドスタートが
10秒を超えるとrejectする。

その状態でも`RouteSettingsPanel`はフォールバック軸で通常どおり重みスライダーを描画し、
ユーザーは重みを編集できる。しかし生成時は`app/page.tsx:1356-1358`の
`weightOverrideEnabled && axisCatalog.loaded`が偽になり`route_preference`が省略され、
**backendの既定重みで探索される**。

**画面には失敗の表示も「既定値で生成しました」の表示も一切出ない。**
評価モデルの研究が主目的の現フェーズでは、実験結果を取り違える形で効く。

## 兄弟フィールドの非対称

すぐ隣の`lensAxisId`（`page.tsx:1347`）には同じガードが無く、存在しない軸idがそのまま送られる。
backend側は`services/road_graph_engine.py:1657`の`AXIS_DEFINITIONS.get(lens_axis_id)`が
Noneを返して**黙って無視する**（422にはならない）ため、レンズ用の風/勾配合成や
lens軸の材料先読みが効かず「選んだ軸で塗られない」状態になるが手掛かりが残らない。

`useAxisCatalog.ts:51-57`のdocstringは「軸スタジオの現在の公開軸集合と一致していることを
要求する処理では`loaded`で未確定状態を区別しなければならない」と明記しており、
実装がその契約を片側でしか満たしていない。

## 対応方針

カタログ取得失敗を利用者に見せる（重みパネルを無効化するか、明示的な再試行導線を出す）。
`lensAxisId`にも同じガードを掛ける。

## 実装メモ

### 1. 失敗を状態として持たせる（`hooks/useAxisCatalog.ts`）

`AxisCatalog`へ`failed`を追加した。3状態を区別する: 未取得=両方false／成功=`loaded`のみ／
失敗=`failed`のみ。`catch`は引き続き取得済みの正常なカタログを巻き戻さず、
**まだ一度も成功していない場合だけ**`failed`を立てる。

明示的な再試行導線として`retryAxisCatalogFetch()`をモジュールレベルにexportした
（成功済みなら何もしない。再取得中は`failed`を下ろすのでUIが「取得中」の見た目へ戻る）。
`useEffect`とこの関数が同じ`loadAxisCatalog()`を呼ぶ形にし、成功/失敗の扱いを1箇所へ寄せた。

### 2. 失敗を見せる（`RouteSettingsPanel.tsx`）

重み配分の上へ、何が起きるかを述べた1行と「再試行」ボタンを出す。重み編集自体は
止めない（編集を捨てさせない）。CSSは定義済みトークン`--color-warning` /
`--color-warning-strong`のみを使う（フォールバック付きの未定義トークン
`--color-warning-soft`が既存コードに複数あるが、これ以上増やさない。[T711](T711.md)の対象）。

### 3. 兄弟フィールドの非対称を解消（`app/page.tsx`）

`lensAxisId`へ`axisCatalog.loaded`ガードを追加。backendは存在しない軸idを422にせず
黙って無視するため、未確定のまま送ると「選んだ軸で塗られない」が手掛かり無しで起きる。

## 検証結果

3つのガードを一時的に戻すと、対応するテストが実際に落ちることを確認した（4件失敗）:

| 戻したもの | 落ちるテスト |
|---|---|
| `catch`内の`failed`公開 | `フェッチ失敗はfailed=trueとして表面化する` / `retryAxisCatalogFetch…` / `失敗を利用者へ見せ、再試行で通常表示へ戻る` |
| `lensAxisId`の`loaded`ガード | `軸カタログの取得に失敗した状態ではlens_axis_id/route_preferenceを送らない` |

`lens_axis_id`のテストは恒真にならないよう作った: ビルド時静的カタログに実在する軸idを
`localStorage`へ保存してからレンダーする（未知idだと`page.tsx`側のフォールバックで
総合難易度へ戻り、ガードの有無に関わらず`null`になる）。対になる正例
（`取得に成功していればlens_axis_idを送る`）も置いた。

フロントエンド全体: `tsc --noEmit`クリーン、`eslint src`クリーン、
`vitest run` 126 files / 1,156 tests passed。

## 見送った案

重み編集UIそのものの無効化（対応方針の選択肢）は採らなかった。編集を止めると、
一時的なコールドスタート失敗のたびに利用者の操作が奪われる一方、実際の害
（送信時に黙って省略される）は文言で正確に伝えられる。
