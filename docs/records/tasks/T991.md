# T991. 地図の説明文が「関東7都県」をベタ書きしている 規模S

状態: 完了

未着手（2026-09-21起票、[T977](T977.md)で収録年をDB由来にしたときに同じ形が範囲側にも
残ると分かった。起票時はT990を採ったが、並行セッションが同じ番号を先に使ったため振り直した）。

## 背景

事故レイヤーの説明文は収録年をDB（`source_runs.profile`の`rows.years`）から受け取るように
なったが、**範囲は`関東7都県`という文字列のまま**（`mapLayers.ts: buildMapLayers`の
`accidentCoverage`）。取り込む範囲はプロファイルのbboxが決めるので、範囲を変えた瞬間に
この一文が嘘になる——T977で年に起きたことと同じ形である。

年ほど簡単ではない。**bboxから都県名は機械的に導けない**（緯度経度と行政区画の対応表が
要る）。そのため次のどれを取るかを決める必要がある。

- 説明文から範囲の言葉を落とす（「取り込んだ範囲の発生地点を表示」）。地図はもともと
  データのある所にしか点を打たないため、範囲は見れば分かる。
- bboxをそのまま出す（利用者には読みにくい）。
- 都県名の対応表を持つ（正確だが、対応表の維持が増える）。

## やること

1. 上のどれにするかを決める（利用者が読んで役に立つかで選ぶ。`docs/architecture/
   design-principles.md`のUI原則に従う）。
2. 決めた形で`mapLayers.ts`から`関東7都県`を消す。
3. 同じ形のベタ書きが他の説明文にも無いかを、そのとき一度だけ機械的に見る
   （`grep -nE "[0-9]+都県|全国|関東"` 程度）。

## 実施記録（2026-09-21）

**3択のうち「説明文から範囲の言葉を落とす」を採った。** 地図はデータのある所にしか点を
打たないため範囲は見れば分かり、走行中のスマホで読む画面に語を足さずに済む。bboxを出す案は
読めず、都県名の対応表を持つ案は維持対象を増やす。

走査したところ、**同じベタ書きが風レイヤーにもあった**——`関東本土の格子点`・
`関東本土全域の格子点`は、backendの`domain/wind_grid.py: WIND_GRID_BBOX`の写しで、
あの定数を動かした瞬間に嘘になる。事故と同じ形なので一緒に落とした。

**背景の記述に誤りがあった。** 事故の取込範囲を決めているのはプロファイルのbboxではなく、
`backend/app/domain/accident.py: KANTO_PREFECTURE_CODES`（都道府県コードの表）である。
profileのbboxとは別に持っていて「同じ関東スコープに揃える」とコメントで断っている。
この二重宣言は[T971](T971.md)が既に守備範囲へ入れているため、ここでは起票しない。

`mapLayers.ts`に残る`関東`は1箇所（コンビニの編集鮮度を測った実測値の出典範囲）で、
これは過去に測った母集団の記述であり、取込範囲が変わっても嘘にならないため残した。

## 完了条件

- `mapLayers.ts`に範囲を決め打ちした文字列が無い。
- 取り込む範囲を変えても説明文が嘘にならない（bboxを変えた状態で実機を見る、または
  範囲に触れない文面になっている）。
