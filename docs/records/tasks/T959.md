# T959: 世代を上げた直後に主要エリアのタイルを先に焼く

状態: 完了（2026-09-26、前提が消えたためクローズ）

未着手（2026-09-19起票）

## 背景

バッチが`derived_data_meta.revision`を上げるとタイルキャッシュが無効になり、次にその範囲を
見た利用者が冷パスを丸ごと負担する（[T955](T955.md)、本番で174秒）。冷パス自体を削っても
16タイルぶんは残るため、上げた直後に主要エリアを先に焼く導線が要る。

詳細はこのファイルへ追記する。

## [T928](T928.md)との違い

T928は地図タイルの配信側（世代が変わった瞬間に視界の全系統を取り直す）。こちらは探索が
使う材料キャッシュ（z12単位、`tile_persistent_cache`）で、入れ物も冷えたときの費用も別物。

## クローズ（周期レビュー第13回、2026-09-26）

問い（周期レビュー第13回、2026-09-26。ダッシュボードの件T958-close）: 「ルート探索の作り直し（T1112）で前提が無くなった2つのタスク（T958・T959）を閉じますか」。選択肢は(1)閉じる: 前提（地図の区画ごとに材料を読む遅い経路）が無くなったため。初回の遅さは承認済みの計測の起票案で扱う (2)残す: 道路網全体の配列の読み込みを速くする目的で、中身を書き直して続ける。

答え: (1) 閉じる（2026-09-26）。

前提: T958・T959はどちらも「ルート生成の初回に、地図の区画（z12）ごとの材料をDBから読むので遅い」ことへの対策として起票された。[T1112](T1112.md)で道路網全体を1つの配列で持つ形になり（graph_service.pyは`road_network_store.current`から範囲を切り出す）、その経路は無くなった。`tile_persistent_cache`の読み手は勾配のway別の値（`dynamic_way_value_cache`）だけになった。初回の遅さの今の内訳は、承認済みの起票案「ルート生成の起動後の初回と広い範囲の所要を測る」（ダッシュボードのproposal-route-generation-first-and-wide-speed）が扱う。

なお[T958](T958.md)の記録は本タスクを「完了済み」と書いていたが、本タスクは未着手のまま閉じた（元の判断D-007の文面は「進める」だった）。
