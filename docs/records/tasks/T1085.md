# T1085. 地図で段が落ちると、体感ラベルの上書きが件数不一致で黙って捨てられる

状態: 完了（2026-09-23起票、2026-09-24完了）

## 背景

T957の担当が挙げた範囲外の不一致2（ユーザー決定 2026-09-23: 起票する）。軸のしきい値のうち地図で段にならない値があると（backend/app/domain/axis_display.py の _map_band_thresholds）、体感ラベルの上書き（display_band_labels_override）の件数が地図の段数と合わなくなり、frontend の mapColorLegend.ts: bandLabelsForBandCount が上書きしたラベルを何も知らせずに捨てる（利用者が軸スタジオで付けたラベルが地図に出ない）。やること: どの段にどのラベルが当たるかを、落ちる値の判定（T957の thresholds_the_map_drops）と同じ規則から決める形にし、黙って捨てない（合わないときは軸スタジオで知らせる・保存時に揃える等。どれにするかは design-principles.md のUI原則と既存の配り方から決め、理由を記録に書く）。フロントに判定を写さない。完了条件: 落ちる値を含む軸で、上書きしたラベルが地図の凡例の各段に正しく当たる（または合わないことが画面で分かる）ことを、入力に対するあるべき値のテストで示す。frontend/e2e/ と playwright.config.ts は触らない。

## 実施内容（2026-09-24）

### 方針

**どの段にどのラベルが当たるか**を、落ちる値の判定と同じ関数からbackendで決める。
`domain/axis_display.py: bands_the_map_keeps`が、人が刻んだ境界の段（下から0始まり）のうち
地図に残るものの番号を地図の段の並び順で返す。境界が落ちてまとまった段は**下側の段**として
扱う——地図の段の下端は、残った境界（または最下段）で始まる入力の段の下端と同じ値なので、
凡例のレンジ（「12以上」）とラベル（12で始まる段に付けたもの）が食い違わない。
`thresholds_the_map_drops`もこの番号から導く形にし、規則を1本にした。

揃え方の選択と理由:

- **地図**: 軸カタログの`display_band_labels_override`を、生の上書きではなく地図の段へ
  引き直した値（`map_band_labels`）で配る。凡例を組むフロントの経路（ramp軸の
  `axisLayers.ts`・専用way値配信の`dedicatedWayValueLayer.ts`・ルート線の`routeStyleModes.ts`）は
  どれもこの1つのフィールドを読むため、フロントを変えずに全経路で揃う。フロントに規則を
  写さない。フィールド名は変えていない——`frontend/e2e/mobile.spec.ts`のモックがこの名前で
  カタログを組んでおり、触れない範囲のため（名前が「生の上書き」に見える点はカタログの型の
  コメントに書いた）。
- **軸スタジオ**: 保存時に揃える（ラベルを消す・詰める）はしない。しきい値を刻み直せば
  段が戻り、付けたラベルもそのまま使えるべきで、保存が人の入力を書き換えると理由が見えない
  （design-principles.md「利用者が意図して決めた値は覚える」）。代わりに、T957の
  「地図では効かない: 15, 20」と同じ配り方で、**地図に出ない段のラベル欄の脇に「地図には
  出ない」と印を付け**、段階プレビューは地図と同じラベルで描く（問い合わせの応答へ
  `bands_on_map`を足し、`axisDraft.ts: bandLabelsOnMap`は番号で引くだけ）。理由の説明は
  既存のしきい値の印のⓘが持つため、文言は増やしていない（UI原則: 説明はⓘの奥）。
  画面に足したのは短い印1種だけで、T957でユーザーが決めた「入力欄の脇に名指しする」の
  延長のため、ユーザー判断は仰がずに進めた。

`mapColorLegend.ts: bandLabelsForBandCount`の件数照合は残した（合わないラベルをずらして
添える嘘を防ぐ守り）。「合わない軸が実在する」というコメントは、backendが揃えて配るように
なったため書き直した。フック`useThresholdsDroppedOnMap`は返す中身が変わったため
`useMapBandsOfThresholds`へ改名した。
