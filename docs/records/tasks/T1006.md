# T1006. 軸の凡例へ単位を配る（backendが常に空を配っている）

状態: 完了（2026-09-23）

## 背景

`registry.py: AxisDisplaySpec` は `unit`・`note` を宣言しているが、値を入れる2箇所
（`domain/axis_display.py:260`・`:269`）のどちらも渡さないため**常に空**である。
一方 frontend は `components/Map/axisLayers.ts:238-239` でそれを読み、`:469` の
`rangeStepLabel(lower, upper, axis.unit)` で**地図の凡例のラベル**に使っている。

つまり凡例に単位が出ない。読み手は正しく、**backendが配っていない側が誤り**（2026-09-22、
判断はユーザー）。

T998段階1のやり直しで「片側だけ存在する」ものとして検出した。コードからは
「backendが配ろうとしているのが誤りか、frontendが空と知りつつ表示しようとしているのが
誤りか」を区別できず、要件の出どころはユーザーだけである。

## 対応方針

`domain/axis_raw_value.py: raw_value_unit` が既に軸の生値の単位を導けるため、
`axis_display_for` からそれを呼んで `AxisDisplaySpec.unit` へ載せる。

`note`（`kind="none"` の理由を書く欄、`AxisDisplaySpec` のdocstringが用途を明記）も
同じく常に空なので、同一タスクで扱う。

## 完了条件

- 凡例に単位が出ることを実機（e2eのfixture）で確認する
- 単位が定まらない軸（`raw_value_unit` が返さないもの）で凡例が壊れないことを確認する
- `unit`/`note` が空のまま配られる経路が残っていないことを、宣言から導いて確かめる

## 実施内容（2026-09-23）

### 方針を変えた点: `AxisDisplaySpec.unit`へ載せず、フィールドごと消した

上の対応方針（`axis_display_for`から`raw_value_unit`を呼んで`AxisDisplaySpec.unit`へ載せる）は
次の2点で採らなかった（方針の変更はユーザー承認済み、司令塔の決定D-012）。

- **同じ値が1つの応答に2度載る**。`GET /api/axis-catalog`の各軸は既に`raw_value_unit`を
  トップレベルに持ち、frontendの`CatalogAxis`も受け取っている（`lib/axisCatalog.ts: toCatalogAxis`）。
- **importが循環する**。`axis_raw_value.py`→`dynamic_way_values.py`→`axis_display.py`の
  向きに既に依存があり、`axis_display.py`から`raw_value_unit`を呼ぶと輪になる。

読み手（`axisLayers.ts: rampAxesFromCatalogAxes`→`axisRampBandLabel`）が単位を読む先を
`axis.raw_value_unit ?? ""`へ変え、`AxisDisplaySpec.unit`を削除した。要件（凡例に単位を出す）は
変わらない。rampの段の境界は折れ点のx値＝生値の目盛りなので、単位が定まる軸では
`raw_value_unit`がそのまま凡例の単位になる（単位が定まるのは折れ線の形で、全項の重みが1の
ときだけ。`CategoricalShape`・他の軸を参照する項・重み1以外は`None`→数値だけのラベル）。

`note`も削除した。宣言上の用途は`kind="none"`の理由だが、`kind="none"`の軸はfrontendが
`rampAxesFromCatalogAxes`で落とすため読み手が無い。唯一の読み手はramp軸の`panelHint`の
フォールバック（`mapLayers.ts`）で、ramp軸の`note`は`axis_display_for`が一度も入れないため
常に空だった。軸スタジオの「地図に出せない」注記は`display.kind`だけを見て固定文言を出しており、
`note`を読んでいない。

「空のまま配られる経路」の母集団: `AxisDisplaySpec`を作る箇所は`axis_display_for`の2つの
`return`だけ（backendで`AxisDisplaySpec(`をgrep）。どちらも`unit`/`note`を持たなくなったため、
空で配る経路はフィールドごと無くなった。

### 変更

- backend: `registry.py: AxisDisplaySpec`から`unit`・`note`を削除。OpenAPI生成物を再生成
- frontend: `RampAxis.unit`は`raw_value_unit`から取る。`RampAxis.note`・`CatalogAxis.display.unit/note`・
  `panelHint`の`note`フォールバックを削除。テスト・フィクスチャの`display`から`unit`/`note`を除き、
  e2eの「段階の細かい軸」の単位（`箇所/km`）を`raw_value_unit`へ移した
- テスト: `axisLayers.test.ts`へ「`raw_value_unit`が段階ラベルに出る」「`null`なら数値だけ」の2件
- 文書: `docs/modules/frontend/map-axis-coloring.md`の判定表へramp軸の凡例の単位の出所を、
  `docs/modules/backend/axis-studio.md`の`raw_value_unit`節へ地図の凡例も使うことを追記

既存DB行への影響なし: `AxisDisplaySpec`は`axis_display_for`が応答のたびに導出する値で、
`axis_definitions`テーブルには保存されない。

### 実機（e2e）確認について

e2eの`mobile.spec.ts`は「段階の細かい軸」（単位`箇所/km`）の凡例の幅を見ている。フィクスチャを
`raw_value_unit`へ移し、段階ラベルに`箇所/km`が出ることのアサーションを足した。e2eは本番ビルドを
要し、この開発機では回していない（CIのe2eジョブが走らせる）。凡例の文字列そのものは上の単体
テストで固定した。
