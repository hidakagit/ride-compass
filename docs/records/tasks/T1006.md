# T1006. 標準を「操作別」に見直す（撤去・移設の手順が無い穴を塞ぐ）

状態: 未着手

## 背景

[T1001](T1001.md)の段階Aで、`staticAttributeLayers.ts`を丸ごと撤去した際に、そのファイル冒頭にしか
無かった判断基準（「1次の分類は中立色、2次の評価は緑〜赤。混同させない」）が一緒に消えた。
`docs/conventions/comments.md`には削除時の判定木（①経緯か ②他で強制されているか →
該当しなければ`docs/modules/*.md`へ昇格してから削除）が既にあったが、通していない。

実測（`git diff origin/master -- frontend/src`、2026-09-22）: 削除した実装6,142行のうち
コメント1,215行、追加側は3,856行中516行。判断・理由を含む言い回しの行は削除側24・追加側3。

## この穴の性質

ルールは**内容別**（コメント・テスト・ログ・キャッシュ・ドキュメント）に並んでいるが、
**操作別**（書く・直す・撤去する・移設する）にどのルールが効くかが定義されていない。

- `CLAUDE.md`のコメント方針が判定木を呼ぶのは「新規に書く/変更するコメント」と
  「経緯コメント一掃タスク」の2つだけで、**実装の撤去からは呼ばれない**
- 「修正の原則」は削除を促す規則を多く持つ（置き換えでなく削除を既定に／死んだものは
  同じコミットで消す／消したものを見張るテストを足さない）が、**撤去時に失われるものを
  守る手順が無い**（非対称）
- 「検査器にできず人が見るしかないのは次の2つだけ」の列挙に、撤去時の文の扱いが無い

## 対応方針（この順で行う）

1. **母集団を出す**: `CLAUDE.md`・`docs/conventions/*.md`・`docs/architecture/design-principles.md`・
   `.claude/commands/review.md`（計2,176行）の各ルールを1件ずつ列挙する
2. **各ルールへ2つの問いを当てる**:
   - **どの操作のときに効くか**（書く／直す／撤去する／移設する／レビューする）。
     撤去・移設が抜けているものを洗い出す
   - **破れたとき何が検知するか**（検知器／テスト／型／人の目／何も無い）
3. **抜けを塞ぐ**。足す場所は`CLAUDE.md`のドキュメント階層表に従う
   （常時・無条件で短いものだけCLAUDE.md、それ以外はconventions）
4. **撤去の手順を1本にする**: 「コードの撤去」と「文の撤去」を別工程として明記し、
   文は`comments.md`の判定木を必ず通す

## 完了条件

- 母集団の全ルールについて、効く操作と検知手段の対応が書き出されている
- 撤去・移設の操作から`comments.md`の判定木への導線が、`CLAUDE.md`から1行で辿れる
- この見直しで見つかった他の穴が、個別に起票されているか塞がれている
