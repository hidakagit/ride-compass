# T1006. 軸の凡例へ単位を配る（backendが常に空を配っている）

状態: 未完了（2026-09-22起票）

## 背景

`registry.py: AxisDisplaySpec` は `unit`・`note` を宣言しているが、値を入れる2箇所
（`domain/axis_display.py:260`・`:269`）のどちらも渡さないため**常に空**である。
一方 frontend は `components/Map/axisLayers.ts:238-239` でそれを読み、`:469` の
`rangeStepLabel(lower, upper, axis.unit)` で**地図の凡例のラベル**に使っている。

つまり凡例に単位が出ない。読み手は正しく、**backendが配っていない側が誤り**（2026-09-22、
判断はユーザー）。

T998段階1のやり直しで「片側だけ存在する」ものとして検出した。コードからは
「backendが配ろうとしているのが誤りか、frontendが空と知りつつ表示しようとしているのが
誤りか」を区別できず、要件の出どころはユーザーだけである。

## 対応方針

`domain/axis_raw_value.py: raw_value_unit` が既に軸の生値の単位を導けるため、
`axis_display_for` からそれを呼んで `AxisDisplaySpec.unit` へ載せる。

`note`（`kind="none"` の理由を書く欄、`AxisDisplaySpec` のdocstringが用途を明記）も
同じく常に空なので、同一タスクで扱う。

## 完了条件

- 凡例に単位が出ることを実機（e2eのfixture）で確認する
- 単位が定まらない軸（`raw_value_unit` が返さないもの）で凡例が壊れないことを確認する
- `unit`/`note` が空のまま配られる経路が残っていないことを、宣言から導いて確かめる
