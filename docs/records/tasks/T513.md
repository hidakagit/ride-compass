# T513: 評価軸の凡例ラベルを軸スタジオ設定可能な汎用フィールド化（T512のハードコード是正）

状態: 完了（2026-08-31）

## 背景

T512で風の評価軸凡例に体感ラベル（「強い向かい風」等）を追加した際、
`WIND_PENALTY_FEEL_LABELS`という**風専用のハードコード配列**をフロントに新設して
しまった。ユーザー指摘（2026-08-31）:「軸スタジオで設定できるものをベタで書かないで」
「実施する度に、勝手に設計原則違反をしないで」。

`display_thresholds_override`（改善計画T404）は既に軸スタジオで設定できる汎用
フィールドとして`page.tsx: dedicatedWayValueBoundaries`（design-principles.md
「軸ごとにpropを新設しない」原則、改善計画T473で確立）経由で配線されている。
段階ラベルもこれと対になる概念のため、同じ汎用パターンに乗せるべきだった。

## 対応方針（ユーザー承認済み、2026-08-31、規模M）

`display_thresholds_override`と対になる新フィールド`display_band_labels_override`
（文字列配列、任意）を`AxisDefinition`に追加し、全く同じ配線パターンで汎用的に扱う。
風・勾配のdedicated_way_value_layer軸だけでなく、通常のramp軸（`buildAxisRampLegend`）
の凡例にも同じ仕組みで使えるようにする（監査の結果、他に同種のハードコードは
見つからなかった——gradientAxisLayer.ts・axisLayers.tsの凡例はどちらも従来から
数値レンジ表記のみで、体感ラベル機能自体を持っていなかった）。

- backend: `AxisDefinition.display_band_labels_override: list[str] | None = None`。
  設定時は`display_thresholds_override`も設定済みで、かつ長さが
  `len(thresholds)+1`（段階数）と一致することを検証する。表示専用フィールド
  （T501の`_COSMETIC_ONLY_FIELDS`）に追加し、公開済み軸でも直接編集可能にする。
- 軸スタジオGUI: 既存の「地図の色分けしきい値」編集欄の各段に、ラベル入力欄を追加する
  （`AxisComposer.tsx`のdisplay_publishステップ）。
- frontend: `useAxisCatalog.ts`/`secondaryAxes.ts`/`evaluationAxes.ts`の型に
  `displayBandLabelsOverride`を追加し、`windAxisLegend`/`gradientAxisLegend`/
  `buildAxisRampLegend`が軸ごとにこれを読む。`WIND_PENALTY_FEEL_LABELS`
  （T512のハードコード）は撤去する。

## 実装メモ

`display_thresholds_override`と全く同じ配線パターン（`page.tsx: dedicatedWayValueBoundaries`
の汎用Map、design-principles.md「軸ごとにpropを新設しない」原則）を`display_band_labels_
override`にも複製した。監査の結果、他に同種のハードコードは見つからなかった
（gradientAxisLayer.ts・axisLayers.tsの凡例はどちらも従来から数値レンジ表記のみで、
体感ラベル機能自体を持っていなかった——「他に無いこと」の確認であり「無いから追加した」
わけではない。追加は風・勾配・通常のramp軸すべてに同じ汎用フィールドとして提供する）。

- backend:
  - `domain/axis_definitions.py`: `AxisDefinition.display_band_labels_override`新設、
    `_COSMETIC_ONLY_FIELDS`へ追加。
  - `api/routers/axis_admin.py`: `AxisDefinitionFields.display_band_labels_override`、
    バリデータ`_check_display_band_labels_override`（thresholds必須・長さ一致）。
  - `api/routers/axis_catalog.py`: `AxisCatalogEntry.display_band_labels_override`
    （`GET /api/axis-catalog`のレスポンスにも反映）。
  - `infrastructure/axis_definition_models.py`・`axis_definition_repository.py`:
    DBカラム・永続化の配線。
  - `migrations/0029_axis_definitions_display_band_labels_override.sql`: DDLのみ
    （行データはaxis_admin API経由、CLAUDE.md「コミット時の同期ルール」）。
  - `scripts/export_openapi.py`: 静的生成物axis-catalog.jsonの手書きdictにもフィールドを
    追加（AxisCatalogEntryのPydanticモデルとは別に手書きされている箇所、見落とすと
    ビルド時静的フォールバックだけこのフィールドを持たなくなる）。
- frontend（`display_thresholds_override`と同じ配線を複製）:
  - `hooks/useAxisCatalog.ts`（`toCatalogAxis`・`buildCatalog`）
  - `components/Map/axisLayers.ts`（`CatalogAxis`・`RampAxis.bandLabelsOverride`・
    `rampAxesFromCatalogAxes`・`axisRampBandLabel`/`buildAxisRampLegend`が段階数一致時に
    体感ラベルを添える）
  - `components/Map/secondaryAxes.ts`・`lib/evaluationAxes.ts`（`SecondaryAxisSummary`/
    `PreferenceAxisDef`型と静的フォールバック構築）
  - `components/Map/windAxisLayer.ts`・`gradientAxisLayer.ts`: `windAxisLegend`/
    `gradientAxisLegend`が任意の`labels`引数を受け取る形へ変更。T512で新設した風専用の
    ハードコード配列`WIND_PENALTY_FEEL_LABELS`は削除した。
  - `app/page.tsx`: `dedicatedWayValueBoundaries`と対になる
    `dedicatedWayValueBandLabels`（軸id→ラベル配列のMap）を新設し、
    `windAxisLegend`/`gradientAxisLegend`の呼び出しへ渡す。
  - `components/AxisStudio/AxisComposer.tsx`: `display_publish`ステップに
    体感ラベルの編集欄を追加（`displayThresholdsOverride`が有効な間だけ表示）。
    しきい値の追加/削除に連動してラベル配列の長さも自動調整
    （`addThresholdOverrideValue`/`removeThresholdOverrideValue`拡張）、「自動計算に戻す」
    でラベルの上書きも一緒にnullへ解除する。複製時はしきい値と同じくnullへリセットする。
