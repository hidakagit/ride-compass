# T1007. 材料単位のタイル失効を、タグから実装する（索引だけ張って読んでいない）

状態: 完了（2026-09-27。材料単位の失効はタグでなく鍵で実装し、タグと索引を撤去した）

## 背景

`infrastructure/dynamic_way_value_cache.py:93` がキャッシュへ `tag="dynway:<材料id>"` を
書き、`infrastructure/tile_persistent_cache.py:45` が `tag_index=True` で索引を張って
**書き込みごとにコストを払っている**。しかし`tile_persistent_cache.py`の掃除は容量上限の退避（LRU）だけで、
**タグを読む経路が1つも無い**（起票時に名指した`prune_stale_generations`・`clear_namespace`はT1112段階3b-2で消えた）。

材料を1つ変えたときにその材料のタイルだけを失効させる導線が、書き手だけあって
読み手が無い状態である。要件として必要（2026-09-22、判断はユーザー）。

T998段階2で検出（グループB・グループGが別モジュールで同型を報告）。

## 対応方針

`diskcache` の `evict(tag)` を使う口を `tile_persistent_cache` へ設け、
`dynamic_way_value_cache` 側から材料idで失効させられるようにする。

**決める必要があるのは「どこから呼ぶか」**——材料の定義が変わったことを誰が検知して
失効を起こすのか。材料カタログの宣言を変えるのはデプロイ時なので、起動時のジョブか、
世代番号の仕組み（`cache_identity.py`）との関係で決まる。着手時に設計を先に書くこと。

## 設計（起点をどこに置くか）

記録の対応方針は「`evict(tag)`の口を設け、どこから呼ぶかを決める」だった。選択肢を品質で比べた:

| | 起動時のジョブで`evict(tag)`（記録の方針） | 鍵に材料の値の作り方の署名を入れる（採った） |
|---|---|---|
| 正しさ | **デプロイの重なりで壊れる**。入れ替わるまで旧コンテナが読み書きを続ける（`road_network_store.py: prune_other_shapes`の説明と同じ事情）ため、新コンテナが起動時に材料ごと消した直後に、旧コンテナが**同じ鍵**へ古い計算の値を書き戻し、以後TTLの間それを配る | 旧コンテナは旧い署名の鍵へ書くので、新コンテナは読まない。重なりに依存しない |
| 変化の検知 | 署名は結局要る。加えて「前回の署名」をどこかへ保存し、起動時に比べる仕組みが要る | 署名だけ。比べる仕組みは要らない（鍵が違えば当たらない） |
| 書き込みの費用 | タグの索引を書き込みごとに更新し続ける | 索引を外せる |
| 古い実体 | 消した分はすぐ空く | TTL（24時間）で失効し、書き込みのたびに`diskcache`が失効したものを消す（`cull_limit`、既定10件ずつ）。容量上限の退避も別に働く |
| 規約 | caching.md「無効化」は「既定は世代番号」・push型の無効化は代償行為 | 同節の既定どおり |

古い実体がすぐ空かない点だけが劣るが、勾配のエントリは本番で2件・52KB（[T1002](T1002.md)）〜0件（[T1112](T1112.md)）で、
24時間残っても容量上限（1GB）に届かない。**起点は鍵の組み立て（`dynamic_way_value_cache._key`）の1箇所**になり、材料の側は
自分の署名を必須キーワード`value_shape`で渡すだけ（渡し忘れはその場で`TypeError`）。

署名に何を入れるか（caching.md「無効化」: 関数のソースはハッシュしない・署名に入らないものを増やさない）:
- 入力のSQL`_FEATURE_GRADIENT_INPUTS_IN_TILE_SQL`の形の署名（`road_graph_repository.py: FEATURE_GRADIENT_INPUTS_SHAPE`。
  SQLは路面タイルと同じ地物の組み立てを埋め込んでいる）
- 直角付近を落とす幅`LENS_PERPENDICULAR_BAND_DEG`と丸めの桁（`_VALUE_DECIMALS`）
- 式（`GradientCalculator.effective_gradient`）を変えたときだけ手で上げるリビジョン（`cache_identity`の第1引数、今は`"1"`）

タグを読む手段を作らないので、`set_by_key`の`tag`と`tag_index`は撤去した。`diskcache`は置き場に設定を保存し、引数で渡さない
設定は前回の値を引き継ぐため（`diskcache/core.py`の`Cache.__init__`: 保存済みの設定で既定値を上書きしてから引数で上書きする）、
`tag_index`は引数から消すのでなく`False`を明示した。一時ディレクトリで実測: `tag_index=True`で作った置き場を引数なしで開き直すと
索引`Cache_tag_rowid`と設定1が残り、`tag_index=False`で開き直すと索引が消えて設定0になり、既存の値はそのまま読めた。

## 実施内容
