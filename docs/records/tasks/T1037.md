# T1037. road_graph_engine.pyを変更理由ごとに分割するか

状態: 完了

## 判断: 見送り（2026-09-23・周期レビュー第12回、ユーザー承認済み）

## 背景

`backend/app/services/road_graph_engine.py`（第12回時点 2,438行、閾値2,700）には、
変更理由の異なるクラスタが同居している——コスト行列の合成、探索、候補と表示値の
組み立て、キャッシュの取得/構築、逆回りループの代数的合成。

とくにコスト合成（評価の式・時刻ビン・重み）は**軸や材料が増えたときに変わる**一方、
探索の本体は**アルゴリズムを変えたときに変わる**。変更理由は別である。

## 見送りの理由

1. **今周期で 2,671 → 2,438 と縮んでおり、悪化していない。**
2. `docs/modules/backend/routing-engine.md`が現行構造を前提に900行超で記述しており、
   分割は文書の作り直しを伴う。**同じ周期で文書の分割も提案している**ため
   （[T1030](T1030.md)の発火分類）、両方を同時に動かすと両方が中途半端になる。
3. **分割の価値が実測されていない。** コスト合成が他のクラスタとどれだけ状態を
   共有しているかを測っていない。測らずに分けると、結合度が高いまま2ファイルになる
   （行数は減るが変更コストは減らない）。

## 再評価の条件

次のどちらかで再評価する。

- **閾値2,700に到達したとき**（`review_checks.py size`が発火する）。
- **`routing-engine.md`の分割が完了したとき。** 文書を先に割ると、実装の境界が
  文書側から見えるようになる。この順序で進めるのが安い。

## 再評価のときに測ること

分割の価値を判断するには、行数ではなく**結合度**を測る。具体的には、コスト合成の
クラスタが探索クラスタのどの状態を読み書きしているかを列挙し、分割後に跨ぐことに
なる境界の幅（受け渡す値の数）を出す。境界が狭ければ分割の価値があり、広ければ
2ファイルになるだけで変更コストは減らない。
