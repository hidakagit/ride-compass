## 調べたこと（2026-09-27）

- **rio-tilerで同じことができるか**（公式のソース、タグ9.4.6の`rio_tiler/io/rasterio.py`・`reader.py`・
  `mosaic/reader.py`）: できる。`Reader(None, dataset=<開いたDatasetReader>)`で開いたままのラスタを渡せ、
  `tile()`は`part()`→`read()`で`resampling_method`・`reproject_method`とも既定が`"nearest"`。
  `mosaic_reader`の既定の`FirstMethod`は先に値が入った画素を残す（今の`np.where(classes == 0, …)`と同じ）。
  範囲外は`TileOutsideBounds`を既定で読み飛ばし、全部外れると`EmptyMosaicError`。置き換えで消えるのは
  `_MAX_SOURCE_READ_SIDE`・`_read_decimated`・`tile_classes`の本体とそのimport（今の約75行）で、代わりに
  約20行（読み手の関数とmosaicの呼び出し・例外の扱い）が要る。差し引き約−55行（見立てどおり）。
  `test_landcover_raster.py`は入口（`render_tile`）で確かめているので、置き換えても直す必要は無い。
- **増える依存**（`pip install --dry-run --ignore-installed --only-binary=:all: --platform manylinux_2_28_aarch64
  --python-version 3.12 --report`で、`requirements-batch.txt`だけと、それに`rio-tiler==9.4.6`を足したものを
  解決して比べた。本番のイメージは`requirements-batch.txt`を入れる）: 解決される配布物が61本→94本で、
  **33本増える**。内訳は rio-tiler・morecantile・color-operations・numexpr と、STACを読むための
  pystac・pystac-core・pystac-ext-*（22本）、遠隔読み取り向けの httpx2・httpcore2・truststore、
  python-dateutil・six。既存の版が動くものは無い。pyproj は`requirements-batch.txt`で既にイメージに
  入っている（morecantile が要るのはこれ）ので、PROJの2本目が入ることにはならない。
- **本番の機械（aarch64）で入るか**: 入る。上の解決は`--only-binary=:all:`でaarch64のwheelだけから
  通った（コンパイルが要る color-operations・numexpr もaarch64のwheelがある）。
- **ライセンス**: rio-tiler は BSD-3-Clause、morecantile・color-operations・numexpr・truststore・six は MIT、
  pystac 系は Apache-2.0、httpx2・httpcore2 は BSD-3-Clause。どれも商用で使える。置き換えない理由ではない。
- **版の動き**（公式の`CHANGES.md`）: メジャー版が 7.0.0（2024-10-21）・8.0.0（2025-11-20）・9.0.0
  （2026-03-11）と約17か月で3回。9.1.0（マイナー版）で`httpx`→`httpx2`への切り替えとモジュールの移動がある。
- **今の自前の部分が何をしているか**: 窓の計算・間引いた読み出し（`dataset.read(out_shape=…)`。GDALが
  縮小画像を選ぶ）・`rasterio.warp.reproject`の最近傍・重ね合わせ。再投影や縮小画像の選択そのものは
  GDALが持ち、自前なのはそれを並べる層だけ。
- **読み出しが効く範囲**: `tile_classes`は地図の塗り（`render_tile`）だけでなく、取込の
  `batch/source_adapters/io_lulc_tile.py`も通る。置き換えると、DBへ入る土地被覆タイルの画素（そこから数える
  道の周りのクラス別の割合）が変わらないことも確かめ直す必要がある。この点は`docs/modules`に書かれて
  いなかったので同じ節へ足した。
