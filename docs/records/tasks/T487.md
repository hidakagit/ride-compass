# T487. ルート設定パネルの軸1行あたりの高さをモバイルで半減させる

状態: 完了（2026-08-31）

- 背景: T486完了後、ユーザーから本番（Render）のモバイル実機スクリーンショットが
  送られ「スマホ画面があまり改善されていない。スマホではより進んだ省スペース設計を
  行って」という指摘を受けた。スクリーンショットは軸1件あたり2行（チェックボックス+
  ラベル+重み値／スライダー+色分けボタン）のレイアウトのままで、T486の
  `max-height: 40dvh`スクロール化だけでは軸1行自体の高さは変わっていなかった。
- 原因（構造）: `RouteSettingsPanel.module.css: .row`はT435でデスクトップサイドバー
  （280px幅）向けに1行→2段CSS Gridへ変更された経緯を持つ。モバイルBottomSheetは
  画面ほぼ全幅（375px以上）を使えるためT435の制約（固定幅要素の合計がスライダー幅を
  潰す）に当てはまらないが、デスクトップ・モバイルで同じ`.row`クラス・同じ2段レイアウトを
  共有していたため、モバイルでも不要に高さを消費していた。
- 対応: `@media (max-width: 640px)`（`useIsMobile.ts: MOBILE_BREAKPOINT_PX`と同じ
  閾値）で`.row`を1行flexへ戻すオーバーライドを追加。ラベルは最長ラベル
  （「自転車インフラ」）でも収まる`max-width: 4.4rem`+省略記号、スライダーは
  `flex: 1 1 auto`で残り幅を確保する。
- 検証: Browserペインで375×812（モバイル実機で最も狭い部類の幅）をエミュレートし、
  軸8件すべてが1行レイアウトで表示されること、各スライダーの実際のDOM幅
  （`getBoundingClientRect().width`、T435と同じ検証方法）が120〜158pxと十分に
  操作可能な幅を保っていること（0pxに潰れていない）を確認した。副産物として、
  `.group`のスクロール量（scrollHeight 332px / clientHeight 323px）も判明し、
  T486で導入した40dvhスクロール境界がほぼ発火しない程度まで軸一覧全体が収まる
  ようになったことを確認した。デスクトップ（800px幅）では引き続き従来の2段
  グリッドのままであることも確認済み（メディアクエリの範囲外）。`tsc --noEmit`・
  `RouteSettingsPanel.test.tsx`10件通過。
- 規模: S
