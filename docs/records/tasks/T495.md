# T495: 重み配分バー（帯グラフ）をドラッグ可能にし直感的な配分UIにする

状態: 完了（2026-08-31）
## 背景

ユーザー要望「操作が分かりにくい。複数要素を足し合わせて1にするのを直感的に省スペース
設定できるUIはないか」。T493でルート設定パネルの各軸行を「現在値ボタン→タップで
ポップオーバー」方式へ圧縮したが、複数軸の重みを相対的に見比べながら配分し直す操作
自体は各軸を個別にポップオーバーで開き直す必要があり、直感的とは言えなかった。

## 対応方針

AskUserQuestionで4つの方向性を提示し、ユーザーが「既存の重み配分バー（帯グラフ）を
ドラッグ可能にする」を選択した。帯グラフは元々「複数軸の重みが合算されて全体になる」
様子を表示専用で示していたため、そこへ直接ドラッグ操作を足すのが最も直感的かつ
省スペース（新規UI領域を追加しない）という判断。

隣り合う2区間の境界をドラッグ（またはフォーカスして矢印キー）すると、その両隣の2軸
間でだけ重みが移動する（他の軸・2軸の合計自体は変わらない）。細かい数値調整
（0.01刻みでの単独設定・0への変更）は従来の詳細ポップオーバー（T493）を引き続き使う。

## 実装

- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.tsx`:
  - `clampBoundaryDrag`: 隣接2軸の重みと生の移動量（重み単位）を受け取り、両軸が
    `[WEIGHT_STEP, 0.6]`範囲に収まるようクランプしてWEIGHT_STEP単位へ丸めた新しい
    2軸ぶんの重みを返す純粋関数。丸め後もdeltaを両軸で共有するため、2軸の合計は
    浮動小数点誤差を含めて変わらない。
  - `handlePairWeightChange`: 隣接2軸ぶんを1回のstate更新へまとめる。
  - `startBoundaryDrag`: pointerdown起点で開始。境界ハンドル要素は16px幅しかなく
    ドラッグ中にポインタが要素の外へ出るのが常態のため、pointer captureではなく
    window直接へpointermove/up/cancelを登録する方式にした（環境によってpointer
    captureが確実に効くとは限らないため）。
  - `handleBoundaryKeyDown`: 矢印キーでWEIGHT_STEPずつ配分し直す
    （`role="slider"`としての最小限のアクセシビリティ）。
  - 帯グラフのJSXを`stackBarOuter`（位置基準の外側コンテナ）+`stackBar`
    （セグメント本体、`overflow:hidden`で角丸）+ 境界ハンドル（`stackBarOuter`の
    直接の子として絶対配置）の3層構成へ変更。ハンドルを`stackBar`の子にすると
    `overflow:hidden`が帯の両端に近い境界のハンドル当たり判定を切り取ってしまうため、
    分離した。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.module.css`:
  `.stackBarOuter`（`position: relative`）・`.stackBarHandle`（幅16px、上下に
  張り出す高さ、`touch-action: none`をこのハンドル自身だけに絞る——T493でコンパスの
  `touch-action: none`が帯全体を覆いスクロールを奪っていた反省を踏まえた設計）を追加。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.test.tsx`: 境界の
  矢印キー操作（隣接2軸間の移動・逆方向・上限到達時に変化しないこと）の3件を追加。
  実際のポインタドラッグはhappy-domがレイアウト計算をしないため単体テストで再現
  できず、Browserペインでの実機確認で検証した。
- `docs/modules/frontend/route-settings-and-results.md`: 「軸ごとの行」の構成図・
  説明が旧スライダー直置き方式（T493以前）のまま更新されていなかった乖離を発見し、
  現状（帯グラフのドラッグ操作・現在値ボタン→ポップオーバー方式）へ合わせて修正した。

## 検証結果

- `npx vitest run src/components/RouteSettingsPanel/ --pool=threads`: 13件全て成功
  （既存10件+新規3件）。
- `npx tsc --noEmit`: エラーなし。
- Browserペインで実機確認: デスクトップ幅でポインタドラッグ（`PointerEvent`を
  直接dispatchして検証——Browserペインの`left_click_drag`はこの環境で中間の
  pointermoveイベントを生成しないためコード自体の検証には使えなかった）により
  隣接2軸（勾配0.15→0.31、風0.26→0.10、合計0.41で不変）が正しく連動することを確認。
  矢印キー操作（舗装質0.19→0.20、停止密度0.20→0.19）も確認。モバイル幅(375x812)、
  BottomSheet展開中でも`pointerType: "touch"`のポインタイベントで同様に動作し
  （舗装質0.20→0.06、停止密度0.19→0.33、合計0.39で不変）、ドラッグ操作の直後も
  パネル全体のスクロールが正常に機能する（ハンドル以外の帯グラフ領域・軸の行が
  スクロールを妨げない）ことを確認した。

## 残課題

なし。細かい数値調整・向きコンパスは既存の詳細ポップオーバー（T493）が引き続き担う。
