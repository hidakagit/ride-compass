# T492: 風・勾配の走行方位コンパスをルート設定パネルへ移設

状態: 完了（2026-08-31）
## 背景

モバイルで下部BottomSheet（ルート設定パネル）を展開中、地図オーバーレイ側にあった
風・勾配のコンパス（走行方位スライダー、`WindBearingSlider`）が画面下部に隠れて
実質操作できなくなっていた（ユーザー指摘）。

## 対応方針

風・勾配の走行方位コンパスは、地図オーバーレイ（`bottomControlRow`、
`.bottomControlRow`で`bottom: calc(var(--space-3) + var(--mobile-tabbar-height))`固定）
から、`RouteSettingsPanel`内の該当軸の行の直下（「色分け」ONの時のみ表示）へ移設した。
これによりコンパス自体がBottomSheetのスクロール領域の一部になり、隠れる問題が構造的に
解消する。

「環境」グループ（環境レイヤー表示トグルから起動する風・勾配のコンパス、
`showWindVector`/`layerVisibility.gradientFill`が起点）は元々の地図オーバーレイのまま
変更していない——このタスクの対象は「評価軸としての風・勾配の色分けON時」のコンパス
のみ。

## 実装

- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.tsx`:
  `windBearingDeg`/`onWindBearingDegChange`/`gradientBearingDeg`/`onGradientBearingDegChange`
  の4propを追加。`bearingControlFor`ヘルパーと`renderBearingControl`を追加し、
  `dedicated_way_value_layer`を持つ軸の「色分け」トグルがONかつ表示中の間だけ、
  行の直下に`WindBearingSlider`を表示する。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.module.css`:
  `.bearingRow`/`.bearingLabel`を追加。
- `frontend/src/app/page.tsx`: 上記4propを配線。地図オーバーレイ側のコンパス表示条件を
  `showWindVector`/`layerVisibility.gradientFill`のみ（「環境」グループ起点のみ）へ
  絞り込み、評価軸の色分けトグルはもう地図オーバーレイ側のコンパスを起動しないようにした。
- `frontend/src/components/RouteSettingsPanel/RouteSettingsPanel.test.tsx`:
  新規必須propを`baseNewProps()`へ追加。

## 検証結果

- `npx vitest run src/components/RouteSettingsPanel/ --pool=threads`: 10件全て成功
- `npx tsc --noEmit`: エラーなし
- Browserペインでモバイル幅(375x812)実機確認: BottomSheetを展開した状態で
  勾配・風それぞれの「色分け」をONにすると、隠れずにコンパスが行の直下に表示され
  操作可能であることを確認。OFFにすると消えることも確認。パネル全体のスクロールも
  引き続き正常（ネストしたスクロール領域は無し）。
- 「環境」グループ起点の地図オーバーレイ側コンパス（風レイヤー表示・勾配レイヤー表示
  トグル由来）は変更していない。デスクトップ幅での動作もあわせて確認済み。

## 残課題

- `windBearingDeg`/`gradientBearingDeg`等が軸id別の個別state/propのままである
  技術的負債はT483で認識済み。今回のUI移設ではその構造は変更していない
  （`useDynamicWayValues.ts`のフェッチライフサイクルの複雑さのため、汎用化は別タスク）。
- 別途報告された「方角設定uiが使いにくい（反応しにくい）」というタッチ操作性の懸念は
  本タスクでは未着手（今回の対応は可視性の問題のみを解消するもの）。再発する場合は
  `WindBearingSlider`（`@fseehawer/react-circular-slider`ベース）のドラッグ処理を
  別途調査する。
