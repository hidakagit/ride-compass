# T1110. 順序のある分類（道路種別）の線を、色と同じ順序で太さでも示す（太さはbackendが順位から導く）

状態: 完了（2026-09-25起票・2026-09-26完了）

## 背景

ユーザー相談（2026-09-25）: 道路種別の線の太さも変えられるか。どこまでbackendで自動導出させるべきか。承認時の方針: 太さは色と同じ順序（幹線ほど太く）を示す二重の手がかりとして、順序のある分類（palette="ordered"、今は道路種別だけ）にだけ付ける。太さの値はbackendが色と同じ場所（backend/app/domain/display_palette.py の順位からの導出）で規則から導き、生成物（primaryAttributes.ts）へ色と並べて出す。frontend（features/map/scene/groups/roadLines.ts・凡例の見本）は受け取ってMapLibreの式にするだけ。注意: 路面等と一緒に表示すると横に並べて描くため、並べる間隔（ROAD_TRACK_OFFSET_STEP_PX）を太さに合わせる。細い側は見える・押せる下限を割らない。設計書の決まり「太さは意味を運ばない」（docs/modules/frontend/static-map-layers.md）を「太さは順序のある分類だけ、色と同じ順序を示す」へ直す。規模の根拠: backendの配色の規則とテスト・export_openapi・生成物・roadLines.ts・凡例の見本・そのテストでおよそ8ファイル（未列挙）。T1105（不明を破線にする）のあとに進める。

## 実施（2026-09-26、T1112のクラウドのセッション）

- 太さの規則: backend `display_palette.ordered_line_widths`が、色と同じ並びの位置（先頭0〜末尾1、`_ordered_positions`を色と共有）から
  太さを線形に導く。細い端は他の線と同じ`ROAD_LINE_WIDTH_PX`（3px）、太い端は`ROAD_ORDERED_MAX_WIDTH_PX`（6px、map_display.py）。
  道路の種類の5行では6・5.25・4.5・3.75・3px。細い端を3pxにしたのは、道を押したときの拾い方が
  `queryRenderedFeatures(e.point)`（押した1点に重なる線だけ）で、今の3pxより細くすると拾いにくくなるため。太い端の6pxは
  見た目で決めた値で、実機の地図では**未確認**（クラウドの開発DBに道路網が無く、タイルを描けない）。
- 配り方: `resolved_display_axes`が、線で描く属性の順序のある分類の行にだけ`line_width_px`を付ける（点の順序のある分類・
  順序を持たない分類には付けない）。生成物`primaryAttributes.ts`へ色と並んで出る。
- 並べ方: 間隔の定数`ROAD_TRACK_OFFSET_STEP_PX`（2px）を、重ね幅`ROAD_TRACK_OVERLAP_PX`（1px）へ置き換えた。隣どうしの中心の
  間隔は互いの太さの半分ずつ−重ね幅で、太さが道ごとに違うので`line-offset`も道ごとの式になる。全部3pxなら中心の間隔は
  従来と同じ2px。二次軸の下敷きの幅は、全部の線が最も太いときの帯の幅（`ROAD_TRACKS_MAX_SPAN_PX`）から導く
  （4本では9px→12px）。
- 凡例: `LegendEntry.line`（線の見本か）を`lineWidthPx`（線の見本の太さ）へ置き換え、見本を地図と同じ太さで描く。
  線の見本の高さは4px固定から地図の太さ（3〜6px）へ変わった。
- 設計書: static-map-layers.mdの「太さは分類を持たない」を「太さは順序のある分類の順序だけを、色と重ねて示す」へ直した。
