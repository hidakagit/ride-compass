# T1055. コードのコメントが、存在しない生成物の名前と古い正本を指している

状態: 未完了（2026-09-23起票。同日、判定を終えた分だけを直して区切った。残りは下の「残り」）

## 背景

2026-09-23、T1034の作業中にD-smallが範囲外で発見。primary-attributes.json・axis-catalog.json（実体の名前と違う）や『registry_defaults.pyが軸の単一ソース』（軸側は撤去済み）をfrontend・backendのコメントが指している。代表例: frontend/src/components/Map/primaryAttributes.ts:23、features/map/scene/groups/points.ts:3、backend/app/api/routers/axis_catalog.py:9、secondaryAxes.ts:8、mapLayers.ts:472、material_catalog.py:787。母集団は機械で導出する（comments.mdの方針で直す）。

同じ性質のものとして、[T1016](T1016.md)「範囲外で見つけたもの」（撤去済みの識別子を名指すコメント:
`build_road_graph`・`RAMP_AXES`・`buildAxisOverlayLayers`・`PREFERENCE_AXES`・`SECONDARY_AXES`・
`mergeFrameTimes`・`DETAIL_HIT_LAYER_ID`・`DEFAULT_ROUTE_PREFERENCE`、`TuningEffect.NODE_ATTRIBUTE_BATCH`の
`road_nodes`）も対象に含めた。

## 母集団の出し方（再現手順）

使い捨てのスクリプト（リポジトリに置いていない）で次の定義どおりに数えた。

- **コメント**: `frontend/src`の`*.ts`/`*.tsx`（`*.test.*`・`__fixtures__/`・`testing/`・`structure/`・
  `types/generated/`・`*.d.ts`を除く）のコメント（TypeScriptの構文木のコメント範囲。JSXの`{/* */}`は
  式を持たない`JsxExpression`の中にあり前後のコメント範囲に出ないので別に拾う）と、`backend/app`・
  `backend/scripts`の`*.py`の`#`コメントとdocstring（`tokenize`）。
- **名指しとして拾う形**: `_`を含む語・camelCaseの語・拡張子（`.ts/.tsx/.py/.json/.md/.yaml/.yml/.sql/.css/.mjs`）
  を持つファイル名・3区切り以上のハイフン区切りの小文字id（`region-road-surface-tiles-line`等）。
  行末で折り返した識別子（`FOO_` + 改行 + ` * BAR`）は1語へ戻してから拾う。
  `_`を含まない全大文字の語（MVT・GUI・T番号・lintのコード）は略語として拾わない。
- **実体（語彙）**: テスト（frontendの`*.test.*`・`__fixtures__/`・`testing/`・`structure/`・`e2e/`、
  `backend/tests/`）を**除いた**コードの、コメント以外に現れる語（TSは識別子・文字列・JSXテキスト、
  Pythonは名前トークン・文字列トークン・f文字列の本文）と、yaml/json/css/sql/生成物の語。
  ファイル名は`git ls-files`のbasename。接頭辞・接尾辞だけの表記（`WIND_GRID_`）は、それで始まる／
  終わる実名があれば実在とみなす。

穴と検算（どれも既知の1件が拾えることを確かめてから数えた）:

- テストを語彙に入れると、撤去した実装と同じ名前をテストが自前の定数に持つ場合に隠れる
  （`MapView.tsx`の`RAMP_AXES`）。語彙からテストを外して拾えることを確認した。
- JSXのコメントを拾わないと`page.tsx`の`DETAIL_HIT_LAYER_ID`が漏れる。拾えることを確認した。
- Python 3.12ではf文字列の本文が`STRING`ではなく`FSTRING_MIDDLE`で来るため、SQLに埋めた列名
  （`on_structure`・`ST_AsMVT`等）が語彙から漏れて誤検知になる。語彙へ足して6種が消えた。
- 行を跨いで折り返した識別子（`_build_search_materials_` + 改行 + `uncached`）と、ハイフン区切りの
  レイヤーid（`region-road-surface-tiles-line`）は、初版の規則では0件として出ていた。規則を足し、
  修正前の本文（`git show 5e912552:<path>`）に当てて両方が拾えることを確認した。

着手時点（5e912552）で、TS 4813件・Python 3751件のコメントから、実体の無い名前が175種・312箇所
（ハイフンid・折り返しの規則を足す前の数え方）。

## 残り（判定していない・範囲外で見つけたもの）

担当の区切りで、次は判定していない。新しい担当が引き継ぐ。

1. `backend/scripts/measure_gradient_outliers.py`（1〜18行のdocstring、45・82・108行のSQL）:
   撤去済みの表`elevation_attributes`と関数`compute_elevation_attribute`を前提にしている。コメントだけでなく
   **スクリプト自体が今のDBで動かない**ため、直すか撤去するかの判断が要る（コメントの修正では済まない）。
2. `backend/app/api/routers/material_catalog.py`の`get_material_values`のdocstring:
   「動的値一覧に対応していない材料（`tracktype`等）」と書くが、`tracktype`は`value_sql`を持つcategorical材料で
   値一覧が返る。名前は実在するため上の列挙には出ない（実在する名前での誤った主張）。docstringは
   OpenAPIへ出うるため、直すときは`export_openapi.py`の生成物のドリフトも見る。
3. `backend/app/domain/material_catalog.py`の`oneway`材料の`CoverageExcluded.reason`（文字列）:
   `osm_raw_ways.direction`を指すが、列は`way_materials.direction`。コメントではなく画面へ出る文字列。
4. `frontend/src/components/Map/MapView.tsx`の`// payload（page.tsx側が…`で始まる段落（167〜174行付近）:
   宣言に結び付かない孤立したコメントで、説明している「このループ」がMapView内に無い（sceneへ移った）。
   名前は実在するため列挙に出ない。
5. 列挙が見ていない形: 実在する名前を使った誤った主張（2・4）、関数・ファイルを名指さない説明文。
   今回の数え方では拾えない。
