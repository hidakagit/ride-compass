# T1081. 定期確認のフックの入口（launch.py）が、子の出力をcp932で出し直して落ちうるのを直す

状態: 未完了（2026-09-23起票）

## 背景

T1076の担当（N-help）の報告: scripts/orchestration/launch.py の標準出力はPostToolUseフックの出力としてClaude Codeが読む。子プロセス（origin/masterの版のorchestrate.py）から受け取ったUTF-8の出力を、JSONを組み直さない print(out) の分岐でそのままWindowsの既定の文字コード（cp932）で出し直すため、— のようなcp932で表せない文字が来るとUnicodeEncodeErrorで落ちる可能性がある。落ちると定期確認（20分ごとのcheck --if-due）が黙って止まる。通常の日本語だけなら落ちないが、Claude CodeがUTF-8として読めば文字化けする可能性もある。どちらも未確認。やること: まず実際に落ちるか・化けるかを、cp932で表せない文字を含む出力をフックの経路で1回流して確かめる（直す前に見る）。直すならT1076と同じく入口で標準出力をUTF-8へ整え、Claude Codeがフックの出力をどの文字コードで読むかを公式の文書で確かめてから決める。
