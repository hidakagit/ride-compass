# T1168. 画面系の担当ごとに手元で本番ビルド（next build）とe2eを回し、1回数分ずつ枠を塞ぐ

状態: 未完了（2026-09-26起票）

## 背景

2026-09-26の第3回では、画面系の担当2本（T1142・T1143）がそれぞれ手元で next build（309秒で失敗・279秒）と playwright を回し、backendの担当のpytestが180秒、画面系のvitestが216秒、枠を待った。09-23〜26では build と playwright の保持が合わせて166分（枠の保持の21%）。作業ブランチのCI（ci.yml の e2e・e2e-scan）は同じビルドとe2eを走らせ、playwright-report を artifact として上げている。まず調べる段階: 手元のビルドが何のために回っているか（画面の確認のスクリーンショット・e2eの新しいテストの実行・型検査の代わり等）を、第3回の担当の報告と枠の記録から分け、CIの artifact（スクリーンショット・レポート）で代えられるものと、手元でしか確かめられないものを決める。代えられるなら、担当が作業ブランチのCIからスクリーンショットを取る道具と規約にする。第3回の改善（派生元 T1162）。
