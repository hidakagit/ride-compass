# T1008. 時刻別・速度別の動的way値を、実際に配る（鍵にあるが常にNone）

状態: 未完了（2026-09-22起票）

## 背景

`infrastructure/dynamic_way_value_cache.py` の鍵には `hour_bucket`・`speed_kmh`
（から導く `speed_bucket`）が入るが、唯一の呼び出し元 `services/gradient_way_service.py` は
`hour_bucket` に**常に `None`** を渡し、速度は渡さない。`grep -rn "hour_bucket" backend/app`
はこのモジュール自身しか出ない。風（`services/wind_way_service.py`）はこのモジュールを
**import していない**。

結果として、時刻帯・速度で値が変わる軸を地図へ配る仕組みが、鍵の形だけあって
動いていない。要件として必要（2026-09-22、判断はユーザー）。

T998段階1のやり直しで検出（グループG）。カバレッジの未到達行（`speed_bucket` の本体）も
これに由来する。

## 対応方針

呼び出し側が実際の時刻帯・速度を渡すようにする。ただし**風がこのモジュールを使っていない**
ことから、配信の設計そのものを先に確認する必要がある——専用way値レイヤーの軸が
`dedicated_way_value_layer` を通る経路と、風が通る経路が別になっている理由を確かめ、
1本道（設計原則 構造仕様3）に照らして決める。

なお同モジュールのdocstringは「風は `dict.fromkeys(feature_keys, penalty)` で作った
全キー同値のdictを渡すだけ」と現行の説明として書いているが、風はこの経路を通っていない
（comments.md「存在しないものの説明」）。同一タスクで直す。

## 完了条件

- 時刻帯を変えると地図に配られる値が変わることを実測で示す
- 鍵に入る要素がすべて実際に使われていること（常に定数が入る要素が残っていないこと）
- `dynamic_way_value_cache` のdocstringが、実際に通る経路だけを説明していること
