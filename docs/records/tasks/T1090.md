# T1090. frontendが呼ぶAPIのパスを、OpenAPIの宣言と型で照合する

状態: 完了（2026-09-24起票・2026-09-26完了）

## 背景

frontendのサービス層は、タイルのURLも含めてAPIのパスを17か所すべて手で書いている（services/*.ts）。OpenAPIの生成物（types/generated/api.d.ts の paths）には同じパスが宣言されているが、突き合わせる仕組みが無いため、backendでパスを変えると画面から実際に呼ぶまで食い違いに気づけない。案: パスの文字列を paths のキーとして型で縛る（例: satisfies keyof paths）。T1001段階Aの見直しでタイルのパスの手書きとして見つけた。サービス層の全呼び出しへ当てるかを1つの判断として決める（2026-09-24、ユーザー承認）。

## 実施（2026-09-26、T1112のクラウドのセッション）

判断: サービス層だけでなく、frontendからbackendのAPIを呼ぶ全箇所へ当てる（一部だけにすると、当てていない呼び出しが食い違いを
黙って抱える）。母集団は`grep -rnE "[\`'\"]/(api|health)" frontend/src`（テスト・生成物を除く）と、`/api/`を含む行の目視で数えた
呼び出し元9ファイル（`services/`の天気・地域・軸カタログ・材料カタログ、ルート、管理画面、気象タイル、背景地図の地図スタイル）。
対象外は3種類で理由付き: 管理APIのプロキシの接頭辞（任意のパスを転送する。パスではない）・`paths`から引く型の参照・frontend自身の
route handler（`/api/version`、backendの宣言に無い）。サーバー側からbackendを呼ぶのは管理APIのプロキシ1本だけ。

`lib/apiPath.ts`: `apiPath(path, params)`は`paths`のキー（`ApiPath`）と`{名前}`の値を受け取り、印の付いた型`DeclaredApiPath<P>`を返す。
骨格（`adminRequest`は`/api/admin/...`の印だけ、生成のPOST・地点の取得）はこの型しか受け取らない。ベースURLは呼び出し側が付ける
（APIは`API_BASE_URL`、タイルと地図スタイルは`tileBaseUrl()`）。管理画面の呼び出しは`/api/admin`より後だけを書いていた形から、
完全なパスを渡して骨格が接頭辞を外す形にした。

検証: `tsc --noEmit` 0件（`next typegen`の後）。呼び出し元の1つを宣言に無いパス（`/api/weather/amedaz`）へ変えると型検査が
その行で落ち、POSTの骨格へ手書きの文字列を渡すと`DeclaredApiPath`でない旨で落ちることを確かめて元に戻した。`apiPath.test.ts`
（埋める・残す・複数区切りの値・宣言に無いパスと名前は`@ts-expect-error`）。変更が届くテスト28ファイル444件passed。prettier・eslintは
変更したファイルで0件。

規模の札: 実装＋テストの変更行233（実装+136/−71・テスト+26/−0）で**規模M**（起票時の予想はS——呼び出し元を
サービス層だけと見ていたが、全箇所へ当てると9ファイル、管理画面の骨格の受け取り方も変わった）。
