# T610. 災害系レイヤー7種を1つの「災害」チップへ統合する 規模M

状態: 完了（2026-09-06。7種の統合まで。要素ごとの表示切替UIは[T612](T612.md)へ分離）

## 背景

ユーザー要望「災害系のパネルを1つにまとめたい。竜巻、落雷、土砂、大雨、浸水、洪水の
6つを1パネルにできない？」。挙げられた6つに加え、雷ナウキャストも竜巻・落雷と同じN3配信で
災害性も同格のため7種として束ねる方針、既定ONを維持する方針をユーザー確認のうえ決定した。

統合前、「環境」グループのメンバーは11個（標高図・勾配・降水・風・雷・竜巻・落雷・土砂・
大雨・浸水・洪水）あった。走行中のスマホという主用途に対してチップ列が長すぎるうえ、
`page.tsx: FIXED_LAYER_VISIBILITY_DEFAULTS`がキキクル4種を既定ONにしている（T420/T606）
一方で「環境」グループは排他ドメイン`"area"`に属するため、ユーザーが環境グループのチップを
1つ触った瞬間に他が全てOFFになる。キキクル4種の同時表示が成立するのは初回ロードの一度きり
で、以後はlocalStorageに保存され復元されない状態だった。

## 対応方針・実装内容

T432で導入済みの「1グループ＝複数の名前付きソース」機構（`DynamicWeatherGroupState`）へ
そのまま乗せた。raster 5・vector 1・gridMark 1という異なるkindの混在も既存の型で表現できる。

- `mapLayers.ts`: `MapLayerId`の7つ（`thunderNowcast`/`tornadoNowcast`/`liden`/
  `landslideRisk`/`heavyRainRisk`/`inundationRisk`/`floodRisk`）を`disaster`1つへ置換。
  `MapLayerCategory`へ`"disaster"`を追加し、`mapOverlayGroupFor`は`"environment"`を返す
  （「環境」グループのメンバーとして並ぶ）が、`mapOverlayExclusiveDomainFor`は
  `category="disaster"`のとき`undefined`を返して排他制御から外す。
- `dynamicWeather.ts`: `CHIP_DYNAMIC_WEATHER_LAYER_IDS`を7要素→`"disaster"`1つへ。
- `MapView.tsx`: `DYNAMIC_WEATHER_RENDERERS`へ`disaster`グループを1つ置き、7要素を
  `heavyRain`/`landslide`/`inundation`/`thunder`/`tornado`/`flood`/`liden`の順の
  名前付きソースにした。この順序がMapLibreのレイヤー追加順＝重なり順になるため、面
  （ラスタ5枚）を下に、線（洪水）・点（落雷）を上に置いている。
- `useDynamicWeatherLayers.ts`: `show*`7個を`showDisaster`1つへ。3本のフェッチ
  （キキクル・雷竜巻・落雷）はいずれもこの1フラグで開閉する。`dynamicWeatherDataStatus`は
  3本のloading/errorをまとめ、7ソースのいずれかが描画できていればloading/errorとしない
  （`precipitationNowcast`の既存パターンと同じ）。
- `page.tsx`: `FIXED_LAYER_VISIBILITY_DEFAULTS`を`disaster: true`へ。旧7キーの移行処理は
  不要（`deserialize`が現在のキー集合だけを走査するため、localStorageに残る旧キーは
  無視され、`disaster`は既定値trueが使われる）。凡例は`DISASTER_LEGEND_DETAILS`として
  キキクル5段階・雷活動度・竜巻発生確度・落雷の4ブロックにまとめた——T432でキキクルの
  凡例を確認する導線が失われていた点も、これで解消する。
- `MapOverlayControls.tsx`: `LAYER_ICONS`を`disaster: ShieldIcon`1行へ。未使用になった
  `TornadoIcon`/`LidenIcon`は`icons.tsx`から削除した（`ThunderIcon`は`weatherCode.ts`が
  引き続き使うため残す）。

## 面レイヤーの重なりについて（既知の制約、T612へ引き継ぎ）

統合により、面レイヤー5種（土砂・大雨・浸水・雷・竜巻）が同時に表示されうるようになった。
いずれも半透明ラスタ（opacity 0.65）のため、重なった領域は混色して危険度5段階を正確に
読み取れない。キキクル3種は3つとも同じ配色（`riskMap.ts: RISK_LEVEL_COLORS`）のため、
色から災害種別を判別することも原理的にできない。形状の異なる洪水（線）・落雷（点）は
面の上に乗るため識別できる。

「重なっているなら最も危険な1枚だけ出す」といった自動制御は実装できない——気象庁は危険度を
ラスタ画像でしか配信しておらず、現在の警戒レベルを返すJSON APIが存在しない（T420で実機
確認済み）。

ユーザー判断（2026-09-06）: 面を1つに絞る排他ではなく、**複数選べる形にしてユーザーに
任せる**。切替の手段は災害チップ専用のUIを作らず、[T612](T612.md)（▶パネルを表示専用から
操作可能にする全チップ共通の内訳トグル）で用意する。それまでの間は7種が常に同時表示となる。

なお平常時は危険度ゼロの領域が配信元のタイルで透明のため、7種すべてONでも地図の見た目は
変わらない（T420実装メモで実機確認済み）。
