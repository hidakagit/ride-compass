- 対応方針・実装メモ:
  - 要確認だった項目8はT462（openrouteserviceエンジン完全削除、2026-08-31完了・push済み）を
    確認したところ`api/dependencies.py`のエンジン分岐は既に削除済みで、`client_id`関数は
    衝突なく単独で存在していたため通常どおり対応した。
  1. `to_definition()`/`_to_response()`: `AxisDefinitionPayload`/`AxisDefinitionResponse`は
     いずれも`AxisDefinitionFields`（フィールド定義の唯一のソース）へバリデータ・`display`を
     足すだけでフィールド自体は追加しないため、`AxisDefinition(**self.model_dump())`/
     `AxisDefinitionResponse(**definition.model_dump(), display=...)`へ置き換え、
     16フィールドの手書き列挙（片側更新漏れの温床）を撤去した。
  2. `_status_count`（2ファイル）・`_chunked`（3ファイル）を`app/batch/_common.py`の
     `status_count`/`chunked`へ統合。テストも各ファイルへ重複していたため
     `tests/test_batch_common.py`へ集約し、重複が0件になったtest_precompute_elevation_
     attributes.pyは削除の代わりに「共有実装をそのままimportしていることの確認」テストへ
     作り替えた（ファイル削除がauto mode classifierにブロックされたため）。
  3. `match_designations.py`: 派生データ系譜追跡用run id取得を`_MATCH_SQL`実行「後」から
     「直前」へ移動。以前は別プロセスのimport_pbf.pyがマッチング実行中に完了すると、
     実際にマッチしたosm_raw_waysより新しいrun idが記録される不整合があった。
  4. `basemap_refresh`（無認証）: 対応不要と判断。axis_admin.py/debug_admin.pyと同じ
     `require_admin_basic_auth`を追加する案を実装したが、このエンドポイントは一般ユーザー
     向け地図UIの「変わらないデータを更新」ボタン（MapView.tsx: refreshBasemapCache）から
     直接叩かれており、本アプリにはユーザーアカウント自体が無い（/adminは別surface）ため
     管理者認証を付けると一般利用者の機能が401で壊れる。実装後にこの依存関係へ気づき撤回、
     コメントで経緯を残すのみに留めた（既存のレート制限で妥当な歯止めと判断）。
  5. `health.py: db_status`: フロントエンドからの呼び出し元が無い（純粋な運用診断API）ことを
     確認したうえで`require_admin_basic_auth`を追加。テーブル行数・migration適用状況等の
     運用上機微な情報を返すため。
  6. `axis_admin.py: unpublish_axis_definition`の`assert definition is not None`を、
     `python -O`実行時に消えない`if`+`raise RuntimeError`へ置き換え。
  7. `*_import_runs`のrunning行がプロセスクラッシュで永久残留する問題: `_common.py`へ
     `reap_stale_running_import_runs(conn, table)`（started_atが6時間より古いrunning行を
     failedへ遷移、次回実行時に自己修復）を新設し、import_pbf.py/import_accidents.py/
     import_designations.pyのrun()冒頭（新規running行INSERT前）へ配線した。
  8. `api/dependencies.py: client_id`: `request.client`がNoneのとき固定文字列"unknown"へ
     フォールバックする既存挙動自体は変えず、運用側が検知できるようWARNINGログを追加。
  9. `region_axis_inspector`: タイル向け`road_tile_rate_limit_per_minute`（`_check_tile_rate_
     limit`経由）の流用をやめ、専用設定値`axis_inspector_rate_limit_per_minute`（既定値は
     同じ120/分、挙動は変更なし）を新設して分離した。road_tile側の値をタイル配信の事情で
     調整するたびに無関係なaxis-inspectorの上限も意図せず変わる結合を解消。
  10. `debug_admin.py: read_recent_logs`: `limit`に`Query(gt=0)`を追加。0以下を渡すと
      `lines[-limit:]`のPythonスライス仕様上「末尾からN件」ではなく異なる範囲を返す不具合
      （例: limit=-5は「先頭5件を除く全件」）を防ぐ。上限側はリングバッファ自体が最大
      1000件しか保持しないため実害が無く、追加のバリデーションはしなかった。
  11. `import_accidents.py`/`import_designations.py`のファイルダウンロード直列await:
      対応不要と判断。ダウンロード件数は少なく（accidents: 年数分、designations: 2kind×
      関東7県=14件）、いずれも外部の政府データソース（警察庁・国土数値情報）への負荷配慮上
      並列化のメリットよりリスクが上回ると判断し、コメントで理由を残すに留めた。
  12. `precompute_edge_attribute_counts.py`: run id取得をチャンク処理開始前の1回から
      チャンクごとの直前へ移動（3の修正と同種）。**追加スコープ（当初のT426棚卸しでは
      未検出）**: 同型の重複実装である`precompute_way_attribute_counts.py`にも全く同じ
      パターンの不整合があったため、CLAUDE.mdの「共有パターン変更時は取り残された消費者を
      grepで確認する」原則に基づき同様に修正した。
- 発見した無関係な既存環境ドリフト（対応せず別タスクへ切り出し）: `tests/test_health.py`の
