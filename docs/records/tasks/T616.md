# T616: 「ルート設定」の実機調整（生成ボタンをタイトル行へ・数値入力の排除・目的地モード自動武装）

状態: 完了（2026-09-06）

## 背景

T614（「ルート設定」パネルの2タブ化）を本番実機で確認したユーザーから、以下の追加調整
依頼があった。

1. 原則としてユーザーに直接数字入力させたくない。「生成条件」タブの距離はスライダー、
   候補数も簡素に選択できるUIにする（省スペースで）。
2. 目的地モードを選んだら、デフォルトで目的地を地図タップで指定できる状態（armed）に
   する。現状はゴールアイコンを押さないとarmedにならず違和感がある。
3. 「ルート生成」ボタンはタブの外（現状: `<form>`末尾）ではなく、「ルート設定」の
   タイトル行（デスクトップ`Disclosure`のtrailing、モバイル`BottomSheet`のheaderAction、
   「ルート結果」の`renderRouteResultHeaderActions`と同じ場所）に置く。

「除外する道路を別タブにしては」という提案も受けたが、現状チェックボックス3件で既に
折りたたみ済み（高さへの影響が小さい）ため今回は見送り、将来項目が増えたときに再検討する
（ユーザーへ提案し合意）。

## 対応方針

- `RouteForm.tsx`から生成ボタン・エラー表示・検証ロジックを`useRouteFormSubmit`
  （新規hook）へ抽出し、page.tsx側のヘッダーアクションから呼べるようにする。
- 距離入力を`<input type="range">`スライダーへ、候補数入力を`‹ 8 ›`形式の
  ステッパー（-/+相当）へ置き換える。数値の直接入力欄は撤去する。
- `page.tsx: handleRouteModeChange`で、目的地モードへ切り替えた時点で
  `destination === null && waypoints.length === 0`（まだ何も指定していない）なら
  `destinationArmed`を自動でtrueにする。既に目的地・経由地がある場合は既存の状態を保つ
  （タップの意図がずれるのを避けるため）。

## 実装内容

- `RouteForm.tsx`から`<form>`・生成ボタン・エラー表示・検証ロジックを撤去し、
  新規`useRouteFormSubmit.ts`（`{error, handleSubmit}`を返すhook）へ抽出した。
  `isMaxRoutesRelevant(routeMode, waypointCount)`を`RouteForm.tsx`・
  `useRouteFormSubmit.ts`共通の単一情報源として切り出した。
- `page.tsx`: `useRouteFormSubmit`を呼び出し、新規`renderRouteSectionHeaderActions()`
  （「ルート生成」ボタン、`Button variant="primary" size="sm"`）を「ルート設定」見出し行
  （デスクトップは`Disclosure`の`trailing`、モバイルは`BottomSheet`の`headerAction`、
  「ルート結果」の`renderRouteResultHeaderActions`と同じ場所）へ配置した。
  `renderRouteSectionBody`は`routeFormSubmit.error`・`errorMessage`の両方を表示する。
- 距離入力を`<input type="range">`スライダー（現在値をkm表示、テキスト入力欄なし）へ、
  候補数入力を「‹ 8 › 件」形式のステッパー（-/+ボタンのみ）へ置き換えた。数値の
  直接入力欄はどちらも撤去した。
- `page.tsx: handleRouteModeChange`で、目的地モードへの切り替え時に
  `destination === null && waypoints.length === 0`なら`destinationArmed`を自動でtrueに
  する。既存の目的地・経由地があるときは自動武装しない。
- 波及した簡略化: 候補数がステッパー操作のみで1〜15の整数文字列以外になり得なくなった
  ため、`handleGenerate`内の`effectiveMaxRoutes`のNaN/範囲外フォールバック計算
  （常に到達不能になった）を撤去し`Number(maxRoutesInput)`に簡素化した。
- テスト: `RouteForm.test.tsx`を新UI（スライダー・ステッパー・タブ）向けに全面書き換え、
  検証ロジックのテストは新規`useRouteFormSubmit.test.ts`へ移設。`page.test.tsx`は
  候補数入力への直接数値入力を前提にしていた3件（うち2件は新UIでは再現不能な
  シナリオのため削除、1件はステッパー操作へ書き換え）を是正し、目的地モード自動武装の
  新規テスト2件を追加。
- 副次対応: `page.tsx: handleMobileTabClick`のReact Compiler警告
  （`react-hooks/preserve-manual-memoization`、`useRouteFormSubmit`hook追加による
  コンポーネント全体の推論変化が原因）を`useCallback`の依存配列へ`setMobileSheet`を
  明示することで解消した（挙動に変化なし、setState関数は常に安定参照のため）。
