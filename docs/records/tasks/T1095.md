# T1095. 経路探索エンジンのテストが持つ探索構造の偽物（FakeLazyGraph・FakeCsr等7種）を、本物の型で作る形へ置き換える

状態: 完了（2026-09-25）

## 背景

T1094で道路グラフと座標の偽物を本物の型へ置き換えた際、同じtest_road_graph_engine.pyにdomain/routing.py・domain/attributes.pyの型をまねた偽物が7種（LazyRoadGraph・CsrGraphStructure・SearchGraphStatics・TurnExpandedStructure・TurnExpandedTree・NodeJunction・ElevationAttributeの代役）、組み立て30箇所残っていると分かった。偽物は本物と形が既にずれている（FakeCsrは本物の必須フィールドindicesを持たず、FakeTreeはstate_cost等を持たない）。本物が変わっても偽物は黙って古い形のまま通る。完了の条件の案: 7種を消して本物で作る。本物で作れない入力でしか成り立たないテストはテストを弱めずに要確認として出す。置き換え前後の件数・行・対象モジュールの行/分岐カバレッジ・T1021完了の条件7の(a)(b)の数を並べる。規模の根拠: ファイルは1本だが組み立て30箇所を本物で組み直すため変更行が200を超える見込み。起票案 kihyoan-engine-test-search-structure-fakes として2026-09-25承認。

## 方針

担当W-engfakes。origin/master e3faed49 の上で行った。実装は変えていない。

- **範囲**: 題名の7種に、同じ性質（7種の本物の型の代役を、読む属性だけ持つ器で作っている）の`Bag`1箇所を加えた——
  `ring_world`が文脈へ渡していた`turn_structure=Bag(state_count=3, target_state=[0])`（`TurnExpandedStructure`の代役）。
  `Bag`の組み立てのうちキーワードに7種のフィールド名を持つものをASTで拾い、この1件だった。
- **作り方**: 本物の型のコンストラクタで直接作る（`domain/routing.py`の組み立て関数は通さない——このファイルは探索カーネルを
  差し替えて見ており、組み立て関数を通すとその実装に結果が依る）。足した作り方は2つだけ:
  `elevation(edge_id, **fields)`（Pydanticのモデルは位置引数を取らないため）と、
  `turn_tree(state_count, *, node_*)`（木。エンジンが読むのはNode側だけで、状態側を辿る経路の復元は各テストが
  差し替えるため、状態側は「どの状態にも届いていない」値で埋める）。
- **本物の型が要る値で埋めた入力**: CSRの`indices`は各世界のグラフから求めた値を書いた（`search_world`・`ring_world`・
  `via_world`は`entry_edge_index`・`indptr`がそのグラフの並びと一致していたので、それに合う`indices`を足しただけ）。
- **本物の型の説明に合わせて値を直した入力**（テストの主張は変えていない）:
  - `test_origin_states_are_the_edges_leaving_the_node`: `entry_edge_index`が`[7, 8, 9]`（区間が3本しか無いのに添字7〜9）
    だったのを、区間3本の並べ替え`[2, 0, 1]`にした。「エントリ位置ではなくEdge indexを返す」ことは位置`[0, 1]`と
    値`[2, 0]`が違うことで引き続き区別できる。
  - `test_destination_states_are_the_edges_entering_the_node`: 遷移構造の`indptr`が長さ1だったのを、本物の説明どおり
    長さ`state_count + 1`（遷移なし）にした。
  - `make_duration_context`: 状態2個の構造に存在しない遷移先`5`を置いて「区間から出る遷移は複数ある」を作っていたのを、
    グラフへ`n1`から出る区間`e2`を足し、実在する遷移先（状態2）にした。
  - 到達しなかったNodeの距離・秒は本物の説明どおりNaNにした（`test_add_terminal_candidate_does_nothing_…`。以前は0）。
- **偽物にしか無い形**: 見つからなかった（本物で作れない入力でしか成り立たないテストは0件）。保留は無い。
  ただし`ring_world`・`via_world`の木は、構造と矛盾する値を持つ（`ring_world`は6 Nodeすべての最良の状態が0、
  `via_world`の後ろ向き木はNode 0の最良の状態が始点の違う区間1）。どちらもエンジンが読まない列で、型は拒まない。
  木は差し替えた探索カーネルが返す作り置きの答えなので、そのままにした。

## 効いていることの確認

本物の型を実行時に作り変えるpytestプラグイン（`-p`で読み込み、`app.*`の読み込み済みモジュールが持つ本物の型を作り変えた型へ
入れ替える）で、置き換え前（`git show HEAD:`で書き出した旧版）と置き換え後のテストを同じ実行で流した。改名したのは、
エンジンが読むフィールド。

| 作り変え | 置き換え前 failed / error | 置き換え後 failed / error |
|---|---|---|
| `LazyRoadGraph.edge_ids`を改名 | 0 / 0 | 5 / 103 |
| `CsrGraphStructure.entry_edge_index`を改名 | 0 / 0 | 2 / 103 |
| `SearchGraphStatics.edge_length_m`を改名 | 0 / 0 | 2 / 103 |
| `TurnExpandedStructure.edge_to`を改名 | 0 / 0 | 1 / 103 |
| `TurnExpandedTree.node_cost`を改名 | 0 / 0 | 2 / 34 |
| `NodeJunction.cost`を改名 | 0 / 0 | 2 / 18 |
| `ElevationAttribute.elevation_gain_m`を改名 | 3 / 0 | 5 / 0 |
| 7種すべてへ既定値の無いフィールドを追加 | 3 / 0 | 13 / 103 |
| 7種すべてへ既定値付きのフィールドを追加 | 0 / 0 | 0 / 0 |

置き換え前は、`LazyRoadGraph`等6種のどれを改名しても全件通っていた（偽物が古い名前を持ち続けるため）。`ElevationAttribute`だけは
置き換え前も3件落ちる——実装自身が`_reverse_elevation_attribute`で本物を組み立てるため。errorはフィクスチャ（`search_world`等）の
組み立てで落ちたテスト。既定値付きのフィールドの追加はどちらも検知しないが、既存の組み立ても実装の読み方も変わらないので検知しなくてよい。

## 範囲外

同じファイルに、7種以外の自分が持つデータ型の代役が残る（直していない）:

- `FakeScoreMatrix`（`domain/evaluation.py: StaticEdgeScoreMatrix`の代役）。形が既にずれている——本物は`axis_scores`の2次元配列を
  持ち、偽物は列の辞書`_axis_columns`を`axis_arrays()`で返す。
- `Bag`による代役: `NodeSpatialIndex`（`build_node_spatial_index`の差し替えが`Bag(node_ids=…)`を返し、テストが`node_ids`で
  渡された引数を確かめている——本物には無い属性なので、置き換えるには記録の仕方から変える）、`SearchMaterials`
  （`Bag(graph=…, materials=Bag())`）、材料（`Bag(elevation_attribute=…)`）、`_LegCostComposer`（`composer=Bag(…)`）等。
