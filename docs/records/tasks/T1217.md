# T1217. 文書を読む構造テストが、CI の paths-ignore のため文書だけの変更では走らない

状態: 未完了（2026-09-27起票）

## 背景

周期レビュー第14回（2026-09-27）の起票案（ダッシュボード proposal-ci-paths-ignore-hole、承認済み）。

規模S（根拠: ci.yml か docs-consistency.yml と tech-stack.md の1行）

■ 背景
性質: 検知器の母集団の穴（再発: 第13回 T1149・T1152）。ci.yml:25-33 が docs/**・**/*.md を paths-ignore にしている（理由のコメント「このワークフローのどの検査の入力でもない」）。一方 backend/tests/structure/test_named_references.py:33 は .md を含む追跡ファイル全件を読む（T1127 段階Aで入った）。常に走る docs-consistency.yml は review_checks.py docs だけ。文書だけのコミットが死んだ「パス: 名前」を足しても緑で master に入り、次の無関係なコードの push が赤くなる。

■ やること
このテストを docs-consistency.yml でも走らせるか、paths-ignore を外す。規則として「ワークフローの起動条件をテストが読む対象から導く」を tech-stack.md の paths-ignore の決め方に1行足す。母集団: テストのうち .md や docs/ を読むもの（read_text・ls-files・glob を grep。今は1件）。

■ なぜ既存のタスクに入らないか
T1127 は文書の名指し、T1149 は scripts の検査。CI の起動条件は別。
