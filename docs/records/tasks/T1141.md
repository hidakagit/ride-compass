# T1141. 材料の一覧が実行時のAPIとビルド時の生成物の2経路で届き、同じlabelが別の意味を持ち、取得失敗が空と区別されない

状態: 完了（2026-09-27）

## 背景

周期レビュー第13回（2026-09-26）の指摘。性質: 多重ドア・同名フィールドの意味の食い違い（構造仕様5）・黙った既定値。hooks/useMaterialCatalog.tsはGET /api/material-catalogを取り、そのlabelは「論理名 - 物理名」（api/routers/material_catalog.py:70-76,153-154）。ビルド時のtypes/generated/material-catalog.jsonのlabelは論理名だけ（export_openapi.py:447-450）で、読むのはroadFacts.tsだけ。export_openapi.py:439-440はJSONを「APIが失敗したときの静的フォールバック」と書くが、frontendはフォールバックせず、useMaterialCatalog.ts:50-53は失敗するとmaterials: []・loaded: trueになり失敗と空を区別しない（軸スタジオのAxisComposerは失敗しても空の選択肢を黙って出す）。roadFacts.ts:34は名前を引けないと材料idで埋める。材料はコードで決まる（再デプロイでしか変わらない）ので経路を1つにし、残した側で失敗を空と区別し、コメントを事実に合わせる。

## 方針（2026-09-27、着手時にorigin/master 5eb7b30cで確かめた）

- 母集団: 材料の一覧をfrontendへ届ける経路。`GET /api/material-catalog`の読み手（`useMaterialCatalog`→page.tsx・AxisStudio.tsx・AxisComposer.tsx）と、`material-catalog.json`の読み手（roadFacts.ts・その2つのテスト・e2e-liveのs1-map）をgrepで列挙した。両経路の材料の集合は同じ（どちらも`MATERIAL_CATALOG`の全件）。
- **残すのはビルド時の生成物**。材料はコードの宣言で決まり、frontendは同じコミットで再生成した生成物とともにデプロイされる（`docs/architecture/directory-layout.md`「backendが持つ値の一覧はtypes/generated/経由」。実行時だけに流すのは本番DBが正本の軸カタログだけ——構造仕様9）。実行時のAPIを残すと、地図のポップアップ（純関数）まで取得待ち・取得失敗を抱える。生成物を残すと取得失敗という状態そのものが無くなるので、「失敗を空と区別する」表示を新しく作らずに済む（画面の見た目は変えない）。
- `label`の意味は1つにする: 生成物の`label`は「論理名 - 物理名」（`MaterialSpec.full_label`）、論理名だけは`name`。APIと同じ名前・同じ意味で、roadFacts.tsは`name`を読む。
- 撤去: `GET /api/material-catalog`とその応答モデル、キャッシュ方針の行と`CATALOG`（他に使う行が無い）、`useMaterialCatalog`・`materialCatalogApi`とそれぞれのテスト、AxisComposerの取得待ち・0件の画面と「カタログが後から入れ替わったら下書きを作り直す」仕組み（入れ替わりが起きない）。

## 結果

- frontendは`lib/axisMaterialsCatalog.ts: MATERIAL_CATALOG`（生成物から作る）だけから材料を知る。page.tsx・AxisStudio・AxisComposerはそれを直接読み、roadFacts.tsは同じ生成物の`name`・`value_labels`・`tile_property`を読む。
- 生成物に`name`と`reference_points`を足し、`label`を「論理名 - 物理名」にした。`dtype`はJSONでは`string`へ広がるため、契約の`MaterialDType`（`MaterialCoverageEntry.dtype`）として読む。
- テストは材料を差し替えず、本物の一覧から型で選んだ材料を通す（page・AxisStudio・AxisComposer）。
- AxisComposerに残っていた、そこに無い取得（実データ値一覧。取得は`AxisScoringSection`）を述べたコメントも消した（同じ内容は`docs/modules/frontend/axis-studio.md`「categorical材料の値入力」節にある）。
- 旧いfrontendを開いたままの画面は、backendが先にデプロイされると`/api/material-catalog`が404になり、再読み込みまで軸スタジオが「0件」の画面を出す（窓はデプロイの間だけ）。
