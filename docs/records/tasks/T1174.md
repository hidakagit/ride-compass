# T1174. 軸の合成に掛け算（または閾値で効かせる形）を足すと、ルート生成がどれだけ重くなるかを測り、入れるかを決める

状態: 完了（2026-09-27）

## 背景

proposal-rain-unpavedの③「雨の後の走りやすさ」を①累計雨量と②舗装質の合成で作るには、今の軸スタジオの合成（重み付きの足し算）では「雨が多く、かつ未舗装のときだけ難しい」を表せず、掛け算か閾値で効かせる形が要る。ユーザー: 「掛け算を持ち込むとルート生成が重くなるからだったはず。どれだけ重くなるのか計測してから決めたい」。調べる段階: 都心40・60・80kmで、今の合成と掛け算を足した試作とで段階別所要（とくに時刻ごとのコストの合成）とメモリを比べる。T1161（ルート生成の計測、進行中）と同じ手順・環境（本番VMの使い捨てコンテナ）を使う。入れるかと実装は結果を見て決める。起票案 proposal-rain-product-cost（2026-09-26承認）

## 計測（2026-09-27、本番VMの使い捨てコンテナ）

配信中のイメージ（12551a00）へ、掛け算を足した試作の3ファイル（`domain/axis_definitions.py`・`axis_display.py`・`axis_raw_value.py`）だけを重ねて、
都心（35.68, 139.76）発の周回を40・60・80kmで生成した。方式は、今の合成（base、前後に2回）・時刻で変わる軸（風）を重み付きで足す（sum_dyn）・
時刻で変わる軸を掛ける（prod_dyn）・時刻で変わらない軸（舗装質）を掛ける（prod_static）。各方式1回ずつ。

| 方式 | 40km | 60km | 80km | ピークのメモリ（60km／80km） |
|---|---|---|---|---|
| 今の合成（2回） | 4.4 / 4.3秒 | 8.5 / 8.4秒 | 13.1 / 11.7秒 | 3.3／4.1〜4.5GB |
| 掛け算（時刻で変わる軸） | 3.7秒 | 9.0秒 | 13.0秒 | 3.3／4.5GB |
| 掛け算（時刻で変わらない軸） | 3.6秒 | 8.3秒 | 11.5秒 | 3.4／4.5GB |
| 時刻で変わる軸を重み付きで足す | 4.4秒 | 11.2秒 | 17.5秒 | 3.3／4.4GB |

掛け算は今の合成とばらつきの範囲で同じ（今の合成自体が80kmで2回に1.4秒ぶれた）。「掛け算を入れるとルート生成が重くなる」は成り立たなかった。
一方、時刻で変わる軸を重み付きで足し算に入れた場合だけ、軸の値の計算（60kmで2.5秒、掛け算では0.25秒）が増えて遅くなった——本番は今、風の重みが0。
