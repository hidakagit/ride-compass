# T967: 経緯コメントの残りを引き取る（T567完了後に残った分）

状態: 完了

未着手（2026-09-20起票）

## 背景

`scripts/review_checks.py docs`の検知器`経緯コメント`が全件実行で103件を出し続けている。
[T567](T567.md)（既存の経緯コメント一掃）は2026-09-06に完了扱いになっており、
[T826](T826.md)がDEFERで2ファイル42件を抱えているだけで、**残り61件には引き取り手が
いない**。参考表示のため誰もブロックされず、作業のたびに読み飛ばされている。

## 対応方針

母集団は検知器の出力そのものから導く（手で一覧を持たない）:

```
python scripts/review_checks.py docs | sed -n '/ソースコードの経緯コメント（参考、全件/,/^## /p' | grep '^  - '
```

T826が抱える`frontend/src/components/Map/axisLayers.ts`・`secondaryAxes.ts`は対象外
（あちらのトリガーで消える）。それ以外を対象にする。

1件ごとの判断はdocs/conventions/comments.mdに従う——**今も成り立つ非自明な制約・理由**なら現在形の
一文へ書き直し、経緯そのものは該当する`docs/records/tasks/Txxx.md`へ任せて削除する。
同じ内容が対応する`docs/modules/*.md`に既にあるならコード側は消す。

## 実施記録（2026-09-21）

**母集団の導出方法が変わった。** 対応方針に書いた`scripts/review_checks.py docs`の
検知器「経緯コメント」は[T986](T986.md)で削除済みで、あのコマンドはもう動かない。
削除直前のコミットからスクリプトを一度だけ取り出し、`find_source_narrative_violations`を
現在のツリーへ当てて母集団を出した（取り出したものはリポジトリへ戻していない）。

出た82件のうち、T826が持つ2ファイル40件を除く**42件**が対象。中身は2種類に割れた。

- **A: タスク記録へのリンク 26件**（`docs/records/tasks/Txxx.md`の名指し）。記録は維持
  しない文書のため、維持されるコードから辿らせると指す先が古いまま残っていることに
  誰も気づけない。リンクと、リンクだけを指していた括弧を落とした。22件はスクリプトで
  機械置換し、括弧が行をまたぐ4件と改行位置が崩れた1件は手で直した
- **B: 経緯そのもの 16件**。3群へ分けて並行で処理した。**うち15件は転記不要**——
  消そうとした背景が、対応するタスク記録・モジュール文書・実装のdocstringに既に
  同じ内容で書かれていた（二重に持っていた側を消したことになる）。今も成り立つ理由は
  現在形の一文へ書き直して残した
- 検出パターンに当たらなかった2件（`proxy.ts`の「ユーザー方針（2026-08-24）:」の引用と
  「（レビュー指摘の修正）」）も、作業中に見つけたので同時に外した

**残った1件は誤検知**。`axis_registry_service.py:219`の「一般ユーザーからは
`GET /api/axis-catalog`経由で見えていない」が、パターンの「ユーザーから」に
一致しただけで、経緯記述ではない。完了条件の「それ以外0件」はこの1件を除いて満たす
（パターンに合わせてコードの文言を変えることはしない）。

## 完了条件
