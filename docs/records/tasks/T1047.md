# T1047. タスク番号の確保を1コマンドにする（手書きの衝突判定をなくす）

状態: 完了（2026-09-23）

## 背景

CLAUDE.md「作業ツリーの安全」節の採番手順（fetch→スタブ＋台帳1行→即push、衝突したら
自分の側を振り直す）が手作業で、手書きの衝突判定を誤る実例が出た
（`git ls-tree --name-only origin/master <path>` は該当が無くても終了コード0を返すため、
存在判定に使うと常に「衝突」と誤判定する）。並行セッション・並行エージェントが1日に何度も
採番するため、文章のルールを足すのではなく手順そのものを1コマンドにする（ユーザー合意）。

## 対応

`scripts/new_task.py` を新設し、CLAUDE.md の手作業手順（1〜3）をこのスクリプトを使う
1項目へ置き換えた。`.claude/commands/task/next.md` の採番手順の言い換えも揃えた。

方式は依頼時の案（手元ブランチでコミット→push→拒否されたらfetch→rebase→振り直し）から
変えた。**手元のブランチ・作業ツリーを一切使わず、リモートのmasterそのものを土台に
一時インデックスでコミットを組む**（`read-tree`→`hash-object`→`update-index`→
`commit-tree`）。理由:

- 手元ブランチでrebaseする方式は、作業ツリーに無関係な未コミット変更が1つあるだけで
  rebaseが拒否される。実際、このタスク自身の番号確保のpushで、並行エージェントのworktree
  に常にある `.claude/settings.local.json` の変更のためにrebaseが止まった
- 手元ブランチのHEADをpushすると、そのブランチに載っている未pushの作業コミットまで
  masterへ出る
- 番号は常に「pushしようとしている土台」から導くので、振り直しはrebase衝突の解消ではなく
  「新しい土台で組み直す」だけになり、add/add衝突を扱う必要が無い。存在判定も要らない
  （土台のファイル名の最大+1。`T317-2.md`・`T145a.md`のような枝番は先頭の数字で数える）

pushが拒否されたら土台を取り直し、リモートのmasterが動いていれば組み直して再試行
（既定10回）、動いていなければ（pre-pushフック・認証等）振り直さずに失敗する。push後は
確保したコミットを手元へ取り込む（自分のコミットが無ければ早送り、あればcherry-pick。
ぶつかれば取り込みだけ飛ばし、取り込み方を表示する）。

テストはリポジトリに置いていない。`scripts/` のテストは慣習が無く（`scripts/tests/` は
現存しない）、使い捨てのbareリポジトリを要する統合テストの置き場は新しい種類の
成果物になるため、置き場を決めずに足さなかった。

## 検証

使い捨てのbareリポジトリ（seed: 本物の `docs/improvement-plan.md`・`T1045〜T1047.md`・
`T317-2.md`・`T145a.md`・`tasks-without-own-file.md`・本スクリプト）と、それをoriginにした
一時クローンで実行した（スクラッチの `try_new_task.py`）。観測値:

1. 通常の採番: T1048を確保。pushしたコミットは2ファイルだけ
   （`improvement-plan.md | 1 +`・`T1048.md | 7 +++++++`）、台帳行は節の最後のタスク行
   （T1047）の直後、「見送りとして…」段落の前に入った
2. 取り合い: Bのpre-pushフックの中でAにT1049を先に取らせると、Bは
   「T1049 のpushは先を越されました…振り直します（1/10回目）」を出してT1050を確保。
   リモートにT1049.md・T1050.mdが両方あり、台帳にT1048〜T1050の3行が揃った
3. 未pushコミット＋未コミット変更＋未追跡ファイルのある別ブランチから: T1051を確保。
   pushしたコミットは2ファイルだけで、未pushの作業コミットはリモートのログに無い。
   手元は `M other.txt`・`?? untracked.txt` のまま、スタブはcherry-pickで取り込まれた
4. ステージ済みの変更がある: T1052を確保し、取り込みだけ飛ばした
   （`your local changes would be overwritten by cherry-pick`）。`A  untracked.txt` はそのまま
5. 手元で台帳を編集中: T1053を確保し取り込みを飛ばした。手元の編集は残り、
   `CHERRY_PICK_HEAD` は残らない
6. 節の指定「の指摘」: 一致した4つの見出しを候補として出し、終了コード1
7. フックが拒否（リモートは動かない）: 振り直さずに「リモートのmasterは動いていない」で
   終了コード1
8. 4クローンから同時に実行: 4本とも成功し、T1054〜T1057が重複なく割り当たった
   （最も遅れた1本は3回振り直した）
