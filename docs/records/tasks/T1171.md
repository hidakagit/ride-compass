# T1171. 評価の停止回数が、区間の端点に乗る停止要因しか数えず、端点の半分ずつが整数の列で1回ずつに丸まる

状態: 未完了（2026-09-26起票）

## 背景

T1137の作業中に担当が本番DBを読み取りで測って見つけた（2026-09-26）。停止要因は区間の端点に乗る点しか数えない（derive_counts.py _EDGE_STOP_COUNTS）。端点に乗る割合: 一時停止182/54,546・踏切（車道用）327/8,221・信号50,636/75,152等。近い点の代表がosm_node_id最小で端点でなければ数えない。端点は前後の区間が0.5ずつ持つ設計だが列が整数で1へ丸まり、交差点の信号を2回と数える。直すには件数の列を小数へ変える型の変更と本番の派生の流し直しが要る（本番DBへ書くのでL）。先に「道の途中の点を区間へどう付けるか」を決める調べの段（S）を切る。T1137（分類の規則の1本化）・T1050（信号とみなす半径）とは別の性質。起票案 proposal-stop-count-endpoints（2026-09-26承認）

## 段階

## 段階A: 道の途中の点の付け方（調べ）

### 測り方

母集団: 本番`public`の`node_materials`のうち数える種別が付くノード全件（316,990点）と、`road_edges`全件（2,582,177区間）。
まとまりは派生と同じ（種別ごと、EPSG:3857でeps=`POI_CLUSTER_EPS_M`のDBSCAN）。点が乗る区間は「区間の形が点と交わる」で取った。

| 種別 | 点 | 端点に乗る点 | 途中の点 | まとまり | 今数えているまとまり（代表が端点） |
|---|---|---|---|---|---|
| 信号 | 163,234 | 56,569 | 106,665 | 50,396 | 39,458 |
| 横断歩道 | 79,754 | 3,456 | 76,298 | 49,028 | 2,524 |
| 一時停止・徐行 | 54,570 | 185 | 54,385 | 37,106 | 156 |
| 踏切 | 8,429 | 336 | 8,093 | 5,085 | 288 |
| 車止め・減速構造 | 11,003 | 3,895 | 7,108 | 8,930 | 3,379 |

付け方の良し悪しは「経路の上で何回と数えるか」で見る。本番の道路網の上で、同じノードへ戻らない
ランダムな歩き（30区間、2万本、乱数の種1171）を作り、**歩きが触れたまとまりの数**（歩いた区間の途中の頂点か、
区間どうしの継ぎ目のノードに点があれば1回。歩きの始点・終点のノードにしか点が無ければ0.5回）を真値とし、
区間の値の和と比べた。スクリプトは使い捨て（リポジトリに置かない）。

候補:

- R0: 今の式（代表が端点のときだけ0.5ずつ、整数へ丸める）
- R0f: 今の式で丸めない
- R1: 代表1点。端点なら0.5ずつ、途中なら乗る区間に1
- R3a: まとまりを場所として数える。内側のノード＝点が乗るノードと、点を途中に持つ区間が2本以上集まるノード。
  点を持つ区間と点が乗るノードに集まる区間について、内側の端0本（点を途中に持つとき）→1、1本→0.5、2本→0
- R3b: R3aに加え、内側のノードに集まる区間はすべて（点を持たなくても）同じ規則で値を持つ

### 結果（真値の合計に対する見積もりの比 / 歩き1本あたりの平均絶対誤差）

| 種別 | R0（今） | R0f | R1 | R3a | R3b |
|---|---|---|---|---|---|
| 信号 | 1.31 / 0.505 | 0.68 / 0.236 | 0.79 / 0.160 | 1.01 / 0.064 | 1.05 / 0.060 |
| 横断歩道 | 0.12 / 0.436 | 0.06 / 0.434 | 0.76 / 0.112 | 0.93 / 0.054 | 1.06 / 0.034 |
| 一時停止・徐行 | 0.01 / 0.350 | 0.01 / 0.350 | 0.78 / 0.077 | 0.87 / 0.055 | 1.10 / 0.041 |
| 踏切 | 0.11 / 0.031 | 0.05 / 0.030 | 0.99 / 0.000 | 1.00 / 0.000 | 1.00 / 0.000 |
| 車止め・減速構造 | 0.45 / 0.035 | 0.23 / 0.031 | 0.89 / 0.004 | 0.99 / 0.002 | 1.04 / 0.002 |

今の式は信号を1.3倍（端の0.5が1へ丸まり、交差点を2回と数える）、それ以外をほぼ0〜半分に数えている。
最初の測りでは歩きが同じ区間を2度通ることを許していて、1点のまとまりでも真値1・見積もり2が出た（2度通れば2回止まるので、
これは真値の定義の側の誤り）。同じノードへ戻らない歩きに直して測り直したのが上の表。

### 決めたこと: R3b

- **正しさ**: 平均絶対誤差はどの種別でもR3bが最小か同等。R3bは「まとまりが道路網の上で占める場所」を1つの規則で
  表し、場所を連結に通り抜ける経路はどこから入ってどこへ出ても合計1になる（入る区間0.5・中の区間0・出る区間0.5、
  場所を跨ぐだけの区間1）。R3aは点を描いていない流入路から入ると0.5になり、この性質が崩れる。比が1を少し超えるのは、
  真値を「点に触れたか」で定めたため——点を描いていない2本の流入路の間を抜ける経路（信号交差点を通る）を真値は0と数えるが、
  利用者から見ればその交差点で止まる。
- **R1（代表1点）を採らない理由**: 代表の選び方（`osm_node_id`最小）に意味が無く、流入路ごとに描いた信号交差点を
  代表の流入路を通る経路だけが数える（信号で比0.79）。
- **保守する量**: まとまりの代表を選ぶ規則が消え、しきい値も増えない（場所は道路網の形とまとまりだけから決まる）。
  式は段の中の1文のまま。

交差点の数（`intersection_count`）は同じ性質（端の0.5を`round`で1へ丸める）を持つため同時に直した——
枝3本以上のノードを両端に持つ区間も片端に持つ区間も1になり、経路上では交差点の数ではなく区間の数を数えていた。

## 段階B: 本番の手順（司令塔）

1. 本番DBで列の型を変える（派生を流す前ならコードのデプロイの前後どちらでもよい。古いコードも小数の列を読める——
   読み手はどれも件数を長さで割るだけ）:

   ```sql
   ALTER TABLE edge_materials ALTER COLUMN intersection_count TYPE real, ALTER COLUMN poi_signal TYPE real,
     ALTER COLUMN poi_crossing TYPE real, ALTER COLUMN poi_stop TYPE real,
     ALTER COLUMN poi_level_crossing TYPE real, ALTER COLUMN poi_barrier TYPE real;
   ALTER TABLE way_materials ALTER COLUMN intersection_count TYPE real, ALTER COLUMN poi_signal TYPE real,
     ALTER COLUMN poi_crossing TYPE real, ALTER COLUMN poi_stop TYPE real,
     ALTER COLUMN poi_level_crossing TYPE real, ALTER COLUMN poi_barrier TYPE real;
   ```

   型の変更は表を書き直し、その間は表の排他ロックでタイル配信の読みが待つ（所要は未計測。同じ文を手元のテストDBで流して
   通ることだけ確かめた）。
2. このコミットがmasterへ入り、本番のbackendへデプロイされてから、`python -m app.batch.derive_cli --from counts`
   （数・面・道の段を作業用スキーマで作り直し、道路網の配列を作って入れ替え、世代を進める）。
3. 確かめ: `edge_materials`の`poi_*`の種別ごとの総和が下の見込みに近いこと、`scripts/schema_gap.py`で数の列の差が消えたこと。
