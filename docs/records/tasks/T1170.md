# T1170. どこまで源泉に従わせて導出するか（同じ事実か・機械的に引けるか・目的が違うか）の判断基準を設計原則に定める

状態: 未完了（2026-09-26起票）

## 背景

2026-09-26、T1140（画面が持つ値をbackendの宣言へ移す）で、地図のレイヤーの説明文を材料カタログの説明から引くか（ユーザーの提案「各材料の源泉の1属性にしたらだめ？」）が論点になった。担当の調べでは、道路タイルのレイヤーidは一次属性idと一致し材料カタログのtile_propertyで属性→材料が引けるが、材料の説明文（何を測るか）と今のⓘの文（地図で何が見えるか・どの評価に使われるか）は中身が違う。設計原則（design-principles.md）は原則1（frontendは描画の都合だけ）・4（正準は1か所）・8（この表の各行はどこかから導けないか）・12（母集団は導出）で「導けるなら導く」までを持つが、同じ語でも言っていることが違う場合の線引きが無い。ユーザーの指示「どこまで従属的な導出にするか、プロジェクトとして判断基準を作りたい」「起票して進めて」。司令塔のたたき台: 導出する条件は①同じ事実（源泉を書き換えたらこちらも必ず変わるべきか）かつ②機械的に引ける（手の対応表を要さない）。独立に宣言する条件は③目的が違う（ただし置き場はbackendの宣言、原則1）④対応表が要るなら表を置かず要素の宣言に属性を持たせる（原則8の具体化）。1つの文の中で同じ事実の部分だけを導出して差し込んでよい。完了条件: design-principles.mdに基準を足し、既存の原則1・4・8・12との関係を整理（重複させない）、今回の例（レイヤーの説明）への当てはめを1つ書く。文面はユーザーの確認を経てからmasterへ入れる。
