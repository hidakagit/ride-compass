# T905. レビュー基盤自身が、どの計測の母集団にも入っていない

規模M。
状態: 完了（2026-09-16）

## 対象の指し方

**対象を本文へ列挙しない**（[T876](T876.md)で決めた指し方）。母集団は
[統合レビュー第10回](../../../.claude/commands/review/history/2026-09-16_all.md)のP3の表のうち`scripts/review_checks.py`・`scripts/tests/`が対象の行（P3-1〜P3-11）で、個票（Evidence・Impact・Recommendation）は
[シャードの生出力](../../../.claude/commands/review/history/2026-09-16_all_shards.md)の該当節にある。列挙すると、列挙した側だけが古くなり、
**起票した束ねタスクが後から対象を指せなくなる**（第7回がこれに当たり、対象を確定できないまま
[T735](T735.md)が残った）。

## 型

[T890](T890.md)・[T891](T891.md)で「検知器が取りこぼしていないか」は測れるようになったが、
**検知器を書いている側のコードそのもの**はまだ死角にある。規模ウォッチの母集団外で、
1ファイルが5日で997→2,996行へ伸びても誰にも見えない。母集団を手書きしている検知器
（1ホップ固定・手書きディレクトリ・手書きファイル一覧）も残っており、これらは
[T890](T890.md)の外縁ケースで**`GAP`として現に測定下にある**——このタスクはその`GAP`を
埋める側である。

## 完了条件

- [T890](T890.md)の外縁ケースのうち、このタスクで埋めた検知器が`GAP`→`COVERED`へ変わる
  （期待値の更新もこのタスクで行う）。**埋めていないものは`GAP`のまま残してよい**
  ——「全部埋める」ではなく「埋めたものが測れている」ことが条件。
- `--since`で件数が2倍になる二重登録（P3-5）のような、結果を直接ゆがめるものは必ず含める。
- `review_checks.py`を規模ウォッチの母集団へ入れる（分割の判断自体は
  [DEFER](../../improvement-plan.md)のまま——トリガーは4,000行到達）。

## 実装メモ

### 一番大きかったのは、起票時に挙がっていなかった穴

再描画の検知器は、母集団に入れたファイルを**連結してから**コメント・文字列を空白化していた。
連結すると、あるファイルの途中で空白化の状態がずれたまま次のファイルへ入り、そこから先が
丸ごと文字列として潰れる。**実測: 526の宣言のうち186（35%）が、宣言として一度も見えて
いなかった**。母集団へ足したファイルが、足した側からは入っているように見えるのに中身は
空、という状態である。ファイルごとに空白化してから連結する形へ直した。

これは[T890](T890.md)の外縁ケースを埋めようとして見つかった——2ホップ先のモジュールを
母集団へ足しても検知されず、「母集団に入っているのに宣言が見えない」を追ったところ空白化に
行き着いた。**外縁ケースが無ければ、母集団を広げた時点で「直った」と判断していた。**

### 母集団の手書きをやめたもの

- **再描画（P3-1）**: 1ホップ固定 → 入口から**到達できる限り**辿る（相対importと
  `@/components/Map/`・`@/hooks/`）。24→32モジュール、誤検知0件。
- **webが読む層（P3-2）**: 手書き4ディレクトリ → `backend/app`配下のうちbatch自身以外。
  `main.py`（本番webが起動時に読む筆頭）が入っていなかった。
- **材料タグ（P3-3）**: 手書き3ファイル → `backend/app`配下から**除外2本**を引いた形。
  除外は`osm_adapter.py`（取込時の生のOSMタグ）と`traffic.py`（POIノードのタグ）で、
  **実測9箇所**（どちらもway_tagsではないため許可リストの対象外）。
- **同名ファイルの照合（P3-8）**: `GENERIC_BASENAMES`の手書き一覧 → 重複しているかで決める。
  対象ファイル表は列で階層を表すため`親/名前`では照合できない。代わりに
  **そのファイルにしか無い階層の語が同じ行にある**ことを求める形にした。
- **同名定数（P3-6）**: 先に見つけた1つで確定していた → **値が割れている名前は返さない**。
- **テスト足場（P3-10）**: frontendだけ → backendの`test_*.py`も（Python用の定義パターンを
  追加）。6件の重複が新たに見え、寄せ先の案内も言語で分けた（[T884](T884.md)の材料になる）。

### その他

- **二重登録（P3-5）**: `--since`で`map_redraw_coverage`が2回登録され件数が2倍になっていた。
- **規模ウォッチ（P3-4）**: `scripts/`を母集団へ入れた。`review_checks.py`は**3,569行で
  リポジトリ最大**だったが、どの表にも現れていなかった。
- **ユニットテスト（P3-9）**: 入口関数を直接呼ぶテストが無かった検知器へ**15件**追加
  （拾う例と拾わない例を対にした）。`main.py`・`hard_filters.py`が対象に入ることと、
  同名ファイルの取り違えが起きないことも、ここで固定してある。
- **README（P3-11）**: 「同じ集合を強制する」が揃えているのは**どの検知器を数えるか**までで、
  どこを走査するかは経路ごとに違う、と書き分けた。
