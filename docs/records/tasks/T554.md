# T554: フロンティア方式の折返し点選定で、同点時に方位の広がりを優先するタイブレーク

状態: 完了（2026-09-03起票・同日完了。[T531](T531.md)推敲時のユーザー質問「すごく似たルートばかり
n件生成されないか」を受けて起票。T531パッケージAの多様性間引きに続けて着手）

## 背景

T531の折返し点ランキングは`(round(平均difficulty, 1), |len_c − D/2|, node index)`で、
データが一様で同点が多い場合（周囲に該当軸のデータが無い等）、往路重複率の間引きを通っても
候補が同じ象限へ寄ることがある。8方位を生成機構として使う案はユーザーが却下済みのため、
方位は**同点グループ内のタイブレークとしてのみ**使う。

## 対応方針

1. 同点グループ（平均difficultyの小数1桁が等しい折返し候補群）の中では、採用済み候補の
   方位（`bearing_between(origin, turnaround)`）との角距離の最小値が最大のノードを優先する
   （最遠点貪欲法）。採用済みが無い最初の1件は`|len_c − D/2|`最小。
2. 同点でない場合（平均difficultyに0.1以上の差がある）は方位を一切考慮しない
   （公開軸の重み配分が主、方位は従、という優先順位を崩さない）。
3. 実装は`select_loop_turnarounds`のランキング関数内に閉じ、`RouteGenerator`側は変更しない。

## 完了条件

- 合成グリッドで「全Edge同一difficultyのとき採用候補の方位が広がる（隣接象限へ固まらない）」
  「difficultyに差があるときは方位に関係なくdifficulty順」「決定的（同じ入力で同じ順）」の
  テストがpass。
- 実機確認（Browserペイン）で、周囲に該当軸のデータが無い重み設定でもn件が複数方位へ
  散ること。

## 実装（2026-09-03）

- `domain/geo.py`に`bearing_between_array`（`bearing_between`のnumpyベクトル化版）を追加。
- `services/road_graph_engine.py`にモジュール関数`_diversify_ties_by_bearing`を追加し、
  `select_loop_turnarounds`の`np.lexsort`によるランキング直後（`select_diverse_by_overlap`
  で間引く前）に適用する。同点グループ（`difficulty_key`が等しい連続区間）ごとに、
  グループの1件目（累積で採用済みが0件の時点）だけは既存どおり`closeness_key`最小、
  それ以降は既に並べた全候補（グループをまたいだ累積）との角距離の最小値が最大の
  ノードを優先する最遠点貪欲法で並べ替える。差がある候補間の順序（`difficulty_key`
  昇順というグループ自体の並び）はこの並べ替えでは変えない。
- 並べ替え後に往路方位を計算していた既存コード（`turnarounds`構築ループ内の
  `bearing_between(origin_node, node)`）とは別に、並べ替え用の`origin_node`が二重に
  計算されていたため、後者（重複）を削除した。
- テスト: `tests/test_road_graph_engine.py`に`_diversify_ties_by_bearing`の直接テスト
  3件（全同点時の象限分散・differing difficultyでの群順序維持・決定性）と、
  `select_loop_turnarounds`経由の統合テスト1件（車輪状フィクスチャ・pool_size=4で
  4象限すべてが選ばれること）を追加。`tests/test_geo.py`に`bearing_between_array`が
  スカラー版と一致することを確認するテストを追加。
- 実機確認（Browserペイン）は本セッションの実行環境（バックエンドAPIのみ、実道路データ
  ・フロントエンド起動なし）では実施できなかった。合成グリッドのユニット・統合テストで
  完了条件の3点（象限分散・difficulty順序維持・決定性）は検証済み。
