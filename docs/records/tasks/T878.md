# T878. 一次属性`cycleway`の`shared=True`が今も要るかを判断する

規模S。
状態: 完了（2026-09-15。[T871](T871.md)の作業中に、根拠コメントが事実と違うことが
判明したため分離）

## 背景

`domain/registry_defaults.py`の一次属性`cycleway`は`shared=True`（排他チェックの対象外）
になっている。その根拠として書かれていたコメントは、**廃止済みの内部軸
`car_stress_bicycle_infra_adjustment`（[T353](T353.md)で廃止）を「現に参照している」と
述べていた**——「2軸が同じ一次属性を共有すること自体が想定どおり」という説明が、既に
成立していない前提の上に立っていた。

[T871](T871.md)でコメントは事実へ直したが、**フラグ自体の要否は判断していない**。

## 実測（2026-09-15、`axis_definitions_snapshot.json`）

`cycleway`属性に属する4材料を参照する軸:

| 材料 | 参照する軸 |
|---|---|
| `highway_is_cycleway` | `bicycle_infra_quality` のみ |
| `cycleway_has_track` | `bicycle_infra_quality` のみ |
| `cycleway_has_lane` | `bicycle_infra_quality` のみ |
| `cycleway_has_shared` | `bicycle_infra_quality` のみ |

**いずれも1軸だけ**。「複数軸が参照してよい共通の一次属性」という`shared=True`の前提は
現在のデータでは満たされていない。

## 判断: 外す（2026-09-15）

`shared=True`は「全軸が参照してよい共通コンテキスト」にだけ与える印で、今その資格を
満たすのは`geometry`（区間の形状・距離）だけである。`cycleway`は`surface`・`lanes`・`lit`と
同じ実質的な属性で、1つの軸に属するのが**排他帰属**の原則どおりの姿になる。免除の根拠
だった内部軸は廃止済みで、支えるものが残っていない。

将来`car_stress`が`cycleway`系材料を参照したくなったときは、軸スタジオでの登録が弾かれる。
これは障害ではなく設計どおりで、「2軸で重ねる」という判断をその時点で明示的に行わせる。
黙って重なるより良い。

### 衝突しないことを実データで確認した

`cycleway`属性の材料（`highway_is_cycleway`・`cycleway_has_track`・`cycleway_has_lane`・
`cycleway_has_shared`・`shared_pedestrian_path`）を参照する軸は、**本番DB・
`axis_definitions_snapshot.json`のどちらでも`bicycle_infra_quality`の1軸だけ**だった
（起票時の表は4材料だが、実際は`shared_pedestrian_path`を含む5材料。いずれも同じ1軸）。

スナップショットの公開10軸を`register_defaults()`へ通し、排他チェックを通過することを
確認した。起動時の`refresh_axis_definitions`は排他チェックを行わない（未知参照だけを見る）
ため、この変更で本番の起動が落ちる経路は無い。

## 検証

回帰テストは`tests/test_registry_defaults.py`（`shared=True`が`geometry`だけであること・
`cycleway`を使う2軸目が`AxisInputConflictError`で弾かれること）。`shared=True`へ戻すと
その2件が落ちることを確認した。

`axis-catalog.json`は`shared: false`へ再生成した（`export_openapi.py`→`npm run generate:api`）。

## 判断が要った点（記録）

- **外す**と1材料1軸の排他チェックが効くようになる。将来2軸目が`cycleway`系材料を参照
  したとき、軸スタジオでの登録が弾かれる（意図した挙動なら正しい）
- **残す**と、`geometry`と同じ「共有してよい属性」の扱いが続く。ただし現に共有している
  軸が無いため、`shared`の一覧を見た人は「2軸が使っている」と誤読する

どちらが正しいかは、`bicycle_infra_quality`と`car_stress`の関係（[T347](T347.md)で
「ニアリーイコールの推定軸」として意図的に重複させた設計）を今後どう扱うかに依存する。

## 保留することで何が起きうるか

1材料1軸原則の点検をする人が、`shared`の一覧を「複数軸が共有している属性」として読み、
実際には1軸しか使っていない`cycleway`をその例として数える。逆に、排他チェックを効かせる
つもりで外すと、`car_stress`側が将来`cycleway`系材料を参照したときに軸スタジオでの登録が
弾かれる——それが意図なのかどうかが記録に無い。
