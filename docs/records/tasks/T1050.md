# T1050. 「信号とみなす半径」の較正値を、ノードの値を埋める派生バッチが読んでいない

状態: 未完了（2026-09-23起票）

## 背景

domain/tuning.py が較正値 signal.match_radius_m（既定40m、効き方NODE_ATTRIBUTE_BATCH）を宣言し管理画面から変えられるが、実際に信号を判定する batch/derive_node_materials.py は自前の定数 SIGNAL_RADIUS_M=25.0 を使い、較正値を読んでいない（grep -rn match_radius_m backend/app の参照は宣言1件のみ、2026-09-23 T1009作業中に確認）。管理画面で変えても何も変わらず、画面の既定40mと実際の25mも食い違う。TuningEffect.NODE_ATTRIBUTE_BATCH のコメントも撤去済みの road_nodes を指す。

## 保留（ユーザー判断）: 「信号がある交差点」とみなす半径を、今効いている25mと管理画面の40mのどちらに揃えるか（2026-09-23 依頼）

利用者への約束: 管理画面に出ている較正値が、実際のルート計算に効いている値と一致すること。

いま: ルート計算は、交差点から半径25m以内に信号があれば「信号あり」とみなし、信号の無い交差点でだけ右左折・幹線の
横断の手間（費用）を足す。管理画面の較正値は40mと表示されているが、変えても何も起きない。25mになったのは道路データの
作り直し（2026-09-21）からで、それまでは40mだった。

場面: 大きな交差点で、信号が交差点の中心から30m離れた流入路に置かれていると、今は「信号なし」とみなされて横断の
手間が付き、その交差点を避けるルートが出やすい。40mなら「信号あり」とみなされ、手間は付かない。
起きない場面: 中心から25m以内に信号がある交差点と、信号の無い交差点は、どちらでも同じ。

1. **（推奨）計算が管理画面の値を読むようにし、既定を今効いている25mにする。** 今のルートは変わらず、以後は管理画面で
   変えられる。正しい値はターンの費用の較正（[T801](T801.md)、実走待ち）で決める。
2. **計算が管理画面の値を読むようにし、既定を40mに戻す。** 9/21より前のルートの傾向に戻る（信号ありとみなす交差点が
   増え、横断の手間が付く交差点が減る）。

**ユーザー決定（2026-09-23）**: 1（計算が管理画面の値を読むようにし、既定は今効いている25m）。正しい値はT801の較正で決める。
