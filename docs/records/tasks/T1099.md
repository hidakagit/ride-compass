# T1099. 風の詳細格子の間隔を「キャッシュ共有のため離散的な段階だけ」とする注記が今も成り立つかを確かめ、成り立たなければ本当の理由へ直す

状態: 完了（2026-09-25起票、2026-09-25完了。保留の答えを受けたT1101のコミットで閉じた）

## 背景

T1021群6の/code-reviewで、設計書に足しかけた「間隔が割り切れれば格子点の値のキャッシュが段階をまたいで使い回せる」が成り立たないと分かった（backendに格子点単位の値のキャッシュは無く毎回ローカルの.omから補間する。HTTPキャッシュは間隔を含むURL単位）。同じ性質の注記がdomain/wind_grid.pyのWIND_GRID_DETAIL_ALLOWED_SPACINGS_DEGとapi/routers/weather.pyに残る。表示範囲は利用者ごとに違うので、間隔を段階に固定してもURLが一致することはほぼ無く、「共有」が何を指すかは確かめていない。規模の根拠: 調べる段と注記・設計書の数行。起票案 kihyoan-wind-grid-spacing-note として2026-09-25承認。

## 調べたこと（2026-09-25、担当 W-windnote）

**「キャッシュ」が指しうるもの**を、格子点の座標（またはその丸め）を鍵に使う仕組みとして両側から列挙した。

- backend: `grep -rn "lru_cache|functools.cache|TTLCache|LRUCache|get_json|set_json" backend/app` の全件（気象庁の警報・
  アメダス・WBGT・洪水予報・タイル・グラフ・軸の依存順）に、風の格子点の座標を鍵にするものは無い。`msm_client.py`は
  モジュール水準の保持を持たず（`^_x =`の代入0件）、`read_series`は毎回手元の`.om`から補間する（ログの`cache=hit`は
  手元のファイルを読んだという意味）。`services/weather_service.py: get_wind_grid`も保持しない。`wind_way_service.py`は
  値をキャッシュしないと明記し、`docs/modules/backend/dynamic-way-values.md`も同じ（1タイル2.8msの節約が保持に見合わない）。
- HTTP: `api/cache_policy.py`で`/api/weather/wind-grid`の前方一致により`wind-grid-detail`も`SHORT`（public, 5分）。
  鍵はURLで、画面（`services/weatherApi.ts: getWindGridDetail`）は表示範囲の四隅をそのまま（丸めずに）クエリへ入れる
  ——間隔を段階にしても、利用者の間でも同じ利用者の中でもURLが一致することはほぼ無い。共有の中継キャッシュ
  （nginxの`proxy_cache`等）の記述はリポジトリに無い（`git grep "proxy_cache|s-maxage"`で実装0件）。
- frontend: 座標を鍵にするのは`windLayer.ts: mergeWindGridKeepingStale`（取り損ねた点を前回の値で補う。
  `"緯度,経度"`の文字列で点を見分ける）だけ。1人の画面の中の持ち越しで、利用者の間で共有するものではない。
  `useWeatherGrid.ts`は間隔が変わった回は持ち越しを捨てる。

**注記が指していたもの**: 間隔を段階に限った変更（0c539e24、2026-08-21）の時点では、Open-Meteoの応答を
`weather_client.py`が緯度経度を丸めた値を鍵に30分保持し、利用者の間で共有していた（`cache_key(point)`。
記録 2026-08-20.md の詳細格子の節）。これは気象庁MSMへの移行（T645 段階1、63aea282b、2026-09-07）で消えた。
注記だけが残っていた。

### 問いと答え（`T1099-spacing-purpose`）

- 問い: 風の詳細格子で、問い合わせの間隔を決まった段階だけに限る目的はどれか。選択肢は
  (1) 画面のズームの段に合わせた値だけを受け付ける（見た目の段の宣言として持つ）——注記にそう書く、挙動は変えない
  (2) 点数の上限を確かめる前に作る点の数を抑える下限として持つ——注記にそう書く、挙動は変えない
  (3) 段階に限る理由は無い——許可リストをやめ、下限つきの範囲で受け付ける（挙動の変更。別の作業として起票案にする）。
  推奨は(1)。
- 答え（2026-09-25）: **(3)**。起票案`kihyoan-wind-grid-spacing-range`として承認されT1101になり、T1101のコミットで
  許可リストを下限つきの範囲へ置き換えた（注記の目的もそこで書き直した）。本タスクに残る作業は無い。
