# T1032. frontend-design-system.mdが、モジュール文書の禁止事項をまとめて破っている

状態: 完了（2026-09-23）

## 背景

`docs/modules/frontend/frontend-design-system.md`は、`docs/modules/README.md`が定めた
規約に複数の点で反しており、かつ数字が実測と合っていない。

読んで確かめたもの:

- **行数・件数のメトリックを書いている。** CSS Modulesのファイル数と総行数を書いているが、
  実測はどちらも記載の約2倍。中心的なUIファイルの行数も記載の約2倍。
  `docs/modules/README.md`は責務・対象ファイル表にメトリックを書くことを明示的に
  禁じている（要素が1つ増えたときに嘘になる文は数え上げている、という基準）。
- **タスク番号を名指ししている**（複数箇所）。`docs/modules/README.md`は
  「タスク番号へのリンクもここへは書かない」と定めている。
- **未起票のフォローアップが文書に埋まっている。** 「将来的な統合候補として記録する」
  「将来の別タスク候補」という形で2件。台帳に対応する`- [ ]`行が無いため、
  `/task:next`等の機械抽出からは**永久に見えない**。
- 存在しないコンポーネントを名指ししている（この1件は[T990](T990.md)の母集団内）。
- **対象ファイル表を持たない。** frontend/backendを通じて、対象ファイル表が無いモジュール
  文書はこの文書と`batch-pipeline-dependencies.md`の2つだけ。

## 対応方針

1. 数字（ファイル数・行数）を落とす。示すべきは「その要素群が何をするか・増えたときに
   何が起きるか」であって個数ではない。
2. タスク番号の名指しを落とす。経緯を残す価値があるなら該当タスク記録側へ。
3. 埋まっている「将来の候補」2件を、**台帳へ`- [ ]`行として起票してから**本文から落とす。
   起票せずに落とすと、検討されないまま消える。
4. 対象ファイル表を新設する。
