## 問い

導く原則: 1・2。

ユーザーに求めることは、採否・判断・操作のお願い・確認のどれも、形（`tools/flow-gate/question_template.md`。写して埋める）の
とおりにファイルに書き、issue のコメントに書いて問う（hidakagit-bot の名義）。回答フォームは、ユーザーがチャットにいないとき（担当の問い）に使う。
開発機の対話のセッションでユーザーがチャットにいるときは、コメントで問わずにチャットで聞き、決まったことを「答え」のとおり記録する
（形の節・製品の言葉の決まりは同じ）。

    GH_TOKEN=$FLOW_BOT_TOKEN gh issue comment <issue の番号> -R ridecompass/ride-compass-tasks --body-file <問いのファイル>

開発機の対話のセッションがコメントで問いを残して終える（ユーザーがあとで答える）ときは、チャットに回答フォームの直リンク
（`flow.config.json: urls.form` の `/answer?issue=<番号>`）を1件1行で添える。

ゲートは、最新の「## 問い」のコメントが形に合い、答えが無ければ回答待ちにする（`tools/flow-gate/src/decide.js: decide`）。形に合わない
問いは問いとして読まない（`tools/flow-gate/src/questions.js: latestQuestion`）。回答待ちの間は、ゲートが本文の先頭に「回答する」のボタンの画像
（リンク付き）を置く。回答フォームは、その issue の最新の
「## 問い」のコメントを読み、上から問いの文 →（イレギュラーなら直前の担当の終わりのコメント）→ 判断材料・issue の本文（ゲートの印の間を除く。
畳んで）→ 回答（問いの種類で出し分ける。判断は案があれば案から1つか「どれでもない（補足に書く）」、確かめは「ユーザーが確かめる」の完了の条件ごとに
よい・よくない、採否とイレギュラーは決まった選択肢。補足は任意）→ 確認へ、と並べる。行き先は出さず、ゲートが答えから決める。保留の理由・確かめる担当の
結果など判断に要るコメントは、判断材料に書く。
問いのコメントを書く前に、本文の先頭にボタン（`tools/flow-gate/src/questions.js: withButton` の形）を書く（問いの通知から開いたときにボタンがあるように）。

- **形の決まり**（照らすのは `tools/flow-gate/src/questions.js: checkQuestion`）: 判断材料（最初の `<details>`）より前に置けるのは、
  1行目の「## 問い」・問いの文（1行）・「### 案」とその下の「- 」で始まる行（1行に1案、書いたとおりの文）・空行だけ。判断材料は
  形の節を、形の順に1つずつ、埋めて持つ（節の頭は行の頭の「**<名前>**:」。ほかの行は直前の節の中身で、表・画像も置ける。
  照らしは Pull Request の本文と同じ部品）。
- **行き先は問いに書かない**。ゲートが答えから決める。問いが持つ個別の部分は、問いの文・案・判断材料だけ。
- **案**: 「A と B のどちらにするか」を決めてほしいときだけ書き、要らなければ節ごと省く。選んだ案は答えに残る。自分の領分（どう直すか・書き方）を案に入れない。案の文と実際に当てる作業を一致させる。
- 判断に付く意思（`急ぎ` など）は、ユーザーが issue のラベルで付け外しする。
- 続ける答え（案・どれでもない・やる・もう一度やる）は、Claude が答え（案・補足）を読んで進める。見送りは閉じて、完了からは戻せない。
- 今の問いは、最新の「## 問い」のコメント。問い直すと新しいコメントになり、回答フォームを開いたあとに新しい問いが来ていれば、
  送信は断られて開き直しになる。
- 答える時点で答えられることだけを聞く。
- **聞くかどうか**: 外から見える振る舞いが変わるときだけ聞く。変わらないなら聞かずに報告して直す。聞いたら答えを待つ。
- 画面の見た目・情報量に関わる判断は、変更前と変更後の画面かモックを添え、画像ごとに画面で見える見出しを付ける。
- **画像の載せ方**: 問いのコメントは形のとおりの文だけにする。問う前に、画像だけのコメントを
  `GH_TOKEN=$FLOW_BOT_TOKEN gh issue comment <番号> -R ridecompass/ride-compass-tasks --body-file <何の画像かの説明> --attach '<画像>#<見出し>'`
  で1枚ずつ書く。出たコメントの id で
  `GH_TOKEN=$FLOW_BOT_TOKEN gh api repos/ridecompass/ride-compass-tasks/issues/comments/<id> --jq .body` を読み、`https://github.com/user-attachments/assets/…`
  の URL を判断材料の `![<見出し>](<URL>)` で指す。開発機の対話のセッションがチャットで問うときも、画像は同じく issue に載せる
  （issue の外のもの（claude.ai の Artifact 等）は、操作して見せたいときに画像へ足すだけにする）。
  画面を `capture.mjs` で撮ったときは、画像のコメントのあとに、.claude/skills/task-work/SKILL.md「作る担当」の5がキャプチャのあとに貼るのと同じ形（`<details>` で
  畳んだ脚本の全文と打った `capture.mjs` の引数）を同じ issue へコメントで書く。脚本が使った道具（モックの応答を作った調べの
  スクリプト等）があれば、それも畳んで足す。
- **製品の言葉で書く**: 実装の語（関数名・引数名）・固有名詞・タスク番号に頼らない。

## 答え

導く原則: 1。

Claude は、タスクの issue のコメントに残った答えだけを判断に使う。残し方は2つある。

- **チャット**: 開発機の対話のセッションでユーザーがチャットで決めたことは、Claude がそのやり取り（ユーザーの言葉の引用を含む）を
  タスクの issue にコメントで書き、それを答えとして扱う。ユーザーに回答フォームで打ち直させない。
- **回答フォーム**（ユーザーがチャットにいないとき）: 回答フォームがユーザーの名義で、問いのコメントの後ろに下のコメントを書く。
  補足は決定を変えない。

答えは、ユーザーがその項目に答えたものだけ。方針に答えがあっても、そこから導いた細部（例外の顔ぶれ・数字・期限）は
答えではないので問いで聞く。前の答えの範囲を広げて読まない。
案を並べた問いに、どの案も選んでいない答え（進め方だけの答え等）が返ったら、案に読み替えず問い直す。
答えの範囲を狭めても読まない。タスクの目的に入るもの（調べる対象・直す画面等）を範囲から外すのは、外す前にユーザーに問う。

## 保留と棚卸

導く原則: 1・4。

保留は「止めて、あとで決める」置き場で、ユーザーの番。ユーザーがボードの移動で1件ずつ決める（AI は決めない）。

- **保留に入る道**: 問いへの答え「保留」（補足が答えのコメントに残る）・ユーザーがボードで保留へ動かす（担当が持っていれば、ゲートがその実行を
  取り消す）。ゲートは、ユーザーが保留から出すまで保留を保つ。
- **保留する判断・実行の書き方**: Claude が保留を選びうる問いを書くとき（判断材料）の決まり。ユーザーが
  ボードで保留へ動かすときは理由を求めない（ゲートは何も書かない）。書くかはユーザーが決め、理由の無い保留を
  ずれとして挙げない。Claude が書くときは、「後で判断」等の一言メモで済ませず、影響範囲（保留することで何がブロックされるか・何が
  動かなくなるか）と、保留し続けた場合に次に何が起きうるかを書く。置き場は、その判断・実行が属するタスクの issue で、問いを書いて
  問う。すぐには答えられない・時期が来ていないなら、そのことと再開の条件を判断材料に書く。属するタスクが無いときだけ新しい
  issue にする（判断を待つためだけに issue を作らない）。
- **日付で再開するものは保留にしない**: 再開の条件が日付だけで決まるもの（日付から導けるもの・外の出来事を決まった日に見に行くものも）は、
  保留にせず未着手＋着手可能日時（.claude/skills/file-issue/SKILL.md「ラベルと種類と欄」）で待つ。保留は、人の判断か、日付で見に行けない外の出来事を待つものに限る。
- **棚卸**（ボード）: 未着手の列へ動かす → Claude の番・完了の列へ動かす → 完成（完了の条件が残っていれば戻る）・`Close as not planned` → 見送り。
  回答待ちの列へは、答えていない問いがあるときだけ入れる（無ければゲートが戻す。`docs/conventions/flow.md`「ステータスと割り当て」の「問い」）。
