## 問い

導く原則: 1・2。

問いの種類は4つ（`tools/flow-gate/src/rules.js: KINDS`）で、頭に種類を書く（「## 問い（確かめ）」）。採否（Claude が起こした改善でない
issue の入口）・確かめ（残りの完了の条件が全部ユーザーの確かめの行になったとき。「完成にしてよいか」の1つの問いの判断材料として、項目を
並べる）・イレギュラー（担当が役目を果たさずに手放したとき）はゲートが出す（`docs/conventions/flow.md`「ステータスと割り当て」）。担当が出すのは
判断だけで、ユーザーの判断が要ることは形（`tools/flow-gate/question_template.md`。写して埋める）のとおりにファイルに書き、道具で問う
（hidakagit-bot の名義）。回答フォームは、ユーザーがチャットにいないとき（担当の問い）に使う。
開発機の対話のセッションでユーザーがチャットにいるときは、道具で問わずにチャットで聞き、決まったことを「答え」のとおり記録する
（形の節・製品の言葉の決まりは同じ）。

    node tools/flow-gate/bin/ask.js <issue の番号> <問いのファイル>

開発機の対話のセッションが道具で問いを残して終える（ユーザーがあとで答える）ときは、チャットに回答フォームの直リンク
（`flow.config.json: urls.form` の `/answer?issue=<番号>`）を1件1行で添える。

道具は形を照らし（合わなければ、合わない所を出して何も書かずに断る）、本文の先頭に「回答する」のボタンの画像（リンク付き）を書いてから
問いをコメントに書く（`tools/flow-gate/src/ask.js: askTask`。問いの通知から開いた時点でボタンがある）。ステータスは書かない: 問いを受けた
ゲートが回答待ちにする（担当が持っている間は持ったまま、手放したときに回答待ちにする）。道具が途中で落ちたら、同じ問いのファイルで打ち直す
（答えの無い最新の問いが同じ文なら、書き直さない）。回答フォームは、その issue の最新の「## 問い」のコメントを読み、上から問いの文 →
判断材料（開いて）・issue の本文（ゲートの印の間を除く）と最近のコメント（上に出した問いのコメントを除く。件数は `tools/flow-gate/src/form.js: RECENT`。
新しいものが上。畳んで）→ 種類ごとに要るもの → 補足（任意）→ 確認へ、と並べる。次のステータスは見せない（答えの決定を受けたゲートが決める）。

| 種類 | フォームが出すもの | 決定 |
|---|---|---|
| 採否 | やる・見送り・保留 | やるは続ける |
| 判断 | 案があれば案から1つか「どれでもない（補足に書く）」 | 続ける |
| 確かめ | 項目ごとに「よい・よくない」と、よくなければ何がおかしいか | 続ける（よい項目はチェックが付き、よくない項目は `- [ ] 直す: …` の行が足される） |
| イレギュラー | 何が起きたか（実行へのリンク・最後の発言は最近のコメント）と、もう一度やる・保留・見送り | もう一度やるは続ける |

保留の理由・確かめる担当の結果は最近のコメントで読めるので、問いに写さなくてよい。

- **形の決まり**（照らすのは `tools/flow-gate/src/rules.js: checkQuestion`）: 判断材料（最初の `<details>`）より前に置けるのは、
  1行目の「## 問い（判断）」・問いの文（1行）・「### 案」とその下の「- 」で始まる行（1行に1案、書いたとおりの文）・空行だけ。判断材料は
  形の節を、形の順に1つずつ、埋めて持つ（節の頭は行の頭の「**<名前>**:」。ほかの行は直前の節の中身で、表・画像も置ける。
  照らしは Pull Request の本文と同じ部品）。
- **次のステータスは問いに書かない**。問いが持つ個別の部分は、問いの文・案・判断材料だけ。
- **案**: 「A と B のどちらにするか」を決めてほしいときだけ書き、要らなければ節ごと省く。選んだ案は答えに残る。
  自分の領分（どう直すか・書き方）を案に入れない。案の文と実際に当てる作業を一致させる。
- 判断に付く意思（`急ぎ` など）は、ユーザーが issue の画面でラベルを付け外しする。
- 続けるの答えは、Claude が答え（案・補足）を読んで進める。見送りは閉じて、完了からは戻せない。
- 今の問いは、最新の「## 問い」のコメント。問い直すと新しいコメントになり、回答フォームを開いたあとに新しい問いが来ていれば、
  送信は断られて開き直しになる。
- 答える時点で答えられることだけを聞く。
- **聞くかどうか**: 外から見える振る舞いが変わるときだけ聞く。変わらないなら聞かずに報告して直す。聞いたら答えを待つ。
- 画面の見た目・情報量に関わる判断は、変更前と変更後の画面かモックを添え、画像ごとに画面で見える見出しを付ける。
- **画像の載せ方**: `ask.js` は文だけを書き、画像を載せられない。問う前に、画像だけのコメントを
  `GH_TOKEN=$FLOW_BOT_TOKEN gh issue comment <番号> -R ridecompass/ride-compass-tasks --body-file <何の画像かの説明> --attach '<画像>#<見出し>'`
  で1枚ずつ書く。出たコメントの id で
  `GH_TOKEN=$FLOW_BOT_TOKEN gh api repos/ridecompass/ride-compass-tasks/issues/comments/<id> --jq .body` を読み、`https://github.com/user-attachments/assets/…`
  の URL を判断材料の `![<見出し>](<URL>)` で指す。開発機の対話のセッションがチャットで問うときも、画像は同じく issue に載せる
  （issue の外のもの（claude.ai の Artifact 等）は、操作して見せたいときに画像へ足すだけにする）。
  画面を `capture.mjs` で撮ったときは、画像のコメントのあとに、.claude/skills/task-work/SKILL.md「作る担当」の5がキャプチャのあとに貼るのと同じ形（`<details>` で
  畳んだ脚本の全文と打った `capture.mjs` の引数）を同じ issue へコメントで書く。脚本が使った道具（モックの応答を作った調べの
  スクリプト等）があれば、それも畳んで足す。
- **製品の言葉で書く**: 実装の語（関数名・引数名）・固有名詞・タスク番号に頼らない。

## 答え

導く原則: 1。

Claude は、タスクの issue のコメントに残った答えだけを判断に使う。残し方は2つある。

- **チャット**: 開発機の対話のセッションでユーザーがチャットで決めたことは、Claude がそのやり取り（ユーザーの言葉の引用を含む）を
  タスクの issue にコメントで書き、それを答えとして扱う。ユーザーに回答フォームで打ち直させない。
- **回答フォーム**（ユーザーがチャットにいないとき）: 回答フォームがユーザーの名義で、問いのコメントの後ろに下のコメントを書く。
  補足は決定を変えない。チャットで決まった答えを記録するときも、決定（続ける・保留・見送り）があれば同じ形で書く（ゲートが決定を受ける）。

答えは、ユーザーがその項目に答えたものだけ。方針に答えがあっても、そこから導いた細部（例外の顔ぶれ・数字・期限）は
答えではないので問いで聞く。前の答えの範囲を広げて読まない。
案を並べた問いに、どの案も選んでいない答え（進め方だけの答え等）が返ったら、案に読み替えず問い直す。
答えの範囲を狭めても読まない。タスクの目的に入るもの（調べる対象・直す画面等）を範囲から外すのは、外す前にユーザーに問う。

    ## 回答
    **<問いの文>**

    決定: <続ける・保留・見送り>
    回答: <選んだ案か採否・イレギュラーの選び方>（あったときだけ）
    - よい: <確かめの項目>（確かめのときだけ）
    - よくない: <確かめの項目>
      - <何がおかしいか>
    補足: <書いたときだけ>

## 保留と棚卸

導く原則: 1・4。

保留は「止めて、あとで決める」置き場で、ユーザーの番。入るのも出るのもユーザーの決定だけ（AI は決めない）。

- **保留に入る道**: 答えの決定「保留」（補足が答えのコメントに残る）と、ユーザーがボードで保留へ動かすことだけ。担当が持っている
  タスクを保留にすると、ゲートがその担当の実行を取り消す。出すのもユーザーで、出すとゲートが表で決め直す（`docs/conventions/flow.md`「ステータスと割り当て」）。
- **保留を選びうる問いの書き方**: Claude が保留を選びうる問い（判断材料）を書くときの決まり。ユーザーが
  ボードで保留へ動かすときは理由を求めない（ゲートは何も書かない）。書くかはユーザーが決め、理由の無い保留を
  ずれとして挙げない。Claude が書くときは、「後で判断」等の一言メモで済ませず、影響範囲（保留することで何がブロックされるか・何が
  動かなくなるか）と、保留し続けた場合に次に何が起きうるかを書く。置き場は、その判断・実行が属するタスクの issue で、問いを書いて
  問う。すぐには答えられない・時期が来ていないなら、そのことと再開の条件を判断材料に書く。属するタスクが無いときだけ新しい
  issue にする（判断を待つためだけに issue を作らない）。
- **日付で再開するものは保留にしない**: 再開の条件が日付だけで決まるもの（日付から導けるもの・外の出来事を決まった日に見に行くものも）は、
  保留にせず未着手＋着手可能日時（.claude/skills/file-issue/SKILL.md「ラベルと種類と欄」）で待つ。保留は、人の判断か、日付で見に行けない外の出来事を待つものに限る。
- **棚卸**（ボード）: 保留の列から出す → ゲートが表で決め直す（ふつうは未着手で Claude の番）・完了の列へ動かす → 完成（完了の条件が残っていれば
  ゲートが決め直す）・`Close as not planned` → 見送り。ほかの列への移動は、ゲートが表で決め直す（`docs/conventions/flow.md`「ステータスと割り当て」）。
