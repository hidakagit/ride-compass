## 開発機の対話のセッション

導く原則: 1・3。

開発機の対話のセッション（と、それが任せる裏の作業役）も、.claude/skills/task-work/SKILL.md の「作る担当」「確かめる担当」の手順で進める。違うのは環境だけで、
違いは次の表のとおり。表に無いことは担当と同じ。

| 項目 | 担当（Actions） | 開発機の対話のセッション |
|---|---|---|
| タスクを持つ | 担当のワークフローが持つ（`docs/conventions/flow.md`「1つのタスクを触るのは1者だけ」） | `hold.js` で持つ（下の「持つ」） |
| 進行中へ動かす | 引き受ける段（`claim.js`）が動かし、着手のコメントを書く | 持ってから `move.js <番号> 進行中 <理由>` で、理由のコメントを付けて動かす |
| 依存 | 担当のワークフローが入れてある（.claude/skills/task-work/SKILL.md「作る担当」の2） | 要る道具を動かすとき（画面を撮る・.claude/skills/run-checks/SKILL.md「手元の検査の回し方」の場面で検査やテストを回す等）だけ、作業ツリーごとに `npm ci --prefix frontend` から入れる（docs/architecture/setup.md「作業ツリーどうしで node_modules を共有しない」）。backend は .claude/skills/run-checks/SKILL.md「開発機でのbackendテストの回し方」 |
| 本番 | 接続情報を持たない。読むのも書くのも、要れば`docs/conventions/flow.md`「担当」の「開発機が要る」で返す（`docs/conventions/flow.md`「自動で進めないもの」） | 接続情報があり、読める（`run_probe.py`）。書くのは、ユーザーがチャットで言ったときだけ。完全に消す操作はユーザーが打つ（下の「本番へ書く」） |
| マージ | 確かめる担当がマージする | ユーザーの指示があれば、対話のセッションがマージする。開発機の gh で打てないもの（ワークフローのファイル `.github/workflows/` を変える Pull Request 等）は、手放して確かめる担当に任せる |
| 答え | 回答フォーム（.claude/skills/ask/SKILL.md「問い」） | ユーザーがチャットで決めたことを、Claude が issue に記録する（.claude/skills/ask/SKILL.md「答え」） |
| 言葉 | CLAUDE.md「出力言語」 | 同じ（裏の作業役の文も） |

- **決まりの出どころ**: 担当と開発機の対話のセッションは、同じ1つの出どころを読む。環境の違いは上の表と、権限の
  `autoMode` の環境の説明にだけ書く。

  | 決まり | 出どころ | 担当の読み方 | 開発機の対話のセッションの読み方 |
  |---|---|---|---|
  | 常時の決まり・規約・手順 | CLAUDE.md と、そこから指す docs/・`.claude/rules/`・`.claude/skills/` | 連携がリポジトリの設定を読む（連携の既定の `settingSources` が `user`・`project`・`local`）。指示は読む節を指すだけ（`docs/conventions/flow.md`「担当」の3） | Claude Code がリポジトリの CLAUDE.md を読む |
  | フック（日本語の検査・セッションの始まり）・言葉 | `.claude/settings.json` | 1行目と同じ | 1行目と同じ |
  | 権限（自動モード・拒否の一覧・判定役への説明） | `tools/flow-gate/settings.json`（master の版） | 連携の `settings` | セッションの始まりのフックの `settings.js`（`docs/conventions/flow.md`「担当の権限」） |
  | 周期レビューの手順 | `.claude/commands/review.md` | 1行目と同じ | 1行目と同じ |

  開発機にしか無い置き場（ユーザーの CLAUDE.md・`.claude/settings.local.json`・自動の記憶）には決まりを置かない
  （CLAUDE.md「ドキュメント階層」）。
- **持つ**: タスクを触る（issue へ書く・ステータスを動かす・作業ブランチへ push する・Pull Request を出す・マージする）前に
  `node tools/flow-gate/bin/hold.js <番号>` でタスクを持つ。種類「開発機」の実行を起こし、前の実行が終わって動き始めたら URL を
  出して戻る（それまで待つ）。もう種類「開発機」の実行が動いていれば、並ばずにその URL を出して終える（自分が持ったものなら
  持ち直さずに続け、別のセッションのものなら手放されてから打ち直す）。待っている種類「開発機」の実行は、前に打って落ちた `hold.js` が
  起こしたものとみて、起こし直さずにそれを待つ。GitHub の一時的な失敗で落ちたら打ち直す（読むのと手放すのは道具が打ち直し、
  起こすのは打ち直さない）。持てなかったら、その回は触らない。`hold.js` はステータスを
  動かさないので、持ったら続けて上の表の「進行中へ動かす」をする。触り終えたら
  `node tools/flow-gate/bin/hold.js <番号> --release <実行の id>` で手放す（id は持ったときに出た打ち方にある）。道具は持った実行を id で
  取り消しを頼み、受け付けられたら止まるのを待たずに「手放した」と出す。受け付けられなければその応答を出して 1 で終えるので、出た応答を見て打ち直すか、ブラウザでその実行を Cancel する。手放す前にまだ進行中なら（Pull Request も問いも出さず、閉じても
  いない）、`move.js <番号> 未着手 <理由>` で戻す。Pull Request を出して検証中に移っても、マージまで続けるなら手放さない。
  持てる長さはジョブの上限（6時間）までで、過ぎると止まって手放す。続けるなら持ち直す。
  この決まりは開発機の対話のセッションが従うことで効く（GitHub は持ち主を見分けない）。
- **裏の作業役に任せる**: その場で手順を書き起こさず、.claude/skills/task-work/SKILL.md の作る担当（確かめるなら確かめる担当）の手順のとおりに進めるよう渡し、
  作業役は `hold.js`・`move.js`・`ask.js` を打たない（タスクは対話のセッションが持つ）、とだけ足す。
- **本番へ書く**: 本番へ書く操作は、誰が打つかで2つに分ける。どちらも、打つスクリプトは開発機の `C:\Users\h7g4b\ride-compass-ops\`
  （コミットしない）へ置き、対象・中身・差（前 → 後）をチャットで見せてから進める。
  - 書く・作り直す・設定を変える（本番 DB へ書く・派生データを作り直す等）: ユーザーがその操作を書くようチャットで言ったときだけ、
    Claude が自分で打つ。
  - 本番のデータ・ファイルを完全に消す（取り戻せない形で消す）: Claude は、ユーザーが言っても自分では打たない（Claude の側の
    安全上の決まりで、手順書や権限の設定では変えられない）。消す話が出た時点で、ユーザーが打つ操作だと先に伝える。Claude は、
    対象・中身・消してよい状態（使っている者がいない等）を確かめてから消すスクリプトを置き、ユーザーが1行打つコマンドをチャットで渡す。

  打ったあと、前後に読んで比べるもの（`run_probe.py` の読み取り等）を読んで確かめ、ユーザーの言葉と
  結果を.claude/skills/ask/SKILL.md「答え」のとおりタスクの issue に記録する。
