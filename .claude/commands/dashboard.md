# 仕掛中のタスク

置き場と1件の形の正本は`docs/conventions/asking-user.md`「仕掛中のダッシュボード」節。先に読む。
このコマンドは呼ばれたその場で読み合わせて出すだけで、結果を保存しない（ダッシュボードの`answer`を書くのは、
ユーザーがこの一覧に答えたときだけ）。

1. **ダッシュボードを書き出す**: `ArtifactData`の`list`（url `https://claude.ai/artifact/E8G458My7xPA8RpbkU3RWF`・
   collection `pending`・`query.limit` 1000）に`out_dir`を付け、このセッションのscratchpadの下の新しいディレクトリ
   （例: `<scratchpad>/pending-<時刻>`）へ全件を書き出す。
2. **読み合わせる**（リポジトリの本体の作業ツリーで。どれも数秒）:
   - `python scripts/orchestrate.py dashboard --pending <1.のディレクトリ>` — タスクごとに件名・台帳の題名と規模・
     進めている担当（状態の表から）・件を並べ、台帳に行の無いタスクの件を「移し忘れ」として出す。状態の表が無い
     機械（クラウドのセッション・別のPC）では、その旨の1行を出して担当の様子を省く——そのまま1行で伝え、表を
     外から写して補わない。
   - `python scripts/orchestrate.py asks` — 記録に旧い形で残っている保留・操作・改善提案。出所のタスクの下へ並べる。
   - 手動で進めているタスク（`dashboard`の出力で「ユーザーが手動で進めている」）ごとに
     `python scripts/orchestrate.py prereqs <Txxx> --pending <1.のディレクトリ>` — 前提ごとの状態と残りの件数。
3. **出す**。先頭に「仕掛中のタスクN件・人の手を待っているものN件」と、出力の先頭の`!`（バックアップの0件の知らせ等）。
   そのあとタスクごとに、件名を見出しにして次の順で並べる（無いものは書かない）:
   - 誰が進めているか・どこまで進んだか（1行）。
   - **決めてほしい問い**: 件数と1行の要旨だけ。答えは`/asks`で聞く（ここでは問いにしない）。
   - **実行してほしい操作**: 1件ずつ、**ユーザーがこの一覧だけで実行できる手順**——開くURL・押す場所・貼るコマンドを
     そのまま書く。「Txxx.md参照」「手順は記録にある」で済ませない。こちらで先に確かめられる部分（リポジトリ・
     手元の設定・読めるAPI）は確かめてから出し、ユーザーの手順を減らす。
   - **入れてよいか決めてほしい改善案**: 1件ずつ「何が起きたか・何を変えるか・入れたら何が変わるか」。
   - **手動タスクの前提**: 前提ごとの状態と、残り0なら「開始してよい」。
   - **答えは出たが記録に入っていないもの**（`answer`のある件・kind `決定`）と、**移し忘れ**。
   最後に**新しいタスクの案（起票案）**を1件ずつ（題名・規模・背景・なぜ既存のタスクに入らないか）、
   最後の行にページのURL（`https://claude.ai/artifact/E8G458My7xPA8RpbkU3RWF`）。ユーザーへ見せる言葉は製品の言葉で
   （`asking-user.md`「製品の言葉で書く」）。
4. **答えを受けたら**: 操作の報告・改善案と起票案の承認/見送りは、その件の`answer`へ`済（日付）`・`承認（日付）`・
   `見送り（日付）`の形で書く（`ArtifactData`の`update`、読んだ`version`を`if_version`に付ける）。記録にしか無い件は、
   先にダッシュボードへ置いてから書く。記録へ移すのは、そのタスクのコミット（担当へ返すか、
   `python scripts/orchestrate.py board todo push "<Txxx>へ<何を>書く: <答え>" --priority 5`）。承認された起票案は
   `asking-user.md`「起票は承認制」の手順で番号を振る。見送られた起票案はダッシュボードから消すだけ。

このコマンド自身はリポジトリも状態の表も書き換えない。
