# レビュー履歴

各レビューコマンドの実行結果をこのディレクトリへ蓄積する。
レビューを毎回ゼロから行わず、「過去 → 現在 → 改善」の変化を追跡するための記録。

## ファイル命名

```
YYYY-MM-DD_<review-type>.md
```

- review-type: `overall` / `complexity` / `consistency` / `ui` / `all` / `improve`
- 例: `2026-08-16_overall.md`、`2026-08-16_all.md`
- 同日に同種を複数回実行した場合は `_2` 等の連番を付ける

## 本基盤構築以前のレビュー

2026-08-15〜16 に実施したレビューは docs/ 直下にある（context.md に一覧あり）。
これらもレビュー履歴の一部として、再発チェック・比較の参照元に含めること。
docs/ から history/ への移動はしない（improvement-plan.md 等からのリンクを維持するため）。

## 各履歴ファイルに最低限含める項目

principles.md の標準フォーマットに従っていれば自然に満たされるが、以下は必須:

- **実施日**・**対象**（範囲・対象コミット/ブランチ。`git rev-parse HEAD` の値を書く）
- **レビュー種別**
- **重要な指摘**（P0/P1）と**優先度**
- **対応状況**（起票済みT番号 / 起票案のまま / ユーザー棄却。
  後日タスク対応が進んだら追記してよい——履歴ファイルの「対応状況」欄の更新のみ許可）
- **前回からの改善**（前回指摘のうち解消されたもの）
- **新たに発生した問題**（前回時点では存在しなかった指摘）

## 運用ルール

- 履歴ファイルは追記型。過去の判断を書き換えない（誤りだった場合は削除せず
  「訂正」節を追記する。docs/ui-review-2026-08-16.md の訂正1・2が先例）
- レビュー実行時は、直近の同種レビュー1〜2件を必ず読み、
  Regression / Previous Findings セクションで対応関係を明示する
- 蓄積が増えて参照が重くなったら、/review:improve で「古い履歴のサマリ化」を提案する
  （現時点では件数が少ないため何もしない）
