# 判断待ちをまとめて出す

確認依頼の形式は`docs/conventions/asking-user.md`が正本。先に全文読む。判断の問いと回答の正本は
各タスクの記録の保留節で、状態の表には持たない（`docs/conventions/orchestration.md`「ユーザーの判断待ち」節）。

1. `python scripts/orchestrate.py decision list $ARGUMENTS`を実行する。台帳の未完了タスクの記録に
   ある、決定の段落の無い保留の単位が出る（1件の中の番号付きの項目は、その保留の選択肢）。
2. 記録の保留は、そのままでは問いにならない。1件ずつ記録を読み、asking-user.mdの形（何の画面・
   機能か／いまどうなっているか／なぜ決めるか／各選択肢で利用者に何が起きるか。推奨を先頭に）へ
   整える。記録から背景・選択肢を補えなければ問いにせず、担当（いなければ司令塔のキュー）へ
   「保留の書き直し」として回す。
3. 画面の見た目・情報量に関わる問いには、変更前と変更後の実画面かモックを添える。
4. 選択式の質問（`AskUserQuestion`）で4問ずつ出す（各2〜4択、推奨を先頭に「（推奨）」）。
5. 回答は、その`Txxx.md`の保留の単位の中へ、行頭が`**ユーザー決定（日付）**:`の段落を書く作業
   （書き方は`docs/conventions/orchestration.md`「ユーザーの判断待ち」節）として担当のエージェントへ
   返すか、`python scripts/orchestrate.py board todo push "<Txxx>の保留へユーザー決定を書く: <回答>" --priority 5`
   で司令塔のキューへ積む。記録へ書かれるまで、その保留は判断待ちとして出続ける。

このコマンド自身はリポジトリを書き換えない。記録への反映は担当エージェントの仕事である。
