# 確認待ちをまとめて出す

`/asks`・`/dashboard`（T1073で作る）ができるまでの入口。できたら、このコマンドは消す（二重に残さない）。

確認待ちの置き場は仕掛中のダッシュボードで、答えが記録へ移るまでそこに残る。記録に既にある保留・操作・改善提案の節も
拾う（置き場と1件の書き方は`docs/conventions/asking-user.md`「仕掛中のダッシュボード」節、記録の保留の書き方は
`docs/conventions/orchestration.md`「ユーザーの判断待ち」節）。問いの形式も`asking-user.md`が正本。先に全文読む。

1. 仕掛中のダッシュボード（`ArtifactData`でcollection `pending`を`list`）の全件と、
   `python scripts/orchestrate.py asks $ARGUMENTS`の出力を集める。後者は、origin/masterの全タスクの記録（閉じた
   タスクを含む）から、**判断**（決定の段落の無い保留の単位。中の番号付きの項目はその保留の選択肢）・
   **操作**（`## ユーザー操作（待ち）: …`）・**改善案**（`## 改善提案（承認待ち）: …`）を、種類ごと・タスクごとに出す。
2. 先頭に種類ごとの件数を置く。ユーザーへ見せる種類の名前は「決めてほしいこと」「ユーザーに実行してほしい操作」
   「入れてよいか決めてほしい改善案（まだ入れていない）」「入れてよいか決めてほしい新しいタスク（起票案）」とする
   （「実施」「改善の承認」と書くと、司令塔が実施したもの・司令塔が入れた改善の承認と読める）。**操作**は1件ずつ、
   本文を読んで、**ユーザーがこの回答だけで実行できる手順**として出す——開くURL・押す場所・貼るコマンドをそのまま書き、
   「Txxx.md参照」「手順は記録にある」で済ませない。司令塔が先に確かめられる部分（リポジトリ・手元の設定・読めるAPI）は
   確かめてから出し、ユーザーの手順を減らす。**改善案**は1件ずつ「何が起きたか・何を変えるか・入れたら何が変わるか」を、
   **起票案**は題名・規模・背景・なぜ既存のタスクに入らないかを出す。
3. **判断**は、保留のままでは問いにならない。1件ずつ本文を読み、asking-user.mdの形（何の画面・
   機能か／いまどうなっているか／なぜ決めるか／各選択肢で利用者に何が起きるか。推奨を先頭に）へ
   整える。背景・選択肢を補えなければ問いにせず、担当（いなければ司令塔のキュー）へ
   「保留の書き直し」として回す。画面の見た目・情報量に関わる問いには、変更前と変更後の実画面か
   モックを添える。選択式の質問（`AskUserQuestion`）で4問ずつ出す（各2〜4択、推奨を先頭に「（推奨）」）。
4. 回答・実施の報告・承認は、ダッシュボードのその件の`answer`へ書く（記録にしか無い件は、ダッシュボードへ置いてから書く）。
   記録へは、そのタスクのコミットで問いと答えをまとめて移す（記録だけのコミットにしない）。その作業は担当の
   エージェントへ返すか、`python scripts/orchestrate.py board todo push "<Txxx>へ<何を>書く: <回答>" --priority 5`
   で司令塔のキューへ積む。承認された起票案は、`asking-user.md`「起票は承認制」の手順で番号を振る。
   記録へ移るまで、その件はダッシュボードに残る。

このコマンド自身はリポジトリを書き換えない（ダッシュボードの`answer`だけを書く）。
