# タスク振り返り

タスク（または一連の作業）が完了した直後に、そのコンテキストから「今後の別タスク・別セッションに
活かすべき教訓」を抽出し、適切な置き場所へ**提案として**振り分ける。**このコマンドはどのファイルも
自動的に書き換えない。** 提案として報告し、ユーザーが承認した項目のみ反映する
（[review/improve.md](../review/improve.md)と同じ「提案→承認→反映」の型）。

## 対象

直近のセッション内で完了した作業（$ARGUMENTS があればそのタスク番号・作業内容）。
実施中に起きた次のような出来事を対象にする:
- ユーザーからの訂正・やり直し指示（アプローチが誤っていた・想定と違った）
- 「実は〜だった」という発見（ドキュメントの記載と実態が食い違っていた等）
- 既存の仕組み・ルールに隙間が見つかり、その場で埋めた対応
- 繰り返し起きている失敗パターンの再発
- 非自明な設計判断（なぜその設計にしたか、理由を残さないと後で失われる）

## 抽出手順

1. 直近のセッション内の作業を振り返り、上記5種の出来事を洗い出す。
   **一般化できないもの（このタスク限定の実装詳細・既に文書化済みの内容）は除外する**
   （メモリ記録の既存基準「保存すべきでないもの」と同じ判断軸）。
2. 各出来事について「これを知らずに次の似た作業をしたら、同じ手戻りが起きるか」を問う。
   起きないと判断したものは提案候補から外す。
3. 残った候補それぞれについて、置き場所を判定する（CLAUDE.md冒頭の「ドキュメント階層」表を
   判定基準として使う）:
   - **CLAUDE.md本体**: 毎回・無条件に適用すべき短いルールで、詳細docsへのポインタで
     足りない場合のみ
   - **docs/`<topic>`.md**: トピック別の詳細方針・経緯・具体例（`logging.md`・`testing.md`等の
     既存ファイル、または新設）
   - **`.claude/commands/review/_history.md`**（該当する場合）: レビュー基盤の運用ルールの経緯
   - **`.claude/commands/task/_history.md`**（本ディレクトリ、無ければ本skill実行時に新設提案する）:
     task基盤（`task:next`等）の運用ルールの経緯
   - **`docs/decisions/`**: アーキテクチャ・設計上の決定とその理由（既存ファイル群と同じ粒度）
   - **メモリ（`user`/`feedback`/`project`/`reference`のいずれか）**: コードリポジトリの外側にある、
     ユーザーとの協働の仕方・プロジェクトの状況に関する教訓
   - **`docs/tasks/Txxx.md`自身**: そのタスク限定の背景・決定（通常のタスク完了フローで
     既に記録されているはずなので、本skillでは重複提案しない）
4. 同じ教訓を複数箇所へ重複提案しない。最も適切な1箇所を選ぶ（CLAUDE.md冒頭の階層表の
   判定基準に従う）。

## 出力フォーマット

```markdown
# タスク振り返り（YYYY-MM-DD、対象: <タスク番号/概要>）

## 提案1: <タイトル>
- 出来事: （何が起きたか、事実ベース）
- 一般化: （なぜ今後にも活きるか。一過性のものは提案しない）
- 置き場所: <CLAUDE.md本体 / docs/xxx.md / review:_history.md / task:_history.md /
  decisions/ / メモリ（種別）>
- 変更案: （具体的な文面、差分が分かる形）

## 見送り（教訓ではあるが提案しないもの、理由つき）
```

提案は多くても3〜5件に絞る（振り返りのたびに大量の追記提案をすると、CLAUDE.md冒頭が
繰り返し警告する肥大化と同じ問題を招く）。

結果は `history/YYYY-MM-DD_retro.md` として保存する（本ディレクトリ配下、無ければ新設する）。

**ユーザー承認前にどのファイルも編集しない。** 承認された提案のみ、承認後の指示で反映する
（メモリへの保存はメモリファイル自体の作成・`MEMORY.md`への追記が「反映」に当たる）。
