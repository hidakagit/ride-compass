# タスク振り返り

タスク（または一連の作業）が完了した直後に、そのコンテキストから「今後の別タスク・別セッションに
活かすべき教訓」を抽出し、流れの摩擦と同じに、対象タスクの issue へ1件1行で記録する（`.claude/skills/file-issue/SKILL.md`
「流れの摩擦を記録する」）。**このコマンドはどのファイルも書き換えず、起票もしない。** 直し方は周期レビューが、ほかの摩擦と
合わせて原則から全体で見て決める。

## 対象

直近のセッション内で完了した作業（$ARGUMENTS があればそのタスク番号・作業内容）。
実施中に起きた次のような出来事を対象にする:
- ユーザーからの訂正・やり直し指示（アプローチが誤っていた・想定と違った）
- 「実は〜だった」という発見（ドキュメントの記載と実態が食い違っていた等）
- 既存の仕組み・ルールに隙間が見つかり、その場で埋めた対応
- 繰り返し起きている失敗パターンの再発

## 抽出手順

1. 直近のセッション内の作業を振り返り、上記の出来事を洗い出す。
   **一般化できないもの（このタスク限定の実装詳細・既に文書化済みの内容）は除外する**。
2. 各出来事について「これを知らずに次の似た作業をしたら、同じ手戻りが起きるか」を問う。
   起きないと判断したものは提案候補から外す。
3. 候補ごとに、対象タスクの issue へ「流れの摩擦:」で始まる1行（出来事）を書く。

## 出力フォーマット

対象タスクの issue へ、候補ごとに1行書く:

```markdown
流れの摩擦: <出来事（何が起きたか、事実ベース）>
```
