# テスト方針

この文書は、テストの土台の決まり（確かめる高さ・単体で確かめるか・警告・壊して確かめる）を持つ。
テストの決まりは、この文書と、同じファイルに当たる`testing-*.md`に分けてある（1つの文書を公式の目安の長さに収めるため。長さの上限は`scripts/size_thresholds.json`の`instruction_limits`）。節の名前とパターンの番号は、分けた文書どうしで重ならない。
検査とテストの回し方は[run-checks/SKILL.md](../skills/run-checks/SKILL.md)が持つ。

**新しいテストを追加するときは、[パターン](testing-patterns-runtime.md)に従って実行時間の増加を最小限に抑えること。**

## 基本原則

1. **ループで実I/O（HTTPリクエスト・新規DB接続）を繰り返さない。** N回ループの検証は、境界に到達する直前までを
   実I/O無しで埋め、境界の1〜2回だけ実際に実行する。
2. **新規リソース（DB接続・テスト環境）の構築コストはテストスイート全体で使い回せないか検討する。**
3. **速度最適化はテストが検証する内容を変えない範囲で行う。** 境界条件の実地検証は残し、その手前の準備コストだけを削る。
4. **結果を見るときはpassedの件数だけを見ない。警告も結果の一部として扱う。**

## 確かめる高さ

**振る舞いは、モジュールの公開の入口で確かめる。** 途中の手順（内部の関数の呼ばれ方・中間の値・呼ぶ順番）を確かめない。

- **内部名（`_`で始まる名前）へ直接入らない。計算を直接確かめたい・入口から条件を作りにくいなら、
  その計算を公開名にする**（`_`を外す、または小さな部品（公開の関数）へ切り出す）**から、その入口で確かめる。**
  内部名へ入る・途中を差し替える、で済ませない。
- **テストを読み手に数えて公開してよいのは、次の3つだけ。** モジュールの外に本番の読み手が無くても、この3つはテストが読むことを
  公開の理由にしてよい（周期レビューの「参照0の公開シンボル」も同じに数える）。
  - (a) 入力を値で受けて判断を持つ計算（関数・クラス。モジュールの状態を読み書きしない）
  - (b) テストが本物の値から境界の入力を組み立てる定数（`count = ID_CHUNK_SIZE + 1` 等）
  - (c) テストが差し替えるプロセス境界の置き場（ディスクのパス・OSのファイル。`infrastructure/road_network_store.py: ROOT`・
    `infrastructure/container_memory.py: CGROUP_MEMORY_MAX`等）。本番がいつも同じ置き場を渡すだけなら、置き場を引数や設定から受ける形にしない（テストのための口になる）。
    3つ以上のテストが同じ置き場を差し替えるなら、差し替えは共有の fixture（`backend/tests/conftest.py: road_network_root`等）が持つ
- **可変の状態（キャッシュ・接続・スケジューラ・時刻や世代の記録・集計）は、テストのために公開しない。**
  テストが空にしたい・差し替えたい状態は、上から順に直す。
  1. 大域に持たない——持ち主のオブジェクトへ寄せ、依存として注入する（例: `api/dependencies.py: get_gsi_tile_client`）
  2. 本番の寿命の口（閉じる・作り直す等、本番が呼ぶもの）を使う。無ければ本番が要る口として作り、足場もそれを使う
  3. どちらもできないものだけ、理由を定義の隣に書いた例外にする
- **差し替えてよいのはプロセス境界**（網・ディスク・時計・外部サービス）と、契約の狭い層の
  境目（依存として注入されるService等。自分のDB（Repository）は除く。例外は
  「フェイクの数は、実装の外向き参照の写し」の「自分のDB（Repository）は差し替えない」の段落が持つ）、
  および本番の正本を持つ宣言のデータ（「テストは、テストだけで成立させる」）**だけ**。
  自分のdomainの関数と自分の定数は**差し替えずに本物を通す**
  （関数・クラスは`backend/tests/structure/test_domain_not_replaced.py`が落とす）。
  上限値のような定数を差し替えて境界を作らず、本物の定数から入力を組み立てる。
- **差し替えた相手への呼び出しを確かめてよいのは、状態を変える呼び出し（送る・書く）だけ。** 読むだけの相手は
  応答を差し替えるだけにし、呼ばれたか・何回・どの引数で、を確かめない。外部サービスへの問い合わせのうち、
  回数そのものが相手との約束（回数制限・利用の上限・課金）に効くものは、送る側に数える。確かめる引数も、そのテストの
  関心事に絞る。
- **呼ばれたかを記録するために自分の関数を包まない**（本物へ委ねる記録用の包みも同じ）。「作る前に断る」のような順序の約束が
  入口の結果に現れないなら、テストでは確かめず、理由を実装の隣のコメントが持つ。入口の結果に現れる形
  （断ったときに外部サービスへ問い合わせない等）があるなら、そちらで確かめる。

### frontend

**入口**は、対象の種類で決まる。内部のstate・フックの呼ばれ方・子へ渡した関数の同一性は見ない。

| 対象 | 入力 | 確かめる出力 |
|---|---|---|
| 部品（`*.tsx`） | props・利用者の操作（`userEvent`） | 描いたもの（role・名前・表示文言・`aria-*`の状態）と、呼ばれたコールバックの引数 |
| フック（`use*.ts`） | 引数（`renderHook`の`rerender`で変える）・戻り値の関数を呼ぶこと | 戻り値と、backendへ送ったもの（状態を変える要求だけ。読むだけの要求は応答を与えるだけで、送ったかを見ない） |
| ページ（`app/**/page.tsx`） | 部品と同じ | 部品と同じ。ある機能の変化が別の機能の振る舞いを変える受け渡しを見る（[page-composition.md](../../docs/modules/frontend/page-composition.md)） |
| 純関数（`lib/`等） | 引数 | 戻り値 |

**画面の操作は、利用者の1つの流れを1本のテストにしてよい**（開く→選ぶ→送る、のような流れ。途中で何度
確かめてもよい）。backendは1つのテストで1つの振る舞いを確かめる。

**差し替えてよいのは次の境界だけ。** 自前のフック・`lib/`の関数・定数は、表の境界（環境変数の読み取り口・ファイルを落とす関数等）を除いて、差し替えずに本物を通す。

| 境界 | 差し替え方 |
|---|---|
| backendとの通信 | 網の層で差し替える（msw）。backendを呼ぶ口のモジュール（`services/*Api.ts`・`features/**/*Api.ts`）も、通信を包む自前のフック（`hooks/useAxisCatalog.ts: useAxisCatalog`等）も差し替えず、本物を通す（取得のキャッシュは`vitest.setup.ts`がテストごとに空にする）。応答は`frontend/src/testing/backendServer.ts`の手引きで経路ごとに与え、応答を与えていない要求はテストを落とす。口それぞれは、網の層で確かめる自分のテストを持つ |
| 時計 | `vi.useFakeTimers()`で進める。待ち時間の定数や、待つフック（`hooks/useDebouncedValue.ts: useDebouncedValue`）を差し替えない |
| 環境変数 | 値を**使う側**は、読み取り口のモジュール（`lib/tileBaseUrl.ts: tileBaseUrl`・`lib/adminBasicAuth.ts: adminBasicAuthCredentials`等）を`vi.mock`して値を固定する。使う側のテストで`process.env`を立てない。立ててよいのは読み取り口そのもののテストだけ（「パターン7」） |
| テスト環境に無いブラウザの機能 | WebGL（`maplibre-gl`）・レイアウトの実寸（`embla-carousel-*`）等。`maplibre-gl`は`frontend/src/testing/maplibre.ts`の代役へ差し替え、地図の部品は本物を描く（代役は受けたものを記録するだけで、出来事と押した所の地物はテストが起こす）。テスト環境が持つもの（`localStorage`・`navigator`の値等。環境変数は上の行）は、それを読むフックを差し替えず、環境に値を置く。`localStorage`が投げる場面を作るときは`window`のゲッター（`vi.spyOn(window, "localStorage", "get")`）を差し替え、`getItem`/`setItem`へスパイを張らない |
| ファイルを落とす | GPXの書き出し等、ブラウザにファイルを保存させる関数 |
| 子の部品 | 下の条件を満たすときだけ |

**子の部品は、既定では本物を描く。** 差し替えてよいのは、子の中身がテスト環境に無い境界（上の表の
「テスト環境に無いブラウザの機能」）を要し、それを境界の側で差し替えられないときだけ。差し替えて親のテストで見るのは
受け渡し（親の状態がどの値として子へ渡るか、子から上がった操作で親の何が変わるか）だけで、差し替えた子の表示は確かめない（子のテストが持つ）。

代役は受け取ったpropsを記録し、`children`を描くだけにする。子の振る舞いを真似ない。差し替えたものと、それで見えなくなるものは、ファイル冒頭の
「ここで見ないもの」に書く。

## 単体で確かめるかを、コードの種類で先に決める

**1本ずつ3問（[testing-necessity.md](testing-necessity.md)）へ通す前に、対象のコードがどの種類かで、単体で確かめるかを決める。** 軸は2つで、計算・業務の
判断を持つか（込み入っているか、外れると利用者への約束が崩れるか）と、つなぐ相手が多いか（呼ぶ他のモジュール・
外部の数）である。

| 種類 | 例 | 確かめ方 |
|---|---|---|
| 判断を持ち、相手が少ない | domainの計算・分類・検証 | 単体で確かめる。3問と起こし直しは主にここへ当てる |
| 判断が無く、相手も少ない | 受け取った値を詰め替えて渡すだけの関数 | 確かめない。使う側のテストが通す（3問の1問目の「1行の委譲」と同じ） |
| 判断が無く、相手が多い（つなぎ役） | 相手を順に呼ぶだけのServiceやフック・子を並べるだけの部品・ルーター | 単体では書かない。上の入口（APIの経路・ページ）のテストで受け渡しを少し通す（3問の3問目の「別の高さで同じ判断を見ている」） |
| 判断を持ち、相手も多い | 判断と結線が1つの関数・部品に混ざったもの | テストの前に実装を分け、判断を相手の少ない部品へ出す（[書きたくなったテストが、実装の歪みを教える](testing-writing.md#書きたくなったテストが実装の歪みを教える)） |

## 警告は既定でエラー

警告は1つでも出たらテストを落とす。

| | 落とす仕組み | 直せない警告を許す場所 |
|---|---|---|
| backend | `backend/pytest.ini`の`filterwarnings`が`error`から始まる | 同じ`filterwarnings`へ`ignore:<メッセージの先頭>:<警告の種類>`の1行 |
| frontend | `frontend/vitest.setup.ts`が`console.warn`・`console.error`（Reactの警告もここへ届く）を受け、出したテストを落とす | `vitest.setup.ts: ALLOWED_WARNINGS`へ文の正規表現の1件 |

直せない／直すべきでない警告（依存ライブラリが自分の内部で出すもの等）だけを、**1件ずつ文で名指して、
理由と外せる条件を添えて許す**。依存を上げて不要になったら消す。

- 絞り込みはメッセージまで書く。`ignore::DeprecationWarning`や「`console.error`を全部」のように
  種類だけで黙らせない
- テストの中で警告を出すこと自体を確かめるテスト（ログの口のテスト等）は、そのテストが
  `vi.spyOn(console, ...)`に`mockImplementation`を付けて出力を止め、中身を確かめる
- vitestはAIの作業役の下では既定のレポーターを`minimal`にする。警告はテストの失敗の文で読む（出力を全部見たいときは
  `--reporter=default --silent=false`）

## 挙動を変えるなら、テストを先に書く

**挙動を変えるタスクは、テストを先に追加/更新してから実装する。**

## わざと壊すのは、テストの中で

検知器・ガード・テストが効いていることは、わざと壊した入力で落ちることを見て確かめる（[fixing.md](fixing.md)「直し方」）。
**壊すのはテストの中の入力で、ソースやビルドを書き換えない。** 例外は、消す・まとめるテストの壊れ方で残す側が落ちるかを見るとき
（「そのテストは要るか（3問を順に）」の表の行の決まりのあと）で、実装の1行を一時に変える。戻し方もそちらが持つ。

- **画面の検知器**は、壊れた状態をテストの中で作る: playwrightなら`page.addStyleTag`で崩れたスタイルを足す・
  モックの応答を差し替える、vitestなら渡す入力（props・フェイクの応答）を差し替える。ソースを書き換えて
  本番ビルドし直さない。
- **道具（`scripts/`）の仕組み**は、一時的なgitリポジトリと入力の差し替え（網・時計・書き出したファイル）で、
  入口から確かめる。
- **数分かかる本物の処理**（本番ビルド・本物の`npm ci`・E2Eの一式）は、最終確認の1回までにする。
