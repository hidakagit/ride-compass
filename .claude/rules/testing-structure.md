# ソースを読む検査と、空のループ

番号は CLAUDE.md「原則」の番号。

## ソースを読む検査は、専用ディレクトリへ置く

- リポジトリのソースをデータとして読む（ASTやテキストとして走査し、コードは動かさない）テストは、backendは
  `backend/tests/structure/`、frontendは`frontend/src/structure/`に置き、普通のテストと混ぜない。コードを動かして確かめるテストは、
  横断的な不変条件を守るものでも、普通のテストとして対象の隣へ置く。（原則3）
- ソースを読む検査のうち、CIが既に回す静的検査（backendの`ruff.toml`・`.importlinter`・`mypy.ini`、frontendのESLint・knip）の設定で
  表せて許可リストが要らないものは、テストにせずその設定へ置く（例: web層が`app.batch`をモジュール直下でimportしない →
  `backend/ruff.toml`の`TID253`）。行ごとの`# noqa`で許せば足りるものも設定の側に置き、古くなった`# noqa`を落とす`RUF100`を
  `select`へ入れる。テストにするのは、自前でソースを読む（ASTの走査・一覧からの母集団）ことが要るものと、許可リストが要るもの
  （ruffの`per-file-ignores`は古くなっても落ちない）だけにする。`scripts/review_checks.py`の検知器へは置かない（[fixing.md](fixing.md)
  「検知器を足す条件は厳しい」）。（原則7）
- 許可リストを持つ検査は、載っているのに実態が無い項目も違反にして、列挙が古くなったら検査自身が落ちる形にする
  （例: `test_redis_skeleton.py`）。（原則8）

## わざと壊すのは、テストの中で

- 検知器・ガードが効いていることは、テストの中の入力をわざと壊して落ちることで確かめ、ソースやビルドを書き換えない。画面の
  検知器なら、playwrightでは`page.addStyleTag`で崩れたスタイルを足す・モックの応答を差し替え、vitestでは渡す入力（props・フェイクの
  応答）を差し替える。テストの効きを測るために実装を一時に変えるのは、これとは別のtesting-review.mdの確かめである。（原則8・11）
- 道具（`scripts/`）の仕組みは、一時的なgitリポジトリと入力の差し替え（網・時計・書き出したファイル）で、入口から確かめる。（原則5）
- 数分かかる本物の処理（本番ビルド・本物の`npm ci`・E2Eの一式）を回すのは、最終確認の1回までにする。（原則11）

## パターン6: 絞り込んだ母集団をループするテストは、空でないことを確かめる

- 要素ごとの検査は、宣言から導いた母集団を`parametrize`へ渡して書く。ループで書くのは、1回の実I/Oの結果を要素ごとに見るとき
  だけにする（testing.md「ループで実I/Oを繰り返さない」）。（原則7・8）
