# キャッシュの置き場

サーバーの中で一度得た値を持つときに、何を持ってよいか・どこに持つか・壊れたらどうするかの決まり。
何を持ち、いつ捨てるか（Redisへ置くもの・TTL・無効化）は[caching-retention.md](caching-retention.md)が持つ。

## 持ってよいもの・壊れたとき

- キャッシュするのは、消えても呼び出し元が取り直す・計算し直すだけで同じ答えに戻れる値だけにする。キャッシュにしか無い値を作らない。（原則3）
- キャッシュの層の障害（Redisへ届かない・壊れた値・ディスクの読み書きの失敗）は、どれも「キャッシュに無い」として通常の取得へ進め、利用者への応答を止めない。（原則5）
- キャッシュで隠すのは遅さだけにする。古い値を返す（stale fallback）ときは、どれだけ古い値まで返すかを定数にして、それより古い値は返さない。（原則5）

## 保持層の選び方

- 置き場は、プロセス内で足りるならプロセス内、プロセスをまたぐ必要があり値が小さく TTL を付けられるなら Redis、数百MB規模か TTL を付けられないならディスク、の順で選ぶ。値の形式（バイト列かオブジェクトか）を置き場を増やす理由にしない。（原則8）
- 速さを理由に Redis を選ばない。読み出しを速くしたいときは、置き場でなく値の表し方（pickle 以外のシリアライズ）を変える。本番の測りは[tech-stack.md](../../docs/architecture/tech-stack.md)「本番Redisの設定」。（原則10）

### プロセス内キャッシュは`cachetools`に統一する

- プロセス内のキャッシュは`cachetools`の`TTLCache`（TTLが要るとき）か`LRUCache`（件数の上限だけのとき）で持ち、追い出し（`OrderedDict`＋`move_to_end`＋`popitem`等）を自前で書かない。ライブラリで表せない要件は、`cachetools`を内側に包む薄い包みで足し、追い出しは包んだ側に任せる。（原則7）

### ディスクを選ぶときの責任

- ディスクに持つキャッシュを足すときは、同じ変更で次の3つを用意し、どの関数をいつ呼ぶかをそのモジュールの`docs/modules/*.md`に書く。ディスクには Redis の`maxmemory`のような上限も退避も無く、世代が変わっても古い実体が残り続けるため。（原則4・5・11）
  1. 容量の上限と退避（退避の順は読み方に合わせて選ぶ）
  2. 世代が変わって要らなくなった実体を消す口と、それを呼ぶ所（上限とは別に要る）
  3. 使用量が見込みに収まっているかを確かめる方法
